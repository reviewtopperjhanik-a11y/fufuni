## Customer Authentication and Middleware

In the Fufuni framework, any route under the `/v1/me/*` prefix is strictly customer-scoped. This isolation is enforced by the `customerAuthMiddleware`. Unlike admin routes that require specific RBAC permissions, the customer middleware primarily focuses on verifying the identity of a user via an Auth0-issued JWT.

The middleware performs several critical tasks:
1.  **JWT Verification**: It validates the `Authorization: Bearer <token>` header against your Auth0 domain and audience.
2.  **Claim Extraction**: It extracts the `sub` (Subject), `email`, and `name` from the token.
3.  **Context Injection**: It populates the Hono context `c.get('auth')` with a `customer` role. This context is used by downstream handlers to identify which database record to interact with.

```typescript
import { createMiddleware } from 'hono/factory';
import { ApiError, type HonoEnv } from '../types';
import { verifyAuth0Jwt } from '../lib/auth0';

/**
 * Ensures the request has a valid Auth0 JWT and populates the 'auth' context.
 */
export const customerAuthMiddleware = createMiddleware<HonoEnv>(async (c, next) => {
  const authHeader = c.req.header('Authorization');
  if (!authHeader?.startsWith('Bearer ')) {
    throw ApiError.unauthorized('Missing or invalid Authorization header');
  }

  const token = authHeader.slice(7);
  const domain = c.env.AUTH0_DOMAIN;
  const audience = c.env.AUTH0_AUDIENCE;

  try {
    const payload = await verifyAuth0Jwt(token, domain, audience);
    const sub = payload.sub as string;
    
    if (!sub) throw new Error('Missing sub claim');

    // Extracting user info from standard claims or custom Auth0 namespaces
    const email = (payload.email as string) || (payload['https://fufuni.com/email'] as string);
    const name = (payload.name as string) || (payload['https://fufuni.com/name'] as string);

    c.set('auth', {
      role: 'customer',
      sub: sub,
      email: email,
      name: name
    });

    await next();
  } catch (err) {
    throw ApiError.unauthorized('Invalid or expired token');
  }
});
```

## Customer Resolution and Auto-Creation

Fufuni follows a "Just-In-Time" (JIT) provisioning pattern for customer records. When a customer authenticates for the first time, they likely do not exist in the local SQLite database. The backend must bridge the gap between the Auth0 `sub` and the local `customers` table.

The `getOrCreateCustomer` logic (often implemented within `resolveCustomer`) handles this synchronization:
1.  **Lookup by Sub**: Attempt to find a record where `auth_provider_id` matches the JWT `sub`.
2.  **Lookup by Email**: If not found, check if a customer exists with the same email (handling legacy accounts or manual imports).
3.  **Creation**: If no match is found, insert a new row.
4.  **Synchronization**: If the record exists but the email or name in the JWT is newer/different from the DB, the DB is updated to match Auth0.

```typescript
import { now, uuid } from '../types';

/**
 * Resolves the local customer ID using Auth0 claims.
 * This is typically called at the start of every /v1/me route handler.
 */
async function getOrCreateCustomer(db: any, sub: string, email?: string, name?: string) {
  // 1. Try to find by Auth0 ID
  let customer = await db.query(
    `SELECT * FROM customers WHERE auth_provider_id = ? LIMIT 1`,
    [sub]
  );

  if (customer.length > 0) {
    const existing = customer[0];
    // Sync email if it changed in Auth0
    if (email && email.toLowerCase() !== existing.email.toLowerCase()) {
      await db.run(`UPDATE customers SET email = ?, updated_at = ? WHERE id = ?`, 
        [email.toLowerCase(), now(), existing.id]);
    }
    return existing;
  }

  // 2. Fallback to Email lookup to link existing accounts
  if (email) {
    const byEmail = await db.query(
        `SELECT * FROM customers WHERE email = ? LIMIT 1`,
        [email.toLowerCase()]
    );
    if (byEmail.length > 0) {
        await db.run(
            `UPDATE customers SET auth_provider = 'auth0', auth_provider_id = ?, updated_at = ? WHERE id = ?`,
            [sub, now(), byEmail[0].id]
        );
        return { ...byEmail[0], auth_provider_id: sub };
    }
  }

  // 3. Create new record
  const newId = uuid();
  await db.run(
    `INSERT INTO customers (id, email, name, auth_provider, auth_provider_id, created_at, updated_at)
     VALUES (?, ?, ?, 'auth0', ?, ?, ?)`,
    [newId, email?.toLowerCase() || '', name || '', sub, now(), now()]
  );

  return { id: newId, email, name, auth_provider_id: sub };
}
```

## Profile Management (GET/PATCH /v1/me)

The profile endpoints allow customers to view and update their basic information. This information is stored in the local SQLite database, though critical identity data (like passwords) remains in Auth0.

### GET /v1/me
Returns the profile of the currently authenticated customer.

### PATCH /v1/me
Updates specific mutable fields. Valid fields include `name`, `phone`, and `marketing_opt_in`.

```typescript
import { z } from 'zod';
import { createRoute } from '@hono/zod-openapi';

const CustomerProfileSchema = z.object({
  id: z.string().uuid(),
  email: z.string().email(),
  name: z.string().nullable(),
  phone: z.string().nullable(),
  marketing_opt_in: z.boolean(),
  created_at: z.number()
});

const UpdateProfileSchema = z.object({
  name: z.string().optional(),
  phone: z.string().optional(),
  marketing_opt_in: z.boolean().optional()
});

// Example implementation of the PATCH route
export const updateMeRoute = createRoute({
  method: 'patch',
  path: '/v1/me',
  request: {
    body: { content: { 'application/json': { schema: UpdateProfileSchema } } }
  },
  responses: {
    200: { content: { 'application/json': { schema: CustomerProfileSchema } }, description: 'Profile updated' }
  }
});
```

## Address Book Patterns

The address book is a collection of physical addresses associated with the `customer_id`. One address can be marked as `is_default`.

| Method | Endpoint | Description |
| :--- | :--- | :--- |
| `GET` | `/v1/me/addresses` | List all addresses for the authenticated customer. |
| `POST` | `/v1/me/addresses` | Add a new address. If `is_default` is true, other addresses are unset as default. |
| `PATCH` | `/v1/me/addresses/:id` | Update an existing address. |
| `DELETE` | `/v1/me/addresses/:id` | Remove an address. |

### Address Schema
Every address object must adhere to the following structure:

```typescript
export const AddressSchema = z.object({
  id: z.string().uuid(),
  label: z.string().describe('e.g., Home, Work, Beach House'),
  first_name: z.string().min(1),
  last_name: z.string().min(1),
  line1: z.string().min(1),
  line2: z.string().optional(),
  city: z.string().min(1),
  postal_code: z.string().min(1),
  country_code: z.string().length(2).describe('ISO 3166-1 alpha-2 code'),
  is_default: z.boolean().default(false)
});
```

## Order History and Pagination

The order history endpoint is strictly filtered by the authenticated `customer_id`. It supports basic pagination to ensure high performance on accounts with many transactions.

```typescript
// GET /v1/me/orders?page=1&limit=10
adminApp.openapi(
  createRoute({
    method: 'get',
    path: '/v1/me/orders',
    request: {
      query: z.object({
        page: z.coerce.number().default(1),
        limit: z.coerce.number().default(10)
      })
    },
    responses: {
      200: { description: 'List of customer orders' }
    }
  }),
  async (c) => {
    const { page, limit } = c.req.valid('query');
    const auth = c.get('auth');
    const db = getDb(c.env);
    
    const customer = await getOrCreateCustomer(db, auth.sub);
    const offset = (page - 1) * limit;

    const orders = await db.query(
      `SELECT * FROM orders WHERE customer_id = ? ORDER BY created_at DESC LIMIT ? OFFSET ?`,
      [customer.id, limit, offset]
    );

    return c.json({ data: orders, page, limit });
  }
);
```

## Saved Cart Endpoints

Fufuni allows customers to persist their shopping cart across sessions. This is separate from the frontend's local storage; when a customer logs in, the frontend should synchronize the local cart with the `saved-cart` endpoint.

*   **GET `/v1/me/saved-cart`**: Retrieves the JSON blob of the saved cart.
*   **PUT `/v1/me/saved-cart`**: Overwrites the saved cart with the current state.
*   **DELETE `/v1/me/saved-cart`**: Clears the persisted cart (usually after order completion).

```typescript
const SavedCartSchema = z.object({
  items: z.array(z.object({
    variant_id: z.string(),
    quantity: z.number().int().positive()
  })),
  updated_at: z.number()
});

// Example PUT handler logic
async function updateSavedCart(db: any, customerId: string, items: any[]) {
  const cartJson = JSON.stringify(items);
  await db.run(
    `INSERT INTO customer_carts (customer_id, items_json, updated_at)
     VALUES (?, ?, ?)
     ON CONFLICT(customer_id) DO UPDATE SET items_json = excluded.items_json, updated_at = excluded.updated_at`,
    [customerId, cartJson, Date.now()]
  );
}
```

## Preferences: Locale and Currency

To provide a localized experience, customers can save their preferred language and display currency. These preferences influence how prices are formatted and which translations are prioritized in the frontend.

```typescript
// PUT /v1/me/preferences
const PreferencesSchema = z.object({
  locale: z.string().regex(/^[a-z]{2}-[A-Z]{2}$/).default('en-US'),
  currency: z.string().length(3).default('USD')
});

adminApp.openapi(
  createRoute({
    method: 'put',
    path: '/v1/me/preferences',
    request: {
      body: { content: { 'application/json': { schema: PreferencesSchema } } }
    },
    responses: {
      200: { description: 'Preferences saved' }
    }
  }),
  async (c) => {
    const { locale, currency } = c.req.valid('json');
    const auth = c.get('auth');
    const db = getDb(c.env);
    const customer = await getOrCreateCustomer(db, auth.sub);

    await db.run(
      `UPDATE customers SET locale = ?, currency = ? WHERE id = ?`,
      [locale, currency, customer.id]
    );

    return c.json({ success: true });
  }
);
```

## Adding a New /v1/me/* Route

When adding a new customer-scoped endpoint, follow these standard steps:

1.  **Define Schema**: Create a Zod schema for the request and response in the `types` or local route file.
2.  **Define Route**: Use `createRoute` from `@hono/zod-openapi` to ensure the route is documented in the Swagger UI.
3.  **Ensure Middleware**: Verify the route is handled by the `adminApp` (or your specific customer sub-router) that has `customerAuthMiddleware` applied.
4.  **Resolve ID**: Always start the handler by calling `getOrCreateCustomer` to get the internal `customers.id`. Never trust a `customer_id` passed in the request body/query; always derive it from the JWT `sub`.

```typescript
// example: /v1/me/wishlist
const WishlistRoute = createRoute({
  method: 'get',
  path: '/v1/me/wishlist',
  responses: {
    200: { description: 'Customer wishlist items' }
  }
});

adminApp.openapi(WishlistRoute, async (c) => {
  const auth = c.get('auth');
  const db = getDb(c.env);
  
  // 1. Resolve local ID from Auth0 'sub'
  const customer = await getOrCreateCustomer(db, auth.sub);
  
  // 2. Query data using the secure ID
  const items = await db.query(
    `SELECT * FROM wishlist_items WHERE customer_id = ?`,
    [customer.id]
  );
  
  return c.json({ items });
});
```
