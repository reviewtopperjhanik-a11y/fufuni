### Double-Entry Migrations
When modifying the database schema, you must define the migration in two places: the SQL file for historical tracking and the `ensureInitialized` method in `do.ts` for the Durable Object's cold-start bootstrap.

```sql
-- apps/merchant/migrations/0003_add_discount_code.sql
ALTER TABLE orders ADD COLUMN discount_code TEXT;
```

```typescript
// apps/merchant/src/do.ts
async ensureInitialized() {
  // ... existing migrations
  await this.db.run(`ALTER TABLE orders ADD COLUMN IF NOT EXISTS discount_code TEXT;`);
}
```

### Monetary Values as Integers
Never use floats or decimals for currency to avoid precision errors. Always store the smallest unit (e.g., cents for USD, subunits for other currencies).

```typescript
// apps/merchant/src/models/product.ts
import { z } from "@hono/zod-openapi";

export const ProductSchema = z.object({
  id: z.string(),
  name: z.string(),
  price_cents: z.number().int().positive().describe("Price in the smallest currency unit"),
});

// Implementation usage
const price = 19.99;
const priceToStore = Math.round(price * 100); // 1999
```

### Centralized Error Handling with ApiError
Instead of throwing generic errors or returning manual JSON responses for failures, use the `ApiError` static helpers to maintain consistent OpenAPI-compliant responses.

```typescript
// apps/merchant/src/routes/products.ts
import { ApiError } from "../utils/errors";

app.openapi(getRoute, async (c) => {
  const { id } = c.req.valid("param");
  const product = await db.select().from(products).where(eq(products.id, id)).get();
  
  if (!product) {
    throw ApiError.notFound(`Product with ID ${id} not found`);
  }
  
  return c.json(product, 200);
});
```

## ANTI-PATTERNS

### NEVER use onClick for Interactive Elements
Fufuni uses HeroUI (built on React Aria). Standard `onClick` events do not provide the necessary accessibility and touch optimizations. Always use `onPress`.

```typescript
// ❌ WRONG
<Button onClick={() => console.log("Clicked")}>Submit</Button>

// ✅ CORRECT
<Button onPress={() => console.log("Pressed")}>Submit</Button>
```

### NEVER use variant="bordered"
The `bordered` variant is deprecated/removed in HeroUI v3. Using it will result in unstyled components or runtime warnings. Use `variant="outline"` instead.

```typescript
// ❌ WRONG
<Button variant="bordered">Cancel</Button>

// ✅ CORRECT
<Button variant="outline">Cancel</Button>
```

### NEVER add radius prop to Buttons
To maintain design consistency and allow Tailwind's utility-first approach, avoid using the `radius` prop on HeroUI buttons. Use Tailwind classes in `className`.

```typescript
// ❌ WRONG
<Button radius="full">Save</Button>

// ✅ CORRECT
<Button className="rounded-full">Save</Button>
```

### NEVER use useEffect for State Synchronization
Syncing state manually with `useEffect` leads to race conditions and "double-render" bugs. Use React Query for server state and derive UI state from props or query results.

```typescript
// ❌ WRONG
const [data, setData] = useState(null);
useEffect(() => {
  fetch('/api/data').then(res => res.json()).then(setData);
}, []);

// ✅ CORRECT
const { data, isLoading } = useQuery({
  queryKey: ['data'],
  queryFn: fetchData
});
```

### NEVER Store Auth0 Tokens in Persistent Storage
Storing tokens in `localStorage` or `sessionStorage` exposes the application to XSS attacks. The Auth0 React SDK handles token storage in-memory automatically.

```typescript
// ❌ WRONG
localStorage.setItem('access_token', token);

// ✅ CORRECT
// Just use the hook provided by the SDK
const { getAccessTokenSilently } = useAuth0();
const token = await getAccessTokenSilently();
```

### NEVER Hardcode Permission Strings
Hardcoding permissions makes the app difficult to maintain and refactor. Use the environment variables on the frontend or the extracted JWT permissions on the backend.

```typescript
// ❌ WRONG
if (user.permissions.includes("admin:delete_user")) { ... }

// ✅ CORRECT
// Frontend
if (import.meta.env.PERMISSIONS.CAN_DELETE_USER) { ... }

// Backend (via middleware)
const permissions = c.get("permissions");
if (permissions.includes(Permissions.DeleteUser)) { ... }
```

### NEVER Access Auth0 Management API Directly from Frontend
Raw Management API tokens must never reach the browser. Use the `getAuth0ManagementToken()` helper on the backend to proxy these requests securely.

```typescript
// ❌ WRONG
const res = await fetch('https://YOUR_DOMAIN.auth0.com/api/v2/users', {
  headers: { Authorization: `Bearer ${EXPOSED_TOKEN}` }
});

// ✅ CORRECT (Inside a Hono route on the backend)
const mgmtToken = await getAuth0ManagementToken(c.env);
const response = await fetch(`${c.env.AUTH0_DOMAIN}/api/v2/users`, {
  headers: { Authorization: `Bearer ${mgmtToken}` }
});
```

### NEVER use dangerouslySetInnerHTML outside renderDescription
To prevent XSS, all user-generated content is sanitized on the backend. Only the specific `renderDescription()` helper function is permitted to render HTML, as it acts as a controlled boundary.

```typescript
// ❌ WRONG
<div dangerouslySetInnerHTML={{ __html: product.description }} />

// ✅ CORRECT
import { renderDescription } from "@/utils/render";

const ProductCard = ({ product }) => {
  return (
    <div>
      {renderDescription(product.description)}
    </div>
  );
};
```

### NEVER use plain HTML file inputs for images
Image handling in Fufuni involves specific processing and upload logic. Always use the provided `ImageUploadInput` component in admin forms to ensure compatibility with the storage backend.

```typescript
// ❌ WRONG
<input type="file" onChange={handleUpload} />

// ✅ CORRECT
import { ImageUploadInput } from "@/components/forms/ImageUploadInput";

<ImageUploadInput 
  name="thumbnail" 
  label="Product Thumbnail" 
  onUploadSuccess={(url) => setValue("thumbnailUrl", url)} 
/>
```
