## Analytics API Endpoints

The Fufuni analytics system provides a set of admin-only REST endpoints under the `/v1/analytics` prefix. Unlike traditional e-commerce platforms that rely on external SaaS providers, Fufuni computes all metrics on-demand directly from the SQLite database inside the merchant's Durable Object.

All endpoints support three primary query parameters:
- `from`: ISO 8601 string (e.g., `2023-01-01T00:00:00Z`).
- `to`: ISO 8601 string (e.g., `2023-01-31T23:59:59Z`).
- `currency`: 3-letter ISO code (e.g., `USD`, `EUR`). Defaults to the store's primary currency.

## Backend Implementation and SQLite Computation

Fufuni avoids pre-aggregating data to maintain a "single source of truth" in the SQLite tables. Metrics are calculated using standard SQL aggregations. Because these operations can be heavy as the store grows, queries are optimized for the SQLite engine within Cloudflare Durable Objects.

### Revenue by Day Calculation
The following example demonstrates how the framework extracts daily time-series data for Recharts using SQLite's `strftime` and `date` functions.

```typescript
// Example: Internal SQL logic for GET /v1/analytics/revenue
const getRevenueByDay = async (db: Database, from: string, to: string) => {
  return await db.query<{ date: string; amount: number }>(`
    SELECT 
      date(created_at) as date,
      SUM(total_cents) as amount
    FROM orders
    WHERE status IN ('paid', 'processing', 'shipped', 'delivered')
      AND created_at BETWEEN ? AND ?
    GROUP BY date(created_at)
    ORDER BY date ASC
  `, [from, to]);
};
```

### Top Products Computation
Ranking is computed by joining `order_items` with the `orders` table to ensure only successful transactions are counted.

```typescript
// GET /v1/analytics/products/top (Limit 10)
const getTopProducts = async (db: Database, from: string, to: string) => {
  return await db.query<{ productId: string; name: string; amount: number }>(`
    SELECT 
      oi.product_id as productId,
      oi.title as name,
      SUM(oi.price_cents * oi.quantity) as amount
    FROM order_items oi
    JOIN orders o ON oi.order_id = o.id
    WHERE o.status NOT IN ('cancelled', 'refunded')
      AND o.created_at BETWEEN ? AND ?
    GROUP BY oi.product_id
    ORDER BY amount DESC
    LIMIT 10
  `, [from, to]);
};
```

## Checkout Funnel Analysis

The funnel tracks the conversion efficiency of the storefront. This data is derived from the `checkouts` table (which tracks intent) and the `orders` table (which tracks completion).

| Step | Metric Name | Definition |
| :--- | :--- | :--- |
| 1 | `cartCreated` | Number of distinct sessions that added at least one item to a cart. |
| 2 | `checkoutStarted` | Number of checkouts where the user entered shipping/contact info. |
| 3 | `checkoutCompleted` | Number of checkouts that converted into a `paid` order. |
| 4 | `conversionRate` | `checkoutCompleted` / `cartCreated` |

```typescript
// Implementation of GET /v1/analytics/funnel
const funnel = {
  cartCreated: await db.queryValue<number>(`SELECT COUNT(*) FROM checkouts WHERE created_at BETWEEN ? AND ?`, [from, to]),
  checkoutStarted: await db.queryValue<number>(`SELECT COUNT(*) FROM checkouts WHERE shipping_address_id IS NOT NULL AND created_at BETWEEN ? AND ?`, [from, to]),
  checkoutCompleted: await db.queryValue<number>(`SELECT COUNT(*) FROM orders WHERE created_at BETWEEN ? AND ?`, [from, to]),
};
```

## Performance Note and Indexing

Since Fufuni computes analytics on-demand, response times can degrade as the `orders` and `order_items` tables grow into the hundreds of thousands of rows. To maintain sub-second dashboard loads, ensure the following indexes are present in the SQLite schema:

```sql
-- Vital for date-range filtering in all analytics endpoints
CREATE INDEX IF NOT EXISTS idx_orders_created_at ON orders(created_at);

-- Vital for top product and revenue-by-product queries
CREATE INDEX IF NOT EXISTS idx_order_items_product_id ON order_items(product_id);

-- Vital for customer retention/returning rate logic
CREATE INDEX IF NOT EXISTS idx_orders_customer_id ON orders(customer_id);

-- Speeds up status-based filtering (e.g., excluding cancelled orders)
CREATE INDEX IF NOT EXISTS idx_orders_status ON orders(status);
```

## Currency Conversion in Analytics

The analytics engine handles multi-currency stores by converting all transactions to the requested `?currency=XXX` parameter using the exchange rate stored at the time of the transaction. If no conversion rate was captured for an old order, it falls back to the current store rate or a 1:1 mapping if the currencies match.

- **Storage:** All values are returned as integers in the smallest unit (e.g., 1000 for $10.00).
- **Rounding:** SQLite's `ROUND()` is used during the `SUM()` of converted values to avoid floating-point errors common in financial calculations.
