## Durable Object Schema Management

In the Fufuni framework, migrations are not executed via traditional CLI tools like `wrangler d1 migrations`. Instead, the **Durable Object (DO)** is the ultimate authority on its own internal SQLite state. When the DO starts, the `ensureInitialized()` method executes a series of SQL statements that define the schema and apply incremental changes.

While migration files exist in `apps/merchant/migrations/` for audit purposes and manual local testing, the `SCHEMA` constant and subsequent `db.prepare().run()` calls in `do.ts` are the source of truth.

### Initialization Pattern in do.ts

Junior developers must ensure that any new table or column is added both to a new migration file and to the `ensureInitialized` logic using `IF NOT EXISTS` or safe `ALTER TABLE` guards.

```typescript
// apps/merchant/src/do.ts example of the initialization pattern
private async ensureInitialized() {
  const db = this.ctx.storage.sql;
  
  // 1. Core Schema (The baseline)
  db.exec(SCHEMA);

  // 2. Incremental Migrations (Applying logic found in .sql files)
  // Example: Migration 019 - Variant Enrichment
  try {
    db.prepare(`ALTER TABLE variants ADD COLUMN requires_shipping INTEGER NOT NULL DEFAULT 1`).run();
    db.prepare(`ALTER TABLE variants ADD COLUMN barcode TEXT`).run();
  } catch (e) {
    // Column might already exist if migration ran previously
  }

  // 3. Trigger Maintenance
  db.exec(`
    CREATE TRIGGER IF NOT EXISTS trg_products_updated_at
    AFTER UPDATE ON products
    FOR EACH ROW
    BEGIN
      UPDATE products SET updated_at = datetime('now') WHERE id = OLD.id;
    END;
  `);
}
```

## Migration Conventions Reference

When adding a new migration, strictly follow these standards:

1.  **ID Generation**: Use `TEXT PRIMARY KEY` for entities (UUIDs generated by the application) and `INTEGER PRIMARY KEY AUTOINCREMENT` only for simple join tables or logs.
2.  **Timestamps**: Always include `created_at TEXT NOT NULL DEFAULT (datetime('now'))` and `updated_at TEXT NOT NULL DEFAULT (datetime('now'))`.
3.  **Soft Checks**: Use `PRAGMA foreign_keys = ON;` at the start of complex migration scripts to ensure referential integrity during table swaps.
4.  **Indexing**: Create indexes for any column used in a `WHERE` clause or `JOIN` condition (e.g., `idx_table_column`).
5.  **Booleans**: SQLite does not have a boolean type. Use `INTEGER` (0 for false, 1 for true).

    UPDATE table_name SET updated_at = datetime('now') WHERE id = OLD.id;
END;
