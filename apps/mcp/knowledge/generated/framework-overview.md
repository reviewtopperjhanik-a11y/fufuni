## Framework Overview

Fufuni is an AI-native, 100% free-tier e-commerce framework designed for high-performance storefronts. By leveraging Cloudflare's edge computing infrastructure—specifically Cloudflare Workers and Durable Objects with built-in SQLite—Fufuni eliminates cold starts and database latency while maintaining zero hosting costs. It is built to be "Universal Commerce Protocol" (UCP) compliant, allowing AI shopping agents to browse, search, and initiate checkouts via standardized endpoints.

## Technical Stack

The architecture is designed to maximize the capabilities of the Cloudflare ecosystem while providing a modern Developer Experience (DX) with strict TypeScript safety.

| Layer | Technology | Notes |
| :--- | :--- | :--- |
| **Frontend** | React 19 + Vite 6 + HeroUI v3 | SPA hosted on GitHub Pages; uses Tailwind CSS for styling. |
| **Backend API** | Hono + Zod-OpenAPI | Type-safe routing with automatic OpenAPI/Swagger generation. |
| **Database** | Durable Objects (SQLite) | ACID-compliant storage inside a single JS isolate; no connection pools. |
| **Authentication**| Auth0 | Passwordless and Social auth; RBAC via JWT permission claims. |
| **Storage** | Cloudflare R2 | S3-compatible object storage for product and category images. |
| **Caching** | Cloudflare KV | Globally distributed cache with prefix-based invalidation for catalog. |
| **Payments** | Stripe | Integration via Stripe Checkout with dynamic server-side shipping rates. |
| **Emails** | Mailgun | Transactional order emails with AI-translated templates. |

## Monorepo Structure

Fufuni uses **Turborepo** for workspace orchestration. The project is organized to separate concerns while sharing types and utilities across the stack.

- **`apps/client`**: The React 19 storefront and admin dashboard.
    - `src/pages/admin`: Back-office views for inventory, orders, and configuration.
    - `src/config/site.ts`: Centralized configuration for navigation and RBAC.
- **`apps/merchant`**: The core backend Worker.
    - `src/index.ts`: Hono application entry point and middleware configuration.
    - `src/do.ts`: The `MerchantDO` class containing the SQLite schema and logic.
    - `migrations/`: Numbered SQL files for database versioning.
- **`apps/mcp`**: A specialized Worker exposing the codebase as a Model Context Protocol server for AI assistants.
- **`scripts/`**: Utility scripts for Auth0 resource deployment, database seeding, and environment initialization.

## Request Lifecycle

Requests in Fufuni follow a streamlined path to ensure minimal latency. Because the database (SQLite) and the logic (Worker) run in the same physical location within the Cloudflare network, total request time is significantly lower than traditional "server + remote DB" setups.

1.  **Ingress**: The request hits the Cloudflare Edge.
2.  **Hono Middleware**:
    - **CORS**: Handles cross-origin requests from the GitHub Pages frontend.
    - **Auth**: Validates `pk_` (Public), `sk_` (Secret), or Auth0 JWTs.
    - **KV Cache**: For `GET` catalog requests, the Worker checks Cloudflare KV first.
3.  **Durable Object Routing**: The Worker obtains a "stub" for the `MerchantDO`. In Fufuni, a single DO named `default` handles all store state to ensure consistency.
4.  **SQLite Execution**: The logic inside the DO executes SQL queries against the local `c.sql` instance.
5.  **Egress**: The result is returned as JSON, and the `kvInvalidateMiddleware` purges relevant cache keys if the request was a mutation (`POST`, `PATCH`, `DELETE`).

### Implementation Example: Typed Route and DO Access

The following example demonstrates how a backend route is defined using Zod-OpenAPI and how it interacts with the Durable Object storage.

```typescript
// apps/merchant/src/routes/catalog.ts
import { createRoute, z } from '@hono/zod-openapi';
import { OpenAPIHono } from '@hono/zod-openapi';
import { type Env, type DOStub } from '../types';

const adminCatalog = new OpenAPIHono<{ Bindings: Env; Variables: { db: DOStub } }>();

// 1. Define the API contract with Zod
const GetProductRoute = createRoute({
  method: 'get',
  path: '/{id}',
  request: {
    params: z.object({
      id: z.string().openapi({ example: 'prod_123' }),
    }),
  },
  responses: {
    200: {
      description: 'The product details',
      content: {
        'application/json': {
          schema: z.object({
            id: z.string(),
            title: z.string(),
            status: z.string(),
          }),
        },
      },
    },
  },
});

// 2. Implement the route logic
adminCatalog.openapi(GetProductRoute, async (c) => {
  const { id } = c.req.valid('param');
  const db = c.get('db');

  // Durable Object RPC call to fetch data from SQLite
  const product = await db.getProduct(id);

  if (!product) {
    return c.json({ error: 'Not Found' }, 404);
  }

  return c.json(product, 200);
});

export { adminCatalog };
```

## Key Conventions

Developers contributing to Fufuni must adhere to the following architectural standards:

### 1. Database Migrations
Fufuni uses a "Triple Definition" strategy for schema changes. When adding a table or column:
- Update the `SCHEMA` constant in `apps/merchant/src/do.ts`.
- Add the creation logic to `ensureInitialized()` in the same file.
- Create a new SQL file in `apps/merchant/migrations/` (e.g., `019_add_new_feature.sql`).

### 2. Authentication & RBAC
- **Identity**: Auth0 is the source of truth.
- **Permissions**: Access control is handled via JWT claims (e.g., `admin:store`).
- **Visibility**: Frontend menu items are controlled by the `permissions` array in `siteConfig`.
- **API Keys**: Use `pk_` for storefront/public operations and `sk_` ONLY for backend-to-backend or legacy integrations. Never expose `sk_` keys in the frontend `.env`.

### 3. Internationalization (i18n)
Product titles, descriptions, and category names are stored as JSON maps in the database to support multilingual content.
- **Storage Format**: `{"en-US": "Hello", "fr-FR": "Bonjour"}`.
- **AI Translation**: The framework provides built-in hooks to translate these JSON objects using LLM providers (Groq/OpenAI/Anthropic) directly from the admin panel.

### 4. Deployment
The framework is fully automated via GitHub Actions:
- **`deploy-cloudflare-worker.yaml`**: Deploys the backend and applies migrations.
- **`pages.yaml`**: Builds and deploys the Vite SPA to GitHub Pages.
- **`reset-demo.yaml`**: A maintenance workflow for the public demo instance.

### 5. Universal Commerce Protocol (UCP)
Fufuni implements UCP to enable AI shopping. The Worker exposes a `.well-known/ucp` manifest and standardized `/ucp/v1/*` routes for browsing and checkouts. This allows shopping assistants to interact with the store without a traditional browser.

```typescript
// apps/merchant/src/routes/ucp.ts
// Example of a UCP-compliant capability response
export const ucp = new OpenAPIHono();

ucp.get('/.well-known/ucp', (c) => {
  return c.json({
    capabilities: [
      'dev.ucp.shopping.catalog',
      'dev.ucp.shopping.browse',
      'dev.ucp.shopping.checkout',
      'dev.ucp.shopping.order'
    ],
    links: {
      catalog: '/ucp/v1/products',
      categories: '/ucp/v1/categories'
    }
  });
});
```

## Development Workflow

To start the entire stack locally with hot-reloading:

```bash
# From the root of the monorepo
npm install
npm run dev:env
```

This command uses Turborepo to:
1. Load variables from the root `.env` file.
2. Start the Vite development server for the frontend (`localhost:5173`).
3. Start the Wrangler dev server for the Merchant Worker (`localhost:8787`).
4. Start the MCP server and inspector.
5. Launch the Stripe webhook listener (if Stripe CLI is installed).
