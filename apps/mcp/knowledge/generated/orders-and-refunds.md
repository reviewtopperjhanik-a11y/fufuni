## Order Lifecycle & Status Machine

The Fufuni order lifecycle is a linear progression for successful transactions, with branching paths for cancellations and refunds. Order statuses are strictly managed to ensure inventory consistency and financial auditing.

```text
       [ Checkout ]
            |
            v
      +-----------+         (Payment Failed)
      |  pending  | --------------------------+
      +-----------+                           |
            |                                 |
     (Stripe Webhook)                         v
            |                          +-----------+
            v                          |  canceled |
      +-----------+                    +-----------+
      |    paid   | <-------------------------+
      +-----------+             (Inventory Restored)
            |
            v
      +------------+
      | processing |
      +------------+
            |
            v
      +-----------+
      |  shipped  | ----> (Tracking link sent)
      +-----------+
            |
            v
      +-----------+
      | delivered |
      +-----------+
            |
            v
      +-----------+         (Full or Partial)
      |  refunded | <-------------------------+
      +-----------+                           |
                                       (Stripe Refund)
```

### Valid Transitions
- **Standard Flow**: `pending` → `paid` → `processing` → `shipped` → `delivered`.
- **Interruption**: Any post-paid status can transition to `refunded` or `partially_refunded`.
- **Abort**: `pending` or `paid` orders can be moved to `canceled`, which triggers inventory restoration.

## Updating Order Status

Administrative status updates are performed via the `PATCH` method. Updating a status to `shipped` triggers a transactional email to the customer containing their tracking information.

### Status Update Implementation
When updating to `shipped`, the system automatically captures the `shipped_at` timestamp if not already set.

```typescript
// Example: Updating an order to 'shipped' with tracking info
import { OpenAPIHono, createRoute } from '@hono/zod-openapi';
import { UpdateOrderBody, OrderIdParam } from '../schemas';
import { adminOnly } from '../middleware/auth';
import { now } from '../types';

// Route definition
const updateStatus = async (c: any) => {
  const { orderId } = c.req.valid('param');
  const { status, tracking_number, tracking_url } = c.req.valid('json');
  const db = c.var.db;

  const updates: string[] = ['status = ?', 'updated_at = ?'];
  const params: any[] = [status, now()];

  if (status === 'shipped') {
    updates.push('shipped_at = ?');
    params.push(now());
  }

  if (tracking_number) {
    updates.push('tracking_number = ?');
    params.push(tracking_number);
  }

  params.push(orderId);

  await db.run(
    `UPDATE orders SET ${updates.join(', ')} WHERE id = ?`,
    params
  );

  return c.json({ success: true });
};
```

## Refund Flow & Stripe Integration

Refunds in Fufuni are processed through Stripe and recorded in a dedicated `refunds` table for auditing. A refund can be partial or full.

1.  **Authorization Check**: Only orders in `paid`, `processing`, or `shipped` states can be refunded.
2.  **Stripe Transaction**: The backend calls the Stripe API using the `stripe_payment_intent_id`.
3.  **Database Audit**: A record is created in the `refunds` table containing the Stripe Refund ID and the reason.
4.  **Order State**: The order status is updated to `refunded` (if total amount is covered) or `partially_refunded`.

### Processing a Refund
```typescript
import Stripe from 'stripe';
import { ApiError, uuid, now } from '../types';

async function processOrderRefund(c: any, orderId: string, amount_cents?: number) {
  const db = c.var.db;
  const stripe = new Stripe(c.env.STRIPE_SECRET_KEY);

  const [order] = await db.query(
    `SELECT total_cents, stripe_payment_intent_id, currency FROM orders WHERE id = ?`, 
    [orderId]
  );

  if (!order.stripe_payment_intent_id) {
    throw ApiError.invalidRequest("No Stripe transaction found for this order");
  }

  const refund = await stripe.refunds.create({
    payment_intent: order.stripe_payment_intent_id,
    amount: amount_cents, // If undefined, Stripe performs a full refund
  });

  const refundId = uuid();
  await db.run(
    `INSERT INTO refunds (id, order_id, stripe_refund_id, amount_cents, status, created_at)
     VALUES (?, ?, ?, ?, ?, ?)`,
    [refundId, orderId, refund.id, refund.amount, refund.status, now()]
  );

  const newStatus = (amount_cents && amount_cents < order.total_cents) 
    ? 'partially_refunded' 
    : 'refunded';

  await db.run(`UPDATE orders SET status = ? WHERE id = ?`, [newStatus, orderId]);
  
  return { refundId, status: newStatus };
}
```

## Order Cancellation & Inventory Restore

Canceling an order is a critical operation because it must reverse the inventory deduction that occurred during checkout. This prevents "ghost" stock-outs.

### Cancellation Side Effect Logic
When an order is moved to `canceled`, the system iterates through all items in the `order_items` table and increments the `on_hand` count in the `inventory` table.

```typescript
// Implementation of PATCH /v1/orders/:id/cancel
async function cancelOrder(c: any, orderId: string) {
  const db = c.var.db;

  // 1. Verify current status
  const [order] = await db.query(`SELECT status FROM orders WHERE id = ?`, [orderId]);
  if (order.status === 'shipped' || order.status === 'delivered') {
    throw ApiError.badRequest("Cannot cancel an order that has already shipped.");
  }

  // 2. Get items to restore inventory
  const items = await db.query(
    `SELECT sku, qty FROM order_items WHERE order_id = ?`, 
    [orderId]
  );

  // 3. Update status and restore stock in a transaction-like sequence
  await db.run(`UPDATE orders SET status = 'canceled', updated_at = ? WHERE id = ?`, [now(), orderId]);

  for (const item of items) {
    await db.run(
      `UPDATE inventory SET on_hand = on_hand + ?, updated_at = ? WHERE sku = ?`,
      [item.qty, now(), item.sku]
    );
  }

  return { ok: true };
}
```

## CSV Exporting

Administrators can export order data for external accounting or shipping software. The endpoint filters by date range and returns a standard CSV file.

### Export Request Structure
The `from` and `to` parameters must be valid ISO 8601 strings.

```typescript
// Example: Frontend call to export CSV
async function downloadOrderExport(dateFrom: string, dateTo: string) {
  const response = await fetch(
    `/api/v1/orders?export=csv&from=${dateFrom}&to=${dateTo}`,
    {
      headers: {
        'Authorization': `Bearer ${adminToken}`
      }
    }
  );

  if (response.ok) {
    const blob = await response.blob();
    const url = window.URL.createObjectURL(blob);
    const a = document.createElement('a');
    a.href = url;
    a.download = `orders_${dateFrom}_to_${dateTo}.csv`;
    a.click();
  }
}
```

## Order Item Immutability

Fufuni enforces strict data capture at the moment of purchase. This is essential for historical accuracy. If a merchant changes a product's price or deletes a variant, the existing orders must remain unchanged.

### Data Capturing Strategy
The `order_items` table does not simply link to the `variants` table; it duplicates the critical fields:

- **unit_price_cents**: The price the customer actually paid.
- **sku**: The specific SKU at the time of purchase.
- **title**: The product/variant title (in case the product is renamed later).
- **tax_rate / tax_amount**: Captured to satisfy legal auditing requirements.

### Table Schema (Conceptual)
```sql
CREATE TABLE order_items (
  id TEXT PRIMARY KEY,
  order_id TEXT NOT NULL,
  variant_id TEXT, -- Reference for internal analytics
  sku TEXT NOT NULL, -- Captured
  title TEXT NOT NULL, -- Captured
  qty INTEGER NOT NULL,
  unit_price_cents INTEGER NOT NULL, -- Captured (Price of 1 unit)
  tax_amount_cents INTEGER DEFAULT 0, -- Captured
  currency TEXT NOT NULL, -- Captured
  FOREIGN KEY (order_id) REFERENCES orders(id)
);
```

By capturing these values, the `subtotal_cents` calculation of an order can always be reconstructed by summing `unit_price_cents * qty` for its items, regardless of current catalog prices.
