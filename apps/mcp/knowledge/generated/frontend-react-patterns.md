## Application Architecture & Providers

The Fufuni frontend is a React 19 application built with Vite, leveraging a strict provider hierarchy to manage state, themes, and commerce logic. The application entry point is wrapped in `Provider` (located in `apps/client/src/provider.tsx`), which enforces a specific stacking order for context providers.

The order of providers is critical for dependency resolution:
1.  **StoreThemeProvider**: Handles custom branding (colors, radiuses) fetched from the `store_themes` database table.
2.  **Toast.Provider**: The HeroUI toast notification system.
3.  **CartProvider**: Manages the local shopping cart state.
4.  **CartDrawerProvider**: Manages the global visibility of the cart sidebar, allowing components like `ProductCard` to trigger the drawer after an item is added.

```typescript
// apps/client/src/provider.tsx
import type React from "react";
import { Toast } from "@heroui/react";
import { CartProvider } from "@/hooks/use-cart";
import { CartDrawerProvider } from "@/contexts/cart-drawer-context";
import { StoreThemeProvider } from "@/providers/theme-provider";

export function Provider({ children }: { children: React.ReactNode }) {
  return (
    <StoreThemeProvider>
      <Toast.Provider />
      <CartProvider>
        <CartDrawerProvider>
          {children}
        </CartDrawerProvider>
      </CartProvider>
    </StoreThemeProvider>
  );
}
```

## Routing & Protection Patterns

Fufuni uses `react-router-dom` for navigation. Routes are defined in `apps/client/src/app.tsx`. We distinguish between three types of routes:
1.  **Public Routes**: Accessible to everyone (e.g., `/`, `/product/:id`).
2.  **Authenticated Routes**: Requires a valid session, managed by `<AuthenticationGuard />`.
3.  **Permissioned Routes**: Requires a specific Auth0 permission (e.g., `admin:store`), managed by `<AuthenticationGuardWithPermission />`.

### Protecting Routes

When adding an admin route, always wrap the component or the route element with the appropriate guard. 

```typescript
// apps/client/src/app.tsx snippet
import { AuthenticationGuard, AuthenticationGuardWithPermission } from "./authentication";
import ProductsPage from "@/pages/admin/products";
import AccountLayout from "@/pages/account/account-layout";

// Protected by Permission (Admin)
<Route
  element={
    <AuthenticationGuardWithPermission permission="admin:store">
      <ProductsPage />
    </AuthenticationGuardWithPermission>
  }
  path="/admin/products"
/>

// Protected by Auth Only (Customer Account)
<Route
  element={<AuthenticationGuard component={AccountLayout} />}
  path="/account"
/>
```

## Navigation & Permission Logic

The Navbar (`apps/client/src/components/navbar.tsx`) is dynamic. It retrieves configuration from `siteConfig()` and filters visibility based on the user's permissions.

### Site Configuration Structure

Navigation items are defined in `apps/client/src/config/site.ts`. Every item has a `permissions` array. If the array is empty `[]`, the item is public. If it contains `"admin:store"`, it will only appear in the admin dropdown if the user has that specific permission.

```typescript
// apps/client/src/config/site.ts entry
{
  label: i18next.t("admin-products-title"),
  href: "/admin/products",
  permissions: ["admin:store"], 
}
```

### Navbar Filtering Implementation

The navbar uses the `isAuthenticated` state and the `AuthenticationGuardWithPermission` component to decide what to render. Desktop admin items are grouped into a `Dropdown` specifically wrapped in a permission guard.

```typescript
// apps/client/src/components/navbar.tsx logic
<AuthenticationGuardWithPermission permission="admin:store">
  <li className="hidden lg:block">
    <Dropdown>
      <Dropdown.Trigger>
        {t("nav-admin")}
      </Dropdown.Trigger>
      <Dropdown.Popover>
        <Dropdown.Menu>
          {siteConfig().navItems
            .filter(item => item.permissions?.includes("admin:store"))
            .map((item) => (
              <Dropdown.Item key={item.href} onPress={() => navigate(item.href)}>
                {item.label}
              </Dropdown.Item>
          ))}
        </Dropdown.Menu>
      </Dropdown.Popover>
    </Dropdown>
  </li>
</AuthenticationGuardWithPermission>
```

## HeroUI v3 & Component Patterns

Fufuni strictly uses **HeroUI v3**. Unlike older versions, v3 relies heavily on the **compound component pattern**. You should always use the sub-component syntax (e.g., `Card.Header`, `Dropdown.Item`, `Modal.Content`).

### Common UI Components

-   **Buttons**: Use `variant="solid"`, `variant="ghost"`, or `variant="flat"`.
-   **Modals**: Controlled via `isOpen` and `onClose` props.
-   **ImageUploadInput**: A specialized Fufuni component that handles WebP conversion and R2/Base64 selection.

```typescript
// Example of a Standard HeroUI Modal pattern in Fufuni
import { Modal, Button, Input } from "@heroui/react";

export const EditTagModal = ({ isOpen, onClose }: { isOpen: boolean, onClose: () => void }) => {
  return (
    <Modal isOpen={isOpen} onClose={onClose}>
      <Modal.Content>
        <Modal.Header>Edit Product Tag</Modal.Header>
        <Modal.Body>
          <Input label="Tag Name" placeholder="e.g. New Arrival" />
        </Modal.Body>
        <Modal.Footer>
          <Button variant="ghost" onPress={onClose}>Cancel</Button>
          <Button color="primary" onPress={() => console.log('Saved')}>Save</Button>
        </Modal.Footer>
      </Modal.Content>
    </Modal>
  );
};
```

## Feature Folder Convention

Code should be organized by feature to maintain scalability. Avoid putting business logic in the `pages/` directory; pages should primarily compose feature components.

**Structure**:
- `apps/client/src/features/<feature-name>/components/`: Feature-specific UI.
- `apps/client/src/features/<feature-name>/hooks/`: Feature-specific logic (API calls using Fetch/Zod).
- `apps/client/src/features/<feature-name>/index.ts`: The public API for the feature.

**Hooks placement**:
- Use `apps/client/src/hooks/` for global commerce hooks (e.g., `use-cart.ts`, `use-seo-meta.ts`).
- Use feature hooks for domain-specific data (e.g., `use-products.ts`).

## Worked Example: Adding a "Product Tags" Admin Page

To add a new administrative interface for managing product tags, follow these three steps.

### Step 1: Create the Page Component

Create `apps/client/src/pages/admin/tags.tsx`. Use `useSeoMeta` to set the document title.

```typescript
import { useTranslation } from "react-i18next";
import { useSeoMeta } from "@/hooks/use-seo-meta";
import { Card, Table } from "@heroui/react";

export default function TagsPage() {
  const { t } = useTranslation();
  useSeoMeta({ title: `Admin - ${t("tags")}` });

  return (
    <div className="p-6">
      <h1 className="text-2xl font-bold mb-4">{t("tags")}</h1>
      <Card>
        <Card.Body>
          <Table aria-label="Product Tags Table">
            <Table.Header>
              <Table.Column>NAME</Table.Column>
              <Table.Column>ACTIONS</Table.Column>
            </Table.Header>
            <Table.Body>
              {/* Data mapping here */}
              <Table.Row key="1">
                <Table.Cell>Summer Collection</Table.Cell>
                <Table.Cell>Edit</Table.Cell>
              </Table.Row>
            </Table.Body>
          </Table>
        </Card.Body>
      </Card>
    </div>
  );
}
```

### Step 2: Register the Route

Add the route to `apps/client/src/app.tsx`. Since this is an admin page, protect it with the `ADMIN_STORE_PERMISSION`.

```typescript
import TagsPage from "@/pages/admin/tags";

// Inside <Routes>
<Route
  element={
    <AuthenticationGuardWithPermission permission={import.meta.env.ADMIN_STORE_PERMISSION}>
      <TagsPage />
    </AuthenticationGuardWithPermission>
  }
  path="/admin/tags"
/>
```

### Step 3: Add to Site Configuration

Add the link to the `navItems` in `apps/client/src/config/site.ts` so it appears in the Admin dropdown.

```typescript
// apps/client/src/config/site.ts
export const siteConfig = () => ({
  // ...
  navItems: [
    // ...
    {
      label: i18next.t("tags"),
      href: "/admin/tags",
      permissions: ["admin:store"],
    },
  ],
  // ...
});
```

## SEO and Metadata

For any user-facing page (Products, Collections, CMS), use the `useSeoMeta` hook. It manages the `<title>`, `<meta name="description">`, and Open Graph tags dynamically without requiring external libraries like `react-helmet`.

```typescript
// Example usage in a Product Page
import { useSeoMeta } from "@/hooks/use-seo-meta";

const ProductPage = ({ product }) => {
  useSeoMeta({
    title: product.name,
    description: product.description,
    ogImage: product.thumbnail_url,
    ogType: "product"
  });

  return (
    <main>
      <h1>{product.name}</h1>
    </main>
  );
};
```

## Image Handling

For administrative forms requiring images, use `ImageUploadInput`. It handles the complexity of file selection and optimization automatically. It supports both direct URL input and file uploads, converting images to WebP on the client side before submission.

```typescript
import { ImageUploadInput } from "@/components/image-upload-input";
import { useState } from "react";

export const ProductForm = () => {
  const [imageUrl, setImageUrl] = useState("");

  return (
    <ImageUploadInput
      label="Product Thumbnail"
      value={imageUrl}
      onChange={(newUrl) => setImageUrl(newUrl)}
    />
  );
};
```
