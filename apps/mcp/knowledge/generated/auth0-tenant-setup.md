## Purpose and Usage

The `deploy-tenant-resources.ts` script is a specialized utility designed to automate the configuration of an Auth0 tenant. In the Fufuni ecosystem, Auth0 acts as the central Identity Provider (IdP). Manually configuring clients, resource servers, and actions is error-prone; this script ensures that every environment (development, staging, production) adheres to the same security architecture.

You should run this script:
1. When setting up a brand new Auth0 tenant for a local development environment.
2. After adding new permission scopes to the API definition in the codebase.
3. When updating the allowed callback URLs or web origins for the frontend.

To execute the script from the monorepo root, use the following command:

```bash
# Execute the deployment script targeting a specific environment file
npm run auth0:deploy -- --env-file=.env.local
```

## Configured Resources

The script automates the creation and synchronization of four critical components within the Auth0 dashboard:

### 1. SPA Application Client
Configures a Single Page Application (SPA) client using Authorization Code Flow with PKCE. It automatically sets `callbacks`, `web_origins`, and `allowed_logout_urls` based on your `STORE_URL`.

### 2. API Resource Server
Registers the backend as a Resource Server (API). It defines the `audience` (the unique identifier for your API) and registers all required OAuth2 scopes.

### 3. Social Connections
Enables standard social login providers. By default, it attempts to enable `github`, `google-oauth2`, `windowslive`, and `apple`. Note that these must be configured with their respective Client IDs/Secrets in the Auth0 Dashboard to work in production.

### 4. The authadmin Role
Creates the high-level administrative role. This role is granted specific scopes that allow access to the Fufuni dashboard and the ability to interact with the Auth0 Management API via our backend proxy.

```typescript
// Example configuration block inside the script for the Resource Server
const api = await createOrUpdateResourceServer(auth0Domain, token, {
  name: `${tenant}-api`,
  identifier: audience,
  scopes: [
    { value: "admin:store", description: "Full access to store management" },
    { value: "auth0:admin:api", description: "Access to Management API proxy" },
    { value: "read:messages", description: "Read-only access to messages" }
  ],
  signing_alg: "RS256",
  allow_offline_access: true,
  token_dialect: "access_token_authz",
});
```

## Adding a New Permission Scope

Permissions in Fufuni are decentralized in logic but centralized in Auth0 configuration. To introduce a new permission (e.g., `refund:orders`), follow these four steps:

1.  **Update the Script**: Add the new scope to the `scopes` array within the `createOrUpdateResourceServer` call in `deploy-tenant-resources.ts`.
2.  **Push to Auth0**: Run `npm run auth0:deploy` to sync the new scope definition to the Auth0 Resource Server settings.
3.  **Update Role Grants**: If the permission is restricted to administrators, navigate to the Auth0 Dashboard > User Management > Roles > `authadmin` and add the new scope to its permissions.
4.  **Implement Guard**: Use the `hasPermission` helper in your React components to protect UI elements.

```typescript
// Step 4: Frontend Guard usage
import { useAuth0 } from "@auth0/auth0-react";
import { hasPermission } from "@/lib/auth-utils";

export const RefundButton = () => {
  const { user } = useAuth0();
  
  // Checks if 'refund:orders' is present in the user's permissions array
  if (!hasPermission(user, "refund:orders")) {
    return null;
  }

  return <button onClick={handleRefund}>Process Refund</button>;
};
```

## The authadmin Role

The `authadmin` role is the primary administrative identity within the Fufuni framework. It is designed to bridge the gap between frontend capabilities and backend administrative actions.

### Granted Permissions
-   `admin:store`: This is the master toggle for the Fufuni Dashboard. Without this scope, the backend will reject requests to `/admin/*` routes, and the frontend will redirect users away from management pages.
-   `auth0:admin:api`: This allows the backend to act as a proxy for the Auth0 Management API on behalf of the user (e.g., for inviting new staff members).

### Assigning the Role
Roles are assigned via the Auth0 Dashboard or via the Management API. Once assigned, the user's next login will trigger the inclusion of these scopes in their Access Token.

```typescript
// Backend Hono route protecting an admin endpoint
import { verifyPermission } from "@/middleware/auth";

app.get("/admin/stats", verifyPermission("admin:store"), async (c) => {
  const stats = await getStoreStats(c.env.DB);
  return c.json(stats);
});
```

## Management API Client vs. SPA Client

It is critical to distinguish between the two types of clients used in the framework:

### Management API Client (M2M)
-   **Identifier**: `AUTH0_MANAGEMENT_CLIENT_ID`
-   **Type**: Machine-to-Machine.
-   **Usage**: Only used by the `deploy-tenant-resources.ts` script and the backend Management API proxy.
-   **Security**: This client holds a `client_secret` and should **never** be exposed to the frontend.

### SPA Client (Public)
-   **Identifier**: `AUTH0_CLIENT_ID`
-   **Type**: Single Page Application.
-   **Usage**: Used by the React application to initiate login.
-   **Security**: Uses PKCE (Proof Key for Code Exchange). It does not have a secret because it runs in an untrusted environment (the browser).

## Login Post-Action

The `deploy-tenant-resources.ts` script automatically uploads a "Post-Login Action" to Auth0. This is a small Node.js script that runs on the Auth0 infrastructure immediately after a user successfully authenticates.

### Why it is needed
By default, Auth0 Access Tokens contain scopes, but ID Tokens (which the frontend uses for user profiles) do not necessarily contain a flattened list of permissions. The Fufuni action enriches the tokens by attaching the user's assigned permissions to a custom claim.

### How it works
The script looks for the `add-userinfo-to-access-jwt.js` file in the `auth0-code` directory and deploys it. This ensures that the frontend property `import.meta.env.PERMISSIONS` (or the equivalent dynamic user object) correctly reflects the scopes defined in the Auth0 tenant.

```javascript
/**
 * Logic inside auth0-code/add-userinfo-to-access-jwt.js
 * This runs inside Auth0's runtime.
 */
exports.onExecutePostLogin = async (event, api) => {
  const namespace = 'https://fufuni.com';
  if (event.authorization) {
    // Add permissions to the ID Token so the frontend can read them easily
    api.idToken.setCustomClaim(`${namespace}/permissions`, event.authorization.permissions);
    // Also ensure they are in the Access Token for backend validation
    api.accessToken.setCustomClaim(`${namespace}/permissions`, event.authorization.permissions);
  }
};
```

This mechanism allows the frontend to perform instantaneous UI state changes (hiding/showing buttons) based on permissions without needing a separate API call to fetch user roles.
