## Purpose and Execution

The `deploy-tenant-resources.ts` script is a one-shot automated setup tool designed to synchronize your local Auth0 configuration with the Auth0 Management API. You should run this script whenever you initialize a new Auth0 tenant for a project or whenever you need to update the permission scopes, application settings, or post-login actions across the infrastructure.

Within the Fufuni monorepo, the script is typically executed via a dedicated npm command. It handles the idempotent creation and updating of all necessary cloud resources to ensure the backend and frontend are aligned.

```bash
# Run the deployment script using the environment variables from .env.local
npm run auth0:deploy -- --env-file=.env.local
```

If the script detects missing environment variables, it will enter an interactive mode in the terminal to prompt you for the necessary IDs and secrets, offering to save them back to your `.env` file upon completion.

## Resource Configuration

The script configures four primary pillars of the Auth0 tenant:

### 1. SPA Application Client
It sets up a Single Page Application (SPA) entry. This client is configured for PKCE (Proof Key for Code Exchange) and defines the `callbacks`, `web_origins`, and `allowed_logout_urls` based on your `STORE_URL` and `localhost:5173`.

### 2. API Resource Server
It defines the "Audience" for your backend. This represents your Hono API. The script ensures all required permission scopes (e.g., `read:messages`, `admin:store`) are registered here so they can be requested by the frontend.

### 3. Social Connections
The script iterates through a list of standard providers—`github`, `google-oauth2`, `apple`, and `windowslive`—and automatically enables them for the newly created SPA client, provided they are configured in the tenant.

### 4. The authadmin Role
It ensures a specialized role exists for administrative access. This role is mapped to specific scopes that allow users to manage the store and interact with the Management API proxy.

```typescript
// Example configuration for the SPA client within the script
const clientConfig = {
  name: "Fufuni Storefront",
  app_type: "spa",
  grant_types: ["authorization_code", "refresh_token"],
  callbacks: ["http://localhost:5173/", "https://store.fufuni.dev/"],
  web_origins: ["http://localhost:5173/", "https://store.fufuni.dev/"],
  token_endpoint_auth_method: "none", // Required for SPAs (Public Client)
  oidc_conformant: true,
};
```

## Required Environment Variables

The script requires specific credentials to authenticate with the Auth0 Management API. These are different from the keys used to log users in.

| Variable | Description |
| :--- | :--- |
| `AUTH0_DOMAIN` | Your Auth0 tenant domain (e.g., `dev-xyz.eu.auth0.com`). |
| `AUTH0_TENANT` | The short name of your tenant, used for resource naming. |
| `AUTH0_MANAGEMENT_API_CLIENT_ID` | The Client ID of a "Machine to Machine" app with Management API access. |
| `AUTH0_MANAGEMENT_API_CLIENT_SECRET` | The Secret for the Management API client. |
| `AUTH0_AUDIENCE` | The unique identifier for your API (e.g., `https://api.fufuni.com/`). |
| `STORE_URL` | The base URL of your frontend, used for callback registration. |

## Adding a New Permission Scope

To introduce a new permission (e.g., `manage:inventory`) to the ecosystem, follow these four steps:

1.  **Modify the Script**: Add the new scope to the `scopes` array in the `createOrUpdateResourceServer` call within `deploy-tenant-resources.ts`.
2.  **Redeploy**: Run `npm run auth0:deploy` to push the updated scope definition to the Auth0 Dashboard.
3.  **Grant to Roles**: If the scope is restricted to admins, add it to the `authadmin` role grants within the script or manually in the Auth0 Dashboard.
4.  **Implement Guard**: Use the `hasPermission` utility in your React components to protect the UI.

```typescript
// Step 1: Update scripts/auth0/deploy-tenant-resources.ts
const api = await createOrUpdateResourceServer(auth0Domain, token, {
  name: `${tenant}-api`,
  identifier: audience,
  scopes: [
    { value: "read:messages", description: "Read messages" },
    { value: "manage:inventory", description: "Create/Edit/Delete Products" }, // New scope
  ],
  // ... other config
});
```

## The authadmin Role

The `authadmin` role is the primary administrative entity in the Fufuni framework. Users assigned this role are granted elevated privileges across both the frontend and backend.

### Permissions Granted
-   `admin:store`: Allows access to the administrative dashboard and protected store settings.
-   `auth0:admin:api`: Specifically used by the backend to proxy requests to the Auth0 Management API (e.g., for user management).

### Assigning the Role
Assigning roles is performed in the Auth0 Dashboard under **User Management > Users**. Select a user, navigate to the **Roles** tab, and click **Assign Roles**. Once assigned, the user must re-log to receive a new token containing these permissions.

## Management API Client vs. SPA Client

It is critical to distinguish between these two clients to avoid security vulnerabilities.

### Management API Client (`M2M`)
-   **Used by**: The `deploy-tenant-resources.ts` script and the backend API.
-   **Capability**: Can read/write all tenant settings, delete users, and change client secrets.
-   **Security**: Must **never** be exposed to the frontend. The `CLIENT_SECRET` is highly sensitive.

### SPA Client (`Public`)
-   **Used by**: React 19 Frontend.
-   **Capability**: Can only initiate the login flow via PKCE.
-   **Security**: Has no `CLIENT_SECRET`. It is identified only by its `CLIENT_ID`.

```typescript
// frontend/src/auth-config.ts
// Use the SPA Client ID here
export const authConfig = {
  domain: import.meta.env.VITE_AUTH0_DOMAIN,
  clientId: import.meta.env.VITE_AUTH0_CLIENT_ID, // This is the SPA ID
  authorizationParams: {
    audience: import.meta.env.VITE_AUTH0_AUDIENCE,
    redirect_uri: window.location.origin,
  },
};
```

## Login Post-Action and Permission Guards

The deployment script automatically installs a "Post-Login" Action named `Add Userinfo to jwt`. This script runs on Auth0's servers immediately after a user successfully authenticates.

### Why it is needed
By default, Auth0 does not include user permissions in the ID Token. The Fufuni frontend requires these permissions to determine which UI elements to show or hide without making additional API calls. The Action enriches the token by injecting a custom claim containing the user's permissions array.

### Frontend Implementation
The frontend compares the permissions found in the token against the required scopes for a component.

```tsx
import { useAuth } from "@/hooks/use-auth";
import { Button } from "@heroui/react";

export const DeleteProductButton = () => {
  const { hasPermission } = useAuth();

  // If the Action correctly enriched the token, hasPermission will find "manage:inventory"
  if (!hasPermission("manage:inventory")) {
    return null;
  }

  return (
    <Button color="danger" onPress={() => console.log("Deleting...")}>
      Delete Product
    </Button>
  );
};
```

### The Action Code (Internal)
The script uploaded by the deployer looks like this:

```javascript
/**
 * Handler that will be called during the execution of a PostLogin flow.
 */
exports.onExecutePostLogin = async (event, api) => {
  const namespace = 'https://fufuni.dev/';
  if (event.authorization) {
    // Add permissions to the ID token for frontend usage
    api.idToken.setCustomClaim(`${namespace}permissions`, event.authorization.permissions);
    // Add permissions to the Access token for backend validation
    api.accessToken.setCustomClaim(`${namespace}permissions`, event.authorization.permissions);
  }
};
```
