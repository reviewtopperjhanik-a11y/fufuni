## Import path

To utilize authenticated API calls within the Fufuni frontend, you must import the hook from the central authentication feature.

```typescript
import { useSecuredApi } from "@/features/auth/components/auth-components";
```

## Hook return values

The `useSecuredApi` hook returns an object containing methods for HTTP operations and permission verification. These methods automatically handle the acquisition and injection of the Auth0 JWT Bearer token.

| Method | Signature | When to use |
| :--- | :--- | :--- |
| `getJson` | `(url: string) => Promise<any>` | Authenticated GET requests that return JSON data (e.g., fetching user orders). |
| `postJson` | `(url: string, body: any) => Promise<any>` | Authenticated POST requests with a JSON payload (e.g., creating a product). |
| `putJson` | `(url: string, body: any) => Promise<any>` | Authenticated PUT requests for full resource replacement. |
| `patchJson` | `(url: string, body: any) => Promise<any>` | Authenticated PATCH requests for partial resource updates. |
| `deleteJson` | `(url: string) => Promise<any>` | Authenticated DELETE requests (e.g., removing an item from a catalog). |
| `postForm` | `(url: string, formData: FormData) => Promise<any>` | Authenticated POST requests for `multipart/form-data` (e.g., image uploads). |
| `hasPermission` | `(permission: string) => Promise<boolean>` | Asynchronous check to see if the current user possesses a specific Auth0 scope. |

## Automatic JWT Bearer token injection

The core benefit of `useSecuredApi` is the abstraction of identity management. In a standard Fufuni implementation, the backend (Hono + Zod-OpenAPI) protects routes using the `jwt` middleware.

When you call any method from this hook:
1. The hook calls the underlying `useAuth` provider.
2. It retrieves a fresh Access Token from the Auth0 SDK.
3. It attaches the token to the request using the `Authorization: Bearer <token>` header.
4. It sets the `Content-Type` to `application/json` automatically (except for `postForm`).

You should **never** manually set the `Authorization` header when communicating with the Fufuni backend.

## Authenticated request examples

The following examples demonstrate how to use the hook within React 19 functional components, utilizing the standard `API_BASE_URL` environment variable.

### GET: Fetching protected data
In this example, we fetch the AI parameters needed for client-side inference.

```typescript
import { useEffect, useState } from "react";
import { useSecuredApi } from "@/features/auth/components/auth-components";
import { SiteLoading } from "@/shared/ui/feedback/site-loading";

export const AIConfigPanel = () => {
  const { getJson } = useSecuredApi();
  const [config, setConfig] = useState<{ apiKey: string; model: string } | null>(null);

  useEffect(() => {
    const fetchAIConfig = async () => {
      const apiBase = import.meta.env.VITE_API_BASE_URL || "";
      // getJson automatically adds the Bearer token
      const data = await getJson(`${apiBase}/v1/ai/parameters`);
      setConfig(data);
    };
    fetchAIConfig();
  }, [getJson]);

  if (!config) return <SiteLoading />;

  return (
    <div className="p-4 border rounded-lg">
      <h3>AI Configuration Loaded</h3>
      <p>Model: {config.model}</p>
    </div>
  );
};
```

### POST: Creating a new resource
This example shows how to send a JSON body to a protected endpoint.

```typescript
import { Button } from "@heroui/react";
import { useSecuredApi } from "@/features/auth/components/auth-components";
import { toast } from "sonner";

export const CreateCategoryButton = ({ name }: { name: string }) => {
  const { postJson } = useSecuredApi();

  const handleCreate = async () => {
    try {
      const apiBase = import.meta.env.VITE_API_BASE_URL || "";
      await postJson(`${apiBase}/v1/categories`, { name });
      toast.success("Category created successfully");
    } catch (error) {
      toast.error("Failed to create category");
      console.error(error);
    }
  };

  return (
    <Button color="primary" onPress={handleCreate}>
      Create Category
    </Button>
  );
};
```

### DELETE: Removing a resource
Using `deleteJson` for administrative actions.

```typescript
import { Button } from "@heroui/react";
import { useSecuredApi } from "@/features/auth/components/auth-components";

export const DeleteProductButton = ({ productId }: { productId: string }) => {
  const { deleteJson } = useSecuredApi();

  const handleDelete = async () => {
    if (window.confirm("Are you sure?")) {
      const apiBase = import.meta.env.VITE_API_BASE_URL || "";
      await deleteJson(`${apiBase}/v1/products/${productId}`);
      window.location.reload();
    }
  };

  return (
    <Button color="danger" variant="flat" onPress={handleDelete}>
      Delete Product
    </Button>
  );
};
```

## Permission-based UI guarding

The `hasPermission` method is essential for conditional rendering. Since it is asynchronous (it may need to parse the JWT or wait for the Auth0 client), it should be used within a `useEffect` or a specialized guard component.

```typescript
import { useEffect, useState, ReactNode } from "react";
import { useSecuredApi } from "@/features/auth/components/auth-components";

interface AdminGuardProps {
  children: ReactNode;
  permission: string;
}

export const AdminGuard = ({ children, permission }: AdminGuardProps) => {
  const { hasPermission } = useSecuredApi();
  const [isAllowed, setIsAllowed] = useState<boolean | null>(null);

  useEffect(() => {
    const verify = async () => {
      const result = await hasPermission(permission);
      setIsAllowed(result);
    };
    verify();
  }, [permission, hasPermission]);

  if (isAllowed === null) return null; // Or a skeleton/spinner
  if (isAllowed === false) return null;

  return <>{children}</>;
};

// Usage in a component:
// <AdminGuard permission="products:delete">
//    <DeleteProductButton productId="123" />
// </AdminGuard>
```

## When NOT to use this hook

The `useSecuredApi` hook is strictly for **authenticated** requests. You should avoid using it in the following scenarios:

1.  **Public Endpoints:** For routes that do not require a login (e.g., `GET /v1/products` for public browsing), use standard `fetch()` or a wrapper that does not include credentials. Including a Bearer token on public routes can lead to unnecessary processing on the Cloudflare Worker or Auth0 validation errors if the token is expired.
2.  **External APIs:** Do not use `getJson` or `postJson` to call third-party APIs (like Stripe or a custom CMS) unless those APIs specifically use your Auth0 JWT for authentication.
3.  **Static Assets:** Do not use this for fetching images, CSS, or static JSON files from a CDN.

## Auth0 Management helpers

The hook provides several helper methods for interacting with the Auth0 Management API via the Fufuni worker proxy. These are typically reserved for administrative dashboards and require the `auth0:admin:api` permission.

### Helper methods list

| Method | Use Case |
| :--- | :--- |
| `getAuth0ManagementToken()` | Fetches a Management API token from the Fufuni worker (uses KV caching). |
| `listAuth0Users(token)` | Retrieves the list of all registered users in the Auth0 tenant. |
| `getUserPermissions(token, userId)` | Lists the specific permissions assigned to a user. |
| `addPermissionToUser(...)` | Dynamically assigns a scope to a user (e.g., promoting a user to moderator). |
| `removePermissionFromUser(...)` | Revokes a permission from a user. |
| `deleteAuth0User(token, userId)` | Permanently deletes a user from the Auth0 database. |
| `getResourceServerScopes(...)` | Checks the available scopes defined for the API audience. |

### Example: Syncing API Scopes
This is used in the Developer Settings panel to ensure the Auth0 dashboard matches the local Zod-OpenAPI definitions.

```typescript
const syncScopes = async () => {
  const { getAuth0ManagementToken, updateResourceServerScopesWithAudience } = useSecuredApi();
  
  const tokenResp = await getAuth0ManagementToken();
  const mgmtToken = tokenResp.access_token;
  
  const targetScopes = [
    { value: "products:read", description: "Read products" },
    { value: "products:write", description: "Create/Update products" }
  ];

  await updateResourceServerScopesWithAudience(
    mgmtToken,
    import.meta.env.VITE_AUTH0_AUDIENCE,
    targetScopes
  );
};
```

Note that the `getAuth0ManagementToken` call invokes the `/v1/__auth0/token` endpoint on your backend, which utilizes the `AUTH0_CLIENT_ID` and `AUTH0_CLIENT_SECRET` stored in your Cloudflare Worker variables to securely obtain a machine-to-machine token.
