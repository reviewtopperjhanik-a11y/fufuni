## Durable Object Persistence Pattern

Fufuni leverages the Cloudflare Durable Objects SQLite storage to provide a strongly consistent, relational database per merchant. Unlike traditional Worker KV or standard Durable Object `storage.put()` operations, Fufuni treats the Durable Object as a stateful SQL engine.

The core of this architecture is the `ensureInitialized()` method within the `MerchantDO` class. This method is called at the beginning of every `fetch` request. It performs two critical tasks:
1. **Schema Bootstrapping**: It executes a large `SCHEMA` constant containing `CREATE TABLE IF NOT EXISTS` statements. This ensures the foundational structure is present.
2. **Runtime Migrations**: It checks a local `migrations` table to see which incremental updates have been applied. If a migration is missing, it executes the corresponding SQL and records the success. This approach avoids the need for external migration tools or `db_version` flags in metadata.

Since Fufuni does not use an ORM like Drizzle or Prisma, all interactions are performed via raw SQL strings. The backend Hono routes access this via a `getDb(c)` helper, which proxies calls to the Durable Object's `query` and `run` methods.

```typescript
// Example of how a backend route interacts with the DO SQLite storage
import { Hono } from 'hono';
import { getDb } from '@/lib/db';

const app = new Hono();

app.get('/products/:id', async (c) => {
  const db = getDb(c);
  const productId = c.req.param('id');
  
  // Fufuni uses raw SQL strings and typed query results
  const products = await db.query<{ title: string; handle: string }>(
    'SELECT title, handle FROM products WHERE id = ?',
    [productId]
  );

  if (products.length === 0) return c.notFound();
  return c.json(products[0]);
});
```

### Key Constraints
- **Foreign Keys**: While SQLite supports foreign keys, they must be enabled via `PRAGMA foreign_keys = ON`. The Fufuni schema uses `REFERENCES` syntax extensively to maintain integrity for orders, variants, and categories.
- **Unique Indexes**: Product `handle`, Variant `sku`, and Order `number` are strictly unique. `viewtoken` is also uniquely indexed to allow secure public access to order status without authentication.
- **Check Constraints**: Used heavily in `status` columns (e.g., `CHECK (status IN ('active', 'draft'))`) and `reason` columns to enforce data quality at the database level.

```typescript
// Schema-safe way to update a product handle (must handle potential collision)
async function updateProductHandle(db: Database, id: string, newHandle: string) {
  try {
    await db.run('UPDATE products SET handle = ? WHERE id = ?', [newHandle, id]);
    return { success: true };
  } catch (e: any) {
    if (e.message.includes('UNIQUE constraint failed')) {
      return { success: false, error: 'Handle already in use' };
    }
    throw e;
  }
}
```
