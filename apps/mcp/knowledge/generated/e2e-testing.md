## E2E Project Structure

The Fufuni framework uses Playwright for end-to-end testing, located in the `e2e/` directory at the monorepo root. This suite validates the integration between the React frontend, the Cloudflare Worker backend, and the SQLite storage (Durable Objects).

```bash
e2e/
├── fixtures/               # Persistent authentication states (JSON)
├── tests/
│   ├── admin/              # Tests requiring admin permissions
│   ├── auth/               # Tests requiring a standard logged-in user
│   ├── public/             # Tests for anonymous visitors
│   └── setup/              # Setup scripts for authenticating and saving state
├── playwright.config.ts    # Global configuration
└── package.json            # E2E-specific dependencies
```

Fufuni manages three distinct authentication states to avoid repeated login overhead during test runs:
1.  **Anonymous**: Default state (no storage state applied).
2.  **Standard User**: Located in `e2e/fixtures/storage-state-user.json`. Used for checkout and profile tests.
3.  **Admin**: Located in `e2e/fixtures/storage-state-admin.json`. Used for CRUD operations on categories and products.

### Storage State Configuration Example
The `playwright.config.ts` file maps these states to specific test projects:

```typescript
// e2e/playwright.config.ts snippet
{
  name: "auth-admin",
  use: {
    ...devices["Desktop Chrome"],
    // Automatically injects cookies and localStorage for every test in this project
    storageState: "./fixtures/storage-state-admin.json",
  },
  testMatch: "**/admin/**/*.spec.ts",
  dependencies: ["setup-admin"], // Ensures credentials are valid before running
}
```

## Running E2E Tests

Before running tests, ensure the development environment is active. Playwright expects the frontend (Vite) and backend (Wrangler/Miniflare) to be reachable.

### Prerequisites
- Create a `.env` file in the monorepo root (not committed).
- Populate it with test credentials:
```bash
# Credentials for the setup scripts
E2E_USER_EMAIL=test-user@example.com
E2E_USER_PASSWORD=YourSecurePassword123
E2E_ADMIN_EMAIL=admin-user@example.com
E2E_ADMIN_PASSWORD=AdminSecurePassword456

# Target URLs
VITE_APP_URL=http://localhost:5173
PLAYWRIGHT_API_BASE_URL=http://localhost:8787
```

### Execution Commands
Run these commands from the monorepo root:

```bash
# Run all tests in headless mode
npm run e2e

# Run tests with the Playwright UI (best for debugging)
npx playwright test --ui

# Run a specific category
npx playwright test tests/admin/
```

## Authentication Setup Logic

Fufuni uses **Auth0 Universal Login**. The setup scripts under `e2e/tests/setup/` automate the login flow on the real Auth0 hosted page. This is preferred over API login to test the actual user journey and ensure CSRF/Cookie configurations are correct.

### Automating the Auth0 Flow
The setup script navigates to the app, triggers login, fills the Auth0-hosted form, and saves the resulting tokens to a JSON fixture.

```typescript
// e2e/tests/setup/admin.setup.ts
import { test as setup, expect } from "@playwright/test";
import * as path from "path";

const STORAGE_STATE = path.join(__dirname, "../../fixtures/storage-state-admin.json");

setup("authenticate as admin", async ({ page }) => {
  // 1. Navigate to the app and click Login
  await page.goto("/");
  await page.getByRole("button", { name: /login|connexion/i }).click();

  // 2. Wait for Auth0 redirection and fill credentials
  // Auth0 uses specific input names for email/password
  await page.waitForURL(/auth0\.com/);
  await page.locator('input[name="username"]').fill(process.env.E2E_ADMIN_EMAIL!);
  await page.locator('input[name="password"]').fill(process.env.E2E_ADMIN_PASSWORD!);
  await page.getByRole("button", { name: /continue/i }).click();

  // 3. Return to app and wait for auth synchronization
  await page.waitForURL(process.env.VITE_APP_URL!);
  await expect(page.getByRole("button", { name: /logout|déconnexion/i })).toBeVisible();

  // 4. Persist tokens (localStorage and Cookies)
  await page.context().storageState({ path: STORAGE_STATE });
});
```

## Creating a New Test Spec

When adding a new feature, place the spec file in the category that matches its permission requirements.

### Standard Template for an Admin Test
Admin tests must use the `auth-admin` project configuration. By default, Fufuni uses an ARIA-first selection strategy.

```typescript
// e2e/tests/admin/product-management.spec.ts
import { test, expect } from "@playwright/test";

test.describe("Product Management", () => {
  test.beforeEach(async ({ page }) => {
    // Navigate directly to the management sub-page
    await page.goto("/admin/products");
  });

  test("should display the product list", async ({ page }) => {
    // Use getByRole for accessibility-compliant testing
    const table = page.getByRole("grid");
    await expect(table).toBeVisible();
    
    // Check for specific UI components from HeroUI
    await expect(page.getByRole("button", { name: /create product/i })).toBeEnabled();
  });
});
```

## Test Categories and Conventions

### 1. Public Tests (`/public`)
Focus on SEO, landing pages, and the Product Detail Page (PDP).
- **Convention**: Use anonymous state.
- **Critical check**: Ensure `robots.txt` and sitemaps are reachable if the API URL is provided.

### 2. Auth Tests (`/auth`)
Focus on the shopping cart, checkout redirection, and user profile.
- **Stripe Logic**: Fufuni redirects to `checkout.stripe.com`. Do not attempt to fill credit card details unless testing on a Stripe-specific domain context (which is typically avoided in smoke tests).
- **Convention**: Verify the redirection URL contains `stripe.com`.

### 3. Admin Tests (`/admin`)
Focus on CRUD (Create, Read, Update, Delete) of the catalog.
- **Convention**: Each test must clean up. If you create a product, you must delete it in the same test or a `following` test to keep the SQLite database clean for the next run.

## Cleanup Discipline

Because Fufuni's backend uses a persistent SQLite database (Durable Objects) during development, orphaned test data can break future assertions (e.g., unique handle collisions).

### Reliable Cleanup Pattern
Use unique timestamps for handles and ensure the deletion step is triggered even if assertions fail.

```typescript
// e2e/tests/admin/admin-crud.spec.ts
const TEST_ID = `test-${Date.now()}`;

test("Create and Cleanup Category", async ({ page }) => {
  await page.goto("/admin/categories");

  // Create
  await page.getByRole("button", { name: /create/i }).click();
  await page.locator('input[name="handle"]').fill(TEST_ID);
  await page.getByRole("button", { name: /^submit$/i }).click();

  // Verify
  await expect(page.getByText(TEST_ID)).toBeVisible();

  // Cleanup (Crucial for Fufuni CI)
  const row = page.getByRole("row").filter({ hasText: TEST_ID });
  await row.locator('[title="Delete"]').click();
  await page.getByRole("button", { name: /confirm/i }).click();
  
  await expect(page.getByText(TEST_ID)).not.toBeVisible();
});
```

## CI Integration

In the GitHub Actions pipeline (`.github/workflows/e2e.yml`), the E2E suite runs after a successful build and deployment to a preview environment or a local action runner.

### Environment Injection
The CI environment provides secrets that are injected into the Playwright runtime:
- `PLAYWRIGHT_BASE_URL`: The URL of the frontend (e.g., a Cloudflare Pages preview).
- `PLAYWRIGHT_API_BASE_URL`: The URL of the worker (e.g., a branch-specific worker).

### Reporter Output
Fufuni is configured to produce multiple reports:
1.  **HTML**: Uploaded as a workflow artifact.
2.  **GitHub**: Summaries appear directly in the PR's "Checks" tab.
3.  **Video/Trace**: Retained only on failure to minimize CI storage usage.

```typescript
// playwright.config.ts reporter config
reporter: [
  ["html", { outputFolder: "../playwright-report" }],
  ["github"],
  ["list"],
],
use: {
  trace: "on-first-retry",
  screenshot: "only-on-failure",
  video: "retain-on-failure",
}
```

### Static Page Verification
The framework includes a loop to verify all core static pages defined in the CMS to ensure the routing table is correctly generated:

```typescript
test("Static pages accessibility", async ({ page }) => {
  const routes = ["/pages/about", "/pages/faq", "/pages/privacy"];
  for (const route of routes) {
    const response = await page.goto(route);
    expect(response?.status()).toBe(200);
    await expect(page.locator("main")).not.toBeEmpty();
  }
});
```
