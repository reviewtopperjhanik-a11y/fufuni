## MCP Server Architecture and AI Integration

The Fufuni Model Context Protocol (MCP) server acts as a structured bridge between the codebase's internal architecture and AI assistants (like Claude Desktop, Cursor, or specialized IDE agents). Unlike raw context windows, the MCP server provides a curated, high-density knowledge base that allows an AI to understand the "why" and "how" of the Fufuni framework—such as Durable Object patterns or Hono + Zod-OpenAPI integrations—without needing to index the entire repository.

AI assistants consume this knowledge through a `get_knowledge` tool. When a developer asks an AI about Fufuni conventions, the agent calls the MCP server, which returns pre-processed, LLM-optimized Markdown documentation derived from the actual source code.

### MCP Component Overview

The server operates in two main modes:
1.  **Cloudflare Workers:** Deployed at the edge for centralized team access.
2.  **Stdio Mode:** Run locally for private development or integration with Claude Desktop.

```typescript
// Example: How the MCP server exposes the knowledge tool (internal src/index.ts snippet)
import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";
import { knowledge } from "./knowledge.js"; // This is the auto-generated module

const server = new McpServer({
  name: "fufuni-knowledge",
  version: "1.0.0",
});

server.tool("get_knowledge", "Retrieves documentation for specific Fufuni topics", async () => {
  return {
    content: knowledge.map(k => ({
      type: "text",
      text: `### ${k.title}\n${k.content}`
    }))
  };
});
```

## Adding a New Topic Definition

To extend the knowledge base, you must create a new file in `apps/mcp/knowledge/topics/`. The generator automatically discovers these files alphabetically. You must never edit `apps/mcp/src/knowledge.ts` directly; it is overwritten every time the build pipeline runs.

### Topic Creation Template

Create a file named `apps/mcp/knowledge/topics/my-topic.ts`. The filename (minus the extension) serves as the unique identifier for the topic.

```typescript
/**
 * Copyright (c) 2026 Ronan LE MEILLAT - SCTG Development / License: AGPL-3.0-or-later
 */
import { Topic, BASE_SYSTEM, appendFacts } from "../base.js";

// Define facts that are absolutely true and must override source code observations
const MANUAL_FACTS = `
- All Durable Objects must use the 'sqlite' storage backend.
- Hono routes must always be exported via 'export const route = ...' for OpenAPI discovery.
`;

const topic: Topic = {
  name: "hono-api-conventions", // Should match filename
  description: "Guidelines for writing Zod-OpenAPI routes and Hono handlers in Fufuni.",
  sources: [
    "apps/backend/src/index.ts",
    "apps/backend/src/routes/products.ts",
  ],
  systemPrompt: appendFacts(BASE_SYSTEM, MANUAL_FACTS),
  maxSourceChars: 60000,
  buildPrompt: (concatenatedSources: string) => `
    Review the following source code examples from the Fufuni backend:
    
    ${concatenatedSources}
    
    Task: Write a technical guide for junior developers on how to implement 
    a new API endpoint. Focus on Zod schema validation and response types.
    Ensure code snippets use the project's standard imports.
  `,
};

export default topic;
```

## The Topic Interface Specification

The `Topic` interface is the contract between your documentation intent and the generator.

| Field | Type | Description |
| :--- | :--- | :--- |
| `name` | `string` | The title of the topic. Used as the MD file name. |
| `description` | `string` | A single sentence describing what this knowledge covers. |
| `sources` | `string[]` | Array of paths relative to the repository root. The generator reads these files. |
| `systemPrompt` | `string` | The instruction set for the LLM generating the Markdown. Use `BASE_SYSTEM`. |
| `manualFacts` | `string?` | Optional string of "Verified Facts" to ground the LLM. |
| `buildPrompt` | `Function` | A function receiving the combined content of all `sources`. Must return the final prompt. |
| `maxSourceChars` | `number` | Optional limit for source text to prevent context window overflow (Default: 50,000). |

### Example: Using manualFacts for grounding
```typescript
const topic: Topic = {
  name: "durable-objects",
  description: "Handling state with SQLite inside Cloudflare Durable Objects.",
  sources: ["apps/backend/src/db/schema.ts"],
  manualFacts: "Fufuni uses Drizzle ORM strictly with the 'durable-sqlite' driver.",
  buildPrompt: (code) => `Analyze the schema: ${code}. Explain the migration flow.`,
  systemPrompt: BASE_SYSTEM,
};
```

## Generation Commands and Environment

The Fufuni MCP server uses an LLM (typically via the Cloudflare AI Gateway or OpenAI) to synthesize the documentation. You must configure your environment before running the generation.

### Required Environment Variables
Create a `.env` in the root or export these:
- `AI_API_KEY`: Your provider key.
- `AI_API_URL`: The endpoint (e.g., Cloudflare Workers AI or OpenAI).
- `AI_MODEL`: The model ID (e.g., `@cf/meta/llama-3.1-70b-instruct`).

### Command Reference

| Command | Action |
| :--- | :--- |
| `npm run mcp:generate` | Runs `generate.ts`. It checks hashes of source files; if unchanged, it uses the cached `.md` in `/mcp/`. |
| `npm run mcp:generate:force` | Bypasses caching and regenerates every topic by calling the LLM API for all files. |
| `npm run mcp:auto` | The standard workflow: runs `mcp:generate` then executes `gen-knowledge.ts` to publish changes. |

### The Publishing Script (`gen-knowledge.ts`)
This script bridges the gap between the generated `.md` files and the runtime. It performs the following:
1.  Scans the `mcp/` directory at the repo root.
2.  Reads every `.md` file.
3.  Escapes the content and wraps it in a TypeScript array.
4.  Writes the result to `apps/mcp/src/knowledge.ts`.

```typescript
// Simplified view of what gen-knowledge.ts produces in apps/mcp/src/knowledge.ts
export const knowledge = [
  {
    title: "hono-api-conventions",
    content: "### Introduction\nFufuni uses Hono..." 
  },
  // ... more topics
];
```

## Running the MCP Server Locally (Stdio Mode)

To test your new knowledge topic before deploying it to a Cloudflare Worker, you can run the server in `stdio` mode and connect it to the Claude Desktop app.

### Step 1: Start the server via npx
```bash
# Run from the repository root
npx tsx apps/mcp/src/stdio.ts
```

### Step 2: Configure Claude Desktop
Edit your `claude_desktop_config.json` (typically found in `~/Library/Application Support/Claude/` on macOS or `%APPDATA%\Claude\` on Windows):

```json
{
  "mcpServers": {
    "fufuni-local": {
      "command": "npx",
      "args": [
        "tsx",
        "/path/to/fufuni/apps/mcp/src/stdio.ts"
      ],
      "env": {
        "AI_API_KEY": "your_key",
        "AI_MODEL": "@cf/meta/llama-3.1-70b-instruct"
      }
    }
  }
}
```

## The "Do Not Edit" Warning

A critical rule in the Fufuni framework: **NEVER edit `apps/mcp/src/knowledge.ts` manually.**

This file is a build artifact. If you modify it:
1.  Your changes will be lost the next time anyone runs `npm run mcp:auto`.
2.  The source of truth (the `.ts` topic files and the `.md` cache) will become out of sync with the runtime.
3.  Automated PR checks will fail because the file content won't match the hash of the source topics.

**The correct workflow is always:**
Modify/Add `apps/mcp/knowledge/topics/topic-name.ts` → Run `npm run mcp:auto` → Commit the changed `knowledge.ts` and the new topic file.
