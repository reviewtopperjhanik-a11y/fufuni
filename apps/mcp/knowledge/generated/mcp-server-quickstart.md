## Understanding the Fufuni MCP Server

The Model Context Protocol (MCP) server in Fufuni acts as a specialized documentation bridge between the framework's source code and AI assistants (like Claude, GPT-4, or local LLMs). Instead of feeding an LLM the entire codebase, which is token-intensive and often includes irrelevant boilerplate, the MCP server provides a curated, high-density knowledge base.

AI assistants consume this via "tools." When an assistant needs to know how Fufuni handles database migrations or React state, it calls a tool that queries the MCP server's SQLite-backed vector and BM25 index. This index is generated from Markdown files, which are themselves generated by an LLM analyzing the actual source code of the framework.

### Directory Layout

The MCP logic and knowledge pipeline are centralized in the `apps/mcp/` directory.

```bash
apps/mcp/
├── src/
│   ├── index.ts          # Main Worker entry point
│   ├── stdio.ts          # Local stdio entry for Claude Desktop
│   ├── knowledge.ts      # AUTO-GENERATED runtime knowledge base (DO NOT EDIT)
│   └── ...               # Tools and server logic
├── knowledge/
│   ├── topics/           # The source of truth (one .ts per topic)
│   │   ├── backend-api.ts
│   │   ├── database-schema.ts
│   │   └── frontend-ui.ts
│   ├── base.ts           # Shared types and base system prompts
│   └── generate.ts       # The LLM-powered generator script
├── scripts/
│   └── gen-knowledge.ts  # Compiles .md files into runtime .ts modules
└── ...
```

## Adding a New Knowledge Topic

Adding a topic file is the **only** supported way to expand the MCP server's intelligence. You must never edit the runtime files directly. Every topic file defines what source code should be analyzed and provides the prompts necessary for an LLM to distill that code into a concise developer guide.

### Topic File Template

Create a new file in `apps/mcp/knowledge/topics/<topic-name>.ts`. Use the following structure, ensuring the copyright header is present.

```typescript
/*
 * Copyright (c) 2026 Ronan LE MEILLAT - SCTG Development / License: AGPL-3.0-or-later
 */
import type { Topic } from "../base.js";
import { BASE_SYSTEM, appendFacts } from "../base.js";

/**
 * Topic definition for Fufuni Authentication and Session management.
 * This will be processed by an LLM to generate a .md file in the mcp/ directory.
 */
const topic: Topic = {
  name: "authentication", // Must match filename without .ts
  description: "Handles user login, JWT tokens, and Durable Object session storage.",
  sources: [
    "apps/backend/src/routes/auth.ts",
    "apps/backend/src/middleware/session.ts",
    "packages/shared/src/schemas/auth-schema.ts"
  ],
  systemPrompt: appendFacts(BASE_SYSTEM, [
    "Fufuni uses signed cookies for session management.",
    "The primary authentication provider is currently internal SQLite-based users.",
    "Passwords must be hashed using Argon2id."
  ]),
  buildPrompt: (sourceCode: string) => `
    Review the following Fufuni authentication source code:
    
    ${sourceCode}

    Generate a high-level technical guide for a junior developer. 
    Focus on the Hono route structure, the Zod validation schemas, and how the session middleware
    interacts with Cloudflare Durable Objects. 
    Use TypeScript code blocks for examples.
  `,
  maxSourceChars: 20000,
  manualFacts: [
    "Sessions expire after 7 days by default.",
    "CSRF protection is enabled on all POST/PUT/DELETE requests via the Hono CSRF middleware."
  ]
};

export default topic;
```

### The Topic Interface Explained

- **`name`**: A unique identifier. It is critical that this matches the filename exactly.
- **`description`**: A single sentence explaining the scope. This helps the generator categorize knowledge.
- **`sources`**: An array of relative paths from the repository root. The generator reads these files and concatenates them.
- **`systemPrompt`**: The personality and constraints for the LLM. Using `appendFacts` ensures that the `BASE_SYSTEM` rules (markdown formatting, no fluff) are preserved while adding topic-specific constraints.
- **`buildPrompt`**: A function that receives the concatenated source code and returns the instruction string for the LLM.
- **`maxSourceChars`**: (Optional) Limits the input size to prevent context window overflows. Defaults to framework-safe limits.
- **`manualFacts`**: Hardcoded technical truths that the LLM must include, even if they aren't explicitly obvious in the source code.

## Knowledge Generation Workflow

The workflow involves two stages: transforming source code into Markdown using an LLM, and then transforming those Markdown files into optimized TypeScript modules for the MCP server.

### Generation Commands

| Command | Description |
| :--- | :--- |
| `npm run mcp:generate` | Dry-run generation. It checks the cache and only processes topics where the source files have changed. |
| `npm run mcp:generate:force` | Ignores the cache and regenerates all `.md` files in the `<repo-root>/mcp/` directory. |
| `npm run mcp:auto` | Orchestrates the entire process: generates Markdown using an LLM (requires env vars), then runs the knowledge publisher. |
| `npm run mcp:auto:flash` | A specialized version of `mcp:auto` that uses Gemini-1.5-Flash. It uses the `CRYPTOKEN` to decrypt `ai.json.enc` for configuration. |

### Environment Variables for `mcp:auto`

To run the generator locally with a custom LLM provider, you need to set these in your `.env` or shell:

```bash
export AI_MODEL="gpt-4o"
export AI_API_KEY="your-api-key"
export AI_API_URL="https://api.openai.com/v1/chat/completions"
# Or for Flash usage:
export CRYPTOKEN="your-decryption-key"
```

## Publishing to Runtime Knowledge

Once the `.md` files are generated in the `mcp/` folder at the repo root, they are not yet usable by the MCP server. The server requires structured data for vector search and rapid retrieval.

The script `apps/mcp/scripts/gen-knowledge.ts` performs the following actions:
1.  Reads every `.md` file in `<repo-root>/mcp/`.
2.  Chunks the text for vectorization.
3.  Calculates BM25 frequency indices for keyword search.
4.  Generates four key files in `apps/mcp/src/`:
    -   `knowledge.ts`: The raw text content.
    -   `bm25-index.ts`: The keyword index.
    -   `chunks.ts`: Content split into logical sections.
    -   `vectors.ts`: (If enabled) Vector embeddings for semantic search.

### Warning: Direct Edits
**NEVER edit `apps/mcp/src/knowledge.ts` or its sibling generated files.**
These files are completely overwritten every time the generation scripts run. Any manual changes will be lost. If a fact is wrong in the AI assistant's response, you must update the corresponding file in `apps/mcp/knowledge/topics/` or the source code itself, then regenerate.

## Local Testing with Claude Desktop

To test your new topic before deploying the Cloudflare Worker, you can run the MCP server in `stdio` mode. This allows the Claude Desktop app to communicate with your local code.

### 1. Build and Run the Server
The `stdio.ts` file provides a entry point that maps standard input/output to the MCP protocol.

```bash
# From the repository root
npx tsx apps/mcp/src/stdio.ts
```

### 2. Configure Claude Desktop
Open your Claude Desktop configuration file (usually `~/Library/Application Support/Claude/claude_desktop_config.json` on macOS or `%APPDATA%\Claude\claude_desktop_config.json` on Windows) and add the Fufuni MCP server:

```json
{
  "mcpServers": {
    "fufuni-local": {
      "command": "npx",
      "args": [
        "tsx",
        "/path/to/fufuni-framework/apps/mcp/src/stdio.ts"
      ],
      "env": {
        "NODE_ENV": "development"
      }
    }
  }
}
```

### 3. Verification
Restart Claude Desktop. Look for the "hammer" icon or check the logs. You can now ask Claude questions related to the `Topic` you just added. For example: *"How does Fufuni handle session expiration according to the authentication topic?"*

## Maintenance and Updates

As the framework evolves, the source code in `apps/backend/` or `apps/frontend/` will change. The MCP server does not automatically stay in sync with your local edits during standard development.

To ensure the knowledge base reflects the latest code:
1.  Perform your code changes.
2.  Run `npm run mcp:generate`. The script will detect the file hash changes in your `sources` list.
3.  Commit the updated `.md` files in the `mcp/` directory and the updated `apps/mcp/src/knowledge.ts`.

```bash
# Example update workflow
git checkout -b feat/new-api
# ... modify code in apps/backend/src/routes/api.ts ...
npm run mcp:generate
# Check if mcp/backend-api.md changed
npm run mcp:auto # to update runtime modules
git add .
git commit -m "docs: update knowledge base for new API"
```

This ensures that any AI assisting future contributors will have the exact technical context of your changes.
