## Locale Architecture and File Structure

Fufuni uses `i18next` and `react-i18next` for internationalization. The configuration centralizes language metadata and loading logic, while translation strings are stored in flat JSON files. 

### Supported Locales

The framework currently supports six locales by default. These are defined in `apps/client/src/i18n.ts`. Every language is identified by its BCP 47 tag (e.g., `en-US`).

| Locale | Language | Direction | File Path |
| :--- | :--- | :--- | :--- |
| `en-US` | English | LTR | `apps/client/src/locales/base/en-US.json` |
| `fr-FR` | Français | LTR | `apps/client/src/locales/base/fr-FR.json` |
| `es-ES` | Español | LTR | `apps/client/src/locales/base/es-ES.json` |
| `zh-CN` | 中文 | LTR | `apps/client/src/locales/base/zh-CN.json` |
| `ar-SA` | العربية | RTL | `apps/client/src/locales/base/ar-SA.json` |
| `he-IL` | עברית | RTL | `apps/client/src/locales/base/he-IL.json` |

### The Configuration File

The `availableLanguages` array in `i18n.ts` is the single source of truth for the UI (like language switchers) and the i18n engine.

```typescript
// apps/client/src/i18n.ts
export interface AvailableLanguage {
  code: string;       // ISO 639-1 language code + region
  nativeName: string; // How the language appears in the selector
  isRTL: boolean;     // Whether the UI layout direction should flip
  isDefault?: boolean;// Fallback language

  { code: "en-US", nativeName: "English", isRTL: false, isDefault: true },
  { code: "fr-FR", nativeName: "Français", isRTL: false },
  { code: "ar-SA", nativeName: "العربية", isRTL: true },
  // ... other languages
];
```

## Adding Translation Keys

Fufuni follows a strict convention for translation keys: **kebab-case** and **flat structure**. While `i18next` supports nested objects, Fufuni uses flat keys for easier searching and consistency across large JSON files.

### Key Naming Conventions

1.  **Prefix by context**: Use prefixes like `admin-`, `cart-`, or `nav-` to group related keys.
2.  **Kebab-case**: Use lowercase letters and hyphens (e.g., `product-card-add-to-cart`).
3.  **Master Language**: Always add the key to `en-US.json` first. This file is treated as the authoritative source.

### JSON Structure and Interpolation

Keys support dynamic variables using double curly braces `{{var}}`.

```json
// apps/client/src/locales/base/en-US.json
{
  "welcome-message": "Welcome back, {{name}}!",
  "admin-products-stock-count": "There are {{count}} items in stock.",
  "cart-item-remove-confirm": "Remove {{productName}} from your cart?"
}
```

### Pluralization

For pluralization, `i18next` looks for suffixes like `_one` and `_other`. Note that different languages (like Arabic) may require more suffixes (`_zero`, `_two`, `_few`, `_many`), but `_one` and `_other` cover the standard English/French logic.

```json
// apps/client/src/locales/base/en-US.json
{
  "duration-day_one": "{{count}} day",
  "duration-day_other": "{{count}} days"
}
```

## Implementation in React Components

To use translations, use the `useTranslation` hook from `react-i18next`.

### Basic Usage

The hook returns a `t` function. **Verified Fact**: Never use the default value parameter of `t('key', 'default')`. Instead, ensure the key exists in `en-US.json`.

```tsx
import { useTranslation } from "react-i18next";
import { Button } from "@heroui/react";

export const AddToCartButton = () => {
  const { t } = useTranslation();

  return (
    <Button color="primary">
      {t("add-to-cart")}
    </Button>
  );
};
```

### Interpolation and Plurals

Pass an object as the second argument to `t` to provide variables or triggers for pluralization.

```tsx
import { useTranslation } from "react-i18next";

interface StockDisplayProps {
  quantity: number;
  userName: string;
}

export const StockDisplay = ({ quantity, userName }: StockDisplayProps) => {
  const { t } = useTranslation();

  return (
    <div>
      <p>{t("welcome-message", { name: userName })}</p>
      <span>
        {/* i18next automatically selects _one or _other based on count */}
        {t("duration-day", { count: quantity })}
      </span>
    </div>
  );
};
```

## Handling RTL (Right-to-Left)

Fufuni provides native support for RTL languages like Arabic (`ar-SA`) and Hebrew (`he-IL`). 

### Automatic Layout Direction

The logic is tied to the `isRTL` property in the `availableLanguages` array. When a user selects an RTL language:
1.  The `i18n.language` state updates.
2.  The framework (via the root layout or a specific provider) detects the `isRTL` flag of the current language.
3.  The HTML `dir` attribute is set to `rtl` on the document or a wrapping container.
4.  HeroUI (v3) components and Tailwind CSS utilities (using `start` and `end` instead of `left` and `right`) automatically flip the layout.

### RTL Logic in `i18n.ts`

The `i18next-http-backend` configuration in Fufuni requires manual handling for Vite to resolve assets correctly:

```typescript
// apps/client/src/i18n.ts (simplified logic)
backend: {
  loadPath: (lng, ns) => {
    // Vite cannot resolve dynamic template strings in new URL() easily
    // We use a switch case to map languages to static imports
    switch (lng[0]) {
      case "ar-SA":
        return new URL("./locales/base/ar-SA.json", import.meta.url).toString();
      case "he-IL":
        return new URL("./locales/base/he-IL.json", import.meta.url).toString();
      default:
        return new URL("./locales/base/en-US.json", import.meta.url).toString();
    }
  }
}
```

## Worked Example: Product Tags Feature

In this example, we will add a "Product Tags" management feature to the admin dashboard. We need three translation keys: a label for the section, an action to add a tag, and a warning when the limit is reached.

### Step 1: Update JSON Locales

Add the keys to the master English file first, then the French file.

**`apps/client/src/locales/base/en-US.json`**
```json
{
  "admin-products-tags-label": "Product Tags",
  "admin-products-tags-add": "Add tag to {{productName}}",
  "admin-products-tags-limit-reached_one": "Limit reached: you can only add {{count}} more tag.",
  "admin-products-tags-limit-reached_other": "Limit reached: you can only add {{count}} more tags."
}
```

**`apps/client/src/locales/base/fr-FR.json`**
```json
{
  "admin-products-tags-label": "Étiquettes du produit",
  "admin-products-tags-add": "Ajouter une étiquette à {{productName}}",
  "admin-products-tags-limit-reached_one": "Limite atteinte : vous ne pouvez ajouter que {{count}} étiquette supplémentaire.",
  "admin-products-tags-limit-reached_other": "Limite atteinte : vous ne pouvez ajouter que {{count}} étiquettes supplémentaires."
}
```

### Step 2: Implement in Component

Create a component that utilizes these keys with variables and pluralization.

```tsx
import React from "react";
import { useTranslation } from "react-i18next";
import { Chip, Button, Card, CardHeader, CardBody } from "@heroui/react";

interface ProductTagManagerProps {
  productName: string;
  tags: string[];
  maxTags: number;
}

export const ProductTagManager: React.FC<ProductTagManagerProps> = ({
  productName,
  tags,
  maxTags
}) => {
  const { t } = useTranslation();
  const remaining = maxTags - tags.length;

  return (
    <Card className="max-w-md">
      <CardHeader className="flex flex-col items-start px-4 pt-4">
        <h4 className="text-large font-bold">{t("admin-products-tags-label")}</h4>
        <p className="text-small text-default-500">
          {/* Interpolation example */}
          {t("admin-products-tags-add", { productName })}
        </p>
      </CardHeader>
      <CardBody className="px-4 py-2">
        <div className="flex flex-wrap gap-2 mb-4">
          {tags.map((tag) => (
            <Chip key={tag} variant="flat">
              {tag}
            </Chip>
          ))}
        </div>
        
        {remaining <= 2 && remaining > 0 && (
          <p className="text-warning text-tiny">
            {/* Pluralization example */}
            {t("admin-products-tags-limit-reached", { count: remaining })}
          </p>
        )}

        <Button 
          isDisabled={remaining <= 0}
          size="sm"
          variant="solid"
          color="primary"
          className="mt-2"
        >
          {t("save")}
        </Button>
      </CardBody>
    </Card>
  );
};
```

### Step 3: Verifying RTL Layout

If you switch the language to Arabic (`ar-SA`), the `ProductTagManager` will automatically:
1.  Align the `CardHeader` text to the right.
2.  Flip the order of items in the `flex-wrap` container (tags will start from the right).
3.  Apply right padding/margins where `ps-` (padding-start) or `ms-` (margin-start) Tailwind classes are used.
4.  Translate "Save" to "حفظ" (assuming it exists in `ar-SA.json`).
