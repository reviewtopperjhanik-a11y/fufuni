## Product Review Data Model

Product reviews in Fufuni are stored in the `product_reviews` table. This table tracks customer feedback, moderation status, and AI-generated insights. The schema enforces data integrity by ensuring ratings are within the 1–5 range and that metadata like timestamps are automatically handled.

### Database Schema (SQLite)

The `product_reviews` table uses a UUID for the primary key and includes a JSON column for AI results.

```sql
CREATE TABLE product_reviews (
  id TEXT PRIMARY KEY,
  product_id TEXT NOT NULL,
  customer_id TEXT NOT NULL,
  rating INTEGER NOT NULL CHECK (rating >= 1 AND rating <= 5),
  title TEXT,
  body TEXT,
  status TEXT NOT NULL DEFAULT 'pending', -- 'pending', 'approved', 'rejected'
  is_verified_purchase INTEGER DEFAULT 0,
  helpful_count INTEGER DEFAULT 0,
  ai_moderation_result TEXT, -- JSON blob containing sentiment and flags
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  -- Ensure one review per customer per product
  UNIQUE(product_id, customer_id),
  FOREIGN KEY (product_id) REFERENCES products(id) ON DELETE CASCADE
);
```

## Public and Customer Endpoints

The public API allows users to read approved reviews, while authenticated customers can submit their own. Submission is restricted to one review per product per customer to prevent review bombing or manipulation.

### Submitting a Review

When a customer submits a review, the framework checks for an existing entry. If a review already exists for that `product_id` and `customer_id` pair, the API returns a `409 Conflict`.

```typescript
// apps/merchant/src/routes/reviews.ts (Submission Logic)
const submitReviewRoute = createRoute({
  method: 'post',
  path: '/v1/products/{productId}/reviews',
  request: {
    params: z.object({ productId: z.string().uuid() }),
    body: {
      content: {
        'application/json': {
          schema: z.object({
            rating: z.number().min(1).max(5),
            title: z.string().optional(),
            body: z.string().optional(),
          }),
        },
      },
    },
  },
  responses: {
    201: { description: 'Review submitted for moderation' },
    409: { description: 'Review already exists for this product' },
  },
});

app.openapi(submitReviewRoute, async (c) => {
  const { productId } = c.req.valid('param');
  const { rating, title, body } = c.req.valid('json');
  const customer = c.get('customer'); // From customerAuthMiddleware
  const db = getDb(c.var.db);

  try {
    await db.prepare(`
      INSERT INTO product_reviews (id, product_id, customer_id, rating, title, body, status, created_at)
      VALUES (?, ?, ?, ?, ?, ?, 'pending', ?)
    `).run(crypto.randomUUID(), productId, customer.id, rating, title, body, new Date().toISOString());
    
    return c.json({ success: true }, 201);
  } catch (e: any) {
    if (e.message.includes('UNIQUE constraint failed')) {
      return c.json({ error: 'ALREADY_REVIEWED' }, 409);
    }
    throw e;
  }
});
```

### Listing Approved Reviews

The public-facing list endpoint only returns reviews with the `approved` status. It uses cursor-based pagination using the `created_at` timestamp to ensure stability.

```typescript
// GET /v1/products/:productId/reviews?limit=10&cursor=2023-01-01T10:00:00Z
const listReviewsRoute = createRoute({
  method: 'get',
  path: '/v1/products/{productId}/reviews',
  // ... parameters: productId, limit, cursor
});

app.openapi(listReviewsRoute, async (c) => {
  const { productId } = c.req.valid('param');
  const { limit, cursor } = c.req.valid('query');
  const db = getDb(c.var.db);

  const items = await db.prepare(`
    SELECT id, author_name, rating, title, body, is_verified_purchase, created_at
    FROM product_reviews
    WHERE product_id = ? AND status = 'approved'
    AND (? IS NULL OR created_at < ?)
    ORDER BY created_at DESC
    LIMIT ?
  `).bind(productId, cursor, cursor, parseInt(limit)).all();

  return c.json({
    items,
    pagination: {
      has_more: items.length === parseInt(limit),
      next_cursor: items.length > 0 ? items[items.length - 1].created_at : null
    }
  });
});
```

## Admin Moderation and Management

The admin interface allows staff to view all reviews regardless of status and update their moderation state.

### Bulk Filtering and Listing

Admins can filter reviews by status (`pending`, `approved`, `rejected`) or by a specific product ID. This is primarily used in the Merchant Dashboard to clear the moderation queue.

```typescript
// apps/merchant/src/routes/reviews.ts (Admin List)
const adminListRoute = createRoute({
  method: 'get',
  path: '/v1/reviews/admin',
  security: [{ AdminAuth: [] }],
  request: {
    query: z.object({
      status: z.enum(['pending', 'approved', 'rejected']).optional(),
      productId: z.string().uuid().optional(),
    }),
  },
  responses: {
    200: { description: 'List of reviews for administration' }
  }
});

app.openapi(adminListRoute, async (c) => {
  const { status, productId } = c.req.valid('query');
  const db = getDb(c.var.db);

  let query = `SELECT * FROM product_reviews WHERE 1=1`;
  const params: any[] = [];

  if (status) {
    query += ` AND status = ?`;
    params.push(status);
  }
  if (productId) {
    query += ` AND product_id = ?`;
    params.push(productId);
  }

  const reviews = await db.prepare(query).bind(...params).all();
  return c.json({ items: reviews.results });
});
```

### Approval and Rejection

Changing a review's status is a critical operation because it triggers a recalculation of product rating aggregates.

```typescript
// PATCH /v1/reviews/:id/status
app.openapi(updateStatusRoute, async (c) => {
  const { id } = c.req.valid('param');
  const { status } = c.req.valid('json');
  const db = getDb(c.var.db);

  // 1. Update the review status
  const review = await db.prepare(
    `UPDATE product_reviews SET status = ? WHERE id = ? RETURNING product_id`
  ).bind(status, id).first();

  if (review) {
    // 2. Trigger aggregate update for the specific product
    await updateProductAggregates(db, review.product_id);
  }

  return c.json({ success: true });
});
```

## AI Moderation Integration

Fufuni integrates AI to assist admins in identifying spam, toxicity, or low-quality reviews. This process happens when an admin opens the moderation dashboard.

### Analysis Workflow

1.  **Trigger**: The frontend `AdminReviewsPage` identifies reviews without an `ai_moderation_result`.
2.  **API Call**: The frontend calls `analyzeReviewsBatchWithAi` (using the AI worker).
3.  **Persistence**: The result (sentiment score, flags, summary) is sent back to the backend and stored in the `ai_moderation_result` column via a `PATCH` request.
4.  **UI Feedback**: The HeroUI `Chip` components display the AI's recommendation (e.g., "Recommended: Approve" in green or "Flagged: Spam" in red).

### AI Data Structure

The `ai_moderation_result` column contains stringified JSON with the following structure:

```typescript
}
```

## Rating Aggregates

To optimize performance, product pages do not calculate averages on the fly. Instead, the `products` table maintains two computed/cached columns: `avg_rating` and `review_count`.

### Synchronization Logic

Whenever a review is approved, rejected, or deleted, the following SQL logic is executed to refresh the `products` table. This ensures that the storefront always shows accurate star ratings without heavy JOIN operations.

```typescript
/**
 * Updates the products table with current rating stats.
 * Only includes 'approved' reviews in the calculation.
 */
async function updateProductAggregates(db: D1Database, productId: string) {
  await db.prepare(`
    UPDATE products
    SET 
      review_count = (
        SELECT COUNT(*) FROM product_reviews 
        WHERE product_id = ? AND status = 'approved'
      ),
      avg_rating = (
        SELECT IFNULL(AVG(rating), 0) FROM product_reviews 
        WHERE product_id = ? AND status = 'approved'
      )
    WHERE id = ?
  `).bind(productId, productId, productId).run();
}
```
