## Product Reviews Data Model

The Fufuni review system is built around the `product_reviews` table in the SQLite-backed Durable Object. It tracks customer feedback, moderation status, and AI-generated insights. Reviews follow a strict moderation workflow: they are submitted as `pending` and only become visible to the public once an administrator transitions them to `approved`.

### Database Schema

The schema includes standard feedback fields and a specific column for storing JSON results from AI analysis.

```sql
CREATE TABLE product_reviews (
  id TEXT PRIMARY KEY,               -- UUID
  product_id TEXT NOT NULL,          -- UUID referencing the product
  customer_id TEXT NOT NULL,         -- UUID referencing the customer
  rating INTEGER NOT NULL,           -- Integer 1-5
  title TEXT,                        -- Optional review headline
  body TEXT,                         -- Review content
  status TEXT DEFAULT 'pending',     -- 'pending' | 'approved' | 'rejected'
  is_verified_purchase INTEGER,      -- 1 if customer has a completed order for this SKU
  ai_moderation_result TEXT,         -- JSON object containing AI score and summary
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  UNIQUE(product_id, customer_id)    -- Enforces one review per product per customer
);
```

### Review Status Values

- **`pending`**: Initial state upon submission. Hidden from public product pages.
- **`approved`**: Visible to all users. Factored into the product's `avgRating`.
- **`rejected`**: Hidden from public view. Removed from aggregate calculations.

## Public Endpoints: Customer Submission and Discovery

The public API is split between open access (listing reviews) and authenticated access (submitting a review).

### Submitting a Review

Customers must be authenticated via `customerAuthMiddleware`. The system automatically sets the status to `pending`. If a customer attempts to review the same product twice, the database unique constraint triggers a `409 Conflict`.

```typescript
// apps/merchant/src/routes/reviews.ts

const submitReviewRoute = createRoute({
  method: 'post',
  path: '/v1/products/{productId}/reviews',
  request: {
    params: z.object({ productId: z.string().uuid() }),
    body: {
      content: {
        'application/json': {
          schema: z.object({
            rating: z.number().min(1).max(5),
            title: z.string().max(100).optional(),
            body: z.string().max(2000).optional(),
          }),
        },
      },
    },
  },
  responses: {
    201: { description: 'Review submitted for moderation' },
    409: { description: 'Customer has already reviewed this product' },
  },
});

app.openapi(submitReviewRoute, async (c) => {
  const { productId } = c.req.valid('param');
  const { rating, title, body } = c.req.valid('json');
  const customerId = c.var.customer.id; // From customerAuthMiddleware
  const db = getDb(c.var.db);

  try {
    await db.run(
      `INSERT INTO product_reviews (id, product_id, customer_id, rating, title, body, status, created_at)
       VALUES (?, ?, ?, ?, ?, ?, 'pending', ?)`,
      [uuid(), productId, customerId, rating, title, body, now()]
    );
    return c.json({ success: true }, 201);
  } catch (e: any) {
    if (e.message?.includes('UNIQUE constraint failed')) {
      return c.json({ error: 'Already reviewed' }, 409);
    }
    throw e;
  }
});
```

### Listing Approved Reviews

The public listing only returns reviews where `status = 'approved'`. It uses cursor-based pagination using the `created_at` timestamp to ensure stability as new reviews are added.

```typescript
  request: {
    params: z.object({ productId: z.string().uuid() }),
    query: z.object({
      limit: z.string().optional().default('20'),
      cursor: z.string().optional(), // ISO string of last item's created_at
    }),
  },
  // ... response schema
});

app.openapi(listReviewsRoute, async (c) => {
  const { productId } = c.req.valid('param');
  const { limit: limitStr, cursor } = c.req.valid('query');
  const limit = Math.min(parseInt(limitStr), 50);
  const db = getDb(c.var.db);

  let query = `SELECT * FROM product_reviews WHERE product_id = ? AND status = 'approved'`;
  const params: any[] = [productId];

  if (cursor) {
    query += ` AND created_at < ?`;
    params.push(cursor);
  }

  query += ` ORDER BY created_at DESC LIMIT ?`;
  params.push(limit + 1);

  const items = await db.all(query, params);
  const hasMore = items.length > limit;
  const result = hasMore ? items.slice(0, limit) : items;

  return c.json({
    items: result,
    pagination: {
      has_more: hasMore,
      next_cursor: hasMore ? result[result.length - 1].created_at : null,
    },
  });
});
```

### Approving or Rejecting a Review

Moderation is performed via a `PATCH` request. Updating the status triggers a recalculation of the product's aggregate rating.

```typescript
app.openapi(updateStatusRoute, async (c) => {
  const { id } = c.req.valid('param');
  const { status } = c.req.valid('json');
  const db = getDb(c.var.db);

  // 1. Update the review status
  const review = await db.get(`UPDATE product_reviews SET status = ?, updated_at = ? WHERE id = ? RETURNING product_id`, 
    [status, now(), id]
  );

  if (!review) return c.json({ error: 'Not found' }, 404);

  // 2. Update aggregates on the product table
  await updateProductAggregates(db, review.product_id);

  return c.json({ success: true });
});
```

## Rating Aggregates

To maintain high performance on product listing pages, Fufuni does not calculate average ratings on the fly. Instead, it stores `avgRating` and `reviewCount` as denormalized columns on the `products` table.

### Updating Aggregates

Whenever a review's status changes to `approved` (added) or from `approved` to `rejected` (removed), the `updateProductAggregates` function must be called.

```typescript
async function updateProductAggregates(db: any, productId: string) {
  const stats = await db.get(
    `SELECT 
      COUNT(*) as count, 
      AVG(rating) as average 
     FROM product_reviews 
     WHERE product_id = ? AND status = 'approved'`,
    [productId]
  );

  await db.run(
    `UPDATE products 
     SET avg_rating = ?, review_count = ? 
     WHERE id = ?`,
    [stats.average || 0, stats.count || 0, productId]
  );
}
```

### Constraints and Business Rules

1.  **One Review per Product**: This is strictly enforced at the database level using `UNIQUE(product_id, customer_id)`.
2.  **Verified Purchase**: The `is_verified_purchase` flag is determined at submission time by checking if the `customer_id` has an `order` in `completed` status containing the `product_id`.
3.  **Immutable Identity**: Once a review is submitted, the `customer_id` and `product_id` cannot be changed. Only the moderation `status`, `rating`, `title`, and `body` are mutable by admins or (optionally) the customer.
