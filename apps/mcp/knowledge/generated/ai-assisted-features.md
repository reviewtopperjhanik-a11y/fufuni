## Architecture: Browser-Side Inference

Fufuni adopts a "Client-Side AI" architecture. Unlike traditional setups where the backend proxies requests to AI providers, Fufuni's backend only serves as a secure vault for credentials. Once an authorized administrator or manager accesses a feature requiring AI, the frontend retrieves the decrypted API key and configuration, then performs the heavy lifting (inference) directly from the user's browser.

This design offers several advantages:
1.  **Cost Efficiency**: Cloudflare Worker compute time is not consumed by waiting for slow AI responses.
2.  **Concurrency**: Multiple users can perform translations or moderation tasks simultaneously without hitting backend request limits.
3.  **Privacy**: Content sent to the AI provider never passes through Fufuni's backend logs.

### AI Parameters Retrieval Example

The frontend uses the `aiAccessOnly` protected endpoint to get temporary credentials for the session.

```typescript
import { AiParams } from '@/utils/ai-client';

async function fetchAiConfig(): Promise<AiParams | null> {
  const response = await fetch('/v1/ai/parameters', {
    headers: {
      'Authorization': `Bearer ${userToken}`,
    },
  });

  if (!response.ok) {
    console.error('AI is not configured or access is denied');
    return null;
  }

  return await response.json() as AiParams;
}
```

## Credential Storage and Encryption

AI credentials (API keys, models, and endpoints) are never stored in plain text. Fufuni utilizes a multi-layered security approach:
-   **Storage**: Credentials are stored in the `KV_CACHE` under the key `ai:config`.
-   **Encryption**: The configuration is encrypted using AES-256-CBC with PBKDF2 key derivation.
-   **Secret**: The `ENCRYPTION_KEY` (referred to as `CRYPTOKEN` in the environment bindings) is a sensitive Wrangler secret that never leaves the Cloudflare environment.

The configuration file `ai.json` is typically encrypted locally using OpenSSL before being uploaded via the Admin API.

### Decryption Logic in the Worker

The `ai-enc.ts` utility handles the decryption using the standard Web Crypto API, ensuring compatibility with Cloudflare Workers.

```typescript
import { decryptAiConfig, AiConfig } from '../lib/ai-enc';

export async function loadConfig(env: HonoEnv['Bindings']): Promise<AiConfig | null> {
  // Retrieve the encrypted string from KV
  const encryptedConfig = await env.KV_CACHE.get('ai:config');
  const secret = env.ENCRYPTION_KEY; // The Wrangler secret

  if (!encryptedConfig || !secret) return null;

  try {
    // Decrypts the OpenSSL-formatted payload in memory
    return await decryptAiConfig(encryptedConfig, secret);
  } catch (error) {
    console.error('Failed to decrypt AI config:', error);
    return null;
  }
}
```

## Backend API: GET /v1/ai/parameters

This endpoint is the bridge between the secure vault and the frontend. It is protected by the `aiAccessOnly` middleware, which checks for the `ai:api` permission.

The endpoint performs the following:
1.  Loads and decrypts the config from `KV_CACHE`.
2.  Filters available models by priority.
3.  Selects a non-expired key from the pool (load-balancing).
4.  Returns the `apiKey`, `model`, and `url`.

### Route Definition (Zod-OpenAPI)

## Review Moderation Workflow

Review moderation assists administrators by pre-scanning customer feedback. When an admin views the "Reviews" management page, the frontend automatically triggers an analysis for pending reviews.

### Implementation in Admin UI

The UI calls `analyzeReviewWithAi` (aliased as `moderateReview` in design documentation) to get a recommendation.

## Auto-Translation for Products

The Product Form in the Merchant dashboard uses AI to localize content across all supported store locales. When the base language (usually `en-US`) is filled, the "Auto-translate" button appears.

### Workflow
1.  **Source Extraction**: The frontend gathers the product title and HTML description.
2.  **Parallel Translation**: It triggers `translateWithAi` for each target locale (e.g., `fr-FR`, `de-DE`, `es-ES`).
3.  **Field Injection**: The results are injected back into the HeroUI tabs for each locale.

```typescript
const handleAutoTranslate = async () => {
  const params = await fetchAiConfig();
  if (!params) return;

  for (const locale of activeLocales) {
    if (locale === baseLocale) continue;

    const titleRes = await translateWithAi(product.name, locale, params, false);
    const descRes = await translateWithAi(product.description, locale, params, true);

    if (titleRes.success && descRes.success) {
      setLocaleValue(locale, 'name', titleRes.content);
      setLocaleValue(locale, 'description', descRes.content);
    }
  }
};
```

## Graceful Degradation

Fufuni is designed to remain fully functional even if no AI provider is configured.

1.  **UI Visibility**: The "Auto-translate" buttons in the Product and Email Template forms are conditionally rendered. If `GET /v1/ai/parameters` returns a 503 or 401, these buttons remain hidden.
2.  **Review Moderation**: If AI is unavailable, the review list simply skips the "AI Recommendation" badge. The admin can still manually approve or reject reviews.
3.  **Error Handling**: All AI client functions catch network errors or API failures and return a `success: false` payload, preventing the entire application from crashing if a provider (like Groq or OpenAI) is down.

### Fallback Logic Example

const [aiConfig, setAiConfig] = useState<AiParams | null>(null);

useEffect(() => {
