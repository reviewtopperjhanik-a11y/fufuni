## User Persistence Architecture

Fufuni employs a hybrid storage strategy to balance performance, latency, and data consistency. User-specific data is split between **Identity Provider Metadata (Auth0)** and **Relational Storage (Durable Object SQLite)**.

- **Wishlist:** Stored in Auth0 `user_metadata`. This allows the wishlist to be encoded directly into the JWT access token. When a user logs in or refreshes their token, the frontend instantly knows their favorites without an additional database query.
- **Saved Cart:** Stored in the `saved_carts` SQL table. Carts can contain complex objects (quantities, variants, metadata) that exceed the recommended size for JWT payloads or Auth0 metadata limits.
- **User Preferences:** Stored in the `user_preferences` SQL table. This includes UI-specific settings like locale and currency display which require relational integrity for reporting and localization.

## Wishlist Management with useWishlist

The `useWishlist` hook is the primary interface for managing a user's favorite products. It leverages the JWT payload to provide reactive updates across the application without a heavy global state manager.

### Hook Return Values

The hook provides the following interface (as per Fufuni core specifications):
- `wishlist`: `string[]` - Array of product IDs.
- `isLoading`: `boolean` - True if the token is being refreshed or metadata is being fetched.
- `addToWishlist`: `(productId: string) => Promise<void>` - Adds an item.
- `removeFromWishlist`: `(productId: string) => Promise<void>` - Removes an item.
- `isInWishlist`: `(productId: string) => boolean` - Sync check for UI state.
- `toggleWishlist`: `(productId: string) => Promise<void>` - High-level toggle helper.

### Implementation Example

The following example demonstrates a "Heart" button component using **HeroUI v3**.

```typescript
import { Button } from "@heroui/react";
import { HeartIcon } from "@/components/icons";
import { useWishlist } from "@/hooks/use-wishlist";
import { useAuth } from "@/authentication";

interface FavoriteButtonProps {
  productId: string;
}

export const FavoriteButton = ({ productId }: FavoriteButtonProps) => {
  const { isInWishlist, toggleWishlist, isLoading } = useWishlist();
  const { isAuthenticated } = useAuth();

  const isFav = isInWishlist(productId);

  const handleToggle = async () => {
    if (!isAuthenticated) {
      // Logic for redirecting to login or showing a modal
      return;
    }
    await toggleWishlist(productId);
  };

  return (
    <Button
      isIconOnly
      variant="light"
      radius="full"
      isLoading={isLoading}
      onPress={handleToggle}
      aria-label={isFav ? "Remove from wishlist" : "Add to wishlist"}
    >
      <HeartIcon 
        className={isFav ? "fill-danger text-danger" : "text-default-400"} 
      />
    </Button>
  );
};
```

## Auth0 Management API Integration

When a user toggles a wishlist item, the backend must update the Auth0 `user_metadata`. Since frontend clients cannot securely call the Auth0 Management API directly, Fufuni acts as a proxy.

The backend uses `getAuth0ManagementToken()` to authenticate as a Machine-to-Machine (M2M) application. This token is cached in the Worker's memory for 60 seconds to prevent rate-limiting and minimize latency on subsequent updates.

### Backend Route Example (Hono)

```typescript
import { Hono } from "hono";
import { getAuth0ManagementToken } from "@/lib/auth0-mgmt";
import { customerAuthMiddleware } from "@/middleware/auth";

const wishlistApp = new Hono();

wishlistApp.post("/v1/me/wishlist", customerAuthMiddleware, async (c) => {
  const { productId } = await c.req.json();
  const user = c.get("user"); // Populated by middleware
  
  const mgmtToken = await getAuth0ManagementToken();
  const currentMetadata = user["extra_user_info/user_metadata"] || {};
  const currentWishlist = currentMetadata.wishlist || [];

  if (!currentWishlist.includes(productId)) {
    const updatedWishlist = [...currentWishlist, productId];
    
    // Call Auth0 Management API
    await fetch(`https://${process.env.AUTH0_DOMAIN}/api/v2/users/${user.sub}`, {
      method: "PATCH",
      headers: {
        Authorization: `Bearer ${mgmtToken}`,
        "Content-Type": "application/json",
      },
      body: JSON.stringify({
        user_metadata: { ...currentMetadata, wishlist: updatedWishlist },
      }),
    });
  }

  return c.json({ success: true });
});
```

## Saved Cart Persistence

While the active cart is managed in local state for immediate feedback, Fufuni persists the cart to the SQLite database to allow cross-device synchronization (e.g., add on mobile, checkout on desktop).

### SQL Schema

The `saved_carts` table stores a serialized JSON representation of the cart items, linked to the user's unique Auth0 ID.

```sql
CREATE TABLE saved_carts (
  user_id TEXT PRIMARY KEY,
  cart_data TEXT NOT NULL, -- JSON string of CartItem[]
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

### Endpoints
- `GET /v1/me/saved-cart`: Retrieves the current saved cart for the authenticated user.
- `PUT /v1/me/saved-cart`: Upserts the cart data.
- `DELETE /v1/me/saved-cart`: Clears the saved cart (usually called after a successful order).

## CartProvider Synchronization

The `CartProvider` in `apps/client/src/contexts/cart-context.tsx` handles the orchestration between the local React state and the remote SQL storage.

1.  **Initial Load:** When `isAuthenticated` becomes true, the provider fetches the saved cart from `/v1/me/saved-cart`.
2.  **Auto-Save:** Any change to the local `cartItems` state triggers a debounced (2 seconds) `PUT` request to the API. This ensures the database is updated without spamming the server on every quantity increment.

### Cart Sync Logic

```typescript
// Inside CartProvider component
useEffect(() => {
  if (isAuthenticated && cartItems.length > 0) {
    const timer = setTimeout(async () => {
      await api.put("/v1/me/saved-cart", { items: cartItems });
    }, 2000);

    return () => clearTimeout(timer);
  }
}, [cartItems, isAuthenticated]);
```

## User Preferences

User preferences govern the display characteristics of the storefront. Unlike the wishlist, these are stored in a dedicated SQL table to allow for complex queries (e.g., "how many users prefer EUR currency?").

### Preference Fields
- `locale`: e.g., `en-US`, `fr-FR`.
- `currency`: e.g., `USD`, `EUR`.
- `marketing_consent`: boolean.

### Usage in Backend

All preference updates require the `customerAuthMiddleware` to ensure the `sub` (Subject) claim is present in the JWT.

```typescript
import { z } from "zod";
import { OpenAPIHono, createRoute } from "@hono/zod-openapi";

const preferencesSchema = z.object({
  locale: z.string().length(5),
  currency: z.string().length(3),
});

const putPreferencesRoute = createRoute({
  method: "put",
  path: "/v1/me/preferences",
  request: {
    body: {
      content: { "application/json": { schema: preferencesSchema } }
    }
  },
  responses: {
    200: { description: "Preferences updated" }
  }
});

const app = new OpenAPIHono();

app.openapi(putPreferencesRoute, async (c) => {
  const body = c.req.valid("json");
  const userId = c.get("user").sub;
  const db = c.get("db");

  await db.prepare(`
    INSERT INTO user_preferences (user_id, locale, currency)
    VALUES (?, ?, ?)
    ON CONFLICT(user_id) DO UPDATE SET
      locale = excluded.locale,
      currency = excluded.currency
  `).bind(userId, body.locale, body.currency).run();

  return c.json({ status: "ok" });
});
```

### Frontend Preference Consumption

To access preferences, use the `useTokenUserData` utility or a direct API call if the data isn't mirrored in the JWT. For high-performance UI rendering, Fufuni recommends including `locale` in the `user_metadata` so it's available on page load via the Auth0 token, while the SQL table remains the source of truth for administrative tasks.
