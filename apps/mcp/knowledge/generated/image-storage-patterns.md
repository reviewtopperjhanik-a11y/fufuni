## Image Storage Architecture

Fufuni employs a hybrid image storage strategy designed to balance database performance with external bucket scalability. By utilizing three distinct storage methods, the framework ensures that small assets are delivered instantly via the primary SQLite payload while large assets are offloaded to Cloudflare R2.

### The Three Storage Methods

1.  **Base64 Local**: For images under 1MB, the data is converted to a WebP Data URI and stored directly in the SQLite column. This eliminates extra HTTP requests for small icons or thumbnails.
2.  **R2 Remote**: For images exceeding 1MB (or when `forceR2` is enabled), the file is uploaded to a Cloudflare R2 bucket. The database stores the resulting URL.
3.  **External URL**: For images already hosted on CDNs like Cloudinary or Unsplash, the framework stores the absolute URL.

```typescript
// Example of the ImageStorageMethod type used across the framework
export type ImageStorageMethod = "base64" | "r2" | "url";

export interface ImageUploadResult {
  url: string; // Either a data:image/webp;base64... or a https://api.store.com/v1/images/...
  method: ImageStorageMethod;
  key?: string; // Only present for R2 uploads
}
```

## Automatic Selection Logic

Fufuni automates the decision-making process for storage. Developers do not need to manually decide where a file goes; the `uploadImageFile` utility handles it based on the post-conversion file size.

### Thresholds and Limits
-   **BASE64_SIZE_LIMIT**: 1,048,576 bytes (1MB). If the WebP-converted file is smaller than this, it defaults to Base64.
-   **FILE_SIZE_LIMIT**: 5,242,880 bytes (5MB). This is the hard cap for any upload attempt to protect Worker memory and R2 costs.
-   **IMAGE_SIZE_THRESHOLD**: Used in the UI component to trigger the `forceR2` logic early.

### Implementation of Logic
The utility `getOptimalStorageMethod` determines the path based on the `forceR2` flag and the actual size.

```typescript
import { uploadImageFile } from "@/utils/image-upload";
import { useSecuredApi } from "@/authentication";

const MyImageUploader = () => {
  const { postForm } = useSecuredApi();
  const apiBaseUrl = "https://api.fufuni.store";

  const handleFile = async (file: File) => {
    try {
      // Automatic selection: <1MB becomes Base64, >=1MB becomes R2
      const result = await uploadImageFile(
        file, 
        apiBaseUrl, 
        postForm
      );
      
      console.log(`Stored via ${result.method}: ${result.url}`);
    } catch (error) {
      console.error("Upload failed:", error);
    }
  };
};
```

## WebP Conversion Strategy

To ensure optimal performance and SEO, Fufuni converts **all** uploaded images to WebP on the client side before they ever reach the network. This reduces bandwidth and ensures consistent storage formats.

### Parameters
-   **Format**: Image/webp
-   **Max Dimension**: 1200px (Width or Height, maintaining aspect ratio)
-   **Quality**: 0.8
-   **Thumbnails**: Generated at 300px max dimension.

### Manual Conversion Example
While `ImageUploadInput` handles this automatically, you can use the underlying `image-utils.ts` manually:

```typescript
import { convertToWebp, blobToBase64 } from "@/utils/image-utils";

async function processProfilePicture(file: File) {
  // 1. Convert to high-res WebP for main display
  const mainBlob = await convertToWebp(file, 1200, 0.8);
  
  // 2. Convert to low-res thumbnail
  const thumbBlob = await convertToWebp(file, 300, 0.6);
  const thumbBase64 = await blobToBase64(thumbBlob);

  return {
    main: mainBlob, // Ready for uploadImageFile
    thumb: thumbBase64 // Ready for direct DB storage
  };
}
```

## Security Guard: isValidImageUrl

When dealing with URLs provided via manual input or external sources, Fufuni enforces a strict security guard to prevent XSS (via `javascript:` URIs) or unauthorized protocol usage.

The `isValidImageUrl` function acts as a validator before rendering any `<img>` tag or saving to the database.

```typescript
/**
 * Strict protocol validation for image sources.
 * Only allows http, https, and data:image/ (Base64)
 */
export function isValidImageUrl(url: string): boolean {
  try {
    const urlObj = new URL(url);
    return (
      urlObj.protocol === "http:" ||
      urlObj.protocol === "https:" ||
      url.startsWith("data:image/")
    );
  } catch {
    // Fallback for relative data URLs or malformed strings
    return url.startsWith("data:image/");
  }
}

// Usage in a component rendering a user-provided image
const SafeImage = ({ src }: { src: string }) => {
  if (!isValidImageUrl(src)) {
    return <div className="bg-danger-50 text-danger p-2">Invalid Image Protocol</div>;
  }
  
  return <img src={src} alt="External Content" />;
};
```

## Backend R2 Integration

The backend provides specific endpoints for managing R2 objects. All image management requires the `admin:store` permission.

### Endpoints
1.  **POST `/v1/images`**: Accepts `multipart/form-data`. It generates a unique key (UUID), uploads the blob to the R2 bucket, and returns the public URL.
2.  **DELETE `/v1/images/:key`**: Removes the object from R2 and issues a purge command for the CDN cache.

### Permissions and Implementation Example (Backend Hono)
```typescript
// backend/src/routes/images.ts
import { Hono } from "hono";
import { verifyAuth } from "@/middleware/auth";

const images = new Hono();

images.post("/", verifyAuth("admin:store"), async (c) => {
  const body = await c.req.parseBody();
  const file = body.file as File;

  if (!file) return c.json({ error: "No file uploaded" }, 400);

  const key = `${crypto.randomUUID()}.webp`;
  
  // Upload to Cloudflare R2
  await c.env.R2_BUCKET.put(key, await file.arrayBuffer(), {
    httpMetadata: { contentType: "image/webp" }
  });

  return c.json({
    key,
    url: `${c.env.CDN_URL}/v1/images/${key}`
  });
});
```

## CDN Caching and Purging

Images served from R2 are typically proxied through a Cloudflare Worker or a Custom Domain with Caching enabled. Fufuni uses a KV-based or Cache-API-based layer to speed up delivery.

### Cache Interaction
-   **Storage**: When an image is requested at `/v1/images/:key`, the Worker checks the Cache API. If it's a miss, it fetches from R2 and stores it in the Cache with a long TTL (usually 1 year).
-   **Purging**: Because images are immutable (using UUID keys), we rarely update them. However, if an image is deleted via the API, the backend triggers a purge.

```typescript
// Backend purge logic example
async function deleteImage(key: string, env: Env) {
  // 1. Delete from R2
  await env.R2_BUCKET.delete(key);
  
  // 2. Purge from Cloudflare Cache (using Cache API or KV invalidation)
  const cache = caches.default;
  const cacheKey = new URL(`${env.CDN_URL}/v1/images/${key}`);
  await cache.delete(cacheKey);
}
```

### Best Practices for Developers
-   **Always use `ImageUploadInput`**: Don't build custom file inputs for the admin dashboard.
-   **Respect `onThumbnailChange`**: In list views (like a product table), always store and use the thumbnail to avoid loading heavy 1200px images.
-   **Trust the WebP conversion**: The framework handles the conversion; do not manually resize images before passing them to the utility unless specific artistic requirements exist.
