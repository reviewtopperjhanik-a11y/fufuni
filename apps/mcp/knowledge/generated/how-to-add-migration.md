## The Three Pillars of Fufuni Migrations

In the Fufuni framework, Durable Objects (DO) use SQLite for storage. Because each merchant has their own isolated DO instance, schema management requires a robust, idempotent approach. You must never simply modify the `SCHEMA` constant; you must ensure that existing databases are upgraded while new ones start with the latest schema.

Every schema change in the `MerchantDO` must be applied in **three distinct places**:

1.  **The `SCHEMA` Constant (`apps/merchant/src/do.ts`):** This is the "blueprint" used when a brand-new Durable Object is created. It must always contain the full, current DDL.
2.  **The `ensureInitialized()` Method (`apps/merchant/src/do.ts`):** This method runs on every request (or at startup) to check if the database needs patching. It uses a `migrations` table to track which version a specific DO instance is currently on.
3.  **A Migration SQL File (`apps/merchant/migrations/NNN-description.sql`):** This file provides a historical record and allows for manual execution via `wrangler d1 execute` if needed for testing or D1-backed environments.

### When to use a migration
- Adding a new table.
- Adding a column to an existing table (e.g., `ALTER TABLE ... ADD COLUMN ...`).
- Creating a new index to optimize performance.
- Changing a constraint or adding a trigger.

## Step-by-Step implementation

### 1. Create the SQL Migration File
Create a new file in `apps/merchant/migrations/`. Use a 3-digit prefix followed by a kebab-case description. Since the current highest migration is **034**, your next migration will be **035**.

**Naming Convention:** `NNN-description.sql` (e.g., `035-add-product-tags.sql`).

```sql
-- apps/merchant/migrations/035-add-product-tags.sql
-- Migration 035: Adds a specialized tags table and the join table for products.

PRAGMA foreign_keys = ON;

CREATE TABLE IF NOT EXISTS tags (
  id         TEXT PRIMARY KEY,
  name       TEXT NOT NULL UNIQUE,
  slug       TEXT NOT NULL UNIQUE,
  created_at TEXT NOT NULL DEFAULT (datetime('now'))
);

CREATE TABLE IF NOT EXISTS product_tags (
  product_id TEXT NOT NULL REFERENCES products(id) ON DELETE CASCADE,
  tag_id     TEXT NOT NULL REFERENCES tags(id) ON DELETE CASCADE,
  PRIMARY KEY (product_id, tag_id)
);

CREATE INDEX IF NOT EXISTS idx_product_tags_tag ON product_tags(tag_id);
```

### 2. Update the SCHEMA Constant
Go to `apps/merchant/src/do.ts` and locate the `const SCHEMA = ...` block. Append your new tables and indexes to the end of this string. Use `CREATE TABLE IF NOT EXISTS` to ensure idempotency.

```typescript
// apps/merchant/src/do.ts

const SCHEMA = `
-- ... existing tables ...

-- ============================================================
-- PRODUCT TAGS (migration 035)
-- ============================================================

CREATE TABLE IF NOT EXISTS tags (
  id         TEXT PRIMARY KEY,
  name       TEXT NOT NULL UNIQUE,
  slug       TEXT NOT NULL UNIQUE,
  created_at TEXT NOT NULL DEFAULT (datetime('now'))
);

CREATE TABLE IF NOT EXISTS product_tags (
  product_id TEXT NOT NULL REFERENCES products(id) ON DELETE CASCADE,
  tag_id     TEXT NOT NULL REFERENCES tags(id) ON DELETE CASCADE,
  PRIMARY KEY (product_id, tag_id)
);

CREATE INDEX IF NOT EXISTS idx_product_tags_tag ON product_tags(tag_id);
`;
```

### 3. Add the Migration Block to ensureInitialized()
In the same `do.ts` file, locate the `ensureInitialized()` method. You must add a block that checks the `migrations` table and applies the SQL if the migration name (matching the file stem) is missing.

**Important:** Durable Object SQL operations via `this.sql.exec()` are synchronous. Do **not** use `await`.

```typescript
// apps/merchant/src/do.ts inside class MerchantDO

private ensureInitialized() {
  // 1. Ensure the base schema and migration tracking table exist
  this.sql.exec(SCHEMA);

  // 2. Fetch applied migrations
  const migrations = this.sql.exec("SELECT name FROM migrations");
  const applied = new Set(migrations.map((m: any) => m.name));

  // 3. Add your migration block
  // The string literal MUST match the filename stem exactly.
  if (!applied.has("035-add-product-tags")) {
    this.sql.exec(`
      CREATE TABLE IF NOT EXISTS tags (
        id         TEXT PRIMARY KEY,
        name       TEXT NOT NULL UNIQUE,
        slug       TEXT NOT NULL UNIQUE,
        created_at TEXT NOT NULL DEFAULT (datetime('now'))
      );
      CREATE TABLE IF NOT EXISTS product_tags (
        product_id TEXT NOT NULL REFERENCES products(id) ON DELETE CASCADE,
        tag_id     TEXT NOT NULL REFERENCES tags(id) ON DELETE CASCADE,
        PRIMARY KEY (product_id, tag_id)
      );
      CREATE INDEX IF NOT EXISTS idx_product_tags_tag ON product_tags(tag_id);
    `);
    
    // Mark as applied
    this.sql.exec("INSERT INTO migrations (name) VALUES (?)", "035-add-product-tags");
    console.log("Applied migration: 035-add-product-tags");
  }
}
```

## Technical Best Practices

### Column Types and Standards
Fufuni uses SQLite within Durable Objects. Follow these typing conventions:
- **UUIDs/IDs:** Use `TEXT`.
- **Dates/Times:** Use `TEXT` stored as ISO 8601 strings (via `datetime('now')`).
- **Booleans:** Use `INTEGER` (0 or 1). SQLite does not have a native BOOLEAN type.
- **Money/Prices:** Use `INTEGER` representing cents (e.g., `1999` for $19.99). Never use REAL/Float for currency.
- **Percentages/Ratings:** Use `REAL`.

### Idempotency and Safety
Migrations are **idempotent by design**. The `ensureInitialized()` method ensures that even if a request fails halfway through, the logic will not break the next time it runs:
1.  The `IF NOT EXISTS` clause in your SQL protects against table/index creation errors.
2.  The `migrations` table check prevents the entire block from executing twice.
3.  The use of `this.sql.exec()` ensures that all statements in a single call are handled by the SQLite engine sequentially.

### Migration Name Matching
The string passed to `applied.has("...")` and `INSERT INTO migrations` must match the file stem in `apps/merchant/migrations/` exactly. 
- File: `028-product-reviews.sql`
- Stem: `028-product-reviews`

## Common Pitfalls

### Missing IF NOT EXISTS
If you omit `IF NOT EXISTS` and a DO instance somehow fails to record the migration but successfully creates the table, subsequent calls to `ensureInitialized()` will throw a "table already exists" error, effectively bricking that Merchant's Durable Object.

### Retroactive Modifications
**Never** modify a migration file or an `ensureInitialized` block once it has been merged and deployed. If you realize you made a mistake in migration `035` (e.g., you misspelled a column), do not edit `035`. Create migration `036-fix-tags-typo` and apply the fix there. This ensures a linear, predictable history for all merchant DOs.

### Synchronous vs Asynchronous
Durable Object `this.sql` is synchronous. 
```typescript
// WRONG - This will cause runtime errors or unexpected behavior
await this.sql.exec("..."); 

// CORRECT
this.sql.exec("...");
```

### Schema bloat
While the `SCHEMA` constant and the `ensureInitialized` blocks contain redundant SQL, this is intentional. The `SCHEMA` constant provides a "fast path" for new objects, while the individual migration blocks provide the "upgrade path" for existing objects. Keep both in sync to avoid "drifting" schemas where new merchants have different table structures than old ones.

## Complete Worked Example: Adding a "Store Announcements" Feature

This example demonstrates adding a simple table to show banners on the frontend.

### Part A: The SQL File
**File:** `apps/merchant/migrations/036-store-announcements.sql`
```sql
CREATE TABLE IF NOT EXISTS announcements (
  id         TEXT PRIMARY KEY,
  content    TEXT NOT NULL,
  bg_color   TEXT DEFAULT '#000000',
  is_active  INTEGER NOT NULL DEFAULT 0,
  starts_at  TEXT,
  ends_at    TEXT,
  created_at TEXT NOT NULL DEFAULT (datetime('now'))
);

CREATE INDEX IF NOT EXISTS idx_announcements_active ON announcements(is_active);
```

### Part B: The DO Update
**File:** `apps/merchant/src/do.ts`

```typescript
const SCHEMA = `
-- ... existing code ...

CREATE TABLE IF NOT EXISTS announcements (
  id         TEXT PRIMARY KEY,
  content    TEXT NOT NULL,
  bg_color   TEXT DEFAULT '#000000',
  is_active  INTEGER NOT NULL DEFAULT 0,
  starts_at  TEXT,
  ends_at    TEXT,
  created_at TEXT NOT NULL DEFAULT (datetime('now'))
);
CREATE INDEX IF NOT EXISTS idx_announcements_active ON announcements(is_active);
`;

// Inside the MerchantDO class
private ensureInitialized() {
  this.sql.exec(SCHEMA);

  const migrations = this.sql.exec("SELECT name FROM migrations");
  const applied = new Set(migrations.map((m: any) => m.name));

  // Migration 036
  if (!applied.has("036-store-announcements")) {
    this.sql.exec(`
      CREATE TABLE IF NOT EXISTS announcements (
        id         TEXT PRIMARY KEY,
        content    TEXT NOT NULL,
        bg_color   TEXT DEFAULT '#000000',
        is_active  INTEGER NOT NULL DEFAULT 0,
        starts_at  TEXT,
        ends_at    TEXT,
        created_at TEXT NOT NULL DEFAULT (datetime('now'))
      );
      CREATE INDEX IF NOT EXISTS idx_announcements_active ON announcements(is_active);
    `);
    this.sql.exec("INSERT INTO migrations (name) VALUES (?)", "036-store-announcements");
  }
}
```

By following this pattern, you ensure that the Fufuni framework remains stable across thousands of independent merchant databases, regardless of when they were first initialized.
