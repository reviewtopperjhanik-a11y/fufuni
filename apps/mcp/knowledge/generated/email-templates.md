## Mailgun Infrastructure

Fufuni uses the Mailgun REST API for all transactional communications. Unlike traditional SMTP, this approach is optimized for Cloudflare Workers, avoiding long-lived connections and heavy libraries. 

To enable email delivery, you must configure specific secrets in your environment. If these secrets are missing (standard for local development), the system will skip delivery without throwing errors.

### Required Environment Variables

Add these to your `wrangler.toml` or set them as secrets using `npx wrangler secret put`:

| Secret | Purpose | Default / Example |
| :--- | :--- | :--- |
| `MAILGUN_API_KEY` | Your Mailgun Private API Key | `key-xxxxxxxxxxxx` |
| `MAILGUN_DOMAIN` | The verified domain in Mailgun | `mg.yourstore.com` |
| `MAILGUN_BASE_URL` | The API endpoint (EU or US) | `https://api.mailgun.net` |
| `MAILGUN_USER` | The default "From" address | `Store Name <hello@yourstore.com>` |
| `ORDER_TOKEN_SECRET` | Secret to sign tracking links | `a-long-random-string` |
| `STORE_URL` | Base URL for tracking links | `https://yourstore.com` |

```typescript
// apps/merchant/src/mailgun.ts
// Internal helper used by the framework to communicate with Mailgun
export async function sendMailgunEmail(env: Env, params: {
  to: string | string[];
  subject: string;
  html: string;
  text: string;
  from?: string;
}) {
  const { MAILGUN_API_KEY, MAILGUN_DOMAIN, MAILGUN_BASE_URL, MAILGUN_USER } = env;

  if (!MAILGUN_API_KEY || !MAILGUN_DOMAIN) {
    console.warn('[Mailgun] Skipping email delivery: API credentials missing.');
    return { success: false, status: 0, statusText: 'Skipped (No Credentials)' };
  }

  const baseUrl = MAILGUN_BASE_URL || 'https://api.mailgun.net';
  const endpoint = `${baseUrl}/v3/${MAILGUN_DOMAIN}/messages`;
  
  const formData = new FormData();
  formData.append('from', params.from || MAILGUN_USER || `noreply@${MAILGUN_DOMAIN}`);
  formData.append('to', Array.isArray(params.to) ? params.to.join(',') : params.to);
  formData.append('subject', params.subject);
  formData.append('text', params.text);
  formData.append('html', params.html);

  const response = await fetch(endpoint, {
    method: 'POST',
    headers: {
      Authorization: `Basic ${btoa(`api:${MAILGUN_API_KEY}`)}`,
    },
    body: formData,
  });

  return {
    success: response.ok,
    status: response.status,
    statusText: response.statusText,
    body: await response.text(),
  };
}
```

## Triggered Lifecycle Events

Emails in Fufuni are tied to order transitions. When an order status changes in the SQLite database, the `sendOrderStatusEmail` helper is invoked.

### Automatic Triggers

| Event | Logic | Content |
| :--- | :--- | :--- |
| `order.created` | Sent immediately after payment success (Stripe Webhook). | Order confirmation with a 30-day signed tracking link. |
| `order.shipped` | Sent when `tracking_number` is added via admin. | Shipping notification + carrier tracking URL. |
| `order.refunded` | Sent when a full or partial refund is processed. | Refund confirmation and updated total. |
| `payment_failed`| Sent if the checkout session expires or fails. | Link to retry payment or contact support. |

```typescript
// Example of triggering a status email from a Hono route
app.post('/orders/:id/ship', async (c) => {
  const orderId = c.req.param('id');
  const db = getDb(c.var.db);
  
  // 1. Update order in SQLite
  await db.run(
    `UPDATE orders SET status = 'shipped', tracking_number = ? WHERE id = ?`,
    ['TRK123456', orderId]
  );

  // 2. Trigger the transactional email (Async/Non-blocking)
  // This helper handles template lookup and localization automatically
  await sendOrderStatusEmail(c.env, db, orderId, 'shipped');

  return c.json({ success: true });
});
```

## Template Architecture

Fufuni avoids heavy templating engines like EJS or Handlebars to maintain a small Worker footprint. Templates are written as plain TypeScript functions using template literals.

### Template Structure (`email-templates.ts`)

Every template must return an object with three fields: `subject`, `html`, and `text`. The plain-text version is mandatory for accessibility and anti-spam compliance.

```typescript
// apps/merchant/src/lib/email-templates.ts

export function buildRefundEmail(params: {
  orderNumber: string;
  amount: number;
  currency: string;
  STORE_NAME: string;
}): { subject: string; html: string; text: string } {
  const formattedAmount = new Intl.NumberFormat('en-US', {
    style: 'currency',
    currency: params.currency.toUpperCase(),
  }).format(params.amount / 100);

  const subject = `Refund Processed for Order ${params.orderNumber}`;

  const text = `Hello, your refund of ${formattedAmount} for order ${params.orderNumber} has been processed.`;

  const html = `
    <div style="font-family: sans-serif; max-width: 600px;">
      <h1 style="color: #d32f2f;">Refund Processed</h1>
      <p>Hello,</p>
      <p>We've successfully processed a refund of <strong>${formattedAmount}</strong> for your order <strong>${params.orderNumber}</strong>.</p>
      <p>It may take 5-10 days to appear on your statement.</p>
      <hr />
      <p style="font-size: 12px; color: #666;">&copy; ${params.STORE_NAME}</p>
    </div>
  `;

  return { subject, html, text };
}
```

## Adding a New Email Template (4 Steps)

To add a new transactional email (e.g., a "Review Request" email), follow these steps:

1.  **Define the Template**: Create a new function in `lib/email-templates.ts` that takes the necessary parameters and returns the `{ subject, html, text }` object.
2.  **Update the Event Type**: Add your new event name to the `ORDER_EMAIL_EVENTS` array in `routes/order-email-settings.ts` to make it manageable via the Admin UI.
3.  **Implement the Trigger**: Call `sendOrderStatusEmail` in the appropriate route where the event occurs.
4.  **Register Defaults (Optional)**: Update the `buildDefaultStatusEmail` helper in `lib/order-email.ts` to provide a fallback if no custom HTML is provided in the admin settings.

## Admin Operations & Testing

The Fufuni Admin API allows merchants to override templates, toggle notifications, and test delivery.

### Configuration (`order_email_settings` table)

Merchants can use the `PUT /v1/admin/order-email-settings/:event` endpoint to customize emails.
- **Enabled**: Toggle notifications on/off.
- **Subject**: Supports JSON maps for localization: `{"en-US": "Thanks!", "fr-FR": "Merci !"}`.
- **Placeholders**: The following variables are injected into templates: `{{storeName}}`, `{{orderNumber}}`, `{{orderUrl}}`, `{{status}}`, `{{total}}`, `{{customerName}}`, `{{trackingNumber}}`.

### Testing via API

## Local Development & Fail-Safe Logic

### The "No-Key" Skip
During development, you likely won't have a Mailgun API key. Fufuni handles this gracefully:
- **No Error**: The code checks for `MAILGUN_API_KEY`. If undefined, it logs a `console.warn` and returns a success-like object to prevent the Worker from crashing or the database transaction from rolling back.
- **Token Generation**: Even if the email isn't sent, the **order view token** is still generated and stored in the database. You can find this token in your local D1/SQLite instance and manually construct the tracking URL for testing.

```typescript
// Logic inside sendOrderConfirmationEmail
const hasMailgun = Boolean(env.MAILGUN_API_KEY && env.MAILGUN_DOMAIN);

if (!hasMailgun) {
  // We still record that we "tried" to send it so the UI shows the link
  await db.run(
    `UPDATE orders SET viewtoken = ?, confirmationemailsentat = ? WHERE id = ?`,
    [tokenHash, new Date().toISOString(), orderId]
  );
  return { success: true, orderUrl }; 
}
```

### Localization Logic
Fufuni resolves templates based on the `locale` field stored on the `order` record.
1. It looks for a JSON key matching the order locale (e.g., `fr-FR`).
2. If missing, it falls back to `en-US`.
3. If that is also missing, it takes the first available key in the JSON map.
4. If the field is not JSON, it treats it as a plain string for all locales.
