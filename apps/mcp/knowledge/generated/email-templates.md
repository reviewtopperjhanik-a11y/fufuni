## Mailgun Configuration

Fufuni uses the Mailgun REST API for all transactional email delivery. To enable email functionality, you must configure specific secrets in your Cloudflare Worker environment. If these secrets are missing, the framework is designed to skip email sending silently without throwing errors, which facilitates a "no-op" environment for local development.

### Required Secrets

Add these keys to your `.dev.vars` for local development or via `wrangler secret put` for production:

*   `MAILGUN_API_KEY`: Your Mailgun private API key.
*   `MAILGUN_DOMAIN`: The verified domain in your Mailgun account (e.g., `mg.yourstore.com`).
*   `MAILGUN_BASE_URL`: Defaults to `https://api.mailgun.net`. Use `https://api.eu.mailgun.net` if your domain is in the EU region.
*   `MAILGUN_USER`: The default "From" address (e.g., `Store Name <noreply@yourstore.com>`).

```typescript
// Example: Sending a raw email via the internal utility
// This utility handles the logic of checking for API keys before attempting the fetch.
import { sendMailgunEmail } from '../mailgun';
import { Env } from '../types';

async function handleTestEmail(env: Env) {
  const result = await sendMailgunEmail(env, {
    to: 'customer@example.com',
    subject: 'Welcome to Fufuni',
    text: 'Thank you for joining our store!',
    html: '<h1>Welcome!</h1><p>Thank you for joining our store!</p>'
  });

  if (result.success) {
    console.log('Email dispatched via Mailgun');
  }
}
```

## The Template Engine (email-templates.ts)

Fufuni avoids heavy templating libraries like Handlebars or EJS to keep the Worker bundle size small and the execution time minimal. Instead, templates are written as **pure TypeScript functions** that return an object containing the subject, HTML body, and a plain-text fallback.

### Template Structure

Every template function follows a standard pattern:
1. Accept a `params` object containing all dynamic data.
2. Format currencies and dates using the `Intl` API.
3. Return a `{ subject: string; html: string; text: string }` object.

```typescript
/**
 * apps/merchant/src/lib/email-templates.ts
 * 
 * Defines the structure for a "Low Stock" alert template.
 */
export function buildLowStockAlertEmail(params: {
  productName: string;
  currentStock: number;
  STORE_NAME: string;
}): { subject: string; html: string; text: string } {
  const { productName, currentStock, STORE_NAME } = params;

  const subject = `⚠️ Low Stock Alert: ${productName}`;
  
  const text = `The stock for "${productName}" is low. Current quantity: ${currentStock}. — ${STORE_NAME}`;

  const html = `
    <!DOCTYPE html>
    <html>
      <body style="font-family: sans-serif; color: #333;">
        <h2 style="color: #d97706;">Low Stock Alert</h2>
        <p>The following item is running low in <strong>${STORE_NAME}</strong>:</p>
        <div style="padding: 16px; background: #fff7ed; border: 1px solid #ffedd5; border-radius: 8px;">
          <strong>Product:</strong> ${productName}<br>
          <strong>Current Stock:</strong> ${currentStock}
        </div>
      </body>
    </html>
  `;

  return { subject, html, text };
}
```

## Triggered Emails and Lifecycle Events

Emails are triggered by state changes in the database or external webhooks (like Stripe). The `sendOrderStatusEmail` helper in `lib/order-email.ts` manages the lookup of merchant-defined templates and fallback logic.

### Supported Events

| Event | Trigger | Content |
| :--- | :--- | :--- |
| `order.created` | Successful checkout completion | Confirmation, Order URL, and Total. |
| `paid` | Stripe `checkout.session.completed` | Payment receipt and next steps. |
| `shipped` | Admin updates tracking info | Tracking number and carrier link. |
| `refunded` | Admin issues a refund | Confirmation of amount returned. |
| `payment_failed` | Stripe payment failure | Link to retry payment or update card. |

### Logic Flow for Status Changes

When a status change occurs, the system:
1. Checks for a specific setting in the `order_email_settings` table.
2. If disabled or missing, it checks for a `global` setting.
3. If still not found, the email is not sent.
4. It resolves variables like `{{orderNumber}}` or `{{customerName}}` within the merchant's custom text.

```typescript
// Triggering an email after shipping an order
import { sendOrderStatusEmail } from './lib/order-email';

async function markAsShipped(orderId: string, env: Env, db: Database) {
  await db.run(
    `UPDATE orders SET status = 'shipped', tracking_number = ? WHERE id = ?`,
    ['TRK12345', orderId]
  );
  
  // This helper fetches the merchant's custom HTML/Subject or uses the default
  await sendOrderStatusEmail(env, db, orderId, 'shipped');
}
```

## How to Add a New Template End-to-End

Follow these four steps to introduce a new transactional email to the Fufuni framework:

### 1. Define the Template Function
Open `apps/merchant/src/lib/email-templates.ts` and add your rendering function. Ensure you include a plain-text version for accessibility and email clients that block HTML.

### 2. Update the Service Layer
In `apps/merchant/src/lib/order-email.ts`, update the `OrderEmailEvent` type and ensure the `buildDefaultStatusEmail` function (if applicable) has a fallback UI for your new event.

### 3. Add the Trigger Call
Identify the route or service where the event originates (e.g., `routes/orders.ts` or `stripe.ts`). Call `sendOrderStatusEmail` after the database transaction is committed.

### 4. Register the Setting
Add the new event string to the `ORDER_EMAIL_EVENTS` array in `apps/merchant/src/routes/order-email-settings.ts`. This allows the Admin UI to toggle the email on/off and customize the body.

## Admin Endpoints and Testing

The Merchant API provides several endpoints for managing and verifying email delivery.

### Configuration CRUD
Merchants manage their templates via `adminOrderEmailSettings`. They can use JSON maps for multi-language support:

## Local Development and Silent Failures

A common pitfall for junior developers is wondering why no emails are being received during local testing. 

Fufuni explicitly checks for `MAILGUN_API_KEY`. If this key is undefined, the `sendMailgunEmail` function returns a success-like object with a "skipped" status. This prevents local development from crashing due to missing secrets while ensuring you don't accidentally send hundreds of test emails from your local machine to real customers if you are using a production database clone.

### Verifying Local Logic
To see what *would* have been sent, you should check the logs. The `sendOrderConfirmationEmail` function updates the `confirmationemaillasterror` column in the SQLite database if a hard error occurs, but it will remain `NULL` if the key is simply missing.
