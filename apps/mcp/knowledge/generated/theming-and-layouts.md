## Core Layout Architectures

Fufuni provides two distinct layout components to handle different browsing experiences. Layouts are responsible for shared UI elements like navigation, shopping carts, and global footers.

### DefaultLayout: Standard E-commerce
The `DefaultLayout` is the workhorse of the storefront. It provides a standard max-width container (`max-w-7xl`), a persistent sticky `Navbar`, and the `CartDrawer` logic. Use this for category pages, search results, and standard product listings.

**Key Features:**
- **Navigation:** Integrated `Navbar` with login/logout states.
- **Cart Management:** Shared state for the `CartDrawer`.
- **Authentication:** Handles JWT token decoding and refresh logic on mount.
- **Toast Support:** Typically wraps the application's toast notification provider.

```typescript
// apps/client/src/layouts/default.tsx
import { Navbar } from "@/components/navbar";
import { CartDrawer } from "@/components/cart-drawer";
import { useCartDrawer } from "@/contexts/cart-drawer-context";

export default function DefaultLayout({ children }: { children: React.ReactNode }) {
  const { isOpen, open, close } = useCartDrawer();

  return (
    <div className="relative flex flex-col h-screen">
      <Navbar onCartOpen={open} />
      <CartDrawer isOpen={isOpen} onClose={(v) => !v && close()} />
      <main className="container mx-auto max-w-7xl px-6 grow pt-16">
        {children} {/* Page content injected here */}
      </main>
      <footer className="w-full bg-default-50 border-t mt-auto">
        {/* standard footer content */}
      </footer>
    </div>
  );
}
```

### LuxuryLayout: Editorial & High-End
The `LuxuryLayout` is designed for high-impact landing pages and premium product showcases. Per the framework design, it removes the standard `Navbar` in favor of a minimal or transparent header and utilizes full-bleed containers (no horizontal padding).

**Usage Strategy:**

- **Hero Sections:** Products requiring large, edge-to-edge imagery.

## StoreThemeProvider and CSS Injection

The `StoreThemeProvider` is a critical system component that bridges the database-stored branding (Store Themes) with the CSS runtime. Unlike standard "Light/Dark" modes, Store Themes define the merchant's brand identity.

### Theme Application Logic
On application startup, the framework fetches the active theme from the backend (typically via `GET /v1/store-themes/active`). The provider then injects CSS variables directly into the `:root` or `<html>` element.

| Variable | Description | Default (HeroUI) |
| :--- | :--- | :--- |
| `--color-primary` | Main brand color for buttons/links | `#006FEE` |
| `--color-secondary` | Accent color for badges/secondary actions | `#7828C8` |
| `--color-background` | Main page background | `#FFFFFF` |
| `--radius-md` | Border radius for UI components | `0.5rem` |

```typescript
// apps/client/src/providers/theme-provider.tsx
import { useEffect } from "react";

export function StoreThemeProvider({ children }: { children: React.ReactNode }) {
  useEffect(() => {
    async function fetchAndApplyTheme() {
      const response = await fetch("/v1/store-themes/active");
      const theme = await response.json();
      
      const root = document.documentElement;
      // Injecting branding variables into the DOM
      root.style.setProperty("--color-primary", theme.primaryColor);
      root.style.setProperty("--color-secondary", theme.secondaryColor);
      root.setAttribute("data-theme", theme.slug);
    }
    fetchAndApplyTheme();
  }, []);

  return <>{children}</>;
}
```

## Adding a New CSS Variable to the System

To extend the branding capabilities (e.g., adding a custom "Announcement Bar" background color), follow these three steps:

1.  **Database Schema:** Add the new field to the `store_themes` table in the SQLite D1 database.
    ```sql
    ALTER TABLE store_themes ADD COLUMN color_announcement_bar TEXT DEFAULT '#000000';
    ```
2.  **Provider Application:** Update `StoreThemeProvider` to read this field and set a CSS variable.
    ```typescript
    root.style.setProperty("--color-announcement-bg", theme.colorAnnouncementBar);
    ```
3.  **Tailwind/Component Usage:** Use the variable in your components or extend the `tailwind.config.js`.
    ```tsx
    <div className="bg-[var(--color-announcement-bg)] text-white p-2">
      New Product Drop!
    </div>
    ```

## ThemeSwitch (UI Mode) vs. StoreTheme (Branding)

It is vital to distinguish between **UI Mode** and **Store Theme**.

*   **ThemeSwitch (Light/Dark):** Managed by HeroUI and the `next-themes` pattern. It toggles the `.dark` or `.light` class on the `<html>` element. This changes the *behavior* of semantic colors (e.g., `text-foreground` becomes white in dark mode).
*   **StoreTheme:** Managed by Fufuni's `StoreThemeProvider`. It injects specific hex values into variables like `--color-primary`. This changes the *identity* of the store, regardless of whether the user is in light or dark mode.

```tsx
// Mixing both: A primary button in dark mode
// HeroUI handles the dark background, StoreTheme handles the button color
<Button color="primary" className="bg-[var(--color-primary)]">
  Branded Button
</Button>
```

## CMS Content Architecture

Fufuni uses a hybrid approach for CMS content. Static structures are defined in `cms-content.ts` for type safety, while actual content is fetched from the Durable Object via `GET /v1/cms/content`.

### Structure of cms-content.ts
The `CMS_CONTENT` object acts as the default fallback and defines the schema for informational pages (About, Shipping, FAQ). It is keyed by `page_handle` and then by `locale`.

```typescript
// apps/client/src/config/cms-content.ts
export type CmsSection = {
  heading: string;
  body: string;
};

export type CmsPageContent = {
  title: string;
  lead: string;
  sections: CmsSection[];
};

export const CMS_CONTENT: Record<string, Record<string, CmsPageContent>> = {
  about: {
    "en-US": {
      title: "About Fufuni",
      lead: "Edge-native e-commerce...",
      sections: [{ heading: "Our Story", body: "..." }]
    }
  }
};
```

### SiteConfig and Fetching
The `siteConfig()` helper aggregates social links, branding titles, and global metadata. While `cms-content.ts` stores static text, dynamic banners and hero sections are fetched at runtime.

```typescript
// Example of fetching dynamic CMS content in a component
const [cmsData, setCmsData] = useState<any>(null);

useEffect(() => {
  fetch(`${apiBase}/v1/cms/content`)
    .then(res => res.json())
    .then(data => setCmsData(data));
}, []);
```

## Adding a New CMS Section

To add a new editable section (e.g., a "Trusted By" logo marquee) to the storefront:

1.  **Define Type:** Update `CmsPageContent` or create a new type in `apps/client/src/config/cms-content.ts`.
    ```typescript
    export type MarqueeSection = {
      logos: { url: string; alt: string }[];
    };
    ```
2.  **Admin Editor:** Add an input field/upload component in the Admin dashboard's CMS page (`apps/admin/src/pages/cms.tsx`).
3.  **API Update:** Call `PUT /v1/cms/content` from the admin panel to persist the new data to the SQLite backend.
4.  **Render:** In your page component (e.g., `Home.tsx`), access the new field and render the UI.
    ```tsx
    {cmsData?.marquee?.logos.map(logo => (
      <img key={logo.url} src={logo.url} alt={logo.alt} />
    ))}
    ```

## HeroUI Color Override Mechanism

Fufuni overrides HeroUI's default palette to ensure merchant branding is consistent. This is achieved through Tailwind CSS variable mapping. HeroUI components use semantic classes like `bg-primary`. In the Tailwind config, we map `primary` to our CSS variable.

**Tailwind Mapping Example:**
```javascript
// tailwind.config.js
module.exports = {
  theme: {
    extend: {
      colors: {
        primary: {
          DEFAULT: "var(--color-primary)",
          foreground: "var(--color-primary-fg)",
        },
      },
    },
  },
};
```

When `StoreThemeProvider` updates `--color-primary` on the `<html>` element, every HeroUI component using the `color="primary"` prop will automatically reflect the merchant's brand color without a page reload. This allows for real-time "Theme Preview" in the admin dashboard.
