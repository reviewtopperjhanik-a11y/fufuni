## Accessing Cloudflare Bindings in Hono

Fufuni uses Hono as its routing engine. Every route handler receives a context object `c` which provides access to the environment bindings defined in `wrangler.jsonc`. These bindings are typed via the `Env` interface generated in `worker-configuration.d.ts`.

### Accessing R2, KV, and Durable Objects

When working within a Hono route, you access services like R2 (storage), KV (caching), or the Merchant Durable Object directly through `c.env`.

```typescript
import { Hono } from 'hono';

const app = new Hono<{ Bindings: Env }>();

app.get('/v1/system/status', async (c) => {
  // 1. Access KV Cache
  const cachedStatus = await c.env.KV_CACHE.get('system:status');
  
  // 2. Access R2 Bucket
  const logo = await c.env.IMAGES.get('assets/logo.png');
  
  // 3. Access Durable Object Namespace
  const id = c.env.MERCHANT.idFromName('singleton');
  const merchantStub = c.env.MERCHANT.get(id);

  return c.json({
    kvAvailable: !!c.env.KV_CACHE,
    r2Available: !!c.env.IMAGES,
    merchantId: id.toString()
  });
});
```

## Durable Object Pattern: The Merchant Singleton

Fufuni follows a "Single Durable Object" architecture for each merchant. This means all SQLite operations for a specific deployment happen within one DO instance to ensure consistency and take advantage of DO's co-located SQLite database.

### Getting the Stub and Calling Methods

The framework abstracts database interactions into `query()` (for reads) and `run()` (for writes). To interact with the database, you must first get a stub for the "singleton" ID.

```typescript
import { Hono } from 'hono';

app.get('/v1/products/:id', async (c) => {
  const productId = c.req.param('id');
  
  // Fufuni uses a single DO instance per worker deployment
  const id = c.env.MERCHANT.idFromName('singleton');
  const merchant = c.env.MERCHANT.get(id);

  // Use .query for read-only SQL operations
  const product = await merchant.query(
    "SELECT * FROM products WHERE id = ?", 
    [productId]
  );

  if (!product || product.length === 0) {
    return c.json({ error: 'Not found' }, 404);
  }

  return c.json(product[0]);
});

app.post('/v1/products', async (c) => {
  const body = await c.req.json();
  const id = c.env.MERCHANT.idFromName('singleton');
  const merchant = c.env.MERCHANT.get(id);

  // Use .run for mutations (INSERT/UPDATE/DELETE)
  await merchant.run(
    "INSERT INTO products (name, price) VALUES (?, ?)",
    [body.name, body.price]
  );

  return c.json({ success: true }, 201);
});
```

## KV Caching and Invalidation Middleware

Fufuni includes automated KV caching to reduce the load on the Durable Object and improve response times for public catalog data.

### The `kvCacheMiddleware`

This middleware serves GET requests from KV. The cache key is structured as `cache:<full-url>`. It bypasses the cache if an Authorization header is present (unless it's a public `pk_` token).

TTL values are controlled by environment variables:
- `KV_CACHE_SEARCH_TTL_SECONDS`: For search results (default 300s).
- `KV_CACHE_REVIEWS_TTL_SECONDS`: For product reviews (default 600s).
- `KV_CACHE_DEFAULT_TTL_SECONDS`: For general catalog data (default 3600s).

```typescript
// apps/merchant/src/middleware/kv-cache.ts logic snippet
export const kvCacheMiddleware = async (c: Context, next: Next) => {
  if (c.req.method !== 'GET') return await next();
  
  const cacheKey = `cache:${c.req.url}`;
  const cached = await c.env.KV_CACHE.get(cacheKey);
  
  if (cached) {
    return c.json(JSON.parse(cached), 200, { 'X-Cache': 'HIT' });
  }

  await next();

  if (c.res.status === 200) {
    const data = await c.res.clone().json();
    const ttl = getTtlForRoute(c.req.path); // Logic selecting from Env vars
    await c.env.KV_CACHE.put(cacheKey, JSON.stringify(data), { expirationTtl: ttl });
  }
};
```

### Manual and Automatic Invalidation

The `kvInvalidateMiddleware` automatically purges relevant cache prefixes (like `cache:*/v1/products`) when a successful POST, PATCH, or DELETE occurs. To manually invalidate from code:

```typescript
async function purgeProductCache(env: Env) {
  const list = await env.KV_CACHE.list({ prefix: 'cache:' });
  for (const key of list.keys) {
    if (key.name.includes('/v1/products')) {
      await env.KV_CACHE.delete(key.name);
    }
  }
}
```

## R2 Image Management

Product images are stored in an R2 bucket and served through a public URL defined in `IMAGES_URL`.

### Storing and Deleting Images

When a merchant uploads a product image, the backend saves it to R2 using a structured path.

```typescript
app.post('/v1/images/upload', async (c) => {
  const formData = await c.req.formData();
  const file = formData.get('file') as File;
  const fileName = `products/${crypto.randomUUID()}-${file.name}`;

  // Upload to R2
  await c.env.IMAGES.put(fileName, file.stream(), {
    httpMetadata: { contentType: file.type }
  });

  const publicUrl = `${c.env.IMAGES_URL}/${fileName}`;
  return c.json({ url: publicUrl });
});
```

## Environment Variables and Secrets

Fufuni distinguishes between "Vars" (public/static config) and "Secrets" (sensitive keys).

### Mailgun Configuration
Mailgun is the default transactional email provider. These must be set as Secrets in Cloudflare:
- `MAILGUN_API_KEY`: The API key from Mailgun.
- `MAILGUN_DOMAIN`: The verified domain (e.g., `mg.example.com`).
- `MAILGUN_BASE_URL`: Usually `https://api.mailgun.net` or `https://api.eu.mailgun.net`.
- `MAILGUN_USER`: The "From" email address.

If `MAILGUN_API_KEY` is missing, the framework silently skips sending emails rather than crashing.

### CI/CD Workflow: `create-env-artifact.yaml`
Fufuni uses a specific flow to bridge GitHub Secrets to the Worker:
1. **GitHub Secrets**: You define a secret in GitHub (e.g., `STRIPE_SECRET_KEY`).
2. **`create-env-artifact.yaml`**: This workflow reads the GitHub Secret and writes it into a `.env` file.
3. **`generate-wrangler-jsonc.py`**: This script reads the `.env` and updates `wrangler.jsonc`. It also creates a `secrets.json`.
4. **`wrangler secret bulk`**: During deployment, CI runs this command to push all variables from `secrets.json` to Cloudflare.

**Rule**: If you add a new `.env` variable, you **must** add it to the `create-env-artifact.yaml` file, or it will be missing in production.

## Frontend Environment Integration

Frontend variables are injected at build time via Vite's `define` block. Fufuni does **not** use the `VITE_` prefix convention; instead, it explicitly maps variables in `apps/client/vite.config.ts`.

### Exposing a New Variable to React

To make a variable available in the frontend:
1. Add it to the root `.env`.
2. Add it to `apps/client/vite.config.ts` in the `define` object.

```typescript
// apps/client/vite.config.ts snippet
export default defineConfig(({ mode }) => {
  const env = loadEnv(mode, process.cwd(), '');
  
  return {
    define: {
      'import.meta.env.STORE_NAME': JSON.stringify(env.STORE_NAME),
      'import.meta.env.API_BASE_URL': JSON.stringify(env.API_BASE_URL),
      // Custom permissions logic
      'import.meta.env.PERMISSIONS': JSON.stringify(getScopesArray(env)),
    }
  };
});
```

### The `PERMISSIONS` Array
Fufuni dynamically calculates available permissions by scanning for any `.env` key ending in `_PERMISSION`. This array is used by the frontend `Navbar` to hide/show links without hardcoding strings.

```typescript
// Usage in React
const permissions = import.meta.env.PERMISSIONS;
const canAccessAI = permissions.includes('AI_PERMISSION');
```

## Adding a New Binding (Checklist)

If you need to add a new Cloudflare service (e.g., a new R2 bucket for backups):

### 1. Update `wrangler.jsonc`
Add the binding definition to the base configuration file.

```jsonc
{
  "r2_buckets": [
    { "binding": "IMAGES" },
    { "binding": "BACKUPS" } // New binding
  ]
}
```

### 2. Update Types
Run `npx wrangler types` to update `worker-configuration.d.ts`, or manually update the `Env` interface.

```typescript
interface Env {
  IMAGES: R2Bucket;
  BACKUPS: R2Bucket; // Add here
  // ... other bindings
}
```

### 3. CI/CD Mapping
If the binding requires a specific ID or secret, add the corresponding mapping in `.github/workflows/create-env-artifact.yaml`.

```yaml
- name: Create .env file
  run: |
    echo "BACKUP_BUCKET_ID=${{ secrets.BACKUP_BUCKET_ID }}" >> .env
```

## Local Development Workflow

### Standard Dev Mode
Run the following from the monorepo root to start both backend and frontend:
```bash
npm run dev:env
```
This command:
1. Copies the root `.env` to `apps/merchant/.dev.vars`.
2. Starts the Worker on `localhost:8787`.
3. Starts Vite on `localhost:5173`.

### Stripe Webhooks
The Stripe listener is not included in `dev:env` because it requires the external CLI. Run it in a separate terminal:
```bash
# Requires Stripe CLI installed
npm run stripe:listen
```
This forwards Stripe events to your local Worker: `stripe listen --forward-to http://localhost:8787/v1/webhooks/stripe`.
