## Purpose of Order View Tokens

In the Fufuni framework, order view tokens provide a secure mechanism for customers to access their order details and invoices without requiring a full user account or active session. This is particularly critical for guest checkouts where the customer needs to view their purchase confirmation or download a PDF invoice from an email link.

These tokens are implemented as short-lived, signed JSON Web Tokens (JWT) using the `jose` library. They grant read-only access to a specific order's data, including:
- Order status and line items.
- Shipping and billing addresses.
- Payment method metadata (e.g., card brand and last 4 digits).
- Total amounts and tax breakdowns.

Because these tokens expose PII (Personally Identifiable Information), they are strictly time-limited and cryptographically bound to a single order ID.

### Token Generation Example

The following example demonstrates how the backend uses the `lib/order-token.ts` utility to generate a signed token during the invoice URL generation process.

```typescript
import { createOrderToken } from '@/lib/order-token';
import { Hono } from 'hono';

const app = new Hono<{ Bindings: { ORDER_TOKEN_SECRET: string } }>();

/**
 * Authenticated endpoint to get a sharable invoice link.
 * Used by the Merchant Dashboard or the Customer Account page.
 */
app.get('/v1/orders/:id/invoice', async (c) => {
  const orderId = c.req.param('id');
  const secret = c.env.ORDER_TOKEN_SECRET;

  // Generate the 1-hour signed token
  const token = await createOrderToken(orderId, secret);
  
  // Construct the public-facing URL for the frontend
  const baseUrl = c.req.url.split('/v1/')[0];
  const viewUrl = `${baseUrl}/order-view?token=${token}`;

  return c.json({
    orderId,
    viewUrl,
    expiresAt: new Date(Date.now() + 3600 * 1000).toISOString()
  });
});
```

## Core API and Signatures

The `lib/order-token.ts` module abstracts the complexity of the Web Crypto API and the `jose` library. It ensures that tokens are signed with the `HS256` algorithm using a SHA-256 hash of the `ORDER_TOKEN_SECRET`.

### createOrderToken()

This function generates a signed JWT. Per verified specifications, the TTL (Time To Live) is strictly capped at **1 hour**.

```typescript
/**
 * @param orderId - The unique identifier of the order.
 * @param secret  - The ORDER_TOKEN_SECRET from environment variables.
 * @returns       - A Promise resolving to a signed JWT string.
 */
export async function createOrderToken(
  orderId: string, 
  secret: string
): Promise<string> {
  const key = await getSecretKey(secret);
  const ttl = 3600; // 1 hour in seconds

  return new SignJWT({ oid: orderId })
    .setProtectedHeader({ alg: 'HS256' })
    .setIssuedAt()
    .setExpirationTime(`${ttl}s`)
    .sign(key);
}
```

### verifyOrderToken()

This function validates the token's signature and expiration. If the token is valid, it returns the decoded payload.

```typescript
/**
 * @param token  - The raw JWT string from the client.
 * @param secret - The ORDER_TOKEN_SECRET from environment variables.
 * @returns      - The decoded payload containing the orderId, or null if invalid.
 */
export async function verifyOrderToken(
  token: string, 
  secret: string
): Promise<{ orderId: string } | null> {
  try {
    const key = await getSecretKey(secret);
    const { payload } = await jwtVerify(token, key);
    
    if (typeof payload.oid !== 'string') {
      return null;
    }

    return { orderId: payload.oid };
  } catch (err) {
    // Returns null if token is expired, tampered with, or invalid
    console.error('Token verification failed:', err);
    return null;
  }
}
```

## Backend Endpoints

Fufuni distinguishes between the **generation** of the link (authenticated) and the **consumption** of the data (unauthenticated via token).

### GET /v1/orders/:id/invoice (Authenticated)
This route requires standard administrative or owner authentication. It doesn't return the order data itself, but rather the `viewUrl` which contains the token. This URL is what the merchant sends to the customer.

### GET /v1/orders/view/:token (Public)
This is a public endpoint that requires no `Authorization` header. It is the primary data source for the guest invoice view.

```typescript
// apps/merchant/src/index.ts (or relevant router)

/**
 * Public endpoint to fetch order data via token.
 * No authentication header required.
 */
app.get('/v1/orders/view/:token', async (c) => {
  const token = c.req.param('token');
  const secret = c.env.ORDER_TOKEN_SECRET;

  const payload = await verifyOrderToken(token, secret);
  if (!payload) {
    return c.json({ error: 'Invalid or expired token' }, 401);
  }

  // The token is valid, fetch the order from the Durable Object/SQLite
  // We use the orderId extracted from the token payload
  const order = await c.env.ORDERS_DO.getById(payload.orderId);
  
  if (!order) {
    return c.json({ error: 'Order not found' }, 404);
  }

  return c.json(order);
});
```

## Frontend Flow and Consumption

The Fufuni frontend handles the order view through a dedicated route (typically `/order-view`). This page extracts the token from the URL search parameters and calls the public backend endpoint.

### React Implementation Example

Using React 19 and HeroUI v3 components, the frontend consumes the token to render the invoice.

```typescript
// apps/merchant/src/pages/OrderView.tsx
import { useEffect, useState } from 'react';
import { useSearchParams } from 'react-router-dom';
import { Card, CardBody, Spinner, Alert } from '@heroui/react';

export default function OrderView() {
  const [searchParams] = useSearchParams();
  const [order, setOrder] = useState<any>(null);
  const [error, setError] = useState<string | null>(null);
  const token = searchParams.get('token');

  useEffect(() => {
    if (!token) {
      setError('Missing access token.');
      return;
    }

    async function fetchOrder() {
      try {
        const response = await fetch(`/v1/orders/view/${token}`);
        if (!response.ok) throw new Error('Unauthorized or Expired');
        const data = await response.json();
        setOrder(data);
      } catch (err) {
        setError('The link has expired or is invalid.');
      }
    }

    fetchOrder();
  }, [token]);

  if (error) return <Alert color="danger" title="Error">{error}</Alert>;
  if (!order) return <Spinner size="lg" label="Loading Invoice..." />;

  return (
    <div className="max-w-3xl mx-auto p-6">
      <Card>
        <CardBody>
          <h1 className="text-2xl font-bold">Invoice #{order.id.slice(0, 8)}</h1>
          <p>Status: {order.status}</p>
          <div className="mt-4">
            <h3 className="font-semibold">Shipping Address</h3>
            <p>{order.shippingAddress.line1}<br/>{order.shippingAddress.city}</p>
          </div>
          {/* Detailed items table and PDF download button would go here */}
        </CardBody>
      </Card>
    </div>
  );
}
```

## Security Considerations

Order view tokens provide a balance between convenience and security. Because they grant access to sensitive PII, the following rules must be strictly observed:

### 1. TTL Restriction
The token lifetime is fixed at **1 hour**. Do not extend this TTL. Short lifetimes mitigate the risk if an email is intercepted or if a user accesses the link on a public computer. 

### 2. Single-Use Concept
While technically valid for the full hour, these tokens are conceptually "single-use." The frontend should fetch the data and immediately provide a way for the user to download a static PDF. The token is not intended for long-term session management.

### 3. ORDER_TOKEN_SECRET
This secret must be managed via Wrangler. It should be a high-entropy string unique to each environment (staging vs production).

```bash
# Adding the secret to Cloudflare Workers
wrangler secret put ORDER_TOKEN_SECRET
```

### 4. Data Exposure
The `GET /v1/orders/view/:token` endpoint must only return data necessary for invoice rendering. Do not return internal metadata, sensitive logs, or full payment gateway tokens (only last 4 digits).

### 5. No Token Revocation
Fufuni does not implement a revocation list (blocklist) for order tokens to maintain the high performance of the unauthenticated edge routes. Security is enforced via the 1-hour expiration and the cryptographic signature.

## Verification of Hashed Tokens

While the raw token is sent to the client, the framework provides a utility to hash these tokens if the merchant requires logging or auditing of used links without storing the sensitive JWT itself.

```typescript
import { hashOrderToken } from '@/lib/order-token';

// Example of logging a generated token hash
async function logTokenGeneration(token: string) {
  const hashedToken = await hashOrderToken(token);
  // Store hashedToken in an audit log table
  console.log(`Token generated: ${hashedToken}`);
}
```

This ensures that even if the audit logs are compromised, an attacker cannot reconstruct the original JWT to gain access to an order.
