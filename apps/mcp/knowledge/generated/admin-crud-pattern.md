## The Three-Component Architecture

The Fufuni framework standardizes admin interfaces through a compositional pattern. Every administrative management page follows a strict three-part architecture to ensure consistency across the store manager, inventory, and user management modules.

1.  **The Logic Hook (`useAdminCrud`):** A generic hook that manages the state of the data list (via TanStack Query), search/filtering, and the lifecycle of the creation/edit modal. It handles the API communication with the Hono backend.
2.  **The Shell (`AdminCrudLayout`):** A structural component that provides the page header (title, breadcrumbs, "Add" button), the filter/search bar, and the table container.
3.  **The Row Logic (`RowActions`):** A small UI component rendered in the final column of the data table. It encapsulates the "Edit" and "Delete" interactions, including a built-in confirmation popover for destructive actions.

### Basic Composition Example

```typescript
import { AdminCrudLayout } from "@/shared/ui/admin/admin-crud-layout";
import { RowActions } from "@/shared/ui/admin/row-actions";
import { useAdminCrud } from "@/hooks/use-admin-crud";
import type { ColumnDef } from "@tanstack/react-table";

export function AdminManagementPage() {
  const { 
    items, 
    isLoading, 
    openModal, 
    remove 
  } = useAdminCrud<Entity>({
    queryKey: ["admin", "entities"],
    listUrl: "/api/admin/entities",
    // ... URLs
  });

  const columns: ColumnDef<Entity>[] = [
    { accessorKey: "name", header: "Name" },
    {
      id: "actions",
      cell: ({ row }) => (
        <RowActions 
          onEdit={() => openModal(row.original)} 
          onDelete={() => remove(row.original.id)}
          deleteConfirmMessage="Are you sure you want to delete this entity?"
        />
      ),
    },
  ];

  return (
    <AdminCrudLayout
      title="Entities"
      addLabel="Add Entity"
      data={items}
      columns={columns}
      isLoading={isLoading}
      onAdd={() => openModal()}
      renderModal={(isOpen, onClose, selectedItem) => (
        <EntityModal isOpen={isOpen} onClose={onClose} item={selectedItem} />
      )}
    />
  );
}
```

## `useAdminCrud` Hook Configuration

The `useAdminCrud<T>` hook is the engine of the admin page. It abstracts TanStack Query's `useQuery` and `useMutation` into a simplified interface. It requires a generic type `T` which must extend `HasIdAndStatus`.

### Hook Options and Return Values

| Option | Type | Description |
| :--- | :--- | :--- |
| `queryKey` | `string[]` | The cache key for TanStack Query. |
| `listUrl` | `string` | The API endpoint for fetching items. |
| `createUrl` | `string` | The API endpoint for POST requests. |
| `updateUrl` | `string` | The API endpoint for PATCH/PUT requests. |
| `deleteUrl` | `string` | The API endpoint for DELETE requests. |
| `zodSchema` | `ZodSchema` | Optional schema for client-side validation. |

### Logic Example

```typescript
import { z } from "zod";
import { useAdminCrud } from "@/hooks/use-admin-crud";

const TagSchema = z.object({
  id: z.string().optional(),
  name: z.string().min(2),
  status: z.enum(["active", "inactive"]),
});

type Tag = z.infer<typeof TagSchema>;

export function useTagCrud() {
  return useAdminCrud<Tag>({
    queryKey: ["admin", "product-tags"],
    listUrl: "/api/admin/tags",
    createUrl: "/api/admin/tags",
    updateUrl: "/api/admin/tags/:id",
    deleteUrl: "/api/admin/tags/:id",
    zodSchema: TagSchema,
  });
}
```

## `AdminCrudLayout` and Table Definition

The `AdminCrudLayout` manages the visual hierarchy of the page. It utilizes HeroUI v3 components (`Card`, `Button`, `Input`) to provide a responsive interface.

### Column Definition Format
The framework uses TanStack Table's `ColumnDef`. For the "Status" column, always use a badge-style indicator for visual clarity.

export const getTagColumns = (

## Row Actions and Delete Confirmation

The `RowActions` component renders an icon-button group (`Edit2` and `Trash2` icons). Per verified facts, the delete confirmation is handled **inside** `RowActions` using a HeroUI Popover. This prevents accidental deletions without requiring a global modal manager.

```typescript
import { RowActions } from "@/shared/ui/admin/row-actions";

// Usage inside a Table Cell
<RowActions
  onEdit={() => openModal(item)}
  onDelete={() => handleRemove(item.id)}
  deleteConfirmMessage="This action cannot be undone. Delete this tag?"
/>
```

The component internally manages a `isOpen` state for the popover. When the user clicks the delete icon, the popover appears with "Cancel" and "Confirm" buttons. `onDelete` is only triggered after user confirmation.

## The Modal Pattern: Create vs Edit

The Fufuni framework uses a "Single Modal" pattern. The same modal component handles both creation and editing. The distinction is made by checking if the `selectedItem` (passed from `useAdminCrud`) exists.

1.  **Create Mode:** `selectedItem` is `null`. The form resets to default values.
2.  **Edit Mode:** `selectedItem` contains the object. The form prepopulates using the `values` or `defaultValues` prop in `react-hook-form`.

### Modal Implementation Pattern

```typescript
import { Modal, ModalContent, ModalHeader, ModalBody, ModalFooter, Button } from "@heroui/react";
import { useForm } from "react-hook-form";
import { zodResolver } from "@hookform/resolvers/zod";

interface EntityModalProps {
  isOpen: boolean;
  onClose: () => void;
  item: Entity | null;
  onSubmit: (data: Entity) => void;
}

export function EntityModal({ isOpen, onClose, item, onSubmit }: EntityModalProps) {
  const isEdit = !!item;
  const { register, handleSubmit, formState: { errors } } = useForm<Entity>({
    resolver: zodResolver(EntitySchema),
    defaultValues: item || { name: "", status: "active" }
  });

  return (
    <Modal isOpen={isOpen} onClose={onClose}>
      <ModalContent>
        <form onSubmit={handleSubmit(onSubmit)}>
          <ModalHeader>{isEdit ? "Edit Entity" : "Create Entity"}</ModalHeader>
          <ModalBody>
            {/* Form Fields using HeroUI Input */}
          </ModalBody>
          <ModalFooter>
            <Button variant="flat" onPress={onClose}>Cancel</Button>
            <Button type="submit" color="primary">Save</Button>
          </ModalFooter>
        </form>
      </ModalContent>
    </Modal>
  );
}
```

## Route Protection and RBAC

All admin features must be protected using the `AuthenticationGuardWithPermission`. This is configured at the router level (usually `app.tsx`), not inside the component. This ensures that the component logic never executes for unauthorized users.

The standard permission for store management is `admin:store`.

```typescript
// apps/client/src/app.tsx
import { AuthenticationGuardWithPermission } from "@/components/auth/guard";

const adminRoutes = [
  {
    path: "/admin/tags",
    element: (
      <AuthenticationGuardWithPermission permission="admin:store">
        <ProductTagsPage />
      </AuthenticationGuardWithPermission>
    ),
  },
];
```

## Worked Example: ProductTags Admin

This example demonstrates a complete implementation of the CRUD pattern for a `ProductTag` entity.

### 1. Schema Definition
```typescript
import { z } from "zod";

export const ProductTagSchema = z.object({
  id: z.string().optional(),
  name: z.string().min(1, "Name is required"),
  slug: z.string().min(1, "Slug is required"),
  status: z.enum(["active", "inactive"]),
});

export type ProductTag = z.infer<typeof ProductTagSchema>;
```

### 2. The CRUD Page Component
```typescript
import { AdminCrudLayout } from "@/shared/ui/admin/admin-crud-layout";
import { useAdminCrud } from "@/hooks/use-admin-crud";
import { RowActions } from "@/shared/ui/admin/row-actions";
import { Badge } from "@heroui/react";
import type { ColumnDef } from "@tanstack/react-table";
import { ProductTagSchema, type ProductTag } from "./schema";
import { TagModal } from "./tag-modal";

export default function ProductTagsPage() {
  const {
    items,
    isLoading,
    create,
    update,
    remove,
    isModalOpen,
    openModal,
    closeModal,
    selectedItem,
  } = useAdminCrud<ProductTag>({
    queryKey: ["admin", "product-tags"],
    listUrl: "/api/admin/product-tags",
    createUrl: "/api/admin/product-tags",
    updateUrl: "/api/admin/product-tags/:id",
    deleteUrl: "/api/admin/product-tags/:id",
    zodSchema: ProductTagSchema,
  });

  const columns: ColumnDef<ProductTag>[] = [
    { accessorKey: "name", header: "Name" },
    { accessorKey: "slug", header: "Slug" },
    {
      accessorKey: "status",
      header: "Status",
      cell: ({ getValue }) => (
        <Badge color={getValue() === "active" ? "success" : "danger"}>
          {getValue() as string}
        </Badge>
      ),
    },
    {
      id: "actions",
      cell: ({ row }) => (
        <RowActions
          onEdit={() => openModal(row.original)}
          onDelete={() => remove(row.original.id)}
          deleteConfirmMessage={`Delete tag "${row.original.name}"?`}
        />
      ),
    },
  ];

  const handleFormSubmit = (data: ProductTag) => {
    if (selectedItem) {
      update({ id: selectedItem.id!, data });
    } else {
      create(data);
    }
    closeModal();
  };

  return (
    <AdminCrudLayout
      title="Product Tags"
      subtitle="Manage taxonomy for your products"
      addLabel="New Tag"
      onAdd={() => openModal()}
      data={items}
      columns={columns}
      isLoading={isLoading}
      renderModal={(isOpen, onClose) => (
        <TagModal
          isOpen={isOpen}
          onClose={onClose}
          item={selectedItem}
          onSubmit={handleFormSubmit}
        />
      )}
    />
  );
}
```
