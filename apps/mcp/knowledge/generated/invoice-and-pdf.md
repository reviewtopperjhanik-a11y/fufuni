## PDF Generation Engine

Fufuni generates invoice PDFs entirely on the client side to minimize server load and ensure privacy. The system uses **jsPDF** for document orchestration and **jsPDF-AutoTable** for rendering itemized lists.

The core logic resides in `generateInvoice()`, which does not trigger a download directly but returns a `jsPDF` instance. This allows the caller to decide whether to save the file, open it in a new tab, or preview it.

### Document Lifecycle Example

```typescript
import { generateInvoice } from "@/lib/invoice-generator";
import { useTranslation } from "react-i18next";

const MyComponent = ({ order, storeInfo }) => {
  const { t } = useTranslation();

  const handleDownload = () => {
    // 1. Generate the document instance
    const doc = generateInvoice(order, storeInfo, t);
    
    // 2. Trigger browser download
    doc.save(`invoice-${order.number}.pdf`);
  };

  const handlePreview = () => {
    const doc = generateInvoice(order, storeInfo, t);
    
    // 3. Open in a new browser tab as a Blob URI
    window.open(doc.output("bloburi"), "_blank");
  };

  return (
    <div className="flex gap-4">
      <button onClick={handleDownload}>Download PDF</button>
      <button onClick={handlePreview}>Preview PDF</button>
    </div>
  );
};
```

## Invoice Content & Structure

An invoice in Fufuni follows a strict professional layout. When modifying the generator, ensure sections are rendered in the following order:

1.  **Store Header**: Includes the store logo (base64) on the left and store name/address on the right.
2.  **Customer Info**: Billing and shipping details (Name, Email, Physical Address).
3.  **Metadata**: Order number, date, and payment method used.
4.  **Itemized Table**: 
    *   Product Title
    *   Quantity
    *   Unit Price (tax inclusive/exclusive based on store settings)
    *   Tax per line
    *   Total per line
5.  **Totals Section**: 
    *   Subtotal (before tax)
    *   Itemized taxes (GST, VAT, etc.)
    *   Shipping costs
    *   Grand Total

### Table Configuration Example

```typescript
import autoTable from "jspdf-autotable";

// Inside generateInvoice(order, storeInfo, t)

      formatCurrency(item.total_price_cents, order.currency)
    ]),

  });
};
```

## Currency Formatting

Fufuni uses a centralized utility for all monetary displays. All values in the database and API are stored in the **smallest unit** (cents). The `formatCurrency` utility handles the conversion and localization using the `Intl.NumberFormat` API.

### Monetary Utility Implementation

```typescript
/**
 * Formats a cent amount into a localized currency string.
 * @param cents - The amount in the smallest currency unit (e.g., 2999)
 * @param currency - ISO 4217 code (e.g., "EUR")
 * @param locale - BCP 47 tag (defaults to browser locale)
 */
export function formatCurrency(
  cents: number,
  currency: string,
  locale: string = "en-US"
): string {
  const amount = cents / 100;
  
  return new Intl.NumberFormat(locale, {
    style: "currency",
    currency: currency.toUpperCase(),
    currencyDisplay: "narrowSymbol",
  }).format(amount);
}

// Usage in UI or PDF
const displayPrice = formatCurrency(1500, "USD"); // "$15.00"
```

## Order-View Tokens & Public Access

Invoices are often accessed by customers who are not logged in (e.g., via an email link). Fufuni uses a **signed token system** to provide secure, temporary access to specific order data.

1.  **Generation**: The server provides a token via `GET /v1/orders/:id/invoice`.
2.  **TTL**: The token is valid for exactly **1 hour**.
3.  **Access**: The public route `/order-view/:token` uses this token to fetch order details.

### Server-side Token Retrieval

```typescript
// Backend (Hono) implementation for fetching the token
// This is called by the Admin or Customer dashboard to generate a sharing link
app.get("/v1/orders/:id/invoice", async (c) => {
  const orderId = c.req.param("id");
  const order = await c.get('db').orders.getById(orderId);
  
  // Sign a token with a 1h expiration including the order ID
  const token = await signOrderViewToken(order.id, c.env.JWT_SECRET);
  
  return c.json({
    view_url: `${c.env.FRONTEND_URL}/order-view/${token}`,
    expires_at: Date.now() + 3600000
  });
});
```

## Public Order-View Page

The Order-View page is a dedicated React route that requires no authentication. It extracts the token from the URL, calls the public viewing endpoint, and renders the invoice interface.

### Public Fetching Logic

```typescript
import { useParams } from "react-router-dom";
import { useQuery } from "@tanstack/react-query";

const OrderViewPage = () => {
  const { token } = useParams<{ token: string }>();

  const { data: order, isLoading } = useQuery({
    queryKey: ["order-view", token],
    queryFn: async () => {
      // Calls the specific public endpoint for token-based access
      const res = await fetch(`/v1/orders/view/${token}`);
      if (!res.ok) throw new Error("Invalid or expired token");
      return res.json();
    }
  });

  if (isLoading) return <Spinner />;
  if (!order) return <p>Order not found</p>;

  return (
    <div className="container mx-auto p-8">
      <InvoiceHeader order={order} />
      <InvoiceItems items={order.items} />
      <button onClick={() => downloadInvoicePdf(order)}>
        Download Invoice
      </button>
    </div>
  );
};
```

## Store Logo & Branding

Store branding is retrieved from the `store_settings` table. The logo is stored as a **base64 data URI**.

### Handling the Logo in PDF

When generating the PDF, the system checks for the existence of the logo. If missing, it falls back to a text-based header using the store name.

```typescript
const addStoreHeader = (doc: jsPDF, storeInfo: StoreSettings) => {
  if (storeInfo.logo_base64) {
    // Parameters: dataUri, format, x, y, width, height
    doc.addImage(storeInfo.logo_base64, "PNG", 14, 10, 40, 20);
  } else {
    // Fallback to Bold Text Store Name
    doc.setFont("helvetica", "bold");
    doc.setFontSize(22);
    doc.text(storeInfo.name, 14, 20);
  }
};
```

## Adding a New Invoice Field

To add a new field (e.g., "VAT Number") to the invoice, you must update three specific areas:

1.  **Types**: Add the field to the `InvoiceData` interface in `apps/client/src/lib/invoice-generator.ts`.
2.  **Rendering Logic**: Update the `generateInvoice` function to calculate the position (`yPosition`) and render the new field using `doc.text()`.
3.  **Translations**: Add the corresponding `invoice-vat-number` key to the translation JSON files.

### Modification Example

```typescript
// 1. In apps/client/src/lib/invoice-generator.ts
interface InvoiceData {
  // ... existing fields
  vatNumber?: string; 
}

// 2. In the rendering logic
if (data.vatNumber) {
  doc.setFontSize(10);
  doc.text(`${t("invoice-vat")}: ${data.vatNumber}`, margin, yPosition);
  yPosition += 5;
}
```
