## Discount Types and Schema

Fufuni supports three primary discount strategies. These are stored in the `discounts` table and synchronized with Stripe for checkout compatibility when a Stripe secret key is configured. All monetary values within these records are handled as integers (smallest currency unit, typically cents).

### Supported Discount Types
1.  **Percentage**: A 0–100% reduction applied to the applicable items or subtotal.
2.  **Fixed Amount**: A specific currency value subtracted from the subtotal (e.g., $10.00 off).
3.  **Free Shipping**: Removes the shipping cost from the total calculation.

### Discount Record structure
The following interface defines the structure used by both the backend and the Durable Object for validation:

```typescript
export type DiscountType = 'percentage' | 'fixed_amount' | 'free_shipping';

export interface Discount {
  id: string;
  code: string;                 // The uppercase alphanumeric coupon code
  type: DiscountType;
  value: number;                // Percentage (e.g. 20) or Cents (e.g. 1000)
  currency: string | null;      // ISO 4217 code (required for fixed_amount)
  minOrderAmount: number;       // Minimum subtotal in cents to qualify
  maxUses: number | null;       // Global usage limit
  current_uses: number;         // Atomic counter of successful applications
  validFrom: string | null;     // ISO date string
  validUntil: string | null;    // ISO date string
  productIds: string[] | null;  // Optional: Restrict discount to specific products
  status: 'active' | 'inactive';
}
```

## Administrative Discount Management

## Public Validation Endpoint

Before a checkout is initiated, the frontend calls the public validation endpoint to check if a code is applicable to the current cart state.

### POST /v1/discounts/validate
This endpoint checks for existence, expiration, and order minimums. It returns a 422 Unprocessable Entity if the code is invalid or exhausted.

```typescript
// Validation request and response
// URL: POST /v1/discounts/validate
// Body: { "code": "SUMMER2025", "cartId": "...", "subtotal": 5000 }

export async function validateDiscount(
  db: Database,
  discount: Discount,
  subtotalCents: number
): Promise<{ applicableAmount: number; newTotal: number }> {
  const now = new Date().toISOString();

  if (discount.status !== 'active') throw ApiError.unprocessable('Code is disabled');
  if (discount.validFrom && now < discount.validFrom) throw ApiError.unprocessable('Not yet active');
  if (discount.validUntil && now > discount.validUntil) throw ApiError.unprocessable('Code expired');
  if (subtotalCents < discount.minOrderAmount) {
    throw ApiError.unprocessable(`Minimum order of $${(discount.minOrderAmount / 100).toFixed(2)} required`);
  }
  
  if (discount.maxUses !== null && discount.current_uses >= discount.max_uses) {
    throw ApiError.unprocessable('Discount usage limit reached');
  }

  // Calculation Logic
  let discountAmount = 0;
  if (discount.type === 'percentage') {
    discountAmount = Math.floor((subtotalCents * discount.value) / 100);
  } else if (discount.type === 'fixed_amount') {
    discountAmount = Math.min(discount.value, subtotalCents);
  }

  return {
    applicableAmount: discountAmount,
    newTotal: subtotalCents - discountAmount
  };
}
```

## Atomic Usage Counting

Fufuni prevents "race condition" double-redemptions by performing usage increments inside the Durable Object's SQLite transaction during order finalization.

If two customers attempt to use the last remaining slot of a discount code simultaneously, the transaction ensures that only one succeeds.

```typescript
/**
 * Atomic increment within a Durable Object transaction
 */
async function finalizeDiscountUsage(db: Database, discountId: string) {
  return await db.transaction(async (tx) => {
    const [discount] = await tx.query<Discount>(
      'SELECT current_uses, max_uses FROM discounts WHERE id = ?',
      [discountId]
    );

    if (discount.max_uses !== null && discount.current_uses >= discount.max_uses) {
      throw new Error('Discount exhausted during finalization');
    }

    await tx.run(
      'UPDATE discounts SET current_uses = current_uses + 1 WHERE id = ?',
      [discountId]
    );
  });
}
```

## The Pricing Pipeline

Fufuni follows a strict 4-step sequence for calculating the final amount a customer pays. This ensures that taxes are correctly calculated on the net amount and that tiered pricing is respected before discounts.

### Calculation Order
1.  **Base Price**: Retrieve the raw price from `variant_prices` based on the selected currency.
2.  **Tier Pricing**: Apply bulk discounts if the quantity meets specific thresholds (e.g., 10% off for 10+ items).
3.  **Discount Application**: Subtract the fixed or percentage discount from the calculated subtotal.
4.  **Tax Computation**: Calculate taxes (VAT/Sales Tax) based on the **discounted subtotal**.

```typescript
async function calculateFinalPrice(cartItems: any[], discountCode?: string) {
  // 1. Base Price & 2. Tier Pricing
  let subtotal = 0;
  for (const item of cartItems) {
    const base = await resolveVariantPrice(db, item.variantId, currencyId);
    const tiered = applyTierPricing(base, item.quantity); // Logic for volume-based pricing
    subtotal += tiered * item.quantity;
  }

  // 3. Discount Application
  let discountAmount = 0;
  if (discountCode) {
    const discount = await getDiscountByCode(db, discountCode);
    discountAmount = calculateDiscount(discount, subtotal);
  }
  const netTotal = subtotal - discountAmount;

  // 4. Tax Computation
  const taxRate = 0.20; // Example: 20% VAT
  const taxAmount = Math.round(netTotal * taxRate);
  
  return {
    subtotal,
    discountAmount,
    netTotal,
    taxAmount,
    grandTotal: netTotal + taxAmount
  };
}
```

## Pricing Helper Functions (`lib/pricing.ts`)

The framework provides a set of strict helpers to ensure multi-currency consistency. Prices are never converted on the fly; they must be explicitly defined for each currency in the `variant_prices` or `shipping_rate_prices` tables.

### Key Signatures and Usage

| Function | Purpose | Example |
| :--- | :--- | :--- |
| `resolveVariantPrice` | Fetches explicit price for a variant + currency. | `await resolveVariantPrice(db, vId, cId)` |
| `resolveShippingPrice`| Fetches explicit shipping cost for a region. | `await resolveShippingPrice(db, sId, cId)` |
| `getCurrencyIdFromCode`| Maps ISO code (USD) to Internal UUID. | `await getCurrencyIdFromCode(db, 'EUR')` |

```typescript
// Example: Strict multi-currency resolution
import { resolveVariantPrice, getCurrencyIdFromCode } from '../lib/pricing';

const eurId = await getCurrencyIdFromCode(db, 'EUR');
if (!eurId) throw ApiError.notFound('Currency EUR not supported');

try {
```

## Currency Handling and Localization

Fufuni treats the backend as a "math only" zone. To avoid floating point inaccuracies, all calculations are done with integers.

### 1. Integer Cents Storage
All columns like `price_cents`, `amount_cents`, or `min_purchase_cents` are stored as `INTEGER` in SQLite. 
*   $10.00 -> `1000`
*   €15.50 -> `1550`
*   ¥1000  -> `1000` (Note: Zero-decimal currencies still use the integer as-is).

### 2. ISO 4217 Codes
The `currencies` table stores the ISO 4217 code (e.g., `USD`, `GBP`, `JPY`). This code is sent to the client alongside the integer amounts.

### 3. Client-side Formatting
The React frontend uses `Intl.NumberFormat` to display prices based on the currency code provided by the API.

```typescript
/**
 * React Component for Price Display
 */
export function PriceDisplay({ amount, currencyCode }: { amount: number; currencyCode: string }) {
  const formatted = new Intl.NumberFormat('en-US', {
    style: 'currency',
    currency: currencyCode,
  }).format(amount / 100);

  return <span className="font-bold text-primary">{formatted}</span>;
}

// Usage in HeroUI v3 Card:
// <PriceDisplay amount={2999} currencyCode="USD" /> -> $29.99
```
