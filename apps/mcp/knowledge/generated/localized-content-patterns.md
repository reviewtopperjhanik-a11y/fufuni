## LocalizedText Structure and Storage

In Fufuni, localization is handled by storing a JSON object within a `TEXT` column in the SQLite (Durable Objects) database. This object, typed as `LocalizedDesc` (referred to as `LocalizedText` in high-level documentation), maps IETF BCP 47 language tags to their respective string values.

Legacy data might still exist as plain strings. The framework utilities are designed to detect if a string starts with `{` and attempt to parse it as JSON; otherwise, they treat the raw string as a fallback for all locales.

```typescript
/**
 * LocalizedText (internal name LocalizedDesc)
 * Maps locale codes (e.g., "en-US") to content strings.
 */
export type LocalizedText = Record<string, string>;

// Example of how data is stored in the 'products.description' or 'products.title' column:
// {
//   "en-US": "Blue Suede Shoes",
//   "fr-FR": "Chaussures en daim bleu",
//   "zh-CN": "蓝色麂皮鞋"
// }

import { parseDescription, isLocalized } from "@/utils/description";

const rawDbValue = '{"en-US": "Hello", "fr-FR": "Bonjour"}';

if (isLocalized(rawDbValue)) {
  const parsed = parseDescription(rawDbValue) as LocalizedText;
  console.log(parsed["fr-FR"]); // "Bonjour"
}
```

### Fallback Chain Mechanics
Fufuni uses a hardcoded fallback chain to ensure the user always sees content, even if the specific requested locale is missing. The sequence is:
1. Requested Locale (e.g., user's browser language).
2. `en-US`
3. `fr-FR`
4. `es-ES`
5. `zh-CN`
6. `ar-SA`
7. `he-IL`

## Resolution with getLocalizedText

The `getLocalizedText` pattern (implemented via `resolveDescription`, `resolveTitle`, etc.) is the primary way to retrieve a displayable string. It abstracts the complexity of checking for JSON, parsing it, and walking the fallback chain.

```typescript
import { resolveDescription, resolveTitle } from "@/utils/description";

/**
 * signature: getLocalizedText(raw: string, locale: string): string
 * Note: In the codebase, specialized versions exist for different safety requirements.
 */

const productTitle = '{"en-US": "Pro Camera", "es-ES": "Cámara Pro"}';

// Usage in a component:
const currentLocale = "fr-FR"; 
const displayTitle = resolveTitle(productTitle, currentLocale); 
// Returns "Pro Camera" because fr-FR is missing, and en-US is the first fallback.

const description = "Normal plain text description";
const displayDesc = resolveDescription(description, currentLocale);
// Returns "Normal plain text description" (legacy support).
```

## Rich-Text vs Plain-Text Safety

Fufuni distinguishes between fields that allow HTML (like product descriptions) and fields that must be plain-text (like titles, vendors, or tax names).

### renderDescription()
When displaying descriptions, we assume the content is HTML. The backend provides sanitized HTML, but the frontend must use `dangerouslySetInnerHTML` to render the rich text. 

### stripHtml()
For contexts like SEO `<meta>` tags, window titles, or PDF invoices, HTML tags must be removed. The `stripHtml` utility removes tags and escapes remaining angle brackets.

```typescript
import { resolveDescription, stripHtml } from "@/utils/description";

interface DescriptionProps {
  rawDescription: string;
  locale: string;
}

export const ProductDescription = ({ rawDescription, locale }: DescriptionProps) => {
  const htmlContent = resolveDescription(rawDescription, locale);
  const plainTextFallback = stripHtml(htmlContent).substring(0, 160);

  return (
    <div>
      {/* 1. Rich Text Rendering */}
      <div 
        className="prose dark:prose-invert"
        dangerouslySetInnerHTML={{ __html: htmlContent }} 
      />

      {/* 2. Plain Text usage (e.g., for ARIA labels or Tooltips) */}
      <button aria-label={`Read more about ${plainTextFallback}`}>
        Details
      </button>
    </div>
  );
};
```

## useLocalizedTextInput Hook

The `useLocalizedTextInput` hook is the standard pattern for managing localized fields in Admin forms. It handles the "per-locale" state, AI translations, and the migration of legacy plain-text data into the JSON format.

### Props and Logic
- `value`: The raw string from the database.
- `onChange`: Callback to update the parent state (usually a Zod-validated form).
- `selectedLocale`: The locale currently being edited in the UI.
- `parseFn / mergeFn / getFn`: Format-specific helpers from `description.ts`.

### AI Translation
The hook integrates with the Fufuni AI subsystem. It calls `/v1/ai/parameters` to get the current AI configuration and uses the `translateWithAi` utility to fill empty fields based on existing translations in other languages.

```tsx
import { Input, Button, Spinner } from "@heroui/react";
import { useLocalizedTextInput } from "@/hooks/use-localized-text-input";
import { 
  parseTitle, 
  mergeTitleLocale, 
  getTitleForLocale 
} from "@/utils/description";

export const LocalizedTitleInput = ({ 
  value, 
  onChange, 
  locale 
}: { 
  value: string; 
  onChange: (val: string) => void; 
  locale: string; 
}) => {
  const {
    inputValue,
    isTranslating,
    canUseAi,
    isRTL,
    handleInputChange,
    handleAiTranslate
  } = useLocalizedTextInput({
    value,
    onChange,
    selectedLocale: locale,
    parseFn: parseTitle,
    mergeFn: mergeTitleLocale,
    getFn: getTitleForLocale,
  });

  return (
    <div className="flex flex-col gap-2">
      <Input
        label={`Title (${locale})`}
        value={inputValue}
        onValueChange={handleInputChange}
        dir={isRTL ? "rtl" : "ltr"}
      />
      {canUseAi && (
        <Button 
          size="sm" 
          onPress={handleAiTranslate} 
          disabled={isTranslating}
        >
          {isTranslating ? <Spinner size="sm" /> : "Translate with AI"}
        </Button>
      )}
    </div>
  );
};
```

## Rich-Text HTML Storage

Rich-text content generated by editors (like TipTap or Quill) is stored as standard HTML strings. When bundled into a `LocalizedText` object, these HTML strings are JSON-escaped.

**Example Database Content:**
```sql
-- What the SQLite 'description' column actually looks like
'{"en-US": "<p>High quality <strong>leather</strong></p>", "fr-FR": "<p>Cuir de <strong>haute qualité</strong></p>"}'
```

When updating rich text, the framework follows this flow:
1. The Editor emits an HTML string.
2. `mergeLocale(raw, locale, html)` is called.
3. If `raw` was a plain string `"Old description"`, it becomes `{"en-US": "Old description", "[new-locale]": "[new-html]"}`.
4. The result is `JSON.stringify`'d and sent to the Hono API.

## Adding a New Locale to Admin Forms

To support a new language in the administration interface, follow these steps to ensure the UI renders the appropriate tabs and inputs.

### 1. Update i18n Configuration
Ensure the locale is defined in `apps/client/src/i18n/index.ts` so `availableLanguages` includes it.

### 2. Implement the Multi-Locale Layout
Use HeroUI `Tabs` to allow the admin to switch between languages. The `useLocalizedTextInput` hook will automatically respond to the `selectedLocale` change.

```tsx
import { useState } from "react";
import { Tabs, Tab, Card, CardBody } from "@heroui/react";
import { availableLanguages } from "@/i18n";

export const ProductDescriptionManager = ({ 
  rawDesc, 
  setRawDesc 
}: { 
  rawDesc: string, 
  setRawDesc: (v: string) => void 
}) => {
  const [activeLocale, setActiveLocale] = useState("en-US");

  return (
    <div className="flex w-full flex-col">
      <Tabs 
        aria-label="Options" 
        selectedKey={activeLocale} 
        onSelectionChange={(key) => setActiveLocale(key as string)}
      >
        {availableLanguages.map((lang) => (
          <Tab key={lang.code} title={lang.name}>
            <Card>
              <CardBody>
                {/* 
                   This child component uses useLocalizedTextInput 
                   internally to manage the specific language key.
                */}
                <RichTextEditor 
                  value={rawDesc}
                  onChange={setRawDesc}
                  locale={lang.code}
                />
              </CardBody>
            </Card>
          </Tab>
        ))}
      </Tabs>
    </div>
  );
};
```

### 3. Data Migration on Switch
When an admin switches to a new tab (e.g., from `en-US` to `de-DE`) and starts typing, the `useLocalizedTextInput` hook detects that the German key doesn't exist yet. It uses `mergeFn` to create the JSON structure, preserving the `en-US` value as the primary fallback within the object. This ensures that adding one translation doesn't accidentally wipe out legacy plain-text data for other languages.
