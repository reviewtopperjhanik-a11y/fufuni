## Authentication Patterns

### Token Types
Fufuni accepts **three token formats** in the `Authorization: Bearer <token>` header:

1. **Auth0 JWT** (3 dot-separated parts)
   - Validated against the tenant's JWKS (`AUTH0_DOMAIN`).
   - Must include the audience claim matching `AUTH0_AUDIENCE`.
   - Admin access requires the permission set in `ADMIN_STORE_PERMISSION` (default: `admin:store`).

2. **Admin API Key** (`sk_` prefix)
   - Stored hashed in the `api_keys` table.
   - Role is read directly from the database.

3. **OAuth Token** (64-char lowercase hex)
   - Stored hashed in the `oauth_tokens` table.
   - Role is always `"oauth"`.
   - Scopes are checked via `requireScope()`.

---

### AuthRole Values
The `role` field in `c.var.auth` (or `useAuth().role`) can be:

| Role            | Assigned When                                                                 |
|-----------------|-------------------------------------------------------------------------------|
| `"public"`      | No token provided (unauthenticated).                                          |
| `"admin"`       | Auth0 JWT with `admin:store` permission **or** `sk_` API key with role `"admin"`. |
| `"oauth"`       | 64-char hex OAuth token (scopes checked separately).                           |
| `"authadmin"`   | Auth0 JWT with `auth0:admin:api` permission.                                 |
| `"databaseadmin"` | Auth0 JWT with `admin:database` permission.                                |
| `"aiadmin"`     | Auth0 JWT with `ai:api` permission.                                          |
| `"mail"`        | Auth0 JWT with `mail:api` permission.                                        |
| `"customer"`    | Auth0 JWT **without** admin permissions (customer-only routes).               |

### Backend RBAC Guards
All guards are middleware factories in `apps/merchant/src/middleware/auth.ts`:

| Guard                     | Checks Role(s)               | Typical Use Case                                                                 |
|---------------------------|------------------------------|---------------------------------------------------------------------------------|
| `adminOnly`               | `"admin"`                    | Admin dashboard routes (e.g., `/v1/admin/products`).                            |
| `superAdminOnly`          | `"authadmin"`                | Auth0 Management API access (e.g., `/v1/__auth0/token`).                       |
| `databaseAdminOnly`       | `"databaseadmin"`            | Database maintenance routes (e.g., `/v1/__db/backup`).                         |
| `aiAccessOnly`            | `"aiadmin"`                  | AI API routes (e.g., `/v1/ai/translate`).                                       |
| `mailAccessOnly`          | `"mail"`                     | Mailgun API proxy routes (e.g., `/v1/mail/send`).                               |
| `validJwtAuthOnly`        | Any valid Auth0 JWT          | Customer-facing routes that reject API keys (e.g., `/v1/me/orders`).           |
| `requireScope(...scopes)` | OAuth token with all scopes  | OAuth-protected routes (e.g., `requireScope("read:profile", "write:orders")`). |

### Backend Examples

#### 1. Protecting a Route with `authMiddleware` + `adminOnly`
```typescript
// apps/merchant/src/routes/admin/products.ts
import { Hono } from 'hono';
import { authMiddleware, adminOnly } from '../../middleware/auth';
import { getDb } from '../../db';

const app = new Hono();

app.use('*', authMiddleware);  // Authenticate first
app.use('*', adminOnly);       // Then authorize

app.get('/', async (c) => {
  const db = getDb(c.var.db);
  const products = await db.query('SELECT * FROM products LIMIT 100');
  return c.json({ products });
});

export default app;
```

#### 2. `superAdminOnly` and the Auth0 Management API Endpoint
```typescript
// apps/merchant/src/routes/__auth0/token.ts
import { Hono } from 'hono';
import { authMiddleware, superAdminOnly } from '../../middleware/auth';
import { getAuth0ManagementToken } from '../../lib/auth0';

const app = new Hono();

app.use('*', authMiddleware);
app.use('*', superAdminOnly);  // Requires "authadmin" role

app.get('/', async (c) => {
  const token = await getAuth0ManagementToken(c.env);
  return c.json({ access_token: token });
});

export default app;
```

#### 3. Customer-Scoped Routes with `customerAuthMiddleware`
```typescript
// apps/merchant/src/routes/me/orders.ts
import { Hono } from 'hono';
import { customerAuthMiddleware } from '../../middleware/customer-auth';

const app = new Hono();

app.use('*', customerAuthMiddleware);  // Only Auth0 JWTs (no API keys)

app.get('/', async (c) => {
  const { sub, email } = c.var.auth;
  // Fetch orders for this customer...
  return c.json({ userId: sub, email, orders: [] });
});

export default app;
```

### Frontend Guards
Frontend auth utilities live in `apps/storefront/src/lib/auth.ts` and `apps/storefront/src/components/guards`.

| Utility                          | Usage                                                                                     |
|----------------------------------|-------------------------------------------------------------------------------------------|
| `<AuthenticationGuard>`          | Wrap a **page** to redirect unauthenticated users to Auth0 login.                        |
| `<AuthenticationGuardWithPermission>` | Conditionally render **UI elements** based on a permission (e.g., "admin:store").      |
| `hasPermission(permission)`     | Async check from `useSecuredApi()` (e.g., before calling an admin API).                  |
| `isAuthenticated`                | Sync boolean from `useAuth()` (e.g., to toggle login/logout buttons).                     |

#### Example: Protecting a Page
```tsx
// apps/storefront/src/pages/admin/dashboard.tsx
import { AuthenticationGuard } from '@/components/guards';

function AdminDashboard() {
  return <div>Admin Dashboard</div>;
}

export default function Page() {
  return (
    <AuthenticationGuard component={AdminDashboard} />
  );
}
```

#### Example: Permission-Based UI
```tsx
// apps/storefront/src/components/admin/DeleteProductButton.tsx
import { AuthenticationGuardWithPermission } from '@/components/guards';

export function DeleteProductButton({ productId }: { productId: string }) {
  return (
    <AuthenticationGuardWithPermission
      permission="admin:products:delete"
      fallback={null}
    >
      <button onClick={() => deleteProduct(productId)}>Delete</button>
    </AuthenticationGuardWithPermission>
  );
}
```

#### Example: Async Permission Check
```tsx
// apps/storefront/src/pages/admin/products.tsx
import { useSecuredApi } from '@/lib/api';

function ProductsPage() {
  const { hasPermission } = useSecuredApi();

  const handleExport = async () => {
    const canExport = await hasPermission('admin:products:export');
    if (!canExport) {
      toast.error('You lack export permissions');
      return;
    }
    // Proceed with export...
  };

  return <button onClick={handleExport}>Export CSV</button>;
}
```

### Managing Permissions
- **Auth0 Dashboard**: Primary source of truth for permissions. Use for bulk changes.
- **UsersAndPermissionsPage** (`/admin/users-and-permissions`):
  - Allows admins to **add/remove permissions** for individual users **without leaving the storefront**.
  - Uses the Auth0 Management API (via `/v1/__auth0/token`).
  - Example: Granting a support user the `mail:api` permission.
- **Deploy Script**: Provisions all Auth0 resources (permissions, actions, etc.):
  ```bash
  pnpm exec tsx scripts/auth0/deploy-tenant-resources.ts
  ```

### OAuth Scope Validation
Use the `requireScope` factory to protect OAuth-scoped routes:
```typescript
// apps/merchant/src/routes/oauth/profile.ts
import { Hono } from 'hono';
import { authMiddleware, requireScope } from '../../middleware/auth';

const app = new Hono();

app.use('*', authMiddleware);
app.use('*', requireScope('read:profile'));  // Requires OAuth token with "read:profile"

app.get('/', (c) => {
  return c.json({ profile: c.var.auth.customerEmail });
});

export default app;
```
