## Supported Token Formats

Fufuni's `authMiddleware` is a polymorphic validator. It identifies and verifies identity based on the structure of the `Authorization: Bearer <token>` header.

| Token Type | Identification Logic | Validation Method | Typical Use Case |
| :--- | :--- | :--- | :--- |
| **Auth0 JWT** | 3-part string (header.payload.signature) | Verified against Auth0 JWKS using `AUTH0_DOMAIN`. | Browser-based admin dashboard or customer app. |
| **Admin API Key** | Starts with `sk_` | SHA-256 hash lookup in the `api_keys` table. | Server-to-server integrations or CLI tools. |
| **OAuth Token** | 64-char lowercase hex string | Lookup in `oauth_tokens` table with expiry check. | Third-party integrations (e.g., Zapier, specialized bots). |

### Example: Manual API Key Generation
If you need to programmatically generate a new secret key for an integration:

```typescript
import { generateApiKey, hashKey } from './middleware/auth';
import { getDb } from './db';

async function createNewAdminKey(c: Context) {
  const rawKey = generateApiKey('sk'); // e.g., sk_...
  const hashedKey = await hashKey(rawKey);
  const db = getDb(c.var.db);

  await db.run(
    'INSERT INTO api_keys (key_hash, role, created_at) VALUES (?, ?, ?)',
    [hashedKey, 'admin', new Date().toISOString()]
  );

  return rawKey; // Return the raw key ONLY ONCE to the user
}
```

## Backend RBAC Guards and AuthRoles

The framework maps Auth0 permissions (claims within the JWT) or database roles to the `AuthRole` type. RBAC is managed exclusively in the Auth0 dashboard for users, while API keys are managed in the SQLite database.

### AuthRole Mapping Table

| Role | Required Auth0 Permission | Guard Middleware |
| :--- | :--- | :--- |
| `admin` | `admin:store` (or `ADMIN_STORE_PERMISSION`) | `adminOnly` |
| `authadmin` | `auth0:admin:api` (or `ADMIN_AUTH0_PERMISSION`) | `superAdminOnly` |
| `databaseadmin` | `admin:database` (or `DATABASE_PERMISSION`) | `databaseAdminOnly` |
| `aiadmin` | `ai:api` (or `AI_PERMISSION`) | `aiAccessOnly` |
| `mail` | `mail:api` (or `MAIL_PERMISSION`) | `mailAccessOnly` |
| `customer` | None (Any valid Auth0 JWT) | `customerAuthMiddleware` |
| `oauth` | N/A (Uses Scopes) | `requireScope('scope_name')` |

### Protecting Routes with Multiple Guards
Guards must be placed *after* the `authMiddleware` has populated the `c.var.auth` context.

```typescript
import { Hono } from 'hono';
import { authMiddleware, adminOnly, aiAccessOnly } from './middleware/auth';
import type { HonoEnv } from './types';

const app = new Hono<HonoEnv>();

// 1. First, authenticate the request
// 2. Then, ensure the user has the 'admin' role
// 3. Finally, ensure the user specifically has AI access permissions
app.post('/v1/ai/translate', 
  authMiddleware, 
  adminOnly, 
  aiAccessOnly, 
  async (c) => {
    // Handler logic here
    return c.json({ success: true });
  }
);
```

## Superadmin and the Management API

The `superAdminOnly` guard (requiring the `auth0:admin:api` permission) protects sensitive infrastructure routes. One critical endpoint is `GET /v1/__auth0/token`, which provides an Auth0 Management API token. This token is cached internally to prevent exhausting Auth0 M2M quotas.

```typescript
import { Hono } from 'hono';
import { authMiddleware, superAdminOnly } from './middleware/auth';
import { ApiError } from './types';

const auth0Internal = new Hono<HonoEnv>();

// This route allows the frontend UsersAndPermissionsPage to fetch 
// a token used to talk directly to Auth0 for user management.
auth0Internal.get('/token', authMiddleware, superAdminOnly, async (c) => {
  const token = await c.var.db.query<any>(
    "SELECT value FROM internal_cache WHERE key = 'auth0_m2m_token' AND expires_at > ?",
    [new Date().toISOString()]
  );

  if (token.length === 0) {
    // Logic to refresh token from Auth0 would go here
    throw ApiError.internalServerError('Management token not in cache');
  }

  return c.json({ access_token: token[0].value });
});
```

## Customer Authentication Pattern

`customerAuthMiddleware` is designed for public-facing storefronts where customers log in via Auth0. Unlike the standard `authMiddleware`, it **rejects all API keys (`sk_`, `pk_`)** and does not require specific admin permissions. It extracts the `sub` (Auth0 ID) and `email` to identify the specific customer.

```typescript
import { Hono } from 'hono';
import { customerAuthMiddleware } from './middleware/customer-auth';
import { getDb } from './db';

const meRouter = new Hono<HonoEnv>();

meRouter.use('*', customerAuthMiddleware);

// Retrieve the profile of the currently logged-in customer
meRouter.get('/profile', async (c) => {
  const auth = c.get('auth');
  const db = getDb(c.var.db);

  // Use the 'sub' claim from Auth0 to find our local customer record
  const customer = await db.query(
    'SELECT * FROM customers WHERE auth0_sub = ? LIMIT 1',
    [auth.sub]
  );

  return c.json(customer[0] || { email: auth.email });
});
```

## Frontend Guards and Conditional UI

Fufuni utilizes React 19 components to synchronize UI visibility with backend permissions.

### Component-Level Protection
- **`AuthenticationGuard`**: Used at the route level. If the user is not logged in, it triggers an Auth0 redirect.
- **`AuthenticationGuardWithPermission`**: Used to wrap specific UI elements (buttons, sidebars, tabs).

```tsx
import { AuthenticationGuardWithPermission } from '@/components/auth/Guard';
import { Button } from '@heroui/react';

export function DatabaseToolbar() {
  return (
    <div>
      <Button>View Logs</Button>
      
      {/* Only show the "Wipe Database" button to users with the specific permission */}
      <AuthenticationGuardWithPermission 
        permission="admin:database"
        fallback={<p className="text-tiny">Contact superadmin for write access.</p>}
      >
        <Button color="danger">Wipe Database</Button>
      </AuthenticationGuardWithPermission>
    </div>
  );
}
```

### Logic-Level Permission Checking
To check permissions inside an event handler or `useEffect`, use `hasPermission` from the `useSecuredApi` hook. Note that `isAuthenticated` is available in `useAuth` for simple login state checks.

```tsx
import { useSecuredApi } from '@/hooks/useSecuredApi';
import { useAuth } from '@/hooks/useAuth';

export function ProductEditor() {
  const { hasPermission } = useSecuredApi();
  const { isAuthenticated } = useAuth();

  const handleSave = async () => {
    if (!isAuthenticated) return;

    const canEdit = await hasPermission('admin:store');
    if (!canEdit) {
      alert("You don't have permission to save products.");
      return;
    }
    // Proceed with save...
  };
}
```

## Managing Users and Permissions

Admins can manage Auth0 users directly through the Fufuni dashboard via the `UsersAndPermissionsPage` (`/admin/users-and-permissions`). 

1.  **Dashboard Integration**: The page uses the internal `/v1/__auth0/token` endpoint to gain authorized access to the Auth0 Management API.
2.  **User Provisioning**: While the `deploy-tenant-resources.ts` script handles initial Auth0 setup, the UI allows for day-to-day role assignments.
3.  **Permissions**: Permissions like `ai:api` or `mail:api` are toggled here, effectively updating the user's JWT payload for subsequent backend requests.

### Login vs. Redirect Patterns
- Use **`LoginLogoutLink`** or **`LoginButton`** in headers and menus. These components handle the transition between authenticated states gracefully.
- Do **not** manually trigger redirects to Auth0 in standard UI components; let the `AuthenticationGuard` handle route protection to maintain a consistent UX.

## OAuth Scope Validation

For third-party integrations using 64-character hex tokens, use the `requireScope` factory. This ensures that even if a token is valid, it only performs actions it was explicitly granted (e.g., `orders:read`).

```typescript
import { authMiddleware, requireScope } from './middleware/auth';

// Define a route that only allows OAuth tokens with 'products:write' scope
app.put('/v1/products/:id',
  authMiddleware,
  requireScope('products:write'),
  async (c) => {
    const auth = c.get('auth');
    if (auth.role === 'oauth') {
      console.log(`OAuth update by customer: ${auth.customerEmail}`);
    }
    // ... logic
  }
);
```
