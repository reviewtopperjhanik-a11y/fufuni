## Authentication Patterns

Fufuni supports three authentication token types and provides middleware for backend route protection and React components for frontend guards.

## Token Types

Three authentication methods are accepted by the backend:

1. **Auth0 JWT** — three-part Bearer token (header.payload.signature) verified against the tenant's JWKS endpoint. Must include the permission specified in `ADMIN_STORE_PERMISSION` (defaults to `admin:store`).

2. **Admin API key** — begins with `sk_` prefix. Stored as SHA-256 hash in the `api_keys` table.

3. **OAuth token** — 64-character lowercase hex string. Validated against the `oauth_tokens` table.

## AuthRole Values

The `AuthRole` type defines possible roles:

```typescript
type AuthRole = 
  | 'public'    // Unauthenticated or public-key request
  | 'admin'     // Auth0 with admin:store or sk_ key
  | 'oauth'     // OAuth token with specific scopes
  | 'authadmin' // Auth0 with auth0:admin:api permission
  | 'databaseadmin' // Auth0 with admin:database permission
  | 'aiadmin'   // Auth0 with ai:api permission
  | 'mail'      // Auth0 with mail:api permission
  | 'customer'; // Auth0 JWT with no admin permissions
```

## Backend RBAC Guards

| Guard | Role Checked | Typical Use Case |
|-------|-------------|------------------|
| `adminOnly` | `'admin'` | Store administration endpoints |
| `superAdminOnly` | `'authadmin'` | Auth0 Management API token endpoint (`/v1/__auth0/token`) |
| `databaseAdminOnly` | `'databaseadmin'` | Database maintenance routes |
| `aiAccessOnly` | `'aiadmin'` | AI configuration endpoints |
| `mailAccessOnly` | `'mail'` | Email sending routes |
| `validJwtAuthOnly` | Any valid JWT | Customer-facing endpoints with JWT verification only |
| `requireScope(...scopes)` | OAuth token scopes | Third-party API access with specific permissions |

## Backend Route Protection

### Basic Admin Route

```typescript
import { Hono } from 'hono';
import { authMiddleware, adminOnly } from '../middleware/auth';

const app = new Hono<HonoEnv>();

// Apply auth middleware to all /admin routes
app.use('/admin/*', authMiddleware);

// Protect specific route with adminOnly
app.get('/admin/products', adminOnly, async (c) => {
  const products = await c.var.db.query('SELECT * FROM products');
  return c.json(products);
});
```

### Super Admin Endpoint

The `/v1/__auth0/token` endpoint demonstrates `superAdminOnly`:

```typescript
app.get('/v1/__auth0/token', authMiddleware, superAdminOnly, async (c) => {
  // Returns cached Auth0 Management API token
  const token = await c.var.db.query(
    'SELECT token FROM auth0_tokens WHERE expires_at > ? LIMIT 1',
    [now()]
  );
  return c.json(token[0] || { token: null });
});
```

### Customer-Scoped Routes

Customer endpoints use `customerAuthMiddleware`:

```typescript
import { customerAuthMiddleware } from '../middleware/customer-auth';

app.get('/v1/me/profile', customerAuthMiddleware, async (c) => {
  const auth = c.get('auth');
  return c.json({
    email: auth.email,
    sub: auth.sub,
    permissions: auth.permissions
  });
});
```

## Frontend Authentication Components

### Page-Level Protection

Wrap entire pages with `AuthenticationGuard` to redirect unauthenticated users:

```jsx
import { AuthenticationGuard } from '@/components/auth/AuthenticationGuard';

function AdminDashboard() {
  return <div>Admin content</div>;
}

export default function Page() {
  return (
    <AuthenticationGuard component={AdminDashboard} />
  );
}
```

### Permission-Based UI

Use `AuthenticationGuardWithPermission` for permission-gated UI:

```jsx
import { AuthenticationGuardWithPermission } from '@/components/auth/AuthenticationGuardWithPermission';

function AdminPanel() {
  return (
    <AuthenticationGuardWithPermission
      permission="admin:store"
      fallback={<p>Access denied</p>}
    >
      <div>Admin controls</div>
    </AuthenticationGuardWithPermission>
  );
}
```

### Programmatic Permission Checks

Check permissions asynchronously with `hasPermission()` from `useSecuredApi()`:

```jsx
import { useSecuredApi } from '@/hooks/useSecuredApi';

function DeleteButton({ productId }) {
  const { hasPermission } = useSecuredApi();

  const handleDelete = async () => {
    if (await hasPermission('admin:products:delete')) {
      // Proceed with deletion
    }
  };

  return <button onClick={handleDelete}>Delete</button>;
}
```

Check authentication state synchronously with `isAuthenticated`:

```jsx
import { useAuth } from '@/hooks/useAuth';

function UserMenu() {
  const { isAuthenticated } = useAuth();

  return isAuthenticated ? (
    <Link to="/account">My Account</Link>
  ) : (
    <Link to="/login">Login</Link>
  );
}
```

## Frontend UI Components

### Login/Logout Links

Use `LoginLogoutLink` for context-aware login/logout toggles:

```jsx
import { LoginLogoutLink } from '@/components/auth/LoginLogoutLink';

function NavBar() {
  return (
    <nav>
      <LoginLogoutLink />
    </nav>
  );
}
```

### Direct Auth0 Integration

For custom authentication flows, use `LoginButton` instead of direct Auth0 redirects:

```jsx
import { LoginButton } from '@/components/auth/LoginButton';

function CustomLogin() {
  return (
    <LoginButton
      onSuccess={() => navigate('/dashboard')}
      onError={(err) => showError(err)}
    />
  );
}
```

## Permission Management

Admins manage Auth0 permissions through the storefront UI:

```jsx
import { UsersAndPermissionsPage } from '@/pages/admin/UsersAndPermissionsPage';

// Route configuration:
{
  path: '/admin/users-and-permissions',
  element: <UsersAndPermissionsPage />
}
```

The page allows assigning permissions without visiting the Auth0 dashboard.

## OAuth Scope Requirements

Protect OAuth endpoints with `requireScope`:

```typescript
import { requireScope } from '../middleware/auth';

app.get(
  '/v1/oauth/orders',
  authMiddleware,
  requireScope('orders:read'),
  async (c) => {
    // Only accessible with orders:read scope
  }
);
```

## Auth0 Resource Provisioning

The `deploy-tenant-resources` script configures all Auth0 requirements:

```bash
npm run auth0:deploy-tenant
```

This creates applications, APIs, permissions, and actions in your Auth0 tenant.
