## Fufuni Framework Overview

Fufuni is an open-source, 100 % free-tier e-commerce framework built for Cloudflare Workers, Auth0, Stripe, and React 19. It is designed to run entirely within Cloudflare’s generous free tiers—no credit card required—while exposing a modern, AI-native commerce API (UCP) that lets shopping agents interact with your store without a UI. The stack is opinionated: Hono + Zod-OpenAPI on the edge, Durable Objects with built-in SQLite for state, React 19 + HeroUI v3 for the frontend, and Auth0 for identity and RBAC. The entire project is a Turborepo monorepo with three workspaces: `apps/client` (storefront + admin SPA), `apps/merchant` (Hono Worker + Durable Object), and `apps/mcp` (MCP server for AI assistants).

### Request Lifecycle

1. **Client request** (browser or AI agent)
   - React SPA or AI tool calls `https://your-worker.workers.dev/v1/products` with an optional `Authorization: Bearer pk_...` or JWT.

2. **Cloudflare Worker (Hono)**
   - CORS middleware runs first.
   - `app.use('*', async (c, next) => { ... })` binds the Durable Object stub to `c.set('db', stub)`.
   - Public routes (`/v1/orders`, `/v1/categories`) bypass auth.
   - Auth middleware validates JWT or API key and injects permissions into `c.var.permissions`.

3. **Durable Object (MerchantDO)**
   - All SQL executes in a single JS isolate (no connection pooling).
   - `ensureInitialized()` runs on first access and applies pending migrations from the `SCHEMA` constant and `migrations/*.sql` files.
   - SQL queries are synchronous (Durable Objects guarantee single-threaded execution).

4. **Response**
   - Hono serializes the JSON response.
   - KV cache middleware (`kvCacheMiddleware`) may short-circuit GET requests for public endpoints.
   - KV invalidation middleware (`kvInvalidateMiddleware`) purges cache entries on mutations.

### Key Conventions

- **Naming**
  - Routes: `/v1/products`, `/v1/orders`, `/v1/me/addresses`
  - DO class: `MerchantDO`
  - Migrations: `001-expand-order-status.sql` (padded 3 digits)
  - API keys: `pk_` (public), `sk_` (admin/legacy)

- **Error handling**
  - All errors thrown by the DO are caught by the Worker’s `app.onError` and normalized to `{ error: { code, message, details? } }`.
  - Custom `ApiError` class carries `code`, `message`, `details`, and `statusCode`.

- **Auth**
  - RBAC via Auth0 JWT permissions (`admin:store`, `ai:api`, etc.).
  - Admin routes require `Authorization: Bearer <token>` with the correct permission.
  - Public keys (`pk_...`) are allowed on read-only endpoints.

- **i18n**
  - All multilingual fields are stored as JSON locale maps (`{"en-US":"...","fr-FR":"..."}`).
  - Frontend helpers (`resolveTitle`, `resolveDescription`) apply fallback chain: `en-US → fr-FR → es-ES → zh-CN → ar-SA → he-IL`.

- **Frontend routing**
  - File-based routing under `apps/client/src/pages/`; visibility controlled by `siteConfig().navItems[].permissions[]`.

- **Deployment**
  - Worker: `wrangler deploy` (auto-deployed on push to `main`).
  - Frontend: GitHub Pages via `pages.yaml` workflow.
  - Demo reset: `reset-demo.yaml` (manual/scheduled).
