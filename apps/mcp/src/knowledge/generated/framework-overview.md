Fufuni is a high-performance, AI-native e-commerce framework designed to operate entirely within the free tiers of modern cloud infrastructure. It leverages a serverless-first architecture where the backend is a Hono-based API running on Cloudflare Workers, persisting state into a single Durable Object utilizing its internal SQLite engine. This unique design ensures 100% consistency, zero-latency database access within the execution isolate, and a simplified operational model with no external database connection strings or connection pools required.

## Technical Stack

The framework is built using a modern, type-safe stack that prioritizes developer experience and zero-cost scaling.

| Layer | Technology | Purpose |
|---|---|---|
| **Frontend** | React 19 + Vite | High-performance Single Page Application (SPA). |
| **UI Library** | HeroUI v3 + Tailwind CSS | Accessible, themeable components and styling. |
| **Backend API** | Hono + Zod-OpenAPI | Type-safe routing and automatic Swagger/OpenAPI generation. |
| **State/Storage** | Durable Objects + SQLite | Transactional storage and business logic isolation. |
| **Authentication** | Auth0 | Managed identity, social login, and RBAC via JWT permissions. |

| **Caching** | Cloudflare KV | Edge-cached catalog responses to minimize DO invocations. |
| **Communication** | Mailgun | Transactional order emails via the Mailgun API. |

### Core Project Structure

Fufuni is managed as a monorepo using **Turborepo** for task orchestration. This allows for unified environment variable injection and parallel development of the frontend and backend.

```bash
# Example: Starting the full development environment
# This command loads .env, copies variables to .dev.vars, and starts all workspaces.
npm run dev:env
```

The monorepo is organized into three primary workspaces:

- `apps/client`: The React SPA. It contains both the customer-facing storefront and the restricted admin dashboard. Routing and visibility are driven by `siteConfig` in `src/config/site.ts`.
- `apps/merchant`: The Cloudflare Worker. This is the heart of the system, containing the Hono API routes and the `MerchantDO` Durable Object class where the SQLite schema and migrations reside.
- `apps/mcp`: A Model Context Protocol server that exposes the framework's internal documentation to AI coding assistants (like Cursor or Claude).

## Request Lifecycle

Understanding the flow of a request is critical for debugging and extending the framework. Because Fufuni uses a single Durable Object for all store data, every stateful request follows a specific path.

### 1. Edge Entry and Middleware
When a request hits the Cloudflare Worker, it first passes through global Hono middleware.
- **CORS**: Handles cross-origin requests from the GitHub Pages frontend.
- **KV Cache**: For public GET requests (like browsing products), `kvCacheMiddleware` checks if a response exists in Cloudflare KV. If it does, the request returns early (a "Cache Hit").
- **Durable Object Binding**: Every request is assigned a "stub" to the `MerchantDO`. Since Fufuni uses one DO per store, we always target the `default` ID.

### 2. The Durable Object Handover
If the request is not cached or is a mutation (POST/PATCH/DELETE), the Hono route handler calls the Durable Object.

```typescript
// apps/merchant/src/index.ts
app.use('*', async (c, next) => {
  // Every request gets a connection to the DO
  const id = c.env.MERCHANT.idFromName('default');
  const stub = c.env.MERCHANT.get(id);
  c.set('db', stub as any);
  await next();
});
```

### 3. SQLite Execution
Inside the Durable Object (`apps/merchant/src/do.ts`), the `fetch` method receives the request. The DO acts as a localized server. It executes SQL queries against its internal SQLite database. Because the code and the data live in the same JS isolate, there is no network latency between the API logic and the database.

### 4. Cache Invalidation
On successful mutations, the `kvInvalidateMiddleware` triggers. It purges related keys from Cloudflare KV (e.g., if a product is updated, it purges all keys starting with `cache:*/v1/products`) to ensure the next visitor sees fresh data.

## Database Schema & Migrations

Fufuni does not use Cloudflare D1. Instead, it uses the SQLite engine built into Durable Objects. This requires a specific pattern for schema management.

### The Triple-Apply Rule
Whenever you change the database schema, you must apply the change in **three places** simultaneously:

1.  **The SCHEMA constant**: Update the SQL string in `apps/merchant/src/do.ts` used for fresh installs.
2.  **ensureInitialized()**: Add an `ALTER TABLE` or `CREATE TABLE` statement inside the initialization logic to update existing local/production databases.
3.  **Migration Files**: Create a new `.sql` file in `apps/merchant/migrations/` (e.g., `019_add_custom_field.sql`). This is used by external tools and for tracking history.

### Migration Example

```typescript
// apps/merchant/src/do.ts
async ensureInitialized() {
  // ... existing migrations
  
  // Migration 018: Add theme support
  await this.db.exec(`
    CREATE TABLE IF NOT EXISTS store_themes (
      id TEXT PRIMARY KEY,
      name TEXT NOT NULL,
      config_json TEXT NOT NULL,
      is_active INTEGER DEFAULT 0
    );
  `);
}
```

## Authentication and Security

Fufuni uses a hybrid authentication model. While it supports legacy API keys for simple integrations, Auth0 is the source of truth for administrative access.

### API Key Prefixes
- **`pk_` (Public Key)**: Safe for use in the frontend. Grants access to categories, products, cart creation, and checkout.
- **`sk_` (Secret Key)**: Admin-level access. **Never** expose these to the client.

### RBAC (Role-Based Access Control)
Roles are not stored in the SQLite database. Instead, Fufuni relies on **Auth0 Permissions** inside the JWT Access Token. The backend checks for specific scopes before allowing access to sensitive routes.

| Permission | Purpose |
|---|---|
| `admin:store` | Manage products, orders, and settings. |
| `ai:api` | Access AI translation and moderation features. |
| `admin:database` | Perform destructive actions like database resets. |

### Middleware Protection Example

```typescript
// apps/merchant/src/middleware/auth.ts (Conceptual)
export const adminAuth = (permission: string) => {
  return async (c: Context, next: Next) => {
    const authHeader = c.req.header('Authorization');
    
    // 1. Check for legacy Secret Key
    if (authHeader === `Bearer ${c.env.MERCHANT_SK}`) return await next();
    
    // 2. Validate Auth0 JWT and check permissions
    const payload = await verifyJwt(authHeader);
    if (payload.permissions.includes(permission)) {
      return await next();
    }
    
    throw new ApiError('Forbidden', 403);
  };
};
```

## AI and Internationalization (i18n)

Fufuni is "AI-native," meaning it is built to be both managed by AI and browsed by AI.

### UCP (Universal Commerce Protocol)
The framework implements the UCP standard at `.well-known/ucp`. This allows shopping agents to discover the store's capabilities and interact with the catalog using a standardized JSON-LD format.

### Multilingual Fields
Fields like product titles and descriptions are stored as JSON strings containing locale maps. The system supports 6 built-in locales (en-US, fr-FR, es-ES, zh-CN, ar-EG, he-IL).

```json
{
  "title": "{\"en-US\": \"Golf Club\", \"fr-FR\": \"Club de golf\"}",
  "description": "{\"en-US\": \"<p>Professional grade</p>\", \"fr-FR\": \"<p>Qualité professionnelle</p>\"}"
}
```

### Client-Side AI Translation
To keep the backend lightweight and secure, **all AI calls (LLM requests) are performed client-side**. The backend exposes a gated endpoint `GET /v1/ai/parameters` which provides the admin's browser with the necessary API key (e.g., Groq or OpenAI) and model settings. The browser then performs the translation and sends the result back to the Worker as a standard update.

## Key Development Conventions

To maintain consistency across the codebase, follow these rules:

### Naming Conventions
- **Routes**: Use kebab-case for URL segments (e.g., `/v1/shipping-rates`).
- **Database Columns**: Use lowercase snake_case (e.g., `created_at`, `is_active`). Note: Some legacy columns use flattened lowercase (e.g., `pricecents`, `shippingclassid`)—always verify against `do.ts`.
- **Variables**: Use camelCase for TypeScript variables and functions.

### Error Handling
Always throw an `ApiError` from the `types.ts` file. This ensures the frontend receives a consistent JSON error object and the correct HTTP status code.

```typescript
import { ApiError } from '../types';

if (!product) {
  throw new ApiError('Product not found', 404, 'PRODUCT_MISSING');
}
```

### Frontend UI Patterns
Use the `siteConfig` and `HeroUI` components to build new pages.
- Add new admin pages to `apps/client/src/config/site.ts` to automatically handle sidebar visibility and permission guarding.
- Use `useSWR` or `react-query` patterns (implemented via custom hooks in `lib/store-api.ts`) for data fetching to benefit from automatic revalidation.

### Deployment
Deployment is fully automated via GitHub Actions.
- **Worker**: `deploy-cloudflare-worker.yaml` handles the Hono/Durable Object deployment.
- **Frontend**: `pages.yaml` builds the Vite app and pushes it to GitHub Pages.
- **Secrets**: All sensitive variables (`STRIPE_SECRET_KEY`, `AUTH0_CLIENT_SECRET`, etc.) must be added to the Cloudflare Worker via `wrangler secret put` or the Cloudflare Dashboard.
