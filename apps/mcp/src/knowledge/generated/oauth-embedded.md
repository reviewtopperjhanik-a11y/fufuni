## Purpose

The embedded OAuth2 server provides machine-to-machine authentication for third-party integrations and merchant API access. It operates alongside Auth0, which handles primary user authentication. This server is designed for programmatic access to Fufuni APIs by external applications, AI agents, or other services.

## Client Registration

OAuth clients are managed via dedicated admin endpoints:

- `GET /v1/oauth/clients` - List registered clients
- `POST /v1/oauth/clients` - Register a new client
- `DELETE /v1/oauth/clients/:id` - Remove a client

When registering a new client via `POST /v1/oauth/clients`, the following fields are required:

```typescript
interface OAuthClient {
  name: string;
  redirect_uris?: string[]; // Optional for client_credentials flow
  scopes: string[]; // Requested permissions
}
```

The server generates a `client_id` and `client_secret` pair. The `client_secret` is returned **once** in the response and must be securely stored by the client application. Secrets are hashed using bcrypt before storage in the `oauth_clients` table.

```sql
-- Database schema for OAuth clients
CREATE TABLE oauth_clients (
  id TEXT PRIMARY KEY,
  client_id TEXT UNIQUE,
  client_secret_hash TEXT, -- bcrypt hash of the secret
  name TEXT,
  redirect_uris TEXT, -- JSON array
  scopes TEXT, -- JSON array of granted scopes
  created_at TEXT
);
```

## Token Request

To obtain an access token, clients use the `client_credentials` grant type:

```bash
curl -X POST 'https://MERCHANT.fufuni.com/v1/oauth/token' \
  -H 'Content-Type: application/json' \
  -d '{
    "grant_type": "client_credentials",
    "client_id": "YOUR_CLIENT_ID",
    "client_secret": "YOUR_CLIENT_SECRET",
    "scope": "read:products write:orders"
  }'
```

Successful response:

```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "token_type": "Bearer",
  "expires_in": 3600,
  "scope": "read:products write:orders"
}
```

## Token Verification

The `oauthMiddleware` handles token validation for protected routes. Routes configured with this middleware accept either:

1. Auth0-issued JWTs (for user contexts)
2. OAuth2-issued access tokens (for machine contexts)

Example middleware usage:

```typescript
import { oauthMiddleware } from '../middleware/auth';

app.get('/api/products', oauthMiddleware, async (c) => {
  // Handle request
});
```

## Scope System

The following scopes are available:

- `read:products` - View product catalog
- `write:products` - Create/update products
- `read:orders` - View order history
- `write:orders` - Create/update orders
- `read:customers` - Access customer data

Requested scopes must be a subset of those granted to the client during registration. Scope validation occurs during token issuance and request processing.

## Token Structure

Access tokens are signed JWTs with the following characteristics:

- **Algorithm**: HS256
- **TTL**: 3600 seconds (1 hour)
- **Claims**: Standard JWT claims plus custom scope information

Example decoded token:

```json
{
  "iss": "https://MERCHANT.fufuni.com",
  "sub": "CLIENT_ID",
  "aud": "fufuni-api",
  "exp": 1735689600,
  "scope": ["read:products", "write:orders"]
}
```

## Required Wrangler Secret

The server requires the `OAUTH_JWT_SECRET` environment variable for token signing:

```bash
# wrangler.toml
[vars]
OAUTH_JWT_SECRET = "your-256-bit-secret-here"
```

This secret must be at least 32 characters long and should be generated using a secure random process.
