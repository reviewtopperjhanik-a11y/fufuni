## Embedded OAuth2 Server Reference

### Purpose
Fufuni's embedded OAuth2 server (`routes/oauth.ts`) coexists with Auth0 to handle **machine-to-machine (M2M) authentication** for:
- Third-party integrations (e.g., ERP systems, AI agents)
- Merchant API access (e.g., bulk product updates)
- UCP-compliant platform interactions

**Key differences from Auth0**:
| Feature               | Embedded OAuth2 Server       | Auth0                     |
|-----------------------|-----------------------------|---------------------------|
| **Use Case**          | M2M tokens for APIs         | Customer authentication   |
| **Token Type**        | JWT (HS256)                 | Auth0 JWT (RS256)         |
| **Grant Types**       | `client_credentials`       | Interactive flows         |
| **Audience**          | External platforms/merchants| Customer-facing apps      |

### Client Registration
Admin endpoints manage OAuth clients via SQLite. Clients are auto-registered on first use in the PKCE flow (for UCP), but **explicit registration is required for M2M access**.

#### **Fields**
| Field          | Type     | Required | Description                                                                 |
|----------------|----------|----------|-----------------------------------------------------------------------------|
| `name`         | string   | Yes      | Human-readable client name (e.g., "Shopify Connector")                     |
| `client_id`    | string   | Auto     | UUIDv4 generated by the server                                              |
| `client_secret`| string   | Auto     | 32-byte secret returned **once** at creation (bcrypt-hashed in storage)    |
| `scopes`       | string[] | Yes      | Allowed scopes (e.g., `["read:products", "write:orders"]`)                |
| `is_active`    | boolean  | Default  | `true`; set to `false` to revoke access                                     |

### Token Verification
Tokens are validated by `oauthMiddleware` (separate from `customerAuthMiddleware`). Routes can accept **either** an Auth0 token **or** an OAuth token.

#### **Middleware Logic**
```typescript
// middleware/oauth.ts
export async function oauthMiddleware(c: Context, next: Next) {
  const authHeader = c.req.header('Authorization');
  if (!authHeader?.startsWith('Bearer ')) {
    throw ApiError.unauthorized('Missing Bearer token');
  }

  const token = authHeader.split(' ')[1];
  try {
    // 1. Verify JWT signature with OAUTH_JWT_SECRET
    const payload = await verifyJwt(token, c.env.OAUTH_JWT_SECRET);

    // 2. Check token in DB (revocation list)
    const db = getDb(c.var.db);
    const [record] = await db.query<{ is_revoked: boolean }>(
      `SELECT is_revoked FROM oauth_tokens WHERE access_token_hash = ?`,
      [await hashKey(token)]
    );

    if (record?.is_revoked) {
      throw ApiError.unauthorized('Token revoked');
    }

    // 3. Attach claims to context
    c.set('oauth', {
      clientId: payload.client_id,
      scopes: payload.scope.split(' '),
      customerId: payload.customer_id, // Only for UCP tokens
    });

    await next();
  } catch (e) {
    throw ApiError.unauthorized('Invalid token');
  }
}
```

### Scope System
#### **Available Scopes**
| Scope               | Description                                  | Example Use Case                     |
|---------------------|----------------------------------------------|--------------------------------------|
| `read:products`     | List/get products                           | ERP syncing inventory                |
| `write:products`    | Create/update products                      | Bulk price updates                   |
| `read:orders`       | List/get orders                              | Analytics dashboard                  |
| `write:orders`      | Cancel/fulfill orders                        | 3PL integration                      |
| `read:customers`    | Access customer profiles (PII-redacted)     | CRM synchronization                  |

#### **Scope Validation**
Scopes are checked in route handlers:
```typescript
// routes/products.ts
app.get('/v1/products', oauthMiddleware, async (c) => {
  const { scopes } = c.get('oauth');
  if (!scopes.includes('read:products')) {
    throw ApiError.forbidden('Insufficient scope');
  }
  // ... fetch products
});
```

### Token Structure
#### **JWT Claims**
```json
{
  "iss": "https://store.example.com",
  "sub": "cl_abc123",          // client_id
  "scope": "read:products write:orders",
  "client_id": "7a6b5d4e-3c2f-1g0h-9i8j-7k6l5m4n3o2p",
  "customer_id": "cus_abc123", // Only for UCP tokens
  "exp": 1735689600,           // Expiry (3600s from issuance)
  "iat": 1735685999
}
```

#### **Key Details**
- **Algorithm**: HS256 (symmetric, using `OAUTH_JWT_SECRET`)
- **TTL**: 3600 seconds (1 hour)
- **Revocation**: Tokens are soft-revoked via `is_revoked` flag in DB
- **Storage**: Only the hash (`access_token_hash`) is stored in SQLite

### Required Wrangler Secret
#### **`OAUTH_JWT_SECRET`**
- **Purpose**: Signs/verifies JWTs
- **Format**: 32+ byte random string (e.g., `openssl rand -base64 32`)
- **Configuration**:
  ```bash
  # wrangler.toml
  [vars]
  OAUTH_JWT_SECRET = "@oauth_jwt_secret"

  # .dev.vars
  OAUTH_JWT_SECRET = "your_32_byte_base64_secret_here"
  ```
- **Rotation**: Deploy a new secret and migrate tokens during low-traffic periods.
