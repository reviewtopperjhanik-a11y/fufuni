## Architecture: Browser-Side Inference

Fufuni employs a "Direct-from-Browser" AI architecture. Instead of proxying AI requests through the Cloudflare Worker backend, the merchant dashboard retrieves ephemeral, decrypted credentials and communicates directly with the AI provider (OpenAI, Anthropic, or Groq) from the user's browser.

### Why Browser-Side?
1.  **Latency & Payload:** Large HTML product descriptions or email templates don't need to be sent to the Worker and then forwarded.
2.  **Execution Limits:** Cloudflare Workers have strict CPU time and memory limits. Offloading heavy translation tasks to the client prevents Worker timeouts.
3.  **Streaming:** Direct browser-to-provider connections make implementing real-time streaming UI much simpler.

### Data Flow
1.  Admin requests AI parameters via `GET /v1/ai/parameters`.
2.  Backend decrypts the configuration using the `CRYPTOKEN` secret.
3.  Backend returns the API key, model, and endpoint to the React frontend.
4.  React frontend uses `ai-client.ts` to perform moderation or translation.

```typescript
// Example: Client-side usage of the AI flow
import { translateWithAi } from '@/utils/ai-client';

async function handleTranslation(content: string, targetLang: string) {
  // 1. Fetch credentials from our backend
  const res = await fetch('/api/v1/ai/parameters', {
    headers: { Authorization: `Bearer ${token}` }
  });
  const aiParams = await res.json();

  // 2. Call AI provider directly from browser
  const result = await translateWithAi(
    content, 
    targetLang, 
    aiParams, 
    true // isHtml
  );

  if (result.success) {
    console.log('Translated content:', result.content);
  }
}
```

## Credential Storage and Encryption

Security is paramount because AI API keys are highly sensitive. Fufuni does not store raw keys in the database. Instead, it uses a multi-layered encryption approach.

### The `ai.json.enc` Format
Configurations are prepared offline as a JSON file and encrypted using OpenSSL before being uploaded to the Cloudflare KV store (under the key `ai:config`).

**Encryption Command:**
```bash
openssl enc -aes-256-cbc -a -pbkdf2 -iter 100000 -salt \
  -in ai.json -out ai.json.enc -pass pass:"YOUR_CRYPTOKEN"
```

### Server-Side Decryption
The backend uses the `CRYPTOKEN` (a secret set in `wrangler.toml` or Cloudflare Dashboard) to decrypt the configuration in memory.

```typescript
// apps/merchant/src/lib/ai-enc.ts snippet
export async function decryptAiConfig(
  base64Ciphertext: string,
  password: string,
): Promise<AiConfig> {
  const raw = Uint8Array.from(atob(base64Ciphertext.trim()), c => c.charCodeAt(0));
  
  // OpenSSL magic header check
  if (new TextDecoder().decode(raw.slice(0, 8)) !== 'Salted__') {
    throw new Error('Invalid encrypted format');
  }

  const salt = raw.slice(8, 16);
  const ciphertext = raw.slice(16);

  // Derive keys using Web Crypto API
  const pwBytes = new TextEncoder().encode(password);
  const baseKey = await crypto.subtle.importKey('raw', pwBytes, 'PBKDF2', false, ['deriveBits']);
  // ... derivation and AES-CBC decryption logic
  return JSON.parse(new TextDecoder().decode(plaintext)) as AiConfig;
}
```

## AI Parameters API (`GET /v1/ai/parameters`)

The endpoint `/v1/ai/parameters` is the bridge between secure storage and client-side execution.

### Access Control
-   **Middleware:** Requires `authMiddleware` and `aiAccessOnly`.
-   **Permissions:** The user must have the `ai:api` permission scope.

### Logic
The backend performs load-balancing by selecting a random key from the pool of non-expired keys associated with the highest-priority model.

```typescript
// apps/merchant/src/routes/ai.ts logic
adminApp.openapi(aiParamsRoute, async (c) => {
  const config = await loadConfig(c.env);
  if (!config) throw new ApiError('not_configured', 503);

  // Filter and sort models by priority (1 is highest)
  const candidates = selectModels(config, { usage: 'chat' });
  
  for (const { providerKey, provider, model } of candidates) {
    const validKeys = provider.keys.filter(k => k.type !== 'expired');
    if (validKeys.length === 0) continue;

    // Pick a random key for load balancing
    const keyObj = validKeys[Math.floor(Math.random() * validKeys.length)];
    
    return c.json({
      providerName: providerKey,
      apiKey: keyObj.key,
      model: model.id,
      url: provider.endpoint,
      cloudflareAigUrl: provider.gatewayEndpoint,
      cloudflareAigToken: c.env.CLOUDFLARE_AIG_TOKEN
    }, 200);
  }
});
```

## Auto-Translation Workflow

Auto-translation is integrated into the Product Management UI. It allows a merchant to write a description in the store's primary language (e.g., `en-US`) and automatically populate other supported locales.

### Supported Scenarios
-   **Product Titles:** Translated as plain text without quotes.
-   **Product Descriptions:** Translated as HTML, preserving all `<div>`, `<span>`, and `<img>` tags.
-   **Email Templates:** Specifically preserves placeholder tokens like `TMPLVAR0` or `ORDER_ID`.

### Target Locales
The framework iterates through the configured languages of the store and sends individual translation requests in parallel (capped at 5 concurrent requests to avoid rate limits).

```typescript
// Typical UI implementation logic
const handleAutoTranslateAll = async () => {
  const params = await getAiParams();
  const source = product.descriptions['en-US'];
  
  for (const lang of otherLanguages) {
    const res = await translateWithAi(source, lang, params, true);
    if (res.success) {
      updateProductLocale(lang, res.content);
    }
  }
};
```

## Graceful Degradation

The framework is designed to work without AI. If the configuration is missing or invalid:

1.  **UI Elements:** "Auto-translate" buttons in the product form are hidden if `GET /v1/ai/parameters` returns a 503.
2.  **Moderation:** The reviews moderation table skips the AI analysis step and shows only manual action buttons.
3.  **Error Handling:** If an AI provider is down, the system catches the `fetch` error and displays a "Provider Unavailable" message to the admin without crashing the form.

### Fallback to Legacy Environment Variables
If no encrypted KV config is found, the system attempts to fall back to standard environment variables (useful for simpler deployments):
-   `AI_API_KEY`
-   `AI_MODEL`
-   `AI_API_URL`
