## AI-Assisted Features Reference

The Fufuni e-commerce framework integrates AI capabilities directly from the client-side to enhance user experience and automate tasks such as review moderation and content translation. This document provides a comprehensive guide to the AI-assisted features, their architecture, and usage within the framework.

## Architecture

AI calls in Fufuni are made directly from the browser to the AI provider's API, rather than routing through the backend. This architecture is chosen to reduce server load and latency, allowing for faster response times and a more responsive user interface. The client-side AI client handles all communication with the AI provider, ensuring that the backend remains lightweight and focused on core e-commerce functionalities.

The AI client supports multiple providers, including OpenAI, Groq, and Anthropic, and is designed to be flexible and extensible. It automatically detects the provider based on the API URL and formats requests accordingly.

## Credential Storage

AI API credentials (API key, model, and URL) are stored encrypted in the database in the `ai_settings` table. The encryption and decryption process is handled by the `lib/ai-enc.ts` module, which uses the `ENCRYPTION_KEY` Wrangler secret to secure the credentials. This ensures that sensitive information is protected both at rest and during transmission.

The encryption process uses AES-256-CBC with PBKDF2-SHA256 key derivation, providing a robust security mechanism for the AI configuration data. The encrypted configuration is stored in Cloudflare KV under the key `ai:config`.

```typescript
// Example of decrypting AI configuration
import { decryptAiConfig } from '../lib/ai-enc';

const encryptedConfig = await env.KV_CACHE.get('ai:config');
const decryptedConfig = await decryptAiConfig(encryptedConfig, env.CRYPTOKEN);
```

## GET /v1/ai/parameters

The `GET /v1/ai/parameters` endpoint is used to retrieve the AI configuration for the client. This endpoint is accessible only to authenticated admin users with the `ai:api` permission. It returns the API key, model, and base URL for the AI provider, which the frontend then uses to make direct API calls to the AI provider.

```typescript
// Example response from GET /v1/ai/parameters
{
  "providerName": "groq",
  "apiKey": "sk-1234567890abcdef",
  "model": "llama-3.3-70b-versatile",
  "url": "https://api.groq.com/openai/v1",
  "cloudflareAigToken": null,
  "cloudflareAigUrl": null
}
```

## ai-client.ts Exports

The `ai-client.ts` module provides several functions for interacting with AI providers. The primary functions are:

- `createChatCompletion`: Sends a chat completion request to the AI provider.
- `moderateReview`: Analyzes a product review and recommends whether to approve or reject it.
- `autoTranslate`: Translates text from the base language to a target locale.

Here is an example of using the `moderateReview` function:

```typescript
import { analyzeReviewWithAi } from './utils/ai-client';

const review = {
  id: 'rev_123',
  rating: 4,
  title: 'Great product!',
  body: 'This product is amazing. It works perfectly and is very easy to use.',
  author_name: 'John Doe'
};

const aiParams = {
  apiKey: 'sk-1234567890abcdef',
  model: 'llama-3.3-70b-versatile',
  url: 'https://api.groq.com/openai/v1'
};

const result = await analyzeReviewWithAi(review, aiParams);
console.log(result);
// Output: { success: true, recommendation: 'approve', reason: 'The review is genuine and relevant to the product.' }
```

## Review Moderation

Review moderation is handled by the `moderateReview` function, which is called by the admin reviews page before displaying the approve/reject buttons. This function analyzes the review content and returns a recommendation on whether to approve or reject the review, along with a reason for the recommendation.

The function returns an object with the following structure:

```typescript
interface ReviewAnalysisResult {
  success: boolean;
  recommendation?: "approve" | "reject";
  reason?: string;
  error?: string;
}
```

The UI uses this information to highlight potentially problematic reviews and provide moderators with a recommended action. If the AI is not configured, the moderation check is silently skipped, and the UI displays the reviews without AI assistance.

## Auto-Translation

Auto-translation is used in the product form admin to pre-fill localized name and description fields. The AI translates content from the base language (en-US) to all other configured locales. This feature is particularly useful for stores that operate in multiple languages, as it automates the translation process and ensures consistency across different language versions of the product descriptions.

The `autoTranslate` function handles the translation process, taking the source content, target language, and AI parameters as inputs. Here is an example of using the `autoTranslate` function:

```typescript
import { translateWithAi } from './utils/ai-client';

const sourceContent = '<p>This is a product description.</p>';
const targetLanguage = 'fr';
const aiParams = {
  apiKey: 'sk-1234567890abcdef',
  model: 'llama-3.3-70b-versatile',
  url: 'https://api.groq.com/openai/v1'
};

const result = await translateWithAi(sourceContent, targetLanguage, aiParams);
console.log(result);
// Output: { success: true, content: '<p>Ceci est une description de produit.</p>' }
```

When AI is not configured, the auto-translate buttons are hidden, and users must manually enter translations for each locale.

## Admin Setup

Administrators can configure AI settings using the `POST /v1/ai/settings` endpoint, which stores new credentials in the database. The endpoint expects a JSON payload with the encrypted AI configuration content.

```typescript
// Example request to POST /v1/ai/settings
{
  "content": "encrypted_AI_config_content_here"
}
```

Additionally, administrators can test the AI connection using the `POST /v1/ai/test` endpoint, which sends a simple ping prompt to the AI provider to verify that the configuration is correct and the provider is reachable.

## Graceful Degradation

The framework is designed to handle cases where AI is not configured or available. In such scenarios:

- Auto-translate buttons are hidden in the product form admin, and users must manually enter translations.
- Review moderation silently skips the AI check, and all reviews are displayed without AI assistance.

This ensures that the framework remains functional and usable even when AI features are not available, providing a seamless experience for both administrators and end-users.

```typescript
// Example of checking if AI is configured before calling auto-translate
if (aiConfig) {
  const translatedContent = await autoTranslate(sourceContent, targetLanguage, aiConfig);
  // Use translated content
} else {
  // Fallback to manual translation or default content
}
```
