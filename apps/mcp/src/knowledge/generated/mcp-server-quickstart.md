## What is the MCP Server?

The MCP (Multi-Context Processing) server is a specialized knowledge base system that provides AI assistants with contextual information about the Fufuni e-commerce framework. It's designed to work with both Cloudflare Workers and local development environments like Claude Desktop. The server exposes tools that AI assistants can use to answer questions about the framework's architecture, implementation details, and best practices.

## Directory Layout

The MCP server's knowledge base is organized in a structured directory layout:

```
apps/mcp/
├── src/
│   ├── knowledge/
│   │   ├── topics/
│   │   │   ├── <topic-name>.ts
│   │   │   └── ...
│   │   ├── generate.ts
│   │   └── base.ts
│   └── stdio.ts
└── scripts/
    └── gen-knowledge.ts
```

- `apps/mcp/src/knowledge/topics/`: Contains individual topic files, each representing a specific area of knowledge about the Fufuni framework.
- `apps/mcp/src/knowledge/generate.ts`: The generator script that processes topic files and generates the knowledge base.
- `apps/mcp/src/knowledge/base.ts`: Contains shared types and utility functions used across the knowledge base.
- `apps/mcp/src/stdio.ts`: Entry point for running the MCP server in local stdio mode.
- `apps/mcp/scripts/gen-knowledge.ts`: Script that publishes the generated .md files to the runtime knowledge.ts module.

## Adding a New Topic

To add a new topic to the knowledge base, follow these steps:

1. Create a new TypeScript file in `apps/mcp/src/knowledge/topics/` with the name of your topic (e.g., `backend-architecture.ts`).
2. Use the following template for your topic file:

```typescript
import { Topic } from "../base.js";
import { BASE_SYSTEM, appendFacts } from "../base.js";

export default {
  name: "backend-architecture",
  description: "Explain the backend architecture of the Fufuni framework",
  sources: [
    "apps/backend/src/index.ts",
    "apps/backend/src/routes/index.ts",
    "apps/backend/src/middleware/index.ts"
  ],
  systemPrompt: BASE_SYSTEM,
  manualFacts: [
    "The backend uses Cloudflare Workers and Durable Objects",
    "Hono is used as the web framework",
    "Zod-OpenAPI is used for API documentation and validation"
  ],
  buildPrompt: (sourceFiles: string) => {
    return appendFacts(
      `You are a senior TypeScript developer documenting the Fufuni e-commerce framework.
      The backend architecture is built on Cloudflare Workers and Durable Objects.
      Here are the source files for the backend architecture:

      ${sourceFiles}

      Please provide a comprehensive documentation of the backend architecture.`,
      [
        "The backend uses Cloudflare Workers and Durable Objects",
        "Hono is used as the web framework",
        "Zod-OpenAPI is used for API documentation and validation"
      ]
    );
  },
  maxSourceChars: 100000
} satisfies Topic;
```

3. Replace the placeholder values with your actual topic information:
   - `name`: The name of your topic (must match the filename without the .ts extension)
   - `description`: A one-sentence description of what the topic covers
   - `sources`: An array of paths to source files that provide context for this topic
   - `manualFacts`: An array of verified facts about the topic
   - `buildPrompt`: A function that takes the concatenated source files and returns a prompt for the LLM

4. Add the required copyright header at the top of the file:

```typescript
/*
 * Copyright (c) 2026 Ronan LE MEILLAT - SCTG Development
 * License: AGPL-3.0-or-later
 */
```

## Topic Interface Fields

Each topic file exports a default object that conforms to the Topic interface. The interface has the following fields:

- `name`: A string that uniquely identifies the topic (must match the filename without the .ts extension)
- `description`: A one-sentence string describing what the topic covers
- `sources`: An array of paths to source files that provide context for this topic
- `systemPrompt`: The base system prompt to use for generating the topic documentation
- `manualFacts`: An array of verified facts about the topic (optional)
- `buildPrompt`: A function that takes the concatenated source files and returns a prompt for the LLM
- `maxSourceChars`: The maximum number of characters to include from the source files (optional, defaults to 100,000)

## Generating the Knowledge Base

The knowledge base is generated using the following commands:

- `npm run mcp:generate`: Runs the generator in dry-run mode, using cached results when possible
- `npm run mcp:generate:force`: Forces regeneration of all topics, ignoring the cache
- `npm run mcp:auto`: Runs the generator and then publishes the knowledge base to the MCP server. Requires AI_MODEL, AI_API_KEY, and AI_API_URL environment variables.
- `npm run mcp:auto:flash`: Runs the generator using Gemini-3 flash with the encrypted ai.json.enc config, then publishes the knowledge base. Requires CRYPTOKEN environment variable for decryption.

## Publishing the Knowledge Base

The `gen-knowledge.ts` script (located in `apps/mcp/scripts/`) is responsible for publishing the generated .md files to the runtime knowledge.ts module. It performs the following steps:

1. Reads all generated .md files from the `mcp/` directory at the repository root
2. Builds the `knowledge.ts`, `bm25-index.ts`, `chunks.ts`, and `vectors.ts` modules used by the MCP server at runtime
3. These modules are then used by the MCP server to provide contextual information to AI assistants

## Running the MCP Server Locally

To run the MCP server in local stdio mode for testing with Claude Desktop, use the following command:

```bash
npx tsx apps/mcp/src/stdio.ts
```

This will start the MCP server in a mode compatible with Claude Desktop, allowing you to test the knowledge base locally.

## Important Note

Never edit the `apps/mcp/src/knowledge.ts` file directly. This file is auto-generated by the `gen-knowledge.ts` script and should only be modified through the topic files in `apps/mcp/src/knowledge/topics/`. Editing the knowledge.ts file directly will cause your changes to be overwritten the next time the knowledge base is generated.
