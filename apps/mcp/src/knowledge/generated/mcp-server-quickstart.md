## The Fufuni MCP Server Architecture

The Model Context Protocol (MCP) server is the primary interface through which AI assistants (like Claude, ChatGPT, or local LLMs) consume Fufuni’s internal documentation and architectural rules. Instead of training a model on the codebase, we provide a structured knowledge base that the AI can query dynamically using tools.

The server operates in two primary modes:
1.  **Cloudflare Workers:** Hosted alongside the backend, providing real-time knowledge to web-based AI interfaces.
2.  **Local Stdio:** A command-line interface used by tools like Claude Desktop to provide local context during development.

The knowledge base is not a static collection of Markdown files. It is a **generated system** where source code files are processed by an LLM to produce structured documentation topics. These topics are then indexed into a BM25 search engine and a vector store for efficient retrieval.

### Directory Layout

The MCP infrastructure is organized to separate the source definitions from the generated runtime code.

```bash
apps/mcp/
├── knowledge/
│   ├── topics/              # SOURCE: One .ts file per documentation topic
│   │   ├── backend-hono.ts
│   │   └── frontend-ui.ts
│   └── base.ts              # Shared types and base system prompts
├── scripts/
│   └── gen-knowledge.ts     # PUBLISHER: Converts .md to runtime .ts files
├── src/
│   ├── knowledge/
│   │   └── generate.ts      # GENERATOR: Calls LLMs to build .md files
│   ├── index.ts             # Worker entry point
│   └── stdio.ts             # Local testing entry point
└── knowledge.ts             # AUTO-GENERATED: DO NOT EDIT
```

## Adding a New Topic

To add knowledge to the Fufuni framework, you never edit the documentation files directly. Instead, you define a **Topic**. A topic tells the generator which source files to read, what the system prompt should be, and how to format the output.

### Step 1: Create the Topic File
Create a new file in `apps/mcp/knowledge/topics/<topic-name>.ts`. The filename must match the `name` property of the topic.

```typescript
/*
 * Copyright (c) 2026 Ronan LE MEILLAT - SCTG Development / License: AGPL-3.0-or-later
 */
import { Topic, BASE_SYSTEM, appendFacts } from "../base.js";

const topic: Topic = {
  name: "durable-objects-sqlite",
  description: "Documentation for Fufuni backend storage using Cloudflare Durable Objects with SQLite.",
  sources: [
    "apps/backend/src/db/schema.ts",
    "apps/backend/src/storage/DurableObjectState.ts",
    "packages/shared/src/models/index.ts"
  ],
  maxSourceChars: 20000,
  systemPrompt: appendFacts(BASE_SYSTEM, [
    "Always emphasize that SQLite in Durable Objects is synchronous.",
    "Explain that migrations are handled via the DO 'alarm' or 'migrate' method.",
    "Detail how Zod-OpenAPI schemas map to SQLite tables."
  ]),
  manualFacts: [
    "Fufuni uses the 'd1-http' driver bridge for remote management.",
    "Transaction isolation is strictly SERIALIZABLE within a single DO."
  ],
  buildPrompt: (concatenatedSources: string) => `
    Generate a comprehensive guide for Fufuni contributors on using SQLite within Durable Objects.
    Focus on the relationship between Hono routes and DO storage.
    
    SOURCE CODE CONTEXT:
    ${concatenatedSources}
    
    Structure the output with ## and ### headings only. 
    Include at least three full TypeScript examples showing CRUD operations.
  `
};

export default topic;
```

### Step 2: The Topic Interface Fields

Understanding the `Topic` interface is crucial for effective knowledge generation:

| Field | Description |
| :--- | :--- |
| `name` | Must match the filename (without `.ts`). Used as the unique ID. |
| `description` | A single sentence describing the topic for the AI tool selector. |
| `sources` | Array of paths relative to the repository root. The generator reads these files. |
| `systemPrompt` | The behavioral instructions for the LLM generating the topic. Always use `appendFacts(BASE_SYSTEM, [...])`. |
| `manualFacts` | Hardcoded facts that are not necessarily present in the source code but are true for the project. |
| `buildPrompt` | A function that receives all text from `sources` and returns the final prompt to generate the `.md` file. |
| `maxSourceChars` | Optional limit to prevent hitting context window errors on very large source files. |

## The Generation Pipeline

Fufuni uses a multi-stage process to move from topic definitions to a searchable knowledge base.

### 1. Generating Markdown (`mcp:generate`)
The generator reads your `.ts` topic files, fetches the source code, sends the `buildPrompt` to an LLM (Gemini 1.5 Pro/Flash or GPT-4o), and saves the result to `<repo-root>/mcp/<topic-name>.md`.

```bash
# Dry-run: Uses cached LLM responses if available
npm run mcp:generate

# Force: Ignores cache and regenerates all .md files from scratch
npm run mcp:generate:force
```

### 2. Publishing Knowledge (`mcp:auto`)
After `.md` files are created, they must be transformed into a format the Cloudflare Worker can import. The script `apps/mcp/scripts/gen-knowledge.ts` parses the Markdown and creates:
- `apps/mcp/src/knowledge.ts`: A TypeScript file containing all documentation as string constants.
- `bm25-index.ts`: A search index for keyword retrieval.

The `mcp:auto` command handles the full lifecycle:
1. Decrypts API keys (if using `mcp:auto:flash`).
2. Runs `generate`.
3. Runs `gen-knowledge`.

```bash
# Standard auto-generation (requires AI_MODEL, AI_API_KEY in .env)
npm run mcp:auto

# Fast generation (uses Gemini-3-flash and encrypted ai.json.enc)
# Requires CRYPTOKEN environment variable
npm run mcp:auto:flash
```

## Running Local Stdio Mode

For testing your changes with Claude Desktop before deploying to Cloudflare, you can run the MCP server locally.

### Local Execution
To start the server in stdio mode:
```bash
npx tsx apps/mcp/src/stdio.ts
```

### Claude Desktop Configuration
To integrate this into Claude Desktop, add the following to your `claude_desktop_config.json` (usually located in `~/Library/Application Support/Claude/` on macOS or `%APPDATA%/Claude/` on Windows):

```json
{
  "mcpServers": {
    "fufuni-local": {
      "command": "npx",
      "args": [
        "-y",
        "tsx",
        "/path/to/fufuni/apps/mcp/src/stdio.ts"
      ],
      "env": {
        "NODE_ENV": "development"
      }
    }
  }
}
```

## Critical Restrictions

### DO NOT EDIT `knowledge.ts` DIRECTLY
The file `apps/mcp/src/knowledge.ts` is a machine-generated build artifact. 

**Why you should never edit it:**
1.  **Volatility:** Any manual changes will be wiped the next time `npm run mcp:auto` is executed.
2.  **Consistency:** The search index (`bm25-index.ts`) will not match your manual changes, leading to the AI being unable to "find" the text you added.
3.  **Source of Truth:** The source of truth for all knowledge is either the **source code** (which the generator reads) or the **topic definition** (manual facts and prompts).

### LLM Dependency
The generation process requires a valid LLM API key. If you are a junior contributor without access to the encrypted `ai.json.enc` key, you should use the standard `mcp:generate` with your own `.env` configuration:

```bash
# .env in apps/mcp/
AI_MODEL=gemini-1.5-pro
AI_API_KEY=your_key_here
AI_API_URL=https://generativelanguage.googleapis.com/v1beta/openai/
```

### Content Formatting
When writing `buildPrompt` in your topic file, always instruct the LLM to use:
- `##` and `###` headings only.
- Typed code blocks (e.g., ` ```typescript `).
- Specific imports from the Fufuni codebase to ensure the AI learns correct patterns.

```typescript
// Example of a specific instruction in a buildPrompt
const myPrompt = (src: string) => `
  Context: ${src}
  Rule: When showing database models, always use the @fufuni/core/db import.
  Rule: Never use 'any' types in examples.
`;
```
