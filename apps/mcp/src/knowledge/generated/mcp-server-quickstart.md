## The MCP Server and AI Consumption

The Model Context Protocol (MCP) server acts as a specialized bridge between the Fufuni codebase and AI assistants (like Claude Desktop or GitHub Copilot). Instead of requiring the AI to guess how Fufuni works, the MCP server provides tools that allow the assistant to "read" curated documentation, search for specific implementation patterns, and retrieve facts from the knowledge base in real-time.

When an AI assistant uses the Fufuni MCP server, it invokes tools to query a SQLite-backed knowledge system running on Cloudflare Workers. This knowledge is not written manually into a single file; it is synthesized from the source code itself using LLMs to ensure it stays synchronized with the latest framework changes.

```bash
# Example: How an AI assistant might "see" the MCP tools
# Tool: fufuni_get_knowledge
# Description: Retrieves specific technical documentation about a framework topic.
# Arguments: { "topic": "backend-routing" }
```

## Directory Layout and Architecture

The knowledge base infrastructure is located within the `apps/mcp/` directory. It follows a modular design where each architectural concept is isolated into its own definition file.

| Path | Purpose |
| :--- | :--- |
| `apps/mcp/knowledge/topics/` | **Source of Truth.** Contains `.ts` files, one per topic. |
| `apps/mcp/src/knowledge/generate.ts` | The generator script that calls LLMs to transform source code into Markdown. |
| `apps/mcp/knowledge/base.ts` | Shared TypeScript interfaces, base system prompts, and helper functions. |
| `apps/mcp/scripts/gen-knowledge.ts` | Post-processor that converts generated `.md` files into runtime TypeScript modules. |
| `apps/mcp/src/knowledge.ts` | **Generated File.** The runtime bundle of all documentation (Do NOT edit). |

```typescript
// apps/mcp/knowledge/base.ts
// Shared interface used by all topic files
export interface Topic {
  name: string;
  description: string;
  sources: string[];
  systemPrompt: string;
  manualFacts?: string;
  buildPrompt: (sources: string) => string;
  maxSourceChars?: number;
}
```

## Step-by-Step: Adding a New Topic

To add a new framework concept (e.g., "Durable Object Storage") to the AI's knowledge, you must create a topic file. The generator automatically discovers these files alphabetically.

### 1. Create the topic file
Create a file in `apps/mcp/knowledge/topics/` using kebab-case matching the topic name.

```typescript
/*
 * Copyright (c) 2026 Ronan LE MEILLAT - SCTG Development / License: AGPL-3.0-or-later
 */
import { Topic, BASE_SYSTEM, appendFacts } from "../base.js";

const topic: Topic = {
  name: "backend-storage",
  description: "Documentation for SQLite-based Durable Object storage patterns in Fufuni.",
  sources: [
    "apps/backend/src/db/schema.ts",
    "apps/backend/src/objects/BaseObject.ts"
  ],
  systemPrompt: BASE_SYSTEM,
  manualFacts: appendFacts([
    "Always use 'db.prepare()' for SQL statements in Durable Objects.",
    "The primary key for entity tables should always be 'id'."
  ]),
  buildPrompt: (sourceCode: string) => `
    Analyze the following Fufuni backend storage code:
    ${sourceCode}
    
    Create a comprehensive guide documenting:
    1. How to define new SQLite tables using Drizzle.
    2. How to access the database from a Hono route.
    3. The standard naming conventions for columns.
    Use structured Markdown with TypeScript examples.
  `
};

export default topic;
```

## The Topic Interface Fields

The `Topic` object is the configuration used by the LLM to generate the documentation.

- **`name`**: Must strictly match the filename (without `.ts`). This is the ID used by the MCP tools.
- **`description`**: A single sentence explaining what this topic covers.
- **`sources`**: An array of file paths relative to the repository root. The generator reads these files and concatenates them.
- **`systemPrompt`**: The personality and constraints for the LLM. Always start with `BASE_SYSTEM`.
- **`manualFacts`**: Hardcoded rules that the LLM must include, even if they aren't explicitly in the source code.
- **`buildPrompt`**: A function that receives the concatenated `sources` and returns the final instruction for the LLM.
- **`maxSourceChars`**: Optional limit to prevent token overflow (defaults to reasonable framework limits).

## Generation Commands

The Fufuni framework provides specific scripts to handle the transition from topic definitions to active knowledge.

| Command | Action |
| :--- | :--- |
| `npm run mcp:generate` | Runs a dry-run/cached generation. It only processes topics that have changed. |
| `npm run mcp:generate:force` | Ignores the cache and regenerates every topic file in the directory. |
| `npm run mcp:auto` | The standard pipeline: generates documentation and then publishes it to the runtime modules. Requires `AI_MODEL` and `AI_API_KEY`. |
| `npm run mcp:auto:flash` | High-speed generation using Gemini-1.5-Flash. Uses the encrypted `ai.json.enc` config (requires `CRYPTOKEN`). |

```bash
# Example: Regenerating a specific topic after changing a backend file
export AI_API_KEY="your-key-here"
export AI_MODEL="gpt-4o"
npm run mcp:auto
```

## Knowledge Publishing via gen-knowledge.ts

After the `generate.ts` script creates Markdown files in the `<repo-root>/mcp/` directory, the `gen-knowledge.ts` script (located in `apps/mcp/scripts/`) processes them into the runtime format.

This script performs several critical tasks:
1.  **Markdown Ingestion**: Reads the `.md` files from the `mcp/` folder.
2.  **Indexing**: Builds a BM25 search index for keyword retrieval.
3.  **Vectorization**: (Optional/Dependent on config) Prepares data for semantic search.
4.  **Module Generation**: Writes `apps/mcp/src/knowledge.ts`, `chunks.ts`, and `bm25-index.ts`.

```typescript
// Example of the resulting apps/mcp/src/knowledge.ts (AUTO-GENERATED)
export const KNOWLEDGE_BASE: Record<string, string> = {
  "backend-storage": "# Durable Object Storage\n\nFufuni uses SQLite...",
  "frontend-ui": "# HeroUI Integration\n\nComponents are located in..."
};
```

## Local Development and stdio Mode

To test your new topic before deploying the Cloudflare Worker, you can run the MCP server locally using `stdio` mode. This allows you to connect the server directly to the Claude Desktop app.

### 1. Run the local server
```bash
npx tsx apps/mcp/src/stdio.ts
```

### 2. Configure Claude Desktop
Add the following to your `claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "fufuni-local": {
      "command": "npx",
      "args": [
        "tsx",
        "/absolute/path/to/fufuni/apps/mcp/src/stdio.ts"
      ],
      "env": {
        "NODE_ENV": "development"
      }
    }
  }
}
```

Once configured, restart Claude. You can ask: *"What are the storage patterns in Fufuni?"*. The assistant will call the `fufuni_get_knowledge` tool, and the MCP server will respond with the Markdown generated from your new topic file.

## The Golden Rule: Do Not Edit knowledge.ts

You must **NEVER** edit `apps/mcp/src/knowledge.ts` or any files in `apps/mcp/src/` that contain "generated" warnings.

**Why?**
- **Persistence**: Any manual changes will be overwritten the next time `npm run mcp:auto` is executed.
- **Consistency**: The AI assistant relies on the `bm25-index.ts` to find information. If you edit the text in `knowledge.ts` but not the index, the AI will fail to find your changes or retrieve mismatched snippets.
- **Source of Truth**: The framework enforces that documentation is a direct reflection of the code. If the documentation is wrong, the fix belongs in the `Topic` definition or the source code itself, not the generated output.
