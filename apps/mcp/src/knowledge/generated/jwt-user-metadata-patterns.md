## JWT & User Metadata Patterns Reference

### useTokenUserData() Hook

The `useTokenUserData` hook manages state derived from JWT access token's user_metadata field. It provides reactive updates and cross-component synchronization.

**Return type:**
```typescript
{
  data: T;
  isLoading: boolean;
  isError: boolean;
  setData: (value: T) => void;
}
```

**Available claims (when parsing Auth0 ID token):**
- `sub`: User identifier
- `email`: User email
- `name`: User full name
- `picture`: Profile picture URL
- `permissions`: Array of permission strings
- `roles`: Array of role strings
- `user_metadata`: Custom user data object

**Usage example:**
```typescript
import { useTokenUserData } from "@/hooks/use-token-user-data";

function UserProfile() {
  const { data: userData, isLoading } = useTokenUserData(
    (token) => token ? JSON.parse(atob(token.split('.')[1])).user_metadata : null,
    "user-data-updated"
  );

  if (isLoading) return <div>Loading...</div>;

  return (
    <div>
      <h1>{userData?.name}</h1>
      <img src={userData?.picture} alt="Profile" />
    </div>
  );
}
```

### Auth0 user_metadata

Auth0 user_metadata is arbitrary JSON stored per-user in the authentication provider. It serves as client-side storage for:

- User preferences
- Wishlist items
- Non-sensitive configuration

**Reading metadata:**
```typescript
// Using the hook (client-side)
const { data: metadata } = useTokenUserData(
  (token) => token ? JSON.parse(atob(token.split('.')[1])).user_metadata : {},
  "metadata-updated"
);

// Server-side (from request)
const metadata = req.user?.user_metadata;
```

**Writing metadata:**
```typescript
// Client-side update
const { setData } = useTokenUserData(/* ... */);
setData(newMetadata);

// Dispatch event to sync across components
window.dispatchEvent(new CustomEvent("metadata-updated", { detail: newMetadata }));
```

Store non-sensitive data that needs to be:
- Accessible across devices
- Persistent between sessions
- Available without database queries

### Store Metadata

Store metadata represents per-store configuration settings, distinct from user-specific metadata.

**Client-side helpers:**
```typescript
import { getStoreMetadata, normalizeStoreUrl } from "@/lib/store-metadata";

// Get metadata for current store
const metadata = getStoreMetadata(userMetadata, "https://store.example.com");

// Normalize store URL for metadata key
const key = normalizeStoreUrl("https://store.example.com/");
// Returns "https___store_example_com"
```

**Server-side helpers:**
```typescript
import { getMetadata } from "@/lib/store-metadata";

// In route handler
const metadata = await getMetadata(db, "theme_settings");
```

**HTTP Endpoints:**
- `GET /v1/store-metadata/:key` - Retrieve store metadata (admin)
- `PUT /v1/store-metadata/:key` - Update store metadata (admin)

### Permissions in JWT

Permissions are injected into the JWT during Auth0 login via post-action. They determine access to features.

**Accessing permissions:**
```typescript
// Using the hook
const { data: claims } = useTokenUserData(/* ... */);
const permissions = claims.permissions;

// Alternative access
const auth = useAuth();
const permissions = auth.user?.[namespace + "permissions"];
```

**Example permission check:**
```typescript
function AdminPanel() {
  const { data: claims } = useTokenUserData(/* ... */);

  if (!claims.permissions?.includes("manage:products")) {
    return <div>Access denied</div>;
  }

  return <ProductManager />;
}
```

### Security Note

Never store sensitive information in:
- Auth0 user_metadata (client-readable)
- JWT payload (base64-encoded, not encrypted)

Store sensitive per-customer state in:
- Database tables with proper access controls
- Durable Object storage with authentication

**Prohibited storage:**
- Payment details
- Personal identification numbers
- Authentication secrets
- Internal business logic configuration
