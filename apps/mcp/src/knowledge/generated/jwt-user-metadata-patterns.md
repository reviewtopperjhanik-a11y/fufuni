## JWT & User Metadata Patterns Reference

### useTokenUserData() Hook

The `useTokenUserData` hook manages state derived from the Auth0 JWT token's payload, providing strongly-typed access to user claims and synchronization across components.

**Return type:**
```typescript
{
  data: T;
  isLoading: boolean;
  isError: boolean;
  setData: (value: T) => void;
}
```

**Available claims (from verified facts):**
- `sub`: User identifier
- `email`
- `name`
- `picture`: Profile picture URL
- `permissions`: Array of permission strings
- `roles`: Array of role strings
- `user_metadata`: Arbitrary JSON object

**Usage example:**
```typescript
import { useTokenUserData } from "@/hooks/use-token-user-data";

// Extract wishlist from user_metadata
const { data: wishlist, isLoading, setData: setWishlist } = useTokenUserData(
  (token) => (token ? JSON.parse(atob(token.split('.')[1])).user_metadata?.wishlist : []),
  "wishlist-updated"
);

// Update wishlist
const updateWishlist = async (newWishlist) => {
  setWishlist(newWishlist);
  // Dispatch event to sync other components
  window.dispatchEvent(new CustomEvent("wishlist-updated", { detail: newWishlist }));
};
```

### Auth0 user_metadata

Auth0 `user_metadata` is an arbitrary JSON object stored per-user in Auth0's database. It is primarily used for client-side preferences and state that needs to persist across sessions.

**What to store:**
- User preferences (e.g., theme, language)
- Wishlist items
- Saved carts
- Non-sensitive user-specific data

**Reading user_metadata:**
```typescript
// Via useTokenUserData hook
const { data: metadata } = useTokenUserData(
  (token) => token ? JSON.parse(atob(token.split('.')[1])).user_metadata : null,
  "metadata-updated"
);

// Directly from token (not recommended for production)
const token = await auth.getAccessToken();
const payload = JSON.parse(atob(token.split('.')[1]));
const userMetadata = payload.user_metadata;
```

**Writing user_metadata:**
User metadata is typically updated via API calls to Auth0 or through Fufuni's backend services that proxy these updates.

### Store Metadata

Store metadata refers to per-store configuration settings stored in the database (separate from Auth0's user_metadata). It is used for store-specific configuration like payment settings, shipping options, etc.

**Client-side helpers:**
```typescript
import { getStoreMetadata, normalizeStoreUrl } from "@/lib/store-metadata";

// Get metadata for current store
const storeConfig = getStoreMetadata(userMetadata, "https://store.example.com");

// Normalize store URL for use as key
const key = normalizeStoreUrl("https://store.example.com/");
// Returns "https___store_example_com"
```

**Server-side helpers:**
```typescript
import { getMetadata, setMetadata } from "@/lib/store-metadata";

// In route handlers
const db = getDB(); // Your database connection
const value = await getMetadata(db, "payment_settings");
await setMetadata(db, "shipping_options", { carrier: "FedEx" });
```

**HTTP Endpoints:**
- `GET /v1/store-metadata/:key`: Retrieve store metadata (admin only)
- `PUT /v1/store-metadata/:key`: Update store metadata (admin only)

### Permissions in JWT

Permissions are injected into the JWT during the Auth0 Login post-action and are available in the token's payload.

**Accessing permissions:**
```typescript
// Via useTokenUserData hook
const { data: permissions } = useTokenUserData(
  (token) => token ? JSON.parse(atob(token.split('.')[1])).permissions : [],
  "permissions-updated"
);

// Alternative access via useAuth
const auth = useAuth();
const permissions = auth.user?.[namespace + "permissions"];
```

**Typical permission structure:**
```typescript
interface TokenClaims {
  permissions: string[]; // e.g., ["read:products", "write:orders"]
  roles: string[]; // e.g., ["admin", "customer"]
  // ... other claims
}
```

### Security Note

**Do NOT store in user_metadata:**
- Sensitive personal information (PII)
- Payment details
- Authentication secrets
- Database credentials
- Any data that should not be client-accessible

User metadata is base64-encoded in the JWT and can be decoded client-side. Always use server-side database storage for sensitive per-customer state.
