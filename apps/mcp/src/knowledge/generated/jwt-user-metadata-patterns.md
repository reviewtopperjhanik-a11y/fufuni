## JWT & User Metadata Patterns Reference

---

### **1. `useTokenUserData()` Hook**
**Return type**:
```typescript
{
  data: T;          // Strongly-typed parsed data
  isLoading: boolean;
  isError: boolean;
  setData: (value: T) => void;  // Updates local state + dispatches CustomEvent
}
```

**Available claims** (from Auth0 ID token payload):
```typescript
interface TokenClaims {
  sub: string;       // User ID
  email: string;
  name?: string;
  picture?: string;
  permissions: string[];  // e.g., ["read:products", "write:orders"]
  roles: string[];         // e.g., ["customer", "admin"]
  user_metadata: any;       // Arbitrary JSON (see §2)
}
```

**Usage example** (wishlist management):
```typescript
// apps/client/src/features/wishlist/use-wishlist.ts
import { useTokenUserData } from "@/hooks/use-token-user-data";

export function useWishlist() {
  const { data: wishlist, setData: setWishlist } = useTokenUserData<string[]>(
    (token) => {
      if (!token) return [];
      const claims = JSON.parse(atob(token.split(".")[1])) as TokenClaims;
      return claims.user_metadata?.wishlist || [];
    },
    "wishlist:update"  // CustomEvent name for cross-component sync
  );

  const addToWishlist = (productId: string) => {
    const updated = [...wishlist, productId];
    setWishlist(updated);
    // Dispatch to Auth0 (see §2) would go here
  };

  return { wishlist, addToWishlist };
}
```

### **2. Auth0 `user_metadata`**
**What it is**:
Client-readable JSON blob attached to each user in Auth0. Used for:
- Wishlists
- Saved carts
- UI preferences (e.g., theme, language)
- Non-sensitive per-user state

**How to read/write**:
```typescript
// Reading (client-side)
const { user } = useAuth();
const wishlist = user?.user_metadata?.wishlist || [];

// Writing (via Auth0 Management API)
const updateMetadata = async (newData: any) => {
  const token = await auth.getAccessToken();
  await fetch("https://YOUR_DOMAIN.auth0.com/api/v2/users/{user_id}", {
    method: "PATCH",
    headers: { Authorization: `Bearer ${token}` },
    body: JSON.stringify({ user_metadata: newData }),
  });
};
```

**What to store there**:
✅ Safe:
- Product IDs (wishlist)
- Cart contents (non-PII)
- Theme preferences
- Last-viewed items

❌ **Never** store:
- Payment details
- Addresses (use `app_metadata` or DB)
- API keys
- Any PII beyond what’s already in the token

### **3. Store Metadata**
**Purpose**:
Server-side key-value storage for per-store configuration (e.g., `shipping_rates`, `tax_settings`). **Not the same as `user_metadata`**—this lives in the `store_metadata` SQLite table.

**Client-side helpers** (`apps/client/src/lib/store-metadata.ts`):
```typescript
import { getStoreMetadata } from "@/lib/store-metadata";

// Usage in a React component
const storeConfig = getStoreMetadata(user.user_metadata, "https://store.example.com");
const shippingRates = storeConfig?.shipping_rates;
```

**Server-side helpers** (`apps/merchant/src/lib/store-metadata.ts`):
```typescript
// In a Hono route handler
import { getMetadata } from "@/lib/store-metadata";

app.get("/config", async (c) => {
  const db = c.get("db");
  const taxSettings = await getMetadata(db, "tax_settings");
  return c.json(taxSettings);
});
```

**HTTP endpoints**:
```typescript
// Admin-only routes (require `write:store_metadata` permission)
app.get("/v1/store-metadata/:key", adminOnly, async (c) => {
  const value = await getMetadata(c.get("db"), c.req.param("key"));
  return c.json(value);
});

app.put("/v1/store-metadata/:key", adminOnly, async (c) => {
  const { value } = await c.req.json();
  await setMetadata(c.get("db"), c.req.param("key"), value);
  return c.json({ success: true });
});
```

### **4. Permissions in the JWT**
**How they get there**:
Injected by the Auth0 **Login Action** (post-authentication script). Example:
```javascript
// Auth0 Login Action
exports.onExecutePostLogin = async (event) => {
  if (event.user.email_verified) {
    event.accessToken.permissions = ["read:products"];
    if (event.user.app_metadata?.roles?.includes("admin")) {
      event.accessToken.permissions.push("write:store_metadata");
    }
  }
};
```

**How to read them**:
```typescript
// Client-side
const { data: { permissions } } = useTokenUserData(
  (token) => token ? JSON.parse(atob(token.split(".")[1])) : { permissions: [] },
  "permissions:update"
);

// Server-side (Hono middleware)
app.use("/admin/*", async (c, next) => {
  const token = c.req.header("Authorization")?.replace("Bearer ", "");
  const claims = JSON.parse(atob(token.split(".")[1]));
  if (!claims.permissions.includes("write:store_metadata")) {
    return c.json({ error: "Forbidden" }, 403);
  }
  await next();
});
```

### **5. Security Note**
**Never store in `user_metadata`**:
1. **Sensitive data**: Payment info, addresses, or API keys (use `app_metadata` or DB).
2. **Large datasets**: Auth0 limits `user_metadata` to **10KB**. For bigger data, use Durable Objects.
3. **Server-side secrets**: Assume the client can decode the JWT and read `user_metadata`.

**Safe alternatives**:
| Data Type          | Storage Location          |
|--------------------|----------------------------|
| Payment methods    | `app_metadata` (Auth0)     |
| Order history      | `orders` table (SQLite)    |
| API keys           | `customer_secrets` table   |
| Large preferences  | Durable Object (e.g., `UserPrefsDO`) |
