## The Dual-Sync Migration Pattern

In the Fufuni framework, migrations follow a "Dual-Sync" requirement. While SQL files are maintained in `apps/merchant/migrations/` for historical tracking and local development via Wrangler, the **Durable Object's `ensureInitialized` method is the absolute source of truth**. When a Merchant Durable Object is woken up, it checks its internal `migrations` table and applies missing logic at runtime.

When adding a new feature, you must:
1. Create a new `.sql` file in the migrations folder (e.g., `035-add-loyalty-points.sql`).
2. Add the corresponding `ALTER TABLE` or `CREATE TABLE` logic to the `ensureInitialized` method in `do.ts`.

```typescript
// apps/merchant/src/do.ts - Example of a runtime migration block
async ensureInitialized() {
  const sqlite = this.storage.sql;
  
  // 1. Ensure the migration tracking table exists
  sqlite.exec(`
    CREATE TABLE IF NOT EXISTS migrations (
      name TEXT PRIMARY KEY,
      applied_at TEXT NOT NULL DEFAULT (datetime('now'))
    );
  `);

  // 2. Check and apply Migration 035
  const hasM35 = sqlite.exec("SELECT 1 FROM migrations WHERE name = '035'").one();
  if (!hasM35) {
    sqlite.exec(`
      ALTER TABLE customers ADD COLUMN loyalty_points INTEGER DEFAULT 0;
      INSERT INTO migrations (name) VALUES ('035');
    `);
  }
}
```

## Indexing & Performance Strategies

Since Fufuni runs on SQLite within a Durable Object, index selection is critical to avoid blocking the single-threaded event loop during complex queries. Migration 005 and 025 focused exclusively on these optimizations.

1. **Partial Indexes**: Used in Migration 005 for high-traffic status filters.
   `CREATE INDEX idx_orders_processing ON orders(created_at) WHERE status = 'processing';`
2. **Composite Indexes**: Used for multi-tenant store filtering.
   `CREATE INDEX idx_carts_store_status_expires ON carts(store_id, status, expires_at);`
3. **Unique Constraints**: Used to prevent duplicate inventory logs or redundant regional prices.
   `UNIQUE(sku, warehouse_id)` in `warehouse_inventory`.

Every table in Fufuni includes `created_at` and `updated_at` columns. Most tables using `updated_at` also feature a SQLite trigger to automate the timestamp update:

```sql
CREATE TRIGGER IF NOT EXISTS trg_tax_rates_updated_at
AFTER UPDATE ON tax_rates
FOR EACH ROW
BEGIN
  UPDATE tax_rates SET updated_at = datetime('now') WHERE id = NEW.id;
END;
```
