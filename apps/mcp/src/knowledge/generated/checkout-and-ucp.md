## Checkout & UCP Reference

### UCP (Universal Cart Protocol)

**Endpoint**: `POST /v1/ucp`

**Request Body**:
```typescript
interface UCPRequest {
  items: Array<{
    id: string; // product ID or SKU
    quantity: number;
  }>;
  currency: string; // ISO 4217 currency code
  buyer?: {
    email?: string;
    first_name?: string;
    last_name?: string;
  };
}
```

**Response Shape**:
```typescript
interface UCPResponse {
  items: Array<{
    id: string;
    title: string;
    quantity: number;
    unit_price: {
      amount: number;
      currency: string;
    };
    total_price: {
      amount: number;
      currency: string;
    };
    tax: {
      amount: number;
      currency: string;
    };
  }>;
  currency: string;
  total: number;
  taxTotal: number;
}
```

**When to Call It**: Call this endpoint whenever the cart changes to validate items, compute prices, and calculate taxes before showing the order summary page.

### Checkout

**Endpoint**: `POST /v1/checkout`

**Required Auth**: Auth0 JWT (customerAuthMiddleware)

**Full Request**:
```typescript
interface CheckoutRequest {
  cartId: string;
  success_url: string;
  cancel_url: string;
  collect_shipping?: boolean;
  shipping_countries?: string[];
  shipping_options?: any[];
}
```

**Full Response**:
```typescript
interface CheckoutResponse {
  clientSecret: string;
  sessionId: string;
  orderId: string;
}
```

**What Happens on Success**:
1. The cart items are validated against live inventory.
2. Taxes are computed using the tax engine.
3. A Stripe PaymentIntent or Checkout Session is created.
4. An order is pre-created in pending status.
5. The response includes the client secret, session ID, and order ID.

### Inventory Validation

**When It Fires**: Inventory validation is checked synchronously inside the Durable Object transaction during the checkout process.

**What Error It Throws**: If any item is out of stock, the endpoint fails with a 409 Conflict error.

### Tax Computation Inside Checkout

**How It Uses the Tax Engine**: The tax computation is handled inside the checkout process using a tax engine. The tax engine calculates the tax amount based on the cart items, shipping address, and other relevant factors. The computed tax is then included in the response.

### Stripe Integration

**PaymentIntent Flow vs Checkout Session Flow**:
- **PaymentIntent Flow**: Used for direct payment processing. The frontend collects payment details and confirms the payment using the client secret.
- **Checkout Session Flow**: Used for a more comprehensive checkout experience, including shipping and billing information collection. The frontend redirects the user to Stripe's checkout page.

### Stripe Webhook Events Handled and Their Side Effects

**Handled Events**:
1. `payment_intent.succeeded`: Updates the order to paid status.
2. `payment_intent.payment_failed`: Updates the order to failed status.
3. `checkout.session.completed`: Handles the completion of the checkout session, including 3DS flow.

**Side Effects**:
- Updates the order status in the database.
- Sends notifications or triggers other processes based on the order status.

### Required Wrangler Secrets for Stripe

The required Wrangler secrets for Stripe are:
- `STRIPE_SECRET_KEY`
- `STRIPE_WEBHOOK_SECRET`

These secrets must be set in the Wrangler configuration and not in the .env file.
