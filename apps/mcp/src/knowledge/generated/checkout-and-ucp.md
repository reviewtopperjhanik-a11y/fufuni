## Checkout & UCP Reference

### UCP (Universal Cart Protocol)

The UCP endpoint is used for validating and computing the cart details without involving Stripe. It's called whenever the cart changes to get the latest product details, quantities, unit prices, taxes, and totals.

**Endpoint**: POST `/v1/ucp`

**Request Body**:
```typescript
{
  items: [
    {
      productId: string,
      variantId: string,
      quantity: number
    }
  ],
  currency: string,
  locale: string
}
```

**Response**:
```typescript
{
  items: [
    {
      product: Product,
      quantity: number,
      unitPrice: number,
      tax: number,
      subtotal: number
    }
  ],
  currency: string,
  total: number,
  taxTotal: number
}
```

**When to Call**: Call this endpoint whenever the cart changes to ensure the frontend has the latest details before showing the order summary page.

### Checkout

The checkout endpoint is specifically for Stripe integration. It validates cart items against live inventory, computes tax, creates a Stripe PaymentIntent or Checkout Session, and returns the necessary details for the frontend to complete the payment.

**Endpoint**: POST `/v1/checkout`

**Required Auth**: Auth0 JWT (customerAuthMiddleware)

**Full Request**:
```typescript
{
  cartId: string,
  success_url: string,
  cancel_url: string,
  collect_shipping: boolean,
  shipping_countries: string[],
  shipping_options: any[]
}
```

**Full Response**:
```typescript
{
  clientSecret: string,
  sessionId: string,
  orderId: string
}
```

**What Happens on Success**:
1. The cart is validated against live inventory.
2. Taxes are computed based on the cart items and shipping address.
3. A Stripe PaymentIntent or Checkout Session is created.
4. The order is pre-created in pending status.
5. The response includes the clientSecret, sessionId, and orderId for the frontend to complete the payment.

### Inventory Validation

Inventory validation occurs synchronously inside the DO transaction. If any item is out of stock, the endpoint fails with a 409 Conflict error.

**When it Fires**: During the checkout process, before creating the Stripe PaymentIntent or Checkout Session.

**What Error it Throws**:
```typescript
{
  code: 'insufficient_inventory',
  message: 'Insufficient inventory for one or more items',
  details: {
    sku: string,
    available: number,
    requested: number
  }
}
```

### Tax Computation Inside Checkout

The checkout process uses a tax engine to compute taxes based on the cart items and shipping address. The tax computation is done using the `calculateCartTaxes` function, which takes the cart ID and shipping country as parameters.

**How it Uses the Tax Engine**:
```typescript
const { taxes } = await calculateCartTaxes(db, cartId, cart.shipping_country);
```

### Stripe Integration

There are two flows for Stripe integration: PaymentIntent flow and Checkout Session flow.

**PaymentIntent Flow**: Used for direct payment processing without redirecting the user to Stripe's checkout page.

**Checkout Session Flow**: Used for redirecting the user to Stripe's checkout page for payment processing.

### Stripe Webhook Events Handled and Their Side Effects

The Stripe webhooks handle the following events:

1. **payment_intent.succeeded**: Updates the order to paid status.
2. **payment_intent.payment_failed**: Updates the order to failed status.
3. **checkout.session.completed**: Handles the completion of the checkout session, typically for 3DS flow.

### Required Wrangler Secrets for Stripe

The following secrets must be configured in Wrangler:

- `STRIPE_SECRET_KEY`: The secret key for the Stripe API.
- `STRIPE_WEBHOOK_SECRET`: The secret for verifying Stripe webhook events.

These secrets should be configured using the Wrangler CLI:
```bash
wrangler secret put STRIPE_SECRET_KEY
wrangler secret put STRIPE_WEBHOOK_SECRET
```
