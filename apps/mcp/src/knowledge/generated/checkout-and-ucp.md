## Universal Commerce Protocol (UCP) Integration

Fufuni implements the [Universal Commerce Protocol](https://ucp.dev/) to facilitate interoperability between autonomous agents and the e-commerce backend. While the framework provides standard REST endpoints for the frontend, UCP serves as the generic validation and price-computation layer.

The primary endpoint is `POST /v1/ucp`. This endpoint is idempotent and does not modify the database state beyond logging; it is used by the frontend to fetch a final order summary, including taxes and shipping, before the user commits to the payment.

### UCP Request and Response

Call this endpoint whenever the cart contents change or when the user navigates to the checkout summary page. It ensures that prices are resolved according to the selected region and currency.

```typescript
// Example: Fetching a UCP Summary (Frontend)
const fetchUcpSummary = async (items: { sku: string; quantity: number }[], currency: string) => {
  const response = await fetch('/v1/ucp', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      line_items: items.map(i => ({
        item: { id: i.sku },
        quantity: i.quantity
      })),
      currency: currency.toUpperCase(),
    }),
  });

  if (!response.ok) {
    const error = await response.json();
    throw new Error(error.message);
  }

  // UCP Response provides a breakdown of all costs
  return await response.json() as {
    id: string;
    items: Array<{
      sku: string;
      title: string;
      quantity: number;
      unitPrice: number;
      tax: number;
      subtotal: number;
    }>;
    currency: string;
    total: number;
    taxTotal: number;
    totals: Array<{ type: string; amount: number; label: string }>;
  };
};
```

## Stripe Checkout Flow

The `POST /v1/checkout` endpoint is the gateway to finalizing a purchase. Unlike UCP, this endpoint is stateful: it validates inventory, locks the cart, computes final taxes, and prepares a Stripe session.

### Authentication and Request

This endpoint is protected by `customerAuthMiddleware`. An Auth0 JWT is required in the `Authorization` header. The system automatically associates the created order with the authenticated customer's ID.

```typescript
/**
 * POST /v1/checkout
 * Required Auth: Bearer <Auth0_JWT>
 */
interface CheckoutRequest {
  cartId: string;
  success_url: string;
  cancel_url: string;
  collect_shipping?: boolean;
}

interface CheckoutResponse {
  clientSecret: string; // Used for Stripe Elements/Embedded
  sessionId: string;    // Stripe Checkout Session ID
  orderId: string;      // The Fufuni Order ID (Status: 'pending')
}
```

### Success Execution Sequence

When a checkout is successfully initiated:
1.  **Inventory Locking:** The system checks all SKUs in the cart against the live SQLite database inside the Durable Object.
2.  **Tax Finalization:** `calculateCartTaxes` is invoked using the customer's provided shipping country.
3.  **Order Pre-creation:** A record is inserted into the `orders` table with a `pending` status.
4.  **Stripe Initialization:** A Stripe Checkout Session or PaymentIntent is created.
5.  **Response:** The `orderId` and Stripe identifiers are returned to the client.

## Inventory Validation and Constraints

Fufuni performs strict inventory validation during the checkout process to prevent overselling. This check is performed synchronously within the Durable Object's transaction scope.

### Synchronous Locking Logic

If the quantity requested for any SKU exceeds the available stock (`on_hand - reserved`), the endpoint immediately aborts and returns a `409 Conflict`.

```typescript
// Backend: Inventory validation inside checkout.ts
const validateInventory = async (db: Database, items: CartItem[]) => {
  for (const item of items) {
    const [inv] = await db.query(
      `SELECT on_hand, reserved FROM inventory WHERE sku = ?`,
      [item.sku]
    );
    
    const available = inv ? (inv.on_hand - inv.reserved) : 0;
    
    if (available < item.qty) {
      // Fires 409 Conflict - Immediately stops checkout flow
      throw ApiError.conflict(`Insufficient inventory for SKU: ${item.sku}`);
    }
  }
};
```

The error response follows the standard Fufuni error schema:
```json
{
  "code": "insufficient_inventory",
  "message": "Only 2 of SKU TEE-BLK-M available",
  "details": { "sku": "TEE-BLK-M", "available": 2 }
}
```

## Tax Computation and Inclusive Pricing

Tax calculation occurs inside the checkout route and relies on the `calculateCartTaxes` helper. Fufuni supports both **Tax Inclusive (TTC)** and **Tax Exclusive (HT)** pricing models, determined at the Region level.

### Logic Flow
1.  **Retrieve Region Settings:** Check if the region is marked as `tax_inclusive`.
2.  **Calculate Per-Item Tax:** Look up `tax_rates` associated with the region and the variant's `tax_code`.
3.  **Adjustment for Stripe:** If pricing is inclusive, Fufuni back-calculates the net amount to ensure Stripe displays the correct tax breakdown without double-charging.

```typescript
// Example: Internal tax calculation logic
const { taxes, shipping_ht_cents } = await calculateCartTaxes(db, cartId, countryCode);

// If inclusive, net = gross / (1 + rate)
const taxInclusive = region.tax_inclusive === 1;
const unitAmount = taxInclusive 
  ? Math.round(item.unit_price_cents / (1 + (itemTaxRate / 100)))
  : item.unit_price_cents;
```

## Stripe Integration Architecture

Fufuni avoids heavy dependencies by using a custom `stripe.ts` utility. This is a thin wrapper around the Stripe REST API, optimized for the Cloudflare Workers runtime (using `fetch` instead of Node-specific libraries).

### PaymentIntent vs Checkout Session

Fufuni supports two primary flows:
1.  **Checkout Session (Redirect/Embedded):** The default flow. It handles 3D Secure, Apple Pay, and Google Pay out of the box. Returns a `sessionId`.
2.  **PaymentIntent (Elements):** Used for custom checkout UIs. Returns a `clientSecret` that the frontend uses with the Stripe.js `confirmPayment` method.

### Stripe Webhook Handling

Webhooks are processed at `POST /v1/webhooks/stripe`. This endpoint is critical for reconciling payment status with the order database.

| Event | Side Effect |
| :--- | :--- |
| `payment_intent.succeeded` | Updates order status to `paid`, releases inventory reservation, and triggers shipment email. |
| `payment_intent.payment_failed` | Updates order status to `failed` and alerts the merchant. |
| `checkout.session.completed` | Used primarily for redirect flows to ensure the order is marked `paid` once the user returns. |
| `charge.refunded` | Updates order status to `refunded`. |

```typescript
// Internal logic for processing a successful payment
async function handlePaymentSucceeded(db: Database, paymentIntent: Stripe.PaymentIntent) {
  const orderId = paymentIntent.metadata.order_id;
  
  await db.run(
    `UPDATE orders SET status = 'paid', updated_at = ? WHERE id = ?`,
    [now(), orderId]
  );
  
  // Inventory is officially moved from 'reserved' to deducted from 'on_hand'
  // logic handled in inventory lib...
}
```

## Infrastructure and Secrets

To enable Stripe processing, specific environment variables must be configured. These must **never** be stored in a `.env` file for production; they are managed via Wrangler Secrets to ensure they are encrypted at rest and only available to the Worker runtime.

### Required Wrangler Secrets

Execute the following commands to set up a new environment:

```bash
# The secret key from the Stripe Dashboard (sk_live_...)
wrangler secret put STRIPE_SECRET_KEY

# The webhook signing secret (whsec_...) found in the Stripe Webhook settings
wrangler secret put STRIPE_WEBHOOK_SECRET

# Optional: Public key for frontend initialization (if shared via backend config)
wrangler secret put STRIPE_PUBLIC_KEY
```

In your `wrangler.toml`, ensure the compatibility date is set to a recent version to support the `fetch` signatures required by the Stripe REST wrapper:

```toml
name = "fufuni-merchant-api"
main = "src/index.ts"
compatibility_date = "2024-04-01"

[vars]
# Non-sensitive config can go here
STRIPE_API_VERSION = "2023-10-16"
```
