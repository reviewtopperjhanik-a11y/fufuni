## Orders & Refunds Reference

### Order Status Machine

```
pending → paid → processing → shipped → delivered
  \__________________/   \___________/
      v (cancel)             v (cancel)
    cancelled              cancelled
      \___________________________/
                 v (refund)
              refunded
```

Valid transitions:
- `pending` → `paid` (payment received)
- `paid` → `processing` (order being prepared)
- `processing` → `shipped` (order sent to carrier)
- `shipped` → `delivered` (carrier confirms delivery)
- Any post-paid status → `cancelled` (order voided before fulfillment)
- Any post-paid status → `refunded` (full or partial refund issued)

```typescript
// Valid status values (from order-status config)
type OrderStatus = 'pending' | 'paid' | 'processing' | 'shipped' | 'delivered' | 'refunded' | 'canceled';
```

### Updating Order Status

To update an order status, use the PATCH endpoint with the new status:

```typescript
import { adminApp } from '@/routes/orders';

await fetch(`/v1/orders/${orderId}/status`, {
  method: 'PATCH',
  headers: {
    'Authorization': 'Bearer sk_...',
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({
    status: 'shipped',
    tracking_number: 'USPS123456789',
    tracking_url: 'https://tracking.example.com/USPS123456789'
  })
});
```

Required permission: `admin:store`

When updating to `shipped`, the system automatically sets `shipped_at` timestamp if not already present.

### Refund Processing Flow

Refunds are processed through the dedicated endpoint:

```typescript
await fetch(`/v1/orders/${orderId}/refund`, {
  method: 'POST',
  headers: {
    'Authorization': 'Bearer sk_...',
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({
    amount_cents: 1500, // Optional: omit for full refund
    reason: 'requested_by_customer',
    notes: 'Customer changed mind about the product'
  })
});
```

1. Stripe API creates the refund for the specified amount
2. Database records the refund in `refunds` table with:
   - Stripe refund ID
   - Amount in cents
   - Reason and notes
   - Status (succeeded/pending/failed)
3. Order status updates:
   - Full refund: `refunded`
   - Partial refund: `partially_refunded`
4. Webhook dispatched with `order.refunded` event
5. Customer receives status update email

### Order Cancellation

Cancellation endpoint restores inventory:

```typescript
await fetch(`/v1/orders/${orderId}/cancel`, {
  method: 'PATCH',
  headers: {
    'Authorization': 'Bearer sk_...',
  }
});
```

Side effects:
- Sets order status to `canceled`
- Increases `on_hand` inventory for each line item
- Updates warehouse inventory records
- Dispatches `order.canceled` webhook event

### CSV Export

Export orders within a date range:

```typescript
await fetch('/v1/orders?export=csv&from=2023-01-01T00:00:00Z&to=2023-01-31T23:59:59Z', {
  headers: {
    'Authorization': 'Bearer sk_...',
  }
});
```

Query parameters:
- `from` (ISO 8601): Start date
- `to` (ISO 8601): End date
- `status` (optional): Filter by status (e.g. `status=paid,shipped`)

### Order Item Immutability

Order items are permanently recorded at purchase time:

```sql
CREATE TABLE order_items (
  id TEXT PRIMARY KEY,
  order_id TEXT NOT NULL,
  sku TEXT NOT NULL,
  title TEXT NOT NULL,
  qty INTEGER NOT NULL,
  unit_price_cents INTEGER NOT NULL,
  -- Captured at purchase time:
  currency TEXT,
  tax_rate TEXT,
  tax_amount INTEGER,
  FOREIGN KEY (order_id) REFERENCES orders(id)
);
```

Key characteristics:
1. Prices are frozen at checkout (protects against future price changes)
2. Product titles are stored as they appeared at purchase time
3. Tax rates and amounts are calculated once and preserved
4. Inventory snapshots prevent discrepancies from future catalog changes

This immutability ensures accurate financial records and prevents disputes about historical pricing.
