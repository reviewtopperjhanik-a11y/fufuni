## Order Status Machine
Valid transitions (→) and terminal states (*):
```
pending → paid → processing → shipped → delivered*
               ↘ refunded*
               ↘ canceled*
```
- **pending**: Initial state for carts awaiting payment.
- **paid**: Payment succeeded (Stripe `payment_intent.succeeded`).
- **processing**: Inventory reserved, fulfillment started.
- **shipped**: Tracking number added via PATCH.
- **delivered**: Manual update after carrier confirmation.
- **refunded**: Full/partial refund processed (Stripe + DB).
- **canceled**: Manual cancellation (restores inventory).

## Updating Order Status
Use the admin-only PATCH endpoint to transition status or add tracking:

```typescript
// Example: Mark order as shipped and add tracking
const response = await fetch(`/v1/orders/${orderId}`, {
  method: 'PATCH',
  headers: {
    'Authorization': `Bearer ${adminToken}`,
    'Content-Type': 'application/json',
  },
  body: JSON.stringify({
    status: 'shipped',
    tracking_number: 'UPS123456789',
    tracking_url: 'https://ups.com/track?num=UPS123456789',
  }),
});

// Response: formatted Order object with updated fields
const updatedOrder = await response.json();
```

**Key behaviors**:
- Setting `status: 'shipped'` auto-populates `shipped_at` if not already set.
- Triggers webhook `order.shipped` and sends customer email (if `STORE_URL` is configured).
- Validates transitions (e.g., cannot go from `delivered` → `processing`).

## Refund Flow
Partial/full refunds are processed via Stripe and recorded in the `refunds` table.

### Endpoint
```typescript
// Partial refund (500 cents = €5.00)
const refund = await fetch(`/v1/orders/${orderId}/refund`, {
  method: 'POST',
  headers: { 'Authorization': `Bearer ${adminToken}` },
  body: JSON.stringify({
    amount_cents: 500,  // Omit for full refund
    reason: 'requested_by_customer',
    notes: 'Customer changed their mind about the red shirt',
  }),
});
```

### Database Changes
1. **Stripe Refund**:
   Calls `stripe.refunds.create()` with the order’s `stripe_payment_intent_id`.
2. **Refunds Table**:
   Inserts a record with `stripe_refund_id`, `amount_cents`, and `status`.
3. **Order Update**:
   - Full refund → `status: 'refunded'`
   - Partial refund → `status: 'partially_refunded'`
4. **Webhook**:
   Emits `order.refunded` with refund details.

**Constraints**:
- Order must be in `paid`, `processing`, `shipped`, or `delivered` status.
- Test orders (no `stripe_payment_intent_id`) cannot be refunded via API.

## Order Cancellation
Cancels an order and restores inventory to warehouses.

```typescript
await fetch(`/v1/orders/${orderId}/cancel`, {
  method: 'POST',
  headers: { 'Authorization': `Bearer ${adminToken}` },
});
```

**Side Effects**:
1. Sets `status: 'canceled'`.
2. **Inventory Restoration**:
   - For each `order_items` row, reverses the `on_hand` deduction in `warehouse_inventory` (prioritized by warehouse `priority`).
   - Falls back to global `inventory` table if no regional warehouses exist.
3. **No Stripe Action**: Cancellation ≠ refund. Use `/refund` separately if needed.

## CSV Export
Generate a CSV of orders within a date range:

```bash
curl -H "Authorization: Bearer $ADMIN_TOKEN" \
  "https://api.example.com/v1/orders?export=csv&from=2023-01-01T00:00:00Z&to=2023-12-31T23:59:59Z" \
  --output orders-2023.csv
```

**CSV Columns**:
`order_number,status,customer_email,created_at,subtotal_cents,tax_cents,shipping_cents,total_cents,currency,tracking_number,tracking_url,shipped_at,items_json`

**Notes**:
- `items_json` contains an array of `{sku, title, qty, unit_price_cents}`.
- Max 10,000 orders per export (use pagination for larger ranges).

## Order Item Immutability
**Why prices are frozen at purchase time**:
1. **Audit Compliance**:
   The `order_items` table stores `unit_price_cents` and `tax_amount_cents` as captured during checkout. This ensures:
   - Tax reports match the exact amounts charged.
   - Customers see the price they agreed to, even if the product price changes later.

2. **Schema**:
   ```sql
   CREATE TABLE order_items (
     id TEXT PRIMARY KEY,
     order_id TEXT NOT NULL,
     sku TEXT NOT NULL,
     title TEXT NOT NULL,  -- Variant title at time of purchase
     qty INTEGER NOT NULL,
     unit_price_cents INTEGER NOT NULL,  -- Immutable
     tax_rate REAL,       -- Immutable
     tax_amount_cents INTEGER,  -- Immutable
     product_id TEXT,     -- Reference only (denormalized)
     FOREIGN KEY (order_id) REFERENCES orders(id)
   );
   ```

3. **Example**:
   If a product’s price increases from €19.99 → €24.99 after purchase, the order item still reflects €19.99.

**Exception**:
- **Discounts**: Applied dynamically during checkout but stored as a fixed `discount_amount_cents` on the order.
