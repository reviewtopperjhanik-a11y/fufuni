## Order Status Machine

The Fufuni framework follows a strict state machine for order processing. Transitions are generally linear, though terminal states like `canceled` or `refunded` can be triggered from multiple points once the order has been paid.

```text
[ pending ] 
     |
     v
[   paid   ] <----------- (Stripe Webhook: checkout.session.completed)
     |
     +----[ canceled ] -- (Inventory restored to warehouses)
     |
     v
[ processing ] ---------- (Packaging/Labeling started)
     |
     v
[  shipped   ] ---------- (Tracking number assigned, email sent)
     |
     v
[ delivered  ] ---------- (Final state for successful delivery)
     |
     +----[ refunded ] -- (Full refund via Stripe, status terminal)
```

## API Endpoint Reference

All order management endpoints are nested under `/v1/orders`. Admin-specific routes require the `admin:store` permission via Auth0 or a legacy secret key.

| Method | Path | Auth | Description |
| :--- | :--- | :--- | :--- |
| `GET` | `/v1/orders` | `admin:store` | List all orders (paginated). Supports `status` and `email` filters. |
| `GET` | `/v1/me/orders` | `customer` | List orders belonging to the authenticated user. |
| `GET` | `/v1/orders/:id` | `admin:store` | Get full order details, including line items. |
| `PATCH` | `/v1/orders/:id` | `admin:store` | Update status, tracking number, or tracking URL. |
| `POST` | `/v1/orders/:id/refund`| `admin:store` | Trigger a Stripe refund (partial or full). |
| `PATCH` | `/v1/orders/:id/cancel`| `admin:store` | Cancel order and restore inventory. |
| `GET` | `/v1/orders/:id/invoice`| `admin:store` | Returns a 1-hour signed URL for the PDF invoice. |

## Updating Order Status

Status updates are performed via the `PATCH /v1/orders/:id` endpoint. When a status changes to `shipped`, `delivered`, `refunded`, or `canceled`, Fufuni automatically triggers transactional emails and dispatches webhooks.

### Admin Status Update Logic
The following code demonstrates how the backend handles status transitions and side effects like email dispatch.

```typescript
// From apps/merchant/src/routes/orders.ts
adminApp.openapi(updateOrder, async (c) => {
  const { orderId } = c.req.valid('param');
  const { status, tracking_number } = c.req.valid('json');
  const db = getDb(c.var.db);

  // 1. Update the record
  await db.run(
    `UPDATE orders SET status = ?, tracking_number = ?, updated_at = ? WHERE id = ?`,
    [status, tracking_number, now(), orderId]
  );

  // 2. Side Effect: Transactional Email
  if (['shipped', 'delivered', 'refunded'].includes(status)) {
    c.executionCtx.waitUntil(
      sendOrderStatusEmail(c.env, c.var.db, orderId, status).catch(console.error)
    );
  }

  // 3. Side Effect: Webhook Dispatch
  await dispatchWebhooks(c.var.db, c.executionCtx, 'order.updated', { orderId, status });

  return c.json({ success: true });
});
```

## Refund Management

Refunds are processed through Stripe and recorded in the SQLite-backed Durable Object. Fufuni supports **partial refunds**, allowing merchants to refund specific amounts (e.g., if one item in a multi-item order is out of stock).

1. **Stripe Call:** The system calls `stripe.refunds.create` using the `stripe_payment_intent_id` stored on the order.
2. **DB Audit:** A new entry is created in the `refunds` table.
3. **Status Update:** If the refund amount equals or exceeds `total_cents`, the order is marked `refunded`. Otherwise, it is marked `partially_refunded`.

### Partial Refund Request Example
```typescript
async function refundOrderItem(orderId: string, amountCents: number) {
  const res = await fetch(`/v1/orders/${orderId}/refund`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      amount_cents: amountCents,
      reason: 'requested_by_customer',
      notes: 'Item damaged during transit'
    })
  });
  return res.json();
}
```

## Order Cancellation & Inventory Restoration

When an order is canceled (via `PATCH /v1/orders/:id/cancel`), the framework ensures that inventory levels are restored. Since Fufuni supports multi-warehouse inventory, the system must identify which warehouse originally "fulfilled" the reservation.

### Restoration Side Effect
```typescript
// Logic triggered during cancellation
async function restoreInventory(db: DOStub, orderId: string) {
  const items = await db.query<any>(
    `SELECT sku, qty FROM order_items WHERE order_id = ?`,
    [orderId]
  );

  for (const item of items) {
    // Note: In a multi-warehouse setup, we restore to the primary warehouse 
    // or the one flagged in the fulfillment record.
    await db.run(
      `UPDATE inventory SET on_hand = on_hand + ?, updated_at = ? WHERE sku = ?`,
      [item.qty, now(), item.sku]
    );
  }
}
```

## Order Item Immutability

One of the core architectural principles of Fufuni is that **orders are a snapshot in time**. When a customer completes a checkout, the specific details of the products are copied into the `order_items` table.

This ensures that if a merchant changes the price of a product or deletes a variant a week later, the historical order record remains accurate for accounting.

### Data Captured at Purchase
The `order_items` table stores the following immutable fields:
- `product_id` & `variant_id`: References for internal linking.
- `sku` & `title`: To preserve the name of the product as it was seen by the customer.
- `unit_price_cents`: The exact price paid.
- `currency`: The currency code used for the transaction.
- `tax_rate` & `tax_amount`: For local compliance reporting.

```sql
-- Schema representation of the immutable item record
CREATE TABLE order_items (
    id TEXT PRIMARY KEY,
    order_id TEXT NOT NULL,
    sku TEXT NOT NULL,
    title TEXT NOT NULL,
    qty INTEGER NOT NULL,
    unit_price_cents INTEGER NOT NULL,
    tax_rate REAL DEFAULT 0.0,
    tax_amount_cents INTEGER DEFAULT 0,
    currency TEXT NOT NULL,
    FOREIGN KEY (order_id) REFERENCES orders(id)
);
```

### Order Summary Logic
When displaying an order, always calculate totals from the captured `order_items` rather than re-querying the `variants` table.

```typescript
interface OrderItem {
  sku: string;
  qty: number;
  unit_price_cents: number;
}

function calculateOrderSubtotal(items: OrderItem[]): number {
  return items.reduce((sum, item) => sum + (item.unit_price_cents * item.qty), 0);
}
```
