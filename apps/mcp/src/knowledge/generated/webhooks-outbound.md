## Outbound Webhooks Reference

### Supported Events and Triggers
Outbound webhooks notify external systems when domain events occur. Each event includes a standardized payload with `id`, `type`, `created_at`, and `data` fields.

| Event Name          | Trigger Point                                                                 |
|---------------------|------------------------------------------------------------------------------|
| `order.created`     | Fired after a Stripe checkout session completes and the order is persisted.  |
| `order.updated`     | Fired when order status changes (e.g., `paid` → `shipped`).                 |
| `order.shipped`     | Fired when an order's status is updated to `shipped`.                       |
| `order.refunded`    | Fired when a refund is processed for an order.                              |
| `inventory.low`     | Fired when a SKU's available quantity (`on_hand - reserved`) ≤ 5.          |
| `order.*`           | Wildcard: subscribes to all order-related events.                            |
| `*`                 | Subscribes to **all** events, including future additions.                   |

**Example Payload (`order.created`)**:
```typescript
{
  id: "whdel_123456789",
  type: "order.created",
  created_at: "2025-01-01T00:00:00Z",
  data: {
    order: {
      id: "ord_123",
      number: "FUF-1001",
      status: "paid",
      customer_email: "customer@example.com",
      shipping: { /* address */ },
      amounts: { /* monetary totals */ },
      items: [ /* line items */ ],
      stripe: { checkout_session_id: "cs_123", payment_intent_id: "pi_123" }
    }
  }
}
```

### Endpoint Registration
Register a new webhook endpoint via `POST /v1/webhooks/outbound` (admin-only). The response includes a **one-time secret** for HMAC verification.

**Request**:
```typescript
POST /v1/webhooks/outbound
Authorization: Bearer sk_admin_...
Content-Type: application/json

{
  "url": "https://your-server.com/fufuni-webhook",
  "events": ["order.created", "inventory.low"]
}
```

**Response (201)**:
```typescript
{
  "id": "wh_123",
  "url": "https://your-server.com/fufuni-webhook",
  "events": ["order.created", "inventory.low"],
  "status": "active",
  "secret": "whsec_abc123...",  // Only shown once!
  "created_at": "2025-01-01T00:00:00Z"
}
```

**Key Rules**:
- `url` must use `http:` or `https:`.
- `events` must be a subset of the [supported events](#supported-events-and-triggers).
- The `secret` is **only returned once** (on creation). Store it securely.

### Delivery Mechanics
Deliveries are **asynchronous** and retried on failure. The system:
1. Inserts a record into `webhook_deliveries` with `status = 'pending'`.
2. Attempts delivery in a background task via `ctx.waitUntil`.
3. Retries failed deliveries (HTTP 4xx/5xx or network errors) with exponential backoff.

**Retry Schedule**:
| Attempt | Delay   | Notes                                  |
|---------|---------|----------------------------------------|
| 1       | 0s      | Immediate first attempt.              |
| 2       | 2s      | After 2^1 seconds.                    |
| 3       | 8s      | After 2^2 seconds.                    |

**Failure Conditions**:
- Permanent failures (e.g., HTTP 400/404/410) are **not retried**.
- Temporary failures (5xx, timeouts) trigger retries up to 3 times.

### HMAC-SHA256 Signature
Each delivery includes a signature header to verify payload integrity.

**Signature Computation** (in `lib/webhooks.ts`):
```typescript
async function signPayload(payload: string, secret: string): Promise<string> {
  const encoder = new TextEncoder();
  const key = await crypto.subtle.importKey(
    'raw',
    encoder.encode(secret),
    { name: 'HMAC', hash: 'SHA-256' },
    false,
    ['sign']
  );
  const signature = await crypto.subtle.sign('HMAC', key, encoder.encode(payload));
  return Array.from(new Uint8Array(signature))
    .map(b => b.toString(16).padStart(2, '0'))
    .join('');
}
```

**Headers Sent**:
| Header                | Value                                                                 |
|-----------------------|-----------------------------------------------------------------------|
| `X-Fufuni-Signature`  | HMAC-SHA256 of the raw JSON payload (hex-encoded).                     |
| `X-Fufuni-Timestamp`  | Unix timestamp (seconds) when the payload was generated.             |
| `X-Fufuni-Delivery-Id`| Unique ID for the delivery attempt (matches `webhook_deliveries.id`). |

### Signature Verification (Node.js)
Consumers **must** verify the signature to ensure the webhook is genuine. Example:

```typescript
import crypto from 'node:crypto';

function verifyWebhook(
  payload: string,
  signature: string,
  secret: string,
  timestamp: string,
  toleranceSeconds = 300 // 5-minute tolerance
): boolean {
  // 1. Check timestamp freshness
  const now = Math.floor(Date.now() / 1000);
  if (Math.abs(now - Number(timestamp)) > toleranceSeconds) {
    return false;
  }

  // 2. Recompute HMAC
  const hmac = crypto.createHmac('sha256', secret)
    .update(payload)
    .digest('hex');

  // 3. Compare with signature (constant-time)
  return crypto.timingSafeEqual(
    Buffer.from(hmac),
    Buffer.from(signature)
  );
}

// Usage:
const rawBody = JSON.stringify(req.body);
const isValid = verifyWebhook(
  rawBody,
  req.headers['x-fufuni-signature'],
  process.env.FUFUNI_WEBHOOK_SECRET!,
  req.headers['x-fufuni-timestamp']
);

if (!isValid) {
  throw new Error('Invalid webhook signature');
}
```

**Security Notes**:
- Use **constant-time comparison** (`timingSafeEqual`) to prevent timing attacks.
- Reject payloads older than 5 minutes to prevent replay attacks.
- The `secret` is the `whsec_...` value returned during endpoint registration.

### Delivery Logs
Query delivery history for an endpoint via `GET /v1/webhooks/outbound/{id}/deliveries` (admin-only).

**Response**:
```typescript
{
  "id": "whdel_123",
  "event_type": "order.created",
  "status": "success", // "pending" | "success" | "failed"
  "attempts": 1,
  "response_code": 200,
  "response_body": "OK", // Truncated to 1000 chars
  "created_at": "2025-01-01T00:00:00Z",
  "last_attempt_at": "2025-01-01T00:00:01Z"
}
```

**Database Schema** (`webhook_deliveries` table):
```sql
CREATE TABLE webhook_deliveries (
  id TEXT PRIMARY KEY,
  webhook_id TEXT NOT NULL,
  event_type TEXT NOT NULL,  -- e.g., "order.created"
  payload TEXT NOT NULL,     -- JSON-serialized WebhookPayload
  status TEXT NOT NULL,      -- "pending" | "success" | "failed"
  attempts INTEGER DEFAULT 0,
  response_code INTEGER,
  response_body TEXT,        -- Truncated to 1000 chars
  created_at TEXT NOT NULL,  -- ISO 8601 timestamp
  last_attempt_at TEXT       -- ISO 8601 timestamp
);
```

### Manual Resend
Retry a failed delivery via `POST /v1/webhooks/outbound/{id}/deliveries/{deliveryId}/retry` (admin-only).

**Use Cases**:
- The recipient system was temporarily down.
- The payload was malformed (e.g., due to a bug fixed since the original attempt).

**Example**:
```bash
curl -X POST \
  -H "Authorization: Bearer sk_admin_..." \
  "https://your-store.com/v1/webhooks/outbound/wh_123/deliveries/whdel_456/retry"
```

**Response (200)**:
```typescript
{ "status": "pending", "message": "Delivery retry triggered" }
```

**Implementation Notes**:
- The endpoint resets `attempts = 0` and `status = 'pending'` in the database.
- The retry uses the **original payload** (no regeneration).

### Inbound vs. Outbound Webhooks

| Feature               | **Inbound Webhooks** (`/v1/webhooks/stripe`)       | **Outbound Webhooks** (`/v1/webhooks/outbound`)   |
|-----------------------|----------------------------------------------------|---------------------------------------------------|
| **Direction**         | Fufuni **receives** events (e.g., Stripe).        | Fufuni **sends** events to external systems.      |
| **Authentication**    | Stripe signature header (`stripe-signature`).    | HMAC-SHA256 (`X-Fufuni-Signature`).               |
| **Payload Format**    | Stripe-specific (e.g., `checkout.session`).       | Standardized Fufuni `WebhookPayload` format.     |
| **Retry Logic**       | N/A (Stripe retries if Fufuni fails to ACK).      | 3 attempts with exponential backoff.              |
| **Admin UI**          | Not configurable (Stripe webhook URL is fixed).    | Full CRUD in `/admin/webhooks`.                   |
| **Use Case**          | Process payments, update order status.            | Notify ERP/CRM, trigger fulfillment, sync data.   |
