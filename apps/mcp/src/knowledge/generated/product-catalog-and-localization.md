## Category Tree

### Database Schema
```sql
CREATE TABLE categories (

  sort_order INTEGER DEFAULT 0,

);

CREATE TABLE category_locales (
  category_id TEXT NOT NULL,
  locale TEXT NOT NULL,      -- e.g., "fr-FR"
  name TEXT NOT NULL,
  description TEXT NULL,
  PRIMARY KEY (category_id, locale)
);
```

### Creating Nested Categories
To create a child category under "Clothing" (slug: `clothing`):

```typescript
// POST /v1/categories
{
  "name": { "en-US": "T-Shirts", "fr-FR": "T-shirts" },
  "slug": "t-shirts", // Auto-converted to lowercase, hyphenated
  "parent_slug": "clothing", // Resolves to parent_id via slug
  "description": { "en-US": "All our t-shirt styles..." }
}
```

**Key Rules:**
1. `slug` must be globally unique (across all levels).
2. `parent_slug` is resolved to `parent_id` during creation.
3. Root categories omit `parent_slug`.

## Localization

### Database Schema
```sql
-- product_locales table
CREATE TABLE product_locales (
  product_id TEXT NOT NULL,
  locale TEXT NOT NULL,      -- e.g., "fr-FR"
  name TEXT NOT NULL,
  description TEXT NULL,
  PRIMARY KEY (product_id, locale)
);
```

### Fallback Logic
1. Request `?locale=fr-FR` → Check `product_locales` for `fr-FR`.
2. If missing, fall back to `en-US`.
3. If `en-US` missing, return `null` for the field.

### Setting Translations
```typescript
// PATCH /v1/products/:id/locales
{
  "locales": {
    "fr-FR": {
      "name": "T-shirt noir",
      "description": "Un t-shirt confortable en coton bio..."
    },
    "es-ES": {
      "name": "Camiseta negra"
      // description omitted → retains existing or falls back to en-US
    }
  }
}
```

**Key Rules:**
- Always provide `en-US` as the base locale during product creation.
- Omit fields (e.g., `description`) to keep existing values.
- Use `PATCH` to update translations without affecting other fields.

## Variant Management

### Creating a Variant
```typescript
// POST /v1/products/:id/variants
{
  "sku": "TSHIRT-BLK-M-001",
  "price_cents": 2999,
  "currency": "USD",
  "stock_quantity": 100,
  "attributes": {
    "color": "black",
    "size": "M"
  },
  "weight_g": 200,
  "dims_cm": { "l": 30, "w": 20, "h": 2 },
  "barcode": "123456789012" // EAN-13
}
```

### Updating a Variant
```typescript
// PUT /v1/products/:id/variants/:variantId
{
  "price_cents": 2499, // Sale price
  "stock_quantity": 50  // Reduced stock
}
```

### Attributes JSON Format
- Must be a flat key-value object (no nesting).
- Keys become filterable attributes (e.g., `?attributes[color]=black`).
- Values must be strings (e.g., `"M"`, not `{"value": "M"}`).

**Example Filter:**
```
GET /v1/products?attributes[color]=black&attributes[size]=M,L
```

### Filtering by Tags
- **OR logic**: `?tags=tag1,tag2` → Products with **either** tag.
- **AND logic**: Use multiple parameters: `?tags=tag1&tags=tag2`.

**Example:**
```bash
# Products tagged "sale" OR "clearance"
curl "/v1/products?tags=sale,clearance"

# Products tagged BOTH "sale" AND "summer-2026"
curl "/v1/products?tags=sale&tags=summer-2026"
```

## Image Array Management

### Reordering Images
```typescript
// PUT /v1/products/:id/images
{
  "images": [
    { "url": ".../side.jpg", "alt": "Side view", "isPrimary": false },
    { "url": ".../main.jpg", "alt": "Front view", "isPrimary": true } // Now first
  ]
}
```

**Key Rules:**
1. Only **one** image can have `isPrimary: true`.
2. The first `isPrimary: true` image becomes the thumbnail.
3. Omit `url`/`alt` to keep existing values (only reorder).
4. To delete an image, exclude it from the array.
