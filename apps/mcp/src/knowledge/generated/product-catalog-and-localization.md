## Product Model and Data Structure

The Fufuni framework uses a hybrid approach for product data: structured relational columns for primary identifiers and flexible JSON columns for complex nested data like images and attributes. This data is stored within a Cloudflare Durable Object using its internal SQLite engine.

### Core Product Fields
Each product record serves as a container for its variants and localized content. The base table contains common metadata that doesn't change per locale or variant.

```typescript
import { z } from '@hono/zod-openapi';

/**
 * Representation of the Product schema as stored in SQLite
 * and returned by the API.
 */
export const ProductSchema = z.object({
  id: z.string().uuid(),
  category_id: z.string().uuid(),
  base_currency: z.string().length(3).default('USD'),
  status: z.enum(['draft', 'active', 'archived']).default('draft'),
  images: z.array(z.object({
    url: z.string().url(),
    alt: z.string(),
    isPrimary: z.boolean()
  })).default([]),
  created_at: z.string().datetime(),
  updated_at: z.string().datetime(),
});

// Example of a product response including localized fields
export const ProductResponse = ProductSchema.extend({
  name: z.string().openapi({ example: 'Wireless Headphones' }),
  description: z.string().nullable(),
  category_slug: z.string(),
  tags: z.array(z.string()),
});
```

### Image Array Structure
Images are stored as a JSON array within a single `TEXT` column in SQLite. This avoids complex join operations for simple gallery fetching. The `isPrimary` flag determines the thumbnail; the framework logic typically defaults to the first image in the array if no flag is set, but the API specifically looks for `isPrimary: true`.

```typescript
// Reordering images or setting a new primary image
async function updateProductImages(productId: string, images: { url: string; alt: string; isPrimary: boolean }[]) {
  const db = getDb();
  const imagesJson = JSON.stringify(images);
  
  await db.prepare('UPDATE products SET images = ?, updated_at = ? WHERE id = ?')
    .bind(imagesJson, new Date().toISOString(), productId)
    .run();
}
```

## Localization and Fallback Logic

Localization is handled via dedicated locale tables: `product_locales` and `category_locales`. This normalization keeps the main tables lean and allows for adding an infinite number of languages without schema migrations.

### Locale Tables Structure
- **product_locales**: `product_id`, `locale` (e.g., 'en-US'), `name`, `description`.
- **category_locales**: `category_id`, `locale`, `name`.

### Fallback Implementation
If a requested locale (e.g., `ja-JP`) does not exist for a specific resource, the system automatically falls back to the `en-US` record.

```typescript
async function getLocalizedProduct(id: string, requestedLocale: string = 'en-US') {
  const db = getDb();
  const query = `
    SELECT p.*, 
      COALESCE(l_req.name, l_def.name) as name,
      COALESCE(l_req.description, l_def.description) as description
    FROM products p
    LEFT JOIN product_locales l_req ON p.id = l_req.product_id AND l_req.locale = ?
    LEFT JOIN product_locales l_def ON p.id = l_def.product_id AND l_def.locale = 'en-US'
    WHERE p.id = ?
  `;
  return await db.prepare(query).bind(requestedLocale, id).first();
}
```

## Variant Management

## Product Tags and Filtering

Tags provide a flexible way to group products outside the strict category hierarchy. They are managed through a many-to-many relationship using a `product_tags` join table.

### Tag Syntax and Querying
When querying by tags via the API, multiple tags should be comma-separated. The framework treats these as an **OR** filter. If a product has any of the specified tags, it will be included in the results.

```typescript
/**
 * Helper to build the TAGS filter in SQLite
 */
function buildTagFilter(tagsQuery: string | undefined) {
  if (!tagsQuery) return { sql: '', params: [] };
  
  const tags = tagsQuery.split(',').map(t => t.trim());
  const placeholders = tags.map(() => '?').join(',');
  
  return {
    sql: `AND p.id IN (
      SELECT product_id FROM product_tags 
      WHERE tag_name IN (${placeholders})
    )`,
    params: tags
  };
}
```

### Assigning Tags
Tags are updated by sending the full array of desired tags in the product update/create request. The backend handles the synchronization of the join table (deleting old tags and inserting new ones).


## Image Array Management

Images are ordered. The order in the JSON array reflects the display order in the storefront gallery.

### Structure
```json
[
  {
    "url": "https://cdn.fufuni.com/prod_1/main.jpg",
    "alt": "Front view of the wireless headphones",
    "isPrimary": true
  },
  {
    "url": "https://cdn.fufuni.com/prod_1/side.jpg",
    "alt": "Side view showing the controls",
    "isPrimary": false
  }
]
```

### Reordering and Primary Selection
To change the primary image or the order, the client must send the entire array in the new desired order. The first image with `isPrimary: true` is treated as the main thumbnail. If no image has the flag, the UI components are expected to fall back to the first element of the array.

```typescript
// Example: Moving the second image to first and making it primary
const images = getExistingImages(productId);
const [first, second] = images;
const reordered = [
  { ...second, isPrimary: true },
  { ...first, isPrimary: false }
];
await updateProductImages(productId, reordered);
```
