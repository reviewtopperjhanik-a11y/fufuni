## API Error Handling Reference

The Fufuni framework uses a structured error handling system via the `ApiError` class to ensure consistent HTTP error responses across the API.

### ApiError Static Helpers

| Method                     | HTTP Status | Use Case |
|----------------------------|-------------|----------|
| `unauthorized()`           | 401         | Authentication required but missing or invalid |
| `forbidden()`              | 403         | Valid authentication but insufficient permissions |
| `notFound()`               | 404         | Resource does not exist |
| `invalidRequest()`         | 400         | Invalid client input |
| `conflict()`               | 409         | Resource state conflict (e.g., duplicate) |
| `insufficientInventory()`  | 409         | Product inventory too low for requested quantity |
| `stripeError()`            | 502         | Stripe API communication failure |
| `internalServerError()`    | 500         | Unexpected server error |
| `badRequest()`             | 400         | General bad request (alternative to `invalidRequest`) |

### Hono Error Conversion

When an `ApiError` is thrown in a route handler, Hono's global error handler automatically converts it to a JSON response with the following structure:

```typescript
{
  error: {
    code: string,
    message: string,
    details?: Record<string, unknown>
  }
}
```

The HTTP status code is set according to the `statusCode` property of the `ApiError` instance.

### Common Error Examples

#### Unauthorized (401)

```typescript
import { ApiError } from '../types';

throw ApiError.unauthorized('API key is missing or invalid');
```

#### Forbidden (403)

```typescript
throw ApiError.forbidden('You do not have permission to access this resource');
```

#### Not Found (404)

```typescript
throw ApiError.notFound('Product not found');
```

#### Invalid Request (400)

```typescript
throw ApiError.invalidRequest('Email is required', {
  field: 'email',
  rule: 'required'
});
```

#### Conflict (409)

```typescript
throw ApiError.conflict('Username already exists');
```

#### Insufficient Inventory (409)

```typescript
throw ApiError.insufficientInventory('SKU12345');
```

#### Internal Server Error (500)

```typescript
throw ApiError.internalServerError('Database connection failed');
```

### Custom Error Messages

To create custom error messages with specific details:

```typescript
throw new ApiError(
  'custom_error',
  422,
  'Invalid product configuration',
  {
    productId: 'prod_123',
    validOptions: ['size', 'color']
  }
);
```

### Frontend Error Handling

When using the `useSecuredApi()` hook in React components, errors are automatically caught and normalized. The hook returns an object with `error` and `loading` states:

```typescript
import { useSecuredApi } from '@/hooks/api';

function ProductPage({ productId }) {
  const { data, error, loading } = useSecuredApi(`/products/${productId}`);

  if (loading) return <Spinner />;
  if (error) {
    switch (error.code) {
      case 'not_found':
        return <NotFoundPage />;
      case 'unauthorized':
        return <LoginPrompt />;
      case 'invalid_request':
        return <div>Invalid product ID format</div>;
      default:
        return <ErrorPage message={error.message} />;
    }
  }

  return <ProductDisplay product={data} />;
}
```

The `error` object matches the backend's JSON error structure with `code`, `message`, and optional `details` properties.

For form submissions using the same hook:

```typescript
const { execute, error } = useSecuredApi();

const handleSubmit = async (formData) => {
  const { error } = await execute('/cart/checkout', {
    method: 'POST',
    body: formData
  });

  if (error?.code === 'insufficient_inventory') {
    showToast(`Not enough stock for ${error.details.sku}`);
  } else if (error) {
    showToast(`Error: ${error.message}`);
  }
};
```
