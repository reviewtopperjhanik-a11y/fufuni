## The ApiError Class Architecture

Fufuni uses a centralized `ApiError` class to manage HTTP exceptions across the backend. This class extends the native JavaScript `Error` but adds specific properties required for standardized JSON responses: `code`, `statusCode`, and an optional `details` object.

### Static Helper Methods

The class provides static factory methods to ensure consistency in HTTP status codes and error strings.

| Method | HTTP Status | Error Code | Typical Use Case |
| :--- | :--- | :--- | :--- |
| `unauthorized()` | 401 | `unauthorized` | Missing or invalid Auth0 token / API key. |
| `forbidden()` | 403 | `forbidden` | Authenticated user lacks specific permissions (e.g., `admin:store`). |
| `notFound()` | 404 | `not_found` | Resource (Product, Order, Category) does not exist in SQLite. |
| `invalidRequest()` | 400 | `invalid_request` | Validation failure or malformed payload. |
| `badRequest()` | 400 | `bad_request` | Generic client-side error. |
| `conflict()` | 409 | `conflict` | Unique constraint violation (e.g., duplicate SKU). |
| `insufficientInventory()` | 409 | `insufficient_inventory` | Attempting to purchase more than what's in stock. |
| `stripeError()` | 502 | `stripe_error` | Failed communication with the Stripe Gateway. |
| `internalServerError()` | 500 | `internal_server_error` | Unhandled exceptions or database crashes. |

```typescript
// apps/merchant/src/types.ts implementation example
export class ApiError extends Error {
  constructor(
    public code: string,
    public statusCode: number,
    message: string,
    public details?: Record<string, unknown>
  ) {
    super(message);
  }

  static notFound(message = 'Not found') {
    return new ApiError('not_found', 404, message);
  }
  
  static insufficientInventory(sku: string) {
    return new ApiError('insufficient_inventory', 409, `Insufficient inventory for SKU: ${sku}`, {
      sku,
    });
  }
}
```

## Backend Error Conversion Flow

Hono does not automatically convert custom classes into JSON responses unless an `onError` handler is defined in the app initialization. In Fufuni, the global error handler intercepts `ApiError` instances and formats them into a standard response envelope.

### Standard JSON Error Envelope
When an error is thrown, the client receives a response with the following structure:
```json
{
  "error": {
    "code": "insufficient_inventory",
    "message": "Insufficient inventory for SKU: FW-2024-BLUE",
    "details": {
      "sku": "FW-2024-BLUE"
    }
  }
}
```

### Implementing the Global Error Handler
The following snippet demonstrates how the Fufuni backend (Merchant Worker) handles thrown `ApiError` instances within the `index.ts` or `app.ts` file.

```typescript
import { Hono } from 'hono';
import { ApiError } from './types';

const app = new Hono();

app.onError((err, c) => {
  if (err instanceof ApiError) {
    return c.json(
      {
        error: {
          code: err.code,
          message: err.message,
          details: err.details,
        },
      },
      { status: err.statusCode as any }
    );
  }

  // Handle unexpected errors (Standard Error or strings)
  console.error(`[Unhandled Error]: ${err.message}`, err.stack);
  return c.json(
    {
      error: {
        code: 'internal_server_error',
        message: 'An unexpected error occurred',
      },
    },
    { status: 500 }
  );
});

export default app;
```

## Common Error Type Implementations

Developers should throw errors as early as possible (fail-fast) within the route handlers or service logic inside the Durable Object.

### Resource Validation and Checks
This example shows a product update route using various error types to handle different failure states.

```typescript
import { Hono } from 'hono';
import { ApiError, HonoEnv } from './types';

const productRouter = new Hono<HonoEnv>();

productRouter.patch('/:id', async (c) => {
  const { id } = c.req.param();
  const body = await c.req.json();
  const db = c.get('db');
  const auth = c.get('auth');

  // 1. Authorization check
  if (!auth.permissions?.includes('admin:store')) {
    throw ApiError.forbidden('You do not have permission to edit products');
  }

  // 2. Existence check
  const product = await db.query('SELECT * FROM products WHERE id = ?', [id]);
  if (product.length === 0) {
    throw ApiError.notFound(`Product with ID ${id} not found`);
  }

  // 3. Logic validation (Conflict)
  if (body.sku) {
    const existing = await db.query('SELECT id FROM products WHERE sku = ? AND id != ?', [body.sku, id]);
    if (existing.length > 0) {
      throw ApiError.conflict('SKU already in use by another product');
    }
  }

  // 4. Inventory Logic
  if (body.stock < 0) {
    throw ApiError.invalidRequest('Stock cannot be negative', { field: 'stock', value: body.stock });
  }

  // ... proceed with update
  return c.json({ success: true });
});
```

### External Service Errors (Stripe)
When wrapping third-party SDK calls, use the specific `stripeError` helper to signal issues with the payment gateway.

```typescript
import Stripe from 'stripe';
import { ApiError } from './types';

async function createStripePayment(amount: number, currency: string, key: string) {
  const stripe = new Stripe(key, { apiVersion: '2025-01-27.acacia' });

  try {
    return await stripe.paymentIntents.create({ amount, currency });
  } catch (err: any) {
    // Wrap Stripe specific errors into Fufuni ApiErrors
    throw ApiError.stripeError(err.message || 'Payment provider communication failed');
  }
}
```

## Creating Custom Error Messages and Details

The `details` property is a flexible `Record<string, unknown>` used to pass machine-readable metadata back to the frontend. This is crucial for form validation or localized error messages.

### Multi-field Validation Example
When validating a complex form, you can aggregate errors into a single `invalid_request` call.

```typescript
import { ApiError } from './types';

function validateAddress(address: any) {
  const errors: Record<string, string> = {};
  
  if (!address.zipCode) errors.zipCode = 'Zip code is required';
  if (!address.country) errors.country = 'Country must be selected';
  
  if (Object.keys(errors).length > 0) {
    // Throwing with specific field details
    throw ApiError.invalidRequest('Address validation failed', { fields: errors });
  }
}
```

## Frontend Error Handling with useSecuredApi

On the React frontend, Fufuni provides a `useSecuredApi()` hook (or similar wrapper around `fetch`) that interacts with the Merchant API. Errors returned by the API should be caught in the component layer to provide user feedback via HeroUI components or toasts.

### Handling API Errors in Components
In React 19, you typically handle these within an `async` function triggered by an event (like a button click) or inside a `useEffect`.

```typescript
import React, { useState } from 'react';
import { Button, Input, addToast } from '@heroui/react';
import { useSecuredApi } from '@/hooks/useSecuredApi';

export const ProductEditor = ({ productId }: { productId: string }) => {
  const [loading, setLoading] = useState(false);
  const api = useSecuredApi();

  const handleUpdate = async (formData: any) => {
    setLoading(true);
    try {
      const response = await api.patch(`/v1/products/${productId}`, formData);
      addToast({
        title: "Success",
        description: "Product updated successfully",
        color: "success"
      });
    } catch (err: any) {
      // The API error is expected to have the structure: { error: { code, message, details } }
      const apiErrorMessage = err.error?.message || "An unexpected error occurred";
      const errorCode = err.error?.code;

      if (errorCode === 'conflict') {
        addToast({
          title: "Duplicate SKU",
          description: "This SKU is already assigned to another product.",
          color: "danger"
        });
      } else if (errorCode === 'invalid_request' && err.error.details?.fields) {
        // Handle specific field errors (e.g. highlight inputs)
        console.error("Validation errors:", err.error.details.fields);
      } else {
        addToast({
          title: "Error",
          description: apiErrorMessage,
          color: "danger"
        });
      }
    } finally {
      setLoading(false);
    }
  };

  return (
    <Button isLoading={loading} onPress={() => handleUpdate({ sku: 'NEW-SKU' })}>
      Update Product
    </Button>
  );
};
```

### Integration with React Error Boundaries
For fatal errors (like a 404 on a page-level fetch), you can throw the error to be caught by a generic `ErrorBoundary`.

```typescript
import { useQuery } from '@tanstack/react-query';
import { useSecuredApi } from '@/hooks/useSecuredApi';
import { ApiError } from '@/types';

export function ProductPage({ id }: { id: string }) {
  const api = useSecuredApi();

  const { data, error } = useQuery({
    queryKey: ['product', id],
    queryFn: async () => {
      const res = await api.get(`/v1/products/${id}`);
      if (!res.ok) {
        const errBody = await res.json();
        // Re-construct error for local handling
        throw new Error(errBody.error?.message || 'Failed to fetch');
      }
      return res.json();
    }
  });

  if (error) {
    return (
      <div className="p-10 text-center">
        <h2 className="text-2xl font-bold">Product not found</h2>
        <p className="text-gray-500">The item you are looking for does not exist.</p>
      </div>
    );
  }

  // Render product...
}
```

### Utility: Checking for Specific Codes
A common pattern in Fufuni is to check the `code` property rather than the numeric status, as the code provides more semantic context (e.g., distinguishing between a generic 409 and `insufficient_inventory`).

```typescript
async function processOrder(orderId: string) {
  try {
    await api.post(`/v1/orders/${orderId}/pay`);
  } catch (err: any) {
    const errorData = err.error;
    
    switch (errorData?.code) {
      case 'insufficient_inventory':
        // Show specific UI for out of stock
        openStockModal(errorData.details?.sku);
        break;
      case 'stripe_error':
        // Prompt user to try a different card
        showPaymentRetry();
        break;
      default:
        // Generic alert
        showAlert(errorData?.message || 'Failed to process order');
    }
  }
}
```
