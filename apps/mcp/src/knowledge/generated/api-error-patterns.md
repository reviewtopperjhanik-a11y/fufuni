## API Error Handling Reference

### ApiError Class Methods

| Method | HTTP Status | Use Case |
|--------|-------------|----------|
| `unauthorized` | 401 | Authentication required |
| `forbidden` | 403 | Authenticated but not authorized |
| `notFound` | 404 | Resource not found |
| `invalidRequest` | 400 | Invalid request data |
| `conflict` | 409 | Resource conflict |
| `insufficientInventory` | 409 | Insufficient inventory for SKU |
| `stripeError` | 502 | Stripe API error |
| `internalServerError` | 500 | Internal server error |
| `badRequest` | 400 | Bad request |
| `serviceUnavailable` | 503 | Service unavailable |

### Hono Error Conversion

When an `ApiError` is thrown in a route handler, Hono's global error handler converts it into a JSON response with the following structure:

```json
{
  "error": {
    "code": "error_code",
    "message": "Error message",
    "details": {
      // Additional error details
    }
  }
}
```

The HTTP status code is set according to the `statusCode` property of the `ApiError` instance.

Here are examples of how to throw different types of errors in your route handlers:

```typescript

throw ApiError.unauthorized('Authentication required');
```


### Custom Error Messages

You can create custom error messages by using the `ApiError` constructor directly:

```typescript
import { ApiError } from '../types';

throw new ApiError('custom_error', 400, 'Custom error message', { detail: 'Additional details' });
```

Or by extending the existing methods with additional details:

```typescript
import { ApiError } from '../types';

const error = ApiError.invalidRequest('Invalid product data', {
  fields: ['name', 'price'],
  reason: 'Name is too short and price is negative'
});
throw error;
```

### Frontend Error Handling

When using `useSecuredApi()` in the frontend, errors are typically handled as follows:

```typescript
import { useSecuredApi } from '../hooks/useSecuredApi';

const { data, error, loading } = useSecuredApi('/api/products/123');

if (error) {
  switch (error.code) {
    case 'not_found':
      // Handle 404 error
      break;
    case 'unauthorized':
      // Handle 401 error
      break;
    case 'invalid_request':
      // Handle 400 error with details
      console.log(error.details);
      break;
    default:
      // Handle other errors
      break;
  }
}
```
