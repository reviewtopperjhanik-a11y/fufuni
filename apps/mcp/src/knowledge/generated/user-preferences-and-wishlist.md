## User Metadata vs. SQL Persistence

In the Fufuni framework, user-related data is partitioned into two storage strategies based on access patterns and performance requirements.

### Wishlist: Decentralized Metadata
The wishlist is stored directly within **Auth0 user_metadata**. This architectural choice ensures that the user's favorites are available immediately within the JWT (JSON Web Token) payload upon authentication. By avoiding a SQL lookup for every product listing page, Fufuni reduces database load and latency. 

The data is stored as a simple array of strings:
```json
{
  "user_metadata": {
    "wishlist": ["prod_01J2H", "prod_09K3L"]
  }
}
```

### Saved Carts and Preferences: SQL Tables
Unlike the wishlist, **Saved Carts** and **User Preferences** are stored in the backend SQLite database (Durable Objects). These items typically involve larger payloads or require complex querying that exceeds the practical limits of a JWT.

```sql
-- apps/server/src/db/schema.sql
CREATE TABLE saved_carts (
    user_id TEXT PRIMARY KEY,
    cart_data TEXT NOT NULL, -- JSON stringified cart items
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE user_preferences (
    user_id TEXT PRIMARY KEY,
    locale TEXT DEFAULT 'en-US',
    currency TEXT DEFAULT 'USD',
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

## The useWishlist() Hook

The `useWishlist` hook is the primary interface for managing product favorites in the frontend. It is reactive, meaning that when a user toggles an item, all components observing the wishlist update instantly via a `CustomEvent`.

### Hook Interface and Implementation
According to framework conventions, the hook provides methods to check state and mutate the Auth0 metadata.

```typescript
// Example usage of useWishlist in a Product Card component
import React from "react";
import { Button } from "@heroui/react";
import { HeartIcon } from "@/components/icons";
import { useWishlist } from "@/hooks/use-wishlist";

export const WishlistToggle = ({ productId }: { productId: string }) => {
  const { toggleWishlist, isInWishlist, isLoading } = useWishlist();
  
  const isFav = isInWishlist(productId);

  return (
    <Button
      isIconOnly
      radius="full"
      variant="light"
      isLoading={isLoading}
      onPress={() => toggleWishlist(productId)}
      aria-label="Toggle Wishlist"
    >
      <HeartIcon 
        className={isFav ? "fill-danger text-danger" : "text-default-400"} 
      />
    </Button>
  );
};
```

### Return Values
The hook returns an object with the following properties:
- `wishlist`: `string[]` - Array of product IDs.
- `isLoading`: `boolean` - True if a mutation or token refresh is in progress.
- `addToWishlist`: `(id: string) => Promise<void>` - Adds an item to metadata.
- `removeFromWishlist`: `(id: string) => Promise<void>` - Removes an item from metadata.
- `isInWishlist`: `(id: string) => boolean` - Utility to check presence.
- `toggleWishlist`: `(id: string) => Promise<void>` - Helper to add/remove based on current state.

## Backend: Auth0 Management API Integration

When a user modifies their wishlist, the backend must communicate with Auth0 to update `user_metadata`. This is handled by the Hono server using the Auth0 Management API.

### Token Caching and Security
To prevent rate-limiting, the backend caches the Management API Access Token in memory for **60 seconds**. The helper `getAuth0ManagementToken()` handles the OAuth2 Client Credentials flow.

```typescript
// apps/server/src/lib/auth0-management.ts
import { useSecuredApi } from "@/hooks/use-secured-api";

export async function updateWishlistMetadata(userId: string, wishlist: string[]) {
  // Internal helper that retrieves or uses cached 60s token
  const managementToken = await getAuth0ManagementToken();
  
  const response = await fetch(`https://${AUTH0_DOMAIN}/api/v2/users/${userId}`, {
    method: 'PATCH',
    headers: {
      Authorization: `Bearer ${managementToken}`,
      'Content-Type': 'application/json',
    },
    body: JSON.stringify({
      user_metadata: { wishlist }
    }),
  });

  if (!response.ok) {
    throw new Error("Failed to sync wishlist with Auth0");
  }
}
```

## Saved Cart Management

Fufuni implements a "Persistent Cart" pattern. If a user adds items to their cart while logged in, or has items in their cart when they log in, the state is synchronized with the `saved_carts` SQL table.

### API Endpoints
- `GET /v1/me/saved-cart`: Retrieves the JSON payload of the saved cart.
- `PUT /v1/me/saved-cart`: Upserts the current cart state.
- `DELETE /v1/me/saved-cart`: Clears the saved cart (usually after successful checkout).

### Backend Implementation Example (Hono)
```typescript
// apps/server/src/routes/me.ts
import { Hono } from "hono";
import { customerAuthMiddleware } from "@/middleware/auth";

const me = new Hono();

me.put("/saved-cart", customerAuthMiddleware, async (c) => {
  const userId = c.get("user").sub;
  const { cartData } = await c.req.json();
  const db = c.get("db");

  await db.prepare(
    "INSERT INTO saved_carts (user_id, cart_data, updated_at) VALUES (?, ?, CURRENT_TIMESTAMP) " +
    "ON CONFLICT(user_id) DO UPDATE SET cart_data = excluded.cart_data, updated_at = CURRENT_TIMESTAMP"
  ).bind(userId, JSON.stringify(cartData)).run();

  return c.json({ success: true });
});
```

## CartProvider Synchronization

The `CartProvider` in the React frontend acts as the orchestrator between local state (in-memory/localStorage) and the backend SQL storage.

### Logic Flow
1. **Login**: When the `useAuth` hook detects a transition to `isAuthenticated`, the `CartProvider` fetches the saved cart via `GET /v1/me/saved-cart` and merges it with any local guest items.
2. **Auto-save**: Every time the cart state changes, a debounced effect triggers. After **2 seconds** of inactivity, the hook calls the `PUT` endpoint to persist the cart.

```typescript
// apps/client/src/contexts/cart-context.tsx logic snippet
useEffect(() => {
  if (!isAuthenticated) return;

  const timer = setTimeout(async () => {
    try {
      await api.put("/v1/me/saved-cart", { cartData: currentCartItems });
    } catch (err) {
      console.error("Failed to auto-save cart", err);
    }
  }, 2000); // 2-second debounce

  return () => clearTimeout(timer);
}, [currentCartItems, isAuthenticated]);
```

## User Preferences and Personalization

User preferences handle non-transactional settings like UI locale and currency display. These are strictly stored in the `user_preferences` table and are accessed via standard REST endpoints.

### Preferences Schema and API
The preferences require the `customerAuthMiddleware` to ensure the `user_id` is extracted from the valid session/JWT.

```typescript
// Example: Updating User Preferences from a Settings page
import { useAuth } from "@/authentication";
import { getApiBase } from "@/lib/api-base";

export function useUpdatePreferences() {
  const auth = useAuth();
  const apiBase = getApiBase();

  const updatePrefs = async (locale: string, currency: string) => {
    const response = await auth.putJson(`${apiBase}/v1/me/preferences`, {
      locale,
      currency
    });
    
    if (response.error) {
      throw new Error("Could not update preferences");
    }
    
    // Preferences might trigger a page reload or a global state update
    window.location.reload(); 
  };

  return { updatePrefs };
}
```

### Summary of Storage Locations

| Feature | Storage Medium | Access Method | Key Characteristic |
| :--- | :--- | :--- | :--- |
| **Wishlist** | Auth0 `user_metadata` | Included in JWT | Extremely fast read on frontend |
| **Saved Cart** | SQL (`saved_carts`) | REST API (`/v1/me/saved-cart`) | Debounced auto-save (2s) |
| **Preferences** | SQL (`user_preferences`) | REST API (`/v1/me/preferences`) | Persists locale/currency |
| **Active Session** | Auth0 JWT | `useAuth()` | Expires based on Auth0 config |

When building new features that require per-user persistence, choose **Auth0 Metadata** only for small, high-frequency read-only data needed during the initial render. For everything else, use the **SQL persistence** pattern to keep the JWT size manageable and maintain data integrity.
