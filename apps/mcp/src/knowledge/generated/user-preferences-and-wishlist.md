## Wishlist Storage

Wishlist data is stored in **Auth0's `user_metadata`** under the key `"wishlist"` as a `string[]` of product IDs. This design avoids SQL tables for three reasons:

1. **Immediate consistency**: The wishlist is embedded in the JWT, so UI updates are instant after token refresh.
2. **No cold starts**: Durable Objects (SQLite) would require a network call even for read operations.
3. **Auth0 as source of truth**: User preferences naturally belong in the identity provider.

**Legacy fallback**: The hook checks both `storeMetadata.wishlist` (current) and `userMetadata.wishlist` (deprecated) for backward compatibility.

```typescript
// Example user_metadata structure in Auth0
{
  "extra_user_info": {
    "user_metadata": {
      "store:https://demo.fufuni.shop": {
        "wishlist": ["prod_123", "prod_456"]
      }
    }
  }
}
```

## `useWishlist()` Hook

### Return Values
| Property       | Type                     | Description                                                                 |
|----------------|--------------------------|-----------------------------------------------------------------------------|
| `wishlist`     | `string[]`               | Current product IDs in wishlist                                             |
| `isLoading`    | `boolean`                | True during initial token decode or refresh                                 |
| `isError`      | `boolean`                | True if token decode failed                                                 |
| `toggle`       | `(productId: string) => Promise<void>` | Toggles product in wishlist (adds/removes)                                  |
| `isFavorite`   | `(productId: string) => boolean`      | Checks if product exists in wishlist (safe to call unauthenticated)       |

### Usage Example: Heart Button Toggle
```tsx
import { useWishlist } from "@/hooks/use-wishlist";
import { Heart } from "@heroicons/react/24/outline";

function ProductWishlistButton({ productId }: { productId: string }) {
  const { isFavorite, toggle, isLoading } = useWishlist();

  return (
    <button
      onClick={() => toggle(productId)}
      disabled={isLoading}
      className="p-2 text-red-500 hover:text-red-700"
    >
      <Heart
        className={`h-6 w-6 ${isFavorite(productId) ? "fill-current" : ""}`}
      />
    </button>
  );
}
```

**Critical Notes**:
- Always call `isFavorite()` before rendering the button state (it handles unauthenticated cases gracefully).
- The hook dispatches a `fufuni:wishlist-updated` CustomEvent after mutations for cross-component reactivity.

## Auth0 Management API Calls

Wishlist mutations use the **Auth0 Management API** via a secured endpoint:

1. **Token flow**:
   - Frontend calls `PATCH /api/v2/users/:userId/metadata`
   - Backend obtains a Management API token using `getAuth0ManagementToken()` (cached for 60s in memory)
   - Token is scoped to `update:users` and `read:users`

2. **Token caching** (backend implementation):
```typescript
// apps/backend/src/lib/auth0.ts
const managementTokenCache = new InMemoryCache<string>(60_000); // 60s TTL

export async function getAuth0ManagementToken() {
  return managementTokenCache.getOrSet(async () => {
    const response = await fetch(`https://${AUTH0_DOMAIN}/oauth/token`, {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({
        client_id: AUTH0_M2M_CLIENT_ID,
        client_secret: AUTH0_M2M_CLIENT_SECRET,
        audience: `https://${AUTH0_DOMAIN}/api/v2/`,
        grant_type: "client_credentials",
      }),
    });
    const data = await response.json();
    return data.access_token as string;
  });
}
```

**Security**: The `/api/v2/users/*` route requires `customerAuthMiddleware` (verifies user JWT and matches `:userId` to the token sub).

## Saved Cart Storage

Saved carts are stored in the **`saved_carts` SQL table** (not `user_metadata`), with these endpoints:

| Method | Endpoint               | Description                          |
|--------|------------------------|--------------------------------------|
| GET    | `/v1/me/saved-cart`    | Loads the user's saved cart          |
| PUT    | `/v1/me/saved-cart`    | Upserts the entire cart (full replace) |
| DELETE | `/v1/me/saved-cart`    | Clears the saved cart                |

**Table schema**:
```sql
CREATE TABLE saved_carts (
  user_id TEXT PRIMARY KEY REFERENCES users(id),
  cart_data JSONB NOT NULL,  -- { items: CartItem[], updated_at: string }
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

**Auto-save behavior**:
- Triggers on cart changes (debounced 2s)
- Only for authenticated users
- Uses `PUT /v1/me/saved-cart` with the full cart payload

## `CartProvider` Integration

The `CartProvider` (in `apps/client/src/contexts/cart-context.tsx`) handles saved cart sync:

1. **Auto-load on login**:
```typescript
// Inside CartProvider's useEffect
if (auth.isAuthenticated && !cartLoaded) {
  const response = await auth.getJson("/v1/me/saved-cart");
  setCart(response.cart_data.items);
  setCartLoaded(true);
}
```

2. **Auto-save on changes** (debounced):
```typescript
useDebouncedEffect(
  () => {
    if (auth.isAuthenticated && cart.length > 0) {
      auth.putJson("/v1/me/saved-cart", {
        items: cart,
        updated_at: new Date().toISOString(),
      });
    }
  },
  [cart],  // Dependency
  { wait: 2000 } // Debounce 2s
);
```

**Key behaviors**:
- Saved carts are **merged** with the current session cart on login (session cart takes precedence for duplicates)
- The provider exposes `isSyncing` to show a loading state during saves

## User Preferences

User preferences (locale, currency display) are stored in the **`user_preferences` table**:

| Method | Endpoint                  | Payload Example                          |
|--------|---------------------------|-------------------------------------------|
| GET    | `/v1/me/preferences`      | Returns `{ locale: "fr-FR", currency: "EUR" }` |
| PUT    | `/v1/me/preferences`      | Accepts partial updates like `{ locale: "en-US" }` |

**Table schema**:
```sql
CREATE TABLE user_preferences (
  user_id TEXT PRIMARY KEY REFERENCES users(id),
  locale TEXT DEFAULT 'en-US',
  currency TEXT DEFAULT 'USD',
  theme_preference TEXT DEFAULT 'system',  -- 'light' | 'dark' | 'system'
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

**Middleware**: All endpoints require `customerAuthMiddleware`.

**Usage example**:
```typescript
// Update user's locale
await auth.putJson("/v1/me/preferences", { locale: "ja-JP" });

// Read preferences
const { locale, currency } = await auth.getJson("/v1/me/preferences");
```
