## How to Add a Database Migration

Every schema change in Fufuni must be applied in three places to ensure consistency across development, deployment, and production environments.

### When to Use Migrations

Use migrations for **all schema changes** that need to be deployed to production or shared with other developers. The `SCHEMA` constant in `do.ts` is the **source of truth** for the full database schema, while migrations ensure changes can be applied incrementally to existing databases.

**Directly editing the `SCHEMA` constant without a migration is only acceptable during initial development when no migrations have been run yet.**

### Step-by-Step Process

#### 1. Create the SQL Migration File

- Place the file in `apps/merchant/migrations/`
- Name it using the pattern `NNN-description.sql` where:
  - `NNN` is a zero-padded 3-digit number (increment from the highest existing migration)
  - `description` is kebab-case (e.g., `035-add-tags-table.sql`)
- Use `PRAGMA foreign_keys = ON;` at the beginning
- Make all statements idempotent with `IF NOT EXISTS`

**Example structure:**
```sql
-- Migration 035: Product tags
-- Enables tagging products for better categorization and search.

PRAGMA foreign_keys = ON;

CREATE TABLE IF NOT EXISTS product_tags (
  id         TEXT PRIMARY KEY,
  name       TEXT NOT NULL UNIQUE,
  handle     TEXT NOT NULL UNIQUE,
  status     TEXT NOT NULL DEFAULT 'active' CHECK (status IN ('active', 'inactive')),
  created_at TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at TEXT NOT NULL DEFAULT (datetime('now'))
);

CREATE TABLE IF NOT EXISTS product_taggings (
  product_id TEXT NOT NULL REFERENCES products(id) ON DELETE CASCADE,
  tag_id     TEXT NOT NULL REFERENCES product_tags(id) ON DELETE CASCADE,
  PRIMARY KEY (product_id, tag_id)
);

CREATE INDEX IF NOT EXISTS idx_product_taggings_tag ON product_taggings(tag_id);
CREATE INDEX IF NOT EXISTS idx_product_tags_handle ON product_tags(handle) WHERE status = 'active';
```

#### 2. Add Migration Block in `ensureInitialized()`

Add your migration to the `migrations` array in `do.ts`. The `name` must match the SQL file stem exactly.


### Common Pitfalls

1. **Mismatched Migration Names**
   - The `name` in the migration block must match the SQL file stem exactly:
     - File: `035-product-tags.sql`
     - Migration name: `'035-product-tags'` ✅
     - Incorrect: `'product-tags'` or `'035_tags'` ❌

2. **Non-Idempotent Statements**
   - Always use `IF NOT EXISTS` for tables and indexes:
     ```sql
     CREATE TABLE IF NOT EXISTS product_tags (...);  // ✅ Correct
     CREATE TABLE product_tags (...);                // ❌ Will fail if table exists
     ```

3. **Incorrect Column Types**
   - Use `TEXT` for UUIDs, ISO dates, and JSON
   - Use `INTEGER` for booleans (0/1), cents, and counts
   - Use `REAL` for percentages and ratings

4. **Modifying Existing Migrations**
   - Never change a migration that has been deployed to production.
   - Instead, create a new migration with the correct sequence number.

5. **Missing Foreign Key Support**
   - Always include `PRAGMA foreign_keys = ON;` at the beginning of SQL files.

6. **Forgetting Indexes**
   - Add indexes for frequently queried columns to maintain performance.

By following these steps, you ensure that your database changes are applied consistently across all environments while maintaining backward compatibility.
