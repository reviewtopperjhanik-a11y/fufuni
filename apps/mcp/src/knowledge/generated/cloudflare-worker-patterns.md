## Cloudflare Worker Patterns

### Accessing Bindings in Route Handlers

All bindings are available via `c.env` in Hono route handlers. The `Env` type is auto-generated by Wrangler and extended in `worker-configuration.d.ts`:

```typescript
// apps/merchant/src/routes/products.ts
import { Hono } from 'hono'
import type { Env } from '../worker-configuration'

const app = new Hono<{ Bindings: Env }>()

// Access Durable Object stub
app.get('/products', async (c) => {
  const merchantStub = c.env.MERCHANT
  const id = merchantStub.id
  const response = await merchantStub.query({ method: 'GET', path: '/products' })
  return response
})

// Access R2 bucket
app.post('/upload', async (c) => {
  const formData = await c.req.formData()
  const file = formData.get('image') as File
  await c.env.IMAGES.put(`products/${Date.now()}.jpg`, file)
  return c.json({ success: true })
})

// Access KV cache
app.get('/cached', async (c) => {
  const cached = await c.env.KV_CACHE.get('some-key')
  return c.json({ cached })
})
```

### Durable Object Pattern

**Why a single DO instance**: Fufuni uses one `MerchantDO` instance per merchant (identified by `MERCHANT_PK`/`MERCHANT_SK`). This ensures all database operations for a merchant are serialized through a single SQLite instance.

**Getting the stub**:
```typescript
// apps/merchant/src/index.ts
import { getMerchantStub } from './do'

export default {
  async fetch(request: Request, env: Env) {
    const merchantStub = getMerchantStub(env)
    // ...
  }
}

// apps/merchant/src/do.ts
export function getMerchantStub(env: Env): DurableObjectStub {
  return env.MERCHANT.get(env.MERCHANT.idFromName('primary'))
}
```

**Calling methods**:
```typescript
// Query (read-only, no transaction)
const response = await merchantStub.query({
  method: 'GET',
  path: '/products/123',
  headers: { 'X-Custom': 'value' }
})

// Run (read-write, transactional)
const response = await merchantStub.run({
  method: 'POST',
  path: '/products',
  body: JSON.stringify({ name: 'New Product' })
})
```

### KV Cache Middleware

The `kvCacheMiddleware` automatically caches GET responses in KV:

```typescript
// apps/merchant/src/middleware/kv-cache.ts
export function kvCacheMiddleware() {
  return async (c: Context, next: Next) => {
    if (c.req.method !== 'GET') return next()

    const cacheKey = `cache:${c.req.url}`
    const cached = await c.env.KV_CACHE.get(cacheKey, { type: 'text' })

    if (cached) {
      const { headers, body, status } = JSON.parse(cached)
      return new Response(body, { headers, status })
    }

    const response = await next()
    if (response.status === 200) {
      const ttl = getCacheTTL(c.req.path) // Uses KV_CACHE_*_TTL_SECONDS
      await c.env.KV_CACHE.put(cacheKey, JSON.stringify({
        headers: Object.fromEntries(response.headers),
        body: await response.text(),
        status: response.status
      }), { expirationTtl: ttl })
    }
    return response
  }
}
```

**Manual invalidation**:
```typescript
// Invalidate all product-related cache keys
const { keys } = await c.env.KV_CACHE.list({ prefix: 'cache:*/v1/products' })
await Promise.all(keys.map(key => c.env.KV_CACHE.delete(key.name)))
```

### R2 Image Storage

Product images are stored in R2 with this structure:
```
/products/{productId}/{variant}.{ext}
/products/123/primary.jpg
/products/123/thumbnail.webp
```

**Upload example**:
```typescript
// apps/merchant/src/routes/images.ts
app.post('/products/:id/images', async (c) => {
  const productId = c.req.param('id')
  const formData = await c.req.formData()
  const file = formData.get('image') as File

  const key = `products/${productId}/${Date.now()}.jpg`
  await c.env.IMAGES.put(key, file.stream())

  return c.json({
    url: `${c.env.IMAGES_URL}/${key}`,
    key
  })
})
```

**Serve via Worker**:
```typescript
app.get('/images/*', async (c) => {
  const key = c.req.param('*')
  const object = await c.env.IMAGES.get(key)
  if (!object) return c.notFound()

  return new Response(object.body, {
    headers: {
      'Content-Type': object.httpMetadata?.contentType || 'application/octet-stream',
      'Cache-Control': 'public, max-age=31536000, immutable'
    }
  })
})
```

### Secrets Management

**Wrangler secrets vs .env**:
- `.env`: Development-only variables (not committed)
- `wrangler.jsonc` + `secrets.json`: Production secrets managed via `wrangler secret`

**Mailgun required secrets**:
```bash
# Must be in both .env and GitHub Secrets
MAILGUN_API_KEY=key-...
MAILGUN_DOMAIN=mg.example.com
MAILGUN_USER=support@example.com
MAILGUN_BASE_URL=https://api.mailgun.net
```

**Adding a new secret**:
1. Add to `.env` (development)
2. Add to `create-env-artifact.yaml` (CI)
3. Run `wrangler secret put KEY` locally
4. The secret will be automatically picked up by `generate-wrangler-jsonc.py`

### Adding New Bindings

**Steps**:
1. Update `wrangler.jsonc`:
```json
{
  "r2_buckets": [
    { "binding": "NEW_BUCKET" }
  ]
}
```

2. Extend `worker-configuration.d.ts`:
```typescript
declare namespace Cloudflare {
  interface Env {
    NEW_BUCKET: R2Bucket
  }
}
```

3. Update the `Env` type:
```typescript
interface Env extends Cloudflare.Env {
  NEW_BUCKET: R2Bucket
}
```

4. Regenerate types:
```bash
npx wrangler types
```

### CI/CD Pipeline

**Environment variables mapping**:
Each `.env` variable must have a matching GitHub Secret with identical name. The `create-env-artifact.yaml` workflow:
1. Creates `.env` from secrets
2. Generates `wrangler.jsonc` and `secrets.json`
3. Encrypts them into `.env.enc` artifact

**Exposing to frontend**:
```typescript
// apps/client/vite.config.ts
export default defineConfig({
  define: {
    'import.meta.env.STORE_URL': JSON.stringify(process.env.STORE_URL),
    'import.meta.env.PERMISSIONS': JSON.stringify(scopesArray)
  }
})
```

**Adding a new frontend variable**:
1. Add to `.env` and `create-env-artifact.yaml`
2. Add to `vite.config.ts` define block
3. Access in React via `import.meta.env.VARIABLE_NAME`

**Deployment flow**:
1. Push to `main` triggers `deploy-cloudflare-worker.yaml`
2. Workflow decrypts `.env.enc` artifact
3. Runs `wrangler secret bulk < secrets.json`
4. Deploys with `wrangler deploy`
