## Accessing Worker Bindings

In Fufuni, the backend is powered by Hono. All Cloudflare bindings (Durable Objects, KV, R2, Environment Variables) are accessed through the Hono context `c.env`. The `Env` type is automatically generated and augmented to ensure type safety across the application.

### Route Handler Access
When defining a route, you use the context object to interact with the infrastructure.

```typescript
import { Hono } from 'hono';
import { env } from 'hono/adapter';

const app = new Hono<{ Bindings: Env }>();

app.get('/v1/system/status', async (c) => {
  // Accessing a simple environment variable (String)
  const storeName = c.env.STORE_NAME;

  // Accessing a KV Namespace
  const cachedData = await c.env.KV_CACHE.get('system:status');

  // Accessing R2 Bucket
  const image = await c.env.IMAGES.get('logo.png');

  return c.json({ 
    status: 'online', 
    store: storeName,
    hasLogo: !!image 
  });
});
```

## Durable Object Singleton Pattern

Fufuni uses a single `MerchantDO` instance per deployment to manage the SQLite database and maintain state consistency. We use `idFromName` with a hardcoded string to ensure we always connect to the same instance.

### Getting the Stub and Calling Methods
We typically wrap DO calls in two primary methods: `query()` for data retrieval and `run()` for state-changing operations.

```typescript
// apps/merchant/src/lib/do-client.ts
export async function getMerchantStub(env: Env) {
  // "singleton" ensures every request hits the same SQLite file
  const id = env.MERCHANT.idFromName('singleton');
  return env.MERCHANT.get(id);
}

// Usage in a Hono route
app.post('/v1/products', async (c) => {
  const stub = await getMerchantStub(c.env);
  const body = await c.req.json();

  // 'run' is used for mutations
  const result = await stub.run('INSERT INTO products (name, price) VALUES (?, ?)', [
    body.name,
    body.price
  ]);

  return c.json(result);
});

app.get('/v1/products/:id', async (c) => {
  const stub = await getMerchantStub(c.env);
  const id = c.req.param('id');

  // 'query' is used for SELECTs
  const product = await stub.query('SELECT * FROM products WHERE id = ?', [id]);
  return c.json(product);
});
```

## KV Caching Strategy

Fufuni implements a layered caching strategy using `kvCacheMiddleware`. This middleware intercepts `GET` requests to serve content directly from Cloudflare's edge, bypassing the Durable Object for significantly lower latency.

### Cache Rules and TTL
The cache uses the full URL as a key (prefixed with `cache:`). It is automatically bypassed for:
1. Non-GET methods.
2. Requests with Admin/Secret Authorization headers (only Public PK Bearer tokens are cached).

The TTL is controlled by environment variables:
- `KV_CACHE_SEARCH_TTL_SECONDS`: Search results (Default: 300s).
- `KV_CACHE_REVIEWS_TTL_SECONDS`: Product reviews (Default: 600s).
- `KV_CACHE_DEFAULT_TTL_SECONDS`: General catalog data (Default: 3600s).

### Manual Cache Invalidation
When data changes (POST/PATCH/DELETE), we use `kvInvalidateMiddleware` to purge relevant keys.

```typescript
// apps/merchant/src/middleware/kv-invalidate.ts
export const kvInvalidateMiddleware = async (c: Context, next: Next) => {
  await next();
  
  // Only invalidate on successful mutations
  if (c.req.method !== 'GET' && c.res.status >= 200 && c.res.status < 300) {
    const kv = c.env.KV_CACHE;
    // Example: Purge all product-related cache keys
    const list = await kv.list({ prefix: 'cache:*/v1/products' });
    for (const key of list.keys) {
      await kv.delete(key.name);
    }
  }
};
```

## R2 Image Management

Product images are stored in the `IMAGES` R2 bucket. In production, these are served via a public URL defined in `IMAGES_URL`.

### Storing and Serving Images
```typescript
app.put('/v1/images/:filename', async (c) => {
  const filename = c.req.param('filename');
  const body = await c.req.arrayBuffer();
  const contentType = c.req.header('content-type') || 'application/octet-stream';

  await c.env.IMAGES.put(filename, body, {
    httpMetadata: { contentType }
  });

  return c.json({ 
    url: `${c.env.IMAGES_URL}/${filename}`,
    key: filename 
  });
});
```

## Secrets and Environment Variables

Fufuni distinguishes between "Variables" (public configuration) and "Secrets" (sensitive keys).

### Mailgun Configuration
Mailgun is the default transactional email provider. If `MAILGUN_API_KEY` is missing, email sending is silently skipped. The following secrets must be configured in your `.env` and GitHub Secrets:
- `MAILGUN_API_KEY`: The API key from Mailgun.
- `MAILGUN_DOMAIN`: Your verified sending domain.
- `MAILGUN_BASE_URL`: Usually `https://api.mailgun.net` (US) or `https://api.eu.mailgun.net` (EU).
- `MAILGUN_USER`: The default "From" address.

### Variable Classification
| Location | Type | Usage |
| :--- | :--- | :--- |
| `wrangler.jsonc` (vars) | Public | `IMAGES_URL`, `compatibility_date` |
| `.env` / GitHub Secrets | Secret | `STRIPE_SECRET_KEY`, `AUTH0_CLIENT_SECRET`, `MERCHANT_SK` |
| GitHub Secrets | Infrastructure | `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID` |

## Adding a New Binding or Variable

To add a new infrastructure binding (like a new KV namespace or Queue) or a new environment variable, follow this mandatory checklist to ensure it works in both local development and CI/CD.

### Step 1: Update Configuration Files
Add the binding to `apps/merchant/wrangler.jsonc` and the variable to the root `.env`.

```jsonc
// apps/merchant/wrangler.jsonc
{
  "kv_namespaces": [
    { "binding": "NEW_KV", "id": "..." }
  ]
}
```

### Step 2: Update TypeScript Types
Run `npx wrangler types` in the `apps/merchant` directory to update `worker-configuration.d.ts`. Ensure the `Env` interface reflects your changes.

```typescript
// apps/merchant/worker-configuration.d.ts
interface Env {
  NEW_KV: KVNamespace;
  NEW_SECRET_VAR: string;
  // ... existing bindings
}
```

### Step 3: Map to CI/CD
You **must** add the new variable to `.github/workflows/create-env-artifact.yaml`. If you skip this, the variable will be undefined in production even if it exists in your local `.env`.

```yaml
# .github/workflows/create-env-artifact.yaml
- name: Create .env file
  run: |
    echo "NEW_SECRET_VAR=${{ secrets.NEW_SECRET_VAR }}" >> .env
```

## Exposing Variables to the Frontend

Frontend variables in Fufuni do **not** use the `VITE_` prefix. Instead, they are explicitly injected via the Vite `define` block in `apps/client/vite.config.ts`.

### Step 1: Update vite.config.ts
Add the variable to the `define` object. This replaces `import.meta.env.VAR_NAME` at build time.

```typescript
// apps/client/vite.config.ts
export default defineConfig({
  define: {
    'import.meta.env.STORE_NAME': JSON.stringify(process.env.STORE_NAME),
    'import.meta.env.API_BASE_URL': JSON.stringify(process.env.API_BASE_URL),
  }
});
```

### Step 2: Usage in React
```tsx
// apps/client/src/components/Header.tsx
export const Header = () => {
  // This is replaced with a hardcoded string during 'npm run build'
  const storeName = import.meta.env.STORE_NAME;
  
  return <h1>{storeName}</h1>;
};
```

### Permissions Logic
Fufuni handles navbar visibility using the `import.meta.env.PERMISSIONS` array. This is dynamically generated in `vite.config.ts` by collecting all keys ending in `_PERMISSION` from the environment.

```typescript
// Inside apps/client/vite.config.ts logic
const permissions = Object.keys(process.env)
  .filter(key => key.endsWith('_PERMISSION'))
  .map(key => process.env[key]);

// Injected as:
// 'import.meta.env.PERMISSIONS': JSON.stringify(permissions)
```

## CI/CD Workflow Summary

1.  **`create-env-artifact.yaml`**: Triggered on push. It reads GitHub Secrets, builds a `.env` file, runs `generate-wrangler-jsonc.py` to merge the environment into the Worker config, and creates an encrypted tarball.
2.  **`deploy-cloudflare-worker.yaml`**: Decrypts the artifact. It uses `wrangler secret bulk < secrets.json` to upload all `.env` values as encrypted secrets to Cloudflare, then deploys the code.
3.  **`pages.yaml`**: Decrypts the artifact to get the environment. It runs `npm run build:env`, which triggers Vite to bake the environment variables into the static JS/HTML files for GitHub Pages deployment.
