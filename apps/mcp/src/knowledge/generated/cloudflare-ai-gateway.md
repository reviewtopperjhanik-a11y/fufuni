## Cloudflare AI Gateway — Unified Access

The Cloudflare AI Gateway provides a unified interface for accessing multiple AI providers through a single endpoint. It offers centralized logging, caching, rate limiting, and observability, making it easier to manage AI integrations across your application.

### Overview

The Cloudflare AI Gateway supports two main paths for AI access:

1. **Compat Path**: Works with all providers (OpenAI, Groq, Anthropic, etc.) using the OpenAI-compatible format. Model IDs must be prefixed with the provider's gateway slug (e.g., "groq/llama-3.3-70b-versatile").

2. **Native Path**: Used specifically for Gemini embeddings, which have a dedicated endpoint and require a different request format.

The gateway is particularly useful when you need to:
- Centralize AI access through a single endpoint
- Gain visibility into AI usage across your application
- Apply rate limiting and caching at the gateway level
- Simplify authentication by using a single token for all providers

### ai.json Schema

The `ai.json` file defines the configuration for all AI providers. Here's the structure:

```typescript
interface AiConfig {
  version: number;
  providers: Record<string, AiProvider>;
}

interface AiProvider {
  protocol: AiProtocol; // "openai", "anthropic", or "gemini"
  endpoint: string; // Base API endpoint
  gatewayEndpoint?: string; // Cloudflare AI Gateway compat endpoint
  gatewayModelPrefix?: string; // Prefix for model IDs when using gateway
  keys: AiKey[]; // API keys for this provider
  models: AiModel[]; // Available models
}

interface AiModel {
  id: string; // Model identifier
  contextWindow: number; // Maximum context window in tokens
  maxOutputTokens: number; // Maximum tokens the model can generate
  tpmLimit: number | null; // Tokens-per-minute hard cap
  priority: number; // Selection priority (1 = highest)
  tags?: string[]; // Arbitrary labels
  usage?: "chat" | "embedding"; // Model usage category
  defaultDimensions?: number; // For embedding models only
}
```

### Encryption

The `ai.json` file is encrypted using AES-256-CBC with PBKDF2 key derivation to create `ai.json.enc`. This encrypted file is committed to version control while the decryption password (CRYPTOKEN) is stored as a Wrangler secret.

To create the encrypted file:

```bash
openssl enc -aes-256-cbc -a -pbkdf2 -iter 100000 -salt \
  -in ai.json -out ai.json.enc -pass pass:"${CRYPTOKEN}"
```

The `decryptAiConfig()` function in `lib/ai-enc.ts` handles decryption:

```typescript
export async function decryptAiConfig(
  base64Ciphertext: string,
  password: string,
): Promise<AiConfig> {
  // 1. base64 decode → raw bytes
  const raw = Uint8Array.from(atob(base64Ciphertext.trim()), c => c.charCodeAt(0));

  // 2. Verify OpenSSL "Salted__" magic header (bytes 0–7)
  if (new TextDecoder().decode(raw.slice(0, 8)) !== 'Salted__') {
    throw new Error('ai.json.enc: invalid format — expected OpenSSL "Salted__" header.');
  }

  const salt = raw.slice(8, 16);       // bytes 8–15
  const ciphertext = raw.slice(16);    // bytes 16–end

  // 3. PBKDF2-SHA256 → 48 bytes (32 key + 16 IV), matching -pbkdf2 -iter 100000
  const pwBytes = new TextEncoder().encode(password);
  const baseKey = await crypto.subtle.importKey('raw', pwBytes, 'PBKDF2', false, ['deriveBits']);
  const derived = new Uint8Array(
    await crypto.subtle.deriveBits(
      { name: 'PBKDF2', hash: 'SHA-256', salt, iterations: 100_000 },
      baseKey,
      384, // 48 bytes × 8 bits
    ),
  );

  // 4. AES-256-CBC decrypt
  const aesKey = await crypto.subtle.importKey(
    'raw', derived.slice(0, 32), 'AES-CBC', false, ['decrypt'],
  );
  const plaintext = await crypto.subtle.decrypt(
    { name: 'AES-CBC', iv: derived.slice(32, 48) },
    aesKey,
    ciphertext,
  );

  return JSON.parse(new TextDecoder().decode(plaintext)) as AiConfig;
}
```

### Gateway Authentication

When the Cloudflare AI Gateway is configured, requests are authenticated using the `cf-aig-authorization` header:

```typescript
// In every request to the gateway
headers: {
  ...(aiParams.cloudflareAigToken ? { "cf-aig-authorization": `Bearer ${aiParams.cloudflareAigToken}` } : {}),
}
```

The `resolveProviderEndpoint()` function determines whether to use the gateway or direct provider endpoint:

```typescript
export function resolveProviderEndpoint(
  provider: AiProvider,
  aigToken: string | undefined,
): { endpoint: string; useGateway: boolean } {
  if (aigToken && provider.gatewayEndpoint) {
    return { endpoint: provider.gatewayEndpoint, useGateway: true };
  }
  return { endpoint: provider.endpoint, useGateway: false };
}
```

### Model ID Prefixing

The `resolveModelId()` function handles model ID prefixing for gateway requests:

```typescript
export function resolveModelId(
  modelId: string,
  provider: AiProvider,
  useGateway: boolean,
): string {
  if (useGateway && provider.gatewayModelPrefix) {
    // Avoid double-prefixing if the model ID already contains a slash
    if (modelId.includes('/')) return modelId;
    return `${provider.gatewayModelPrefix}/${modelId}`;
  }
  return modelId;
}
```

Examples:
- Groq: "llama-3.3-70b-versatile" → "groq/llama-3.3-70b-versatile"
- Anthropic: "claude-haiku-4-5" → "anthropic/claude-haiku-4-5"
- Gemini: "gemini-3-flash-preview" → "google-ai-studio/gemini-3-flash-preview"

### CORS Limitation

Direct browser-to-gateway calls fail due to CORS restrictions. The Cloudflare AI Gateway with "Authenticated Gateway" enabled returns a 401 on the CORS preflight OPTIONS request because browsers cannot send custom headers (like `cf-aig-authorization`) in OPTIONS requests. This limitation prevents any JavaScript library from working around the issue.

As an interim solution, you can set `DISABLE_CLOUDFLARE_AIG=true` in your `.env` file to force the frontend to skip gateway routing and call the provider directly. This is exposed via the `vite.config.ts` define block as `import.meta.env.DISABLE_CLOUDFLARE_AIG`.

### Known Pitfalls

1. **Usage Field**: All models must have the `usage` field set to either "chat" or "embedding". Failure to set this field can cause embedding models to be selected as chat models, leading to unexpected behavior.

2. **Field Names**: The field names in the `AiParams` interface must match exactly with the response from the `/v1/ai/parameters` endpoint. Any mismatch will cause runtime errors.

3. **CORS Issue**: The CORS limitation with the Cloudflare AI Gateway requires the `DISABLE_CLOUDFLARE_AIG` workaround until Cloudflare addresses the issue.
