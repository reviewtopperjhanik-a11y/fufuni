## Unified AI Access and Gateway Architecture

Fufuni uses a unified approach to AI provider integration, abstracting multiple protocols (OpenAI, Anthropic, Gemini) behind a consistent internal interface. At the core of this system is the **Cloudflare AI Gateway**, which acts as a proxy for observability, request logging, response caching, and unified rate limiting.

The framework supports two distinct access paths through the gateway:
1.  **Compat Path**: A universal OpenAI-compatible endpoint (`/compat`) that translates standard OpenAI-format requests to any backend provider (Groq, Anthropic, etc.).
2.  **Native Path**: Used specifically for Gemini embeddings to support native Google AI Studio features like `embedContent` that are not fully covered by the compat layer.

## The ai.json Configuration Schema

AI credentials and model capabilities are defined in a structured JSON file. This file is never committed in plaintext; it is encrypted into `ai.json.enc` using a project-wide secret.

### Configuration Structure
Each provider entry in `ai.json` defines its protocol, direct endpoint, and gateway-specific metadata.

```typescript
// Example of a provider block in ai.json
{
  "version": 1,
  "providers": {
    "groq": {
      "protocol": "openai",
      "gatewayEndpoint": "https://gateway.ai.cloudflare.com/v1/YOUR_ACCOUNT/YOUR_GATEWAY/compat",
      "gatewayModelPrefix": "groq",
      "endpoint": "https://api.groq.com/openai/v1",
      "keys": [
        { "key": "gsk_...", "owner": "dev@fufuni.com", "type": "paid" }
      ],
      "models": [
        {
          "id": "llama-3.3-70b-versatile",
          "usage": "chat",
          "contextWindow": 131072,
          "maxOutputTokens": 32768,
          "tpmLimit": 12000,
          "priority": 1,
          "tags": ["fast", "code"]
        }
      ]
    }
  }
}
```

### Critical Model Usage Field
The `usage` field (`"chat"` | `"embedding"`) is mandatory. Failing to set this correctly causes the selection logic to pick a high-priority embedding model for a chat request, leading to API failures. The `priority` field acts as a rank: `1` is the primary choice, with higher numbers serving as fallback candidates.

## Encryption and Runtime Decryption

Fufuni uses `AES-256-CBC` with `PBKDF2` to secure AI credentials. The decryption happens entirely in memory within the Cloudflare Worker or the MCP process using the Web Crypto API.

### Encrypting the configuration
To update the AI configuration, use the following `openssl` command with your `CRYPTOKEN`:

```bash
openssl enc -aes-256-cbc -a -pbkdf2 -iter 100000 -salt \
  -in ai.json -out ai.json.enc -pass pass:"${CRYPTOKEN}"
```

### Decryption logic (lib/ai-enc.ts)
The `decryptAiConfig` function is designed to be environment-agnostic (Node.js 18+ and Workers).

```typescript
import { type AiConfig } from './ai-enc';

export async function decryptAiConfig(
  base64Ciphertext: string,
  password: string,
): Promise<AiConfig> {
  const raw = Uint8Array.from(atob(base64Ciphertext.trim()), c => c.charCodeAt(0));
  
  // OpenSSL "Salted__" header check
  if (new TextDecoder().decode(raw.slice(0, 8)) !== 'Salted__') {
    throw new Error('Invalid encryption format');
  }

  const salt = raw.slice(8, 16);
  const ciphertext = raw.slice(16);

  const pwBytes = new TextEncoder().encode(password);
  const baseKey = await crypto.subtle.importKey('raw', pwBytes, 'PBKDF2', false, ['deriveBits']);
  const derived = new Uint8Array(
    await crypto.subtle.deriveBits(
      { name: 'PBKDF2', hash: 'SHA-256', salt, iterations: 100_000 },
      baseKey,
      384 // 48 bytes (32 key + 16 IV)
    ),
  );

  const aesKey = await crypto.subtle.importKey(
    'raw', derived.slice(0, 32), 'AES-CBC', false, ['decrypt'],
  );
  
  const plaintext = await crypto.subtle.decrypt(
    { name: 'AES-CBC', iv: derived.slice(32, 48) },
    aesKey,
    ciphertext,
  );

  return JSON.parse(new TextDecoder().decode(plaintext)) as AiConfig;
}
```

## Gateway Authentication and Model Routing

Routing a request through the Cloudflare AI Gateway requires two main transformations: injecting the `cf-aig-authorization` header and prefixing the model ID with the provider slug.

### Provider Resolution
The `resolveProviderEndpoint` helper determines if the gateway should be used based on the presence of the `CLOUDFLARE_AIG_TOKEN` environment variable.

```typescript
export function resolveProviderEndpoint(
  provider: AiProvider,
  aigToken: string | undefined,
): { endpoint: string; useGateway: boolean } {
  if (aigToken && provider.gatewayEndpoint) {
    return { endpoint: provider.gatewayEndpoint, useGateway: true };
  }
  return { endpoint: provider.endpoint, useGateway: false };
}

export function resolveModelId(
  modelId: string,
  provider: AiProvider,
  useGateway: boolean,
): string {
  if (useGateway && provider.gatewayModelPrefix) {
    // Prevents double-prefixing: "groq/llama" remains "groq/llama"
    if (modelId.includes('/')) return modelId;
    return `${provider.gatewayModelPrefix}/${modelId}`;
  }
  return modelId;
}
```

## Backend Parameter Exposure

The Merchant Worker provides an endpoint for the frontend to retrieve active AI parameters. This route handles model rotation and credential load-balancing across the key pool.

### GET /v1/ai/parameters
This route requires the `ai:api` permission. It returns the `cloudflareAigToken` and `cloudflareAigUrl` only if the backend environment variable is configured.

```typescript
// apps/merchant/src/routes/ai.ts
adminApp.openapi(aiParamsRoute, async (c) => {
  const config = await loadConfig(c.env);
  if (!config) throw new ApiError('not_configured', 503);

  const candidates = selectModels(config, { usage: 'chat' });
  
  for (const { providerKey, provider, model } of candidates) {
    const validKeys = provider.keys.filter(k => k.type !== 'expired');
    if (validKeys.length === 0) continue;

    const keyObj = validKeys[Math.floor(Math.random() * validKeys.length)];
    
    return c.json({
      providerName: providerKey,
      apiKey: keyObj.key,
      model: model.id,
      url: provider.endpoint,
      // Injected from Worker environment
      cloudflareAigToken: c.env.CLOUDFLARE_AIG_TOKEN || null,
      cloudflareAigUrl: provider.gatewayEndpoint || null,
    }, 200);
  }
  throw new ApiError('no_valid_keys', 503);
});
```

### The Critical CORS Pitfall
**Authenticated Cloudflare AI Gateways currently fail on browser CORS preflights.**
When a browser makes a `POST` request to the gateway, it first sends an `OPTIONS` (preflight) request. Browsers do not allow custom headers like `cf-aig-authorization` in the `OPTIONS` request. Because the gateway requires this header for authentication, it returns a `401 Unauthorized` before the `POST` ever happens.

**Solution**: The framework includes a `DISABLE_CLOUDFLARE_AIG` build-time flag.
- Set `DISABLE_CLOUDFLARE_AIG=true` in your frontend `.env` file.
- This forces the client to bypass the gateway and talk directly to the provider (e.g., Groq) until Cloudflare implements CORS-compliant authentication for the AI Gateway.

## Summary of Usage Rules

### Choosing Models
- **Chat**: Always filter by `usage: 'chat'`.
- **Embedding**: Always filter by `usage: 'embedding'`.
- **Priority**: Lower numbers are better.

### Gateway Endpoint mapping
| Provider | gatewayModelPrefix | Compat Path Required? |
| :--- | :--- | :--- |
| Groq | `groq` | Yes |
| Anthropic | `anthropic` | Yes |
| Google AI Studio | `google-ai-studio` | For Chat only |

### Gemini Embedding Specifics
- **Model**: `gemini-embedding-2-preview`
- **Dimensions**: `256` (configured via `defaultDimensions` in `ai.json`)
- **Protocol**: Uses a specialized Google AI Studio flow via `generateEmbeddingViaGateway`.
