## Cloudflare AI Gateway — Unified Access

The Cloudflare AI Gateway provides a unified interface for accessing multiple AI providers through a single endpoint. It offers several benefits including observability, logging, caching, and rate limiting. The gateway supports two main paths: the compat path for all providers and the native path for Gemini embeddings.

### Overview

The Cloudflare AI Gateway acts as a middleman between your application and AI providers, offering several advantages:

1. **Observability**: Monitor all AI requests through a single interface
2. **Logging**: Centralized logging for all AI interactions
3. **Caching**: Reduce costs and latency by caching responses
4. **Rate Limiting**: Manage request rates across all providers
5. **Unified Interface**: Access multiple providers through a single endpoint

The gateway supports two main access paths:

1. **Compat Path**: Works with all providers using OpenAI-compatible format
2. **Native Path**: Specialized path for Gemini embeddings (256 dimensions)

### ai.json Schema

The `ai.json` file defines the configuration for all AI providers. Here's the basic structure:

```typescript
interface AiConfig {
  version: number;
  providers: Record<string, AiProvider>;

interface AiProvider {
  protocol: AiProtocol; // 'openai' | 'anthropic' | 'gemini'
  endpoint: string; // Base API endpoint
  gatewayEndpoint?: string; // Cloudflare AI Gateway compat endpoint
  gatewayModelPrefix?: string; // Prefix for model IDs when using gateway

interface AiModel {
  id: string; // Model identifier
  contextWindow: number; // Maximum context window in tokens

  priority: number; // Selection priority (1 = highest)
  tags?: string[]; // Arbitrary labels

  defaultDimensions?: number; // For embedding models only
}
```

### Encryption

The `ai.json` file is encrypted to `ai.json.enc` using AES-256-CBC with PBKDF2 key derivation:

```bash
openssl enc -aes-256-cbc -a -pbkdf2 -iter 100000 -salt \
  -in ai.json -out ai.json.enc -pass pass:"${CRYPTOKEN}"
```

The `decryptAiConfig()` function in `lib/ai-enc.ts` handles decryption:

```typescript
export async function decryptAiConfig(
  base64Ciphertext: string,
  password: string,
): Promise<AiConfig> {
  // 1. base64 decode → raw bytes
  const raw = Uint8Array.from(atob(base64Ciphertext.trim()), c => c.charCodeAt(0));

  // 2. Verify OpenSSL "Salted__" magic header (bytes 0–7)
  if (new TextDecoder().decode(raw.slice(0, 8)) !== 'Salted__') {
    throw new Error('ai.json.enc: invalid format — expected OpenSSL "Salted__" header.');
  }

  const salt = raw.slice(8, 16);       // bytes 8–15
  const ciphertext = raw.slice(16);    // bytes 16–end

  // 3. PBKDF2-SHA256 → 48 bytes (32 key + 16 IV), matching -pbkdf2 -iter 100000
  const pwBytes = new TextEncoder().encode(password);
  const baseKey = await crypto.subtle.importKey('raw', pwBytes, 'PBKDF2', false, ['deriveBits']);
  const derived = new Uint8Array(
    await crypto.subtle.deriveBits(
      { name: 'PBKDF2', hash: 'SHA-256', salt, iterations: 100_000 },
      baseKey,
      384, // 48 bytes × 8 bits
    ),
  );

  // 4. AES-256-CBC decrypt
  const aesKey = await crypto.subtle.importKey(
    'raw', derived.slice(0, 32), 'AES-CBC', false, ['decrypt'],
  );
  const plaintext = await crypto.subtle.decrypt(
    { name: 'AES-CBC', iv: derived.slice(32, 48) },
    aesKey,
    ciphertext,
  );

  return JSON.parse(new TextDecoder().decode(plaintext)) as AiConfig;
}
```

The `CRYPTOKEN` Wrangler secret is used as the decryption password.

### Gateway Authentication

When using the Cloudflare AI Gateway, requests must include the `cf-aig-authorization` header:

```typescript
headers: {
  ...(aiParams.cloudflareAigToken ? { "cf-aig-authorization": `Bearer ${aiParams.cloudflareAigToken}` } : {}),
}
```

The `resolveProviderEndpoint()` function determines whether to use the gateway or direct provider endpoint:

```typescript
export function resolveProviderEndpoint(
  provider: AiProvider,
  aigToken: string | undefined,
): { endpoint: string; useGateway: boolean } {
  if (aigToken && provider.gatewayEndpoint) {
    return { endpoint: provider.gatewayEndpoint, useGateway: true };
  }
  return { endpoint: provider.endpoint, useGateway: false };
}
```

### Model ID Prefixing

The `resolveModelId()` function prefixes model IDs when using the gateway:

```typescript
export function resolveModelId(
  modelId: string,
  provider: AiProvider,
  useGateway: boolean,
): string {
  if (useGateway && provider.gatewayModelPrefix) {
    // Avoid double-prefixing if the model ID already contains a slash
    if (modelId.includes('/')) return modelId;
    return `${provider.gatewayModelPrefix}/${modelId}`;
  }
  return modelId;
}
```

Examples of prefixed model IDs:
- Groq: `groq/llama-3.3-70b-versatile`
- Anthropic: `anthropic/claude-haiku-4-5`
- Google: `google-ai-studio/gemini-3-flash-preview`

### CORS Limitation

Direct browser-to-gateway calls fail due to CORS restrictions:

1. The gateway requires the `cf-aig-authorization` header
2. Browsers cannot send custom headers in OPTIONS preflight requests
3. No JavaScript workaround exists for this browser security restriction

The interim solution is to set `DISABLE_CLOUDFLARE_AIG=true` in `.env`:

```typescript
// vite.config.ts
define: {
  'import.meta.env.DISABLE_CLOUDFLARE_AIG': JSON.stringify(process.env.DISABLE_CLOUDFLARE_AIG === 'true'),
},
```

### Known Pitfalls

1. **Usage Field Requirement**: All models must have the `usage` field set to either "chat" or "embedding". Failure to set this field can cause embedding models to be selected as chat models.

2. **Field Name Matching**: The `AiParams` interface fields must exactly match the `/v1/ai/parameters` response fields. Any mismatch will cause runtime errors.

3. **CORS Workaround**: The `DISABLE_CLOUDFLARE_AIG` flag is a temporary solution until Cloudflare addresses the CORS preflight issue.
