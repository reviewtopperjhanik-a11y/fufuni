## Execution and Environment Setup

The Fufuni seed script is a standalone TypeScript utility designed to populate a fresh database instance with realistic data. It interacts with the backend via the standard HTTP API, meaning the Merchant API must be active and the store must have undergone initial setup (via the `/init` flow or equivalent) before the script can run.

To execute the script, you must provide the base API URL and a valid Admin Secret Key. The script uses `tsx` to execute TypeScript directly without a manual compilation step.

```bash
# Navigate to the merchant app directory
cd apps/merchant

# Run the seed script targeting a local environment
# Syntax: npx tsx scripts/seed.ts <API_URL> <ADMIN_KEY>
npx tsx scripts/seed.ts http://localhost:8787 sk_test_fufuni_12345
```

The script is designed to be largely idempotent. It checks for the existence of certain entities (like reviews) before attempting creation, though rerunning it multiple times may result in duplicate orders or inventory adjustments depending on the current state of the SQLite database.

### Variant Pricing and Stock
Prices in Fufuni are always handled as **integers (cents)** to prevent floating-point inaccuracies during currency conversion or tax calculation. When a product is seeded, the script automatically generates prices for USD and GBP based on the configured exchange rates.

## Expanding Seed Categories

Categories in Fufuni support hierarchical structures (parent/child relationships). The `seedCategories` function orchestrates this by first creating parent categories and then passing their IDs to child category creation calls.

### Defining a New Category

To add a category, update the `seedCategories` function. You should use the `createCat` helper, which handles the localized JSON strings and image processing (converting to WebP and generating thumbnails).

```typescript
async function seedCategories() {

  // 3. Return the ID so it can be used by the product seeder
  return {
    // ... existing returns ...
    footwear: footwearCategory.id,
  };
}
```

## Resilience with apiWithRetry

Since Fufuni backends typically run on Cloudflare Workers, they are subject to various limits. The `apiWithRetry` helper is a wrapper around the standard `fetch` call that implements exponential backoff specifically for "Rate limit exceeded" errors (HTTP 429).

### Usage in Custom Scripts

When adding custom seeding logic that performs a high volume of requests (like generating thousands of orders), always use `apiWithRetry` instead of the raw `api` function.

```typescript
/**
 * Example of high-volume seeding for stress testing
 */
async function seedManyCustomers(count: number) {
  for (let i = 0; i < count; i++) {
    const payload = {
      email: `test-user-${i}@example.com`,
      first_name: 'Test',
      last_name: `User ${i}`
    };

    // This will pause and retry if the Worker hits a rate limit
    await apiWithRetry('/v1/customers', payload);
    console.log(`👤 Created customer ${i + 1}/${count}`);
  }
}
```

The helper looks for a specific string pattern in the error message: `Try again in (\d+) seconds`. If found, it sleeps for that duration; otherwise, it uses $2^{attempt}$ seconds as the backoff delay.

## Currency and Price Conversion

Fufuni follows a "Price per Currency" model rather than a dynamic conversion at checkout. The seed script simulates this by calculating prices for the three main supported currencies (EUR, USD, GBP) at the time of creation.

### Conversion Logic

The base currency for seeding is EUR. The constants `EUR_TO_USD` and `EUR_TO_GBP` define the rates.

```typescript
const EUR_TO_USD = 1.14;
const EUR_TO_GBP = 0.86;

/**
 * Rounds to the nearest cent after conversion to ensure integer values.
 */
function convertCents(cents: number, rate: number): number {
  return Math.round(cents * rate);
}

// Example usage in seedProducts
const baseEur = 2999; // €29.99
const priceUsd = convertCents(baseEur, EUR_TO_USD); // 3419 cents -> $34.19
const priceGbp = convertCents(baseEur, EUR_TO_GBP); // 2579 cents -> £25.79
```

This approach ensures that price displays remain consistent across the application and that the database reflects fixed prices for different regions.

## Image Processing and WebP Embedding

To ensure the seed script remains portable and doesn't require complex image hosting during development, it converts all source images (PNG/JPEG) into **WebP Data URIs**. This allows images to be stored directly in the SQLite database.

### The toWebpDataUri Workflow

1.  **Resolution:** The script looks for the image in the local `img/` directory. If not found, it checks the `image_map.ts` file for a base64 fallback.
2.  **Decoding:** It uses `pngjs` or `jpeg-js` to get raw RGBA pixel data.
3.  **Resizing:** If the image exceeds `maxSide` pixels, the `nnsResize` (Nearest-Neighbor) function downscales it to keep the database size manageable.
4.  **Encoding:** It uses `webp-wasm` to encode the pixels into a WebP buffer.
5.  **Output:** Returns a `data:image/webp;base64,...` string.

```typescript
async function processProductImage(fileName: string) {
  // Generate a large hero image (max 1200px)
  const heroUrl = await toWebpDataUri(fileName, 1200, 80);
  
  // Generate a small thumbnail (max 300px)
  const thumbUrl = await toWebpDataUri(fileName, 300, 75);
  
  return { heroUrl, thumbUrl };
}
```

This mechanism allows the frontend to immediately render product images without needing an external S3 bucket or CDN during the initial development phase.

## Pattern for Custom Seed Helpers

When extending the framework, you should follow the modular pattern established in `seed.ts`. Each major entity type (e.g., Discounts, Gift Cards, Blog Posts) should have its own dedicated `seedX` function.

### Implementing a New Helper

Follow this structure to maintain consistency:

1.  Define the data set.
2.  Create the async function.
3.  Include logging with emojis for visual feedback.
4.  Update the `seed()` orchestrator.

```typescript
/**
 * Example: Seeding store promotions/discounts
 */
async function seedDiscounts() {
  console.log('🎟️ Seeding discount codes...');
  
  const discounts = [
    { code: 'WELCOME10', percentage: 10, starts_at: new Date().toISOString() },
    { code: 'FREESHIP', percentage: 0, free_shipping: true, starts_at: new Date().toISOString() }
  ];

  for (const d of discounts) {
    try {
      await api('/v1/discounts', d);
      console.log(`   ✅ Created: ${d.code}`);
    } catch (e) {
      console.warn(`   ⚠️  Failed to create ${d.code}: ${e.message}`);
    }
  }
}

// Inside the main seed() function:
async function seed() {
  // ... steps 1-5 ...
  await seedDiscounts(); // New Step 6
  // ...
}
```

This modular approach ensures that dependencies between entities (e.g., a discount needing a specific product ID) can be managed by passing data between the functions in the orchestrator.
