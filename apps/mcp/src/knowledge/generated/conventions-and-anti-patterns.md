## Conventions & Anti-Patterns Guide

## CONVENTIONS

### File Placement for New Topics
Always add new topic files in `apps/mcp/knowledge/topics/`. Each topic file must export a default Topic object with name, description, sources, systemPrompt, and buildPrompt.

```typescript
// Example: apps/mcp/knowledge/topics/new-feature.ts
import { Topic } from "../types";

export default {
  name: "new-feature",
  description: "Description of the new feature",
  sources: ["source1", "source2"],
  systemPrompt: "System prompt for the new feature",
  buildPrompt: "Build prompt for the new feature",
} as Topic;
```

### Regenerating Knowledge Files
Always run `npm run mcp:generate:force` after editing a topic file, followed by `npm run mcp:gen-knowledge` to publish to the MCP server.

```bash
npm run mcp:generate:force
npm run mcp:gen-knowledge
```

### Avoid Direct Edits
Do not edit `apps/mcp/src/knowledge.ts` directly as it is auto-generated from `apps/mcp/src/knowledge/generated/*.md` files by `gen-knowledge.ts`.

### Event Handling
Never use `onClick` on interactive elements; always use `onPress` (HeroUI/React Aria requirement).

```typescript
// Correct
<button onPress={() => console.log('Pressed')}>Click me</button>
```

### Button Variants
Never use `variant="bordered"`; use `variant="outline"` instead.

```typescript
// Correct
<Button variant="outline">Outline Button</Button>
```

### Button Styling
Never use the `radius` prop on Button; use Tailwind classes (e.g., `rounded-none`, `rounded-full`) in `className`.

```typescript
// Correct
<Button className="rounded-full">Full Radius Button</Button>
```

### State Management
Never use `useEffect` to synchronize state; use React Query for server state, derive UI state from props/query data.

```typescript
// Correct
const { data } = useQuery('key', fetchData);
```

### Auth0 Token Storage
Never store the Auth0 access token in localStorage or sessionStorage; the Auth0 React SDK stores it in memory.

### Permission Strings
Never hardcode permission strings; use `import.meta.env.PERMISSIONS` (frontend) or the permissions array from the JWT (backend middleware).

```typescript
// Correct
const permissions = import.meta.env.PERMISSIONS;
```

### Auth0 Management API
Never call the Auth0 Management API from the frontend without using the `getAuth0ManagementToken()` helper; raw Management API tokens must not be exposed in the browser.

```typescript
// Correct
const token = await getAuth0ManagementToken();
```

### Admin Route Protection
Always wrap admin routes in `AuthenticationGuardWithPermission` in `app.tsx`; never rely only on UI hiding.

```typescript
// Correct
<AuthenticationGuardWithPermission>
  <AdminRoute />
</AuthenticationGuardWithPermission>
```

### Database Access
Always use `getDb(c.var.db)` in Hono route handlers; never access `c.env.MERCHANT` directly in route logic.

```typescript
// Correct
const db = getDb(c.var.db);
```

### Migrations
Always add new migrations to both the `.sql` file in `apps/merchant/migrations/` and the `ensureInitialized()` function in `do.ts`.

```typescript
// Example: apps/merchant/migrations/002_new_table.sql
CREATE TABLE new_table (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL
);
```

```typescript
// Example: apps/merchant/do.ts
async function ensureInitialized(db: D1Database) {
  await db.exec(`CREATE TABLE IF NOT EXISTS new_table (id INTEGER PRIMARY KEY, name TEXT NOT NULL)`);
}
```

### Environment Variables
Always add new backend environment variables to `.github/workflows/create-env-artifact.yaml` to ensure they are available in CI deployments.

```yaml
# Example: .github/workflows/create-env-artifact.yaml
env:
  NEW_VARIABLE: "value"
```

### Monetary Values
Always store monetary values as integers (smallest currency unit, e.g., cents); never store floats for money.

```typescript
// Correct
const price = 1000; // $10.00 in cents
```

### Error Handling
Use `ApiError` static helpers (e.g., `ApiError.notFound()`, `ApiError.unauthorized()`) rather than throwing raw errors in route handlers.

```typescript
// Correct
throw new ApiError.notFound('Product not found');
```

### Image Uploads
Always use the `ImageUploadInput` component in admin forms; never use a plain `<input type="file">`.

```typescript
// Correct
<ImageUploadInput onChange={(file) => console.log(file)} />
```

### i18n Keys
Always add new i18n keys to `en-US.json` first (master language), then to all other locale files. Never use `t()` without a translation key that exists in `en-US.json`.

```json
// Correct: en-US.json
{
  "new_key": "New translation"
}
```

```typescript
// Correct usage
const translation = t('new_key');
```

### Auth0 user_metadata
Avoid adding fields to the Auth0 `user_metadata` for data that should be in the DB; `user_metadata` is for client-managed preferences only (wishlist, UI prefs).

### dangerouslySetInnerHTML
Do not use `dangerouslySetInnerHTML` outside of `renderDescription()`; all user-generated HTML has already been sanitized by the backend.

```typescript
// Correct
<div dangerouslySetInnerHTML={renderDescription(htmlContent)} />
```

## ANTI-PATTERNS

### Direct Edits to Auto-Generated Files
Never edit `apps/mcp/src/knowledge.ts` directly — it is auto-generated from `apps/mcp/src/knowledge/generated/*.md` files by `gen-knowledge.ts`.

### Using onClick
Never use `onClick` on interactive elements — always use `onPress` (HeroUI/React Aria requirement).

### Using variant="bordered"
Never use `variant="bordered"` — use `variant="outline"` instead.

### Using radius Prop on Button
Never use the `radius` prop on Button — use Tailwind classes (e.g., `rounded-none`, `rounded-full`) in `className`.

### Using useEffect for State Synchronization
Never use `useEffect` to synchronize state — use React Query for server state, derive UI state from props/query data.

### Storing Auth0 Access Token in localStorage/sessionStorage
Never store the Auth0 access token in localStorage or sessionStorage — the Auth0 React SDK stores it in memory.

### Hardcoding Permission Strings
Never hardcode permission strings — use `import.meta.env.PERMISSIONS` (frontend) or the permissions array from the JWT (backend middleware).

### Direct Auth0 Management API Calls
Never call the Auth0 Management API from the frontend without going through the `getAuth0ManagementToken()` helper — raw Management API tokens must not be exposed in the browser.

### Relying Only on UI Hiding for Admin Routes
Never rely only on UI hiding for admin routes — always wrap admin routes in `AuthenticationGuardWithPermission` in `app.tsx`.

### Direct Access to c.env.MERCHANT
Never access `c.env.MERCHANT` directly in route logic — always use `getDb(c.var.db)` in Hono route handlers.

### Incomplete Migrations
Never add new migrations to only one place — always add them to both the `.sql` file in `apps/merchant/migrations/` and the `ensureInitialized()` function in `do.ts`.

### Missing Environment Variables in CI
Never forget to add new backend environment variables to `.github/workflows/create-env-artifact.yaml` — this ensures they are available in CI deployments.

### Storing Monetary Values as Floats
Never store monetary values as floats — always store them as integers (smallest currency unit, e.g., cents).

### Throwing Raw Errors
Never throw raw errors in route handlers — use `ApiError` static helpers (e.g., `ApiError.notFound()`, `ApiError.unauthorized()`).

### Plain File Inputs for Images
Never use a plain `<input type="file">` for image uploads — always use the `ImageUploadInput` component in admin forms.

### Missing i18n Keys in en-US.json
Never use `t()` without a translation key that exists in `en-US.json` — always add new i18n keys to `en-US.json` first (master language), then to all other locale files.

### Misusing Auth0 user_metadata
Never add fields to the Auth0 `user_metadata` for data that should be in the DB — `user_metadata` is for client-managed preferences only (wishlist, UI prefs).

### Improper Use of dangerouslySetInnerHTML
Never use `dangerouslySetInnerHTML` outside of `renderDescription()` — all user-generated HTML has already been sanitized by the backend.
