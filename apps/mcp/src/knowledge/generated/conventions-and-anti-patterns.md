## Conventions (What You MUST Do)

### **File Placement for New Features**
New topic files must be added to `apps/mcp/knowledge/topics/` and export a default `Topic` object with `name`, `description`, `sources`, `systemPrompt`, and `buildPrompt`. After editing, regenerate knowledge files with:
```bash
npm run mcp:generate:force && npm run mcp:gen-knowledge
```
*Example topic file:*
```typescript
// apps/mcp/knowledge/topics/payments.ts
export default {
  name: "Payments",
  description: "Handling payment processing and refunds",
  sources: ["apps/merchant/src/routes/payments.ts"],
  systemPrompt: "You are a payments expert...",
  buildPrompt: (input: string) => `Explain payments: ${input}`
};
```

### **Database Migrations**
Add new migrations to **both** the `.sql` file in `apps/merchant/migrations/` **and** the `ensureInitialized()` function in `do.ts`:
```typescript
// apps/merchant/src/do.ts
ensureInitialized(async (db) => {
  await db.exec(`
    CREATE TABLE IF NOT EXISTS refunds (
      id INTEGER PRIMARY KEY,
      amount_cents INTEGER NOT NULL
    )
  `);
});
```

### **Monetary Values**
Store amounts as **integers** (smallest currency unit, e.g., cents). Use `formatCurrency()` for display:
```typescript
// Correct: 1000 cents = $10.00
const priceCents = 1000;
const displayPrice = formatCurrency(priceCents, "USD"); // "$10.00"
```

### **Admin Route Protection**
Wrap admin routes in `AuthenticationGuardWithPermission` in `app.tsx`:
```tsx
// apps/admin/src/app.tsx
<AuthenticationGuardWithPermission permission="read:products">
  <ProductsAdminPage />
</AuthenticationGuardWithPermission>
```

### **Error Handling in Routes**
Use `ApiError` static helpers instead of raw errors:
```typescript
// apps/merchant/src/routes/products.ts
app.get("/products/:id", async (c) => {
  const product = await getProduct(c.var.db, c.req.param("id"));
  if (!product) throw ApiError.notFound("Product not found");
  return c.json(product);
});
```

### **Image Uploads**
Use `ImageUploadInput` in admin forms—never plain `<input type="file">`:
```tsx
// apps/admin/src/components/ProductForm.tsx
<ImageUploadInput
  name="productImage"
  label="Product Image"
  maxSizeMB={5}
/>
```

### **i18n Keys**
Add new keys to `en-US.json` first, then other locales. Never use `t()` without a valid key:
```json
// apps/admin/public/locales/en-US.json
{
  "product": {
    "title": "Product Title"
  }
}
```
```tsx
// Usage
t("product.title"); // Never hardcode "Product Title"
```

### **Environment Variables**
Add new backend env vars to `.github/workflows/create-env-artifact.yaml`:
```yaml
# .github/workflows/create-env-artifact.yaml
env:
  STRIPE_SECRET_KEY: ${{ secrets.STRIPE_SECRET_KEY }}
```

### **Database Access in Routes**
Use `getDb(c.var.db)`—never access `c.env.MERCHANT` directly:
```typescript
// apps/merchant/src/routes/orders.ts
app.get("/orders", async (c) => {
  const db = getDb(c.var.db); // Correct
  const orders = await db.prepare("SELECT * FROM orders").all();
  return c.json(orders);
});
```

## Anti-Patterns (What You MUST NOT Do)

### **❌ Never Use `onClick` on Interactive Elements**
**Why:** HeroUI/React Aria requires `onPress` for accessibility.
**Instead:**
```tsx
<Button onPress={handleSubmit}>Submit</Button>  // Correct
<Button onClick={handleSubmit}>Submit</Button> // ❌ Wrong
```

### **❌ Never Use `variant="bordered"`**
**Why:** HeroUI v3 replaced it with `variant="outline"`.
**Instead:**
```tsx
<Button variant="outline">Cancel</Button>  // Correct
<Button variant="bordered">Cancel</Button> // ❌ Wrong
```

### **❌ Never Use `radius` Prop on Buttons**
**Why:** Tailwind classes are required for consistency.
**Instead:**
```tsx
<Button className="rounded-full">Submit</Button>  // Correct
<Button radius="full">Submit</Button>            // ❌ Wrong
```

### **❌ Never Use `useEffect` for State Sync**
**Why:** React Query manages server state; derive UI state from props.
**Instead:**
```tsx
const { data: product } = useQuery(getProductQuery(id)); // Correct
useEffect(() => { /* sync state */ }, [deps]);          // ❌ Wrong
```

### **❌ Never Store Auth0 Tokens in `localStorage`**
**Why:** The Auth0 SDK stores tokens in memory securely.
**Instead:**
```tsx
const { getAccessTokenSilently } = useAuth0(); // Correct
localStorage.setItem("token", token);         // ❌ Wrong
```

### **❌ Never Hardcode Permission Strings**
**Why:** Permissions must come from `import.meta.env.PERMISSIONS` (frontend) or JWT (backend).
**Instead:**
```tsx
// Frontend
if (hasPermission("read:products")) { ... } // Correct
if (userPermissions.includes("read:products")) { ... } // ❌ Wrong
```

### **❌ Never Call Auth0 Management API Directly**
**Why:** Raw tokens must not be exposed in the browser.
**Instead:**
```tsx
const mgmtToken = await getAuth0ManagementToken(); // Correct
const rawToken = await getToken({ audience: "auth0" }); // ❌ Wrong
```

### **❌ Never Use `dangerouslySetInnerHTML` Outside `renderDescription()`**
**Why:** Backend already sanitizes user-generated HTML.
**Instead:**
```tsx
<div dangerouslySetInnerHTML={{ __html: sanitizedHtml }} /> // ❌ Wrong (unless in renderDescription())
{renderDescription(product.description)} // Correct
```

### **❌ Never Store Non-Preference Data in `user_metadata`**
**Why:** `user_metadata` is for client-managed prefs only (e.g., wishlist).
**Instead:**
```typescript
// Store in DB:
await db.prepare("INSERT INTO user_settings (user_id, theme) VALUES (?, ?)").run(userId, "dark");
// ❌ Wrong:
await auth0.updateUserMetadata(userId, { theme: "dark" });
```
