## Inventory & Warehouses Reference

### Data Model

#### **`inventory` Table (Legacy)**
```sql
CREATE TABLE inventory (
  id TEXT PRIMARY KEY,
  sku TEXT NOT NULL UNIQUE,
  on_hand INTEGER NOT NULL DEFAULT 0,
  reserved INTEGER NOT NULL DEFAULT 0,
  updated_at TEXT NOT NULL,
  FOREIGN KEY (sku) REFERENCES variants(sku) ON DELETE CASCADE
);
```
- **Purpose**: Legacy table for backward compatibility. Mirrors the *aggregated* total across all warehouses.
- **Note**: Always kept in sync with `warehouse_inventory` via triggers.

#### **`warehouse_inventory` Table**
```sql
CREATE TABLE warehouse_inventory (
  id TEXT PRIMARY KEY,
  sku TEXT NOT NULL,
  warehouse_id TEXT NOT NULL,
  on_hand INTEGER NOT NULL DEFAULT 0,
  reserved INTEGER NOT NULL DEFAULT 0,
  updated_at TEXT NOT NULL,
  FOREIGN KEY (sku) REFERENCES variants(sku) ON DELETE CASCADE,
  FOREIGN KEY (warehouse_id) REFERENCES warehouses(id) ON DELETE CASCADE,
  UNIQUE (sku, warehouse_id)
);
```
- **Purpose**: Tracks stock per SKU per warehouse. Used for all real-time operations.

#### **`warehouses` Table**
```sql
CREATE TABLE warehouses (
  id TEXT PRIMARY KEY,
  display_name TEXT NOT NULL,
  address TEXT NOT NULL,
  is_default BOOLEAN NOT NULL DEFAULT false,
  priority INTEGER NOT NULL DEFAULT 0,
  region_id TEXT,
  FOREIGN KEY (region_id) REFERENCES regions(id) ON DELETE SET NULL
);
```
- **Key Fields**:
  - `is_default`: Used for new products if no warehouse is specified.
  - `priority`: Determines allocation order during reservation (highest priority first).

### Transaction Safety

All inventory mutations **must** run inside Durable Object (DO) transactions to prevent race conditions. Example:

```typescript
// Correct: Wrapped in a DO transaction
await c.var.db.transaction(async (tx) => {
  await reserveInventory(tx, sku, 2);
  await createOrder(tx, orderData);
});
```

**Why?**
1. **Atomicity**: Ensures `reserved` and `on_hand` updates succeed or fail together.
2. **Isolation**: Prevents concurrent checkouts from overselling the same stock.
3. **Sync Guarantee**: The legacy `inventory` table is updated in the same transaction.

**Critical Sections**:
- `reserveInventory`: Checks `(on_hand - reserved) >= qty` in a single SQL statement.
- `commitSale`: Deducts both `on_hand` and `reserved` atomically.

### Core Utility Functions (`lib/inventory.ts`)

#### **1. `getAvailableQty(db, sku)`**
```typescript
export async function getAvailableQty(db: Database, sku: string): Promise<number>;
```
- **Purpose**: Returns `on_hand - reserved` for a SKU.
- **Resolution Order**:
  1. Sums `warehouse_inventory` rows for the SKU.
  2. Falls back to the legacy `inventory` table if no warehouse rows exist.
- **Usage**: Displaying stock levels in the storefront or admin panel.

#### **2. `reserveInventory(db, sku, qty)`**
```typescript
export async function reserveInventory(db: Database, sku: string, qty: number): Promise<void>;
```
- **Purpose**: Holds stock during checkout (called when adding to cart or at payment).
- **Behavior**:
  - For multi-warehouse SKUs: Reserves from the warehouse with the highest `(on_hand - reserved)`.
  - For legacy SKUs: Updates the `inventory` table directly.
  - Throws `ApiError.insufficientInventory` if stock is insufficient.
- **Sync**: Updates the legacy `inventory.reserved` to mirror the total.

#### **3. `releaseReservation(db, sku, qty)`**
```typescript
export async function releaseReservation(db: Database, sku: string, qty: number): Promise<void>;
```
- **Purpose**: Releases held stock (called on checkout failure or cart expiry).
- **Behavior**:
  - Reduces `reserved` in *all* warehouses holding the SKU (warehouse-agnostic release).
  - Uses `MAX(reserved - qty, 0)` to avoid negative values.

#### **4. `commitSale(db, sku, qty)`**
```typescript
export async function commitSale(db: Database, sku: string, qty: number): Promise<void>;
```
- **Purpose**: Permanently deducts stock after successful payment.
- **Behavior**:
  - Deducts `on_hand` **and** `reserved` in the same transaction.
  - Syncs the legacy `inventory` table with aggregated totals.
- **Trigger**: Called by the Stripe webhook handler after `payment_intent.succeeded`.

### Checkout Lifecycle

1. **Reservation** (`reserveInventory`):
   - Triggered when a customer adds an item to cart *or* starts checkout.
   - SQL Condition: `WHERE (on_hand - reserved) >= ?`.

2. **Commit** (`commitSale`):
   - Triggered **only** after payment confirmation (Stripe webhook).
   - Deducts both `on_hand` and `reserved`:
     ```sql
     UPDATE warehouse_inventory
     SET on_hand = on_hand - ?, reserved = reserved - ?
     WHERE sku = ? AND reserved >= ?
     ```

3. **Release** (`releaseReservation`):
   - Triggered if:
     - Payment fails.
     - Cart expires (after 30 minutes).
     - Customer cancels the order.
   - Uses `MAX(reserved - ?, 0)` to avoid negative values.

**Example Flow**:
```typescript
// 1. Customer adds to cart
await reserveInventory(db, "SKU123", 2);

// 2. Payment succeeds
await commitSale(db, "SKU123", 2);

// 3. Payment fails → release
await releaseReservation(db, "SKU123", 2);
```

### Admin Endpoints

#### **1. Adjust Stock**
```http
POST /admin/inventory/{sku}/adjust
```
- **Body**: `{ delta: number, reason: string }`
- **Behavior**:
  - Updates the legacy `inventory` table (for non-warehouse SKUs).
  - Logs the change to `inventory_logs`.
  - Triggers low-stock webhook if applicable.

#### **2. Adjust Warehouse Stock**
```http
POST /admin/inventory/{sku}/warehouse-adjust
```
- **Body**: `{ warehouse_id: string, delta: number, reason: string }`
- **Behavior**:
  - Creates a `warehouse_inventory` record if it doesn’t exist.
  - Syncs the legacy `inventory` table with the new total.
  - Logs to `warehouse_inventory_logs`.

#### **3. List Inventory**
```http
GET /admin/inventory
```
- **Query Params**:
  - `sku`: Filter by SKU.
  - `low_stock=true`: Only show SKUs with ≤10 available units.
  - `cursor`: Pagination.
- **Response**: Aggregated stock across warehouses + per-warehouse breakdown.

#### **4. Warehouse CRUD**
```http
GET|POST|PATCH|DELETE /admin/warehouses
```
- **Fields**:
  - `is_default`: Only one warehouse can be default.
  - `priority`: Higher values = allocated first during reservation.

### Low-Stock Webhook

**Trigger Conditions**:

### Multi-Warehouse Logic

#### **Stock Aggregation**
- **Available Stock**: Sum of `(on_hand - reserved)` across all warehouses for a SKU.
- **Reservation Strategy**: Allocates from the warehouse with the highest `(on_hand - reserved)` (simplest approach).

#### **Default Warehouse**
- **Purpose**: Used when:
  - A new product is created without specifying a warehouse.
  - A legacy SKU is migrated to multi-warehouse.
- **Selection**: The warehouse with `is_default = true`.

#### **Legacy Sync**
- **Why**: The checkout engine still reads from the `inventory` table for backward compatibility.
- **How**: After *any* `warehouse_inventory` change, the system updates `inventory.on_hand` and `inventory.reserved` to match the aggregated totals:
  ```sql
  UPDATE inventory
  SET on_hand = (SELECT COALESCE(SUM(on_hand), 0) FROM warehouse_inventory WHERE sku = ?),
      reserved = (SELECT COALESCE(SUM(reserved), 0) FROM warehouse_inventory WHERE sku = ?)
  WHERE sku = ?;
  ```
