## Development Architecture

The Fufuni MCP server is a Cloudflare Worker + Durable Object (class `FufuniMCP`) that exposes knowledge-base tools to AI assistants via HTTP SSE (`/mcp`) or stdio transport. Tool registration happens in `apps/mcp/src/tools.ts` via `registerFufuniTools()`, where each tool handler is wrapped in `withKvCache()` to avoid redundant decryption and BM25 searches.

The knowledge base is a static bundle compiled at build time. Key auto-generated files include:

- `apps/mcp/src/knowledge.ts`: Markdown content for all topics
- `apps/mcp/src/search/chunks.ts`: BM25 chunks for semantic search
- `apps/mcp/src/search/bm25-index.ts`: BM25 index
- `apps/mcp/src/manifest.ts`: Topic metadata (name, description, tags, commit hash)

These files are generated by `scripts/gen-knowledge.ts` and must never be edited manually. The `KV_CACHE` binding (defined in `wrangler.jsonc`) caches responses with keys including `MANIFEST_COMMIT`, ensuring cache invalidation on redeploy.

## Authoring and Maintaining Topics

Each topic is defined by a `Topic` object with these fields:

- `name`: File stem (e.g., `"db-schema"` for `mcp/db-schema.md`)
- `description`: One-sentence summary (≤ 200 chars)
- `tags`: Lowercase kebab-case keywords
- `sources`: Relative paths to source files
- `systemPrompt`: Role/instructions for the AI (usually `BASE_SYSTEM`)
- `buildPrompt`: Function generating the user prompt from sources
- `manualFacts`: Curated facts the AI must treat as authoritative
- `staticAppend`: Verbatim Markdown appended after AI output
- `maxSourceChars`: Override for source truncation

### Maintenance Checklist

When adding a new feature:
1. Check if an existing topic covers it → add source file to its `sources[]`
2. If no topic covers it → create a new topic file in `apps/mcp/src/knowledge/topics/`
3. Add non-obvious facts to `manualFacts[]`
4. Run `npm run mcp:auto:flash`

When renaming source files: update all `sources[]` arrays referencing the old path.

When changing conventions: add to `manualFacts[]` of relevant topics and to `BASE_SYSTEM` if global.

## VS Code Installation

Configure `.vscode/mcp.json` (in `.gitignore`):

### 1. HTTP Mode (Production)
```json
{
  "servers": {
    "fufuni": {
      "type": "http",
      "url": "https://fufuni-mcp.fufuni.workers.dev/mcp"
    }
  }
}
```

### 2. stdio Mode (Local)
```json
{
  "servers": {
    "fufuni": {
      "type": "stdio",
      "command": "npm",
      "args": ["--prefix", "apps/mcp", "run", "stdio"]
    }
  }
}
```

### 3. Local HTTP Mode
```json
{
  "servers": {
    "fufuni": {
      "type": "http",
      "url": "http://localhost:8788/mcp"
    }
  }
}
```

For Claude Desktop, add to `claude_desktop_config.json`:
```json
{
  "mcpServers": {
    "fufuni": {
      "command": "npx",
      "args": ["mcp-remote", "https://fufuni-mcp.fufuni.workers.dev/mcp"]
    }
  }
}
```

## Regeneration Workflow

### Commands

1. **`mcp:auto:flash`**
   - Provider: Gemini (21 keys, round-robin)
   - Use: Fast iteration with auto-refresh
   - Requires: `CRYPTOKEN`
   - Flags: `--auto-refresh --max-token-override=30000 --no-model-fallback --provider=gemini`

2. **`mcp:auto:mistral`**
   - Provider: Mistral (6 keys)
   - Use: Large context window (99k tokens)
   - Flags: `--max-token-override=99000`

3. **`mcp:generate`**
   - Use: CI or single-topic regeneration
   - Reads: `AI_MODEL`, `AI_API_KEY`, `AI_API_URL` from env

4. **`mcp:generate:force`**
   - Use: Major refactors or `BASE_SYSTEM` changes

5. **`gen-knowledge`**
   - Use: Final step after `.md` changes
   - Rebuilds: `knowledge.ts`, `bm25-index.ts`, `chunks.ts`, `manifest.ts`

### Example: Single-Topic Regeneration
```bash
cd apps/mcp
npm run mcp:generate -- --topic=example-topic --force --provider=gemini
```

### Deployment

cd apps/mcp
npm run deploy  # Runs build:sources + wrangler deploy
