## Development Architecture

The Fufuni MCP server is a Cloudflare Worker + Durable Object (class `FufuniMCP`) that exposes knowledge-base tools to AI assistants via HTTP SSE (`/mcp`) or stdio transport.

### Runtime Structure
- **Cloudflare Worker**: Handles HTTP requests and SSE connections.
- **Durable Object**: Manages stateful operations (e.g., rate limiting, caching).
- **Transport Modes**: Supports both HTTP SSE (production) and stdio (local development).

### Tool Registration
Tools are registered in `apps/mcp/src/tools.ts` via `registerFufuniTools()`. Each tool handler is wrapped with `withKvCache()` to avoid redundant computations and cache responses:

```typescript
// Example tool registration
server.registerTool("list_topics", {
  title: "List all Fufuni knowledge topics",
  description: "List all available Fufuni knowledge topics with their tags and metadata.",
}, async () => {
  const cacheKey = makeCacheKey("list_topics", {});
  return withKvCache(env.KV_CACHE, cacheKey, 86_400, async () => {
    // Tool logic here
  });
});
```

### Auto-Generated Files
The following files are auto-generated by `scripts/gen-knowledge.ts` and must never be edited manually:
- `apps/mcp/src/knowledge.ts`: Markdown content for all topics.
- `apps/mcp/src/search/chunks.ts`: BM25 search chunks.
- `apps/mcp/src/search/bm25-index.ts`: BM25 search index.
- `apps/mcp/src/manifest.ts`: Topic metadata (name, description, tags, commit hash).

### Caching Strategy
- **KV_CACHE Binding**: Used for caching tool responses.
- **Cache Invalidation**: Based on `MANIFEST_COMMIT` — redeploying the Worker invalidates all cache entries automatically.

## Authoring and Maintaining Topics

### Topic Interface
Each topic is defined by a `Topic` object with the following fields:

| Field          | Type                     | Required | Description |
|----------------|--------------------------|----------|-------------|
| `name`         | `string`                 | Yes      | File stem (e.g., `db-schema` for `mcp/db-schema.md`). |
| `description`  | `string` (≤ 200 chars)   | Yes      | One-sentence description shown in logs. |
| `tags`         | `string[]`               | Yes      | Curated tags for retrieval filtering (lowercase, kebab-case). |
| `sources`      | `string[]`               | Yes      | Relative paths of source files to include in the prompt. |
| `systemPrompt` | `string`                 | Yes      | Role/instructions for the AI (always `BASE_SYSTEM`). |
| `buildPrompt`  | `(sources: string) => string` | Yes | Function that receives concatenated source text and returns the full user prompt. |
| `manualFacts`  | `string[]`               | No       | Curated facts treated as absolute truth by the AI. |
| `staticAppend` | `string`                 | No       | Verbatim Markdown appended after AI output. |
| `maxSourceChars` | `number`               | No       | Override per-file character budget for source truncation. |

### Mandatory Checklist
When adding a new feature to Fufuni:
1. **Check Existing Topics**: If an existing topic covers the feature, add the new source file to its `sources[]` array.
2. **Create New Topic**: If no topic covers it, create a new topic file in `apps/mcp/src/knowledge/topics/`.
3. **Add Manual Facts**: Add non-obvious facts (security rules, conventions, gotchas) to `manualFacts[]`.
4. **Regenerate**: Run `npm run mcp:auto:flash` or `npm run mcp:auto:mistral` to regenerate only the changed topics.

## VS Code Installation

### HTTP Mode (Remote Production Worker)
```json
{
  "servers": {
    "fufuni": {
      "type": "http",
      "url": "https://fufuni-mcp.fufuni.workers.dev/mcp"
    }
  }
}
```

### stdio Mode (Local npm run stdio Subprocess)
```json
{
  "servers": {
    "fufuni": {
      "type": "stdio",
      "command": "npm",
      "args": ["--prefix", "apps/mcp", "run", "stdio"]
    }
  }
}
```

### Local HTTP Mode (wrangler dev on port 8788)
```json
{
  "servers": {
    "fufuni": {
      "type": "http",
      "url": "http://localhost:8788/mcp"
    }
  }
}
```

### Claude Desktop Config
Add to `~/Library/Application Support/Claude/claude_desktop_config.json`:
```json
{
  "mcpServers": {
    "fufuni": {
      "command": "npx",
      "args": ["mcp-remote", "https://fufuni-mcp.fufuni.workers.dev/mcp"]
    }
  }
}
```

**Note**: `.vscode/mcp.json` is in `.gitignore`. After changes, run "MCP: Restart Server" from the VS Code command palette.

## Regeneration Workflow

| Command | Provider | When to Use | Required Env Vars | Output |
|---------|----------|--------------|-------------------|--------|
| `npm run mcp:auto:flash` | Gemini (free tier) | Regular updates (small changes) | `CRYPTOKEN` | Updates changed topics |
| `npm run mcp:auto:mistral` | Mistral (free tier) | Large context windows (many sources) | `CRYPTOKEN` | Updates changed topics |
| `npm run mcp:generate` | Direct AI env vars | CI or single-topic regeneration | `AI_MODEL`, `AI_API_KEY`, `AI_API_URL` | Updates changed topics |
| `npm run mcp:generate:force` | Direct AI env vars | Major refactors or BASE_SYSTEM changes | `AI_MODEL`, `AI_API_KEY`, `AI_API_URL` | Forces full rebuild |
| `npm run gen-knowledge` | N/A | Final step after regeneration | None | Rebuilds `knowledge.ts`, `bm25-index.ts`, `chunks.ts`, `manifest.ts` |
| `npm run mcp:generate -- --topic=<name> --force --provider=gemini` | Gemini | Iterating on a single topic | `CRYPTOKEN` | Updates one topic |

**Typical Workflow**:
1. Make changes to source files or topic definitions.
2. Run `npm run mcp:auto:flash` or `npm run mcp:auto:mistral` to regenerate topics.
3. Run `cd apps/mcp && npm run gen-knowledge` to update the static bundle.
4. Deploy with `npm run deploy` inside `apps/mcp/`.

**Deployment**: Run `npm run deploy` inside `apps/mcp/` to build sources and deploy to Cloudflare. The `MANIFEST_COMMIT` value is baked in at build time, ensuring cache invalidation on redeploy.
