## Development Architecture

The Fufuni MCP server is implemented as a Cloudflare Worker combined with a Durable Object (class `FufuniMCP`). It serves the knowledge base through two transport modes:

1. **HTTP SSE endpoint** at `/mcp` for remote clients
2. **stdio transport** for local development with VS Code and Claude Desktop

All tools are registered in `apps/mcp/src/tools.ts` via `registerFufuniTools()`, which accepts dependencies including the manifest, knowledge base content, and encrypted AI configuration. Each tool handler is wrapped with `withKvCache()` to avoid redundant computations and cache responses based on the `MANIFEST_COMMIT` value.

The system relies on several auto-generated files that should **never be edited manually**:
- `apps/mcp/src/knowledge.ts` — Markdown content of all topics
- `apps/mcp/src/search/chunks.ts` — BM25 search chunks
- `apps/mcp/src/search/bm25-index.ts` — Search index
- `apps/mcp/src/manifest.ts` — Topic metadata (name, description, tags, commit hash)

Cache invalidation is automatic via `MANIFEST_COMMIT` baked into KV cache keys. The KV_CACHE binding (configured in `wrangler.jsonc`) stores responses with TTLs ranging from 3600s for dynamic tools to 86400s for static content.

## Authoring and Maintaining Topics

Each topic is defined by a TypeScript file in `apps/mcp/src/knowledge/topics/` that exports a `Topic` object with these fields:

| Field           | Type                     | Required | Purpose |
|-----------------|--------------------------|----------|---------|
| `name`          | string                   | Yes      | Filename stem (e.g., "db-schema") |
| `description`   | string (≤200 chars)      | Yes      | One-line description for tool listings |
| `tags`          | string[]                 | Yes      | Closed-vocabulary tags for filtering |
| `sources`       | string[]                 | Yes      | Repo-relative paths of source files |
| `systemPrompt`  | string                   | Yes      | Always `BASE_SYSTEM` from base.ts |
| `buildPrompt`   | (sources: string) => string | Yes   | Function generating the user prompt |
| `manualFacts`   | string[]                 | No       | Curated facts with higher priority than source code |
| `staticAppend`  | string                   | No       | Verbatim Markdown appended after AI output |
| `maxSourceChars`| number                   | No       | Override per-source character budget |

**Mandatory Checklist for New Features:**

1. **New route/migration/component**:
   - Add source file path to existing topic's `sources[]` OR
   - Create new topic file with proper `sources[]`

2. **Non-obvious conventions**:
   - Add to `manualFacts[]` in relevant topic
   - Consider adding to `BASE_SYSTEM` if global

3. **DB migrations**:
   - Update `migrations-reference` topic's `sources[]`

4. **Auth0 changes**:
   - Update `auth-patterns.ts` or `jwt-user-metadata-patterns.ts`

## VS Code Installation

Configure `.vscode/mcp.json` (in `.gitignore`) for your preferred mode:

1. **HTTP mode (production)**:
```json
{
  "servers": {
    "fufuni": {
      "type": "http",
      "url": "https://fufuni-mcp.fufuni.workers.dev/mcp"
    }
  }
}
```

2. **stdio mode (local dev)**:
```json
{
  "servers": {
    "fufuni": {
      "type": "stdio",
      "command": "npm",
      "args": ["--prefix", "apps/mcp", "run", "stdio"]
    }
  }
}
```

3. **Local HTTP mode (wrangler dev)**:
```json
{
  "servers": {
    "fufuni": {
      "type": "http",
      "url": "http://localhost:8788/mcp"
    }
  }
}
```

**Claude Desktop configuration** (`~/Library/Application Support/Claude/claude_desktop_config.json`):
```json
{
  "mcpServers": {
    "fufuni": {
      "command": "npx",
      "args": ["mcp-remote", "https://fufuni-mcp.fufuni.workers.dev/mcp"]
    }
  }
}
```

After changes to `mcp.json` or Worker restarts, run **"MCP: Restart Server"** from the VS Code command palette.

## Regeneration Workflow

| Command | Provider | When to Use | Required Env Vars | Output |
|---------|----------|-------------|-------------------|--------|
| `npm run mcp:auto:flash` | Gemini | Regular updates (small topics) | `CRYPTOKEN` | Updates changed topics, runs gen-knowledge |
| `npm run mcp:auto:mistral` | Mistral | Large topics (more context) | `CRYPTOKEN` | Updates changed topics, runs gen-knowledge |
| `npm run mcp:generate` | Any | CI or single-topic testing | `AI_MODEL`, `AI_API_KEY`, `AI_API_URL` | Updates changed topics |
| `npm run mcp:generate:force` | Any | Major changes | `AI_MODEL`, `AI_API_KEY`, `AI_API_URL` | Rebuilds ALL topics |
| `npm run gen-knowledge` | N/A | Final step | None | Rebuilds knowledge.ts, chunks.ts, etc |

**Typical workflow**:
```bash
# For routine updates
cd apps/mcp
npm run mcp:auto:flash

# For large documentation changes
npm run mcp:generate -- --topic=db-schema --force --provider=gemini

# Final step after any regeneration
npm run gen-knowledge
```

Always verify changes by checking the generated Markdown in `mcp/` before deployment.
