## Development Architecture

The Fufuni MCP server is a Cloudflare Worker + Durable Object (class FufuniMCP) that exposes knowledge-base tools to AI assistants. It serves two transport modes:
1. HTTP SSE endpoint at /mcp (for remote clients)
2. stdio transport (for local development with VS Code)

The core of the server is the registerFufuniTools() function in apps/mcp/src/tools.ts. This function registers all 8 MCP tools with the McpServer instance. Each tool handler is wrapped in withKvCache() from apps/mcp/src/lib/kv-cache.ts to avoid redundant decryption and BM25 searches.

The knowledge base is a static bundle compiled at build time. These auto-generated files must never be edited manually:
- apps/mcp/src/knowledge.ts: Contains the Markdown content of all topics
- apps/mcp/src/search/chunks.ts: Contains the BM25 chunks for full-text search
- apps/mcp/src/search/bm25-index.ts: Contains the BM25 index for fast keyword search
- apps/mcp/src/manifest.ts: Contains the topic metadata (name, description, tags, commit hash)

The KV_CACHE binding in wrangler.jsonc is used for caching tool responses. The cache is automatically invalidated when the MANIFEST_COMMIT value changes, which happens on every redeploy.

## Authoring and Maintaining Topics

Each topic is defined by a TypeScript file in apps/mcp/src/knowledge/topics/ that exports a default Topic object. The Topic interface has these fields:

```typescript
export type Topic = {
  name: string;
  description: string;
  tags: string[];
  sources: string[];
  systemPrompt: string;
  buildPrompt: (sources: string) => string;
  manualFacts?: string[];
  staticAppend?: string;
  maxSourceChars?: number;
};
```

- name: The filename stem (e.g., "db-schema" for db-schema.ts)
- description: A one-sentence description of the topic (≤ 200 chars)
- tags: An array of tags (lowercase kebab-case) from the approved vocabulary
- sources: An array of paths to source files (relative to repo root) to include in the prompt
- systemPrompt: Always BASE_SYSTEM (from base.ts)
- buildPrompt: A function that takes the concatenated source text and returns the full user prompt
- manualFacts: Optional array of curated facts the LLM must treat as absolute truth
- staticAppend: Optional verbatim Markdown to append after the AI-generated content
- maxSourceChars: Optional override for the per-source character budget

Here's the complete mandatory checklist for maintaining topics:

1. When adding a new feature to Fufuni:
   - Check if an existing topic covers it → add the new source file to its sources[] array
   - If no existing topic covers it → create a new topic file
   - Add any non-obvious facts (security rules, naming conventions, gotchas) to manualFacts[]
   - Run npm run mcp:auto:flash (or mcp:auto:mistral) to regenerate only the changed topics

2. When renaming or moving a source file:
   - Update all sources[] arrays in every topic that references that path
   - The generator will fail silently if a path is wrong

3. When changing a naming convention or adding a global constraint:
   - Add it to the manualFacts[] of the most relevant topic
   - Add it to apps/mcp/src/knowledge/base.ts BASE_SYSTEM if it applies to all topics

4. When adding a new DB migration:
   - Update the migrations-reference topic sources[] to include the new SQL file
   - Run mcp:auto:flash after

5. When changing Auth0 actions, rules, or flows:
   - Update auth-patterns.ts and/or jwt-user-metadata-patterns.ts manualFacts[]

Here's a complete minimal topic file example:

```typescript
/**

 */

import { Topic, BASE_SYSTEM } from "../base.js";

const topic: Topic = {
  name: "example-topic",
  description: "Example topic for Fufuni MCP documentation",
  tags: ["example", "documentation"],
  sources: ["apps/mcp/src/example.ts"],
  systemPrompt: BASE_SYSTEM,
  buildPrompt: (sources: string) => `Write a comprehensive documentation for the following code:\n\n${sources}`,
  manualFacts: [
    "This is an example topic",
    "It demonstrates the required structure for a Fufuni MCP topic"
  ],
  staticAppend: "## Additional Resources\n\n- [Fufuni GitHub](https://github.com/sctg-development/fufuni)\n- [MCP Documentation](https://github.com/sctg-development/fufuni/tree/main/apps/mcp)",
};

export default topic;
```

## VS Code Installation

There are three installation modes for the Fufuni MCP server in VS Code:

1. HTTP mode (remote production Worker):
```json
{
  "servers": {
    "fufuni": {
      "type": "http",
      "url": "https://fufuni-mcp.fufuni.workers.dev/mcp"
    }
  }
}
```

2. stdio mode (local npm run stdio subprocess):
```json
{
  "servers": {
    "fufuni": {
      "type": "stdio",
      "command": "npm",
      "args": ["--prefix", "apps/mcp", "run", "stdio"]
    }
  }
}
```

3. Local HTTP mode (wrangler dev on port 8788):
```json
{
  "servers": {
    "fufuni": {
      "type": "http",
      "url": "http://localhost:8788/mcp"
    }
  }
}
```

For Claude Desktop, add this to ~/Library/Application Support/Claude/claude_desktop_config.json:
```json
{
  "mcpServers": {
    "fufuni": {
      "command": "npx",
      "args": ["mcp-remote", "https://fufuni-mcp.fufuni.workers.dev/mcp"]
    }
  }
}
```

After changing mcp.json or restarting the Worker, run "MCP: Restart Server" from the VS Code command palette to reconnect Copilot.

## Regeneration Workflow

Here are the regeneration commands in order of typical use:

1. npm run mcp:auto:flash
   - Provider: Gemini free tier
   - Use when: Daily development, auto-refresh mode
   - Required env vars: CRYPTOKEN
   - Writes to disk: All changed topics in mcp/

2. npm run mcp:auto:mistral
   - Provider: Mistral free tier
   - Use when: Regenerating topics with many large source files
   - Required env vars: CRYPTOKEN
   - Writes to disk: All changed topics in mcp/

3. npm run mcp:generate
   - Provider: Direct AI env vars (not encrypted config)
   - Use when: CI or single-topic regeneration
   - Required env vars: AI_MODEL, AI_API_KEY, AI_API_URL
   - Writes to disk: All changed topics in mcp/

4. npm run mcp:generate:force
   - Provider: Any (uses env vars)
   - Use when: After a major BASE_SYSTEM change or global refactor
   - Required env vars: AI_MODEL, AI_API_KEY, AI_API_URL
   - Writes to disk: All topics in mcp/

5. Single-topic regeneration:
   - Command: npm run mcp:generate -- --topic=<name> --force --provider=gemini
   - Use when: Iterating on one topic
   - Required env vars: CRYPTOKEN
   - Writes to disk: Only the specified topic in mcp/

6. Final step (always):
   - Command: cd apps/mcp && npm run gen-knowledge
   - Use when: After any manual edit to a .md file or after generate finishes
   - Required env vars: None
   - Writes to disk: knowledge.ts, bm25-index.ts, chunks.ts, manifest.ts
