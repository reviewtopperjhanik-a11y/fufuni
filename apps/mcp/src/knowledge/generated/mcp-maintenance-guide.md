## Development Architecture

The Fufuni MCP server is a Cloudflare Worker + Durable Object (class FufuniMCP) that exposes knowledge-base tools to AI assistants. It supports two transport modes: HTTP SSE (/mcp) for remote clients and stdio for local development (e.g., VS Code).

The core of the server is the registerFufuniTools() function in tools.ts, which registers all 8 tools (list_topics, get_topic, search_topics, get_manifest, retrieve_knowledge, read_source, inspect_schema, list_routes, list_migrations). Each tool handler is wrapped in withKvCache() to avoid redundant decryption and BM25 searches, using the KV_CACHE binding.

The knowledge base is a static bundle compiled at build time. The generator creates four auto-generated files:

1. knowledge.ts — Contains the Markdown content of all topics. Never edit this file directly.
2. bm25-index.ts — Holds the BM25 index for full-text search. Auto-generated from the Markdown content.
3. chunks.ts — Contains the BM25 chunks (small text segments) used for semantic search. Auto-generated from the Markdown content.
4. manifest.ts — Holds the topic metadata (name, description, tags, commit hash). Auto-generated from the topic files.

The KV_CACHE binding is used to cache tool responses. Cache keys include MANIFEST_COMMIT, which is baked into the manifest at build time. This ensures that redeploying the Worker always starts with a cold cache, as the commit hash changes with each deployment.

## Authoring and Maintaining Topics

Each topic is defined by a Topic object in apps/mcp/src/knowledge/topics/. The Topic interface has these fields:

- name: string — File stem (mcp/<name>.md). Must match the filename stem.
- description: string — One-line description shown in logs. ≤ 200 chars. Auto-generated by LLM then patched by patchTopicTs().
- tags: string[] — Curated tags for retrieval filtering. Lowercase, kebab-case, min 2. Auto-patched by patchTopicTs().
- sources: string[] — Relative paths (from repo root) of source files to include verbatim in the prompt.
- systemPrompt: string — Role / format instructions for the AI. Always BASE_SYSTEM.
- buildPrompt: (sources: string) => string — Function that receives the concatenated source text and returns the full user prompt sent to the AI.
- manualFacts?: string[] — Curated facts that the AI must incorporate into the document. Injected into the user prompt under a "## Verified facts" heading.
- staticAppend?: string — Verbatim Markdown appended AFTER the AI-generated section.
- maxSourceChars?: number — Override the per-file character budget for source truncation.

When you add a new feature to Fufuni, follow this checklist:

1. Check if an existing topic covers it → add the new source file to its sources[] array.
2. If no existing topic covers it → create a new topic file.
3. Add any non-obvious facts (security rules, naming conventions, gotchas) to manualFacts[].
4. Run npm run mcp:auto:flash (or mcp:auto:mistral) to regenerate only the changed topics.

When you rename or move a source file, update all sources[] arrays in every topic that references that path. The generator will fail silently if a path is wrong.

When you change a naming convention or add a global constraint, add it to the manualFacts[] of the most relevant topic AND to apps/mcp/src/knowledge/base.ts BASE_SYSTEM if it applies to all topics.

When you add a new DB migration, update the migrations-reference topic sources[] to include the new SQL file. Run mcp:auto:flash after.

When you add an Auth0 action, rule, or flow change, update auth-patterns.ts and/or jwt-user-metadata-patterns.ts manualFacts[].

```typescript
// Example minimal topic file: apps/mcp/src/knowledge/topics/example.ts
import { BASE_SYSTEM, appendFacts, type Topic } from "../base.js";

const topic: Topic = {

```

## VS Code Installation

There are three installation modes for the MCP server in VS Code:

1. HTTP mode — remote production Worker:
```json
{
  "servers": {
    "fufuni": {
      "type": "http",
      "url": "https://fufuni-mcp.fufuni.workers.dev/mcp"
    }
  }
}
```

2. stdio mode — local npm run stdio subprocess:
```json
{
  "servers": {
    "fufuni": {
      "type": "stdio",
      "command": "npm",
      "args": ["--prefix", "apps/mcp", "run", "stdio"]
    }
  }
}
```

3. Local HTTP mode — wrangler dev on port 8788:
```json
{
  "servers": {
    "fufuni": {
      "type": "http",
      "url": "http://localhost:8788/mcp"
    }
  }
}
```

For Claude Desktop, add this to ~/Library/Application Support/Claude/claude_desktop_config.json:
```json
{
  "mcpServers": {
    "fufuni": {
      "command": "npx",
      "args": ["mcp-remote", "https://fufuni-mcp.fufuni.workers.dev/mcp"]
    }
  }
}
```

After changing mcp.json or restarting the Worker, run "MCP: Restart Server" in the VS Code command palette to reconnect Copilot.

## Regeneration Workflow

The regeneration workflow consists of several commands, each with a specific use case:

1. npm run mcp:auto:flash — Uses Gemini free tier (round-robin across 21 keys in ai.json.enc). Flags: --auto-refresh (only regenerates topics whose source+manualFacts checksum changed), --max-token-override=30000, --no-model-fallback, --provider=gemini. Then runs gen-knowledge. Requires CRYPTOKEN env var for decrypting ai.json.enc.

2. npm run mcp:auto:mistral — Same as flash but uses Mistral free tier (6 keys). Flags: --max-token-override=99000 (larger context window). Prefer for topics with many large source files.

3. npm run mcp:generate — Dry-run-safe: skips topics that already have valid .md output. Reads AI_MODEL, AI_API_KEY, AI_API_URL from env (not ai.json.enc). Useful for CI or single-topic regeneration.

4. npm run mcp:generate:force — Forces regeneration of ALL topics regardless of existing .md files. Use after a major BASE_SYSTEM change or a global refactor.

5. cd apps/mcp && npm run gen-knowledge — Reads all .md files in mcp/ (repo root) and rebuilds knowledge.ts, bm25-index.ts, chunks.ts, manifest.ts. Run this after any manual edit to a .md file or after generate finishes.

6. Single-topic regeneration: npm run mcp:generate -- --topic=<name> --force --provider=gemini (with CRYPTOKEN set). Fastest for iterating on one topic.

Deployment is done with npm run deploy inside apps/mcp/, which runs build:sources then wrangler deploy. The MANIFEST_COMMIT value is baked in at build time and invalidates all KV cache entries automatically on every redeploy.
