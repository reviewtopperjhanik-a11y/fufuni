## Setup & Initialization Reference

### GET /v1/setup/status
Returns the initialization status of the store.

**Response:**
```typescript
{ initialized: boolean }
```

**Frontend Usage:**
The frontend setup wizard uses this endpoint to determine whether to show the setup wizard or redirect to the admin dashboard.

**Example:**
```typescript
import { hono } from '@/lib/hono';
import { z } from '@hono/zod-openapi';

const app = new OpenAPIHono<HonoEnv>();

const SetupStatusResponse = z.object({
  initialized: z.boolean(),
}).openapi('SetupStatusResponse');

const getSetupStatus = createRoute({
  method: 'get',
  path: '/v1/setup/status',
  tags: ['Setup'],
  summary: 'Check if setup is complete',
  responses: {
    200: { content: { 'application/json': { schema: SetupStatusResponse } }, description: 'Setup status' },
  },
});

app.openapi(getSetupStatus, async (c) => {
  const db = getDb(c.var.db);
  const adminExists = await db.query<{ id: string }>(`SELECT id FROM admins LIMIT 1`);
  return c.json({ initialized: adminExists.length > 0 }, 200);
});
```

### POST /v1/setup/init
Initializes the store with basic configuration and admin user.

**Request Body:**
```typescript
{
  adminEmail: string;
  storeName: string;
  defaultCurrency: string;
  defaultCountryCode: string;
}
```

**Behavior:**
- Creates the initial admin user
- Sets up store info (name, default currency, default country)
- Calls Auth0 Management API to invite the admin user
- Can only be called when no admin exists yet (returns 409 if already initialized)

**Example:**
```typescript
const SetupInitBody = z.object({
  adminEmail: z.string().email(),
  storeName: z.string().min(1),
  defaultCurrency: z.string().length(3),
  defaultCountryCode: z.string().length(2),
}).openapi('SetupInitBody');

const setupInit = createRoute({
  method: 'post',
  path: '/v1/setup/init',
  tags: ['Setup'],
  summary: 'Initialize store',
  request: {
    body: { content: { 'application/json': { schema: SetupInitBody } } },
  },
  responses: {
    200: { content: { 'application/json': { schema: OkResponse } }, description: 'Store initialized' },
    409: { content: { 'application/json': { schema: ErrorResponse } }, description: 'Already initialized' },
  },
});

app.openapi(setupInit, async (c) => {
  const { adminEmail, storeName, defaultCurrency, defaultCountryCode } = c.req.valid('json');
  const db = getDb(c.var.db);

  // Check if already initialized
  const adminExists = await db.query<{ id: string }>(`SELECT id FROM admins LIMIT 1`);
  if (adminExists.length > 0) {
    throw ApiError.conflict('Store already initialized');
  }

  // Create admin user and store config
  await db.run(
    `INSERT INTO admins (email, created_at) VALUES (?, ?)`,
    [adminEmail, now()]
  );

  // Call Auth0 Management API to invite admin
  if (process.env.AUTH0_MANAGEMENT_CLIENT_ID) {
    await inviteAuth0User(adminEmail);
  }

  return c.json({ ok: true }, 200);
});
```

### Auth0 Management API Interaction
During setup, the system interacts with Auth0 in two ways:

1. **Admin Invitation:** When `/v1/setup/init` is called, it invites the admin user via Auth0 Management API.
2. **Tenant Configuration:** If `AUTH0_MANAGEMENT_CLIENT_ID` is set and the tenant isn't configured, it automatically deploys the Auth0 configuration.

**Example Auth0 Invitation:**
```typescript
async function inviteAuth0User(email: string) {
  const response = await fetch('https://YOUR_AUTH0_DOMAIN.api.auth0.com/api/v2/users', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'Authorization': `Bearer ${process.env.AUTH0_MANAGEMENT_API_TOKEN}`,
    },
    body: JSON.stringify({
      email,
      connection: 'Username-Password-Authentication',
      password: generateRandomPassword(),
    }),
  });

  if (!response.ok) {
    throw new Error('Failed to invite admin user to Auth0');
  }
}
```

### Store Info Management
After initial setup, store information is managed separately via:

- **GET /v1/store-info** - Retrieve current store info
- **PUT /v1/store-info** - Update store info

**Example Store Info Schema:**

### Setup Wizard Frontend Flow
The frontend setup wizard (located in `apps/client/src/pages/setup/`) guides the admin through three steps:

1. **Store Configuration:**
   - Set store name
   - Select default currency
   - Choose default country

2. **Admin Invitation:**
   - Enter admin email address
   - System sends invitation via Auth0

3. **Auth0 Verification:**
   - Verify Auth0 tenant configuration
   - Confirm admin user creation

**Frontend Example:**
```typescript
// apps/client/src/pages/setup/SetupWizard.tsx
const SetupWizard = () => {
  const [step, setStep] = useState(1);
  const [formData, setFormData] = useState({
    storeName: '',
    defaultCurrency: 'USD',
    defaultCountryCode: 'US',
    adminEmail: '',
  });

  const checkSetupStatus = async () => {
    const res = await fetch('/v1/setup/status');
    const { initialized } = await res.json();
    if (initialized) navigate('/admin');
  };

  useEffect(() => {
    checkSetupStatus();
  }, []);

  const handleSubmit = async () => {
    const res = await fetch('/v1/setup/init', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify(formData),
    });
    if (res.ok) {
      // Proceed to next step or dashboard
    }
  };

  return (
    <div className="setup-wizard">
      {step === 1 && (
        <StoreConfigStep
          formData={formData}
          onChange={setFormData}
          onNext={() => setStep(2)}
        />
      )}
      {step === 2 && (
        <AdminInviteStep
          formData={formData}
          onChange={setFormData}
          onNext={() => setStep(3)}
        />
      )}
      {step === 3 && (
        <Auth0VerifyStep onComplete={handleSubmit} />
      )}
    </div>
  );
};
```

### Multiple Setup Calls
The initialization endpoint is designed to be called only once:

- **First Call:** Successfully initializes the store
- **Subsequent Calls:** Return 409 Conflict error with message "Store already initialized"

This idempotency guard prevents accidental re-initialization of an already configured store.

**Error Handling Example:**
```typescript
try {
  const response = await fetch('/v1/setup/init', {
    method: 'POST',
    body: JSON.stringify({ /* ... */ }),
  });
  if (response.status === 409) {
    // Show message that store is already initialized
  }
} catch (error) {
  // Handle other errors
}
```
