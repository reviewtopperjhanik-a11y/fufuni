## Setup Status Endpoint
The `GET /v1/setup/status` endpoint checks whether the store has been initialized. It returns a simple JSON response:

```typescript
{ initialized: boolean }
```

### Frontend Usage
The React setup wizard (`apps/client/src/pages/setup/`) polls this endpoint to determine whether to:
1. Show the setup form (if `initialized: false`)
2. Redirect to the admin dashboard (if `initialized: true`)

Example frontend check:
```typescript
// apps/client/src/pages/setup/SetupPage.tsx
const { data: status } = useQuery({
  queryKey: ['setupStatus'],
  queryFn: async () => {
    const res = await fetch('/v1/setup/status');
    return res.json() as Promise<{ initialized: boolean }>;
  },
});

if (status?.initialized) {
  return <Navigate to="/admin" replace />;
}
```

## Initial Setup Endpoint
The `POST /v1/setup/init` endpoint performs first-run initialization. It:
1. Creates the initial admin user via Auth0 Management API
2. Sets up the store's default region and currency
3. Locks itself after first successful call (409 guard)

### Required Fields
```typescript
{
  adminEmail: string;      // Admin user's email (sent to Auth0)
  storeName: string;       // Display name for the store
  defaultCurrency: string; // ISO 4217 code (e.g., "USD")
  defaultCountryCode: string; // ISO 3166-1 alpha-2 (e.g., "US")
}
```

### Idempotency Guard
The endpoint checks for existing admins before proceeding:
```typescript
// Pseudocode from the actual implementation
const adminExists = await db.query(`SELECT 1 FROM admins LIMIT 1`);
if (adminExists.length > 0) {
  throw ApiError.conflict('Store already initialized');
}
```

### Example Call
```typescript
await fetch('/v1/setup/init', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    adminEmail: 'admin@example.com',
    storeName: 'My Store',
    defaultCurrency: 'USD',
    defaultCountryCode: 'US',
  }),
});
```

## Auth0 Management API Interaction
During setup, the endpoint automatically:
1. Creates an Auth0 user with the provided email
2. Assigns the `admin` role
3. Triggers an invite email

### Auto-Deployment
If `AUTH0_MANAGEMENT_CLIENT_ID` is configured, it also:
1. Verifies the Auth0 tenant exists
2. Deploys the default rules/actions if missing
3. Creates the required API clients

## Store Info Management
After initial setup, store details are managed separately via:
- `GET /v1/store-info` - Retrieve current store info
- `PUT /v1/store-info` - Update store info (admin-only)

### Store Info Schema
```typescript
{
  name: string;
  logoUrl?: string;
  address?: {
    line1: string;
    line2?: string;
    city: string;
    postalCode: string;
    countryCode: string;
  };
  supportEmail: string;
  socialLinks?: {
    twitter?: string;
    instagram?: string;
    facebook?: string;
  };
}
```

## Setup Wizard Frontend Flow
The frontend guides admins through 3 steps:

1. **Store Configuration**
   - Collects: store name, default currency, country
   - Validates currency/country codes against supported lists

2. **Admin Invitation**
   - Collects admin email
   - Shows confirmation message about the invite email

3. **Auth0 Verification**
   - Checks if Auth0 tenant is properly configured
   - Shows success/error messages
   - Auto-redirects to dashboard on completion

## Double Setup Attempts
If `POST /v1/setup/init` is called after successful initialization:
1. Returns `409 Conflict` with message "Store already initialized"
2. Does not modify any existing data
3. Logs the attempt with IP address for security monitoring

### Recovery Procedure
To re-run setup in development:
```bash
# 1. Reset the database
curl -X POST /v1/setup/reset \
  -H "Authorization: Bearer $DATABASE_ADMIN_JWT"

# 2. Clear Auth0 users (manual step in Auth0 dashboard)
# 3. Restart the setup flow
```
