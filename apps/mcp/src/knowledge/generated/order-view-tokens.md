## Order View Tokens Reference

### Purpose
Order view tokens enable **unauthenticated**, time-limited access to a single order's invoice. They are used to:
1. Allow customers to view/download their invoice without logging in.
2. Share order details with third parties (e.g., accountants) via a secure link.

**Scope of access**:
- Only the specified order (by `orderId`).
- Read-only: invoice data (items, totals, customer address, payment last4).
- No access to other orders, user accounts, or sensitive data (full payment details, emails).

---

### Core Functions

#### `generateOrderViewToken()`
Generates a signed JWT for an order. **Always call this on the backend** (never expose the secret to the frontend).

```typescript
import { generateOrderViewToken } from '@/lib/order-token';

const token = await generateOrderViewToken(
  'd5e9c7a1-2b3f-4e8d-8c1a-5b6d7e8f9012', // orderId (UUID)
  process.env.ORDER_TOKEN_SECRET!,       // Wrangler secret
  { ttlSeconds: 3600 }                   // 1 hour (default if omitted)
);
```

**Parameters**:
| Name          | Type     | Required | Description                                  |
|---------------|----------|----------|----------------------------------------------|
| `orderId`     | `string` | Yes      | UUID of the order in the database.           |
| `secret`      | `string` | Yes      | `ORDER_TOKEN_SECRET` from Wrangler.          |
| `opts.ttlSeconds` | `number` | No       | Token lifetime in seconds (default: `3600`). |
| `opts.issuedAt`   | `Date`   | No       | Force a specific issuance time (for testing).|

**Returns**: `Promise<string>` – A signed JWT (e.g., `eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...`).

#### `verifyOrderViewToken()`
Validates a token and extracts the `orderId`. **Throws on failure** (invalid/expired/tampered).

```typescript
import { verifyOrderViewToken } from '@/lib/order-token';

try {
  const { oid: orderId } = await verifyOrderViewToken(
    'eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...', // token from URL
    'd5e9c7a1-2b3f-4e8d-8c1a-5b6d7e8f9012',   // orderId from path
    process.env.ORDER_TOKEN_SECRET!
  );
  // Token is valid for this order.
} catch (err) {
  // Token is invalid/expired/tampered.
  return new Response('Unauthorized', { status: 401 });
}
```

**Parameters**:
| Name      | Type     | Required | Description                              |
|-----------|----------|----------|------------------------------------------|
| `token`   | `string` | Yes      | Raw JWT from the URL.                    |
| `orderId` | `string` | Yes      | Expected order ID (cross-check).         |
| `secret`  | `string` | Yes      | `ORDER_TOKEN_SECRET` from Wrangler.      |

**Returns**: `Promise<{ oid: string }>` – Decoded payload (throws if invalid).

### Backend Endpoints

#### 1. `GET /v1/orders/:id/invoice` (Authenticated)
**Purpose**: Generate a token and return a public view URL for an order.
**Auth**: Requires merchant admin or order owner (via session cookie).
**Response**: `{ viewUrl: string }` (e.g., `https://merchant.example.com/order-view?token=...`).

**Example Route (Hono)**:
```typescript
// apps/merchant/src/routes/orders.ts
app.get(
  '/v1/orders/:id/invoice',
  zValidator('param', z.object({ id: z.string().uuid() })),
  async (c) => {
    const { id: orderId } = c.req.valid('param');
    const token = await generateOrderViewToken(orderId, c.env.ORDER_TOKEN_SECRET);
    const viewUrl = `${c.env.PUBLIC_MERCHANT_URL}/order-view?token=${token}`;
    return c.json({ viewUrl });
  }
);
```

---

#### 2. `GET /v1/orders/view/:token` (Public)
**Purpose**: Verify a token and return the order data for invoice rendering.
**Auth**: None (token is validated via `verifyOrderViewToken`).
**Response**: Full order object (items, totals, customer address, payment last4).

**Example Route (Hono)**:
```typescript
// apps/merchant/src/routes/public.ts
app.get(
  '/v1/orders/view/:token',
  zValidator('param', z.object({ token: z.string() })),
  async (c) => {
    const { token } = c.req.valid('param');
    const orderId = c.req.param('orderId'); // From path (e.g., /view/token?orderId=...)
    const payload = await verifyOrderViewToken(token, orderId, c.env.ORDER_TOKEN_SECRET);

    // Fetch order from Durable Object (SQLite)
    const order = await c.env.ORDERS_DO.get(payload.oid);
    if (!order) throw new Error('Order not found');

    return c.json(order);
  }
);
```

### Frontend Flow

1. **Token Generation**:
   - Merchant clicks "Share Invoice" in the dashboard (`/orders/:id`).
   - Frontend calls `GET /v1/orders/:id/invoice` → receives `{ viewUrl }`.
   - Merchant copies/pasts the `viewUrl` (e.g., to an email).

2. **Token Consumption**:
   - Customer opens `viewUrl` (e.g., `https://merchant.example.com/order-view?token=...`).
   - Frontend extracts the `token` from `URLSearchParams`:
     ```typescript
     // apps/merchant/src/routes/order-view.tsx
     const [searchParams] = useSearchParams();
     const token = searchParams.get('token');
     ```
   - Frontend calls `GET /v1/orders/view/${token}` → receives order data.
   - Renders the invoice PDF (using `@react-pdf/renderer`) and auto-downloads it.

3. **Token Discard**:
   - The token is **single-use in practice** (PDF is generated immediately).
   - No explicit revocation; tokens expire after 1 hour.

### Security Considerations

#### 1. Token Lifetime (TTL)
- **Hard limit**: 1 hour (`3600` seconds).
- **Why not extend?**:
  - Tokens grant access to **PII** (customer address, payment last4).
  - Short TTL minimizes exposure if a token is leaked (e.g., in browser history).
  - Customers should download the invoice immediately (not bookmark the link).

#### 2. Data Access
Tokens **only** grant read access to:
```sql
-- Pseudocode: Data accessible via token
SELECT
  id, created_at, status,
  customer_name, customer_address,  -- PII (redacted in logs)
  total_amount, tax_amount,
  items,                         -- Array of { product_id, quantity, price }
  payment_method_last4           -- e.g., "4242" (never full card number)
FROM orders
WHERE id = :orderId;
```

#### 3. Secret Management
- **`ORDER_TOKEN_SECRET`** must be:
  - A **Wrangler secret** (never committed to Git).
  - At least **32 characters** (random, e.g., `openssl rand -hex 32`).
  - Rotated if compromised (all existing tokens become invalid).

**Example `.dev.vars`**:
```bash
ORDER_TOKEN_SECRET="9f86d081884c7d659a2feaa0c55ad015a3bf4f1b2b0b822cd15d6c15b0f00a08"
```

#### 4. Defense in Depth
- **Hashing**: The raw token is **never stored** in the database. Only a SHA-256 hash is logged (for audit trails).
- **Rate Limiting**: The public `/v1/orders/view/:token` endpoint should be rate-limited (e.g., 5 requests/minute per IP).
- **CORS**: The public endpoint must **not** allow credentials or complex origins:
  ```typescript
  app.use('/v1/orders/view/*', cors({ origin: '*', allowMethods: ['GET'] }));
  ```

### Common Pitfalls

1. **Clock Skew**:
   - Cloudflare Workers use **monotonic clocks**. If testing locally, ensure your system time is accurate.
   - Symptoms: Tokens fail verification immediately with `"JWT expired"`.
   - Fix: Use `issuedAt` in tests to mock time:
     ```typescript
     await generateOrderViewToken(orderId, secret, {
       issuedAt: new Date('2025-01-01T00:00:00Z'),
       ttlSeconds: 3600,
     });
     ```

2. **Token Leaks**:
   - Never log raw tokens (even in `console.debug`).
   - Use `hashOrderToken()` if you must store a reference:
     ```typescript
     const hash = await hashOrderToken(token);
     console.log('Token hash (safe to log):', hash); // e.g., "a3f5..."
     ```

3. **Order ID Mismatch**:
   - Always cross-check the `orderId` from the token payload with the path/URL.
   - Attack vector: An attacker could swap the `orderId` in the URL to `/view/token?orderId=OTHER_ID`. The `verifyOrderViewToken` check prevents this.
