## Order View Tokens Reference

Order view tokens enable unauthenticated access to a single order's invoice page. They are short-lived (1 hour) signed JWTs that allow customers to view their order details without logging in.

### Token Generation and Verification

The core functions for working with order tokens:

```typescript
// Generate a new order view token
const token = await createOrderToken(orderId, ORDER_TOKEN_SECRET);

// Verify and decode a token
const payload = await verifyOrderToken(token, ORDER_TOKEN_SECRET);
```

### API Endpoints

Two endpoints handle order view tokens:

1. **Authenticated endpoint** (for generating tokens):
   ```http
   GET /v1/orders/:id/invoice
   ```
   Requires authentication (admin or order owner). Returns:
   ```typescript
   { viewUrl: string }
   ```

2. **Public endpoint** (for viewing invoices):
   ```http
   GET /v1/orders/view/:token
   ```
   No authentication required. Returns full order + items for invoice rendering.

### Frontend Flow

1. Customer receives email with invoice link containing token
2. Link directs to frontend route: `/order-view?token=...`
3. Frontend calls `GET /v1/orders/view/:token`
4. Backend verifies token and returns order data
5. Frontend renders PDF invoice and discards token

### Security Considerations

- **Token TTL**: 1 hour (do not extend)
- **Data access**: Read-only access to order details including:
  - Customer address
  - Payment method (last 4 digits only)
- **Single-use**: Tokens are designed for immediate PDF generation
- **No revocation**: Tokens expire automatically after 1 hour

### Required Configuration

Set the Wrangler secret:
```bash
wrangler secret put ORDER_TOKEN_SECRET
```

Example token generation with custom TTL:
```typescript
import { generateOrderViewToken } from './lib/order-token';

const token = await generateOrderViewToken(
  '123e4567-e89b-12d3-a456-426614174000',
  process.env.ORDER_TOKEN_SECRET,
  { ttlSeconds: 3600 } // 1 hour
);
```
