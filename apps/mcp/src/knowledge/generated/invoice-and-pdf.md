## Client-Side PDF Generation

Fufuni generates all invoices entirely on the client side using the `jsPDF` and `jsPDF-AutoTable` libraries. This approach ensures that sensitive order data is not processed by external PDF generation services and reduces server load. The core logic resides in `apps/client/src/utils/invoice-pdf.ts`.

The primary function `generateInvoice(order, storeInfo, t)` returns a `jsPDF` document instance. This allows the calling component to decide whether to trigger an immediate download or open the document in a new browser tab for previewing.

### Usage Example

```typescript
import { generateInvoice } from "@/utils/invoice-pdf";
import { useTranslation } from "react-i18next";

const InvoiceActions = ({ order, storeInfo }) => {
  const { t } = useTranslation();

  const handleDownload = () => {
    // Returns a jsPDF instance
    const doc = generateInvoice(order, storeInfo, t);
    
    // Trigger browser download
    doc.save(`invoice-${order.number}.pdf`);
  };

  const handlePreview = () => {
    const doc = generateInvoice(order, storeInfo, t);
    
    // Open in a new tab using a Blob URI
    window.open(doc.output("bloburl"), "_blank");
  };

  return (
    <div className="flex gap-2">
      <button onClick={handleDownload}>Download PDF</button>
      <button onClick={handlePreview}>Preview</button>
    </div>
  );
};
```

## Invoice Content and Layout

The invoice structure follows a strict professional layout. When adding new elements, they must be positioned relative to the `yPosition` cursor within the `generateInvoice` function to avoid overlapping content.

### Standard Sections Order
1.  **Store Header**: Displays the store logo (Base64) or store name (if logo is missing) followed by the store's physical address.
2.  **Order Metadata**: Displays the Invoice/Order number, the creation date, and the customer's email.
3.  **Customer Info**: "Bill To" and "Ship To" sections including names and addresses.
4.  **Itemized Table**: A table generated via `autoTable` containing:
    *   Product Title
    *   Quantity
    *   Unit Price (tax inclusive/exclusive based on store settings)
    *   Line Total
5.  **Totals Section**: Breakdown of Subtotal, applied discounts, shipping costs, individual tax lines, and the Grand Total.
6.  **Footer**: Displays the payment method used and a localized "Thank you" message.

### Adding a New Invoice Field
To add a new field (e.g., a VAT number or a custom order note), you must modify two main areas:
1.  **The Interface**: Update `OrderForPdf` in `apps/client/src/utils/invoice-pdf.ts`.
2.  **The Generator**: Add a `doc.text()` or `doc.splitTextToSize()` call within the `generateInvoice` function, ensuring you update the `yPosition` to prevent overlap with the items table.

```typescript
// Example: Adding a custom footer note in generateInvoice
if (order.custom_note) {
  doc.setFontSize(9);
  doc.setFont("helvetica", "italic");
  const noteLines = doc.splitTextToSize(order.custom_note, pageWidth - 28);
  doc.text(noteLines, 14, currentY);
  currentY += noteLines.length * 5;
}
```

## Currency Formatting

Fufuni treats all monetary values as integers in the smallest unit (cents) to avoid floating-point errors. The `formatCurrency` utility handles the conversion to a display string using the standard `Intl.NumberFormat` API.

### formatCurrency Signature
The function signature is: `formatCurrency(amount: number, currency: string, locale: string): string`.

```typescript
/**
 * Utility located in apps/client/src/utils/currency.ts
 * amount: value in cents (e.g., 1000 for $10.00)
 */
export function formatCurrency(
  amount: number,
  currency: string = "EUR",
  locale: string = "en-US"
): string {
  const value = amount / 100;
  
  return new Intl.NumberFormat(locale, {
    style: "currency",
    currency: currency.toUpperCase(),
    currencyDisplay: "narrowSymbol",
  }).format(value);
}

// Example results:
// formatCurrency(2999, "USD", "en-US") -> "$29.99"
// formatCurrency(2999, "EUR", "fr-FR") -> "29,99 €"
// formatCurrency(500, "JPY", "ja-JP")  -> "¥5" (Intl handles 0-decimal currencies)
```

## The Order-View Workflow

To allow customers to view and download invoices without logging into a full account (e.g., via a link in an email), Fufuni uses a signed **Order-View Token** system.

### Token Generation
Tokens are generated on the server (Cloudflare Worker) when the backend identifies an invoice request.
- **Endpoint**: `GET /v1/orders/:id/invoice` (Requires admin or owner authentication).
- **TTL**: Tokens are valid for **1 hour**.
- **Security**: The token is a signed JWT or a unique encrypted string stored in the SQLite database that grants read-only access to a specific order's data.

### Public Order-View Page
The frontend provides a dedicated public route: `/order-view/:token`. This page acts as a simplified order confirmation and invoice portal.

1.  The component reads the `:token` from the URL.
2.  It calls `GET /v1/orders/view/:token`. This specific endpoint does not require a session cookie; it validates the token instead.
3.  If valid, it returns the order details and store settings required to render the invoice.

```typescript
// apps/client/src/pages/public/OrderView.tsx (Simplified)
export const OrderView = () => {
  const { token } = useParams();
  const { data: order, isLoading } = useQuery({
    queryKey: ['public-order', token],
    queryFn: () => api.get(`/v1/orders/view/${token}`).json<OrderForPdf>()
  });

  if (isLoading) return <Spinner />;

  return (
    <div className="container mx-auto p-8">
      <h1>Order #{order.number}</h1>
      <Button 
        onPress={() => {
          const doc = generateInvoice(order, storeSettings, t);
          doc.save(`invoice-${order.number}.pdf`);
        }}
      >
        Download Invoice
      </Button>
    </div>
  );
};
```

## Internationalization (i18n)

Labels within the PDF must be translated using the same engine as the React frontend. The `generateInvoice` function accepts the `t` function from `react-i18next` as its third argument.

### Translation Keys
All translation keys used in the PDF generation are prefixed with `invoice-`. This separates invoice-specific terminology (which may be more formal) from general UI text.

```json
// apps/client/public/locales/en/common.json
{
  "invoice-bill-to": "Bill To",
  "invoice-ship-to": "Ship To",
  "invoice-date": "Date",
  "invoice-order-number": "Order Number",
  "invoice-item": "Description",
  "invoice-qty": "Qty",
  "invoice-total": "Total",
  "invoice-thank-you": "Thank you for your business!"
}
```

When rendering the PDF, use the keys as follows:
```typescript
doc.text(t("invoice-bill-to"), margin, yPosition);
```

## Store Logo and Branding

The invoice layout adapts based on the available store branding.

### Storage and Retrieval
- **Storage**: The store logo is stored as a **Base64 data URI** string in the `store_settings` table in the SQLite database.
- **Handling**: In the `generateInvoice` function, the code checks for the existence of the logo URI.
- **Fallback Behavior**:
    *   **Logo present**: The logo is rendered at the top-left using `doc.addImage()`. The text-based store name is either moved or omitted depending on the template.
    *   **Logo absent**: The PDF defaults to rendering the `store_name` as a large, bold header using standard Helvetica fonts.

```typescript
// Example logo handling in invoice-pdf.ts
if (storeInfo.logo_base64) {
  // x, y, width, height
  doc.addImage(storeInfo.logo_base64, 'PNG', 14, 10, 40, 20);
  yPosition = 35; 
} else {
  doc.setFontSize(20);
  doc.setFont("helvetica", "bold");
  doc.text(storeInfo.name, 14, 20);
  yPosition = 30;
}
```

### Constraints
Developers must ensure that Base64 logos are not excessively large (recommended < 50KB) to prevent slow generation times and large PDF file sizes, as the entire string is embedded directly into the document.
