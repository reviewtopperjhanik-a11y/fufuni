### Date Range Handling

- **Default range**: Last 30 days (`30d`).
- **Query params**:
  - `period` (enum): `7d`, `30d`, `90d`, or `all` (convenience shortcut).
  - `from`/`to` (ISO strings): Overrides `period` if both are provided.
- **SQL implementation**: Uses `datetime('now', '-N days')` for relative ranges.

```typescript
// Example: Building a safe SQL date filter
const days  = period === '7d' ? 7 : period === '30d' ? 30 : 90;
const since = days ? `datetime('now', '-${days} days')` : `'1970-01-01'`;
const query = `SELECT * FROM orders WHERE created_at >= ${since}`;
```

### Currency Handling

- **Default**: Store’s base currency (configured in `store_settings`).
- **Override**: Pass `?currency=EUR` to convert amounts.
- **Storage**: All monetary values are stored in **cents** (smallest unit) to avoid floating-point errors.
- **Conversion**: Uses `currency_rates` table if `currency` ≠ base currency.

```typescript
// Example: Currency-aware revenue query
const currency = c.req.query('currency') || 'USD';
const rate     = currency === 'USD' ? 1 :
                 await getConversionRate(currency);

const [revenue] = await db.query<{ total_cents: number }>(`
  SELECT COALESCE(SUM(total_cents * ${rate}), 0) AS total_cents
  FROM orders
  WHERE status IN ('paid', 'processing', 'shipped', 'delivered')
    AND created_at BETWEEN ${from} AND ${to}
`);
```

### Customer Metrics

- **`total`**: All-time unique customers (distinct `user_id` in `orders`).
- **`newInPeriod`**: Customers whose **first order** falls in the date range.
- **`returningRate`**:
  `(returning_orders / total_orders) * 100` where a *returning order* is any order by a customer with ≥1 prior order.

```typescript
// Example: Returning rate calculation
const [returningRate] = await db.query<{ rate: number }>(`
  WITH customer_first_order AS (
    SELECT user_id, MIN(created_at) AS first_order_at
    FROM orders
    GROUP BY user_id
  )
  SELECT
    (COUNT(*) FILTER (WHERE o.created_at > cfo.first_order_at) * 100.0 /
     NULLIF(COUNT(*), 0)) AS rate
  FROM orders o
  JOIN customer_first_order cfo ON o.user_id = cfo.user_id
  WHERE o.created_at BETWEEN ${from} AND ${to}
`);
```

### Top Products

- **Ranking**: Products sorted by **revenue** (descending), then by **units sold**.
- **Scope**: Limited to the date range (default: 10 products).
- **Frontend**: Displayed in a `<Table>` with columns: *Product*, *Units Sold*, *Revenue*.

```typescript
// Example: Top products query
const [topProducts] = await db.query<{
  product_id:    string;
  product_title: string;
  units_sold:    number;
  revenue_cents: number;
}>(
  `SELECT
     p.id           AS product_id,
     p.title        AS product_title,
     SUM(oi.quantity) AS units_sold,
     SUM(oi.total_cents) AS revenue_cents
   FROM order_items oi
   JOIN products p ON oi.product_id = p.id
   JOIN orders o ON oi.order_id = o.id
   WHERE o.status IN ('paid', 'processing', 'shipped', 'delivered')
     AND o.created_at BETWEEN ${from} AND ${to}
   GROUP BY p.id, p.title
   ORDER BY revenue_cents DESC, units_sold DESC
   LIMIT 10`
);
```

### Checkout Funnel

- **Steps**:
  1. **`cartCreated`**: A cart record is created (no items required).
  2. **`checkoutStarted`**: User views `/checkout` (tracked via `checkout_sessions`).
  3. **`checkoutCompleted`**: Order is placed (status `paid`).
- **`conversionRate`**: `(checkoutCompleted / cartCreated) * 100`.
- **Frontend**: Rendered as a horizontal `<BarChart>` with drop-off percentages.

```typescript
// Example: Funnel query
const [funnel] = await db.query<{
  cartCreated:       number;
  checkoutStarted:   number;
  checkoutCompleted: number;
}>(
  `SELECT
     (SELECT COUNT(*) FROM carts WHERE created_at BETWEEN ${from} AND ${to}) AS cartCreated,
     (SELECT COUNT(*) FROM checkout_sessions WHERE created_at BETWEEN ${from} AND ${to}) AS checkoutStarted,
     (SELECT COUNT(*) FROM orders WHERE status = 'paid' AND created_at BETWEEN ${from} AND ${to}) AS checkoutCompleted`
);
```

### Performance Notes

1. **On-demand computation**: No pre-aggregated tables. Queries run at request time.
2. **Index recommendations**:
   - `orders(created_at, status)`
   - `order_items(product_id, created_at)`
   - `products(id)` (for joins)
3. **Caching**: Frontend caches responses for 5 minutes (React Query `staleTime`).
4. **Large stores**: For >10K orders, consider:
   - Materialized views for common aggregations.
   - Partitioning `orders` by `created_at`.
