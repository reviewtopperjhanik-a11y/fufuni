## Customer Authentication Middleware

The `customerAuthMiddleware` is the entry point for all `/v1/me/*` routes. It performs two critical functions: verifying the identity of the user via an Auth0 JWT and establishing the customer identity within the local SQLite database. 

Unlike admin authentication which checks for specific API permissions, customer authentication focuses on the `sub` (subject) claim. The middleware verifies the JWT against the configured `AUTH0_DOMAIN` and `AUTH0_AUDIENCE`, then populates the Hono context with a role of `customer`.

### Middleware Implementation Example

```typescript
import { createMiddleware } from 'hono/factory';
import { ApiError, type HonoEnv } from '../types';
import { verifyAuth0Jwt } from '../lib/auth0';

export const customerAuthMiddleware = createMiddleware<HonoEnv>(
  async (c, next) => {
    const authHeader = c.req.header('Authorization');
    if (!authHeader?.startsWith('Bearer ')) {
      throw ApiError.unauthorized('Missing Authorization header');
    }

    const token = authHeader.slice(7);
    const domain = c.env.AUTH0_DOMAIN;
    const audience = c.env.AUTH0_AUDIENCE;

    try {
      const payload = await verifyAuth0Jwt(token, domain, audience);
      const sub = payload.sub as string;
      
      if (!sub) throw ApiError.unauthorized('Missing sub claim');

      // Set the auth context for downstream handlers
      c.set('auth', {
        role: 'customer',
        sub: sub,
        email: (payload.email as string) || undefined,
        permissions: []
      });

      await next();
    } catch (err) {
      throw ApiError.unauthorized('Invalid Auth0 JWT');
    }
  }
);
```

## Identity Resolution and Auto-Creation

Fufuni follows a "Just-In-Time" (JIT) provisioning pattern. The first time a customer interacts with an authenticated endpoint, the system resolves their Auth0 identity to a local `customers` table record. If no record exists for that `auth_provider_id`, a new row is created.

The `resolveCustomer` function (or `getOrCreateCustomer`) ensures that:
1. Lookup occurs primarily by `auth_provider_id` (the Auth0 `sub`).
2. Fallback lookup occurs by `email` to merge accounts if a customer existed before Auth0 was linked.
3. Profile data (email, name) stays synced with the Auth0 JWT.

### Identity Resolution Flow

```typescript
async function resolveCustomer(db: any, jwtSub: string, email?: string) {
    // 1. Try finding by Auth0 ID
    let customer = await db.query(
        `SELECT * FROM customers WHERE auth_provider_id = ? AND auth_provider = 'auth0' LIMIT 1`,
        [jwtSub]
    );

    if (customer.length > 0) return customer[0];

    // 2. Fallback to email for legacy account linking
    if (email) {
        const emailMatch = await db.query(
            `SELECT * FROM customers WHERE email = ? LIMIT 1`,
            [email.toLowerCase()]
        );
        if (emailMatch.length > 0) {
            await db.run(
                `UPDATE customers SET auth_provider = 'auth0', auth_provider_id = ? WHERE id = ?`,
                [jwtSub, emailMatch[0].id]
            );
            return { ...emailMatch[0], auth_provider_id: jwtSub };
        }
    }

    // 3. Auto-creation on first access
    const newId = crypto.randomUUID();
    await db.run(
        `INSERT INTO customers (id, email, auth_provider, auth_provider_id, created_at) 
         VALUES (?, ?, 'auth0', ?, ?)`,
        [newId, email?.toLowerCase(), jwtSub, new Date().toISOString()]
    );
    
    return { id: newId, email, auth_provider_id: jwtSub };
}
```

## Profile Management

The profile endpoints allow customers to view and manage their core identity data. These routes are defined within the `me.ts` router and are scoped to the authenticated user's ID derived from the middleware.

### GET /v1/me
Returns the profile including identity and timestamps.
- **Fields:** `id`, `email`, `name`, `created_at`, `auth_provider_id`.

### PATCH /v1/me
Updates editable customer fields.
- **Accepted Fields:** `name`, `phone`, `marketing_opt_in`.

```typescript
// PATCH /v1/me implementation pattern
adminApp.openapi(
  createRoute({
    method: 'patch',
    path: '/',
    request: {
      body: {
        content: {
          'application/json': {
            schema: z.object({
              name: z.string().optional(),
              phone: z.string().optional(),
              marketing_opt_in: z.boolean().optional(),
            }),
          },
        },
      },
    },
    responses: {
      200: { description: 'Profile updated', content: { 'application/json': { schema: CustomerSchema } } },
    },
  }),
  async (c) => {
    const db = getDb(c);
    const auth = c.get('auth');
    const body = await c.req.json();
    const customer = await resolveCustomer(db, auth.sub, auth.email);

    const updates = [];
    const params = [];
    for (const [key, value] of Object.entries(body)) {
      updates.push(`${key} = ?`);
      params.push(value);
    }
    params.push(customer.id);

    await db.run(
      `UPDATE customers SET ${updates.join(', ')}, updated_at = CURRENT_TIMESTAMP WHERE id = ?`,
      params
    );

    return c.json({ success: true });
  }
);
```

## Order History

The order history endpoint provides a read-only view of all orders placed by the customer. It uses standard pagination parameters to handle large histories.

- **Endpoint:** `GET /v1/me/orders`
- **Query Params:** `page` (default: 1), `limit` (default: 10)

### Order Retrieval Example

```typescript
adminApp.openapi(
  createRoute({
    method: 'get',
    path: '/orders',
    parameters: [
      { name: 'page', in: 'query', schema: z.string().optional() },
      { name: 'limit', in: 'query', schema: z.string().optional() }
    ],
    responses: {
      200: { description: 'Paginated order list' }
    }
  }),
  async (c) => {
    const db = getDb(c);
    const auth = c.get('auth');
    const customer = await resolveCustomer(db, auth.sub, auth.email);
    
    const page = parseInt(c.req.query('page') || '1');
    const limit = parseInt(c.req.query('limit') || '10');
    const offset = (page - 1) * limit;

    const orders = await db.query(
      `SELECT * FROM orders WHERE customer_id = ? ORDER BY created_at DESC LIMIT ? OFFSET ?`,
      [customer.id, limit, offset]
    );

    return c.json({ data: orders, page, limit });
  }
);
```

## Saved Cart and Preferences

Fufuni supports persisting the shopping cart state across devices and storing localized UI preferences.

### Saved Cart
- `GET /v1/me/saved-cart`: Retrieves the JSON representation of the persisted cart.
- `PUT /v1/me/saved-cart`: Overwrites the persisted cart with current frontend state.
- `DELETE /v1/me/saved-cart`: Clears the cart after checkout or manual reset.

### Preferences
Stores locale-specific settings to ensure a consistent experience across sessions.
- `GET /v1/me/preferences`: Returns `{ locale: "en-US", currency: "USD" }`.
- `PUT /v1/me/preferences`: Updates these fields.

```typescript

const updatePrefs = async (c) => {
  const { locale, currency } = await c.req.json();
  const db = getDb(c);
```

## Extending Account Routes

To add a new route under the `/v1/me` namespace, follow the existing pattern of using the `adminApp` instance in `me.ts` which is already wrapped in the `customerAuthMiddleware`.

### Pattern for Adding New Routes

1.  **Define the Zod Schema:** Use `zod-openapi` to define the response.
2.  **Create the Route:** Use `createRoute` from `@hono/zod-openapi`.
3.  **Resolve Customer:** Always call `resolveCustomer` inside the handler to ensure you have the correct local `customers.id`.
4.  **Scope the Query:** Ensure every SQL query uses `WHERE customer_id = ?`.

```typescript
// Example: Adding /v1/me/wishlist
const WishlistSchema = z.array(z.string());

const wishlistRoute = createRoute({
  method: 'get',
  path: '/wishlist',
  responses: {
    200: {
      description: 'Customer wishlist',
      content: { 'application/json': { schema: WishlistSchema } }
    }
  }
});

adminApp.openapi(wishlistRoute, async (c) => {
  const db = getDb(c);
  const auth = c.get('auth');
  const customer = await resolveCustomer(db, auth.sub, auth.email);

  const wishlist = await db.query(
    `SELECT product_id FROM customer_wishlists WHERE customer_id = ?`,
    [customer.id]
  );

  return c.json(wishlist.map(w => w.product_id));
});
```
