## Customer Account Patterns Reference

### Authentication Middleware

The `customerAuthMiddleware` validates Auth0-issued JWTs and resolves the customer record. It must be applied to all `/v1/me/*` routes.

Key behaviors:
- Validates Bearer token format and JWT structure
- Verifies token against Auth0 domain/audience
- Extracts `sub`, email, name, and permissions
- Sets context with `c.set('auth', { role: 'customer', sub, email, permissions })`

```typescript
// Example route using the middleware
import { customerAuthMiddleware } from '../middleware/customer-auth';

const app = new OpenAPIHono<HonoEnv>();
app.use('/v1/me/*', customerAuthMiddleware);

app.get('/v1/me', (c) => {
  const auth = c.get('auth');
  return c.json({ customerId: auth.sub });
});
```

### Customer Auto-Creation Flow

On first authenticated request, the system auto-creates a customer record using the Auth0 `sub` claim:

1. Try to find by `auth_provider_id = sub` (fastest)
2. Fallback to email lookup if provided
3. Create new record if neither exists

```typescript
// Database schema for customers table
interface CustomerRow {
  id: string; // UUID
  auth_provider: 'auth0';
  auth_provider_id: string; // Auth0 sub claim
  email: string;
  name?: string;
  phone?: string;
  marketing_opt_in: boolean;
  created_at: string; // ISO timestamp
  updated_at: string;
}
```

### Profile Endpoints

#### GET /v1/me
Returns the authenticated customer's profile.

Response:
```json
{
  "id": "cus_abc123",
  "email": "user@example.com",
  "name": "John Doe",
  "phone": "+1234567890",
  "created_at": "2023-01-01T00:00:00Z",
  "auth_provider_id": "auth0|abc123"
}
```

#### PATCH /v1/me
Updates profile fields. Only whitelisted fields are updatable.

Request:
```json
{
  "name": "Updated Name",
  "phone": "+1987654321",
  "marketing_opt_in": true
}
```

### Saved Cart

Manages persisted cart state:

```typescript
// GET /v1/me/saved-cart
app.get('/v1/me/saved-cart', async (c) => {
  const db = getDb(c);
  const auth = c.get('auth');
  const result = await db.query(
    `SELECT cart_data FROM saved_carts WHERE customer_id = ?`,
    [auth.sub]
  );
  return c.json(result[0]?.cart_data || null);
});

// PUT /v1/me/saved-cart
app.put('/v1/me/saved-cart', async (c) => {
  const db = getDb(c);
  const auth = c.get('auth');
  const { cart_data } = await c.req.json();
  await db.run(
    `INSERT OR REPLACE INTO saved_carts (customer_id, cart_data, updated_at) VALUES (?, ?, ?)`,
    [auth.sub, cart_data, now()]
  );
  return c.json({ success: true });
});
```

### Adding New Routes

To add a new customer-scoped route:

1. Apply `customerAuthMiddleware` to the router
2. Access customer via `c.get('auth')`
3. Use `getDb(c)` for database access

```typescript
// Example: New route for customer notifications
const app = new OpenAPIHono<HonoEnv>();
app.use('*', customerAuthMiddleware);

app.get('/v1/me/notifications', async (c) => {
  const db = getDb(c);
  const { sub } = c.get('auth');

  const notifications = await db.query(
    `SELECT * FROM notifications WHERE customer_id = ? ORDER BY created_at DESC`,
    [sub]
  );

  return c.json({ notifications });
});
```

All examples follow the framework's conventions for database access, context usage, and response formatting.
