## Customer Account Patterns Reference

### Authentication Middleware

The `customerAuthMiddleware` validates Auth0 JWTs and resolves the customer row from the database. It is applied to all `/v1/me/*` routes.

Key behaviors:
- Validates the `Authorization: Bearer <token>` header
- Rejects API keys (tokens starting with `pk_` or `sk_`)
- Verifies the JWT signature using Auth0's domain and audience
- Extracts the `sub` claim (Auth0 user identifier) and email
- Sets `c.get('auth')` with the resolved context

Example middleware usage:
```typescript
import { customerAuthMiddleware } from '../middleware/customer-auth';

const app = new OpenAPIHono<HonoEnv>();
app.use('/v1/me/*', customerAuthMiddleware);
```

### Auto-creation on First Access

When a customer accesses any `/v1/me/*` route for the first time, the system automatically creates a customer record:

1. The middleware extracts the Auth0 `sub` and email from the JWT
2. The route handler calls `resolveCustomer(db, jwtSub, email)`
3. If no customer exists with that `auth_provider_id`, a new row is inserted

Example customer creation flow:
```typescript
// From resolveCustomer function
if (customer.length === 0 && email) {
  const newCustomer = {
    id: uuid(),
    auth_provider: 'auth0',
    auth_provider_id: jwtSub,
    email: email.toLowerCase(),
    created_at: now(),
    updated_at: now()
  };
  await db.run(
    `INSERT INTO customers (id, auth_provider, auth_provider_id, email, created_at, updated_at) VALUES (?, ?, ?, ?, ?, ?)`,
    [newCustomer.id, newCustomer.auth_provider, newCustomer.auth_provider_id, newCustomer.email, newCustomer.created_at, newCustomer.updated_at]
  );
  return newCustomer;
}
```

### Profile Endpoints

#### GET /v1/me

Returns the authenticated customer's profile:
```typescript
app.get('/v1/me', async (c) => {
  const { db } = c.var;
  const auth = c.get('auth');
  const customer = await resolveCustomer(db, auth.sub, auth.email);
  return c.json(customer);
});
```

#### PATCH /v1/me

Updates profile fields:
```typescript
app.patch('/v1/me', zValidator('json', z.object({
  name: z.string().optional(),
  phone: z.string().optional(),
  marketing_opt_in: z.boolean().optional()
})), async (c) => {
  const { db } = c.var;
  const auth = c.get('auth');
  const customer = await resolveCustomer(db, auth.sub, auth.email);
  const data = c.req.valid('json');

  await db.run(
    `UPDATE customers SET name = ?, phone = ?, marketing_opt_in = ?, updated_at = ? WHERE id = ?`,
    [data.name, data.phone, data.marketing_opt_in, now(), customer.id]
  );

  return c.json({ success: true });
});
```

```typescript
app.post('/v1/me/addresses', zValidator('json', addressSchema), async (c) => {
```

### Order History

GET /v1/me/orders with pagination:
```typescript
app.get('/v1/me/orders', async (c) => {
  const { db } = c.var;
  const auth = c.get('auth');
  const customer = await resolveCustomer(db, auth.sub, auth.email);

  const page = Number(c.req.query('page')) || 1;
  const limit = Number(c.req.query('limit')) || 10;
  const offset = (page - 1) * limit;

  const orders = await db.query(
    `SELECT * FROM orders WHERE customer_id = ? ORDER BY created_at DESC LIMIT ? OFFSET ?`,
    [customer.id, limit, offset]
  );

  return c.json(orders);
});
```

```typescript
  const { db } = c.var;
```

```typescript
  // Resolve customer
  const customer = await resolveCustomer(db, auth.sub, auth.email);

  // Your logic here
```

3. Follow existing patterns:
- Always use `c.get('auth')` for auth context
- Resolve customer using `resolveCustomer(db, auth.sub, auth.email)`
- Use Zod validation for request bodies
- Return consistent error responses via `ApiError`
