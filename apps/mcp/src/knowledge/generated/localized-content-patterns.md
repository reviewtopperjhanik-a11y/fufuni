## Localized Content Patterns Reference

### LocalizedText Type and Storage Format

The core type for localized content is defined as:

```typescript
export type LocalizedDesc = Record<string, string>;
```

This represents a mapping from locale codes (e.g., `"en-US"`, `"fr-FR"`) to localized strings. In the database, this is stored as a JSON string in TEXT columns.

Example storage format:
```json
{
  "en-US": "<p>Product description</p>",
  "fr-FR": "<p>Description du produit</p>"
}
```

### getLocalizedText Function

The function to resolve localized content follows this signature:

```typescript
function getLocalizedText(
  raw: string,
  locale: string,
  fallbackLocale?: string
): string
```

It automatically handles both legacy plain-text values and JSON-localized content, with this fallback chain:

1. Exact locale match
2. Provided fallback locale (if any)
3. `en-US` (default fallback)
4. `fr-FR`, `es-ES`, `zh-CN`, `ar-SA`, `he-IL` (in order)

Usage example:
```typescript
import { resolveDescription } from '@/utils/description';

const description = resolveDescription(dbValue, 'fr-FR');
// Returns French version, or falls back to English, etc.
```

### renderDescription vs stripHtml

Use `renderDescription` when you need to display rich text content in HTML contexts:

```typescript
import { resolveDescription } from '@/utils/description';

// For HTML injection
const htmlContent = resolveDescription(dbValue, currentLocale);
<div dangerouslySetInnerHTML={{ __html: htmlContent }} />
```

Use `stripHtml` when you need plain text for non-HTML contexts:

```typescript
import { stripHtml } from '@/utils/description';

// For SEO meta descriptions, PDFs, etc.
const plainText = stripHtml(localizedContent);
```

### useLocalizedTextInput Hook

The hook manages localized input fields in admin forms:

```typescript
import { useLocalizedTextInput } from '@/hooks/use-localized-text-input';

const { inputValue, handleInputChange } = useLocalizedTextInput({
  value: product.title,
  onChange: (newValue) => updateProduct({ title: newValue }),
  selectedLocale: 'fr-FR',
  parseFn: parseTitle,
  mergeFn: mergeTitleLocale,
  getFn: getTitleForLocale,
});

// In your input component:
<input
  value={inputValue}
  onChange={(e) => handleInputChange(e.target.value)}
/>
```

Key features:
- Auto-migrates legacy plain text to JSON format
- Handles locale switching
- Supports AI translation (when enabled)

### Rich Text HTML Storage

Rich text descriptions are stored as HTML strings per locale within the JSON:

```json
{
  "en-US": "<p>This is <strong>HTML</strong> content</p>",
  "fr-FR": "<p>Ceci est du <em>contenu HTML</em></p>"
}
```

The backend ensures proper escaping before storage to prevent XSS.

### Adding New Locale Support

To add a new locale (e.g., `de-DE`) to an existing admin form:

1. Add the locale to the supported languages array:
```typescript
const supportedLocales = [...existingLocales, 'de-DE'];
```

2. Update the locale selector in your form component:
```tsx
<LocaleSelector
  locales={supportedLocales}
  selectedLocale={currentLocale}
  onChange={setLocale}
/>
```

3. The `useLocalizedTextInput` hook will automatically render an additional tab for the new locale. No other changes are needed - the hook handles the new locale automatically.

The system will:
- Show empty fields for the new locale initially
- Use the fallback chain when displaying content
- Persist new translations when saved
