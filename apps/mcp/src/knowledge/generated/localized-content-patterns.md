## Localized Content Patterns Reference

### 1. LocalizedText Type and Storage Format

All multi-language text in Fufuni uses the `LocalizedText` type (aliased as `LocalizedDesc` in `description.ts`):

```typescript
type LocalizedText = Record<string, string>;
// Example: { "en-US": "<p>Hello</p>", "fr-FR": "<p>Bonjour</p>" }
```

**Storage rules:**
- Stored as JSON-serialized strings in SQLite TEXT columns
- Legacy plain-text values are auto-migrated to JSON on first edit
- Empty strings are stored as `""` (not omitted keys)

**Database schema example:**
```sql
CREATE TABLE products (
  id INTEGER PRIMARY KEY,
  title TEXT NOT NULL,  -- JSON: {"en-US": "Cap", "fr-FR": "Casquette"}
  description TEXT      -- JSON: {"en-US": "<p>Cotton cap</p>", ...}
);
```

### 2. `getLocalizedText()`: Fallback Chain and Usage

Signature:
```typescript
function getLocalizedText(
  localizedText: LocalizedText | string,
  locale: string,
  fallbackLocale?: string
): string;
```

**Fallback chain:**
1. Exact locale match
2. Provided `fallbackLocale` (if any)
3. First available key in `DESCRIPTION_FALLBACK` array
4. Empty string if no match

**Usage example:**
```typescript
import { getLocalizedText } from "@/utils/description";

const product = {
  title: { "en-US": "Cap", "fr-FR": "Casquette" }
};

const displayTitle = getLocalizedText(product.title, "es-ES");
// Returns "Cap" (falls back to en-US)
```

### 3. `renderDescription()` vs `stripHtml()`

| Function          | Purpose                          | When to use                     |
|-------------------|----------------------------------|---------------------------------|
| `renderDescription()` | Returns HTML for current locale  | Product pages, rich-text display |
| `stripHtml()`     | Removes all HTML tags            | SEO meta, PDFs, plain-text APIs |

**Example usage:**
```typescript
// Product page (safe HTML rendering)
const html = renderDescription(product.description, "fr-FR");
<div dangerouslySetInnerHTML={{ __html: html }} />

// SEO meta tag (plain text only)
const plainText = stripHtml(renderDescription(product.description, "en-US"));
<meta name="description" content={plainText} />
```

### 4. `useLocalizedTextInput()` Hook

**Props:**
```typescript
interface UseLocalizedTextInputOptions {
  value: string;          // Raw DB value (JSON or legacy string)
  onChange: (v: string) => void;
  selectedLocale: string;
  parseFn: (raw: string) => LocalizedText | string;
  mergeFn: (raw: string, locale: string, text: string) => string;
  getFn: (raw: string, locale: string) => string;
}
```

**Return value:**
```typescript
{
  inputValue: string;
  isTranslating: boolean;
  canUseAi: boolean;
  isRTL: boolean;
  handleInputChange: (text: string) => void;
  handleAiTranslate: () => Promise<void>;
}
```

**Admin form usage:**
```tsx
import { useLocalizedTextInput } from "@/hooks/use-localized-text-input";
import { parseTitle, mergeTitleLocale, getTitleForLocale } from "@/utils/description";

function ProductTitleField({ value, onChange, locale }) {
  const {
    inputValue,
    isRTL,
    handleInputChange,
    handleAiTranslate
  } = useLocalizedTextInput({
    value,
    onChange,
    selectedLocale: locale,
    parseFn: parseTitle,
    mergeFn: mergeTitleLocale,
    getFn: getTitleForLocale
  });

  return (
    <div dir={isRTL ? "rtl" : "ltr"}>
      <input
        value={inputValue}
        onChange={(e) => handleInputChange(e.target.value)}
      />
      {canUseAi && (
        <button onClick={handleAiTranslate} disabled={isTranslating}>
          {isTranslating ? "Translating..." : "AI Translate"}
        </button>
      )}
    </div>
  );
}
```

### 5. Rich-Text HTML Storage

Rich text descriptions are stored as HTML strings per locale:

```typescript
const product = {
  description: {
    "en-US": "<p>Cotton <strong>cap</strong></p>",
    "fr-FR": "<p>Casquette en <strong>coton</strong></p>"
  }
};
```

**Backend safety:**
- HTML is escaped before storage
- Admin WYSIWYG editor sanitizes input
- Always use `renderDescription()` for display (never raw JSON)

### 6. Adding a New Locale to Admin Forms

1. **Add locale to constants:**
```typescript
// description.ts
export const DESCRIPTION_FALLBACK = [
  "en-US",
  "fr-FR",
  "es-ES",
  "zh-CN",
  "ar-SA",
  "he-IL",
  "de-DE"  // New locale
] as const;
```

2. **Update i18n config:**
```typescript
// i18n.ts
export const availableLanguages = [
  // ... existing languages
  { code: "de-DE", name: "German", nativeName: "Deutsch", isRTL: false }
];
```

3. **Admin form integration:**
The `useLocalizedTextInput` hook automatically handles new locales. Existing forms will:
- Show a new tab for the locale
- Auto-fallback to other languages
- Enable AI translation to the new locale

**Example migration:**
```tsx
// Before (3 locales)
const locales = ["en-US", "fr-FR", "es-ES"];

// After (4 locales)
const locales = ["en-US", "fr-FR", "es-ES", "de-DE"];
```

The hook's `isRTL` property automatically handles directionality based on the locale configuration.
