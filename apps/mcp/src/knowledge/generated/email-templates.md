## Transactional Email Reference

### 1. Mailgun Setup
Fufuni uses Mailgun's REST API for email delivery. Configure these **Wrangler secrets** in `wrangler.toml`:

```toml
[vars]
MAILGUN_API_KEY = "key-1234567890abcdef"  # Your Mailgun private API key
MAILGUN_DOMAIN = "mg.yourdomain.com"     # Your Mailgun domain
MAILGUN_BASE_URL = "https://api.mailgun.net/v3"  # Optional (default)
MAILGUN_USER = "noreply@mg.yourdomain.com"       # Default sender address
```

**Verification**:
- After deployment, test connectivity via the admin endpoint:
  ```bash
  curl -X POST "$ADMIN_URL/v1/mails/send" \
    -H "Authorization: Bearer $ADMIN_TOKEN" \
    -H "Content-Type: application/json" \
    -d '{"to":"test@example.com","subject":"Test"}'
  ```

### 2. Triggered Emails
Emails are sent automatically for these order lifecycle events:

| Event          | Trigger                          | Contents                                                                 |
|----------------|----------------------------------|--------------------------------------------------------------------------|
| `order.created`| Stripe checkout success           | Order confirmation, total, items, shipping address, tracking link       |
| `order.shipped`| Admin marks order as shipped      | Shipping notification, tracking number/URL, estimated delivery date     |
| `order.refunded`| Admin issues refund              | Refund confirmation, amount, reason (if provided)                      |

**Example trigger** (from `orders.ts`):
```typescript
// After successful Stripe payment:
await sendOrderConfirmationEmail(env, db, { orderId: order.id });
```

### 3. Template Structure
Templates in `lib/email-templates.ts` are **plain TypeScript functions** returning:
```typescript
{ subject: string; html: string; text: string }
```

**Key conventions**:
- Use `Intl.NumberFormat` for currency/date localization.
- Include both HTML and plain-text versions.
- Embed CSS in `<style>` tags (no external assets).
- Return a **complete HTML document** (with `<!DOCTYPE html>`).

**Example template**:
```typescript
export function buildOrderConfirmationEmail(params: {
  orderNumber: string;
  orderUrl: string;
  STORE_NAME: string;
  totalcents: number;
  currency: string;
}) {
  const total = new Intl.NumberFormat('en-US', {
    style: 'currency',
    currency: params.currency.toUpperCase(),
  }).format(params.totalcents / 100);

  return {
    subject: `Order Confirmation ${params.orderNumber} — ${params.STORE_NAME}`,
    text: `Your order ${params.orderNumber} (${total}) is confirmed. Track it: ${params.orderUrl}`,
    html: `<!DOCTYPE html>
      <html>
        <head><style>/* Inline styles */</style></head>
        <body>
          <h1>Order Confirmed</h1>
          <p>Total: ${total}</p>
          <a href="${params.orderUrl}">Track Order</a>
        </body>
      </html>`,
  };
}
```

### 4. Adding a New Template (4 Steps)
**Step 1**: Add the template function to `email-templates.ts`:
```typescript
export function buildRefundConfirmationEmail(params: {
  orderNumber: string;
  refundAmount: number;
  currency: string;
  reason?: string;
}) {
  return { subject: "...", html: "...", text: "..." };
}
```

**Step 2**: Create a sender function in `order-email.ts`:
```typescript
export async function sendRefundConfirmationEmail(
  env: Env,
  db: Database,
  orderId: string,
  reason?: string,
) {
  const [order] = await db.query<any>(`SELECT * FROM orders WHERE id = ?`, [orderId]);
  const email = buildRefundConfirmationEmail({
    orderNumber: order.number,
    refundAmount: order.refund_cents,
    currency: order.currency,
    reason,
  });
  await sendMailgunEmail(env, {
    to: order.customer_email,
    ...email,
  });
}
```

**Step 3**: Trigger the email in the relevant route (e.g., `orders.ts`):
```typescript
// In the refund handler:
await sendRefundConfirmationEmail(env, db, orderId, body.reason);
```

**Step 4** (Optional): Add a toggle to `order_email_settings`:
```sql
INSERT INTO order_email_settings (id, event, enabled, subject, html_body, text_body)
VALUES ('refunded', 'refunded', 1, 'Refund for Order {{orderNumber}}', '', '');
```

### 5. Admin Endpoints
| Endpoint                          | Method | Description                                                                 |
|-----------------------------------|--------|-----------------------------------------------------------------------------|
| `/v1/mails/preview/:type`         | GET    | Render template with mock data (returns HTML).                             |
| `/v1/mails/test`                  | POST   | Send a real test email. Body: `{ type: "order_confirmation" }`.             |
| `/v1/order-email-settings`       | GET    | List all email settings (one per event).                                   |
| `/v1/order-email-settings/:event`| PUT    | Update settings for an event (subject, HTML body, etc.).                   |

**Example: Preview a template**:
```bash
curl -X GET "$ADMIN_URL/v1/mails/preview/order_confirmation" \
  -H "Authorization: Bearer $ADMIN_TOKEN"
```

**Example: Send a test email**:
```bash
curl -X POST "$ADMIN_URL/v1/mails/test" \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"type":"order_confirmation"}'
```

### 6. Local Development
**Emails are silently skipped** if `MAILGUN_API_KEY` is missing. This is intentional to:
1. Avoid accidental emails during local testing.
2. Prevent errors when Mailgun credentials aren’t configured.

**Check for skipped emails** in logs:
```typescript
if (!env.MAILGUN_API_KEY) {
  console.log(`[mail] Skipped sending email (no MAILGUN_API_KEY): ${email.subject}`);
  return { success: true }; // Treat as successful
}
```

**To test locally**:
1. Set `MAILGUN_API_KEY` in `.dev.vars`.
2. Use the test endpoint:
   ```bash
   wrangler dev --local --var MAILGUN_API_KEY:mock_key
   ```
