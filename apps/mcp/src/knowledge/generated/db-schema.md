## Durable Object Pattern in Fufuni
Fufuni uses Cloudflare Durable Objects (DO) to provide a per-tenant SQLite database.
Each tenant (merchant) runs in its own Durable Object instance (`MerchantDO`).
The schema is bootstrapped and migrated **entirely in SQL** via the `SCHEMA` constant and the `ensureInitialized()` method.

1. **Schema Bootstrapping**
   `SCHEMA` contains the full DDL for all tables, indexes, and triggers.
   When the DO starts, `ensureInitialized()` executes every statement in `SCHEMA` to create or recreate tables if they do not exist.

2. **Runtime Migrations**
   After bootstrapping, `ensureInitialized()` runs a list of **inline migration objects**.
   Each migration has a unique `name` and `sql`.
   The method checks the `migrations` table (`name TEXT PRIMARY KEY, applied_at TEXT`) to avoid re-applying migrations.
   If the SQL succeeds, the migration name is inserted into `migrations`.
   If the SQL fails (e.g., column already exists), the migration is still marked as applied so the DO does not retry it.

3. **Querying the Database**
   From the Worker, use `getDb(c.var.db)` to obtain a `Database` object with two methods:
   - `query<T>(sql, params?): Promise<T[]>` – runs a SELECT and returns typed rows.
   - `run(sql, params?): Promise<{ changes }>` – runs INSERT/UPDATE/DELETE and returns the number of affected rows.

4. **Key Design Notes**
   - All SQL is executed synchronously inside the DO via `this.sql.exec()`.
   - The Worker calls the DO asynchronously via the `MERCHANT` binding.
   - There is **no** `storage.put("db_version")` pattern; migration state is **only** in the `migrations` table.
