## Image Storage Architecture

Fufuni employs a hybrid image storage strategy designed to balance database performance with delivery speed. Every image in the framework is categorized into one of three storage methods. This abstraction allows developers to handle product photos, avatars, and assets through a single interface regardless of where the bytes physically reside.

### The Three Storage Methods

1.  **Base64 (Local):** Small images (under 1MB) are converted to WebP data URIs and stored directly in the SQLite column. This eliminates extra HTTP requests for tiny icons or thumbnails and simplifies backups since the images are "in-row."
2.  **R2 (Remote):** Large images or assets requiring CDN delivery are uploaded to a Cloudflare R2 bucket. The database stores the R2 URL (typically routed through the Worker API).
3.  **External URL:** Direct references to external services (like Cloudinary or Unsplash). These are stored as-is without being mirrored to internal storage.

```typescript
import { ImageStorageMethod, detectImageMethod } from '@/utils/image-upload';

const imageUrl = "data:image/webp;base64,UklGR...";
const storageType: ImageStorageMethod = detectImageMethod(imageUrl);

if (storageType === 'base64') {
  console.log("Image is stored directly in the database row.");
} else if (storageType === 'r2') {
  console.log("Image is hosted in the Cloudflare R2 bucket.");
}
```

## Automatic Selection Logic

Fufuni automates the decision between Base64 and R2 based on the file size after WebP conversion. This ensures that the SQLite database does not bloat with large binary blobs, while small assets benefit from the zero-latency "inline" loading.

### Size Thresholds and Constants

-   **`BASE64_SIZE_LIMIT` (1MB):** The maximum size an image can be to remain a Data URI.
-   **`FILE_SIZE_LIMIT` (5MB):** The hard cap for any single image upload in the system.
-   **`forceR2`:** A flag that bypasses the size check, forcing even small files into R2 storage (useful for public assets that need heavy CDN caching).

```typescript
// Internal logic simplified from upload-image.ts
function getOptimalStorageMethod(fileSize: number, forceR2 = false): ImageStorageMethod {
  if (forceR2) return "r2";
  
  // If the file is <= 1MB, keep it in the DB as base64 to save R2 costs
  // and reduce the number of initial HTTP requests.
  return fileSize <= 1024 * 1024 ? "base64" : "r2";
}
```

## Pre-processing and WebP Conversion

Before any image is sent to storage, it undergoes mandatory client-side processing. Fufuni converts all uploaded files to the WebP format. WebP provides superior compression compared to JPEG/PNG, which is critical when storing data URIs in a SQLite database.

### Conversion Parameters

-   **Main Image:** Max width 1200px, Quality 0.8.
-   **Thumbnail:** Max width 300px, Quality 0.8 (generated automatically if requested).

Conversion is handled by `convertToWebp` within the upload pipeline to ensure consistent behavior across the admin dashboard.

```typescript
import { convertToWebp } from '@/utils/image-utils';

async function processImage(file: File) {
  // Convert original to 1200px WebP for primary storage
  const mainBlob = await convertToWebp(file, 1200, 0.8);
  
  // Convert to 300px WebP for the thumbnail field
  const thumbBlob = await convertToWebp(file, 300, 0.8);
  
  return { mainBlob, thumbBlob };
}
```

## The uploadImageFile Utility

The `uploadImageFile` function is the low-level engine for Fufuni's image handling. It coordinates validation, method selection, and the actual network request. It requires a `postForm` function, which should be retrieved from the `useSecuredApi` hook to ensure the request includes the necessary `Authorization` headers.

### Usage Example

```typescript
import { useSecuredApi } from '@/authentication';
import { uploadImageFile } from '@/utils/image-upload';
import { useConfig } from '@/hooks/use-config';

export function useAvatarUpload() {
  const { postForm } = useSecuredApi();
  const { apiBaseUrl } = useConfig();

  const handleUpload = async (file: File) => {
    try {
      const result = await uploadImageFile(
        file,
        apiBaseUrl,
        postForm,
        false // forceR2
      );
      
      console.log(`Uploaded to: ${result.url} via ${result.method}`);
      return result.url;
    } catch (err) {
      console.error("Upload failed", err);
    }
  };

  return { handleUpload };
}
```

## URL Validation and Security

Allowing users to input manual URLs (External URL method) introduces security risks like XSS via `javascript:` protocols. Fufuni utilizes `isValidImageUrl()` to guard against these vectors.

-   **Accepted Protocols:** `http:`, `https:`, and `data:image/`.
-   **Security Guard:** Always call this function before rendering a URL in an `<img>` tag or saving a manual URL input to the database.

```typescript
import { isValidImageUrl } from '@/utils/image-upload';

function handleManualEntry(input: string) {
  if (!isValidImageUrl(input)) {
    alert("Security Error: Only http, https, and data-images are allowed.");
    return;
  }
  // Safe to save or display
  saveToDatabase(input);
}
```

## Backend Integration and CDN Caching

The Fufuni backend manages the interface between the Cloudflare Worker and the R2 bucket.

### R2 Endpoints

-   **`POST /v1/images`**: Accepts `multipart/form-data`. Requires `admin:store` permission. It returns a JSON object containing the R2 `key` and the public `url`.
-   **`DELETE /v1/images/:key`**: Removes the object from the R2 bucket. 

### CDN and Cache Purging

Images served from R2 are automatically cached at Cloudflare's edge (CDN) via a KV-based cache layer in the Worker. 
When an image is deleted via the API, the backend performs two actions:
1.  Deletes the object from the R2 bucket.
2.  Purges the corresponding entry from the CDN cache.

This ensures that once an image is deleted in the admin dashboard, it is no longer accessible via its URL globally, preventing "zombie" images from lingering in the cache.

```typescript
// Illustrative logic for the DELETE /v1/images/:key backend route
async function handleDelete(key: string, env: Env) {
  // 1. Remove from physical storage
  await env.R2_BUCKET.delete(key);
  
  // 2. Clear from the Fufuni CDN cache layer
  const cacheKey = new URL(`https://fufuni-assets/v1/images/${key}`);
  const cache = caches.default;
  await cache.delete(cacheKey);
  
  return { success: true };
}
```
