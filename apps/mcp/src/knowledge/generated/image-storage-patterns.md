## Image Storage Patterns

### Storage Methods
Fufuni supports **three storage methods** for images, each with distinct use cases:

| Method   | Description                                                                 | When to Use                                                                 |
|----------|-----------------------------------------------------------------------------|-----------------------------------------------------------------------------|
| `base64` | WebP data URI stored directly in SQLite column                              | Small images (< 1 MB after conversion). No CDN needed.                     |
| `r2`     | Uploaded to Cloudflare R2 bucket via `/v1/images` endpoint                  | Large images (≥ 1 MB) or when CDN delivery is required.                   |
| `url`    | External URL (e.g., Cloudinary) stored as-is in the database                | Pre-existing images hosted elsewhere. No upload needed.                    |

---

### Automatic Storage Selection
The `uploadImageFile()` utility **automatically chooses** between `base64` and `r2` based on file size:

```typescript
// Thresholds (defined in image-upload.ts)
const BASE64_SIZE_LIMIT = 1024 * 1024; // 1MB
const FILE_SIZE_LIMIT   = 5 * 1024 * 1024; // 5MB (max upload size)
```

**Logic**:
1. If `forceR2=true`, always use R2.
2. If file size ≤ **1 MB** → `base64`.
3. If file size > **1 MB** → `r2`.
4. Reject files > **5 MB**.

**Example**:
```typescript
import { uploadImageFile } from '@/utils/image-upload';
import { useSecuredApi } from '@/authentication';

// In a React component:
const { postForm } = useSecuredApi();
const file = event.target.files[0];

// Auto-selects storage method (base64 or r2)
const result = await uploadImageFile(
  file,
  'https://api.your-store.com', // apiBaseUrl
  postForm,                     // Secured API function
  false                         // forceR2 (optional)
);

console.log(result.method); // "base64" or "r2"
```

### WebP Conversion
**All uploaded images are converted to WebP** before storage, with these parameters:
- **Max dimension**: 1200px (longest side)
- **Quality**: 0.8 (80% quality)
- **Thumbnails**: Separately generated at 300px (always stored as `base64`).

**Why WebP?**
- Smaller file sizes (~30% reduction vs. JPEG/PNG).
- Supports transparency (like PNG) and lossy/compression (like JPEG).
- Universally supported in modern browsers.

**Conversion Code** (from `image-utils.ts`):
```typescript
// Called automatically in ImageUploadInput
const webpBlob = await convertToWebp(file, 1200, 0.8);
```

### `uploadImageFile()` Signature
```typescript
async function uploadImageFile(
  file: File,                     // Image file from input
  apiBaseUrl: string,             // e.g., "https://api.your-store.com"
  postForm: PostFormFunction,     // Secured API function (from useSecuredApi())
  forceR2 = false                 // Override auto-selection to always use R2
): Promise<ImageUploadResult>     // { url, method, key? }
```

**Usage Example**:
```typescript
import { uploadImageFile } from '@/utils/image-upload';
import { useSecuredApi } from '@/authentication';

function ProductImageUploader() {
  const { postForm } = useSecuredApi();

  const handleUpload = async (e: React.ChangeEvent<HTMLInputElement>) => {
    const file = e.target.files?.[0];
    if (!file) return;

    try {
      const result = await uploadImageFile(
        file,
        import.meta.env.VITE_API_BASE_URL,
        postForm
      );
      console.log('Stored via:', result.method);
      console.log('URL:', result.url);
      if (result.key) console.log('R2 Key:', result.key);
    } catch (error) {
      console.error('Upload failed:', error);
    }
  };

  return <input type="file" onChange={handleUpload} />;
}
```

### `ImageUploadInput` Component
The **canonical admin UI** for image fields. Supports drag-and-drop (via `<input type="file">`), manual URL entry, and storage method toggling.

#### Props
| Prop                 | Type                     | Required | Description                                                                 |
|----------------------|--------------------------|----------|-----------------------------------------------------------------------------|
| `value`              | `string \| null`         | Yes      | Current image URL or `data:` URI.                                           |
| `onChange`           | `(url: string) => void` | Yes      | Called with the new URL when an image is uploaded/removed.                  |
| `onThumbnailChange`  | `(url: string) => void` | No       | Called with a 300px WebP thumbnail (always `base64`).                       |
| `apiBaseUrl`         | `string`                 | Yes      | Base URL for API endpoints (e.g., `https://api.your-store.com`).           |
| `disabled`           | `boolean`                | No       | Disables all interactions.                                                  |
| `forceR2`            | `boolean`                | No       | Forces R2 storage regardless of file size.                                  |
| `postForm`           | `PostFormFunction`       | No       | Overrides the default `useSecuredApi().postForm`.                           |

#### Complete Usage Example
```tsx
import { ImageUploadInput } from '@/components/image-upload-input';
import { useState } from 'react';

function ProductForm() {
  const [imageUrl, setImageUrl] = useState<string | null>(null);
  const [thumbnailUrl, setThumbnailUrl] = useState<string | null>(null);

  return (
    <div className="space-y-6">
      <h2>Product Image</h2>
      <ImageUploadInput
        value={imageUrl}
        onChange={setImageUrl}
        onThumbnailChange={setThumbnailUrl}
        apiBaseUrl={import.meta.env.VITE_API_BASE_URL}
        forceR2={false} // Let auto-selection choose
      />
      {thumbnailUrl && (
        <div>
          <p>Thumbnail Preview:</p>
          <img src={thumbnailUrl} alt="Thumbnail" className="w-32 h-32" />
        </div>
      )}
    </div>
  );
}
```

### `isValidImageUrl()` Security Guard
**Purpose**: Prevents XSS/malicious URLs by restricting allowed protocols.

**Accepts**:
- `http:` / `https:` (standard web URLs)
- `data:image/` (base64 data URIs)

**Rejects**:
- `javascript:` (XSS risk)
- `file:` (local file access)
- Invalid URLs (throws `TypeError`)

**Usage**:
```typescript
import { isValidImageUrl } from '@/utils/image-upload';

function SafeImage({ src }: { src: string }) {
  const safeSrc = isValidImageUrl(src) ? src : '/placeholder.png';
  return <img src={safeSrc} alt="User content" />;
}
```

**When to Call**:
- Before rendering user-provided URLs in `<img>`.
- Before storing a URL in the database (e.g., in `ImageUploadInput`).

### R2 Backend Endpoints
| Endpoint               | Method | Permission       | Description                                                                 |
|------------------------|--------|------------------|-----------------------------------------------------------------------------|
| `/v1/images`           | POST   | `admin:store`    | Uploads an image to R2. Returns `{ url, key }`.                           |
| `/v1/images/:key`      | DELETE | `admin:store`    | Deletes an R2 object **and purges its CDN cache**.                         |
| `/v1/images/purge/:key`| DELETE | `admin:store`    | **Purges CDN cache only** (keeps R2 object). Use after updating an image.  |

**Example: Upload + Delete Flow**
```typescript
// 1. Upload (POST /v1/images)
const formData = new FormData();
formData.append('file', file);
const { url, key } = await postForm('/v1/images', formData);

// 2. Delete (DELETE /v1/images/:key)
await deleteForm(`/v1/images/${key}`);
```

### CDN Caching Behavior
- **Cache Layer**: Cloudflare KV caches R2-served images (TTL: 1 year by default).
- **Cache Keys**: Derived from the R2 object key (e.g., `images/{key}.webp`).
- **Purge Triggers**:
  - **Automatic**: `DELETE /v1/images/:key` purges both R2 and CDN.
  - **Manual**: `DELETE /v1/images/purge/:key` purges CDN only (e.g., after replacing an image).

**When to Purge**:
| Scenario                     | Action                                  |
|------------------------------|-----------------------------------------|
| Image replaced with same key | Call `purge/:key` after uploading new.  |
| Image deleted permanently    | Call `DELETE /v1/images/:key`.          |
| Debugging cache issues       | Purge via Cloudflare Dashboard.          |
