## DefaultLayout vs LuxuryLayout — when to use each

Fufuni ships with two layout components that enforce consistent UI patterns across the storefront.

### DefaultLayout
- **Purpose**: Standard e-commerce storefront layout.
- **Provides**:
  - `Navbar` with logo, search, cart icon, locale switcher, and user menu
  - `CartDrawer` triggered by the cart icon
  - Responsive grid footer with links, newsletter, and social icons
  - Full-page structure with sticky footer
  - Built-in Auth0 token handling and user technical info modal
  - Theme provider integration
- **When to use**: Every regular page (`/pages/*`, `/products/*`, `/cart`, `/account/*`, etc.).
- **Constraint**: Pages rendered under `DefaultLayout` must **not** add their own `<Navbar>` or `<CartDrawer>` — they are already provided.

```tsx
// ✅ Correct — DefaultLayout wraps the page
import DefaultLayout from "@/layouts/default";
import ProductPage from "@/pages/products/[slug]";

export default function ProductPageWrapper() {
  return (
    <DefaultLayout>
      <ProductPage />
    </DefaultLayout>
  );
}
```

### LuxuryLayout
- **Purpose**: Full-bleed, immersive layout for high-end product pages or editorial content.
- **Provides**:
  - Minimal transparent header (no navbar)
  - `CartDrawer` still available
  - Full-bleed `<main>` with no horizontal padding
  - Uses `Footer` component (different from DefaultLayout's footer)
  - Theme provider and global styles
- **When to use**: Only for product landing pages, lookbooks, or brand stories where full-width imagery is required and a minimal header is preferred.
- **Constraint**: Do **not** use on checkout, account pages, or any page requiring search or navigation.

```tsx
// ✅ Correct — LuxuryLayout for immersive product page
import LuxuryLayout from "@/layouts/luxury";
import ProductShowcase from "@/pages/luxury/[slug]";

export default function ShowcaseWrapper() {
  return (
    <LuxuryLayout>
      <ProductShowcase />
    </LuxuryLayout>
  );
}
```

## StoreThemeProvider — how themes are fetched and applied

`StoreThemeProvider` is the central theme manager in Fufuni. It fetches the active theme from the backend and applies CSS variables to `:root`, enabling dynamic theming across the storefront.

### Key behaviors
- **Authenticated users**: Theme is stored in the JWT `user_metadata` and synced with the backend via `PATCH /v1/me/preferences`.
- **Unauthenticated users**: Theme is persisted in `localStorage`.
- **Cross-component sync**: Uses `THEME_UPDATED_EVENT` to notify all components (even outside the auth tree) when the theme changes.

### Theme sources
1. On mount: reads from `localStorage` (to avoid flash of unstyled content).
2. After auth: reads from JWT `user_metadata` via `getThemeFromToken()`.
3. On change: dispatches `THEME_UPDATED_EVENT` to apply the new theme globally.

### Example: applying a theme
```ts
// In theme-provider.tsx
function applyTheme(slug: string | null) {
  const root = document.documentElement;
  if (!slug || slug === "default") {
    root.removeAttribute("data-theme");
    localStorage.removeItem(THEME_LS_KEY);
  } else {
    root.setAttribute("data-theme", slug);
    localStorage.setItem(THEME_LS_KEY, slug);
  }
}
```

### Available theme slugs
```ts
export const AVAILABLE_THEMES = ["default", "luxury", "luxury-dark"] as const;
export type ThemeSlug = (typeof AVAILABLE_THEMES)[number];
```

## Adding a new CSS variable to the theme system (3 steps)

To extend the theme system with a new design token (e.g., `--color-accent`), follow these steps:

### Step 1: Add the variable to the database schema
Update the `store_themes` table in the Durable Object (SQLite) to include the new column:

```sql
-- In your DO migration (e.g., apps/backend/src/durable-objects/migrations/0001-store-themes.sql)
ALTER TABLE store_themes ADD COLUMN accent_color TEXT DEFAULT NULL;
```

### Step 2: Apply the variable in `theme-provider.tsx`
Modify `applyTheme()` to inject the new variable into `:root`:

```ts
function applyTheme(slug: string | null) {
  const root = document.documentElement;
  if (!slug || slug === "default") {
    root.removeAttribute("data-theme");
    localStorage.removeItem(THEME_LS_KEY);
  } else {
    root.setAttribute("data-theme", slug);
    localStorage.setItem(THEME_LS_KEY, slug);

    // Inject new CSS variable
    root.style.setProperty("--color-accent", "#ff6b6b");
  }
}
```

### Step 3: Use the variable in Tailwind or components
Reference the variable in your Tailwind config or component styles:

```ts
// tailwind.config.js
module.exports = {
  theme: {
    extend: {
      colors: {
        accent: "rgb(var(--color-accent) / <alpha-value>)",
      },
    },
  },
};
```

```tsx
// In a component
<button className="bg-accent text-white px-4 py-2 rounded">
  Click me
</button>
```

## ThemeSwitch vs StoreTheme — the difference

| Feature | `ThemeSwitch` (light/dark mode) | `StoreTheme` (store-scoped theme) |
|--------|-------------------------------|-----------------------------------|
| Scope | Global color mode (HeroUI) | Store-specific design tokens |
| Mechanism | Adds `class="dark"` to `<html>` | Injects CSS variables into `:root` |
| User control | Toggles between light/dark | Selects from predefined store themes |
| Persistence | `localStorage` (`theme-mode`) | JWT `user_metadata` or `localStorage` |
| Purpose | Accessibility & preference | Brand identity & store design |

### ThemeSwitch component
This is a simple UI toggle that changes the HeroUI color mode class on `<html>`. It does **not** affect store-scoped themes.

```tsx
// Example usage in Navbar
import { ThemeSwitcher } from "@/components/ui/theme-switcher";

function Navbar() {
  return (
    <header>
      <ThemeSwitcher /> {/* Toggles light/dark mode globally */}
      {/* ... */}
    </header>
  );
}
```

### StoreThemeProvider
This manages the store's design tokens (e.g., `--color-primary`, `--color-secondary`) and applies them via CSS variables. It is **independent** of the color mode toggle.

## CMS content: `cms-content.ts` structure and `siteConfig()`

`cms-content.ts` is the **static CMS data layer** for informational pages (About, Blog, Careers, etc.). It centralizes large text blocks per locale to avoid bloating i18n JSON files.

### Key types
```ts
export type CmsSection = {
  heading: string;
  body: string;
};

export type CmsPageContent = {
  title: string;
  lead: string;
  sections: CmsSection[];
};
```

### Data structure
```ts
export const CMS_CONTENT: Record<string, Record<string, CmsPageContent>> = {
  about: {
    "en-US": { title: "...", lead: "...", sections: [...] },
    "fr-FR": { title: "...", lead: "...", sections: [...] },
    // ...
  },
  blog: { /* ... */ },
  careers: { /* ... */ },
  // ...
};
```

### `getCmsPage()` helper
Fetches content for a given handle and locale, with fallback logic:

```ts
export function getCmsPage(
  handle: string,
  locale: string,
): CmsPageContent | null {
  const page = CMS_CONTENT[handle];
  if (!page) return null;

  return (
    page[locale] ??
    page[Object.keys(page).find((k) => k.startsWith(locale.split("-")[0])) ?? ""] ??
    page["en-US"] ??
    null
  );
}
```

### `siteConfig()` — dynamic CMS content
For **dynamic** CMS content (e.g., hero banners, featured categories), use `siteConfig()`:

```ts
// In apps/client/src/config/site.ts
import { getCmsPage } from "./cms-content";

export function siteConfig() {
  return {
    links: {
      twitter: "https://twitter.com/fufuni",
      discord: "https://discord.gg/fufuni",
      github: "https://github.com/sctg-development/fufuni",
    },
    hero: getCmsPage("home-hero", "en-US"),
    featuredCategories: [
      { id: "electronics", name: "Electronics", slug: "/categories/electronics" },
      { id: "fashion", name: "Fashion", slug: "/categories/fashion" },
    ],
  };
}
```
