## Theming & Layouts Reference

### Layout Components

Fufuni provides two primary layout components for different page types:

#### DefaultLayout
Use for standard e-commerce pages (product listings, cart, account pages). Includes:
- Navbar with cart icon and mobile menu
- CartDrawer component
- ThemeSwitcher
- Footer with multiple columns (company info, help links, legal)
- Container with horizontal padding and max-width

```tsx
// apps/client/src/layouts/default.tsx
export default function DefaultLayout({ children }: { children: React.ReactNode }) {
  return (
    <div className="relative flex flex-col h-screen">
      <Navbar onCartOpen={openCart} />
      <CartDrawer isOpen={isCartOpen} onClose={closeCart} />
      <main className="container mx-auto max-w-7xl px-6 grow pt-16">
        {children}
      </main>
      <footer className="w-full bg-default-50 border-t border-separator mt-auto">
        {/* Footer content */}
      </footer>
      <ThemeSwitcher />
    </div>
  );
}
```

#### LuxuryLayout
Use for premium product landing pages requiring full-bleed design:
- No navbar (uses transparent header pattern)
- Full-width main content area
- Dark-themed Footer component
- Still includes CartDrawer and ThemeSwitcher

```tsx
// apps/client/src/layouts/luxury.tsx
export default function LuxuryLayout({ children }: { children: React.ReactNode }) {
  return (
    <div className="relative flex flex-col min-h-screen">
      <Navbar onCartOpen={() => setIsCartOpen(true)} />
      <CartDrawer isOpen={isCartOpen} onClose={setIsCartOpen} />
      <main className="w-full grow pt-16">{children}</main>
      <Footer />
      <ThemeSwitcher />
    </div>
  );
}
```

### StoreThemeProvider

Manages theme application and persistence:

1. **Theme Storage**:
   - Authenticated users: Stores theme in Auth0 `user_metadata` via JWT
   - Guests: Persists in `localStorage` under `ui-theme` key

2. **Application**:
   - Sets `data-theme` attribute on `<html>` element
   - Broadcasts changes via `THEME_UPDATED_EVENT` custom event

3. **CSS Variables**:
   - Applies theme-specific variables to `:root`
   - Supported themes: `default`, `luxury`, `luxury-dark`

```tsx
// apps/client/src/providers/theme-provider.tsx
function applyTheme(slug: string | null) {
  const root = document.documentElement;
  if (!slug || slug === "default") {
    root.removeAttribute("data-theme");
  } else {
    root.setAttribute("data-theme", slug);
  }
}
```

### Adding CSS Variables

To add a new CSS variable to the theme system:

1. **Extend the database schema** (store_themes table):
```sql
ALTER TABLE store_themes ADD COLUMN new_variable VARCHAR(255);
```

2. **Update theme-provider.tsx** to apply the variable:
```tsx
// In applyTheme function
if (slug === "luxury") {
  root.style.setProperty("--color-new-variable", "value-for-luxury");
}
```

3. **Use in components** via Tailwind or CSS:
```tsx
<div className="bg-[var(--color-new-variable)]">
  Themed content
</div>
```

### ThemeSwitch vs StoreTheme

| Feature               | ThemeSwitch               | StoreThemeProvider          |
|-----------------------|---------------------------|-----------------------------|
| Purpose               | Light/dark mode toggle    | Store design system themes  |
| Implementation        | CSS class on `<html>`     | `data-theme` attribute      |
| Storage              | localStorage preference   | Auth0 metadata or localStorage |
| Affects              | HeroUI color mode         | Custom theme variables      |

```tsx
// ThemeSwitch component usage
<ThemeSwitcher />

// StoreTheme application
const { theme, setTheme } = useStoreTheme();
```

### CMS Content Structure

Content is managed via `cms-content.ts` with:

1. **Content Types**:
```typescript
type CmsSection = { heading: string; body: string };
type CmsPageContent = {
  title: string;
  lead: string;
  sections: CmsSection[];
};
```

2. **Locale Support**:
```typescript
export const CMS_CONTENT: Record<string, Record<string, CmsPageContent>> = {
  about: {
    "en-US": { /* English content */ },
    "fr-FR": { /* French content */ }
  }
};
```

3. **Content Fetching**:
```typescript
export function getCmsPage(handle: string, locale: string) {
  return CMS_CONTENT[handle][locale] ?? CMS_CONTENT[handle]["en-US"];
}
```

### Adding CMS Sections

To add new content sections:

1. **Extend CmsContent type**:
```typescript
type CmsSection = {
  heading: string;
  body: string;
  // Add new fields here
  ctaText?: string;
};
```

2. **Create admin editor** in `/admin/cms`:
```tsx
// Admin CMS editor component
function CmsEditor() {
  const [content, setContent] = useState(initialContent);
  // Add form fields for new sections
}
```

3. **API Integration**:
```typescript
// PUT to update content
await fetch(`${apiBase}/v1/cms/content`, {
  method: 'PUT',
  body: JSON.stringify(newContent)
});
```

4. **Render in components**:
```tsx
function AboutPage() {
  const content = getCmsPage("about", "en-US");
  return (
    <DefaultLayout>
      <h1>{content.title}</h1>
      {/* Render new sections */}
    </DefaultLayout>
  );
}
```

### HeroUI Color Overrides

StoreThemeProvider overrides HeroUI variables via CSS:

```css
:root {
  --color-primary: var(--hui-primary, #3b82f6);
  --color-secondary: var(--hui-secondary, #10b981);
  /* Additional overrides */
}

[data-theme="luxury"] {
  --color-primary: #8b5cf6;
  --color-secondary: #f59e0b;
}
```

The system maintains compatibility with HeroUI's color palette while allowing theme-specific overrides.
