## Core Layout Architectures

Fufuni provides two distinct layout components to handle different page requirements. These layouts act as the root wrappers for the application's view layer, managing persistent UI elements like navigation and shopping carts.

### DefaultLayout
The `DefaultLayout` is the standard e-commerce interface. It provides a structured container with horizontal padding and includes the full suite of storefront utilities.

- **Usage**: Product listings, account pages, checkout, and standard informational pages.
- **Includes**: `Navbar`, `CartDrawer`, `Footer`, `ThemeSwitcher`, and `UserTechnicalInfoModal`.
- **Constraint**: Pages rendered within this layout must not include their own Navbar to avoid duplication.

```typescript
// apps/client/src/routes/shop.tsx
import DefaultLayout from "@/layouts/default";
import ProductGrid from "@/features/products/ProductGrid";

export default function ShopPage() {
  return (
    <DefaultLayout>
      <div className="py-8">
        <h1 className="text-2xl font-bold mb-6">All Products</h1>
        <ProductGrid />
      </div>
    </DefaultLayout>
  );
}
```

### LuxuryLayout
The `LuxuryLayout` is designed for high-impact, editorial-style product landing pages. It removes the standard horizontal padding on the main container to allow for full-bleed imagery.

- **Usage**: Premium product launches, "Brand Story" pages, and hero-heavy landing pages.
- **Includes**: Minimal transparent header (via `Navbar` configuration), `CartDrawer`, and the dark-themed `Footer`.
- **Constraint**: Components inside this layout are responsible for managing their own internal `max-width` using Tailwind's `container` or `max-w-7xl` classes if centering is needed.

```typescript
// apps/client/src/routes/luxury-watch.tsx
import LuxuryLayout from "@/layouts/luxury";

export default function LuxuryWatchPage() {
  return (
    <LuxuryLayout>
      {/* Full-bleed hero section */}
      <section className="h-[90vh] bg-[url('/hero-watch.jpg')] bg-cover bg-center">
        <div className="container mx-auto h-full flex items-center">
          <h1 className="text-6xl text-white font-serif">The Zenith Collection</h1>
        </div>
      </section>
    </LuxuryLayout>
  );
}
```

## StoreThemeProvider and CSS Variables

The `StoreThemeProvider` is the engine for Fufuni’s white-labeling capabilities. It dynamically applies CSS variables to the document root based on the store's configuration.

### Theme Logic
The provider follows a strict hierarchy for theme resolution:
1. **Authenticated Users**: The theme is fetched via the `GET /v1/store-themes/active` endpoint and stored in the Auth0 `user_metadata` (synced via the JWT access token).
2. **Guest Users**: The theme is persisted in `localStorage`.
3. **Application**: The `THEME_UPDATED_EVENT` broadcasts changes across components, and the provider applies a `data-theme` attribute to the `<html>` element.

### Core CSS Variables
When a theme is active, the following variables are injected into `:root`:

| Variable | Description | Usage |
| :--- | :--- | :--- |
| `--color-primary` | The main brand color | Buttons, active states, links |
| `--color-secondary` | Accent color | Badges, secondary CTAs |
| `--color-background` | Base page color | Body background |
| `--color-separator` | Border/Line color | Dividers, card borders |

### Adding a New CSS Variable
To extend the theme system with a new variable (e.g., `--color-accent-gold`), follow these three steps:

1.  **Database & API**: Add the field to the `store_themes` table in SQLite and update the backend Zod schema to include `accent_gold`.
2.  **Provider Integration**: Update `applyTheme` in `theme-provider.tsx` to set the new property on `document.documentElement.style`.
3.  **Tailwind Configuration**: Map the variable in `tailwind.config.js`.

```typescript
// Example: Step 2 in apps/client/src/providers/theme-provider.tsx
function applyTheme(slug: string | null, customColors?: Record<string, string>) {
  const root = document.documentElement;
  
  if (customColors?.accent_gold) {
    root.style.setProperty('--color-accent-gold', customColors.accent_gold);
  }
  
  if (!slug || slug === "default") {
    root.removeAttribute("data-theme");
  } else {
    root.setAttribute("data-theme", slug);
  }
}
```

## ThemeSwitch vs. StoreTheme

It is critical to distinguish between the **HeroUI Color Mode** and the **Fufuni Store Theme**.

-   **ThemeSwitch (Light/Dark)**: This is a user-level preference. It toggles between HeroUI's `light` and `dark` classes on the `<html>` element. It affects built-in component shadows, contrast ratios, and base semantic colors.
-   **StoreTheme (Branding)**: This is a merchant-level preference. It applies the `data-theme` attribute which overrides specific color variables (like `primary`).

A user can be in "Dark Mode" (ThemeSwitch) while the store is using the "Luxury" branding (StoreTheme).

```typescript
// Overriding HeroUI defaults in apps/client/src/App.tsx
import { HeroUIProvider } from "@heroui/react";

export function App() {
  return (
    <HeroUIProvider>
      <StoreThemeProvider>
        {/* App content */}
      </StoreThemeProvider>
    </HeroUIProvider>
  );
}
```

## CMS Content Architecture

Fufuni uses a "Static-Hydrated" CMS approach. Content is defined in `cms-content.ts` for localization support but is synchronized with the backend via the `GET /v1/cms/content` endpoint.

### Structure of `cms-content.ts`
The file maps page handles (e.g., `about`, `shipping-policy`) to locale-specific objects.

```typescript
// apps/client/src/config/cms-content.ts
export const CMS_CONTENT: Record<string, Record<string, CmsPageContent>> = {
  "shipping-policy": {
    "en-US": {
      title: "Shipping & Delivery",
      lead: "We deliver globally using carbon-neutral shipping.",
      sections: [
        { heading: "Rates", body: "Calculated at checkout." }
      ]
    }
  }
};
```

### siteConfig()
The `siteConfig()` function provides global metadata used across layouts, such as social links and SEO titles.

```typescript
// apps/client/src/config/site.ts
export const siteConfig = () => ({
  name: "Fufuni Store",
  description: "High-performance edge commerce",
  links: {
    twitter: "https://twitter.com/fufuni",
    github: "https://github.com/sctg-development/fufuni",
  }

```

## Adding a New CMS Section

Adding a new content block (e.g., a "Featured Video" section on the About page) requires updating the full pipeline:

1.  **Schema Definition**: Update the `CmsPageContent` type in `cms-content.ts` to include the new field.
2.  **Admin Interface**: Add an input field in the Admin CMS dashboard (`apps/admin/src/pages/cms.tsx`) to allow merchants to edit the video URL.
3.  **Persistence**: Ensure the Admin dashboard calls `PUT /v1/cms/content` when the merchant saves.
4.  **Frontend Rendering**: Access the field in your page component.

```typescript
// Step 4: Rendering in apps/client/src/pages/about.tsx
import { CMS_CONTENT } from "@/config/cms-content";
import { useTranslation } from "react-i18next";

export function AboutPage() {
  const { i18n } = useTranslation();
  const content = CMS_CONTENT.about[i18n.language] || CMS_CONTENT.about["en-US"];

  return (
    <div>
      <h1>{content.title}</h1>
      {content.videoUrl && (
        <video src={content.videoUrl} controls className="w-full rounded-xl" />
      )}
      {content.sections.map(s => (
        <section key={s.heading}>
          <h2>{s.heading}</h2>
          <p>{s.body}</p>
        </section>
      ))}
    </div>
  );
}
```

## HeroUI Color Override Mechanism

Fufuni leverages HeroUI's CSS variable extensibility. Instead of hardcoding hex values in the Tailwind config, we map HeroUI's semantic tokens to our store's CSS variables.

When the `StoreThemeProvider` sets `--color-primary`, the following mapping occurs in the global CSS:

```css
/* apps/client/src/styles/globals.css */
@layer base {
  :root {
    /* HeroUI variable overrides */
    --heroui-primary: var(--color-primary);
    --heroui-primary-50: color-mix(in srgb, var(--color-primary), white 90%);
    --heroui-primary-900: color-mix(in srgb, var(--color-primary), black 80%);
  }

  [data-theme="luxury"] {
    --color-primary: #d4af37; /* Metallic Gold */
    --color-background: #0a0a0a;
    --color-separator: #262626;
  }
}
```

This ensures that any HeroUI component (e.g., `<Button color="primary">`) automatically inherits the merchant's brand color without manual prop drilling. Using `color-mix` allows the framework to generate the entire palette (50-900 shades) dynamically from a single primary hex value provided by the API.
