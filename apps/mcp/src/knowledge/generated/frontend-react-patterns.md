## React Router and Protected Routes

Fufuni utilizes `react-router-dom` v6 for client-side navigation. The routing architecture is centralized in `apps/client/src/app.tsx`. Routes are categorized into public routes (accessible to everyone), customer account routes (requires any authentication), and admin routes (requires specific permissions).

To protect routes, Fufuni provides two primary components:
- `AuthenticationGuard`: Wraps a component to ensure the user is logged in. If not, it triggers the login flow.
- `AuthenticationGuardWithPermission`: Ensures the user is logged in **and** possesses a specific Auth0 permission (e.g., `admin:store`).

```typescript
// apps/client/src/app.tsx (Simplified Example)
import { Route, Routes } from "react-router-dom";
import { AuthenticationGuard, AuthenticationGuardWithPermission } from "./authentication";
import IndexPage from "@/pages/index";
import ProductsPage from "@/pages/admin/products";
import AccountLayout from "@/pages/account/account-layout";

function App() {
  return (
    <Routes>
      {/* Public Route */}
      <Route element={<IndexPage />} path="/" />

      {/* Customer Route: Requires authentication */}
      <Route
        element={<AuthenticationGuard component={AccountLayout} />}
        path="/account"
      />

      {/* Admin Route: Requires specific permission */}
      <Route
        element={
          <AuthenticationGuardWithPermission permission="admin:store">
            <ProductsPage />
          </AuthenticationGuardWithPermission>
        }
        path="/admin/products"
      />
    </Routes>
  );
}
```

## Adding a New Page

Adding a page to the Fufuni framework follows a strict three-step process to ensure consistency across the UI, routing, and navigation menus.

### Step 1: Create the Page Component
Create a new file in `apps/client/src/pages/`. Use the `useSeoMeta` hook to handle page titles and Open Graph metadata dynamically.

```typescript
// apps/client/src/pages/admin/tags.tsx
import { useTranslation } from "react-i18next";
import { useSeoMeta } from "@/hooks/use-seo-meta";

const TagsPage = () => {
  const { t } = useTranslation();
  
  useSeoMeta({
    title: t("admin-tags-title"),
    description: "Manage product tags and labels",
  });

  return (
    <div className="p-6">
      <h1 className="text-2xl font-bold">{t("admin-tags-title")}</h1>
      {/* Content goes here */}
    </div>
  );
};

export default TagsPage;
```

### Step 2: Register the Route
Add the new page to the `Routes` component in `apps/client/src/app.tsx`.

```typescript
// Add to imports in app.tsx
import TagsPage from "@/pages/admin/tags";

// Add to Routes in app.tsx
<Route
  element={
    <AuthenticationGuardWithPermission permission="admin:store">
      <TagsPage />
    </AuthenticationGuardWithPermission>
  }
  path="/admin/tags"
/>
```

### Step 3: Update Site Configuration
Update `apps/client/src/config/site.ts` to include the page in the navigation menus. This controls visibility in both the desktop navbar and mobile menu.

```typescript

export const siteConfig = () => ({
  // ... other config
  navItems: [
    // ... existing items
    {
      label: i18next.t("admin-tags-title"),
      href: "/admin/tags",
      permissions: ["admin:store"], 
    },
  ],
});
```

## Permission-Based UI Logic

The `Navbar` component handles visibility dynamically. It does not just check if a user is logged in; it validates specific permissions defined in `siteConfig`.

1. **Filtering**: The navbar filters `navItems` based on the `permissions` array.
2. **Admin Dropdown**: Items with the `admin:store` permission are grouped into a dedicated admin dropdown, which itself is wrapped in an `AuthenticationGuardWithPermission`.
3. **Login Modal**: If a user is unauthenticated, a `LoginModal` is used instead of a hard redirect to maintain the current context.

```typescript
// apps/client/src/components/navbar.tsx snippet
<AuthenticationGuardWithPermission permission="admin:store">
  <li className="hidden lg:block">
    <Dropdown>
      <Dropdown.Trigger className="cursor-pointer">
        {t("nav-admin")}
      </Dropdown.Trigger>
      <Dropdown.Popover>
        <Dropdown.Menu aria-label="Admin actions">
          {siteConfig().navItems
            .filter(item => item.permissions?.includes("admin:store"))
            .map((item) => (
              <Dropdown.Item key={item.href} onPress={() => navigate(item.href)}>
                {item.label}
              </Dropdown.Item>
            ))}
        </Dropdown.Menu>
      </Dropdown.Popover>
    </Dropdown>
  </li>
</AuthenticationGuardWithPermission>
```

## HeroUI v3 Compound Component Patterns

Always import from `@heroui/react` and use the dot notation for sub-components.

```typescript

export const ProductSummary = ({ title, price }: { title: string; price: string }) => {
```

## ThemeSwitch and Global Providers

The application state is managed by a specific hierarchy of providers in `apps/client/src/provider.tsx`. The order is critical for dependency resolution (e.g., the Cart depends on Toasts).

1.  **StoreThemeProvider**: Manages the custom CSS variables fetched from the `store_themes` SQLite table.
2.  **Toast.Provider**: Enables HeroUI's imperative toast system.
3.  **CartProvider**: Logic for the shopping cart.
4.  **CartDrawerProvider**: Global state for whether the side-cart is open or closed.

```typescript
// apps/client/src/provider.tsx
import { Toast } from "@heroui/react";
import { CartProvider } from "@/hooks/use-cart";
import { CartDrawerProvider } from "@/contexts/cart-drawer-context";
import { StoreThemeProvider } from "@/providers/theme-provider";

export function Provider({ children }: { children: React.ReactNode }) {
  return (
    <StoreThemeProvider>
      <Toast.Provider />
      <CartProvider>
        <CartDrawerProvider>
          {children}
        </CartDrawerProvider>
      </CartProvider>
    </StoreThemeProvider>
  );
}
```

The `ThemeSwitch` component (found in the Navbar) allows users to toggle between system, light, and dark modes. It interacts directly with the `StoreThemeProvider` to apply theme classes to the HTML root.

## Feature Architecture and Hooks

Fufuni follows a feature-based folder structure to keep the codebase scalable.

- **`apps/client/src/features/<feature-name>/`**: Contains everything related to a specific domain (e.g., `auth`, `products`, `orders`).
    - `components/`: Local components used only by this feature.
    - `hooks/`: Hooks that encapsulate feature logic (e.g., `use-product-mutation`).
    - `index.ts`: The public API for the feature.
- **`apps/client/src/hooks/`**: Reserved for cross-cutting concerns (e.g., `use-cart`, `use-seo-meta`, `use-local-storage`).

### The `useCartDrawer` Hook
Standard components like `ProductCard` use `useCartDrawer` to provide immediate feedback after an action.

```typescript
import { useCart } from "@/hooks/use-cart";
import { useCartDrawer } from "@/contexts/cart-drawer-context";

export const AddToCartButton = ({ productId }: { productId: string }) => {
  const { addItem } = useCart();
  const { open } = useCartDrawer();

  const handleAdd = () => {
    addItem(productId);
    open(); // Auto-opens the cart drawer so the user sees the result
  };

  return <button onClick={handleAdd}>Add to Cart</button>;
};
```
