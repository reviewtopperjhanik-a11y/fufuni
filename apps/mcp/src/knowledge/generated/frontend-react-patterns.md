## React Router Setup

Routes are declared in `apps/client/src/app.tsx` using React Router v6. Public routes use plain `<Route>` components while protected routes wrap the element in authentication guards:

```typescript
// Public route
<Route element={<IndexPage />} path="/" />

// Auth-protected route
<Route
  element={<AuthenticationGuard component={CartPage} />}
  path="/cart"
/>

// Permission-protected admin route
<Route
  element={
    <AuthenticationGuardWithPermission permission={import.meta.env.ADMIN_STORE_PERMISSION}>
      <ProductsPage />
    </AuthenticationGuardWithPermission>
  }
  path="/admin/products"
/>
```

The `AuthenticationGuard` and `AuthenticationGuardWithPermission` components handle:
- Redirecting unauthenticated users to login
- Checking for specific permissions (e.g., "admin:store")
- Showing loading states during auth checks

## Adding a New Page

To add a new page to the application:

1. **Create the page component** in `apps/client/src/pages/`. Example for a new admin page:

```typescript
// apps/client/src/pages/admin/product-tags.tsx
import { useTranslation } from "react-i18next";

export function ProductTagsPage() {
  const { t } = useTranslation();
  return (
    <div className="container mx-auto py-8">
      <h1 className="text-2xl font-bold">{t("product-tags")}</h1>
      {/* Page content */}
    </div>
  );
}
```

2. **Add the route** to `apps/client/src/app.tsx`. Use appropriate guards:

```typescript
import { ProductTagsPage } from "@/pages/admin/product-tags";

// In the Routes component:
<Route
  element={
    <AuthenticationGuardWithPermission permission={import.meta.env.ADMIN_STORE_PERMISSION}>
      <ProductTagsPage />
    </AuthenticationGuardWithPermission>
  }
  path="/admin/product-tags"
/>
```

3. **Add navigation entry** (optional) to `apps/client/src/config/site.ts`:

```typescript
// In navItems array:
{
  label: i18next.t("product-tags"),
  href: "/admin/product-tags",
  permissions: ["admin:store"],
}
```

## Navbar Permission System

The navbar automatically shows/hides items based on Auth0 permissions by filtering `siteConfig().navItems`:

```typescript
// Public items (permissions: [])
{siteConfig().navItems.filter(item => !item.permissions || item.permissions.length === 0).map(item => (
  <li key={item.href}>
    <RouterLink to={item.href}>{item.label}</RouterLink>
  </li>
))}

// Admin dropdown (requires "admin:store")
<AuthenticationGuardWithPermission permission="admin:store">
  <Dropdown>
    <Dropdown.Trigger>{t("nav-admin")}</Dropdown.Trigger>
    <Dropdown.Popover>
      <Dropdown.Menu>
        {siteConfig().navItems.filter(item => item.permissions?.includes("admin:store")).map(item => (
          <Dropdown.Item key={item.href} onPress={() => navigate(item.href)}>
            {item.label}
          </Dropdown.Item>
        ))}
      </Dropdown.Menu>
    </Dropdown.Popover>
  </Dropdown>
</AuthenticationGuardWithPermission>
```

## HeroUI v3 Patterns

The application uses HeroUI v3 components with compound component syntax. Key components:


## ThemeSwitch Implementation

The `ThemeSwitch` component (imported from `@/shared/ui/navigation/theme-switch`) is pre-wired in the navbar and provides:
- Light/dark theme toggling
- Custom theme support
- Persistence via `store_themes` database table

Usage example (already included in navbar):

```typescript
import { ThemeSwitch } from "@/shared/ui/navigation/theme-switch";

// In navbar component:
<ThemeSwitch />
```

Themes are managed through `StoreThemeProvider` in `apps/client/src/provider.tsx`.

## Feature Folder Structure

Features follow this convention:
```
apps/client/src/features/
  └── <feature-name>/
      ├── components/  # Presentational components
      ├── hooks/       # Feature-specific hooks
      ├── index.ts     # Public API exports
      └── ...          # Other feature-specific files
```

Example feature structure for authentication:
```
features/auth/
  ├── components/
  │   ├── login-modal.tsx
  │   └── social-buttons.tsx
  ├── hooks/
  │   └── use-auth.ts
  └── index.ts       # Exports public API
```

New hooks should go in:
- `apps/client/src/hooks/` for page-agnostic hooks
- Feature-specific hooks in the feature's `hooks/` folder

```typescript
import { ProductTagsPage } from "@/pages/admin/product-tags";
```
