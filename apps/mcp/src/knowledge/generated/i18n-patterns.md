## Supported Locales and File Structure

Fufuni uses `i18next` along with `react-i18next` for frontend translations. The framework currently supports six locales by default. All translation files are stored as flat JSON objects within the `base` namespace.

### Locale Inventory

| Language | Code | RTL | Path |
| :--- | :--- | :--- | :--- |
| **English (Default)** | `en-US` | No | `apps/client/src/locales/base/en-US.json` |
| **French** | `fr-FR` | No | `apps/client/src/locales/base/fr-FR.json` |
| **Spanish** | `es-ES` | No | `apps/client/src/locales/base/es-ES.json` |
| **Chinese (Simplified)** | `zh-CN` | No | `apps/client/src/locales/base/zh-CN.json` |
| **Arabic** | `ar-SA` | Yes | `apps/client/src/locales/base/ar-SA.json` |
| **Hebrew** | `he-IL` | Yes | `apps/client/src/locales/base/he-IL.json` |

The `en-US.json` file serves as the **Master Language**. When developing new features, you must first define the keys in the English file before propagating them to other languages.

### The i18n Configuration

The configuration is managed in `apps/client/src/i18n.ts`. Due to how Vite handles static asset resolution with `new URL(..., import.meta.url)`, the `loadPath` for the `i18next-http-backend` must use an explicit `switch` statement rather than dynamic string interpolation to ensure the bundler correctly identifies the translation files.

```typescript
// apps/client/src/i18n.ts
import i18n from "i18next";
import { initReactI18next } from "react-i18next";
import i18nextHttpBackend, { type HttpBackendOptions } from "i18next-http-backend";

export interface AvailableLanguage {
  code: string;
  nativeName: string;
  isRTL: boolean;
  isDefault?: boolean;
}

export const availableLanguages: AvailableLanguage[] = [
  { code: "en-US", nativeName: "English", isRTL: false, isDefault: true },
  { code: "fr-FR", nativeName: "Français", isRTL: false },
  { code: "es-ES", nativeName: "Español", isRTL: false },
  { code: "zh-CN", nativeName: "中文", isRTL: false },
  { code: "ar-SA", nativeName: "العربية", isRTL: true },
  { code: "he-IL", nativeName: "עברית", isRTL: true },
];

i18n
  .use(i18nextHttpBackend)
  .use(initReactI18next)
  .init<HttpBackendOptions>({
    lng: localStorage.getItem("preferredLanguage") || "en-US",
    fallbackLng: "en-US",
    ns: ["base"],
    defaultNS: "base",
    backend: {
      loadPath: (lng, ns) => {
        // Vite requires static paths for import.meta.url resolution
        if (ns[0] === "base") {
          switch (lng[0]) {
            case "fr-FR": return new URL("./locales/base/fr-FR.json", import.meta.url).toString();
            case "es-ES": return new URL("./locales/base/es-ES.json", import.meta.url).toString();
            case "zh-CN": return new URL("./locales/base/zh-CN.json", import.meta.url).toString();
            case "ar-SA": return new URL("./locales/base/ar-SA.json", import.meta.url).toString();
            case "he-IL": return new URL("./locales/base/he-IL.json", import.meta.url).toString();
            default: return new URL("./locales/base/en-US.json", import.meta.url).toString();
          }
        }
        return new URL("./locales/base/en-US.json", import.meta.url).toString();
      },
    },
  });

export default i18n;
```

## Managing Translation Keys

Fufuni follows strict conventions for translation keys to maintain consistency across the large-scale e-commerce platform.

### Naming Conventions
- **Format**: Use `kebab-case` for keys.
- **Prefixing**: Prefix keys based on the module or page (e.g., `admin-products-`, `checkout-`, `nav-`).
- **Structure**: The JSON files must remain flat. Nested objects are discouraged as they complicate key lookups and AI-based translation scripts.

### Interpolation and Plurals
Fufuni uses double curly braces `{{}}` for variables and the `_one`, `_other` suffix for pluralization.

```json
// apps/client/src/locales/base/en-US.json
{
  "product-count_one": "{{count}} product found",
  "product-count_other": "{{count}} products found",
  "welcome-message": "Welcome back, {{name}}!",
  "delete-confirmation": "Are you sure you want to delete {{item}}?"
}
```

### Adding a Key
1. Open `apps/client/src/locales/base/en-US.json`.
2. Add your new key in alphabetical order within its group.
3. Propagate the key to other locale files (fr-FR, es-ES, etc.). If you are not fluent in the target language, use the English value as a placeholder or use the built-in AI translation tools provided in the admin dashboard.
4. **Rule**: Never use the default value parameter in the `t()` function. If a key is missing in the current language, it will automatically fallback to the `en-US` value defined in the master JSON.

## Using i18n in React Components

To access translations in your React 19 components, use the `useTranslation` hook from `react-i18next`.

### Basic Usage
The hook returns the `t` function and the `i18n` instance.

```typescript
import React from "react";
import { useTranslation } from "react-i18next";
import { Button } from "@heroui/react";

export const NewsletterSection = () => {
  const { t } = useTranslation();

  return (
    <div className="flex flex-col gap-4">
      <h3>{t("newsletter-title")}</h3>
      <p>{t("newsletter-description")}</p>
      <Button color="primary">
        {t("newsletter-subscribe-btn")}
      </Button>
    </div>
  );
};
```

### Advanced Translation Features
When dealing with numbers, dynamic names, or complex UI strings, pass an options object as the second argument to `t()`.

```typescript
import React from "react";
import { useTranslation } from "react-i18next";

interface ProductStatsProps {
  count: number;
  lastUpdatedBy: string;
}

export const ProductStats = ({ count, lastUpdatedBy }: ProductStatsProps) => {
  const { t } = useTranslation();

  return (
    <section>
      {/* Pluralization: uses product-count_one or product-count_other */}
      <p className="text-large font-bold">
        {t("product-count", { count })}
      </p>

      {/* Interpolation */}
      <span className="text-small text-default-500">
        {t("admin-products-last-edit", { name: lastUpdatedBy })}
      </span>
    </section>
  );
};
```

## Right-to-Left (RTL) Support

Fufuni handles RTL layout direction automatically. The framework detects the `isRTL` property from the `availableLanguages` array in `i18n.ts`.

### How it Works
1. When a user selects `ar-SA` or `he-IL`, the `LanguageSwitch` component updates the `dir` attribute of the `<html>` tag to `rtl`.
2. HeroUI v3 (based on Tailwind CSS) uses logical properties (e.g., `ms-4` instead of `ml-4`, `pe-2` instead of `pr-2`) to handle directional spacing.
3. The global layout uses the `isRTL` flag to flip sidebars, icons, and text alignment.

### Implementation in Layouts
If you need to manually check the direction for a specific component (like a custom chart or a complex animation), you can derive it from the current language.

```typescript
import { useTranslation } from "react-i18next";
import { availableLanguages } from "@/i18n";

export const DirectionalIcon = () => {
  const { i18n } = useTranslation();
  const currentLang = availableLanguages.find(l => l.code === i18n.language);
  const isRTL = currentLang?.isRTL ?? false;

  return (
    <div className="flex items-center">
      {/* Flip arrow icons manually if not using logical CSS */}
      <i className={`icon-arrow ${isRTL ? "rotate-180" : ""}`} />
    </div>
  );
};
```

## Worked Example: Adding "Product Tags"

In this example, we will add a feature that displays tags on a product card, including a count of how many tags are assigned.

### Step 1: Update Translation Files
Add the following keys to `apps/client/src/locales/base/en-US.json`:

```json
{
  "product-tags-label": "Product Tags",
  "product-tags-empty": "No tags assigned",
  "product-tags-count_one": "{{count}} tag",
  "product-tags-count_other": "{{count}} tags"
}
```

Add the French translations to `apps/client/src/locales/base/fr-FR.json`:

```json
{
  "product-tags-label": "Étiquettes du produit",
  "product-tags-empty": "Aucune étiquette",
  "product-tags-count_one": "{{count}} étiquette",
  "product-tags-count_other": "{{count}} étiquettes"
}
```

### Step 2: Implement the Component
Create the component using HeroUI components and the `useTranslation` hook.

```typescript
import React from "react";
import { useTranslation } from "react-i18next";
import { Chip } from "@heroui/react";

interface ProductTagsProps {
  tags: string[];
}

export const ProductTagManager: React.FC<ProductTagsProps> = ({ tags }) => {
  const { t } = useTranslation();

  return (
    <div className="p-4 border border-default-200 rounded-medium">
      <div className="flex justify-between items-center mb-2">
        <h4 className="text-small font-semibold uppercase">
          {t("product-tags-label")}
        </h4>
        <span className="text-tiny text-default-400">
          {t("product-tags-count", { count: tags.length })}
        </span>
      </div>

      <div className="flex flex-wrap gap-2">
        {tags.length > 0 ? (
          tags.map((tag) => (
            <Chip key={tag} size="sm" variant="flat">
              {tag}
            </Chip>
          ))
        ) : (
          <p className="text-small text-default-500 italic">
            {t("product-tags-empty")}
          </p>
        )}
      </div>
    </div>
  );
};
```

### Step 3: Verify the i18n Config
Ensure the `loadPath` switch case in `i18n.ts` includes all languages you intend to test. If you add a seventh language (e.g., `de-DE`), you must add a new object to `availableLanguages` and a new case in the `switch` statement within `i18n.init`.

```typescript
// Adding a new language to i18n.ts
export const availableLanguages: AvailableLanguage[] = [
  // ... existing languages
  { code: "de-DE", nativeName: "Deutsch", isRTL: false },
];

// Inside i18n.init backend.loadPath switch(lng[0])
case "de-DE":
  url = new URL("./locales/base/de-DE.json", import.meta.url);
  break;
```
