## Framework Localization Architecture

Fufuni utilizes a robust internationalization architecture based on `i18next`, `react-i18next`, and `i18next-http-backend`. The system is designed to handle static translations with high performance, supporting features like Right-to-Left (RTL) layouts, pluralization, and variable interpolation.

The core configuration resides in `apps/client/src/i18n.ts`. This file defines the supported languages, fallback logic, and a manual loader required for Vite's static asset resolution.

### Supported Locales

Fufuni currently supports six major locales. Each locale corresponds to a JSON file located in `apps/client/src/locales/base/[code].json`.

| Language | Code | RTL | JSON Path |
| :--- | :--- | :--- | :--- |
| **English (US)** | `en-US` | No | `src/locales/base/en-US.json` |
| **French (France)** | `fr-FR` | No | `src/locales/base/fr-FR.json` |
| **Spanish (Spain)** | `es-ES` | No | `src/locales/base/es-ES.json` |
| **Chinese (Simplified)** | `zh-CN` | No | `src/locales/base/zh-CN.json` |
| **Arabic (Saudi Arabia)** | `ar-SA` | Yes | `src/locales/base/ar-SA.json` |
| **Hebrew (Israel)** | `he-IL` | Yes | `src/locales/base/he-IL.json` |

The English locale (`en-US`) is treated as the **master language**. All new translation keys must be defined in `en-US.json` first. If a translation is missing in a sub-language, the framework will automatically fallback to the English string.

### The Language Configuration Interface

The `availableLanguages` array in `i18n.ts` is the source of truth for the UI (like the `LanguageSwitch` component).

```typescript
// apps/client/src/i18n.ts

export interface AvailableLanguage {
  code: string;       // ISO 639-1 language code
  nativeName: string; // How the language appears in the selector
  isRTL: boolean;     // Triggers direction: rtl in the layout
  isDefault?: boolean; // Used for fallbackLng logic
}

export const availableLanguages: AvailableLanguage[] = [
  { code: "en-US", nativeName: "English", isRTL: false, isDefault: true },
  { code: "fr-FR", nativeName: "Français", isRTL: false },
  { code: "es-ES", nativeName: "Español", isRTL: false },
  { code: "zh-CN", nativeName: "中文", isRTL: false },
  { code: "ar-SA", nativeName: "العربية", isRTL: true },
  { code: "he-IL", nativeName: "עברית", isRTL: true },
];
```

## Adding New Translation Keys

Translations in Fufuni use a **flat JSON structure** with **kebab-case** keys. This prevents nesting complexity and makes it easier for AI-assisted translation scripts to process the files.

### 1. Edit JSON Translation Files

To add a key, append it to the relevant namespace file (usually `base`). You must use double curly braces `{{variable}}` for interpolation.

```json
// apps/client/src/locales/base/en-US.json
{
  "admin-products-tags-label": "Product Tags",
  "admin-products-tags-placeholder": "Add tag...",
  "admin-products-tags-count": "This product has {{count}} tags"
}
```

### 2. Implementation Rules

- **Naming:** Always use semantic prefixes (e.g., `admin-products-`, `checkout-`, `nav-`).
- **Pluralization:** i18next uses suffixes for plurals. For English, use `_one` and `_other`.
- **Master First:** Never add a key to `fr-FR.json` without adding it to `en-US.json`.

```json
// Example of pluralization in en-US.json
{
  "items-in-cart_one": "{{count}} item in cart",
  "items-in-cart_other": "{{count}} items in cart"
}
```

**Note on Arabic Pluralization:** Unlike English, Arabic has multiple plural forms (`zero`, `one`, `two`, `few`, `many`, `other`). Ensure your JSON files reflect these suffixes when targeting RTL languages.

```json
// Example of pluralization in ar-SA.json
{
  "duration-day_zero": "{{count}} يوم",
  "duration-day_one": "يوم واحد",
  "duration-day_two": "يومان",
  "duration-day_few": "{{count}} أيام",
  "duration-day_many": "{{count}} يومًا",
  "duration-day_other": "{{count}} يوم"
}
```

## Using Translations in React Components

The `react-i18next` hook `useTranslation` is the standard way to access translation functions within functional components.

### Basic Usage

Import the hook and destructure the `t` (translate) function.

```tsx
import React from "react";
import { useTranslation } from "react-i18next";
import { Button } from "@heroui/react";

export const AddToCartButton = () => {
  // Pull t function from the 'base' namespace (default)
  const { t } = useTranslation();

  return (
    <Button color="primary">
      {t("add-to-cart")}
    </Button>
  );
};
```

### Variable Interpolation and Plurals

The `t` function accepts a second argument: an object containing variables for interpolation or a `count` property for plurals.

```tsx
import React from "react";
import { useTranslation } from "react-i18next";

interface CartStatusProps {
  itemCount: number;
  taxName: string;
}

export const CartStatus = ({ itemCount, taxName }: CartStatusProps) => {
  const { t } = useTranslation();

  return (
    <div className="flex flex-col gap-2">
      {/* Pluralization triggered by 'count' */}
      <p>{t("items-in-cart", { count: itemCount })}</p>
      
      {/* Basic interpolation */}
      <span>{t("product-card-tax-included", { name: taxName })}</span>
    </div>
  );
};
```

## Handling RTL Layouts

Fufuni automatically handles Right-to-Left (RTL) layout shifts. When a user selects Arabic or Hebrew, the `isRTL` flag in `availableLanguages` is detected.

### How RTL works in Fufuni

1.  **HTML Direction:** The root element or the main layout container typically sets `dir="rtl"` based on the current language.
2.  **Logical Properties:** The framework uses Tailwind CSS with logical properties (e.g., `ms-4` instead of `ml-4`, `pe-2` instead of `pr-2`). This ensures margins and paddings flip automatically.
3.  **HeroUI Integration:** HeroUI v3 components (Buttons, Inputs, Modals) are RTL-aware and will reposition icons and text alignment based on the `dir` attribute.

If you need to perform conditional logic in your TypeScript code for RTL:

```tsx
import { useTranslation } from "react-i18next";
import { availableLanguages } from "../i18n";

export const CustomComponent = () => {
  const { i18n } = useTranslation();
  
  // Find the language object to check if it's RTL
  const currentLang = availableLanguages.find(l => l.code === i18n.language);
  const isRTL = currentLang?.isRTL ?? false;

  return (
    <div className={isRTL ? "text-right" : "text-left"}>
      {/* ... */}
    </div>
  );
};
```

## Worked Example: Product Tags Feature

This example demonstrates adding a new "Product Tags" management feature. We will add translation keys and implement them in a React component.

### Step 1: Add Keys to `en-US.json`

```json
{
  "admin-products-tags-heading": "Product Tags",
  "admin-products-tags-placeholder": "Enter tag name (e.g. Vintage)...",
  "admin-products-tags-empty": "No tags assigned to this product.",
  "admin-products-tags-added_one": "Added {{count}} tag",
  "admin-products-tags-added_other": "Added {{count}} tags"
}
```

### Step 2: Add Keys to `fr-FR.json` (Translation)

```json
{
  "admin-products-tags-heading": "Étiquettes du produit",
  "admin-products-tags-placeholder": "Entrez le nom de l'étiquette...",
  "admin-products-tags-empty": "Aucune étiquette assignée.",
  "admin-products-tags-added_one": "{{count}} étiquette ajoutée",
  "admin-products-tags-added_other": "{{count}} étiquettes ajoutées"
}
```

### Step 3: Implement in the Component

```tsx
import React, { useState } from "react";
import { useTranslation } from "react-i18next";
import { Input, Chip, Card, CardHeader, CardBody } from "@heroui/react";

export const ProductTagManager = () => {
  const { t } = useTranslation();
  const [tags, setTags] = useState<string[]>([]);
  const [inputValue, setInputValue] = useState("");

  const handleKeyDown = (e: React.KeyboardEvent) => {
    if (e.key === "Enter" && inputValue.trim()) {
      setTags([...tags, inputValue.trim()]);
      setInputValue("");
    }
  };

  return (
    <Card className="max-w-md">
      <CardHeader className="flex flex-col items-start px-4 pt-4">
        <h4 className="text-large font-bold">
          {t("admin-products-tags-heading")}
        </h4>
        <p className="text-small text-default-500">
          {t("admin-products-tags-added", { count: tags.length })}
        </p>
      </CardHeader>
      <CardBody>
        <div className="flex flex-wrap gap-2 mb-4">
          {tags.length > 0 ? (
            tags.map((tag, idx) => (
              <Chip key={idx} variant="flat" onClose={() => setTags(tags.filter((_, i) => i !== idx))}>
                {tag}
              </Chip>
            ))
          ) : (
            <p className="text-tiny italic">{t("admin-products-tags-empty")}</p>
          )}
        </div>
        <Input
          label={t("admin-products-tags-heading")}
          placeholder={t("admin-products-tags-placeholder")}
          value={inputValue}
          onValueChange={setInputValue}
          onKeyDown={handleKeyDown}
          variant="bordered"
        />
      </CardBody>
    </Card>
  );
};
```

## Adding a New Language

Adding a language requires four distinct steps to satisfy the build system and the UI:

1.  **Define Language:** Add a new entry to `availableLanguages` in `apps/client/src/i18n.ts`.
2.  **Create JSON:** Create `apps/client/src/locales/base/[new-code].json`.
3.  **Update Loader:** Add a `case` to the `switch` statement inside the `loadPath` function in `i18n.ts`. This is critical because Vite cannot dynamically resolve URLs using variables at runtime for static assets.
4.  **Translate:** Copy keys from `en-US.json` and translate them.
