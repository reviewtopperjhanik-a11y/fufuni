## Internationalisation (i18n) Reference

Fufuni supports 6 locales out of the box:

| Locale  | Native Name       | RTL  | JSON File Location                     |
|---------|-------------------|------|----------------------------------------|
| en-US   | English           | ❌   | `src/locales/base/en-US.json`          |
| fr-FR   | Français          | ❌   | `src/locales/base/fr-FR.json`          |
| es-ES   | Español           | ❌   | `src/locales/base/es-ES.json`          |
| zh-CN   | 中文              | ❌   | `src/locales/base/zh-CN.json`          |
| ar-SA   | العربية           | ✅   | `src/locales/base/ar-SA.json`          |
| he-IL   | עברית             | ✅   | `src/locales/base/he-IL.json`          |

---

### 1. Adding a new translation key

#### a. Files to edit
1. **Master file**: `src/locales/base/en-US.json` (always start here)
2. **Target files**: `src/locales/base/{locale}.json` for each supported locale

#### b. JSON structure
- Flat key-value pairs with kebab-case keys
- Interpolation uses `{{variable}}` syntax
- Pluralization uses i18next plural suffixes (`_one`, `_other`, etc.)

```typescript
// Example structure
{
  "product-card-title": "Product: {{name}}",
  "items-count_one": "{{count}} item",
  "items-count_other": "{{count}} items"
}
```

### 2. Using translations in components

#### Basic usage
```typescript
import { useTranslation } from 'react-i18next';

function ProductCard({ name }) {
  const { t } = useTranslation('base'); // 'base' is the namespace

  return (
    <div>
      <h3>{t('product-card-title', { name })}</h3>
      <p>{t('items-count', { count: 5 })}</p>
    </div>
  );
}
```

#### Important rules
1. Always specify the namespace (`'base'` in most cases)
2. Never use the `t()` default value parameter - always add the key to `en-US.json` first
3. For pluralization, i18next automatically selects the correct form based on the `count` value

### 3. RTL language support

RTL (Right-To-Left) support is automatic for Arabic (ar-SA) and Hebrew (he-IL):

1. **Language declaration**: RTL languages are marked with `isRTL: true` in `i18n.ts`
2. **Layout direction**: The framework automatically applies RTL styles when these languages are active
3. **Component considerations**: Ensure your components use logical CSS properties (start/end instead of left/right)

```typescript
// In i18n.ts
export const availableLanguages: AvailableLanguage[] = [
  // ...
  { code: "ar-SA", nativeName: "العربية", isRTL: true },
  { code: "he-IL", nativeName: "עברית", isRTL: true },
];
```

#### Step 4: Add new language support (if needed)
To add a new language (e.g., German):

1. Add to `availableLanguages` in `i18n.ts`:
```typescript
export const availableLanguages: AvailableLanguage[] = [
  // ... existing languages
  { code: "de-DE", nativeName: "Deutsch", isRTL: false }
];
```

2. Create `src/locales/base/de-DE.json` with translations
3. Add a new case in the `loadPath` switch statement in `i18n.ts`:
```typescript
case "de-DE":
  url = new URL("./locales/base/de-DE.json", import.meta.url);
  break;
```

### 5. Best practices

1. **Key naming**: Use descriptive kebab-case keys with hierarchy
   - Good: `admin-products-modal-title`
   - Bad: `modalTitle` or `AdminProductsModalTitle`

2. **Interpolation**: Always use named variables (`{{name}}`) rather than concatenation

3. **Pluralization**: Use i18next plural forms for countable items
   ```json
   {
     "cart-items-count_zero": "Your cart is empty",
     "cart-items-count_one": "{{count}} item in cart",
     "cart-items-count_other": "{{count}} items in cart"
   }
   ```

4. **RTL considerations**:
   - Test RTL layouts thoroughly
   - Use logical CSS properties (`margin-inline-start` instead of `margin-left`)
   - Ensure icons and directional elements flip appropriately

5. **Fallbacks**: English (en-US) is the default fallback language - always keep it complete

6. **Testing**: Verify all translations appear correctly in both LTR and RTL layouts
