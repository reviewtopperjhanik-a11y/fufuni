## Building the Fufuni MCP Server

Remote Model‑Context Protocol (MCP) servers let large‑language‑model (LLM) tools run in the cloud and respond to requests from local AI clients (Claude Desktop, VS Code Copilot, etc.).  
By hosting a MCP server on Cloudflare Workers you get:

* **Zero‑cost scalability** – the free Workers tier gives you instant, global edge execution.
* **Low latency** – the server sits on the same edge network that hosts your site.
* **Secure file access** – the static knowledge‑base stays on the server and is never exposed to the client.
* **Fast iterations** – tools are refreshed only when you redeploy, not on every request.

Below is a complete, step‑by‑step recipe for turning the `mcp/` folder into a remote MCP server.

---

### 1. Worker Entry File (`index.ts`)

```ts
// ──────────────────────────────────────────────────────────────────────
// index.ts
// ──────────────────────────────────────────────────────────────────────

import { McpServer, McpTool } from "@cloudflare/agents";
import { readdirSync, readFileSync } from "fs";
import path from "path";

// Bind the KV namespace (configured in wrangler.jsonc)
declare const MCP_KV: KVNamespace;

// Helper: read a file and cache it in KV
async function getFileContent(filePath: string): Promise<string> {
  const key = path.basename(filePath);
  // Try KV first
  let content = await MCP_KV.get(key);
  if (!content) {
    // Load from disk (only on first invocation / deploy)
    content = readFileSync(filePath, "utf8");
    await MCP_KV.put(key, content);
  }
  return content;
}

// Load all Markdown files in `mcp/`
const tools: McpTool[] = [];
const markdownFiles = readdirSync("mcp").filter((f) => f.endsWith(".md"));

for (const file of markdownFiles) {
  const fullPath = path.join("mcp", file);
  // The tool name is the filename without extension
  const toolName = file.replace(/\.md$/, "");

  // The description is the first H1 line (e.g. "# Getting started")
  const fileRaw = readFileSync(fullPath, "utf8");
  const descriptionMatch = fileRaw.match(/^#\s+(.+)/m);
  const description = descriptionMatch ? descriptionMatch[1] : "";

  // The response is the whole file content
  const response = fileRaw;

  tools.push({
    name: toolName,
    description,
    response,
  });
}

// Create the MCP server
const server = new McpServer();

// Register all tools
for (const tool of tools) {
  server.addTool(tool);
}

// Cloudflare Workers fetch handler
addEventListener("fetch", (event) => {
  event.respondWith(server.handleRequest(event.request));
});
```

**Key points**

* The first `#` line of each file becomes the tool’s description.
* File content is cached in KV (`MCP_KV`) so subsequent requests read from KV instead of disk.
* `McpServer` automatically exposes the `/mcp` (HTTP) and `/sse` (SSE) endpoints.

### 2. `wrangler.jsonc` Configuration

```jsonc
// ──────────────────────────────────────────────────────────────────────
// wrangler.jsonc
// ──────────────────────────────────────────────────────────────────────
{
  "name": "fufuni-mcp",
  "compatibility_date": "2024-03-01",
  "compatibility_flags": ["nodejs_compat"],
  "routes": [
    {
      "pattern": "mcp.yourdomain.com/mcp",
      "script": "fufuni-mcp"
    },
    {
      "pattern": "mcp.yourdomain.com/sse",
      "script": "fufuni-mcp"
    }
  ],
  "kv_namespaces": [
    {
      "binding": "MCP_KV",
      "id": "xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"   // <-- replace with your KV ID
    }
  ],
  "node_modules": ["@cloudflare/agents"]
}
```

* **Routes** – both `/mcp` and `/sse` are served by the same worker script.
* **KV Namespace** – used to cache Markdown file contents.
* **`compatibility_flags`** – enable Node.js compatibility for file I/O during build.

> **Tip:** Create the KV namespace from the dashboard or via  
> `wrangler kv:namespace create MCP_KV` and copy the ID into the file.

### 3. Serving SSE and HTTP Endpoints

The `McpServer` instance automatically handles the following paths:

| Path | Method | Description |
|------|--------|-------------|
| `/mcp` | POST | Standard HTTP JSON request/response |
| `/sse` | GET | Server‑Sent Events stream (useful for streaming LLM replies) |

No additional code is needed; the `server.handleRequest(event.request)` call covers both.

If you wish to customize the base URL or add additional middleware, wrap the server in a Hono route or add `event.respondWith(...)` logic before delegating to the server.

---

### 4. KV Caching Strategy

* On the first run after deployment, each Markdown file is read from disk and stored under its basename (`help.md` → `help` key) in the KV namespace.
* Subsequent requests hit KV, eliminating expensive file system access.
* If you change a file locally, redeploy the worker to refresh the KV cache automatically.

### 5. Deployment

```bash

npm run build

```

> `wrangler publish` automatically uploads the `index.ts` (and any bundled assets) to the Worker.

---

### 6. Connecting the MCP Server to AI Clients

#### Claude Desktop

1. Open **Claude Desktop** → Settings → `Advanced`.
2. Under “Remote MCP server” paste:
   * **MCP URL**: `https://mcp.yourdomain.com/mcp`
   * **SSE URL**: `https://mcp.yourdomain.com/sse`
3. Save and restart Claude.

#### VS Code Copilot

1. Open VS Code → Settings → search for `copilot.ai.assistants.remote.mcpEndpoint`.
2. Set the value to `https://mcp.yourdomain.com/mcp`.
3. (Optional) In the Copilot settings, enable “Use remote MCP”.

After these steps, both Claude Desktop and VS Code Copilot will invoke your MCP server, and the server will provide the tools built from the `mcp/` folder.
