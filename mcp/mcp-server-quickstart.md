## Understanding Remote MCP for Fufuni
The Model Context Protocol (MCP) is an open standard that enables AI models (like Claude 3.5 Sonnet or GPT-4o) to access local or remote tools and data sources. By exposing the Fufuni `mcp/` directory as a Remote MCP server, we allow AI assistants to "read" our framework's internal documentation, coding standards, and architectural blueprints in real-time.

Running this on the Cloudflare Workers free tier provides a low-latency, globally distributed documentation engine. Unlike local MCP servers that require a node process running on your machine, a Remote MCP server is reachable via a URL, making it accessible to Claude Desktop, VS Code Copilot, and custom agentic workflows without local configuration drift.

### The Role of static documentation
In Fufuni, the `mcp/` directory is generated via a build script that extracts metadata from source code and combines it with manual `README` files. Each file represents a specific "Knowledge Base" entry. By exposing these as tools, the AI can call `get_framework_docs({ topic: "durable-objects" })` and receive the exact Markdown needed to generate bug-free code.

## Worker Entry Point and MCP Server Setup
The core of the server uses the Cloudflare Agents SDK to handle the MCP lifecycle. We implement an SSE (Server-Sent Events) transport for communication with AI clients.

```typescript
import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";
import { SSEServerTransport } from "@modelcontextprotocol/sdk/server/sse.js";
import { z } from "zod";

/**
 * Interface for the compiled documentation manifest.
 * In Fufuni, this is generated by a build step and imported as a JSON module.
 */
import docsManifest from "./mcp-manifest.json";

interface Env {
  MCP_CACHE: KVNamespace;
}

const server = new McpServer({
  name: "fufuni-mcp-docs",
  version: "1.0.0",
});

// Define the tool that exposes the framework documentation
server.tool(
  "query_fufuni_docs",
  "Retrieves technical documentation and code standards for a specific Fufuni module.",
  {
    topic: z.string().describe("The filename/slug of the documentation file in the mcp/ folder."),
  },
  async ({ topic }, { extra }) => {
    const env = extra.env as Env;
    
    // Check KV Cache first to avoid unnecessary processing
    const cached = await env.MCP_CACHE.get(`doc:${topic}`);
    if (cached) {
      return {
        content: [{ type: "text", text: cached }],
      };
    }

    // Look up in the static manifest
    const doc = docsManifest.find((d) => d.slug === topic);
    if (!doc) {
      return {
        isError: true,
        content: [{ type: "text", text: `Error: Documentation for '${topic}' not found.` }],
      };
    }

    // Cache the result for future calls
    await env.MCP_CACHE.put(`doc:${topic}`, doc.content, { expirationTtl: 3600 });

    return {
      content: [{ type: "text", text: doc.content }],
    };
  }
);

export default {
  async fetch(request: Request, env: Env, ctx: ExecutionContext): Promise<Response> {
    const url = new URL(request.url);

    // Handle SSE registration
    if (url.pathname === "/sse") {
      const transport = new SSEServerTransport("/mcp", {
        // Pass the environment to the tool handlers via the 'extra' context
        env,
      });
      
      // Handle the connection
      await server.connect(transport);
      
      return transport.handleRequest(request);
    }

    // Handle MCP messages post-connection
    if (url.pathname === "/mcp") {
      const transport = new SSEServerTransport("/mcp", { env });
      return transport.handlePostRequest(request);
    }

    return new Response("Fufuni MCP Server Operational", { status: 200 });
  },
};
```

## Dynamic Tool Registration from Markdown
While the above example uses a single tool to query multiple files, Fufuni best practices recommend registering one tool per major architectural concept. This allows the AI's "Router" to see high-level descriptions of every doc file in its tool list, improving its ability to choose the right context.

### Generating the Tool Map
We use a build script (usually `scripts/build-mcp.ts`) to parse the `mcp/` directory and generate a TypeScript file that registers these tools.

```typescript
// Example of the generated registration logic
import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";

export function registerDynamicTools(server: McpServer, docs: Array<{ slug: string, title: string, content: string }>) {
  for (const doc of docs) {
    server.tool(
      `read_fufuni_${doc.slug.replace(/-/g, '_')}`,
      `Read documentation about: ${doc.title}`,
      {}, // No arguments needed as the tool is specific to the file
      async () => {
        return {
          content: [{ type: "text", text: doc.content }]
        };
      }
    );
  }
}
```

## Configuration for Cloudflare Workers
To deploy the MCP server, we use `wrangler.jsonc`. We must ensure the KV namespace is bound so the server can cache parsed documentation and session states.

```jsonc
{
  "$schema": "node_modules/wrangler/config-schema.json",
  "name": "fufuni-mcp-server",
  "main": "src/index.ts",
  "compatibility_date": "2024-05-01",
  "compatibility_flags": ["nodejs_compat"],
  "kv_namespaces": [
    {
      "binding": "MCP_CACHE",
      "id": "xxxx-your-kv-id-here-xxxx"
    }
  ],
  "observability": {
    "enabled": true
  }
}
```

### Essential Settings
- **`compatibility_flags`**: `["nodejs_compat"]` is required because the MCP SDK relies on certain Node.js primitives for stream handling and event emitters.
- **`compatibility_date`**: Use a recent date to ensure the latest Fetch API standards are available.

## KV Caching and Performance
To keep the MCP server within the Free Tier limits (100k requests/day), we utilize Cloudflare KV to cache the rendered output of documentation. While the docs are "static," the MCP server might perform transformations (like stripping HTML or shortening code blocks) that are expensive to run on every request.

```typescript
async function getDocContent(slug: string, env: Env): Promise<string> {
  const cacheKey = `fufuni:doc:v1:${slug}`;
  
  // 1. Try KV
  const cached = await env.MCP_CACHE.get(cacheKey);
  if (cached) return cached;

  // 2. If not in KV, find in the bundled manifest
  const doc = docsManifest.find(d => d.slug === slug);
  if (!doc) throw new Error("Doc not found");

  // 3. Process/Clean content
  const cleanContent = doc.content.trim();

  // 4. Save back to KV for 24 hours
  await env.MCP_CACHE.put(cacheKey, cleanContent, { expirationTtl: 86400 });

  return cleanContent;
}
```

## Full Implementation Example: index.ts
This complete example combines the server setup, SSE routing, and KV-aware tool handling.

```typescript
import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";
import { SSEServerTransport } from "@modelcontextprotocol/sdk/server/sse.js";
import { z } from "zod";

// Embedded manifest generated at build time
const docs = [
  { slug: "routing", title: "Fufuni Routing with Hono", content: "..." },
  { slug: "sqlite", title: "Durable Objects SQLite Guide", content: "..." }
];

interface Env {
  MCP_CACHE: KVNamespace;
}

const server = new McpServer({
  name: "Fufuni Framework Docs",
  version: "1.0.0",
});

// Register individual tools for better AI discovery
docs.forEach((doc) => {
  server.tool(
    `get_${doc.slug}_docs`,
    `Detailed technical documentation regarding ${doc.title}`,
    {},
    async (_, { extra }) => {
      const env = (extra as any).env as Env;
      const cacheKey = `mcp:${doc.slug}`;
      
      const cached = await env.MCP_CACHE.get(cacheKey);
      if (cached) return { content: [{ type: "text", text: cached }] };

      await env.MCP_CACHE.put(cacheKey, doc.content, { expirationTtl: 3600 });
      return { content: [{ type: "text", text: doc.content }] };
    }
  );
});

export default {
  async fetch(request: Request, env: Env): Promise<Response> {
    const url = new URL(request.url);

    if (url.pathname === "/sse") {
      // The transport needs to know where to send POST messages
      const transport = new SSEServerTransport("/mcp", { env });
      await server.connect(transport);
      return transport.handleRequest(request);
    }

    if (url.pathname === "/mcp") {
      const transport = new SSEServerTransport("/mcp", { env });
      // We don't call server.connect here; handlePostRequest processes individual messages
      return transport.handlePostRequest(request);
    }

    return new Response("Not Found", { status: 404 });
  }
};
```
