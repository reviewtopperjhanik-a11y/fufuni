## Understanding the MCP Server and Knowledge Base

The Fufuni MCP (Model Context Protocol) server is a specialized bridge that allows AI assistants—specifically Claude and other LLM-based agents—to "understand" the Fufuni framework. Instead of the AI guessing how Fufuni works based on outdated public training data, the MCP server provides real-time, context-aware documentation derived directly from the source code.

The server exposes a toolset that an AI can call to retrieve documentation on specific topics (e.g., "How do I create a new Hono route?" or "What are the rules for React 19 in Fufuni?"). The knowledge base is not a static set of files; it is a generated system where source code is processed by an LLM into structured Markdown documentation, which is then compiled into a runtime module for the Cloudflare Worker or local stdio environment.

## Directory Layout and Core Components

The knowledge management system lives within `apps/mcp/`. It follows a strict architecture to ensure that the AI-generated documentation stays in sync with the actual framework code.

### File Structure

### Shared Logic: apps/mcp/knowledge/base.ts

This file defines the `Topic` interface and provides the base instructions given to the LLM during the documentation generation process.

```typescript
// Example from apps/mcp/knowledge/base.ts
export interface Topic {
  name: string;
  description: string;
  sources: string[];      // Repo-root relative paths
  systemPrompt: string;
  manualFacts?: string[]; // Hardcoded "Verified Facts"
  buildPrompt: (concatenatedSources: string) => string;
  maxSourceChars?: number;
}

export const BASE_SYSTEM = "You are a senior TypeScript developer documenting the Fufuni framework...";

export function appendFacts(facts: string[]): string {
  return facts.map(f => `- ${f}`).join("\n");
}
```

## Adding a New Knowledge Topic

Adding a topic is the **only** way to expand the AI's understanding of Fufuni. You must never edit the generated output; instead, you define the "recipe" for the documentation.

### Step-by-Step Instructions

1.  Create a new file in `apps/mcp/knowledge/topics/<topic-name>.ts`.
2.  Import the required types and helpers from `../base.js`.
3.  Define the files the AI should read to learn about this topic.
4.  Export a `default Topic` object.

### The Topic Template

Every topic file must include the 2026 copyright header as shown below.

```typescript
/**
 * Copyright (c) 2026 Ronan LE MEILLAT - SCTG Development / License: AGPL-3.0-or-later
 */
import { Topic, BASE_SYSTEM, appendFacts } from "../base.js";

const facts = [
  "Fufuni uses SQLite via Durable Objects for backend storage.",
  "Every Hono route must be defined using Zod-OpenAPI for automatic documentation.",
];

const topic: Topic = {
  name: "backend-api",
  description: "Standard practices for creating Hono routes and Zod schemas in Fufuni.",
  sources: [
    "apps/backend/src/index.ts",
    "packages/shared/src/schemas/index.ts"
  ],
  systemPrompt: BASE_SYSTEM + "\n" + appendFacts(facts),
  buildPrompt: (code) => `
    Review the following source code from the Fufuni framework:
    
    ${code}
    
    Based on this code, generate a comprehensive Markdown guide for junior developers.
    Focus on:
    - Route structure (Hono + OpenAPI)
    - Input validation with Zod
    - Error handling patterns
  `,
  maxSourceChars: 30000
};

export default topic;
```

## The Topic Interface Fields

To effectively control how documentation is generated, you must understand the fields in the `Topic` object:

| Field | Type | Description |
| :--- | :--- | :--- |
| `name` | `string` | The unique ID of the topic. Must match the filename (e.g., `backend.ts` -> `backend`). |
| `description` | `string` | A short summary used by the AI to decide if this topic is relevant to a user's question. |
| `sources` | `string[]` | Array of file paths relative to the repository root. The generator reads these files and concatenates them. |
| `systemPrompt` | `string` | The instruction set for the LLM. Usually `BASE_SYSTEM` + `manualFacts`. |
| `manualFacts` | `string[]` | Hardcoded truths that override anything the LLM might hallucinate from the source code. |
| `buildPrompt` | `function` | A function that receives the raw source code and returns the specific prompt for generating the `.md` file. |
| `maxSourceChars`| `number` | Optional limit to prevent hitting LLM context windows (default is usually 100k). |

## Generation Commands and Environment

The generation process uses an LLM (typically via an OpenAI-compatible API) to transform raw code into polished documentation.

### Required Environment Variables

Before running the generation, ensure your `.env` in the root (or `apps/mcp/.env`) contains:
- `AI_MODEL`: The model name (e.g., `gpt-4o` or `claude-3-5-sonnet`).
- `AI_API_KEY`: Your provider's API key.
- `AI_API_URL`: The endpoint URL for the API.

### Command Reference

| Command | Purpose |
| :--- | :--- |
| `npm run mcp:generate` | Checks `apps/mcp/knowledge/topics/`. For each topic, it checks if a corresponding `.md` exists in `mcp/`. If missing, it generates it. |
| `npm run mcp:generate:force` | Ignores existing files and regenerates every topic from scratch. Use this when core framework patterns change. |
| `npm run mcp:auto` | A shortcut that runs `generate` and then immediately runs `gen-knowledge` to update the runtime module. |

## The Publishing Pipeline: gen-knowledge.ts

Once the Markdown files are generated in the `<repo-root>/mcp/` directory, they are not yet usable by the MCP server. The `gen-knowledge.ts` script performs the final "compilation" step.

1.  It reads all `.md` files from the `/mcp/` folder.
2.  It escapes the content to be safe for a TypeScript template literal.
3.  It writes a single file: `apps/mcp/src/knowledge.ts`.

### Why you MUST NOT edit knowledge.ts directly

The file `apps/mcp/src/knowledge.ts` contains a large constant object mapping topic names to their Markdown content. Because this file is entirely machine-generated:
- Any manual changes will be **deleted** the next time someone runs `npm run mcp:auto`.
- Formatting errors introduced manually can break the MCP server's ability to boot.
- The "Source of Truth" must always remain the files in `apps/mcp/knowledge/topics/`.

## Testing the MCP Server Locally (Stdio Mode)

Before deploying changes to Cloudflare, you should test the MCP server using Claude Desktop. This allows you to verify that the AI can actually see and read your new documentation.

### 1. Running the server
You can start the server in stdio mode (standard input/output) using `tsx`:

```bash
# From repo root
npx tsx apps/mcp/src/stdio.ts
```

### 2. Configuring Claude Desktop
On macOS, edit `~/Library/Application Support/Claude/claude_desktop_config.json`. On Windows, it's `%APPDATA%\Claude\claude_desktop_config.json`.

Add the Fufuni MCP server to the `mcpServers` object:

```json
{
  "mcpServers": {
    "fufuni-dev": {
      "command": "npx",
      "args": [
        "-y",
        "tsx",
        "/absolute/path/to/fufuni/apps/mcp/src/stdio.ts"
      ],
      "env": {
        "AI_MODEL": "your-model",
        "AI_API_KEY": "your-key",
        "AI_API_URL": "your-url"
      }
    }
  }
}
```

After restarting Claude Desktop, a hammer icon will appear. You can then ask: *"Using the fufuni-dev tool, explain how the backend architecture works,"* and the AI will call the MCP tool, read the generated knowledge, and provide a verified response.
