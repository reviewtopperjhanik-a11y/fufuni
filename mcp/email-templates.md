## Email Architecture and Storage

Fufuni utilizes a hybrid approach for transactional emails. While the initial order confirmation uses a hardcoded high-performance template for reliability, all subsequent lifecycle emails (shipping updates, refunds, cancellations) are managed via the `order_email_settings` table in the SQLite database (Durable Objects).

### Database Schema and Event Hierarchy

Templates are stored per-event. When the system needs to send an email for a specific status change, it follows a resolution hierarchy:
1.  **Event-Specific**: Looks for a row where `event` matches the status (e.g., `shipped`) and `enabled = 1`.
2.  **Global Fallback**: If no specific enabled row is found, it looks for the row where `event = 'global'` and `enabled = 1`.
3.  **Built-in Fallback**: If no database settings are enabled, the system uses a hardcoded minimal template defined in `buildDefaultStatusEmail`.

```typescript
// Example: Querying the resolution hierarchy in SQL (SQLite)
// This logic is encapsulated in sendOrderStatusEmail
const query = `
  SELECT * FROM order_email_settings 
  WHERE event IN (?, 'global') AND enabled = 1 
  ORDER BY CASE WHEN event = ? THEN 0 ELSE 1 END 
  LIMIT 1
`;
```

### Multilingual Templates (Locale Mapping)

The `subject`, `html_body`, and `text_body` fields in the database support both plain strings and JSON locale maps. This allows a single template entry to serve multiple customer languages. If a JSON object is detected, the system attempts to match the customer's locale (e.g., `fr-FR`).

```typescript
/**
 * Example of a multilingual subject stored in the database:
 * {
 *   "en-US": "Order {{orderNumber}} has shipped!",
 *   "fr-FR": "Votre commande {{orderNumber}} a été expédiée !"
 * }
 */

function resolveLocaleField(field: string, locale: string): string {
  const raw = field.trim();
  if (raw.startsWith('{')) {
    try {
      const map = JSON.parse(raw) as Record<string, string>;
      // Priority: Specific locale -> en-US -> first available -> empty string
      return map[locale] ?? map['en-US'] ?? Object.values(map)[0] ?? '';
    } catch {
      return raw; // Fallback to raw string if JSON parsing fails
    }
  }
  return raw;
}
```

## Variable Interpolation and Rendering

Fufuni uses a simple double-curly-brace syntax `{{variable}}` for interpolation. The rendering engine is intentionally lightweight to ensure it runs efficiently within Cloudflare Workers without the overhead of heavy templating libraries.

### Available Variables

The `OrderEmailVars` interface in `lib/order-email.ts` defines the data available to all status-change templates:

| Variable | Description |
| :--- | :--- |
| `{{storeName}}` | The name of the store configured in environment variables. |
| `{{orderNumber}}` | The human-readable order ID (e.g., ORD-123). |
| `{{orderUrl}}` | A secure, signed link to the order tracking page. |
| `{{status}}` | The current status of the order (e.g., processing, shipped). |
| `{{total}}` | The formatted currency total (e.g., $45.00). |
| `{{customerName}}` | The shipping name associated with the order. |
| `{{trackingNumber}}` | The carrier tracking number, if available. |
| `{{trackingUrl}}` | The direct link to the carrier's tracking page. |

### Implementation of the Renderer

The `renderTemplate` function performs a global regex replacement for each known variable.

```typescript
// apps/merchant/src/lib/order-email.ts
function renderTemplate(template: string, vars: OrderEmailVars): string {
  return template
    .replace(/\{\{storeName\}\}/g, vars.storeName)
    .replace(/\{\{orderNumber\}\}/g, vars.orderNumber)
    .replace(/\{\{orderUrl\}\}/g, vars.orderUrl)
    .replace(/\{\{status\}\}/g, vars.status)
    .replace(/\{\{total\}\}/g, vars.total)
    .replace(/\{\{customerName\}\}/g, vars.customerName)
    .replace(/\{\{trackingNumber\}\}/g, vars.trackingNumber)
    .replace(/\{\{trackingUrl\}\}/g, vars.trackingUrl);
}
```

## Order Confirmation Dispatch

The initial order confirmation is the most critical email. It is dispatched via `sendOrderConfirmationEmail` which performs three critical tasks:
1.  **Token Generation**: It creates a 30-day signed JWT that allows the customer to view their order without logging in.
2.  **State Persistence**: It hashes the token and saves it to the `orders` table to prevent replay attacks or unauthorized access.
3.  **Delivery**: It sends the email and logs the `confirmationemailsentat` timestamp.

```typescript
// Example usage during a successful Stripe checkout webhook
import { sendOrderConfirmationEmail } from '../lib/order-email';

async function handleSuccessfulPayment(env: Env, db: Database, orderId: string) {
  const result = await sendOrderConfirmationEmail(env, db, {
    orderId,
    regenerateToken: true // Generate a fresh view token upon payment
  });

  if (result.success) {
    console.log(`Confirmation sent to ${result.customerEmail}`);
  } else {
    console.error(`Mail failure: ${result.errorMessage}`);
  }
}
```

## Troubleshooting and Mailgun Integration

Fufuni uses Mailgun as its primary delivery provider. The integration is designed to be "fail-soft" in development environments but requires strict configuration for production.

### Silent Failures and Configuration

If `MAILGUN_API_KEY` or `MAILGUN_DOMAIN` are missing from the environment variables, the system will **silently ignore** the send request. No error is thrown to the user/webhook to prevent breaking the checkout flow, but a warning is logged to the console.

**Priority Checklist for Missing Emails:**
1.  **Check Env Vars**: Ensure `MAILGUN_API_KEY`, `MAILGUN_DOMAIN`, and `MAILGUN_USER` (the "from" address) are set in `wrangler.toml` or the Cloudflare Dashboard.
2.  **Verify DB Status**: Check the `order_email_settings` table. If the `enabled` column is `0` for an event and the `global` event is also disabled, no email will be sent.
3.  **Review Order Logs**: The `orders` table contains `confirmationemaillasterror`. If a delivery fails at the API level, the error message is stored there for debugging.

The system captures and persists errors specifically for order confirmations to ensure merchants can identify customers who didn't receive their digital receipt.

## Summary of Template Logic Flow

When `sendOrderStatusEmail` is called:
1.  **Context Loading**: Fetch the order and its associated customer data (name, email, total, tracking).
2.  **Setting Resolution**: Locate the active template in `order_email_settings` (Specific -> Global -> Default).
3.  **Locale Resolution**: Select the correct translation from the JSON fields based on `order.locale`.
4.  **Interpolation**: Run the `renderTemplate` logic to swap `{{tags}}` for real data.
5.  **Dispatch**: Attempt transmission via `sendMailgunEmail`.
6.  **Cleanup**: Log any failures to the worker console.
