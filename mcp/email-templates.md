## Email System Architecture

Fufuni utilizes a hybrid approach for transactional emails. Initial order confirmations use a structured HTML builder for high reliability and consistent branding, while subsequent order lifecycle events (shipped, delivered, etc.) are driven by dynamic templates stored in the Durable Object's SQLite database.

All email operations are centralized in `apps/merchant/src/lib/order-email.ts`, which handles template resolution, variable replacement, and delivery via Mailgun.

### Template Storage and Persistence

Dynamic templates are stored in the `order_email_settings` table. This allows merchants to modify email content through the admin dashboard without redeploying the Worker. Each row represents a specific order event or a `global` fallback.

```sql
-- Schema representation of order_email_settings
CREATE TABLE order_email_settings (
  id TEXT PRIMARY KEY,
  event TEXT UNIQUE NOT NULL, -- 'global', 'shipped', 'delivered', etc.
  enabled INTEGER DEFAULT 1,
  subject TEXT NOT NULL,      -- Supports JSON locale maps
  html_body TEXT,             -- Supports {{variables}}
  text_body TEXT,             -- Plain text fallback
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
```

To update a template programmatically or via the internal API, you target the `event` key. If a specific event template (e.g., `shipped`) is disabled or missing, the system automatically falls back to the `global` template.

## Dynamic Variable Interpolation

The framework uses a double-curly-brace syntax `{{variable}}` for interpolation. The `renderTemplate` function in `lib/order-email.ts` performs global regex replacement on these placeholders before dispatching.

### Available Template Variables

The following variables are injected into the `OrderEmailVars` context and are available in the `subject`, `html_body`, and `text_body` fields:

| Variable | Description | Example |
| :--- | :--- | :--- |
| `{{storeName}}` | Configured name of the shop | "Fufuni Boutique" |
| `{{orderNumber}}` | Human-readable order ID | "ORD-2024-X12" |
| `{{orderUrl}}` | Signed link to the order tracking page | `https://store.com/order/id?token=...` |
| `{{status}}` | The current state of the order | "shipped" |
| `{{total}}` | Formatted price with currency symbol | "$120.00" |
| `{{customerName}}` | Shipping name from the order | "Jane Doe" |
| `{{trackingNumber}}` | Courier tracking ID (if available) | "1Z999AA1" |
| `{{trackingUrl}}` | Direct link to courier tracking | `https://ups.com/track/...` |

### Multi-language Support (Locales)

Fufuni supports localized templates using JSON maps within the database fields. The `resolveLocaleField` helper detects if a string starts with `{` and attempts to parse it.

```typescript
// Example of a localized subject line stored in the DB
const localizedSubject = JSON.stringify({
  "en-US": "Your order {{orderNumber}} has shipped!",
  "fr-FR": "Votre commande {{orderNumber}} a été expédiée !"
});

// The system resolves this based on order.locale
// If the specific locale is missing, it falls back to en-US or the first available key.
```

## Dispatching Order Status Emails

To send an email when an order status changes, use the `sendOrderStatusEmail` helper. This function is typically called from the order management routes or Stripe webhook handlers.

```typescript
import { sendOrderStatusEmail } from '../lib/order-email';
import { Env } from '../types';
import { Database } from '../db';

/**
 * Example: Triggering a 'shipped' email after updating tracking info
 */
async function handleOrderShipped(env: Env, db: Database, orderId: string) {
  // 1. Update order in DB (omitted)
  
  // 2. Dispatch email
  // This will look for 'shipped' settings, then 'global', then fallback to built-in defaults
  await sendOrderStatusEmail(env, db, orderId, 'shipped');
}
```

The dispatch logic follows this priority:
1. **Event-Specific Template**: If `event = 'shipped'` and `enabled = 1`.
2. **Global Template**: If the specific event is missing/disabled, but `event = 'global'` is enabled.
3. **Hardcoded Fallback**: If no DB templates are enabled, `buildDefaultStatusEmail` generates a standard Fufuni-branded message.

## Order Confirmation Logic

The initial order confirmation is handled differently via `sendOrderConfirmationEmail`. This function is responsible for:
1. Generating or re-using a signed JWT `viewtoken`.
2. Hashing and storing that token in the database for security.
3. Building a tracking URL that includes the raw token.
4. Sending the email via Mailgun.

```typescript
import { sendOrderConfirmationEmail } from '../lib/order-email';

// Manual resend from admin dashboard
const result = await sendOrderConfirmationEmail(env, db, {
  orderId: "opt_12345",
  regenerateToken: false // Keep existing link valid
});

if (result.success) {
  console.log(`Confirmation sent to ${result.customerEmail}`);
} else {
  console.error(`Failed: ${result.errorMessage}`);
}
```

## Mailgun Integration and Troubleshooting

Fufuni uses Mailgun as the primary email provider. Proper environment configuration is required for any emails to be delivered.

### Configuration Requirements

The following variables must be set in your `wrangler.toml` or Cloudflare Dashboard:
- `MAILGUN_API_KEY`: Your secret API key.
- `MAILGUN_DOMAIN`: The verified sending domain (e.g., `mg.fufuni.com`).
- `STORE_URL`: Used to generate absolute links for `{{orderUrl}}`.
- `ORDER_TOKEN_SECRET`: Used to sign the JWT tracking links.

### Troubleshooting Missing Keys

**Verified Fact**: If `MAILGUN_API_KEY` or `MAILGUN_DOMAIN` are missing, email sending is **silently ignored**. The system will log a warning to the console but will not throw an error to avoid interrupting the checkout flow or database transactions.

If emails are not arriving:
1. Check the `orders` table columns: `confirmationemailsentat` and `confirmationemaillasterror`.
2. Verify that the `order_email_settings` for that event is marked as `enabled`.
3. Use the test endpoint to verify raw connectivity:

```bash
# Test the Mailgun integration via the Admin API
curl -X POST https://api.yourstore.com/v1/admin/mails/send \
  -H "Authorization: Bearer <ADMIN_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{
    "to": "dev@example.com",
    "subject": "Fufuni Mail Test",
    "text": "Checking integration..."
  }'
```

### Manual Template Resolution

If you are building a custom previewer in the frontend, you can replicate the resolution logic. The backend provides an endpoint to fetch these settings via `adminOrderEmailSettings`.

```typescript
// GET /v1/admin/order-email-settings/:event
// Returns the raw template strings and enabled status
import { adminOrderEmailSettings } from '../routes/order-email-settings';

// Example response:

//   "html_body": "<h1>Good news {{customerName}}!</h1><p>Track it here: {{orderUrl}}</p>"
// }
```

## Built-in Fallback Styles

When no custom HTML is provided in the database, the system uses a standard CSS-in-HTML wrapper defined in `buildDefaultStatusEmail`. It uses system fonts and a clean "badge" UI consistent with HeroUI v3 aesthetics.

The badge colors are automatically selected based on the event:
- **Paid**: Blue (`#0369a1`)
- **Shipped**: Dark Blue (`#1d4ed8`)
- **Delivered**: Green (`#16a34a`)
- **Canceled/Failed**: Red (`#b91c1c`)
