## Mailgun Setup and Environment

Fufuni uses the Mailgun REST API for all transactional email delivery. To enable email functionality, you must configure specific secrets in your Cloudflare Worker environment. If these keys are missing, Fufuni will log a warning or silently skip the delivery attempt to prevent breaking the checkout flow during local development.

The following secrets must be added via `wrangler secret put` or defined in your `.dev.vars` file for local testing:

| Secret | Description | Example |
| :--- | :--- | :--- |
| `MAILGUN_API_KEY` | Your Mailgun Private API Key. | `key-xxxxxxxxxxxxxxxx` |
| `MAILGUN_DOMAIN` | The verified domain in Mailgun. | `mg.yourstore.com` |
| `MAILGUN_USER` | The default "From" address for emails. | `orders@yourstore.com` |
| `MAILGUN_BASE_URL` | The API endpoint (defaults to US). | `https://api.mailgun.net` |
| `ORDER_TOKEN_SECRET` | Secret used to sign order tracking links. | `a-very-long-random-string` |
| `STORE_URL` | Base URL used to generate tracking links. | `https://yourstore.com` |
| `STORE_NAME` | The name of the store used in templates. | `Fufuni Boutique` |

```bash
# Example: Configuring secrets for production
npx wrangler secret put MAILGUN_API_KEY
npx wrangler secret put MAILGUN_DOMAIN
npx wrangler secret put MAILGUN_USER
```

## Template Architecture

Fufuni avoids heavy templating engines like Handlebars or EJS. Instead, templates are written as **Plain TypeScript String Templates** in `apps/merchant/src/lib/email-templates.ts`. This provides full type safety, easy variable injection, and no runtime overhead.

Every template function must return an object containing three fields: `subject`, `html`, and `text`.

```typescript
/**
 * apps/merchant/src/lib/email-templates.ts
 */
export function buildShippingNotificationEmail(params: {
  customerName: string;
  orderNumber: string;
  trackingNumber: string;
  trackingUrl: string;
  STORE_NAME: string;
}): { subject: string; html: string; text: string } {
  const { customerName, orderNumber, trackingNumber, trackingUrl, STORE_NAME } = params;

  const subject = `Your order ${orderNumber} has shipped!`;
  
  const text = `Hi ${customerName}, your order from ${STORE_NAME} is on its way. 
    Tracking Number: ${trackingNumber}. Track here: ${trackingUrl}`;

  const html = `
    <!DOCTYPE html>
    <html>
      <body style="font-family: sans-serif; line-height: 1.5;">
        <h1>Great news, ${customerName}!</h1>
        <p>Your order <strong>${orderNumber}</strong> has been shipped.</p>
        <div style="margin: 20px 0; padding: 15px; background: #f3f4f6; border-radius: 8px;">
          <p><strong>Tracking Number:</strong> ${trackingNumber}</p>
          <a href="${trackingUrl}" style="background: #111; color: #fff; padding: 10px 20px; text-decoration: none; border-radius: 5px;">
            Track Shipment
          </a>
        </div>
        <p>— The ${STORE_NAME} Team</p>
      </body>
    </html>
  `;

  return { subject, html, text };
}
```

## Transactional Triggers

The framework automatically triggers specific emails based on order lifecycle events. These triggers are managed via the `sendOrderStatusEmail` helper in `lib/order-email.ts`.

| Event | Trigger Point | Content |
| :--- | :--- | :--- |
| `order_confirmation` | Stripe Webhook (`checkout.session.completed`) | Order details, total, and a 30-day signed tracking link. |
| `payment_failed` | Stripe Webhook (`invoice.payment_failed`) | Notification that the transaction did not clear. |
| `processing` | Admin Panel (Order Status Update) | Confirmation that the merchant is preparing the order. |
| `shipped` | Admin Panel (Set Tracking Info) | Tracking number and courier link. |
| `refunded` | Stripe Webhook or Admin Panel | Confirmation of the returned amount. |

To trigger an email manually in a Hono route:

```typescript
import { sendOrderStatusEmail } from '../lib/order-email';

// Inside a Hono handler
app.post('/v1/admin/orders/:id/ship', async (c) => {
  const orderId = c.req.param('id');
  const db = getDb(c.var.db);
  
  // ... logic to update tracking_number in SQLite ...

  // Trigger the email
  await sendOrderStatusEmail(c.env, db, orderId, 'shipped');

  return c.json({ success: true });
});
```

## Admin Customization and Localization

Merchants can override the default TypeScript templates using the Admin API. These overrides are stored in the `order_email_settings` table. Fufuni supports **Variable Substitution** and **Multi-language Support**.

### Variable Substitution
Custom templates can use `{{variable}}` syntax. Available variables include:
- `{{storeName}}`, `{{orderNumber}}`, `{{orderUrl}}`
- `{{status}}`, `{{total}}`, `{{customerName}}`
- `{{trackingNumber}}`, `{{trackingUrl}}`

### Localized Subject and Body
The `subject`, `html_body`, and `text_body` fields can be stored as a JSON map to support international customers. If the customer's locale (stored on the order) matches a key in the map, that version is used; otherwise, it falls back to `en-US`.

```sql
-- Example of a localized subject entry in the database
UPDATE order_email_settings 
SET subject = '{"en-US": "Order Shipped!", "fr-FR": "Commande Expédiée !"}'
WHERE event = 'shipped';
```

### Admin Endpoints for Settings
The `adminOrderEmailSettings` router provides CRUD operations for these configurations:

```typescript
/**
 * GET /v1/admin/order-email-settings/:event
 * Fetches the configuration for a specific event (e.g., 'shipped').
 * If no specific config exists, it falls back to the 'global' entry.
 */

/**
 * PUT /v1/admin/order-email-settings/:event
 * Upserts a custom template.
 */
const updatePayload = {
  enabled: true,
  subject: "Your {{storeName}} package is coming!",
  html_body: "<h1>Hello {{customerName}}</h1><p>Order {{orderNumber}} is on the way!</p>"
};
```

## Adding a New Email Template End-to-End

To add a new transactional email (e.g., a "Product Review Request" 7 days after delivery), follow these four steps:

### 1. Define the Template
Add a function in `apps/merchant/src/lib/email-templates.ts` that takes raw data and returns the email structure.

### 2. Add an Event Type
Update the `OrderEmailEvent` type in `apps/merchant/src/lib/order-email.ts` and the `ORDER_EMAIL_EVENTS` constant in `apps/merchant/src/routes/order-email-settings.ts` to include your new event name (e.g., `review_request`).

### 3. Implement the Trigger Logic
Find the logical place in your backend where this email should be sent. Call `sendOrderStatusEmail`.

```typescript
// Example: New delivery confirmation route
app.post('/v1/admin/orders/:id/delivered', async (c) => {
  const orderId = c.req.param('id');
  await sendOrderStatusEmail(c.env, getDb(c.var.db), orderId, 'delivered');
  return c.json({ ok: true });
});
```

### 4. Register in Admin UI (Optional)
Add the event to the `order_email_settings` table via a migration or the Admin API so the merchant can toggle it off or customize the text.

## Testing and Local Development

During development, Fufuni simplifies the email workflow to avoid accidental spam and configuration frustration.

### Silent Skipping
If `MAILGUN_API_KEY` is not present in your environment, `sendMailgunEmail` and its wrappers will return a success state but log a warning to the console instead of attempting an HTTP request. This allows you to test checkout flows without a live Mailgun account.

### Manual Test Route
You can send a real test email using the `/v1/admin/mails/send` endpoint. This is useful for verifying that your Mailgun credentials and SPF/DKIM records are correctly configured.

```typescript
// Example: POST /v1/admin/mails/send
{
  "to": "dev-tester@example.com",
  "subject": "Testing Fufuni Integration",
  "html": "<h1>It works!</h1>",
  "text": "It works!"
}
```

### Template Previewing
To see how a template renders without sending an email, use the preview utility (standard in the Merchant Admin UI):
1. The Admin UI calls the `GET /v1/admin/order-email-settings/:event` endpoint.
2. It uses the `html_body` returned to render an iframe.
3. If no `html_body` is set in the DB, the UI logic displays the default output from `buildDefaultStatusEmail`.
