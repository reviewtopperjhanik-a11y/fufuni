## Mailgun Infrastructure and Setup

Fufuni uses the Mailgun REST API for all transactional email delivery. The integration is designed to be lightweight, relying on Cloudflare Worker `fetch` calls rather than heavy Node.js libraries. 

To enable email delivery, you must configure specific secrets in your environment. If `MAILGUN_API_KEY` is missing, the framework will silently skip email sending. This is a deliberate design choice to allow local development and CI/CD testing without accidentally hitting Mailgun quotas or sending emails to real users.

### Required Environment Secrets

The following variables must be set using `wrangler secret put <NAME>`:

*   `MAILGUN_API_KEY`: Your Mailgun Private API key.
*   `MAILGUN_DOMAIN`: The verified domain in your Mailgun account (e.g., `mg.example.com`).
*   `MAILGUN_BASE_URL`: Defaults to `https://api.mailgun.net`. Use `https://api.eu.mailgun.net` for EU regions.
*   `MAILGUN_USER`: The "From" address used by default (e.g., `Support <noreply@fufuni.com>`).

```typescript
// Example configuration in apps/merchant/wrangler.toml
[vars]
MAILGUN_BASE_URL = "https://api.mailgun.net"
STORE_NAME = "Fufuni Pro Shop"

// Set these via CLI for security:
// npx wrangler secret put MAILGUN_API_KEY
// npx wrangler secret put MAILGUN_DOMAIN
// npx wrangler secret put MAILGUN_USER
```

## Template Architecture: email-templates.ts

Fufuni avoids external templating engines (like Handlebars or EJS) to minimize cold-start times and bundle size. Instead, templates are written as plain TypeScript functions that return a standardized object containing the subject line, the HTML body, and a plain-text fallback.

Templates live in `apps/merchant/src/lib/email-templates.ts`. Every template function must follow this signature:

```typescript
/**
 * Standardized template structure in Fufuni.
 */
export function buildShippingNotificationEmail(params: {
  orderNumber: string;
  customerName: string;
  trackingNumber: string;
  trackingUrl: string;
  STORE_NAME: string;
}): { subject: string; html: string; text: string } {
  const { orderNumber, customerName, trackingNumber, trackingUrl, STORE_NAME } = params;

  const subject = `Your order ${orderNumber} has shipped!`;
  
  const text = `Hi ${customerName}, your order ${orderNumber} is on its way. Tracking: ${trackingUrl}`;

  const html = `
    <!DOCTYPE html>
    <html>
      <body style="font-family: sans-serif; padding: 20px;">
        <h2>Great news, ${customerName}!</h2>
        <p>Your order <strong>${orderNumber}</strong> has been shipped.</p>
        <div style="margin: 20px 0; padding: 15px; background: #f0f7ff; border-radius: 8px;">
          <p>Tracking Number: <strong>${trackingNumber}</strong></p>
          <a href="${trackingUrl}" style="background: #0070f3; color: white; padding: 10px 20px; text-decoration: none; border-radius: 5px;">
            Track Shipment
          </a>
        </div>
        <p>— The ${STORE_NAME} Team</p>
      </body>
    </html>
  `;

  return { subject, html, text };
}
```

## Triggered Email Events

Emails are triggered by state changes in the `orders` table or specific Stripe webhook events. Fufuni distinguishes between "Confirmation" emails (the initial order receipt) and "Status Change" emails (shipped, refunded, etc.).

### Automatic Triggers

| Event | Logic Hook | Recipient |
| :--- | :--- | :--- |
| **Order Created** | Stripe Webhook (`checkout.session.completed`) | Customer & Admin |
| **Order Shipped** | Admin Update (`PUT /v1/admin/orders/:id`) | Customer |
| **Order Refunded** | Stripe Webhook (`charge.refunded`) | Customer |
| **Payment Failed** | Stripe Webhook (`invoice.payment_failed`) | Customer |

To send a status email manually or from a new logic path, use the `sendOrderStatusEmail` helper:

```typescript
import { sendOrderStatusEmail } from '../lib/order-email';

// Example: Triggering a refund email after processing a return
async function handleRefund(env: Env, db: Database, orderId: string) {
  // ... refund logic ...
  
  await sendOrderStatusEmail(env, db, orderId, 'refunded');
}
```

## Adding a New Template End-to-End

To introduce a new transactional email (e.g., a "Review Request" email), follow these four steps:

### 1. Define the Template
Add a new function in `apps/merchant/src/lib/email-templates.ts` that accepts your required variables and returns the `{ subject, html, text }` object.

### 2. Update the Event Types
Add your new event name to the `OrderEmailEvent` type in `apps/merchant/src/lib/order-email.ts` and the `ORDER_EMAIL_EVENTS` array in `apps/merchant/src/routes/order-email-settings.ts`.

### 3. Implement the Trigger
Call the sending logic in the relevant route. If it's a status update, ensure the `sendOrderStatusEmail` logic can handle the new event type.

### 4. Configure Admin Toggle (Optional)
Insert a record into the `order_email_settings` table to allow the merchant to enable/disable or customize the template from the dashboard.

```sql
-- Migration or initial setup for a new email event
INSERT INTO order_email_settings (id, event, enabled, subject, html_body, text_body, created_at, updated_at)
VALUES (
  'uuid-review-request', 
  'review_request', 
  1, 
  'How was your purchase from {{storeName}}?', 
  '', -- Leave empty to use the built-in TS fallback
  '', 
  CURRENT_TIMESTAMP, 
  CURRENT_TIMESTAMP
);
```

## Admin Management and Testing

Fufuni provides a robust set of admin endpoints to manage email behavior. These endpoints are protected by the `adminOnly` or `mailAccessOnly` middleware.

### Configuring Settings
Merchants can override the default TypeScript templates by saving custom HTML/Text into the `order_email_settings` table. The backend supports variable interpolation using double curly braces (e.g., `{{orderNumber}}`).

### Previewing and Testing
*   **Preview**: `GET /v1/admin/mails/preview/:type` renders the template with mock data. This is useful for UI development.
*   **Test Send**: `POST /v1/admin/mails/test` sends a real email to the `MAILGUN_USER` address.

```typescript
// Example of the test email route implementation
adminApp.openapi(testRoute, async (c) => {
  const { type } = c.req.valid('json');
  
  // Logic to fetch a dummy order and call sendMailgunEmail
  const result = await sendMailgunEmail(c.env, {
    to: c.env.MAILGUN_USER,
    subject: `[TEST] ${type}`,
    html: "<p>This is a test</p>",
    text: "This is a test"
  });

  return c.json(result);
});
```

## Local Development and Fail-safes

When developing locally, you usually do not want to configure a live Mailgun API key. The `sendMailgunEmail` helper checks for the presence of the key before attempting a request.

If the key is missing:
1.  A warning is logged to the console (in development).
2.  The function returns a `success: true` mock response to prevent the calling logic (like an order placement flow) from crashing.
3.  The `orders` table is still updated with a "sent" timestamp, but the `confirmationemaillasterror` field will remain empty.

### Verifying Email Content Locally
To verify the HTML structure without sending, use the preview endpoint or simply log the generated HTML to the console:

```typescript
// apps/merchant/src/mailgun.ts snippet
export async function sendMailgunEmail(env: Env, options: MailOptions) {
  if (!env.MAILGUN_API_KEY) {
    console.log('--- MAILGUN SILENT SKIP (Local Dev) ---');
    console.log('To:', options.to);
    console.log('Subject:', options.subject);
    // console.log('HTML:', options.html); // Uncomment for deep debugging
    return { success: true, status: 200, statusText: 'Skipped (No API Key)', body: {} };
  }
  
  // Real fetch call to api.mailgun.net...
}
```

This ensures that the checkout flow remains functional in `wrangler dev` even without internet access or valid credentials, while providing enough feedback to the developer that the email logic was reached.### Variable Interpolation
When using the database-driven settings (`order_email_settings`), Fufuni uses a simple regex-based replacement for variables. The following variables are globally available in all status templates:

*   `{{storeName}}`: Display name of the store.
*   `{{orderNumber}}`: The human-readable ID (e.g., ORD-123).
*   `{{orderUrl}}`: Signed link to the order tracking page.
*   `{{status}}`: Current status string.
*   `{{total}}`: Formatted currency string.
*   `{{customerName}}`: Shipping name from the order.
*   `{{trackingNumber}}`: Carrier tracking ID.
*   `{{trackingUrl}}`: Link to carrier tracking page.
