## Embedded OAuth Server Reference

The Fufuni e-commerce framework features an embedded OAuth server that allows third-party applications to access the Fufuni API on behalf of customers. This embedded OAuth server is distinct from the main Auth0 instance, providing a secure way to expose the Fufuni API without sharing sensitive Auth0 credentials (e.g., `sk_` keys).

### Difference from Auth0

The embedded OAuth server is designed to provide a limited subset of OAuth 2.0 functionality, specifically tailored for third-party app integration. Unlike the main Auth0 instance, which offers a broader range of features and scopes, the embedded OAuth server focuses on providing a streamlined authorization flow for third-party clients.

### Authorization Code Flow for Third-Party Apps

The embedded OAuth server supports the `authorization_code` flow, which allows third-party apps to obtain an access token on behalf of a customer. The flow involves the following steps:

1. ** Redirect to Authorization Endpoint**: The third-party app redirects the customer to the Fufuni authorization endpoint (`/oauth/authorize`) with the required parameters, including `client_id`, `redirect_uri`, `response_type`, and `scope`.
2. **Customer Authorization**: The customer is prompted to authorize the third-party app, selecting the desired scopes.
3. **Authorization Code**: After authorization, the Fufuni server redirects the customer back to the third-party app with an authorization code.
4. **Token Request**: The third-party app exchanges the authorization code for an access token by sending a request to the Fufuni token endpoint (`/oauth/token`).

### Limited Scopes

Compared to the main Auth0 instance, the embedded OAuth server offers a limited set of scopes that third-party apps can request. These scopes are a subset of the permissions available in Auth0 and are designed to provide a more restricted access to customer data. The available scopes include:

* `openid`
* `profile`
* `ucp:scopes:checkout_session`
* `ucp:scopes:order`
* `ucp:scopes:identity`
* `checkout`
* `orders.read`
* `orders.write`
* `addresses.read`
* `addresses.write`

These scopes are defined in the `VALID_SCOPES` array in the `oauth.ts` file and are used to validate the `scope` parameter in the authorization request.

### Example Use Case

To demonstrate the authorization code flow, consider a third-party app that wants to access a customer's order history. The app would redirect the customer to the Fufuni authorization endpoint with the required parameters, including the `scope` parameter set to `orders.read`. After the customer authorizes the app, the Fufuni server would redirect the customer back to the app with an authorization code. The app would then exchange the authorization code for an access token, which could be used to retrieve the customer's order history from the Fufuni API.

```typescript
// Example authorization request
const authUrl = new URL('/oauth/authorize');
authUrl.searchParams.set('client_id', 'third-party-client-id');
authUrl.searchParams.set('redirect_uri', 'https://third-party-app.com/callback');
authUrl.searchParams.set('response_type', 'code');
authUrl.searchParams.set('scope', 'orders.read');

// Redirect the customer to the authorization endpoint
window.location.href = authUrl.toString();
```
