## Architecture Overview

The Fufuni framework implements a built-in, lightweight OAuth 2.0 server directly within the merchant backend. This server is distinct from the primary Auth0/OIDC provider used for merchant administrative access. While Auth0 handles the identity of the store owner, the embedded OAuth server manages the identity and permissions of **customers** and **third-party applications** (like AI agents or external shipping tools).

The primary goal of this implementation is to allow external services to act on behalf of a customer without ever requiring the merchant to share their private API keys (`sk_` keys) or the customer to share their login credentials directly with the third party.

### Internal vs. External Identity

| Feature | Auth0 (Identity Provider) | Embedded OAuth Server |
| :--- | :--- | :--- |
| **Primary Audience** | Merchants / Store Admins | Customers / Third-party Apps |
| **Data Store** | External (Auth0 Cloud) | Internal (Durable Object SQLite) |
| **Permission Level** | Full Admin Access | Scoped Customer Access |
| **Auth Method** | Standard OIDC Login | OAuth 2.0 + PKCE + Magic Link |

To mount the OAuth sub-router in your Hono application, use the following pattern:

```typescript
// apps/merchant/src/index.ts
import { Hono } from 'hono';
import { oauth } from './routes/oauth';
import type { HonoEnv } from './types';

const app = new Hono<HonoEnv>();

// Mount the OAuth 2.0 routes under the /oauth prefix
app.route('/oauth', oauth);

export default app;
```

## The Authorization Code Flow (PKCE)

Fufuni enforces the **Proof Key for Code Exchange (PKCE)** for all OAuth requests. This is a security extension to the authorization code flow that prevents authorization code injection attacks. It is mandatory for "public" clients like SPAs or AI agents that cannot securely store a `client_secret`.

### Phase 1: Initial Authorization Request

The third-party application initiates the flow by redirecting the user to the `/oauth/authorize` endpoint. Fufuni's implementation automatically registers new platforms on their first attempt, creating an entry in the `oauth_clients` table based on the `client_id` and the domain of the `redirect_uri`.

```typescript
// Example of a 3rd party application initiating the flow
const clientId = "ai-shopping-agent-001";
const redirectUri = "https://agent-ui.com/callback";
const codeVerifier = "a-very-long-random-string-that-is-kept-secret";

// Generate code_challenge from code_verifier (SHA-256)
async function generateChallenge(verifier: string) {
  const encoder = new TextEncoder();
  const data = encoder.encode(verifier);
  const hash = await crypto.subtle.digest('SHA-256', data);
  return btoa(String.fromCharCode(...new Uint8Array(hash)))
    .replace(/\+/g, '-').replace(/\//g, '_').replace(/=+$/, '');
}

const challenge = await generateChallenge(codeVerifier);

const authUrl = new URL("https://your-merchant-worker.fufuni.workers.dev/oauth/authorize");
authUrl.searchParams.set("client_id", clientId);
authUrl.searchParams.set("redirect_uri", redirectUri);
authUrl.searchParams.set("response_type", "code");
authUrl.searchParams.set("scope", "ucp:scopes:order orders.read");
authUrl.searchParams.set("code_challenge", challenge);
authUrl.searchParams.set("code_challenge_method", "S256");
authUrl.searchParams.set("state", "random-state-string");

console.log(`Redirect user to: ${authUrl.toString()}`);
```

### Phase 2: Magic Link and Verification

Since Fufuni operates in a serverless, often stateless environment, it uses a **Magic Link** strategy for customer authentication within the OAuth flow.
1. The user enters their email on the Fufuni-generated login page.
2. Fufuni creates a `pending` authorization in the SQLite database.
3. A magic token is generated and hashed.
4. In development, the link is displayed on the screen; in production, it is intended to be sent via email providers (e.g., Resend).

The database schema for tracking these authorizations is as follows:

```sql
-- Conceptual schema used within the Durable Object
CREATE TABLE oauth_authorizations (
  id TEXT PRIMARY KEY,
  client_id TEXT NOT NULL,
  redirect_uri TEXT NOT NULL,
  customer_email TEXT,
  scope TEXT,
  state TEXT,
  code_challenge TEXT NOT NULL,
  code_hash TEXT,
  magic_token_hash TEXT,
  status TEXT DEFAULT 'pending', -- pending, authorized, used
  expires_at DATETIME,
  created_at DATETIME
);
```

### Phase 3: Token Exchange

Once the user clicks the magic link and verifies their identity, they are redirected back to the third-party app with an `authorization_code`. The app then swaps this code for an `access_token`.

```typescript
// Example: POST /oauth/token
async function exchangeCodeForToken(code: string, verifier: string) {
  const response = await fetch('https://your-merchant.com/oauth/token', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      grant_type: 'authorization_code',
      client_id: 'ai-shopping-agent-001',
      code: code,
      redirect_uri: 'https://agent-ui.com/callback',
      code_verifier: verifier // The secret string used in Phase 1
    })
  });

  const tokens = await response.json();
  // Result: { access_token: "...", refresh_token: "...", expires_in: 3600 }
  return tokens;
}
```

## Scopes and Permissions

Scopes in the embedded OAuth server are strictly limited to customer-level actions. Unlike the Merchant API keys which allow deleting products or changing store settings, OAuth tokens are restricted to the `VALID_SCOPES` array defined in the source.

### Available Scopes

Fufuni follows the **Universal Commerce Protocol (UCP)** naming conventions for interoperability with AI agents.

| Scope | Description |
| :--- | :--- |
| `openid` / `profile` | Basic identity information (email). |
| `ucp:scopes:checkout_session` | Permission to create and manage the user's cart/checkout. |
| `ucp:scopes:order` | Full access to order creation and tracking. |
| `orders.read` / `orders.write` | Legacy access to order history. |
| `addresses.read` | Access to the customer's saved shipping addresses. |

### Scope Validation Logic

When a request for authorization is made, Fufuni validates the requested string against the whitelist:

```typescript
const VALID_SCOPES = [
  'openid', 'profile', 'ucp:scopes:checkout_session', 
  'ucp:scopes:order', 'ucp:scopes:identity',
  'checkout', 'orders.read', 'orders.write',
  'addresses.read', 'addresses.write'
] as const;

// Internal validation logic
const requestedScopes = scope.split(' ').filter(Boolean);
const invalidScopes = requestedScopes.filter(s => !VALID_SCOPES.includes(s as any));

if (invalidScopes.length > 0) {
  throw ApiError.invalidRequest(`Invalid scopes: ${invalidScopes.join(', ')}`);
}
```

## Token Management and Revocation

Fufuni stores issued tokens in the `oauth_tokens` table. Each record includes a hash of the access token and the refresh token. This allows the system to verify tokens without storing the raw strings, maintaining security even if the SQLite database is compromised.

### Refreshing Tokens

Access tokens are short-lived (usually 1 hour). Third-party apps should use the `refresh_token` to obtain a new access token without re-authenticating the user.

```typescript
// POST /oauth/token (Refresh Grant)
const refreshResponse = await fetch('/oauth/token', {
  method: 'POST',
  body: new URLSearchParams({
    grant_type: 'refresh_token',
    refresh_token: 'stored_refresh_token_string',
    client_id: 'ai-shopping-agent-001'
  })
});
```

### Manual Revocation

Fufuni provides an RFC 7009 compliant revocation endpoint. When a user logs out of the third-party app, the app should call this endpoint to invalidate the tokens immediately.

```typescript
// apps/merchant/src/routes/oauth.ts logic
oauth.post('/revoke', async (c) => {
  const body = await c.req.parseBody();
  const token = body['token'] as string;
  
  const db = getDb(c.var.db);
  const tokenHash = await hashKey(token);
  
  // Delete both access and refresh tokens associated with this hash
  await db.run(
    `DELETE FROM oauth_tokens WHERE access_token_hash = ? OR refresh_token_hash = ?`,
    [tokenHash, tokenHash]
  );
  
  return c.json({ revoked: true });
});
```

## Discovery and Metadata

To facilitate automatic configuration for AI agents and OAuth libraries, Fufuni exposes a metadata endpoint at `.well-known/oauth-authorization-server`. This endpoint provides the URLs for authorization, token exchange, and the supported scopes.

  "revocation_endpoint": "https://your-store.com/oauth/revoke",
  "response_types_supported": ["code"],
  "grant_types_supported": ["authorization_code", "refresh_token"],

  "scopes_supported": [
