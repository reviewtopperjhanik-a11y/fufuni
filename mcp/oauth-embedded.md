## Embedded OAuth Server Reference
The Fufuni embedded OAuth server is a distinct entity from the main Auth0 instance, designed to expose the Fufuni API to third-party applications without sharing sensitive `sk_` keys. This allows for secure authorization and authentication of third-party apps, while maintaining the security and integrity of the Fufuni platform.

### Difference from Auth0
The main difference between the embedded OAuth server and the main Auth0 instance is the level of access and control. The Auth0 instance is used for authentication and authorization of first-party applications, whereas the embedded OAuth server is specifically designed for third-party applications. This separation ensures that sensitive information, such as `sk_` keys, is not shared with third-party apps, while still allowing them to access the Fufuni API.

### Authorization Code Flow for Third-Party Apps
The authorization code flow is used for third-party apps to obtain an access token to the Fufuni API. The flow is as follows:

1. The third-party app redirects the user to the Fufuni authorization endpoint (`/oauth/authorize`) with the required parameters, such as `client_id`, `redirect_uri`, `response_type`, `scope`, and `state`.
2. The user is prompted to authenticate and authorize the third-party app.
3. Upon successful authorization, the Fufuni server redirects the user back to the third-party app with an authorization code.
4. The third-party app exchanges the authorization code for an access token by sending a request to the Fufuni token endpoint (`/oauth/token`).
5. The access token is then used to access the Fufuni API.

### Scopes and Limitations
The scopes available for third-party OAuth clients are a subset of Auth0 permissions. The available scopes are defined in the `VALID_SCOPES` array and include:

* `openid`
* `profile`
* `ucp:scopes:checkout_session`
* `ucp:scopes:order`
* `ucp:scopes:identity`
* `checkout`
* `orders.read`
* `orders.write`
* `addresses.read`
* `addresses.write`

These scopes are limited compared to Auth0 permissions to ensure that third-party apps only have access to the necessary data and functionality.

### Example Code
To obtain an access token using the authorization code flow, a third-party app would make the following request:
```typescript
import axios from 'axios';

const clientId = 'your_client_id';
const redirectUri = 'https://your-app.com/callback';
const scope = 'openid profile';
const state = 'your_state';

const authUrl = `https://your-fufuni-instance.com/oauth/authorize?client_id=${clientId}&redirect_uri=${redirectUri}&response_type=code&scope=${scope}&state=${state}`;

// Redirect the user to the authorization endpoint
window.location.href = authUrl;

// Handle the redirect and exchange the authorization code for an access token
axios.post('https://your-fufuni-instance.com/oauth/token', {
  grant_type: 'authorization_code',
  code: 'authorization_code_here',
  redirect_uri: redirectUri,
  client_id: clientId,
})
  .then((response) => {
    const accessToken = response.data.access_token;
    // Use the access token to access the Fufuni API
  })
  .catch((error) => {
    console.error(error);
  });
```
Note that this is a simplified example and you should handle errors and implement additional security measures in your production application.
