## Embedded OAuth Server Reference
The Embedded OAuth Server is a distinct OAuth server from the main Auth0 instance, designed to expose the Fufuni API to third-party apps without sharing sensitive `sk_` keys. This allows for secure integration with external services while maintaining control over access to the Fufuni platform.

### Difference from Auth0
The main difference between the Embedded OAuth Server and the main Auth0 instance is its purpose and scope. While Auth0 handles authentication and authorization for the entire Fufuni platform, the Embedded OAuth Server is specifically designed for exposing the Fufuni API to third-party apps. This separation ensures that sensitive `sk_` keys are not shared with external services, enhancing the overall security of the platform.

## Authorization Code Flow
The Embedded OAuth Server implements the `authorization_code` flow for third-party apps. This flow involves the following steps:

1. **Client Registration**: The third-party app registers with the Embedded OAuth Server, providing a unique `client_id` and `redirect_uri`.
2. **Authorization Request**: The third-party app redirects the user to the Embedded OAuth Server's authorization endpoint, specifying the `client_id`, `redirect_uri`, `response_type`, and `scope`.
3. **User Authorization**: The user is prompted to authorize the third-party app, selecting the scopes they wish to grant access to.
4. **Authorization Code**: After authorization, the Embedded OAuth Server redirects the user back to the third-party app with an authorization code.
5. **Token Request**: The third-party app exchanges the authorization code for an access token by sending a request to the Embedded OAuth Server's token endpoint.

### Authorization Code Flow Example
```typescript
// Third-party app redirects user to Embedded OAuth Server
const clientId = 'third-party-app-client-id';
const redirectUri = 'https://third-party-app.com/callback';
const responseType = 'code';
const scope = 'openid profile';
const state = 'third-party-app-state';

const authorizationUrl = `https://fufuni-api.com/oauth/authorize?
  client_id=${clientId}&
  redirect_uri=${redirectUri}&
  response_type=${responseType}&
  scope=${scope}&
  state=${state}`;

// User is redirected to authorization URL, grants access, and is redirected back to third-party app
// with authorization code
const authorizationCode = 'authorization-code-from-embedded-oauth-server';

// Third-party app exchanges authorization code for access token
const tokenUrl = 'https://fufuni-api.com/oauth/token';
const tokenRequest = {
  grant_type: 'authorization_code',
  code: authorizationCode,
  redirect_uri: redirectUri,
  client_id: clientId,
};

// Send token request to Embedded OAuth Server
fetch(tokenUrl, {
  method: 'POST',
  headers: { 'Content-Type': 'application/x-www-form-urlencoded' },
  body: new URLSearchParams(tokenRequest),
})
  .then((response) => response.json())
  .then((tokenResponse) => {
    const accessToken = tokenResponse.access_token;
    // Use access token to access Fufuni API
  });
```

## Scopes
The Embedded OAuth Server has a limited set of scopes compared to the main Auth0 instance. The available scopes are:

* `openid`
* `profile`
* `ucp:scopes:checkout_session`
* `ucp:scopes:order`
* `ucp:scopes:identity`
* `checkout`
* `orders.read`
* `orders.write`
* `addresses.read`
* `addresses.write`

These scopes are a subset of the permissions available in Auth0, ensuring that third-party apps only have access to the necessary resources and data.

### Scope Example
```typescript
// Third-party app requests access to specific scopes
const scope = 'openid profile ucp:scopes:checkout_session';

// Embedded OAuth Server will only grant access to the requested scopes
const authorizationUrl = `https://fufuni-api.com/oauth/authorize?
  client_id=${clientId}&
  redirect_uri=${redirectUri}&
  response_type=${responseType}&
  scope=${scope}&
  state=${state}`;
```
