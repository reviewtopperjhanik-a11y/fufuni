## Supported Locales and Architecture

Fufuni uses `i18next` with a custom HTTP backend loader optimized for Vite and Cloudflare. The framework currently supports six locales by default. Each locale requires a dedicated JSON file containing flat key-value pairs.

### Locale File Locations
All translation files are stored in the `apps/client/src/locales/base/` directory:
- `en-US.json` (English - **Primary Source**)
- `fr-FR.json` (French)
- `es-ES.json` (Spanish)
- `zh-CN.json` (Chinese Simplified)
- `ar-SA.json` (Arabic - **RTL**)
- `he-IL.json` (Hebrew - **RTL**)

### Language Configuration
Languages are defined in `apps/client/src/i18n.ts` within the `availableLanguages` array.

```typescript
// apps/client/src/i18n.ts
export interface AvailableLanguage {
  code: string; 
  nativeName: string;
  isRTL: boolean;
  isDefault?: boolean;
}

export const availableLanguages: AvailableLanguage[] = [
  { code: "en-US", nativeName: "English", isRTL: false, isDefault: true },
  { code: "fr-FR", nativeName: "Français", isRTL: false },
  // ... other languages
  { code: "ar-SA", nativeName: "العربية", isRTL: true },
];
```

Due to Vite's static analysis requirements for assets, the `loadPath` function in `i18n.ts` uses a manual `switch` statement to resolve locale URLs. When adding a new language, you must update this switch.

## Adding Translation Keys

Fufuni uses a flat JSON structure. Nesting objects in JSON is discouraged to maintain simplicity and ease of search.

### JSON Rules
1.  **Naming**: Use `kebab-case` for keys.
2.  **Context Prefixing**: Prefix keys with the module name (e.g., `admin-products-`, `cart-`, `checkout-`).
3.  **Master File**: Always add the key to `en-US.json` first.
4.  **Interpolation**: Use double curly braces `{{var}}` for dynamic values.

### Example Key Structure
```json
{
  "product-tags-label": "Product Tags",
  "product-tags-count_one": "{{count}} tag applied",
  "product-tags-count_other": "{{count}} tags applied",
  "product-tags-placeholder": "Add a tag for {{productName}}..."
}
```

## Using the translation hook

The standard way to access translations is the `useTranslation` hook from `react-i18next`. 

### Basic Usage
```typescript
import { useTranslation } from "react-i18next";
import { Button } from "@heroui/react";

export const ActionButton = () => {
  const { t } = useTranslation();

  return (
    <Button>
      {t("admin-common-save")}
    </Button>
  );
};
```

### Interpolation and Plurals
The `t` function accepts an object as the second argument for variables. For pluralization, use the `count` property.

```typescript
import { useTranslation } from "react-i18next";

interface TagListProps {
  tags: string[];
}

export const TagList = ({ tags }: TagListProps) => {
  const { t } = useTranslation();

  return (
    <div>
      <h3>{t("admin-products-field-tags")}</h3>
      <p>
        {/* Will automatically choose between _one and _other keys based on count */}
        {t("product-tags-count", { count: tags.length })}
      </p>
    </div>
  );
};
```

## Handling RTL (Right-to-Left) Layouts

Fufuni handles RTL layouts automatically. When a user selects `ar-SA` or `he-IL`, the `isRTL` flag in the language configuration is detected.

### Implementation Detail
The `LanguageSwitch` component or the main application provider typically sets the `dir` attribute on the `<html>` or `<body>` tag based on `i18n.dir()`.

### CSS/Styling RTL
HeroUI (v3) and Tailwind CSS handle RTL via logical properties. Instead of using `ml-4` (margin-left), use `ms-4` (margin-start). Instead of `pr-2` (padding-right), use `pe-2` (padding-end).

```tsx
import { useTranslation } from "react-i18next";

export const RTLComponent = () => {
  const { i18n } = useTranslation();
  const isRTL = i18n.dir() === 'rtl';

  return (
    <div className="flex items-center gap-2">
      {/* 'ms-2' adds margin to the left in LTR, and to the right in RTL */}
      <span className="ms-2 font-bold">
        {isRTL ? "هذا نص عربي" : "This is English text"}
      </span>
    </div>
  );
};
```

## Worked Example: Product Tags Feature

In this example, we add a new "Tags" feature to the product management screen.

### 1. Update `en-US.json`
Add the keys to the base locale file.

```json
{
  "admin-products-tags-title": "Product Organization",
  "admin-products-tags-label": "Tags",
  "admin-products-tags-placeholder": "Type tag and press enter...",
  "admin-products-tags-hint": "Maximum 5 tags allowed for {{name}}"
}
```

### 2. Update `fr-FR.json`
Add the translated values.

```json
{
  "admin-products-tags-title": "Organisation du produit",
  "admin-products-tags-label": "Étiquettes",
  "admin-products-tags-placeholder": "Tapez une étiquette et appuyez sur entrée...",
  "admin-products-tags-hint": "Maximum 5 étiquettes autorisées pour {{name}}"
}
```

### 3. Implement in Component
Create the React component using the new keys.

```typescript
import React from "react";
import { useTranslation } from "react-i18next";
import { Input, Card, CardHeader, CardBody } from "@heroui/react";

interface ProductTagsProps {
  productName: string;
}

export const ProductTagsManager: React.FC<ProductTagsProps> = ({ productName }) => {
  const { t } = useTranslation();

  return (
    <Card className="max-w-md">
      <CardHeader className="flex flex-col items-start px-4 pt-4">
        <p className="text-tiny uppercase font-bold text-default-400">
          {t("admin-products-tags-title")}
        </p>
        <h4 className="font-bold text-large">
          {t("admin-products-tags-label")}
        </h4>
      </CardHeader>
      <CardBody>
        <Input
          label={t("admin-products-tags-label")}
          placeholder={t("admin-products-tags-placeholder")}
          description={t("admin-products-tags-hint", { name: productName })}
          variant="bordered"
          className="w-full"
        />
      </CardBody>
    </Card>
  );
};
```
