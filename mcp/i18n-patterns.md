## Supported Locales and Structure

Fufuni uses `i18next` with a JSON-based backend for translations. The application currently supports six locales, categorized by their direction and region. All translation files are stored in `apps/client/src/locales/base/`.

### Locale Mapping
| Code | Language | Direction | File Path |
| :--- | :--- | :--- | :--- |
| `en-US` | English (US) | LTR | `src/locales/base/en-US.json` |
| `fr-FR` | Français | LTR | `src/locales/base/fr-FR.json` |
| `es-ES` | Español | LTR | `src/locales/base/es-ES.json` |
| `zh-CN` | 中文 (简体) | LTR | `src/locales/base/zh-CN.json` |
| `ar-SA` | العربية | **RTL** | `src/locales/base/ar-SA.json` |
| `he-IL` | עברית | **RTL** | `src/locales/base/he-IL.json` |

### Configuration File
The `apps/client/src/i18n.ts` file is the source of truth for supported languages. If you add a new language, you must update the `availableLanguages` array and the `loadPath` switch statement.

```typescript
// apps/client/src/i18n.ts snippet
export const availableLanguages: AvailableLanguage[] = [
  { code: "en-US", nativeName: "English", isRTL: false, isDefault: true },
  { code: "ar-SA", nativeName: "العربية", isRTL: true },
  // ... other languages
];
```

## Adding Translation Keys

Fufuni follows a **Master Language** approach. `en-US.json` is the authoritative source. When adding a feature, you must first add the key to the English file, then propagate it to others.

### JSON Rules
1.  **Naming Convention**: Use `kebab-case` for keys.
2.  **Flat Structure**: Avoid deep nesting; use prefixes to group keys (e.g., `admin-products-`).
3.  **Interpolation**: Use double curly braces `{{variable}}` for dynamic content.
4.  **Pluralization**: Append `_one` or `_other` to the key for count-based translations.

### Example Key Definition
```json
{
  "product-tags-title": "Product Tags",
  "product-tags-count_one": "{{count}} tag assigned",
  "product-tags-count_other": "{{count}} tags assigned",
  "product-tags-deleted-success": "Tag {{tagName}} was successfully removed"
}
```

## Using Translations in Components

To access translations in React components, use the `useTranslation` hook from `react-i18next`.

### Basic Usage
```tsx
import { useTranslation } from "react-i18next";
import { Button } from "@heroui/react";

export const TagButton = () => {
  const { t } = useTranslation();

  return (
    <Button>
      {t("admin-products-btn-add-variant")}
    </Button>
  );
};
```

### Interpolation and Plurals
When handling counts or variables, pass an options object as the second argument to `t()`.

```tsx
import { useTranslation } from "react-i18next";

interface TagListProps {
  tags: string[];
}

export const TagList = ({ tags }: TagListProps) => {
  const { t } = useTranslation();

  return (
    <div>
      <h3>{t("admin-products-field-tags")}</h3>
      <p>
        {/* Automatically picks _one or _other based on count */}
        {t("product-tags-count", { count: tags.length })}
      </p>
    </div>
  );
};
```

## Handling Right-to-Left (RTL) Languages

RTL support for Arabic (`ar-SA`) and Hebrew (`he-IL`) is handled at the configuration level. When a user selects an RTL language, the `isRTL: true` flag in `availableLanguages` triggers layout shifts.

### Layout Direction
The application usually wraps the main content in a container that detects the current language's direction. Most HeroUI (formerly NextUI) components handle RTL automatically if the `dir="rtl"` attribute is set on the `<html>` or a parent `div`.

```tsx
// Example of accessing direction in a custom component
import { useTranslation } from "react-i18next";
import { availableLanguages } from "../i18n";

export const DirectionalComponent = () => {
  const { i18n } = useTranslation();
  const currentLang = availableLanguages.find(l => l.code === i18n.language);
  const isRTL = currentLang?.isRTL ?? false;

  return (
    <div className={isRTL ? "pr-4" : "pl-4"}>
      {/* Custom spacing logic for RTL vs LTR */}
    </div>
  );
};
```

## Worked Example: Product Tags Feature

This example demonstrates adding a "Product Tags" management feature requiring three new translation keys.

### 1. Update the Master Locale
Add the keys to `apps/client/src/locales/base/en-US.json`.

```json
{
  "admin-products-tags-label": "Product Tags",
  "admin-products-tags-placeholder": "Enter tags separated by commas...",
  "admin-products-tags-empty": "No tags assigned to this product"
}
```

### 2. Implement the Component
Create a component that utilizes these keys.

```tsx
import React from "react";
import { useTranslation } from "react-i18next";
import { Input, Chip } from "@heroui/react";

interface TagManagerProps {
  tags: string[];
  onTagsChange: (tags: string[]) => void;
}

export const TagManager: React.FC<TagManagerProps> = ({ tags, onTagsChange }) => {
  const { t } = useTranslation();

  const handleKeyDown = (e: React.KeyboardEvent<HTMLInputElement>) => {
    if (e.key === "Enter") {
      const val = e.currentTarget.value.trim();
      if (val && !tags.includes(val)) {
        onTagsChange([...tags, val]);
        e.currentTarget.value = "";
      }
    }
  };

  return (
    <div className="flex flex-col gap-2">
      <label className="text-small font-medium">
        {t("admin-products-tags-label")}
      </label>
      
      <Input
        placeholder={t("admin-products-tags-placeholder")}
        onKeyDown={handleKeyDown}
        variant="bordered"
      />

      <div className="flex flex-wrap gap-2 mt-2">
        {tags.length > 0 ? (
          tags.map((tag) => (
            <Chip key={tag} onClose={() => onTagsChange(tags.filter(t => t !== tag))}>
              {tag}
            </Chip>
          ))
        ) : (
          <span className="text-tiny text-default-400">
            {t("admin-products-tags-empty")}
          </span>
        )}
      </div>
    </div>
  );
};
```

### 3. Verification
Switch the language to French or Arabic via the `LanguageSwitch` component. If the key is not yet translated in `fr-FR.json`, i18next will fallback to the `en-US` value automatically because `en-US` is defined as the `fallbackLng` in `i18n.init`.
