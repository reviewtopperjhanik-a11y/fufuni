## Internationalisation (i18n) Architecture

Fufuni uses a robust internationalisation system built on `i18next`, `react-i18next`, and `i18next-http-backend`. The architecture is designed to support high-performance serverless environments by loading only the necessary locale chunks on demand.

### Supported Locales

The framework currently supports six locales. These are defined in `apps/client/src/i18n.ts` within the `availableLanguages` array.

| Locale Code | Language | Direction | File Path |
|:---|:---|:---|:---|
| `en-US` | English | LTR | `src/locales/base/en-US.json` |
| `fr-FR` | Français | LTR | `src/locales/base/fr-FR.json` |
| `es-ES` | Español | LTR | `src/locales/base/es-ES.json` |
| `zh-CN` | 中文 | LTR | `src/locales/base/zh-CN.json` |
| `ar-SA` | العربية | RTL | `src/locales/base/ar-SA.json` |
| `he-IL` | עברית | RTL | `src/locales/base/he-IL.json` |

### Configuration File

The `apps/client/src/i18n.ts` file is the central point of configuration. It handles language detection (via `localStorage`), fallback logic, and the manual loading paths required by Vite's build system.

```typescript
// apps/client/src/i18n.ts (Partial snippet)
import i18n from "i18next";
import { initReactI18next } from "react-i18next";
import i18nextHttpBackend from "i18next-http-backend";

export const availableLanguages = [
  { code: "en-US", nativeName: "English", isRTL: false, isDefault: true },
  { code: "fr-FR", nativeName: "Français", isRTL: false },
  // ... other languages
  { code: "ar-SA", nativeName: "العربية", isRTL: true },
];

i18n
  .use(i18nextHttpBackend)
  .use(initReactI18next)
  .init({
    lng: localStorage.getItem("preferredLanguage") || "en-US",
    fallbackLng: "en-US",
    ns: ["base"],
    defaultNS: "base",
    backend: {
      loadPath: (lng, ns) => {
        // Manual resolution for Vite asset bundling
        if (ns[0] === "base") {
          switch (lng[0]) {
            case "fr-FR": return new URL("./locales/base/fr-FR.json", import.meta.url).toString();
            case "ar-SA": return new URL("./locales/base/ar-SA.json", import.meta.url).toString();
            default: return new URL("./locales/base/en-US.json", import.meta.url).toString();
          }
        }
        return new URL("./locales/base/en-US.json", import.meta.url).toString();
      },
    },
  });

export default i18n;
```

## Adding New Translation Keys

When adding features, you must ensure all text is translatable. Fufuni follows strict conventions for key naming and file structure.

### Key Naming Conventions
- **Format**: Use `kebab-case`.
- **Prefixing**: Scope keys by feature or page (e.g., `admin-products-field-sku`).
- **Hierarchy**: Use flat JSON structures. Do not nest objects within the translation files.

### Step-by-Step workflow
1.  **Edit the Master File**: Always add the key to `apps/client/src/locales/base/en-US.json` first.
2.  **Add Translations**: Add the same key to the other five JSON files (`fr-FR`, `es-ES`, etc.).
3.  **Update i18n.ts**: If you are adding a completely new language (not just a key), you must update the `availableLanguages` array and the `switch` statement in `loadPath`.

### JSON Structure Example
```json
{
  "admin-products-title": "Products",
  "admin-products-btn-add": "Add Product",
  "product-card-tax-included": "Includes {{name}}"
}
```

## Using i18n in React Components

Fufuni uses the `useTranslation` hook from `react-i18next`.

### Basic Usage
The `t` function is used to retrieve strings. **Never pass a default value to the `t()` function** (e.g., `t('key', 'Default')`). If a key is missing, it should fallback to the `en-US` definition automatically via the i18next configuration.

```typescript
import { useTranslation } from "react-i18next";
import { Button } from "@heroui/react";

export const ProductHeader = () => {
  const { t } = useTranslation();

  return (
    <div className="flex justify-between items-center">
      <h2>{t("admin-products-title")}</h2>
      <Button color="primary">
        {t("admin-products-btn-add")}
      </Button>
    </div>
  );
};
```

### Interpolation and Pluralization
Keys can accept dynamic variables using double curly braces `{{variable}}`.

**JSON Definition:**
```json
{
  "admin-webhooks-attempt": "{{count}} attempt",
  "admin-webhooks-attempt_plural": "{{count}} attempts"
}
```

**Component Implementation:**
```typescript
const { t } = useTranslation();
const attempts = 3;

// i18next handles pluralization based on the count variable
return (
  <span>{t("admin-webhooks-attempt", { count: attempts })}</span>
);
```

## Handling RTL (Right-to-Left)

Languages like Arabic (`ar-SA`) and Hebrew (`he-IL`) require the layout to flip. Fufuni handles this via the `isRTL` flag in the configuration.

### How RTL works in Fufuni
1.  The `LanguageSwitch` component updates the `preferredLanguage` in `localStorage`.
2.  The `i18n.on('languageChanged')` event (or initial load) checks the `isRTL` property of the current language.
3.  The framework sets `document.dir = "rtl"` and `document.documentElement.lang = code`.
4.  HeroUI (v3) and Tailwind CSS classes like `ms-2` (margin-start) and `pe-4` (padding-end) automatically adjust.

### RTL-Safe CSS
Always use logical properties instead of directional ones:
- Use `ps-*` (padding-start) instead of `pl-*` (padding-left).
- Use `me-*` (margin-end) instead of `mr-*` (margin-right).
- Use `text-start` instead of `text-left`.

```typescript
// Component layout that is RTL-safe
<div className="flex items-center gap-2">
  <span className="ms-auto">{t("total")}</span> {/* margin-left in LTR, margin-right in RTL */}
  <div className="ps-4 border-s">Content</div>  {/* border-left in LTR, border-right in RTL */}
</div>
```

## Worked Example: Product Tags Feature

In this example, we will add a "Product Tags" feature. This requires three keys: a label for the input, a placeholder, and a helper text.

### 1. Update Locale Files

Add the following to `apps/client/src/locales/base/en-US.json`:

```json
{
  "admin-products-tags-label": "Product Tags",
  "admin-products-tags-placeholder": "Enter tags (comma separated)...",
  "admin-products-tags-helper": "Tags help customers find products via search."
}
```

Then add the French equivalents in `apps/client/src/locales/base/fr-FR.json`:

```json
{
  "admin-products-tags-label": "Étiquettes de produit",
  "admin-products-tags-placeholder": "Entrez les étiquettes (séparées par des virgules)...",
  "admin-products-tags-helper": "Les étiquettes aident les clients à trouver des produits via la recherche."
}
```

### 2. Implement in Component

Create a specialized input component for product tags using HeroUI components.

```typescript
import React from "react";
import { useTranslation } from "react-i18next";
import { Input } from "@heroui/react";
import { TagIcon } from "@heroicons/react/24/outline";

interface ProductTagsProps {
  value: string;
  onChange: (value: string) => void;
}

/**
 * ProductTags component demonstrates the use of prefixed kebab-case keys
 * and logical CSS properties for RTL compatibility.
 */
export const ProductTags: React.FC<ProductTagsProps> = ({ value, onChange }) => {
  const { t } = useTranslation();

  return (
    <div className="w-full py-4">
      <Input
        label={t("admin-products-tags-label")}
        placeholder={t("admin-products-tags-placeholder")}
        description={t("admin-products-tags-helper")}
        value={value}
        onValueChange={onChange}
        variant="bordered"
        labelPlacement="outside"
        startContent={
          // Use 'me-2' for spacing to support LTR and RTL
          <TagIcon className="w-4 h-4 text-default-400 me-2" />
        }
        classNames={{
          // Logical text alignment
          input: "text-start",
          label: "font-semibold"
        }}
      />
    </div>
  );
};
```

### 3. Usage in Admin View

Finally, integrate the component into the product management form.

### Summary Table for Developers

| Rule | Description |
|:---|:---|
| **Master Source** | English (`en-US.json`) is the authoritative source. |
| **No Default Value** | Do not provide a fallback string in the `t()` function call. |
| **Kebab Case** | All JSON keys must be `feature-sub-action` style. |
| **Logical CSS** | Use `s` (start) and `e` (end) classes instead of `l` (left) and `r` (right). |
| **Vite Bundle** | Any new namespace or language requires a manual `new URL()` entry in `i18n.ts`. |
