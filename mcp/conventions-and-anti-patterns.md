## Backend Development: Routes, Schemas, and DB

Fufuni backend architecture relies on Hono with Zod-OpenAPI for strict type safety and Cloudflare Durable Objects (SQLite) for stateful data storage. Adhering to validation and migration standards is non-negotiable for system stability.

### Request Validation & Route Definition

**DON'T:** Use `c.req.json()` or `c.req.query()` directly inside a Hono handler. This bypasses the OpenAPI documentation and type safety, leading to runtime errors.
**DON'T:** Define Zod schemas inline within your route files.

**DO:** Use `createRoute()` from `@hono/zod-openapi` and retrieve validated data via `c.req.valid("json")` or `c.req.valid("param")`. Always import schemas from the centralized directory.

```typescript
// apps/merchant/src/routes/products/update-product.ts

import { createRoute } from "@hono/zod-openapi";
import { ProductSchema } from "../../schemas/product-schemas"; // Correct: Centralized schema
import { getDb } from "../../utils/db";

export const updateProductRoute = createRoute({
  method: "post",
  path: "/v1/products/{id}",
  request: {
    params: ProductIdParams,
    body: {
      content: {
        "application/json": {
          schema: ProductSchema,
        },
      },
    },
  },
  responses: {
    200: { description: "Product updated" },
  },
});

// Handler Implementation
// DON'T: const body = await c.req.json(); 
// DO:
export const updateProductHandler = async (c: any) => {
  const { id } = c.req.valid("param");
  const body = c.req.valid("json"); 
  const db = getDb(c.env);
  
  await db.run("UPDATE products SET name = ? WHERE id = ?", [body.name, id]);
  return c.json({ success: true });
};
```

### Database Queries and Multi-Region Context

**DON'T:** Use Drizzle ORM or attempt to find a `db/queries.ts` file. Fufuni uses raw SQL for maximum performance and control within Durable Objects.
**DON'T:** Select prices directly from a `variants` table.

**DO:** Use the `getDb()` utility to access the SQLite interface and always join with `variant_prices` to ensure the correct currency and region data is used.

```typescript
// Correct pattern for fetching price-aware data
async function getProductWithPrice(db: SQLiteDatabase, productId: string, regionCode: string) {
  const sql = `
    SELECT 
      v.id, 
      v.sku, 
      vp.amount, 
      vp.currency 
    FROM variants v
    INNER JOIN variant_prices vp ON v.id = vp.variant_id
    INNER JOIN regions r ON vp.region_id = r.id
    WHERE v.product_id = ? AND r.code = ?
  `;
  
  // Use .query<T> for fetch, .run() for mutations
  return await db.query(sql, [productId, regionCode]);
}
```

### Migrations and Schema Updates

**DON'T:** Modify an existing SQL migration file or the `migrations` array entry once it has been deployed.
**DON'T:** Simply update the `SCHEMA` constant in `do.ts` and assume existing stores will update.

**DO:** Add a new migration object to the `ensureInitialized` method in `do.ts` and create a corresponding file in `apps/merchant/migrations/`.

```typescript
// apps/merchant/src/do.ts

async function ensureInitialized() {
  const migrations = [
    { name: "0001_initial", sql: INITIAL_SQL },
    { 
      name: "0002_add_discount_code", 
      sql: "ALTER TABLE orders ADD COLUMN discount_code TEXT;" 
    } // ALWAYS append to the end
  ];

  for (const m of migrations) {
    const applied = await this.db.query("SELECT name FROM migrations WHERE name = ?", [m.name]);
    if (applied.length === 0) {
      await this.db.run(m.sql);
      await this.db.run("INSERT INTO migrations (name) VALUES (?)", [m.name]);
    }
  }
}
```

## Frontend Engineering: React 19 & HeroUI

The Fufuni frontend is optimized for speed and compatibility with AI-assisted development (Artifacts).

### API Communication and Authentication

**DON'T:** Use standard `fetch` with manually attached headers or `localStorage.getItem("token")`.
**DON'T:** Call the Auth0 Management API directly from the browser (this exposes secrets).

**DO:** Use the `useSecuredApi()` hook which automatically injects JWTs and handles CSRF. For Auth0 management tasks, use the backend proxy endpoints.

```typescript
// apps/client/src/hooks/use-product-actions.ts
import { useSecuredApi } from "./use-secured-api";

export const useProductActions = () => {
  const api = useSecuredApi();

  const updateStock = async (variantId: string, quantity: number) => {
    // DO: The hook handles authorization headers automatically
    const response = await api.post(`/v1/inventory/${variantId}`, {
      json: { quantity }
    });
    return response.json();
  };

  const updateUserInfo = async (data: any) => {
    // DO: Use the proxy for Auth0 actions
    return await api.patch("/v1/__auth0/user", { json: data });
  };

  return { updateStock, updateUserInfo };
};
```

## Infrastructure: Secrets and Webhooks

Security and consistency across environments (Development, Preview, Production) are maintained through strict secret management.

### Environment Variables & Secrets

**DON'T:** Expose Stripe Secret Keys (`sk_...`) or Auth0 Client Secrets to the frontend code or the `wrangler.toml` (unless encrypted).
**DON'T:** Update the database state for a refund without verifying the event via the Stripe API.

**DO:** Use `pk_...` (Publishable Keys) only on the frontend. Process all sensitive operations (Refunds, Payouts) via backend services that verify signatures.

```typescript
// apps/merchant/src/routes/webhooks/stripe.ts

export const handleStripeWebhook = async (c: any) => {
  const signature = c.req.header("stripe-signature");
  const body = await c.req.text();
  
  // DO: Always verify the event via Stripe library before touching the DB
  const event = await stripe.webhooks.constructEventAsync(
    body, 
    signature, 
    c.env.STRIPE_WEBHOOK_SECRET
  );

  if (event.type === "charge.refunded") {
    const charge = event.data.object;
    // Perform DB update ONLY after verification
    const db = getDb(c.env);
    await db.run("UPDATE orders SET status = 'refunded' WHERE stripe_id = ?", [charge.id]);
  }
  
  return c.json({ received: true });
};
```
