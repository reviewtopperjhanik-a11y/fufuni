## Backend Development Standards

Backend logic in Fufuni is strictly governed by Type Safety and Contract-First design. All routes must be defined using `hono/zod-openapi` to ensure the generated documentation and TypeScript types remain synchronized.

### Route Validation and Schema Management

**DON'T:** Define Zod schemas inline within the route file or use `c.req.json()` to parse request bodies. This bypasses the OpenAPI documentation layer and makes schemas non-reusable.

```typescript
// ❌ WRONG: Inline schema and unsafe body parsing
import { Hono } from 'hono';
import { z } from 'zod';

const app = new Hono();
app.post('/v1/products', async (c) => {
  const body = await c.req.json(); // Type is 'any', no validation
  const result = z.object({ name: z.string() }).safeParse(body);
  // ...
});
```

**DO:** Define schemas in `apps/merchant/src/schemas/` and use `createRoute()` from `@hono/zod-openapi`. Always use `c.req.valid("json")` (or "param", "query") to access validated data.

```typescript
// ✅ CORRECT: Schema imported and used in createRoute
// apps/merchant/src/schemas/product.schema.ts
import { z } from '@hono/zod-openapi';
export const CreateProductSchema = z.object({
  name: z.string().openapi({ example: 'Wireless Mouse' }),
  price: z.number().positive()
});

// apps/merchant/src/routes/products.ts
import { createRoute } from '@hono/zod-openapi';
import { CreateProductSchema } from '../schemas/product.schema';

export const createProductRoute = createRoute({
  method: 'post',
  path: '/v1/products',
  request: {
    body: { content: { 'application/json': { schema: CreateProductSchema } } },
  },
  responses: {
    200: { description: 'Product created', content: { 'application/json': { schema: CreateProductSchema } } }
  }
});

// Implementation
app.openapi(createProductRoute, async (c) => {
  const data = c.req.valid('json'); // Fully typed as CreateProductSchema
  return c.json(data, 200);
});
```

### Multi-Region Pricing Queries

Fufuni is designed for global e-commerce. Prices are not static properties of a variant but are scoped to specific regions.

**DON'T:** Query price directly from the `variants` table. This field is deprecated or used only as a fallback and will fail in multi-currency environments.

```sql
-- ❌ WRONG: Ignoring the regional context
SELECT v.id, v.price 
FROM variants v 
WHERE v.id = 'var_123';
```

**DO:** Join with the `variant_prices` table and filter by `region_id`.

```typescript
// ✅ CORRECT: Joining with region prices in apps/merchant/src/db/queries.ts
import { sql } from 'drizzle-orm';

export const getVariantWithPrice = async (db: any, variantId: string, regionId: string) => {
  return await db.prepare(`
    SELECT 
      v.id, 
      v.sku, 
      vp.amount, 
      vp.currency_code 
    FROM variants v
    INNER JOIN variant_prices vp ON v.id = vp.variant_id
    WHERE v.id = ? AND vp.region_id = ?
  `).bind(variantId, regionId).first();
};
```

## Frontend Development Conventions

Fufuni's frontend leverages React 19 and HeroUI (formerly NextUI) v3. All data fetching must be authenticated and type-safe.

### API Requests and Authentication

**DON'T:** Manually attach JWT tokens to fetch headers or use `localStorage` to manage session state. Fufuni components run in environments (like AI artifacts) where `localStorage` is restricted.

```typescript
// ❌ WRONG: Manual token handling and localStorage
const token = localStorage.getItem('token');
const res = await fetch('/api/v1/orders', {
  headers: { 'Authorization': `Bearer ${token}` }
});
```

**DO:** Use the `useSecuredApi()` hook. This hook automatically retrieves the current session, injects the necessary Authorization headers, and provides a pre-configured instance of the Fufuni API client.

```typescript
// ✅ CORRECT: Using the useSecuredApi hook
import { useSecuredApi } from '@/hooks/use-secured-api';
import { useQuery } from '@tanstack/react-query';

export const OrderList = () => {
  const api = useSecuredApi();

  const { data, isLoading } = useQuery({
    queryKey: ['orders'],
    queryFn: async () => {
      const response = await api.v1.orders.$get();
      if (!response.ok) throw new Error('Failed to fetch');
      return response.json();
    }
  });

  if (isLoading) return <Spinner />;
  return <div>{/* Render logic */}</div>;
};
```

## Infrastructure and Security

Security boundaries between the frontend and backend are strictly enforced to prevent sensitive key leakage.

### Stripe Integration and Secrets

**DON'T:** Use Stripe Secret Keys (`sk_...`) in any frontend code or component. Never process a refund by manually updating a database row status to `refunded`.

```typescript
// ❌ WRONG: Leaking secret keys and bypassing external state
const stripe = new Stripe('sk_test_123...'); // NEVER on frontend
await db.update(orders).set({ status: 'refunded' }); // DB update before Stripe call
```

**DO:** Only use Publishable Keys (`pk_...`) on the frontend. Process refunds through a backend route that calls the Stripe API first. Only update the local database once the Stripe API call succeeds (or via a Webhook).

```typescript
// ✅ CORRECT: Backend Stripe logic (apps/merchant/src/routes/payments.ts)
import Stripe from 'stripe';

app.post('/v1/payments/refund', async (c) => {
  const { orderId, amount } = c.req.valid('json');
  const stripe = new Stripe(c.env.STRIPE_SECRET_KEY);

  // 1. Initiate Stripe Refund
  const refund = await stripe.refunds.create({
    payment_intent: orderId,
    amount: amount,
  });

  // 2. Update DB only after successful external call
  if (refund.status === 'succeeded') {
    await updateOrderInDB(orderId, { status: 'refunded' });
  }
  
  return c.json({ success: true });
});
```

### External API Proxies (Auth0)

**DON'T:** Call the Auth0 Management API directly from the client. This requires an Administrative token that cannot be safely stored in a browser.

**DO:** Use the built-in Fufuni proxy endpoints starting with `/v1/__auth0/`. These routes are protected by backend-level authorization checks.

