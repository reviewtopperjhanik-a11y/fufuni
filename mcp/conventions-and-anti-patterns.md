## CONVENTIONS

### Unified Database Access via getDb helper
Route handlers must never interact with the environment binding directly; instead, use the `getDb` helper with the context variable. This ensures that the Drizzle ORM instance is correctly scoped to the current Durable Object transaction.

### Dual-Sync Migration Protocol
Every schema change requires two updates: a new `.sql` file in `apps/merchant/migrations/` for CI/CD and an update to the `ensureInitialized()` function in `do.ts` for local/runtime initialization. This redundancy guarantees that the SQLite schema remains consistent across all Durable Object instances.

### Integer-Based Monetary Storage
All currency values must be stored and processed as integers representing the smallest unit (e.g., cents for USD, yen for JPY). Floating-point math is strictly forbidden for financial calculations to prevent rounding errors.

### Static ApiError Helpers for Consistency
Use the `ApiError` static methods to terminate requests with standard HTTP status codes and formatted JSON responses. This standardizes error structures across the backend and allows the frontend to parse error messages predictably.

### Standardized i18n Key Provisioning
New translation keys must be added to `en-US.json` first as the source of truth before being propagated to other locales. Code must use the `t('key')` function, and the build will fail if a key is missing from the master English file.

### Admin Route Protection via Guards
All administrative routes in the frontend must be wrapped with the `AuthenticationGuardWithPermission` component. This ensures that users are not only authenticated but also possess the specific scoped permission required for that view.

### MCP Knowledge Management Workflow
When adding major features, you must create or update topic files in `apps/mcp/knowledge/topics/` and run `npm run mcp:generate:force`. This ensures the AI context remains synchronized with the evolving codebase.

### Environment Variable Synchronization
Any new backend environment variable must be added to `.github/workflows/create-env-artifact.yaml`. This ensures that the CI/CD pipeline correctly injects necessary secrets and configuration during the deployment to Cloudflare.

```typescript
import { Hono } from 'hono';
import { zValidator } from '@hono/zod-validator';
import { z } from 'zod';
import { getDb } from '@/db/client';
import { products } from '@/db/schema';
import { ApiError } from '@/utils/errors';
import { eq } from 'drizzle-orm';

const app = new Hono<{ Variables: { db: D1Database } }>();

// Convention: Use Zod for validation and getDb for data access
app.patch(
  '/api/admin/products/:id/price',
  zValidator('json', z.object({
    // Convention: Monetary values are integers (cents)
    priceInCents: z.number().int().positive(),
  })),
  async (c) => {
    const id = c.req.param('id');
    const { priceInCents } = c.req.valid('json');
    const db = getDb(c.var.db);

    const product = await db.select()
      .from(products)
      .where(eq(products.id, id))
      .get();

    if (!product) {
      // Convention: Use ApiError helper instead of raw throw
      throw ApiError.notFound('Product not found');
    }

    await db.update(products)
      .set({ price: priceInCents })
      .where(eq(products.id, id))
      .run();

    return c.json({ success: true });
  }
);
```

## ANTI-PATTERNS

### Forbidden use of onClick on Buttons
Never use the standard `onClick` event on HeroUI or React Aria interactive elements. You must use `onPress` to ensure proper touch-device handling, keyboard accessibility, and consistency with the framework's internal event system.

### Deprecated variant="bordered"
The `bordered` variant is no longer supported in HeroUI v3. Use `variant="outline"` instead for outlined components to maintain visual consistency and avoid console warnings.

### Illegal radius Prop on Buttons
Do not use the `radius` prop directly on the `Button` component. All rounding logic must be applied via Tailwind CSS utility classes (e.g., `className="rounded-full"`) to keep the design system centralized.

### Misuse of useEffect for State Synchronization
Never use `useEffect` to synchronize state when one state depends on another or on a prop. Use React Query for server state and derived state (via `useMemo`) for UI logic to prevent unnecessary re-renders and race conditions.

### Direct Storage of Auth0 Tokens
Do not store Auth0 access tokens in `localStorage` or `sessionStorage`. The Auth0 React SDK handles tokens in memory; storing them in persistent browser storage creates a Cross-Site Scripting (XSS) vulnerability.

### Raw Auth0 Management API Calls
Never invoke the Auth0 Management API directly from the frontend. Always route these requests through the `getAuth0ManagementToken()` helper or a backend proxy to avoid exposing administrative tokens to the client.

### Direct Manipulation of user_metadata
Avoid adding business-critical fields to Auth0 `user_metadata`. This storage is reserved for client-managed preferences like UI themes or wishlists; core entity data (roles, organization links) belongs in the SQLite database.

### Vulnerable dangerouslySetInnerHTML Usage
Do not use `dangerouslySetInnerHTML` outside of the shared `renderDescription()` helper. The backend sanitizes HTML before storage, and the helper provides a safe, consistent way to render that content without exposing the app to XSS.
