## CONVENTIONS

### Standard Database Access and Context
Always use the `getDb(c.var.db)` utility to interact with the SQLite database within Hono route handlers. You must never access `c.env.MERCHANT` directly for database operations to ensure that the request context and Durable Object bindings are handled correctly.

```typescript
import { Hono } from 'hono';
import { getDb } from '@/db/client';
import { products } from '@/db/schema';
import { eq } from 'drizzle-orm';

const app = new Hono<{ Variables: { db: D1Database } }>();

app.get('/products/:id', async (c) => {
  const id = c.req.param('id');
  // CORRECT: Using getDb with the context variable
  const db = getDb(c.var.db);
  
  const product = await db.select().from(products).where(eq(products.id, id)).get();
  return c.json(product);
});
```

### Dual-Entry Database Migrations
New database schema changes must be added to two locations: the `.sql` migration file for initial provisioning and the `ensureInitialized()` function in `do.ts` to handle the schema evolution of existing Durable Objects.

```sql
-- apps/merchant/migrations/0002_add_discount_code.sql
ALTER TABLE products ADD COLUMN discount_code TEXT;
```

```typescript
// apps/merchant/src/do.ts
async function ensureInitialized(db: DrizzleDb) {
  // Check for column existence and run migration logic manually for DO instances
  const tableInfo = await db.run(sql`PRAGMA table_info(products)`);
  const hasDiscountColumn = tableInfo.results.some(col => col.name === 'discount_code');
  
  if (!hasDiscountColumn) {
    await db.run(sql`ALTER TABLE products ADD COLUMN discount_code TEXT`);
  }
}
```

### Monetary Value Storage
Monetary values must always be stored as integers representing the smallest currency unit (e.g., cents for USD, pennies for GBP). Never use floats or decimals in the database or backend logic to avoid precision errors.

```typescript
import { z } from '@hono/zod-openapi';

// Schema defining price in cents
export const ProductSchema = z.object({
  id: z.string(),
  name: z.string(),
  // price_cents: 1000 = $10.00
  price_cents: z.number().int().positive(),
});

// Logic example
const calculateTotal = (price: number, quantity: number): number => {
  return price * quantity; // Results in 2000 (cents), not 20.00 (dollars)
};
```

### Standardized Error Handling
Use the `ApiError` static helpers for all expected error states in the backend. Throwing raw errors or returning custom JSON objects for errors breaks the consistent error response contract expected by the frontend.

```typescript
import { createRoute } from '@hono/zod-openapi';
import { ApiError } from '@/utils/errors';

app.openapi(
  createRoute({
    method: 'get',
    path: '/orders/{id}',
    responses: {
      404: { description: 'Order not found' },
    },
  }),
  async (c) => {
    const orderId = c.req.param('id');
    const order = await findOrder(orderId);

    if (!order) {
      // CORRECT: Use the built-in helper
      throw ApiError.notFound(`Order with ID ${orderId} not found`);
    }

    return c.json(order, 200);
  }
);
```

### Admin Route Protection


### Internationalization (i18n) Workflow
All new translation keys must be added to `en-US.json` first as the master source of truth. After adding the key to the master file, it can be added to other locale files; the `t()` function must only use keys that exist in the master file.

```json
// apps/web/src/locales/en-US.json
{
  "cart": {
    "checkout_button": "Proceed to Checkout",
    "empty_message": "Your cart is currently empty."
  }
}
```

```tsx
import { useTranslation } from 'react-i18next';

export const CartSummary = () => {
  const { t } = useTranslation();
  
  // CORRECT: Key matches the structure in en-US.json
  return <Button>{t('cart.checkout_button')}</Button>;
};
```

## ANTI-PATTERNS

### Forbidden Event Handlers in HeroUI
Never use the standard HTML `onClick` attribute on interactive components like `Button` or `Card`. HeroUI v3 uses React Aria under the hood, which requires `onPress` to properly handle touch events, focus management, and accessibility.

```tsx
import { Button } from '@heroui/react';

export const MyComponent = () => {
  // INCORRECT: <Button onClick={() => ...}>
  
  // CORRECT: Always use onPress
  return (
    <Button onPress={() => console.log('Pressed!')}>
      Click Me
    </Button>
  );
};
```

### Invalid Component Props
Do not use `variant="bordered"` or the `radius` prop on HeroUI components. `variant="bordered"` was removed in v3 in favor of `variant="outline"`, and radius should be controlled via Tailwind utility classes to maintain design system consistency.

```tsx
import { Button } from '@heroui/react';

export const MyButton = () => {
  // INCORRECT: <Button variant="bordered" radius="md">
  
  // CORRECT: Use outline and Tailwind classes
  return (
    <Button variant="outline" className="rounded-md">
      Confirm
    </Button>
  );
};
```

### Manual State Synchronization
Never use `useEffect` to synchronize local state with server data or props. This leads to "flash of old content" and race conditions; instead, use React Query to manage server state and derive UI state directly from query data.

```tsx
// INCORRECT: Synchronizing via useEffect
// const [items, setItems] = useState([]);
// useEffect(() => { setItems(data); }, [data]);

// CORRECT: Derive state or use useMemo
const { data: products = [] } = useQuery({ queryKey: ['products'], queryFn: fetchProducts });

const featuredProducts = useMemo(() => 
  products.filter(p => p.isFeatured), 
[products]);
```

### Insecure Token Management
Never store Auth0 access tokens in `localStorage` or `sessionStorage`. The Auth0 React SDK handles tokens in memory for security; persisting them to storage exposes the application to XSS-based token theft.

```typescript
// INCORRECT:
// localStorage.setItem('access_token', token);

// CORRECT: Use the SDK hook
import { useAuth0 } from '@auth0/auth0-react';

const MyApiCall = () => {
  const { getAccessTokenSilently } = useAuth0();
  
  const callApi = async () => {
    const token = await getAccessTokenSilently();
    // Use token in headers
  };
};
```

### Direct Management API Calls
Never call the Auth0 Management API directly from the frontend using raw credentials. All Management API interactions must be proxied through a backend helper or use the `getAuth0ManagementToken()` utility to prevent leaking administrative tokens.

```typescript
// INCORRECT: Fetching a token manually via client secret in frontend code

// CORRECT: Use the internal helper that handles the secure exchange
import { getAuth0ManagementToken } from '@/utils/auth0-admin';

export const updateUserSettings = async (userId: string, data: any) => {
  const token = await getAuth0ManagementToken(); // Internal secure fetch
  // ... proceed with backend-initiated call
};
```

### Hardcoded Permissions
Never hardcode permission strings as raw strings in your components. Always use the `import.meta.env.PERMISSIONS` object (frontend) or the verified permissions array from the JWT (backend) to ensure consistency and easier refactoring.

```tsx
// INCORRECT: if (user.permissions.includes('admin:write'))

// CORRECT:
import { PERMISSIONS } from '@/constants/permissions';

const hasAccess = user.permissions.includes(import.meta.env.PERMISSIONS.WRITE_PRODUCTS);
```

### Raw HTML Injection
Do not use `dangerouslySetInnerHTML` for content rendering unless specifically using the `renderDescription()` helper. The Fufuni backend sanitizes all user-generated HTML (like product descriptions) before storage; the helper ensures this remains safe.

```tsx
// INCORRECT: <div dangerouslySetInnerHTML={{ __html: product.description }} />

// CORRECT:
import { renderDescription } from '@/utils/security';

const ProductInfo = ({ description }: { description: string }) => {
  return (
    <div className="prose">
      {renderDescription(description)}
    </div>
  );
};
```

### Unauthorized Metadata Usage
Avoid adding complex business logic fields to the Auth0 `user_metadata`. This storage is reserved for client-managed UI preferences (e.g., dark mode, collapsed sidebar) and wishlists. All core identity, role, and transaction data must reside in the SQLite database.

```typescript
// INCORRECT: Storing "total_spent" or "order_count" in user_metadata

// CORRECT: 
// SQLite 'users' table stores order history and totals.
// user_metadata stores: { "theme": "dark", "sidebar_collapsed": true }
```

### Standard File Inputs in Admin
Never use a plain `<input type="file">` for image uploads in admin forms. You must use the `ImageUploadInput` component which handles the integration with the CDN, generates necessary thumbnails, and returns the correct URL structure for the database.
