### Core Backend Logic and Database Access
All database operations within Fufuni’s Cloudflare Workers must use the `getDb` helper. Never access the SQLite database binding directly via `c.env.MERCHANT`. This abstraction ensures that Drizzle ORM or raw query runners are properly initialized with the correct Durable Object instance context.

```typescript
import { Hono } from 'hono';
import { getDb } from '../db/client';
import { ApiError } from '../utils/errors';
import { products } from '../db/schema';
import { eq } from 'drizzle-orm';

const app = new Hono<{ Variables: { db: D1Database } }>();

app.get('/products/:id', async (c) => {
  // CORRECT: Using the getDb helper with the context variable
  const db = getDb(c.var.db);
  const id = c.req.param('id');
  
  const product = await db.select().from(products).where(eq(products.id, id)).get();
  
  if (!product) {
    // CORRECT: Using ApiError static helpers
    throw ApiError.notFound(`Product with ID ${id} not found`);
  }
  
  return c.json(product);
});
```

## ANTI-PATTERNS (WHAT YOU MUST NOT DO)

### Forbidden Frontend State Management
**NEVER use `useEffect` to synchronize or derive state.**
Using `useEffect` for state synchronization causes unnecessary re-renders, race conditions, and makes the data flow hard to trace. Instead, use React Query for server state and standard JavaScript variable derivation for UI state.

```tsx
// BAD: Synchronization via useEffect
const [total, setTotal] = useState(0);
useEffect(() => {
  setTotal(items.reduce((acc, item) => acc + item.price, 0));
}, [items]);

// GOOD: Derived state
const total = useMemo(() => items.reduce((acc, item) => acc + item.price, 0), [items]);
```

### Improper Token Handling
**NEVER store the Auth0 access token in `localStorage` or `sessionStorage`.**
Storing tokens in persistent browser storage makes the application vulnerable to XSS attacks. The Auth0 React SDK handles tokens in memory. If you need to make a request, use the SDK's `getAccessTokenSilently()` method.

**NEVER call the Auth0 Management API directly from the frontend.**
Exposing Management API tokens in the browser is a severe security risk. Always route these requests through a backend helper or use the `getAuth0ManagementToken()` utility on the server side.

### Invalid HeroUI Prop Patterns
**NEVER use `variant="bordered"` or the `radius` prop on Buttons.**
HeroUI v3 has deprecated `variant="bordered"` in favor of `variant="outline"`. Similarly, the `radius` prop is often inconsistent with the design system; Fufuni enforces Tailwind classes for layout and border-radius consistency.

```tsx
// BAD
<Button variant="bordered" radius="md">Old Way</Button>

// GOOD
<Button variant="outline" className="rounded-md">New Way</Button>
```

### Backend "Raw" Access and Floating Point Money
**NEVER store prices as floats.**
Floats (e.g., `19.99`) lead to rounding errors during calculations (e.g., `0.1 + 0.2 !== 0.3`). Always use integers (cents) and perform division only at the final display layer.

**NEVER access `c.env` variables directly in route business logic.**
Accessing environment bindings like `c.env.MERCHANT` directly bypasses our DI (Dependency Injection) layer and makes unit testing significantly harder. Always use the provided middleware variables and helpers like `getDb(c.var.db)`.

### Bypassing Sanitization
**DO NOT use `dangerouslySetInnerHTML` outside of the `renderDescription()` helper.**
Fufuni provides a specific utility for rendering sanitized HTML content. Using the raw React prop directly bypasses security checks and risks XSS if the content was not properly handled.

```tsx
// BAD
<div dangerouslySetInnerHTML={{ __html: product.description }} />

// GOOD
import { renderDescription } from "@/utils/render";
return <div>{renderDescription(product.description)}</div>;
```

### Hardcoded Permissions
**NEVER hardcode permission strings in components.**
Permission strings are environment-specific and should be managed via constants or environment variables. Hardcoding `"admin:write"` throughout the app makes it impossible to update the permission structure without a full code refactor.

```tsx
// BAD
if (user.permissions.includes("admin:all")) { ... }

// GOOD
import { PERMISSIONS } from "@/constants/auth";
if (user.permissions.includes(PERMISSIONS.ADMIN_WRITE)) { ... }
```
