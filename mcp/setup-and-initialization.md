## Setup & Initialization Overview
The setup and initialization process for a Fufuni store involves several key steps and endpoints. This reference will guide you through the first-time store setup flow, config table management, migration management, database reset, and security considerations.

### First-time Store Setup Flow
The first-time store setup flow involves the following steps:

1. **Initialize API keys**: Send a `POST` request to `/v1/setup/init` with an array of API key objects. This endpoint creates the first API key pair and is idempotent, returning a `409` error if API keys already exist.
2. **Connect Stripe**: Send a `POST` request to `/v1/setup/stripe` with a Stripe secret key and optional webhook secret. This endpoint validates the Stripe secret key via an API call and stores it in the config table.
3. **Seed data**: After initializing the API keys and connecting Stripe, seed data can be added to the store.

### Config Table
The config table stores key-value pairs for configurable settings. The following endpoints are used to manage the config table:

* **GET /v1/setup/config**: Returns all config entries, masking sensitive values such as Stripe keys.
* **POST /v1/setup/stripe**: Updates the Stripe secret key and optional webhook secret in the config table.

To add a new configurable setting, follow the config table pattern:

### Migration Management
Migrations are managed via the following endpoints:

* **GET /v1/setup/migrations/list**: Returns all rows from the migrations table, including the name and applied_at timestamp.
* **POST /v1/setup/migrations/run**: Re-executes the `ensureInitialized()` function to apply any pending migrations.
* **POST /v1/setup/migrations/clean**: Deletes all rows from the migrations table.

### Database Reset
The database reset endpoint (`POST /v1/setup/reset`) wipes all data and re-runs schema initialization. This endpoint requires the `databaseAdminOnly` permission and should **never** be exposed in production without IP restriction.

### Security Warning
The setup routes must be protected at the network level in production, as they are used before any admin account exists. Use Cloudflare Access or an IP allowlist to restrict access to these endpoints.

### Example Use Cases
```bash
# Initialize API keys
curl -X POST \
  https://example.com/v1/setup/init \
  -H 'Content-Type: application/json' \
  -d '[{"id": "pk_123", "key_hash": "hash_123", "key_prefix": "prefix_123", "role": "admin"}]'

# Connect Stripe
curl -X POST \
  https://example.com/v1/setup/stripe \
  -H 'Content-Type: application/json' \
  -d '{"stripe_secret_key": "sk_123", "stripe_webhook_secret": "whsec_123"}'

# Get config values
curl -X GET \
  https://example.com/v1/setup/config

# Update config value
curl -X POST \
  https://example.com/v1/my-config \
  -H 'Content-Type: application/json' \
  -d '{"mySetting": "new value"}'
```
