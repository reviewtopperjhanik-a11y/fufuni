## Supported Token Types

Fufuni's `authMiddleware` acts as a multi-protocol gateway. It identifies the requester based on the structure and content of the `Authorization: Bearer <token>` header.

| Token Type | Identification Logic | Validation Method |
| :--- | :--- | :--- |
| **Auth0 JWT** | 3 segments separated by dots; does not start with `sk_` or `pk_`. | Verified against the Auth0 JWKS. Requires specific permission claims (e.g., `admin:store`). |
| **Admin API Key** | Starts with `sk_` (Secret Key). | SHA-256 hashed and compared against the `api_keys` table in the Durable Object SQLite database. |
| **OAuth Token** | Exactly 64 characters, lowercase hexadecimal. | SHA-256 hashed and compared against the `oauth_tokens` table. Scopes are checked via `requireScope`. |

## AuthRole Values and Assignment

The `AuthRole` (defined in `apps/merchant/src/types.ts`) determines the level of access granted to a request. A single Auth0 JWT can grant multiple roles simultaneously if the user possesses multiple permissions.

- `public`: Default for unauthenticated requests or routes using public keys (`pk_`).
- `admin`: Assigned if the token contains the `admin:store` permission (or the value of `ADMIN_STORE_PERMISSION` env).
- `oauth`: Assigned to valid 64-char hex tokens.
- `authadmin`: Assigned if the token contains `auth0:admin:api` (Superadmin role).
- `databaseadmin`: Assigned if the token contains `admin:database`.
- `aiadmin`: Assigned if the token contains `ai:api`.
- `mail`: Assigned if the token contains `mail:api`.
- `customer`: Assigned by `customerAuthMiddleware` for standard users without administrative permissions.

## Backend RBAC Guards

Guards are Hono middleware that should be placed *after* `authMiddleware` or `customerAuthMiddleware`. They inspect the `c.var.auth` object and throw an `ApiError.forbidden()` (403) if the criteria are not met.

| Guard | Required Role/Permission | Typical Use Case |
| :--- | :--- | :--- |
| `adminOnly` | `admin` (`admin:store`) | Managing products, orders, and general store settings. |
| `superAdminOnly` | `authadmin` (`auth0:admin:api`) | Accessing Auth0 Management API tokens or user list. |
| `databaseAdminOnly` | `databaseadmin` (`admin:database`) | Direct SQL execution or database backup/restore routes. |
| `aiAccessOnly` | `aiadmin` (`ai:api`) | Configuring AI models and translation parameters. |
| `mailAccessOnly` | `mail` (`mail:api`) | Managing email templates and SMTP/Mailgun configuration. |
| `validJwtAuthOnly` | Any valid Auth0 JWT | Generic verification that the user is logged in via Auth0. |

### Example: Protecting Storefront Admin Routes

This example demonstrates how to compose middleware to protect a standard admin endpoint.

```typescript
import { Hono } from 'hono';
import { authMiddleware, adminOnly } from '../middleware/auth';
import { ApiError, type HonoEnv } from '../types';

const app = new Hono<HonoEnv>();

// Apply authMiddleware to all routes in this router
app.use('*', authMiddleware);

app.get('/products', adminOnly, async (c) => {
  const db = c.get('db');
  const products = await db.query('SELECT * FROM products', []);
  return c.json({ data: products });
});

app.post('/products', adminOnly, async (c) => {
  const auth = c.get('auth');
  // API keys and JWTs both populate c.var.auth
  console.log(`Action performed by role: ${auth.role}`);
  
  // Implementation...
  return c.json({ success: true }, 201);
});

export default app;
```

### Example: Superadmin and the Management API

Fufuni caches Auth0 Management API tokens to prevent hitting rate limits. Only users with the `authadmin` role can request these tokens.

```typescript
import { Hono } from 'hono';
import { authMiddleware, superAdminOnly } from '../middleware/auth';
import type { HonoEnv } from '../types';

const app = new Hono<HonoEnv>();

/**
 * Returns a Management API token. 
 * Requires 'auth0:admin:api' permission in the bearer JWT.
 */
app.get('/v1/__auth0/token', authMiddleware, superAdminOnly, async (c) => {
  const { getManagementToken } = await import('../lib/auth0');
  
  // This helper handles internal KV caching of the M2M token
  const token = await getManagementToken(
    c.env.AUTH0_DOMAIN!,
    c.env.AUTH0_CLIENT_ID!,
    c.env.AUTH0_CLIENT_SECRET!
  );

  return c.json({ access_token: token });
});
```

## Customer Authentication

The `customerAuthMiddleware` is specialized for the `/v1/me/*` endpoints. Unlike the standard `authMiddleware`, it rejects API keys (`sk_`) and focuses on identifying the specific user via the `sub` (Subject) claim.

```typescript
import { Hono } from 'hono';
import { customerAuthMiddleware } from '../middleware/customer-auth';
import type { HonoEnv } from '../types';

const app = new Hono<HonoEnv>();

app.get('/v1/me/profile', customerAuthMiddleware, async (c) => {
  const auth = c.get('auth');
  
  // auth.sub contains the Auth0 user ID (e.g., 'auth0|12345')
  // auth.role is always 'customer' here
  return c.json({
    id: auth.sub,
    email: auth.email,
    metadata: auth.user_metadata
  });
});
```

## Frontend Guard Patterns

### Route Protection with `AuthenticationGuard`

Use `AuthenticationGuard` in your router configuration (typically in `App.tsx` or a dedicated routes file) to force a redirect to Auth0 if the user is not logged in.

```tsx

  element: <AuthenticationGuard component={DashboardPage} />
```

### Hooks: `useAuth` vs `useSecuredApi`

- **`useAuth()`**: Provides synchronous state about the session. Use `isAuthenticated` to check if a user is logged in at all.
- **`useSecuredApi()`**: Provides the `hasPermission(permission: string)` helper. This is asynchronous because it may need to refresh or inspect the current access token.

```typescript
import { useAuth } from './hooks/useAuth';
import { useSecuredApi } from './hooks/useSecuredApi';

const ProductActions = () => {
  const { isAuthenticated, user } = useAuth();
  const { hasPermission } = useSecuredApi();
  const [canDelete, setCanDelete] = useState(false);

  useEffect(() => {
    if (isAuthenticated) {
      hasPermission('admin:store').then(setCanDelete);
    }
  }, [isAuthenticated, hasPermission]);

  if (!isAuthenticated) return null;

  return (
    <div>
      <p>Hello, {user?.name}</p>
      {canDelete && <button>Delete Product</button>}
    </div>
  );
};
```

## OAuth Scope Validation

For third-party integrations using the 64-char hex tokens, use the `requireScope` factory to enforce granular access control.

```typescript
import { authMiddleware, requireScope } from '../middleware/auth';

// Only allows OAuth tokens that have the 'orders:read' scope
app.get(
  '/external/orders', 
  authMiddleware, 
  requireScope('orders:read'), 
  async (c) => {
    const auth = c.get('auth');
    // For OAuth tokens, auth.oauthScopes is an array of strings
    return c.json({ orders: [] });
  }
);
```
