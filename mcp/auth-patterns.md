## Authentication Patterns
### Token Types
The Fufuni e-commerce framework accepts three token types for authentication:

1. **Auth0 JWT**: A three-part JSON Web Token (JWT) issued by Auth0, which must contain the `admin:store` permission (or a configurable permission) to grant admin access.
2. **sk_ API key**: A database-stored API key with a `sk_` prefix, used for server-to-server authentication.
3. **OAuth hex token**: A 64-character hexadecimal token used for scoped API access.

### Auth Roles
The following Auth Roles are assigned based on the token type and permissions:

* `public`: unauthenticated or public-key request
* `admin`: Admin API key or Auth0 token with `admin:store` permission
* `oauth`: OAuth API key with specific scopes
* `authadmin`: token with `admin:auth0` permission
* `databaseadmin`: token with `admin:database` permission
* `aiadmin`: token with AI permission
* `mail`: token with `mail:api` permission
* `customer`: Auth0 token with no specific admin permission

### Backend RBAC Guards
The following table summarizes the available RBAC guards, the role they check, and typical use cases:

| Guard | Role | Use Case |
| --- | --- | --- |
| `adminOnly` | `admin` or `roles.includes('admin')` | Protect admin-only routes |
| `superAdminOnly` | `authadmin` | Protect super admin-only routes (e.g., Management API token) |
| `databaseAdminOnly` | `databaseadmin` | Protect database admin-only routes |
| `aiAccessOnly` | `aiadmin` | Protect AI-related routes |
| `mailAccessOnly` | `mail` | Protect mail-related routes |
| `validJwtAuthOnly` | any valid JWT | Protect routes requiring valid JWT authentication |

### Protecting Routes with authMiddleware and adminOnly

```typescript
import { authMiddleware, adminOnly } from '../middleware/auth';

export const app = new Hono();

app.get('/admin/dashboard', authMiddleware, adminOnly, async (c) => {
  // Only admins can access this route

```

```typescript

export const app = new Hono();

app.get('/v1/__auth0/token', superAdminOnly, async (c) => {
  // Only super admins can access this route to obtain a Management API token
```


## Frontend Authentication
### Authentication Guard Components
The following components are used to protect frontend routes and conditionally render UI based on authentication and permissions:

* `AuthenticationGuard`: Protects a whole page/component and redirects to login if not authenticated.
* `AuthenticationGuardWithPermission`: Conditionally shows UI based on a specific Auth0 permission.
* `hasPermission(permission)`: Asynchronously checks if the current user's token contains a specific Auth0 permission string.
* `isAuthenticated`: Synchronously checks if the user is logged in.

### Login Modal
Use `LoginModal` instead of redirecting to Auth0 when you want to provide a local login experience with email/passwordless and social login options.

### Users and Permissions Page
The `UsersAndPermissionsPage` (/admin/users-and-permissions) allows admins to manage Auth0 user permissions from the storefront UI without going to the Auth0 dashboard.

## Verified Facts
The following facts are verified and authoritative:

* Auth0 is the sole identity provider, and RBAC (roles/permissions) is managed exclusively in the Auth0 dashboard.
* The three token types accepted by `authMiddleware` are Auth0 JWT, sk_ API key, and OAuth hex token.
* The available RBAC guards are `adminOnly`, `superAdminOnly`, `databaseAdminOnly`, `aiAccessOnly`, `mailAccessOnly`, and `validJwtAuthOnly`.
* `superAdminOnly` is required to reach the GET /v1/__auth0/token endpoint, which returns a cached Auth0 Management API token.
* `customerAuthMiddleware` validates the JWT but does not require `admin:store` permission for customer-facing endpoints.
* On the frontend, use `AuthenticationGuard` to protect pages/components and `AuthenticationGuardWithPermission` to conditionally render UI based on permissions.
