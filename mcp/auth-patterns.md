## Authentication Patterns
The Fufuni e-commerce framework utilizes Auth0 as its sole identity provider, and Role-Based Access Control (RBAC) is managed exclusively in the Auth0 dashboard. This section provides a comprehensive overview of authentication patterns for both backend middleware and frontend guards.

### Token Types and AuthRole Values
The framework accepts three token types:
1. **Auth0 JWT**: a three-part Bearer token that must include the permission set in `ADMIN_STORE_PERMISSION` env var (default "admin:store").
2. **sk_ API key**: a hashed lookup in the `api_keys` table.
3. **64-char lowercase hex OAuth token**: a lookup in the `oauth_tokens` table.

The `AuthRole` values are:
* "public"
* "admin"
* "oauth"
* "authadmin"
* "databaseadmin"
* "aiadmin"
* "mail"
* "customer"

These roles are stored in `c.var.auth.role` after the middleware runs.

### Backend RBAC Guards
The framework provides the following RBAC guards in `apps/merchant/src/middleware/auth.ts`:
| Guard | Role | Auth0 Permission | Typical Use Case |
| --- | --- | --- | --- |
| `adminOnly` | "admin" | "admin:store" | Admin dashboard |
| `superAdminOnly` | "authadmin" | "auth0:admin:api" | GET /v1/__auth0/token |
| `databaseAdminOnly` | "databaseadmin" | "admin:database" | Database management |
| `aiAccessOnly` | "aiadmin" | "ai:api" | AI-related routes |
| `mailAccessOnly` | "mail" | "mail:api" | Mail-related routes |
| `validJwtAuthOnly` | - | - | Any valid Auth0 JWT |

### Backend Code Examples

### Frontend Authentication Guards
The framework provides the following frontend authentication guards:
* `AuthenticationGuard` (prop: `component={MyComponent}`): protects a whole page and redirects to login if not authenticated.
* `AuthenticationGuardWithPermission` (props: `permission="admin:store"`, `children`, `fallback?`): conditionally shows UI based on a specific Auth0 permission.
* `hasPermission(permission)` from `useSecuredApi()`: checks asynchronously whether the current user's access token contains a specific Auth0 permission string.
* `isAuthenticated` from `useAuth()`: a synchronous boolean indicating whether the user is logged in.

### Frontend Code Examples
#### Using AuthenticationGuard
```typescript
import { AuthenticationGuard } from '../guards/AuthenticationGuard';

const MyComponent = () => {
  // Only authenticated users can access this component
  return <div>Hello, User!</div>;
};

const App = () => {
  return (
    <AuthenticationGuard component={MyComponent} />
  );
};
```

#### Using AuthenticationGuardWithPermission

### LoginLogoutLink and LoginButton
Use `LoginLogoutLink` or `LoginButton` instead of redirecting to Auth0 when you want to provide a seamless login experience for your users.

### UsersAndPermissionsPage
The `UsersAndPermissionsPage` (`/admin/users-and-permissions`) allows admins to manage Auth0 user permissions from the storefront UI without going to the Auth0 dashboard.

### requireScope Factory
The `requireScope` factory is used to create OAuth-scoped routes. It checks whether the current user's access token contains the required scopes.

```typescript
import { requireScope } from '../middleware/oauth';

export const route = {
  method: 'GET',
  path: '/v1/orders',
  handler: [
    requireScope('read:orders'),
    (c) => {
      // Only users with the 'read:orders' scope can access this route
      return 'Orders';
    },
  ],
};
```
