## Authentication Patterns
This reference covers both backend middleware and frontend guards for authentication in the Fufuni e-commerce framework.

### Token Types
The framework accepts three token types:
1. **Auth0 JWT**: A three-part Bearer token that must include the permission set in the `ADMIN_STORE_PERMISSION` environment variable (default: "admin:store").
2. **sk_ API key**: A database API key that is hashed and stored in the `api_keys` table.
3. **64-char lowercase hex OAuth token**: An OAuth token that is stored in the `oauth_tokens` table.

### AuthRole Values
The `AuthRole` type has the following values:
* "public"
* "admin"
* "oauth"
* "authadmin"
* "databaseadmin"
* "aiadmin"
* "mail"
* "customer"

The role is stored in `c.var.auth.role` after the middleware runs.

### Backend RBAC Guards
The following RBAC guards are available in `apps/merchant/src/middleware/auth.ts`:
| Guard | Role | Auth0 Permission | Typical Use Case |
| --- | --- | --- | --- |
| adminOnly | "admin" | "admin:store" | Admin-only routes |
| superAdminOnly | "authadmin" | "auth0:admin:api" | Super admin-only routes, e.g., `/v1/__auth0/token` |
| databaseAdminOnly | "databaseadmin" | "admin:database" | Database admin-only routes |
| aiAccessOnly | "aiadmin" | "ai:api" | AI admin-only routes |
| mailAccessOnly | "mail" | "mail:api" | Mail-only routes |
| validJwtAuthOnly | - | - | Routes that require a valid Auth0 JWT, no specific permission |
| requireScope | - | - | Routes that require a specific OAuth token scope |

### Code Examples: Backend
#### Protecting a Route with authMiddleware + adminOnly
```typescript
import { authMiddleware } from '../middleware/auth';
import { adminOnly } from '../middleware/auth';

const app = new Hono();

app.get('/admin-only', {
  middleware: [authMiddleware, adminOnly],
  handler: async (c) => {
    // Only admins can access this route
    return c.json({ message: 'Hello, admin!' });
  },
});
```

#### superAdminOnly and the /v1/__auth0/token Management API Endpoint
```typescript
import { authMiddleware } from '../middleware/auth';
import { superAdminOnly } from '../middleware/auth';

const app = new Hono();

app.get('/v1/__auth0/token', {
  middleware: [authMiddleware, superAdminOnly],
  handler: async (c) => {
    // Only super admins can access this route
    return c.json({ token: ' cached-auth0-management-api-token' });
  },
});
```

#### customerAuthMiddleware
```typescript
import { customerAuthMiddleware } from '../middleware/customer-auth';

const app = new Hono();

app.get('/v1/me', {
  middleware: [customerAuthMiddleware],
  handler: async (c) => {

  },

```

### Frontend: Authentication Guards
The following authentication guards are available:
* `AuthenticationGuard`: Protects a whole page and redirects to login if not authenticated.
* `AuthenticationGuardWithPermission`: Conditionally shows UI based on a specific Auth0 permission.
* `hasPermission(permission)`: Exposed by `useSecuredApi()`, checks asynchronously whether the current user's access token contains a specific Auth0 permission string.
* `isAuthenticated`: Exposed by `useAuth()`, a synchronous boolean indicating whether the user is logged in.

#### Example: Protecting a Page with AuthenticationGuard
```typescript
import { AuthenticationGuard } from '../components/AuthenticationGuard';

const App = () => {
  return (
    <div>
      <AuthenticationGuard component={MyComponent} />
    </div>
  );
};
```

#### Example: Conditionally Showing UI with AuthenticationGuardWithPermission
```typescript
import { AuthenticationGuardWithPermission } from '../components/AuthenticationGuardWithPermission';

const App = () => {
  return (
    <div>
      <AuthenticationGuardWithPermission
        permission="admin:store"
        children={<MyAdminComponent />}
        fallback={<MyFallbackComponent />}
      />
    </div>
  );
};
```

### Frontend: LoginLogoutLink and LoginButton
Use `LoginLogoutLink` or `LoginButton` instead of redirecting to Auth0 when you need to handle login and logout flows in your application.

### Frontend: UsersAndPermissionsPage
The `UsersAndPermissionsPage` allows admins to manage Auth0 user permissions from the storefront UI without going to the Auth0 dashboard.

### requireScope Factory
The `requireScope` factory is used to protect OAuth-scoped routes. It checks whether the current OAuth token has the required scope.
```typescript
import { requireScope } from '../middleware/auth';

const app = new Hono();

app.get('/v1/oauth-protected', {
  middleware: [requireScope('required-scope')],
  handler: async (c) => {
    // Only OAuth tokens with the required scope can access this route
    return c.json({ message: 'Hello, OAuth!' });
  },
});
```
