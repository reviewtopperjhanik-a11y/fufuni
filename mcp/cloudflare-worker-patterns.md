Cloudflare Worker Patterns
========================
### Accessing Bindings in a Route Handler
To access bindings in a route handler, use the following properties:
```typescript
c.env.MERCHANT
c.env.IMAGES
c.env.KV_CACHE
```
These properties provide access to the Merchant Durable Object, R2 bucket, and KV cache, respectively.

### The Durable Object Pattern
We use a single Durable Object instance to ensure data consistency and reliability. To get the stub, use the following code:
```typescript
const id = c.env.MERCHANT.idFromName('merchant');
const stub = c.env.MERCHANT.get(id);
```
To call a method on the Durable Object, use the `query()` or `run()` method:
```typescript
const result = await stub.query('methodName', 'arg1', 'arg2');
const result = await stub.run('methodName', 'arg1', 'arg2');
```
The `query()` method is used for read-only operations, while the `run()` method is used for write operations.

### KV Cache
The kv-cache middleware works by serving GET responses from the KV cache before hitting the Durable Object. The cache key is generated based on the full URL, including query parameters:
```typescript
cache:<full-url>
```
To invalidate the cache manually, use the `kvInvalidateMiddleware`:
```typescript
await kvInvalidateMiddleware(c);
```
This middleware purges all cache keys that match a prefix-based pattern.

### R2
Product images are stored and served from the R2 bucket. To upload an image, use the following code:
```typescript
const image = await c.env.IMAGES.put('image-name', imageBuffer);
```
To serve an image, use the following code:
```typescript
const image = await c.env.IMAGES.get('image-name');
```
### Secrets
The following secrets must be stored in Wrangler secrets:

* MAILGUN_API_KEY
* MAILGUN_DOMAIN
* MAILGUN_BASE_URL (default: https://api.mailgun.net)
* MAILGUN_USER (sender address)

The following secrets can be stored in the `.env` file:

* Any other environment variables not related to sensitive data

### Adding a New Binding
To add a new binding, follow these steps:

1. Update `wrangler.jsonc` to include the new binding:
```json
"bindings": [
  {
    "name": "NEW_BINDING",
    "class_name": "NewBindingDO"
  }
]
```
2. Update `worker-configuration.d.ts` to include the new binding:
```typescript
interface Env {
  NEW_BINDING: DurableObjectNamespace<import("./src/index").NewBindingDO>;
}
```
3. Update the `Env` type to include the new binding:
```typescript
interface Env {
  NEW_BINDING: DurableObjectNamespace<import("./src/index").NewBindingDO>;
}
```
### CI/CD
To expose a new variable to the frontend, add it to the `define` block in `vite.config.ts`:
```typescript
define: {
  'import.meta.env.VARIABLE_NAME': process.env.VARIABLE_NAME,
}
```
To map an environment variable to a GitHub secret, update `.github/workflows/create-env-artifact.yaml` to include the new variable:
```yaml
- name: Create Env Artifact
  uses: ./.github/workflows/create-env-artifact
  with:
    vars: |
      VARIABLE_NAME=${VARIABLE_NAME}
```
Note: Make sure to update the `create-env-artifact.yaml` file to include the new variable, otherwise it will be absent from CI deployments.
