## Cloudflare Worker Patterns
This reference guide provides an overview of common patterns and best practices for developing Cloudflare Workers, specifically for the Fufuni e-commerce framework.

### Accessing Bindings in a Route Handler
In a Cloudflare Worker route handler, you can access bindings using the `c.env` object. For example:

```typescript
export const GET = async (c: Context) => {
  const merchant = c.env.MERCHANT;
  const images = c.env.IMAGES;
  const kvCache = c.env.KV_CACHE;
  // Use the bindings as needed
};
```

### The Durable Object Pattern
Fufuni uses a single Durable Object instance for the Merchant. To get the stub, use the `c.env.MERCHANT.idFromName()` method:

```typescript
const merchantId = c.env.MERCHANT.idFromName('MERCHANT');
const stub = merchantId.stub;
```

You can then call methods on the stub using `query()` or `run()`:

```typescript
const result = await stub.query({ method: 'GET', path: '/products' });
// or
await stub.run({ method: 'POST', path: '/orders', body: 'orderData' });
```

### KV Cache
The `kvCacheMiddleware` (apps/merchant/src/middleware/kv-cache.ts) serves GET responses from KV before hitting the Durable Object. The cache key is generated based on the full URL, including query parameters.

To invalidate the cache manually, you can use the `kvInvalidateMiddleware` (apps/merchant/src/middleware/kv-invalidate.ts) which purges all cache keys with a specific prefix after a successful POST/PATCH/DELETE request.

### R2
Product images are stored and served using Cloudflare's R2 storage. To access R2, use the `c.env.IMAGES` binding:

```typescript
const images = c.env.IMAGES;
const imageUrl = await images.get('image-name');
// Use the image URL as needed
```

### Secrets
Secrets are managed using Wrangler secrets and .env files. Any secrets that should be accessible to the Worker should be added to Wrangler secrets, while secrets that should only be accessible to the frontend should be added to the .env file.

Mailgun secrets required for transactional emails include:

* `MAILGUN_API_KEY`
* `MAILGUN_DOMAIN`
* `MAILGUN_BASE_URL` (default: `https://api.mailgun.net`)
* `MAILGUN_USER` (sender address)

### Adding a New Binding
To add a new binding, follow these steps:

1. Add the binding to `wrangler.jsonc` using the `durable_objects` section or other relevant section.
2. Update `worker-configuration.d.ts` to include the new binding in the `Env` type.
3. Use the new binding in your Worker code, accessing it via `c.env.NEW_BINDING_NAME`.

### CI/CD
The CI/CD pipeline uses GitHub secrets to manage sensitive environment variables. To expose a new variable to the frontend, add it to the `.env` file and update the `vite.config.ts` define block to include the new variable.

```javascript
// vite.config.ts
import { defineConfig } from 'vite';
import { scopesArray } from './scopesArray';

export default defineConfig({
  // ...
  define: {
    'import.meta.env.PERMISSIONS': JSON.stringify(scopesArray),
    'import.meta.env.NEW_VAR': process.env.NEW_VAR,
  },
});
```

In your frontend code, you can then access the new variable using `import.meta.env.NEW_VAR`.
