## Accessing Bindings in Hono Routes

Fufuni uses Hono as its routing framework. All Cloudflare bindings (Durable Objects, R2 buckets, KV namespaces, and environment variables) are accessible through the context object (`c.env`). These bindings are typed via the `Env` interface generated in `worker-configuration.d.ts`.

When defining a route, you must ensure the Hono instance is aware of the `Env` type to provide autocompletion and type safety.

```typescript
import { Hono } from 'hono';

// The Env interface is typically defined in a shared types file 
// or generated by wrangler types
const app = new Hono<{ Bindings: Env }>();

app.get('/v1/system/status', async (c) => {
  // Accessing a simple variable
  const storeName = c.env.STORE_NAME;

  // Accessing a KV namespace
  const cachedData = await c.env.KV_CACHE.get('system:status');

  // Accessing an R2 bucket
  const image = await c.env.IMAGES.get('logo.png');

  return c.json({
    status: 'ok',
    store: storeName,
    hasCache: !!cachedData,
    hasLogo: !!image
  });
});
```

### Type Safety with Zod-OpenAPI

## The Durable Object SQLite Pattern

Fufuni centralizes state in a single Durable Object (DO) instance per merchant. This DO hosts an internal SQLite database, providing ACID compliance and consistent storage within the Cloudflare edge. We use a singleton pattern where all requests are routed to a DO instance named "default".

### Accessing the DO Stub
To interact with the SQLite database, you first obtain a stub for the "default" ID.

```typescript
/**
 * Utility to get the merchant singleton stub
 */
export const getMerchantStub = (env: Env) => {
  const id = env.MERCHANT.idFromName('default');
  return env.MERCHANT.get(id);
};

// Inside a route handler:
const stub = getMerchantStub(c.env);
```

### Query vs Run
The DO provides two primary entry points for data interaction:
1.  **`query()`**: Used for READ operations (`SELECT`).
2.  **`run()`**: Used for WRITE operations (`INSERT`, `UPDATE`, `DELETE`).

```typescript
// Reading data
const products = await stub.query('SELECT * FROM products WHERE status = ?', ['active']);

// Mutating data
const result = await stub.run(
  'INSERT INTO categories (id, name) VALUES (?, ?)',
  [crypto.randomUUID(), 'New Category']
);
```

## KV Cache and Cache Management

To reduce latency and lower Durable Object compute costs, Fufuni uses a multi-layered caching strategy. The `kvCacheMiddleware` handles automatic response caching for `GET` requests.

### TTL Configuration
Caching behavior is governed by environment variables defined in the `.env` and mapped to GitHub Secrets:
- `KV_CACHE_SEARCH_TTL_SECONDS`: Defaults to 300s (5 minutes) for search results.
- `KV_CACHE_REVIEWS_TTL_SECONDS`: Defaults to 600s (10 minutes) for product reviews.
- `KV_CACHE_DEFAULT_TTL_SECONDS`: Defaults to 3600s (1 hour) for general catalog data.

### Cache Middleware Logic
The middleware only caches `GET` requests. It automatically bypasses the cache if:
1.  The request method is not `GET`.
2.  The `Authorization` header contains an Admin JWT or a Secret Key (`sk_*`). Only Public Keys (`pk_*`) are served from cache.

```typescript
// apps/merchant/src/index.ts usage
import { kvCacheMiddleware } from './middleware/kv-cache';

const app = new Hono<{ Bindings: Env }>();

// Apply cache to catalog routes
app.use('/v1/products/*', kvCacheMiddleware);
app.use('/v1/categories/*', kvCacheMiddleware);
```

### Manual Invalidation
When data is updated, the cache must be purged. The `kvInvalidateMiddleware` handles this by scanning for keys prefixed with `cache:` and deleting relevant entries after a successful mutation.

```typescript
// Example of manual invalidation logic within a handler if needed
async function purgeProductCache(env: Env) {
  const list = await env.KV_CACHE.list({ prefix: 'cache:' });
  for (const key of list.keys) {
    if (key.name.includes('/v1/products')) {
      await env.KV_CACHE.delete(key.name);
    }
  }
}
```

## R2 Storage for Product Media

Product images are stored in a Cloudflare R2 bucket bound to `IMAGES`. Serving these images is done via a public URL defined in `IMAGES_URL`.

### Storing an Image
When a merchant uploads a product image, it is stored in R2. We typically use the product ID or a hash as the key.

```typescript
app.post('/v1/products/{id}/image', async (c) => {
  const productId = c.req.param('id');
  const body = await c.req.parseBody();
  const file = body['file'] as File;

  if (!file) return c.text('No file uploaded', 400);

  const key = `products/${productId}/${file.name}`;
  await c.env.IMAGES.put(key, await file.arrayBuffer(), {
    httpMetadata: { contentType: file.type }
  });

  const publicUrl = `${c.env.IMAGES_URL}/${key}`;
  return c.json({ url: publicUrl });
});
```

## Environment Variables and Secrets

Fufuni distinguishes between "Variables" (non-sensitive, in `wrangler.jsonc`) and "Secrets" (sensitive, managed via `wrangler secret`).

### Secret Management
Secrets are never checked into git. In local development, they live in `.env`. In production, they are injected via the `wrangler secret bulk` command during CI.

**Required Mailgun Secrets:**
Mailgun is used for transactional emails. If `MAILGUN_API_KEY` is missing, the framework silently skips sending.
- `MAILGUN_API_KEY`: The API key from Mailgun.
- `MAILGUN_DOMAIN`: Your verified sending domain.
- `MAILGUN_BASE_URL`: Usually `https://api.mailgun.net`.
- `MAILGUN_USER`: The "From" address (e.g., `Support <support@example.com>`).

```typescript
// Logic check for Mailgun
const sendEmail = async (env: Env, to: string, subject: string, body: string) => {
  if (!env.MAILGUN_API_KEY) {
    console.warn('Mailgun API key missing, skipping email');
    return;
  }
  // ... fetch call to Mailgun API
};
```

## Extending the Worker Environment

To add a new binding (e.g., a new KV namespace for analytics), follow these steps:

### 1. Update `wrangler.jsonc`
Add the binding to the appropriate array.

```jsonc
"kv_namespaces": [
  {
    "binding": "KV_CACHE",
    "id": "..."
  },
  {
    "binding": "ANALYTICS_KV"
  }
]
```

### 2. Update Types
Run `npx wrangler types` to update `worker-configuration.d.ts`. This ensures `c.env.ANALYTICS_KV` is recognized by TypeScript.

### 3. Update the global Env interface
If you have a manual `Env` definition, ensure it matches:

```typescript
interface Env {
  KV_CACHE: KVNamespace;
  ANALYTICS_KV: KVNamespace; // New binding
  IMAGES: R2Bucket;
  // ...
}
```

## CI/CD Pipeline and Frontend Injection

Fufuni uses a sophisticated pipeline to ensure environment parity between the backend Worker and the frontend React application.

### GitHub Secrets to Worker
Every variable in the local `.env` has a matching GitHub Secret. The `create-env-artifact.yaml` workflow collects these secrets and packages them into an encrypted `.env` file. The `generate-wrangler-jsonc.py` script then uses this to build the final `wrangler.jsonc` for deployment.

```bash
# Example step in create-env-artifact.yaml
echo "STRIPE_SECRET_KEY=${{ secrets.STRIPE_SECRET_KEY }}" >> .env
```

### Exposing Vars to the Frontend
Frontend variables are **not** prefixed with `VITE_`. Instead, they are explicitly injected via the `define` block in `apps/client/vite.config.ts`. To expose a new variable to the browser, you must add it there.

```typescript
// apps/client/vite.config.ts
export default defineConfig({
  define: {
    'import.meta.env.STORE_NAME': JSON.stringify(process.env.STORE_NAME),
    'import.meta.env.API_BASE_URL': JSON.stringify(process.env.API_BASE_URL),
    // Add your new variable here
  }
});
```

### Dynamic Permissions
The frontend determines which navigation items to show based on the `PERMISSIONS` array. This array is constructed at build time from any `.env` variable ending in `_PERMISSION`.

```typescript
// Inside vite.config.ts logic
const scopesArray = Object.keys(process.env)
  .filter(key => key.endsWith('_PERMISSION'))
  .map(key => process.env[key]);

// Then in define:
'import.meta.env.PERMISSIONS': JSON.stringify(scopesArray)
```

This allows the UI to adapt based on the permissions granted to the deployment without hardcoding strings in the frontend source code.
