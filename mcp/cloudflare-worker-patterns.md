## Cloudflare Worker Patterns
### Accessing Bindings in a Route Handler
To access bindings in a route handler, you can use the `c.env` object. For example:
```typescript
export const GET = async (c: Context) => {
  const merchant = c.env.MERCHANT;
  const images = c.env.IMAGES;
  const kvCache = c.env.KV_CACHE;
  // Use the bindings as needed
};
```
### The Durable Object Pattern
We use a single Durable Object instance to manage state. To get the stub, you can use the `DurableObjectNamespace` binding:
```typescript
const merchantStub = c.env.MERCHANT.get(c.request.params.id);
```
To call `query()` or `run()` on the Durable Object, you can use the stub:
```typescript
const result = await merchantStub.query('methodName');
const result = await merchantStub.run('methodName');
```
### KV Cache
The KV cache middleware serves GET responses from KV before hitting the Durable Object. The cache key is generated based on the full URL, including query parameters. To invalidate the cache manually, you can use the `kvInvalidateMiddleware`:
```typescript
await kvInvalidateMiddleware(c.env.KV_CACHE, 'cacheKey');
```
### R2
Product images are stored and served using R2. To upload an image, you can use the `R2Bucket` binding:
```typescript
const image = await c.env.IMAGES.put('imageName', imageBuffer);
```
To serve an image, you can use the `R2Bucket` binding:
```typescript
const image = await c.env.IMAGES.get('imageName');
```
### Secrets
Secrets that must be stored in Wrangler secrets include:

* `AUTH0_CLIENT_SECRET`
* `AUTH0_MANAGEMENT_API_CLIENT_SECRET`
* `STRIPE_SECRET_KEY`
* `MAILGUN_API_KEY`

Secrets that can be stored in the `.env` file include:

* `AUTH0_DOMAIN`
* `AUTH0_CLIENT_ID`
* `STRIPE_PUBLISHABLE_KEY`
* `MAILGUN_DOMAIN`

Mailgun secrets include:

* `MAILGUN_API_KEY`
* `MAILGUN_DOMAIN`
* `MAILGUN_BASE_URL`
* `MAILGUN_USER`

### Adding a New Binding
To add a new binding, you need to:

1. Add the binding to `wrangler.jsonc`
2. Update `worker-configuration.d.ts` to include the new binding
3. Update the `Env` type to include the new binding

For example:
```typescript
// wrangler.jsonc
{
  "bindings": [
    {
      "name": "NEW_BINDING",
      "class_name": "NewBindingDO"
    }
  ]
}

// worker-configuration.d.ts
interface Env {
  NEW_BINDING: DurableObjectNamespace<import("./src/index").NewBindingDO>;
}

// Env type
interface Env extends Cloudflare.Env {
  NEW_BINDING: DurableObjectNamespace<import("./src/index").NewBindingDO>;
}
```
### CI/CD
To expose a new variable to the frontend via `vite.config.ts` define block, you need to:

1. Add the variable to the `.env` file
2. Update `create-env-artifact.yaml` to include the new variable
3. Update `vite.config.ts` to include the new variable in the define block

For example:
```typescript
// .env
NEW_VARIABLE=getValue

// create-env-artifact.yaml
echo "NEW_VARIABLE=${{ secrets.NEW_VARIABLE }}" >> .env

// vite.config.ts
define: {
  'import.meta.env.NEW_VARIABLE': process.env.NEW_VARIABLE,
},
```
To map an env var to a GitHub secret, you need to:

1. Add the variable to the `.env` file
2. Update `create-env-artifact.yaml` to include the new variable
3. Update `deploy-cloudflare-worker.yaml` to include the new secret

For example:
```typescript
// .env
NEW_VARIABLE=getValue

// create-env-artifact.yaml
echo "NEW_VARIABLE=${{ secrets.NEW_VARIABLE }}" >> .env

// deploy-cloudflare-worker.yaml
env:
  NEW_VARIABLE: ${{ secrets.NEW_VARIABLE }}
```
