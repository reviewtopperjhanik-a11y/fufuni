## Product Review Lifecycle & Eligibility

The Fufuni review system follows a strict "Verified Purchase" policy. A customer is only eligible to review a product if they have a completed and delivered order containing that specific item. This ensures high-quality, trustworthy feedback for other shoppers.

### Eligibility Check Flow

Before showing a review form, the frontend must query the eligibility endpoint. This endpoint verifies the link between the authenticated customer and their order history.

```typescript
// apps/merchant/src/routes/reviews.ts

const eligibilityRoute = createRoute({
  method: 'get',
  path: '/eligibility',
  tags: ['Reviews'],
  summary: 'Check if current customer can review this product',
  responses: {
    200: {
      description: 'Eligibility status',
      content: {
        'application/json': {
          schema: z.object({
            eligible: z.boolean(),
            reason: z.string().optional(),
          }),
        },
      },
    },
  },
});

app.openapi(eligibilityRoute, async (c) => {
  const { productId } = c.req.valid('param');
  const customerId = c.get('customerId'); // Set by customerAuthMiddleware
  const db = getDb(c.var.db);

  // 1. Check if already reviewed (Prevent duplicates)
  const existing = await db.prepare(
    'SELECT id FROM product_reviews WHERE product_id = ? AND customer_id = ?'
  ).bind(productId, customerId).first();

  if (existing) {
    return c.json({ eligible: false, reason: 'ALREADY_REVIEWED' }, 200);
  }

  // 2. Check for delivered order (Verified Purchase)
  const orderItem = await db.prepare(`
    SELECT oi.id 
    FROM order_items oi
    JOIN orders o ON oi.order_id = o.id
    WHERE o.customer_id = ? AND oi.product_id = ? AND o.status = 'delivered'
  `).bind(customerId, productId).first();

  if (!orderItem) {
    return c.json({ eligible: false, reason: 'NO_DELIVERED_ORDER' }, 200);
  }

  return c.json({ eligible: true }, 200);
});
```

### Review Submission

When a review is submitted via `POST /v1/products/:id/reviews`, it is initially saved with a `pending` status. It will not appear in the public product listing until an administrator manually approves it. Attempting to submit a second review for the same product results in a `409 Conflict`.

## Cursor-Based Pagination Pattern

Fufuni uses cursor-based pagination for reviews rather than offset-based pagination. This prevents items from being skipped or duplicated when new reviews are approved and inserted at the top of the list while a user is browsing.

**Important:** We use the `created_at` timestamp (ISO 8601 string) as the cursor, not the UUID `id`. UUIDs in Fufuni are not naturally sorted by time.

```typescript
// Implementation of cursor-based retrieval
app.openapi(listReviewsRoute, async (c) => {
  const { productId } = c.req.valid('param');
  const { limit: limitStr, cursor } = c.req.valid('query');
  const db = getDb(c.var.db);
  const limit = Math.min(parseInt(limitStr), 50);

  let sql = `
    SELECT id, author_name, rating, title, body, is_verified_purchase, helpful_count, created_at 
    FROM product_reviews 
    WHERE product_id = ? AND status = 'approved'
  `;
  const params: any[] = [productId];

  if (cursor) {
    // Return items older than the cursor
    sql += ` AND created_at < ? `;
    params.push(cursor);
  }

  sql += ` ORDER BY created_at DESC LIMIT ? `;
  params.push(limit + 1); // Fetch one extra to determine has_more

  const { results } = await db.prepare(sql).bind(...params).all();
  const hasMore = results.length > limit;
  const items = hasMore ? results.slice(0, limit) : results;
  const nextCursor = hasMore ? (items[items.length - 1].created_at as string) : null;

  return c.json({
    items,
    pagination: {
      has_more: hasMore,
      next_cursor: nextCursor,
    },
  }, 200);
});
```

## The Inline JWT Extraction Pattern

In `apps/merchant/src/routes/reviews.ts`, you will notice that we do not always rely on standard `authMiddleware` at the sub-router level. This is because Hono sub-apps sometimes struggle with path prefix propagation when calculating signatures for standard middleware in complex Cloudflare Worker deployments.

Instead, we use a manual extraction pattern to ensure reliability across all deployment environments:

```typescript

const adminModerateRoute = createRoute({
  method: 'patch',
  path: '/:reviewId/status',
  // ... schema
});

app.openapi(adminModerateRoute, async (c) => {
  const authHeader = c.req.header('Authorization');
  if (!authHeader || !authHeader.startsWith('Bearer ')) {
    return c.json({ error: 'Unauthorized' }, 401);
  }

  // We manually verify the token or check the context provided by

  const payload = c.get('jwtPayload'); 
  if (!payload || payload.role !== 'admin') {
    return c.json({ error: 'Forbidden' }, 403);
  }
```

## Worked Example: Adding Merchant Replies

This example demonstrates how to extend the review system to allow admins to reply to customer feedback.

### 1. Database Migration

First, we need to add the `merchant_reply` and `replied_at` columns to the `product_reviews` table.

```sql

```

### 2. Backend Route Update

Update the admin route to accept a reply string in the PATCH request.

```typescript
// apps/merchant/src/routes/reviews.ts

const replyToReviewRoute = createRoute({
  method: 'patch',
  path: '/:reviewId/reply',
  tags: ['Reviews Admin'],
  security: [{ BearerAuth: [] }],
  request: {
    params: z.object({ reviewId: z.string().uuid() }),
    body: {
      content: {
        'application/json': {
          schema: z.object({
            reply: z.string().min(1).max(2000),
          }),
        },
      },
    },
  },
  responses: {
    200: { description: 'Reply saved' },
    404: { description: 'Review not found' }
  },
});

app.openapi(replyToReviewRoute, async (c) => {
  const { reviewId } = c.req.valid('param');
  const { reply } = c.req.valid('json');
  const db = getDb(c.var.db);

  const result = await db.prepare(
    'UPDATE product_reviews SET merchant_reply = ?, replied_at = ? WHERE id = ?'
  ).bind(reply, new Date().toISOString(), reviewId).run();

  if (result.changes === 0) return c.json({ error: 'Not found' }, 404);
  return c.json({ success: true }, 200);
});
```
