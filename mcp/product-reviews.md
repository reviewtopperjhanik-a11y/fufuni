## Review Data Model

The product reviews system in Fufuni is designed to balance user trust with platform safety. Every review is stored in the `product_reviews` table and goes through a lifecycle managed by status transitions.

The schema includes the following primary fields:
- `id`: A unique UUID.
- `product_id`: Reference to the product being reviewed.
- `customer_id`: Reference to the customer who authored the review.
- `rating`: An integer between 1 and 5.
- `title`: An optional summary of the review.
- `body`: The detailed feedback text.
- `status`: One of `pending`, `approved`, or `rejected`.
- `ai_moderation_result`: A JSON column storing sentiment analysis and policy violation flags.
- `created_at`: ISO timestamp for chronological ordering.

```sql
-- apps/merchant/src/db/schema.sql (Representational)
CREATE TABLE product_reviews (
  id TEXT PRIMARY KEY,
  product_id TEXT NOT NULL,
  customer_id TEXT NOT NULL,
  rating INTEGER CHECK (rating BETWEEN 1 AND 5),
  title TEXT,
  body TEXT,
  status TEXT DEFAULT 'pending' CHECK (status IN ('pending', 'approved', 'rejected')),
  ai_moderation_result TEXT, -- JSON blob
  is_verified_purchase INTEGER DEFAULT 0,
  helpful_count INTEGER DEFAULT 0,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (product_id) REFERENCES products(id),
  FOREIGN KEY (customer_id) REFERENCES customers(id),
  UNIQUE(product_id, customer_id) -- Enforces one review per product per customer
);
```

### Review Status Lifecycle
1.  **Pending**: The default state for any new submission. These are not visible on the public product page.
2.  **Approved**: The review is visible to all users. This status triggers an update to the product's aggregate rating.
3.  **Rejected**: The review is hidden. It remains in the database but does not contribute to ratings.

## Public Endpoints

Public access is divided into listing (read) and submission (write). Listing is open to all, while submission requires a valid customer session.

### Listing Approved Reviews
The public API returns only reviews with the `approved` status. To maintain performance, Fufuni uses cursor-based pagination instead of offset-based pagination. The `cursor` is the `created_at` timestamp of the last retrieved item.

### Submitting a Review
Customers submit reviews via a `POST` request. The backend automatically sets the status to `pending`. If the customer has already reviewed the product, the database unique constraint (`product_id`, `customer_id`) will trigger a `409 Conflict`.

```typescript
// POST /v1/products/:productId/reviews
app.openapi(submitReviewRoute, async (c) => {
  const { productId } = c.req.valid('param');
  const { rating, title, body } = c.req.valid('json');
  const customer = c.get('customer'); // From customerAuthMiddleware

  const db = getDb(c.var.db);
  
  try {
    await db.prepare(`
      INSERT INTO product_reviews (id, product_id, customer_id, rating, title, body, status)
      VALUES (?, ?, ?, ?, ?, ?, 'pending')
    `).bind(uuid(), productId, customer.id, rating, title, body).run();
    
    return c.json({ success: true }, 201);
  } catch (e: any) {
    if (e.message.includes('UNIQUE constraint failed')) {
      return c.json({ error: 'You have already reviewed this product' }, 409);
    }
    throw e;
  }
});
```

## AI Moderation Integration

Fufuni integrates AI to assist admins in identifying toxic content or spam. This is not fully automated; instead, it provides "hints" to the admin.

### Workflow
1.  **Trigger**: When an admin loads the `AdminReviewsPage`, the client checks for the `AI_PERMISSION`.
2.  **Analysis**: For every pending review, the client calls `analyzeReviewsBatchWithAi` from `ai-client.ts`.
3.  **Storage**: The results (sentiment score, flags) are stored in the `ai_moderation_result` column via a background patch.
4.  **UI Feedback**: The frontend displays a `Sparkles` icon and a summary chip (e.g., "Positive", "Potential Spam") next to the review.

```typescript
// apps/client/src/utils/ai-client.ts
export async function analyzeReviewsBatchWithAi(
  reviews: any[], 
  params: AiParams
): Promise<Map<string, ReviewAnalysisResult>> {
  // Calls Cloudflare AI or external LLM to evaluate text
  // Returns a map of Review ID -> { recommendation, sentiment, flags }
  const results = new Map();
  for (const review of reviews) {
    const analysis = await callAiProvider(review.body);
    results.set(review.id, analysis);
  }
  return results;
}
```

## One-Review-Per-Product Constraint

To prevent rating manipulation, Fufuni strictly enforces a one-review-per-customer policy for every product. This is enforced at two levels:

1.  **Database Level**: A `UNIQUE(product_id, customer_id)` constraint ensures that no two rows can share the same pairing, even if concurrent requests bypass application logic.
2.  **Application Level**: Before rendering the "Write a Review" button in the frontend, the UI checks if the customer already has a review (of any status) for that product.

If a customer attempts to submit a second review, the server responds with a `409 Conflict`. To update an existing review, the framework expects an `EDIT` flow (if enabled), rather than a new `POST`.

## Rating Aggregates Maintenance

To avoid expensive `JOIN` and `AVG()` operations on every product page load, Fufuni uses denormalized columns on the `products` table: `avg_rating` and `review_count`.

### Synchronization Logic
These aggregates must only reflect **approved** reviews. When a review status changes, the framework recalculates these values for the associated product.

```typescript
async function updateProductAggregates(db: D1Database, productId: string) {
  const stats = await db.prepare(`
    SELECT 
      COUNT(*) as total,
      AVG(rating) as average
    FROM product_reviews 
    WHERE product_id = ? AND status = 'approved'
  `).bind(productId).first<{ total: number; average: number }>();

  await db.prepare(`
    UPDATE products 
    SET 
      review_count = ?, 
      avg_rating = ? 
    WHERE id = ?
  `).bind(stats?.total ?? 0, stats?.average ?? 0, productId).run();
}
```

### When Updates Occur
-   **Review Approved**: `review_count` increases by 1, `avg_rating` is recalculated.
-   **Review Rejected**: If it was previously approved, `review_count` decreases by 1, `avg_rating` is recalculated.
-   **Review Deleted**: (Admin only) Recalculates the remaining approved set.

This strategy ensures that the `GET /v1/products/:id` endpoint remains extremely fast, as it simply returns the pre-computed values directly from the `products` row.
