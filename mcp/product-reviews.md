## Database Schema and Data Model

Product reviews in Fufuni are stored in the `product_reviews` table. This table tracks the relationship between customers and products, enforces uniqueness constraints, and stores AI-generated moderation metadata.

### SQL Schema Definition

The table uses UUIDs for primary and foreign keys and maintains a status field to handle the moderation lifecycle.

```sql
CREATE TABLE product_reviews (
    id TEXT PRIMARY KEY,               -- UUID
    product_id TEXT NOT NULL,          -- UUID referencing products
    customer_id TEXT NOT NULL,         -- UUID referencing customers
    rating INTEGER NOT NULL CHECK (rating >= 1 AND rating <= 5),
    title TEXT,
    body TEXT,
    status TEXT NOT NULL DEFAULT 'pending', -- 'pending', 'approved', 'rejected'
    is_verified_purchase INTEGER DEFAULT 0, -- Boolean (0 or 1)
    helpful_count INTEGER DEFAULT 0,
    ai_moderation_result TEXT,         -- JSON string from AI analysis
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    -- Ensure one review per customer per product
    UNIQUE(product_id, customer_id),
    FOREIGN KEY (product_id) REFERENCES products(id) ON DELETE CASCADE
);
```

### Review Status Values

- **`pending`**: Default state for new submissions. Not visible to the public.
- **`approved`**: Review has been vetted by an admin or auto-moderated. Visible on the product page and factored into rating aggregates.
- **`rejected`**: Review is hidden. This is used for spam, offensive content, or reviews violating guidelines.

## Customer Submission and Validation

The submission process is restricted to authenticated customers. Fufuni enforces a strict "one review per product" policy to prevent rating manipulation.

### POST /v1/products/:id/reviews

When a customer submits a review, the backend first checks for an existing entry for that specific `customer_id` and `product_id`.

```typescript

app.openapi(postReviewRoute, async (c) => {
  const { productId } = c.req.valid('param');
  const { rating, title, body } = c.req.valid('json');
  const customer = c.get('customer'); // From customerAuthMiddleware
  const db = getDb(c.var.db);

  // 1. Check for existing review (One-review-per-product constraint)
  const existing = await db.prepare(
    'SELECT id FROM product_reviews WHERE product_id = ? AND customer_id = ?'
  ).bind(productId, customer.id).first();

  if (existing) {
    return c.json({ 
      error: 'CONFLICT', 
      message: 'You have already reviewed this product.' 
    }, 409);
  }

  // 2. Determine verified purchase status
  const purchase = await db.prepare(
    'SELECT id FROM orders WHERE customer_id = ? AND status = ? AND id IN (SELECT order_id FROM order_items WHERE product_id = ?)'
  ).bind(customer.id, 'delivered', productId).first();

  // 3. Insert new review
  const reviewId = uuid();
  await db.prepare(`
    INSERT INTO product_reviews (id, product_id, customer_id, rating, title, body, status, is_verified_purchase)
    VALUES (?, ?, ?, ?, ?, ?, 'pending', ?)
  `).bind(reviewId, productId, customer.id, rating, title, body, purchase ? 1 : 0).run();

  return c.json({ id: reviewId }, 201);
});
```

### Approving/Rejecting and Aggregates

When a review is updated to `approved` or moved away from it, the `avgRating` and `reviewCount` on the `products` table must stay synchronized.

```typescript
// PATCH /v1/reviews/:id/status
app.openapi(updateStatusRoute, async (c) => {
  const { id } = c.req.valid('param');
  const { status } = c.req.valid('json'); // 'approved' | 'rejected'
  const db = getDb(c.var.db);

  // 1. Get the review info first
  const review = await db.prepare('SELECT product_id, rating FROM product_reviews WHERE id = ?')
    .bind(id).first<any>();

  // 2. Update the review status
  await db.prepare('UPDATE product_reviews SET status = ?, updated_at = CURRENT_TIMESTAMP WHERE id = ?')
    .bind(status, id).run();

  // 3. Recalculate and update the products table
  // Note: In Fufuni, avgRating and reviewCount are treated as cached computed columns
  await db.prepare(`
    UPDATE products 
    SET 
      avg_rating = (SELECT AVG(rating) FROM product_reviews WHERE product_id = ? AND status = 'approved'),
      review_count = (SELECT COUNT(*) FROM product_reviews WHERE product_id = ? AND status = 'approved')
    WHERE id = ?
  `).bind(review.product_id, review.product_id, review.product_id).run();

  return c.json({ success: true });
});
```

## AI-Assisted Moderation

Fufuni integrates AI to help admins process large volumes of reviews. The analysis typically checks for sentiment, spam, and policy violations.

### Workflow
1.  **Trigger**: When an admin opens the Reviews page, the frontend identifies reviews lacking an `ai_moderation_result`.
2.  **Analysis**: The frontend calls `analyzeReviewsBatchWithAi` (using a LLM like GPT-4 or Claude).
3.  **Persistence**: The result is sent back to the server to be stored in the `ai_moderation_result` column.
4.  **UI Display**: The admin sees a recommendation (e.g., "Recommend: Approve - Positive sentiment, no spam detected").

### AI Analysis Result Schema

The `ai_moderation_result` is stored as a JSON object:

```typescript
interface ReviewAnalysisResult {

  flagged: boolean;
  reasoning: string;
  suggested_action: 'approve' | 'reject' | 'manual_review';
  confidence_score: number; // 0.0 to 1.0
}
```

The React admin page uses `tanstack-query` and handles the AI calls in the background.

```tsx
  setAnalyzing(true);
  const pendingReviews = reviews.filter(r => !r.ai_moderation_result);

      id: review.id,

    }]);

      ai_moderation_result: result[review.id]
    });
  }
  setAnalyzing(false);
  refetch();
};
```

## Rating Aggregates Update Strategy

While SQLite handles the atomic updates within the `PATCH` route, it is important to understand the "source of truth" relationship.

1.  **Product Reviews Table**: The absolute source of truth. Every rating is stored here.
2.  **Products Table**: Contains `avg_rating` (FLOAT) and `review_count` (INTEGER). These are read-heavy fields used for listing products and sorting by popularity.
3.  **Sync Trigger**: Synchronization occurs **only** on status changes. If a review is deleted or its rating is edited (not allowed by default in Fufuni), the aggregates must be recomputed using the `AVG()` and `COUNT()` subqueries shown in the Moderation section.

### Manual Aggregate Re-sync (CLI/Admin)

If data becomes desynchronized, the following SQL corrects a specific product:

```sql
UPDATE products 
SET 
  avg_rating = IFNULL((SELECT AVG(rating) FROM product_reviews WHERE product_id = products.id AND status = 'approved'), 0),
  review_count = (SELECT COUNT(*) FROM product_reviews WHERE product_id = products.id AND status = 'approved')
WHERE id = 'PRODUCT_UUID_HERE';
```
