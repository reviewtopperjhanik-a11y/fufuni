## Review Submission Lifecycle

The Fufuni framework implements a strict moderation-first approach for product reviews. A review undergoes a specific lifecycle to ensure data integrity and prevent spam. By default, reviews are created with a `pending` status and are only visible to the public once an admin transitions them to `approved`.

1.  **Eligibility Check**: Before a customer can see the review form, the frontend calls `GET /v1/products/:productId/reviews/eligibility`. The backend verifies if the customer has a "delivered" order containing that specific product.
2.  **Submission**: The customer submits a `POST` request. If a review already exists for this customer-product pair, the API returns a `409 Conflict`.
3.  **Moderation**: The review enters the `product_reviews` table with `status = 'pending'`. It is invisible to `listReviewsRoute`.
4.  **Approval**: An admin uses the Admin Dashboard (optionally assisted by AI) to set the status to `approved`.

## Cursor-Based Pagination Implementation

Fufuni uses cursor-based pagination for reviews rather than offset-based pagination. This prevents "skipping" items or seeing duplicates when new reviews are approved while a user is scrolling. 

Since UUIDs in SQLite are not chronologically ordered, we use the `created_at` timestamp (ISO 8601 string) as the cursor.

### Pagination SQL Pattern
The query always selects `limit + 1` items. If the result count equals `limit + 1`, we know there is a next page.

```typescript
// apps/merchant/src/routes/reviews.ts implementation pattern
let sql = `SELECT * FROM product_reviews 
           WHERE product_id = ? AND status = 'approved'`;
const params: any[] = [productId];

if (cursor) {
  // Use < because we sort DESC (newest first)
  sql += ` AND created_at < ?`;
  params.push(cursor);
}

sql += ` ORDER BY created_at DESC LIMIT ?`;
params.push(limit + 1);

const rows = await db.prepare(sql).all(...params);
const hasMore = rows.length > limit;
const items = hasMore ? rows.slice(0, limit) : rows;
const nextCursor = hasMore ? items[items.length - 1].created_at : null;

return c.json({ items, pagination: { has_more: hasMore, next_cursor: nextCursor } });
```

## Inline JWT Extraction Pattern

In `apps/merchant/src/routes/reviews.ts`, you will notice that we do not always use standard `authMiddleware` on the router level. This is because this specific file defines two separate Hono instances: one for public product-scoped reviews and one for admin moderation.

When a sub-router is mounted under complex paths (like `/v1/products/:productId/reviews`), Hono's middleware context can sometimes lose the ability to correctly parse the path prefix. To guarantee reliability, Fufuni uses **manual JWT extraction** for customer identity when submitting a review.

```typescript
// Manual extraction pattern inside an openapi handler
app.openapi(submitReviewRoute, async (c) => {
  const authHeader = c.req.header('Authorization');
  if (!authHeader?.startsWith('Bearer ')) {
    return c.json({ error: 'Unauthorized' }, 401);
  }

  const token = authHeader.split(' ')[1];
  // Manual decode because middleware might be bypassed in sub-app routing
  const payload = await verifyToken(token, c.env.JWT_SECRET); 
  const customerId = payload.sub;

  // ... proceed with logic
});
```

## Admin Moderation and AI Assistance

The Admin Dashboard includes an AI-assisted moderation tool. If the user has the `ai:api` permission, they can trigger a batch analysis. This calls a Cloudflare Worker AI model (via `analyzeReviewsBatchWithAi`) to generate a sentiment score and a recommendation.

The AI analyzes:
1.  **Sentiment**: Is the review coherent or gibberish?
2.  **Policy**: Does it contain prohibited links or toxic language?
3.  **Recommendation**: `approve` or `reject`.

```typescript
// apps/client/src/pages/admin/reviews.tsx
const handleAiAnalyze = async () => {
  setAnalyzing(true);
  try {
    const results = await analyzeReviewsBatchWithAi(reviewsToAnalyze, {
      locale: i18n.language,
      threshold: 0.7
    });
    
    // Update local state to show Sparkles icon + recommendation
    const newAnalyses = new Map(aiAnalyses);
    results.forEach(res => newAnalyses.set(res.reviewId, res));
    setAiAnalyses(newAnalyses);
  } finally {
    setAnalyzing(false);
  }
};
```
