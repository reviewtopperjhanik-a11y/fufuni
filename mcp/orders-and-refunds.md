## Order Lifecycle and State Machine

The Fufuni framework follows a strict state machine for order progression. Orders typically originate from a successful Stripe Checkout session or a manual "Test Order" creation. Once an order enters the `paid` state, it follows a linear path toward fulfillment, though it can be diverted to `canceled` or `refunded` at specific stages.

### Status Transitions

The following ASCII diagram illustrates the valid transitions within the system:

```text
[ Pending ] ──────────┐
      │               │ (Payment Success)
      ▼               ▼
  [ Paid ] ──────▶ [ Processing ] ──────▶ [ Shipped ] ──────▶ [ Delivered ]
      │               │                      │                    │
      └───────────────┴──────────┬───────────┴────────────────────┘
                                 │
                                 ▼
                    [ Refunded / Partially Refunded ]
                                 OR
                            [ Canceled ]
```

### State Definitions

| Status | Description |
| :--- | :--- |
| `pending` | Initial state before payment confirmation. |
| `paid` | Payment received; inventory has been decremented. |
| `processing` | Order is being picked/packed in the warehouse. |
| `shipped` | Order has been handed to the carrier; tracking info should be present. |
| `delivered` | Final state; customer has received the package. |
| `canceled` | Order invalidated; inventory must be restored to the warehouse. |
| `refunded` | Payment returned via Stripe; order items remain in DB for audit. |

## Managing Order Status

Updating an order's status is restricted to administrative users with the `admin:store` permission. When a status changes, the framework automatically triggers specific side effects, such as sending transactional emails (via Mailgun) or dispatching webhooks to external services.

### Status Update Side Effects

1.  **Email Notification**: Changing status to `processing`, `shipped`, `delivered`, `refunded`, or `canceled` triggers `sendOrderStatusEmail`.
2.  **Tracking Data**: Transitioning to `shipped` expects `tracking_number` and `tracking_url` to be provided in the request body.
3.  **Webhook Dispatch**: Dispatches `order.updated` or specific events like `order.shipped`.

```typescript
// Example: Updating an order to 'shipped' via the Admin API
async function markAsShipped(orderId: string, trackingNumber: string) {
  const response = await fetch(`/api/v1/orders/${orderId}`, {
    method: 'PATCH',
    headers: {
      'Content-Type': 'application/json',
      'Authorization': `Bearer ${adminToken}`,
    },
    body: JSON.stringify({
      status: 'shipped',
      tracking_number: trackingNumber,
      tracking_url: `https://carrier.com/track/${trackingNumber}`,
    }),
  });

  if (!response.ok) {
    const error = await response.json();
    throw new Error(error.error.message);
  }

  return response.json();
}
```

## Refund Flow: Stripe and Database

The refund process is handled via the `POST /v1/orders/{id}/refund` endpoint. Fufuni supports both full and partial refunds.

### Execution Steps
1.  **Validation**: Verify the order status is refundable (`paid`, `processing`, `shipped`, `delivered`, or `partially_refunded`).
2.  **Stripe API Call**: The Worker initiates a refund using the `stripe_payment_intent_id` stored on the order.
3.  **Database Audit**: A record is created in the `refunds` table containing the Stripe Refund ID, amount, and reason.
4.  **Order Update**: The order status is updated to `refunded` (if total amount matches) or `partially_refunded`.
5.  **Notification**: A refund confirmation email is sent to the customer.

```typescript
// Internal logic for processing a refund within the Hono route
const refundOrderLogic = async (order: any, amountCents?: number, reason?: string) => {
  const stripe = new Stripe(env.STRIPE_SECRET_KEY);
  
  // 1. Trigger Stripe Refund
  const stripeRefund = await stripe.refunds.create({
    payment_intent: order.stripe_payment_intent_id,
    amount: amountCents, // If null, Stripe performs a full refund
    reason: reason as any,
  });

  // 2. Record in SQLite (Durable Object)
  await db.run(
    `INSERT INTO refunds (id, order_id, stripe_refund_id, amount_cents, status, created_at)
     VALUES (?, ?, ?, ?, ?, ?)`,
    [uuid(), order.id, stripeRefund.id, stripeRefund.amount, 'succeeded', now()]
  );

  return stripeRefund;
};
```

## Order Cancellation & Inventory Restoration

Cancellation is a critical operation because it involves reversing the inventory decrement that occurred at the time of purchase. When `PATCH /v1/orders/:id/cancel` is called, the system iterates through all `order_items` and adds their quantities back to the respective warehouse stocks.

### Inventory Logic
Fufuni uses a multi-warehouse system. During cancellation, the system attempts to restore inventory to the same warehouse it was originally drawn from. If that information is lost, it falls back to the primary warehouse for the order's region.

```typescript
// Conceptual implementation of inventory restoration during cancellation
async function handleCancellation(db: DOStub, orderId: string) {
  const items = await db.query<any>(
    `SELECT sku, qty, warehouse_id FROM order_items WHERE order_id = ?`,
    [orderId]
  );

  for (const item of items) {
    // Increment on_hand count back to its original state
    await db.run(
      `UPDATE warehouse_inventory 
       SET on_hand = on_hand + ?, updated_at = ? 
       WHERE sku = ? AND warehouse_id = ?`,
      [item.qty, now(), item.sku, item.warehouse_id]
    );
  }

  await db.run(
    `UPDATE orders SET status = 'canceled', updated_at = ? WHERE id = ?`,
    [now(), orderId]
  );
}
```

## CSV Export for Reporting

Administrators can export order data for accounting or logistics purposes. The export endpoint supports date range filtering via `from` and `to` ISO strings.

### Query Parameters
-   `export`: Must be set to `csv`.
-   `from`: Start date (ISO 8601).
-   `to`: End date (ISO 8601).
-   `status`: Optional filter for specific statuses.

```typescript
/**
 * Example request for CSV export of all delivered orders in January 2026
 * GET /v1/orders?export=csv&from=2026-01-01T00:00:00Z&to=2026-01-31T23:59:59Z&status=delivered
 */
const exportOrdersCsv = async (from: string, to: string) => {
  const url = new URL('/api/v1/orders', window.location.origin);
  url.searchParams.set('export', 'csv');
  url.searchParams.set('from', from);
  url.searchParams.set('to', to);

  const response = await fetch(url.toString(), {
    headers: { 'Authorization': `Bearer ${adminToken}` }
  });

  const blob = await response.blob();
  const downloadUrl = window.URL.createObjectURL(blob);
  const a = document.createElement('a');
  a.href = downloadUrl;
  a.download = `orders-export-${from.split('T')[0]}.csv`;
  a.click();
};
```

## Order Item Immutability

One of the core architectural principles in Fufuni is that **orders are a snapshot in time**. When a customer completes a purchase, all relevant product details are copied into the `order_items` table.

### Why capture at purchase time?
1.  **Price Changes**: If a product price is raised tomorrow, existing orders must still reflect the price the customer actually paid.
2.  **Product Deletion**: If a product is deleted from the catalog, the order history must remain intact.
3.  **Tax Compliance**: Tax rates are captured at the moment of transaction to satisfy auditing requirements.
4.  **Title/Variant Snapshots**: If a product is renamed, the order should show the name as it appeared during checkout.

### Schema Structure
The `order_items` table stores:
-   `product_id` & `variant_id`: References for internal tracking.
-   `sku`: The physical identifier.
-   `title`: The display name (e.g., "Premium T-Shirt - Blue / XL").
-   `unit_price_cents`: The exact price paid.
-   `tax_rate` & `tax_amount`: Calculated cents for taxation.
-   `currency`: The currency code (e.g., "USD", "EUR").

```sql
-- Representation of the immutable order item record
CREATE TABLE order_items (
    id TEXT PRIMARY KEY,
    order_id TEXT NOT NULL,
    product_id TEXT,
    variant_id TEXT,
    sku TEXT NOT NULL,
    title TEXT NOT NULL,
    qty INTEGER NOT NULL,
    unit_price_cents INTEGER NOT NULL,
    tax_rate REAL DEFAULT 0,
    tax_amount_cents INTEGER DEFAULT 0,
    currency TEXT NOT NULL,
    FOREIGN KEY (order_id) REFERENCES orders(id)
);
```
