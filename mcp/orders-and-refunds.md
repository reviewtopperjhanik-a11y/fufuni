## Order Lifecycle and Statuses

In Fufuni, the order lifecycle is managed through a set of predefined statuses that transition a customer's purchase from initial payment to fulfillment or cancellation. These statuses are strictly enforced and mapped to specific UI indicators in the Merchant dashboard and the customer-facing storefront.

The system recognizes exactly seven statuses. Each status corresponds to a specific HeroUI color variant used in the frontend `Chip` components for consistent visual feedback.

| Status | Color | Description |
| :--- | :--- | :--- |
| `pending` | `warning` | The order has been created but payment is not yet confirmed. |
| `paid` | `success` | Payment has been successfully captured (via Stripe or test bypass). |
| `processing` | `accent` | The merchant has acknowledged the order and is preparing for shipment. |
| `shipped` | `accent` | The order has been handed to the carrier; tracking info is usually attached. |
| `delivered` | `success` | The customer has received the package. |
| `refunded` | `danger` | The payment has been returned to the customer (full or partial). |
| `canceled` | `danger` | The order was voided before fulfillment. |

### Updating Order Status via API

When an admin updates an order's status, the backend performs several side effects:
1.  **Database Update**: The `status` column in the `orders` table is updated.
2.  **Timestamping**: If the status changes to `shipped`, the `shipped_at` timestamp is automatically set.
3.  **Webhooks**: A `order.updated` or `order.shipped` event is dispatched to configured endpoints.
4.  **Emails**: Transactional emails are triggered via `c.executionCtx.waitUntil` to avoid blocking the API response.

```typescript
// Example: Updating an order to 'shipped' with tracking information
import { OrderResponse } from '../schemas';

async function shipOrder(orderId: string, trackingNumber: string, trackingUrl: string) {
  const response = await fetch(`/v1/orders/${orderId}`, {
    method: 'PATCH',
    headers: {
      'Content-Type': 'application/json',
      'Authorization': `Bearer ${process.env.ADMIN_TOKEN}`,
    },
    body: JSON.stringify({
      status: 'shipped',
      tracking_number: trackingNumber,
      tracking_url: trackingUrl,
    }),
  });

  if (!response.ok) {
    const error = await response.json();
    throw new Error(error.error.message);
  }

  return (await response.json()) as OrderResponse;
}
```

## The Refund Process

Refunds in Fufuni are designed with a "Stripe-First" safety pattern. Because the framework relies on Stripe as the source of truth for financial transactions, the backend is architected to ensure that a database state never reflects a refund that hasn't been successfully authorized by the payment processor.

### Transactional Workflow
1.  **Pre-flight Check**: The system verifies the order exists, isn't already fully refunded, and contains a valid `stripe_payment_intent_id`. Test orders without Stripe IDs cannot be refunded through this flow.
2.  **Stripe API Call**: The backend initializes a `Stripe` instance using the merchant's secret key and calls `stripe.refunds.create`.
3.  **Database Persistence**: Only after Stripe returns a successful response does the backend:
    *   Insert a record into the `refunds` table.
    *   Update the order status to `refunded` if the refund is full.
    *   Dispatch the `order.refunded` webhook.
4.  **Communication**: An asynchronous task is queued to send the refund confirmation email to the customer.

### Refund Implementation Details

The following code illustrates the backend implementation of the refund logic within the Hono router. Note the use of `ApiError` for graceful error handling of Stripe-specific exceptions.

```typescript
// apps/merchant/src/routes/orders.ts snippet logic
adminApp.openapi(refundOrder, async (c) => {
  const { orderId } = c.req.valid('param');
  const { amount_cents } = c.req.valid('json'); // Optional: null for full refund
  const stripeSecretKey = c.get('auth').stripeSecretKey;
  
  if (!stripeSecretKey) throw ApiError.invalidRequest('Stripe not connected');

  const db = getDb(c.var.db);
  const [order] = await db.query<any>(`SELECT * FROM orders WHERE id = ?`, [orderId]);

  if (!order) throw ApiError.notFound('Order not found');
  if (order.status === 'refunded') throw ApiError.conflict('Order already refunded');
  
  const stripe = new Stripe(stripeSecretKey);

  try {
    // 1. STRIKE FIRST: Call Stripe before touching our DB
    const refund = await stripe.refunds.create({
      payment_intent: order.stripe_payment_intent_id,
      amount: amount_cents, // If undefined, Stripe performs a full refund
    });

    // 2. LOG THE REFUND: Record the transaction in SQLite
    await db.run(
      `INSERT INTO refunds (id, order_id, stripe_refund_id, amount_cents, status) 
       VALUES (?, ?, ?, ?, ?)`,
      [crypto.randomUUID(), order.id, refund.id, refund.amount, refund.status ?? 'succeeded']
    );

    // 3. UPDATE ORDER STATUS: Only if it's a full refund or specific logic applies
    if (!amount_cents || amount_cents >= order.total_cents) {
      await db.run(`UPDATE orders SET status = 'refunded' WHERE id = ?`, [orderId]);
      
      // Trigger side effects
      c.executionCtx.waitUntil(
        sendOrderStatusEmail(c.env, c.var.db, orderId, 'refunded').catch(() => {})
      );
    }

    return c.json({ stripe_refund_id: refund.id, status: refund.status }, 200);
  } catch (e: any) {
    // Handle Stripe rejection (e.g., expired card, insufficient funds)
    throw ApiError.stripeError(e.message || 'Refund failed');
  }
});
```

## Public Order Access and Tracking

Fufuni provides two primary ways for customers to view their order status without requiring a full account login. This is critical for guest checkout flows.

### 1. Stripe Session Lookup
Immediately after a successful checkout, the frontend redirects to a `/success?session_id=...` page. The client calls the public `/v1/orders/lookup` endpoint.
*   **Security**: The Stripe `session_id` acts as an opaque, unguessable token.
*   **Data Masking**: This endpoint returns a limited "safe" view of the order, excluding internal IDs, customer email, or full addresses.

### 2. Signed Order Tokens (JWT)
For long-term tracking via email links, Fufuni generates a signed JWT (using `ORDER_TOKEN_SECRET`).
*   **Token Storage**: A hash of the token is stored in the `viewtoken` column of the `orders` table.
*   **Verification**: The public endpoint `/v1/orders/{orderId}/status?token={JWT}` verifies the signature and matches the hash before returning data.

```typescript
// Example: Public order status retrieval via signed token
import { z } from 'zod';

const OrderStatusSchema = z.object({
  number: z.string(),
  status: z.enum(['pending', 'paid', 'processing', 'shipped', 'delivered', 'refunded', 'canceled']),
  total_cents: z.number(),
  items: z.array(z.object({
    sku: z.string(),
    title: z.string(),
    qty: z.number()
  }))
});

async function getPublicOrderStatus(orderId: string, token: string) {
  const url = new URL(`${process.env.API_URL}/v1/orders/${orderId}/status`);
  url.searchParams.set('token', token);

  const response = await fetch(url.toString());
  if (!response.ok) {
    // We return 404 for both 'not found' and 'invalid token' to prevent ID enumeration
    throw new Error('Invalid tracking link');
  }

  const data = await response.json();
  return OrderStatusSchema.parse(data);
}
```

## Inventory Reconciliation on Cancellation

When an order is created (specifically via `createTestOrder` or the checkout webhook), inventory is deducted from the `warehouse_inventory` table based on region-specific priority. 

However, the `orders.ts` routes provided primarily handle status transitions. It is a framework convention that if an order status is changed to `canceled`, a corresponding inventory restock logic must be triggered. Currently, this is handled via the `order.updated` webhook or manually via a separate inventory adjustment route to ensure that "shipped" items aren't accidentally restocked without a physical return verification.

### Database Schema Reference for Orders

| Table | Primary Use |
| :--- | :--- |
| `orders` | Main order header (totals, status, shipping, stripe IDs). |
| `order_items` | Line items (SKU, quantity, snapshot of price at time of purchase). |
| `refunds` | Audit trail of Stripe refund IDs and amounts. |
| `discount_usage` | Links orders to the `discounts` table for usage limit tracking. |

### Example: Triggering a Full Refund from a React Component

Using the HeroUI patterns typical of the Fufuni frontend, a refund button in the admin dashboard would look like this:

```typescript
import React, { useState } from 'react';
import { Button, Modal, ModalContent, ModalHeader, ModalBody, ModalFooter } from "@heroui/react";

export const RefundButton = ({ orderId, totalAmount }: { orderId: string, totalAmount: number }) => {
  const [isOpen, setIsOpen] = useState(false);
  const [isLoading, setIsLoading] = useState(false);

  const handleRefund = async () => {
    setIsLoading(true);
    try {
      const res = await fetch(`/api/v1/orders/${orderId}/refund`, {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ amount_cents: totalAmount })
      });
      
      if (!res.ok) throw new Error('Refund failed');
      
      alert('Order successfully refunded');
      setIsOpen(false);
    } catch (err) {
      console.error(err);
    } finally {
      setIsLoading(false);
    }
  };

  return (
    <>
      <Button color="danger" onPress={() => setIsOpen(true)}>Refund Order</Button>
      <Modal isOpen={isOpen} onClose={() => setIsOpen(false)}>
        <ModalContent>
          <ModalHeader>Confirm Refund</ModalHeader>
          <ModalBody>
            Are you sure you want to refund ${(totalAmount / 100).toFixed(2)}? 
            This action will call the Stripe API and cannot be undone.
          </ModalBody>
          <ModalFooter>
            <Button variant="light" onPress={() => setIsOpen(false)}>Cancel</Button>
            <Button color="danger" isLoading={isLoading} onPress={handleRefund}>
              Confirm Stripe Refund
            </Button>
          </ModalFooter>
        </ModalContent>
      </Modal>
    </>
  );
};
```
