## Automated Tenant Provisioning

The Fufuni framework uses a centralized deployment script to ensure all Auth0 resources—Applications, APIs, and Actions—are synchronized across development and production environments. The script `scripts/auth0/deploy-tenant-resources.ts` uses the Auth0 Management API to idempotently create or update the necessary infrastructure.

### Resources Provisioned
- **SPA Application**: Configured for React 19 with PKCE, required callbacks, and logout URLs.
- **Resource Server (API)**: Defines the Fufuni API audience and all supported RBAC scopes.
- **Social Connections**: Automatically enables GitHub, Google, Microsoft, and Apple for the application.
- **Post-Login Action**: Deploys Node.js code to the Auth0 pipeline to enrich tokens.

### Running the Deployment
To provision a new tenant or update an existing one, you must provide an environment file containing the Management API credentials.

```bash
# Display detailed setup instructions
npx tsx scripts/auth0/deploy-tenant-resources.ts -- --detailed-help

# Run the deployment for a specific environment
npx tsx scripts/auth0/deploy-tenant-resources.ts -- --env-file=.env.production
```

## Permissions and RBAC Matrix

Fufuni utilizes a strict Role-Based Access Control (RBAC) system. Permissions (scopes) are defined at the Resource Server level in Auth0 and are assigned to users via Roles.

| Permission | Intended Role | Description |
| :--- | :--- | :--- |
| `admin:store` | Admin | General access to the dashboard, orders, and product management. |
| `auth0:admin:api` | Auth Admin | Access to the Management API proxy for user and permission editing. |
| `ai:api` | AI Admin | Permissions to trigger LLM re-indexing or AI generation features. |
| `mail:api` | Mail Admin | Access to email logs and template configuration. |
| `admin:database` | DB Admin | Direct access to internal SQLite/Durable Object maintenance tools. |

### Scopes Definition in Script
Scopes are defined within the `createOrUpdateResourceServer` call:

```typescript
const api = await createOrUpdateResourceServer(auth0Domain, token, {
  name: `${tenant}-api`,
  identifier: audience, // e.g., https://api.fufuni.com/
  scopes: [
    { value: "admin:store", description: "General store administration" },
    { value: "auth0:admin:api", description: "Manage users via Auth0 Proxy" },
    { value: "ai:api", description: "Access AI processing endpoints" }
  ],
  signing_alg: "RS256",
  allow_offline_access: true, // Enables Refresh Tokens
});
```

## Post-Login Action: JWT Enrichment

Fufuni minimizes latency by injecting frequently accessed user data directly into the Access Token. This eliminates the need for the frontend or backend to make secondary "UserInfo" requests or database lookups for basic preferences.

The post-login Action injects `user_metadata` (containing data like `wishlist_count` or `preferred_currency`) into the JWT as a custom claim.

### Action Implementation
The following code is automatically uploaded by the deployment script:

```javascript
/**
 * scripts/auth0/auth0-code/add-userinfo-to-access-jwt.js
 */
exports.onExecutePostLogin = async (event, api) => {
  const namespace = 'https://fufuni.com/';
  
  // Inject metadata into the Access Token
  if (event.user.user_metadata) {
    api.accessToken.setCustomClaim(`${namespace}user_metadata`, event.user.user_metadata);
  }

  // Also inject standard roles for easier RBAC parsing in the backend
  if (event.authorization && event.authorization.roles) {
    api.accessToken.setCustomClaim(`${namespace}roles`, event.authorization.roles);
  }
};
```

## Management API Token Caching

The Auth0 Management API has strict rate limits, specifically for Machine-to-Machine (M2M) token generation. To prevent exhaustion of the monthly quota, Fufuni caches the Management Token in Cloudflare KV.

### Caching Strategy
- **Storage**: Cloudflare KV.
- **Key**: `auth0_management_token`.
- **TTL**: ~23 hours (Tokens typically last 24 hours).

### Implementation in Backend
The framework checks KV before requesting a new token from Auth0:

```typescript
// server/src/auth/mgmt-token.ts
export async function getCachedManagementToken(env: Env) {
  const cached = await env.FUFUNI_KV.get("auth0_management_token");
  if (cached) return cached;

  const response = await fetch(`https://${env.AUTH0_DOMAIN}/oauth/token`, {
    method: "POST",
    headers: { "content-type": "application/json" },
    body: JSON.stringify({
      client_id: env.AUTH0_MGMT_CLIENT_ID,
      client_secret: env.AUTH0_MGMT_CLIENT_SECRET,
      audience: `https://${env.AUTH0_DOMAIN}/api/v2/`,
      grant_type: "client_credentials",
    }),
  });

  const data = await response.json();
  // Cache for 23 hours (82800 seconds)
  await env.FUFUNI_KV.put("auth0_management_token", data.access_token, { expirationTtl: 82800 });
  return data.access_token;
}
```

## User Management UI

The `UsersAndPermissionsPage` located at `/admin/users-and-permissions` is the administrative hub for managing team access. 

### Security Requirements
1.  **Permission**: The user must have the `auth0:admin:api` scope in their JWT.
2.  **Proxying**: To avoid exposing Management API secrets to the browser, the frontend calls a Hono backend route which proxies the request to Auth0 using the cached M2M token.

## Step-by-Step: Adding a New Permission

Follow these steps to implement a new permission (e.g., `report:export`) end-to-end in the Fufuni framework.

### 1. Update Deployment Script
Add the new scope to the resource server definition in `scripts/auth0/deploy-tenant-resources.ts`.

```typescript
// Inside deployResources() function
const api = await createOrUpdateResourceServer(auth0Domain, token, {
  // ... existing config
  scopes: [
    ...existingScopes,
    { value: "report:export", description: "Ability to export CSV reports" },
  ],
});
```

### 2. Synchronize Auth0
Run the script to push the new scope to the Auth0 dashboard.

```bash
npx tsx scripts/auth0/deploy-tenant-resources.ts -- --env-file=.env.local
```

### 3. Apply Backend Guard
Use the Zod-OpenAPI middleware in Hono to protect your routes.

```typescript
// server/src/routes/reports.ts
import { createRoute } from "@hono/zod-openapi";
import { authMiddleware } from "@/middleware/auth";

const exportRoute = createRoute({
  method: 'get',
  path: '/export',
  middleware: [authMiddleware(['report:export'])] as const,
  responses: {
    200: { description: 'CSV File' }
  }
});
```

### 4. Gate the Frontend
Use the `AuthenticationGuardWithPermission` component to hide UI elements from unauthorized users.

```tsx
// frontend/src/pages/Reports.tsx
import { AuthenticationGuardWithPermission } from "@/components/auth/Guard";
import { Button } from "@heroui/react";

export const ExportButton = () => (
  <AuthenticationGuardWithPermission permission="report:export">
    <Button color="primary" onPress={handleExport}>
      Export to CSV
    </Button>
  </AuthenticationGuardWithPermission>
);
```

By following this workflow, the new permission is strictly enforced at the API layer and provides a seamless user experience by hiding unavailable actions in the HeroUI frontend.
