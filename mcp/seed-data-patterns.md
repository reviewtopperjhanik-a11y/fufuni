## Execution and Prerequisites

The Fufuni seed script is a standalone TypeScript utility located at `apps/merchant/scripts/seed.ts`. It interacts with the backend via the `v1` REST API. Before running the script, the Fufuni backend must be active, and a store must have been initialized (usually via the first-run setup in the merchant dashboard).

The script requires two positional arguments: the API URL and a valid Admin Secret Key. The Admin Key is generated during the initial store setup or found in your environment variables as `ADMIN_KEY`.

### Running the Script

```bash
# Navigate to the merchant app
cd apps/merchant

# Run the seed script targeting a local environment
npx tsx scripts/seed.ts http://localhost:8787 sk_fufuni_dev_123456

# Run the seed script targeting a production/staging environment
npx tsx scripts/seed.ts https://api.yourstore.com sk_live_abcdef
```

The script is designed to be largely idempotent. It uses a specialized `seedReviews` logic to skip existing entries and relies on unique handles for products and categories to prevent duplicates, although repeated runs will generate new test orders.

## Defining Seed Categories

Categories in Fufuni support a hierarchical structure. The `seedCategories` function orchestrates the creation of these hierarchies. It utilizes a local helper `createCat` which handles localized names, descriptions, and the generation of WebP images (both full-size and thumbnails).

### Category Creation Pattern

To add a new category, update the `seedCategories` function. If the category should be a child, ensure you pass the `parent_id` retrieved from a previously created category.

```typescript
async function seedCategories() {
  console.log('📁 Creating categories...');

  // 1. Create a top-level category
  const gearCategory = await createCat({
    handle: 'professional-gear',
```

## API Resilience with apiWithRetry

Since the seed script performs hundreds of rapid HTTP requests, it is susceptible to rate-limiting by Cloudflare Workers or the internal Hono middleware. The `apiWithRetry` helper manages these transient failures using exponential backoff.

### Usage of the Retry Helper

The helper specifically looks for the "Rate limit exceeded" string in the error message and attempts to parse the `Retry-After` suggestion if provided by the server.

```typescript
/**
 * Example of using apiWithRetry for a custom bulk operation
 * that might trigger rate limits.
 */
async function bulkUpdateInventory(sku: string, warehouses: string[]) {
  for (const warehouseId of warehouses) {
    try {
      // Wraps the standard 'api' call with 5 default retry attempts
      await apiWithRetry(`/v1/inventory/${encodeURIComponent(sku)}/warehouse-adjust`, {
        warehouse_id: warehouseId,
        delta: 100,
        reason: 'seasonal_restock'
      });
      console.log(`✅ Restocked ${sku} in ${warehouseId}`);
    } catch (error) {
      console.error(`❌ Failed to restock ${sku} after retries:`, error);
    }
  }
}
```

## Image Processing and WebP Conversion

To maintain high performance and SEO scores, Fufuni serves images in WebP format. The seed script includes a built-in processing pipeline using `webp-wasm` and `pngjs`.

### The toWebpDataUri Workflow

The `toWebpDataUri` helper handles three critical tasks:
1.  **Source Resolution**: It checks for a local file in `scripts/img/` or falls back to a base64 string in `scripts/image_map.ts`.
2.  **Resizing**: It uses a `nnsResize` (Nearest-Neighbour) algorithm to downscale images if they exceed a `maxSide` pixel limit.
3.  **Encoding**: It converts the raw RGBA buffer into a WebP Data URI.

```typescript
/**
 * Generating a thumbnail for a product variant
 */
async function generateVariantThumb(fileName: string) {
  const thumbDataUri = await toWebpDataUri(
    fileName, 
    400, // maxSide: Resize to 400px while maintaining aspect ratio
    75   // quality: 75%
  );

  if (thumbDataUri) {
    console.log('WebP URI ready for upload:', thumbDataUri.substring(0, 50) + '...');
  }
}
```

## Adding New Seed Helpers

The seed script is modular. When adding support for new entities (like Promotions, Discounts, or Customers), you should follow the existing pattern: create a dedicated `seed[Entity]` function and register it in the `seed()` orchestrator.

### Example: Implementing a seedPromotions Helper

This pattern ensures that dependencies (like `productIds`) are passed down correctly.

```typescript
/**
 * 1. Define the helper
 */
async function seedPromotions(productIds: Record<string, string>) {
  console.log('🎟️ Seeding promotions...');
  
  const promo = await api('/v1/promotions', {
    code: 'WELCOME20',
    type: 'percentage',
    value: 20,
    is_active: true,
  });

  // Link to a specific product if needed
  const teeId = productIds['tee'];
  if (teeId) {
    await api(`/v1/promotions/${promo.id}/products`, {
      product_ids: [teeId]
    });
  }
}

/**
 * 2. Update the main orchestrator
 */
async function seed() {
  const regionData = await seedRegions();
  const categoryData = await seedCategories();
  const productIds = await seedProducts(regionData, categoryData);
  
  // New helper called after productIds are available
  await seedPromotions(productIds);

  await seedOrders(regionData);
  await seedReviews(productIds);
}
```
