## Client-Side PDF Generation

Fufuni generates all invoices entirely on the client side. This architecture offloads heavy PDF processing from Cloudflare Workers to the user's browser and ensures that sensitive order data used for rendering (like customer addresses) is handled locally. The framework utilizes `jsPDF` for basic document structure and `jsPDF-AutoTable` for rendering the itemized list of products.

As per Fufuni core standards, the `generateInvoice` function does not trigger a download automatically. Instead, it returns a `jsPDF` instance, allowing the calling component to decide whether to save the file, open it in a new tab, or generate a preview.

### Generation Logic Example

```typescript
import jsPDF from "jspdf";
import autoTable from "jspdf-autotable";
import { TFunction } from "i18next";

interface StoreInfo {
  name: string;
  address?: string;
  logoBase64?: string; // Data URI
}

/**
 * Core invoice generator following Verified Facts
 */
export function generateInvoice(
  order: any, 
  storeInfo: StoreInfo, 
  t: TFunction
): jsPDF {
  const doc = new jsPDF({
    orientation: "portrait",
    unit: "mm",
    format: "a4",
  });

  // Example of using the returned instance
  doc.setFontSize(20);
  doc.text(storeInfo.name, 14, 20);
  
  // Implementation details follow the standard structure...
  // (Header -> Customer -> Table -> Totals)
  
  return doc;
}

// Usage in a React component
const handleDownload = () => {
  const doc = generateInvoice(orderData, storeSettings, t);
  doc.save(`invoice-${orderData.number}.pdf`);
};

const handlePreview = () => {
  const doc = generateInvoice(orderData, storeSettings, t);
  window.open(doc.output("bloburi"), "_blank");
};
```

## Invoice Structure and Content

The Fufuni invoice follows a strict visual hierarchy. When modifying the layout, developers must maintain this order to ensure consistency across different store themes.

1.  **Store Header**: Displays the store logo (Base64) if available. If the logo is missing, it falls back to the store name in bold text. Below the name, the store's physical address is rendered if configured.
2.  **Customer Information**: Labeled with "Bill To" or "Ship To" (using `invoice-` i18n keys). Includes customer name, email, and shipping/billing addresses.
3.  **Order Metadata**: Clearly identifies the Order ID/Number, the date of purchase, and the payment method used.
4.  **Itemized Table**: A table generated via `jsPDF-AutoTable` containing:
    *   Product Title
    *   Quantity
    *   Unit Price (tax-exclusive or inclusive based on store settings)
    *   Tax Rate/Amount per line
    *   Row Total
5.  **Totals Section**: A right-aligned block showing Subtotal, Shipping fees, individual Tax lines, and the Grand Total.

### Table Implementation with AutoTable

```typescript
import autoTable from "jspdf-autotable";

function renderItemsTable(doc: jsPDF, order: any, t: TFunction) {
  const tableBody = order.items.map((item: any) => [
    item.product_title,
    item.quantity,
    formatCurrency(item.unit_price_cents, order.currency),
    formatCurrency(item.total_price_cents, order.currency),
  ]);

  autoTable(doc, {
    startY: 70,
    head: [[
      t("invoice-item"), 
      t("invoice-qty"), 
      t("invoice-unit-price"), 
      t("invoice-total")
    ]],
    body: tableBody,
    headStyles: { fillColor: [0, 0, 0] }, // Fufuni default black header
    margin: { left: 14, right: 14 },
  });
}
```

## Currency and Monetary Formatting

In Fufuni, all monetary values are stored as integers in the smallest currency unit (e.g., cents for USD/EUR, yen for JPY). The `utils/currency.ts` module is the single source of truth for converting these integers into human-readable strings.

The `formatCurrency` utility uses the native `Intl.NumberFormat` API. This is critical for supporting Fufuni’s global reach, as it automatically handles currency symbol placement (prefix vs. suffix) and decimal separators based on the user's locale.

### Formatting Utility Usage

```typescript
/**
 * apps/client/src/utils/currency.ts implementation
 */
export function formatCurrency(
  cents: number,
  currency: string = "EUR",
  locale: string = "en-US"
): string {
  const amount = cents / 100;

  return new Intl.NumberFormat(locale, {
    style: "currency",
    currency: currency.toUpperCase(),
    currencyDisplay: "narrowSymbol",
  }).format(amount);
}

// Example: Handling 0-decimal currencies (JPY)
// formatCurrency(1000, "JPY", "ja-JP") -> "￥1,000"
// formatCurrency(1000, "USD", "en-US") -> "$10.00"
```

## Secure Public Access (Order-View Token)

Fufuni allows customers to view and download their invoices without requiring a full account login. This is managed through a "Signed Order-View Token" system.

### Token Flow
1.  **Generation**: When a user clicks "View Invoice" in an email or success page, the client (or email link) points to a server endpoint: `GET /v1/orders/:id/invoice`.
2.  **Validation & Signing**: The server verifies the requester's context and generates a HMAC-signed JWT or encrypted token containing the `order_id`.
3.  **TTL**: The token is short-lived, defaulting to **1 hour**.
4.  **Redirection**: The user is redirected to the public route: `/order-view/:token`.

### Server-side Token Retrieval (Hono)

```typescript
// apps/server/src/routes/orders.ts
app.get("/:id/invoice", zValidator("param", z.object({ id: z.string() })), async (c) => {
  const { id } = c.req.valid("param");
  const order = await c.get('repo').orders.getById(id);
  
  // Generate a token valid for 1 hour
  const token = await signOrderViewToken(order.id, c.env.JWT_SECRET);
  
  return c.json({ 
    view_url: `${c.env.FRONTEND_URL}/order-view/${token}`,
    expires_at: Date.now() + 3600000 
  });
});
```

## The Public Order-View Page

The page located at `apps/client/src/pages/public/OrderView.tsx` (route `/order-view/:token`) is a specialized React component that does not require an authentication header. Instead, it sends the token as a parameter to the backend to retrieve the necessary order details.

import { useParams } from "react-router-dom";

export const OrderView = () => {

## Internationalization (i18n)

All strings rendered inside the PDF must be passed through the `t()` function. Fufuni maintains a strict naming convention for invoice-related keys to prevent collisions with UI elements.

*   **Prefix**: All keys must start with `invoice-`.
*   **Location**: Keys are typically stored in `public/locales/[lang]/common.json` under the "invoice" section or as flat keys.

## Identity and Branding: Store Logo

The invoice generator prioritizes branding via the `store_settings` configuration.

### Logo Processing
The store logo is stored as a **Base64 data URI** in the `store_settings` table in the SQLite (Durable Object) database. This allows the PDF generator to embed the image immediately without making additional network requests for assets, which could fail or be blocked by CORS during PDF generation.

### Handling Missing Logos
If `storeInfo.logoBase64` is null or undefined:
1.  The generator skips the `doc.addImage()` call.
2.  It increases the font size for the `storeInfo.name` string.
3.  The Y-axis position for the store address is adjusted upwards to fill the white space.

```typescript
function drawHeader(doc: jsPDF, storeInfo: StoreInfo, y: number) {
  if (storeInfo.logoBase64) {
    // Add image: (data, format, x, y, width, height)
    doc.addImage(storeInfo.logoBase64, "PNG", 14, y, 40, 20);
    return y + 25;
  } else {
    doc.setFont("helvetica", "bold");
    doc.setFontSize(22);
    doc.text(storeInfo.name, 14, y + 10);
    return y + 20;
  }
}
```

## Developer Guide: Adding New Fields

To add a new field to the invoice (e.g., "VAT Identification Number"), follow these steps across the framework:

1.  **Database/API**: Ensure the field exists in the `orders` table or `store_settings`. Update the Zod schema in `apps/server/src/schemas` so the field is included in the `GET /v1/orders/view/:token` response.
2.  **Types**: Update the `OrderForPdf` interface in `apps/client/src/utils/invoice-pdf.ts` to include the new property.
3.  **i18n**: Add the translation key (e.g., `"invoice-vat-id": "VAT ID"`) to the localization files.
4.  **Generator Logic**: Modify `generateInvoice` in `apps/client/src/lib/invoice-generator.ts` to read the new property and use `doc.text()` or `autoTable` to render it.
