## Adding a New API Route

To add a new API route to the Fufuni e-commerce framework, follow these steps:

### Step 1: Create a new route file

Create a new file in the `apps/merchant/src/routes` directory, e.g., `my-feature.ts`.

### Step 2: Add minimal boilerplate

In the new file, add the following minimal boilerplate:
```typescript
// apps/merchant/src/routes/my-feature.ts
import { OpenAPIHono, createRoute } from '@hono/zod-openapi';
import { z } from 'zod';
import { getDb } from '../db';
import { authMiddleware, adminOnly } from '../middleware/auth';
import { ApiError } from '../types';
import { MyFeatureResponse, MyFeatureBody } from '../schemas';

const publicApp = new OpenAPIHono();
const adminApp = new OpenAPIHono();

// ...
```
### Step 3: Split public vs admin endpoints

Split your endpoints into public and admin endpoints using the `publicApp` and `adminApp` instances. For example:
```typescript
// Public route
const listMyFeaturesRoute = createRoute({
  method: 'get',
  path: '/',
  tags: ['My Features'],
  summary: 'List my features',
  responses: {
    200: { 
      content: { 'application/json': { schema: MyFeatureResponse } },
      description: 'List of my features',
    },
    500: { 
      content: { 'application/json': { schema: ApiError } },
      description: 'Server error',
    },
  },
});

publicApp.openapi(listMyFeaturesRoute, async (c) => {
  const db = getDb(c.var.db);
  try {
    const rows = await db.query<MyFeatureResponse[]>(`SELECT * FROM my_features`);
    return c.json({ items: rows }, 200);
  } catch (error) {
    throw ApiError.internalServerError(error instanceof Error ? error.message : 'Failed to fetch my features');
  }
});

// Admin route
const createMyFeatureRoute = createRoute({
  method: 'post',
  path: '/',
  tags: ['My Features'],
  summary: 'Create a new my feature',
  responses: {
    201: { 
      content: { 'application/json': { schema: MyFeatureResponse } },
      description: 'New my feature created',
    },
    400: { 
      content: { 'application/json': { schema: ApiError } },
      description: 'Invalid request',
    },
    500: { 
      content: { 'application/json': { schema: ApiError } },
      description: 'Server error',
    },
  },
});

adminApp.openapi(createMyFeatureRoute, async (c) => {
  const db = getDb(c.var.db);
  try {
    const body = c.req.valid('json');
    const result = await db.run(`INSERT INTO my_features (name, description) VALUES (?, ?)`, [body.name, body.description]);
    return c.json({ id: result.insertId }, 201);
  } catch (error) {
    throw ApiError.internalServerError(error instanceof Error ? error.message : 'Failed to create my feature');
  }
});
```
### Step 4: Use getDb() to run queries

Use the `getDb()` function to run queries on the database. For example:
```typescript
const db = getDb(c.var.db);
const rows = await db.query<MyFeatureResponse[]>(`SELECT * FROM my_features`);
```
### Step 5: Use ApiError for error responses

Use the `ApiError` class to throw error responses. For example:
```typescript
throw ApiError.internalServerError(error instanceof Error ? error.message : 'Failed to fetch my features');
```
### Step 6: Register the route in index.ts

Register the public route before the `authMiddleware` in `index.ts`. Register the admin route after the `authMiddleware`. For example:
```typescript
app.use('/v1/my-features', publicApp);
app.use('/v1/my-features', adminApp);
```
### Step 7: Available RBAC guards

The following RBAC guards are available to import from `../middleware/auth`:

* `adminOnly`: Requires the user to be an admin.
* `superAdminOnly`: Requires the user to be a super admin.
* `databaseAdminOnly`: Requires the user to have database admin permissions.
* `aiAccessOnly`: Requires the user to have AI access permissions.
* `mailAccessOnly`: Requires the user to have mail access permissions.
* `validJwtAuthOnly`: Requires a valid JWT authentication.
