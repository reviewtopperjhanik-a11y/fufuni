## Architecture of Fufuni API Routes

Fufuni routes are built using `@hono/zod-openapi` to ensure strict type safety and automatic OpenAPI 3.1 documentation generation. Every feature follows a standardized pattern: a single file in `apps/merchant/src/routes/` that exports two distinct Hono apps—one for public access and one for administrative tasks.

### The Standard Route Pattern

A route file typically contains:
1.  **Public Router**: An `OpenAPIHono` instance for endpoints accessible to storefronts (using `pk_` public keys or no auth).
2.  **Admin Router**: An `OpenAPIHono` instance protected by `authMiddleware`, requiring `sk_` secret keys or Auth0 JWTs with specific permissions.
3.  **Schema Imports**: All request/response validation logic must be imported from `../schemas`. Never define Zod schemas directly inside the route file.

```typescript
// apps/merchant/src/routes/tags.ts
import { OpenAPIHono, createRoute } from '@hono/zod-openapi';
import { type HonoEnv, ApiError, uuid, now } from '../types';
import { getDb } from '../db';
import { authMiddleware, adminOnly } from '../middleware/auth';
import { 
  TagResponse, 
  TagListResponse, 
  CreateTagBody,
  ErrorResponse 
} from '../schemas';

// Public endpoints (GET list, GET detail)
const publicApp = new OpenAPIHono<HonoEnv>();

// Admin endpoints (POST, PATCH, DELETE)
const adminApp = new OpenAPIHono<HonoEnv>();
adminApp.use('*', authMiddleware); // Protect all routes in this sub-router

export { publicApp as publicTags, adminApp as adminTags };
```

## Implementing the Endpoint Handler

When defining a route, use `createRoute` to describe the metadata and the Zod schema for the request and response. Fufuni strictly forbids the use of `c.req.json()` or `c.req.param()` directly; you must use `c.req.valid('json')` or `c.req.valid('param')` to ensure the data has been validated against the Zod schema.

### Database Access with getDb()

The database is an SQLite instance running inside a Cloudflare Durable Object. You access it via `c.var.db`.
-   **`db.query<T>(sql, params)`**: Used for `SELECT` statements. Always returns an array.
-   **`db.run(sql, params)`**: Used for mutations (`INSERT`, `UPDATE`, `DELETE`). Returns the number of changes.

```typescript
const listTagsRoute = createRoute({
  method: 'get',
  path: '/',
  tags: ['Tags'],
  summary: 'List all tags',
  responses: {
    200: {
      content: { 'application/json': { schema: TagListResponse } },
      description: 'List of tags',
    },
  },
});

publicApp.openapi(listTagsRoute, async (c) => {
  const db = getDb(c.var.db);
  try {
    const rows = await db.query<any>(`SELECT * FROM tags ORDER BY name ASC`);
    return c.json({ items: rows }, 200);
  } catch (error) {
    throw ApiError.internalServerError('Failed to fetch tags');
  }
});
```

### Error Handling with ApiError

Never return generic JSON objects for errors. Throw an `ApiError` using its static factory methods. This ensures the response follows the standard Fufuni error envelope: `{ error: { code, message, details } }`.

| Method | Status | Use Case |
| :--- | :--- | :--- |
| `ApiError.notFound(msg)` | 404 | Resource does not exist in DB |
| `ApiError.badRequest(msg, details)` | 400 | Invalid input that Zod missed or logic error |
| `ApiError.conflict(msg)` | 409 | Unique constraint violation (e.g., duplicate handle) |
| `ApiError.unauthorized()` | 401 | Missing or invalid credentials |
| `ApiError.forbidden()` | 403 | Authenticated user lacks permission |

```typescript
// Example of a Conflict and Internal Server Error
if (existingTag) {
  throw ApiError.conflict(`Tag with name "${body.name}" already exists`);
}
```

## RBAC Guards and Permissions

Fufuni uses a granular Role-Based Access Control (RBAC) system. While `authMiddleware` validates the identity (JWT or Secret Key), specific guards ensure the user has the required scopes. These guards are passed as `middleware` in the `createRoute` configuration.

| Guard | Required Permission | Usage |
| :--- | :--- | :--- |
| `adminOnly` | `admin:store` | Standard management tasks (products, categories) |
| `superAdminOnly` | `admin:all` | Critical system settings |
| `databaseAdminOnly` | `admin:database` | Direct SQL execution or migration routes |
| `aiAccessOnly` | `ai:api` | Configuring AI translation or generation |
| `mailAccessOnly` | `mail:api` | Sending or configuring transactional emails |
| `validJwtAuthOnly` | N/A | Ensures the user is a logged-in customer (no admin required) |

```typescript
const createTagRoute = createRoute({
  method: 'post',
  path: '/',
  tags: ['Tags'],
  summary: 'Create a new tag',
  security: [{ bearerAuth: ['admin:store'] }],
  middleware: [adminOnly] as const, // Guard applied here
  request: {
    body: { content: { 'application/json': { schema: CreateTagBody } } },
  },
  responses: {
    201: { content: { 'application/json': { schema: TagResponse } }, description: 'Created' },
    403: { content: { 'application/json': { schema: ErrorResponse } }, description: 'Forbidden' },
  },
});
```

## Registering the Route in index.ts

Once your route file is ready, you must mount it in the main `apps/merchant/src/index.ts`. The order of registration is critical for authentication and caching to work correctly.

1.  **Public Registration**: Register public apps *before* the general `v1/*` rate limiting or global auth checks.
2.  **KV Cache**: If the route serves high-traffic public data, register it for caching.
3.  **Admin Registration**: Register admin apps near the bottom.

```typescript
// apps/merchant/src/index.ts

// 1. Import your routers
import { publicTags, adminTags } from './routes/tags';

// ... standard middleware setup ...

// 2. Configure KV Caching (Optional but recommended for public GETs)
app.use('/v1/tags', kvCacheMiddleware);
app.use('/v1/tags', kvInvalidateMiddleware); // Auto-purges cache on POST/PATCH/DELETE

// 3. Mount Public Routes (No auth required)
app.route('/v1/tags', publicTags);

// ... later in the file, after authMiddleware might be used ...

// 4. Mount Admin Routes
app.route('/v1/tags', adminTags);
```

## Full Implementation Example: Tags Feature

This example demonstrates a complete "Tags" feature with a public list and an admin creation endpoint.

### 1. The Route File (`apps/merchant/src/routes/tags.ts`)

```typescript
import { OpenAPIHono, createRoute } from '@hono/zod-openapi';
import { z } from 'zod';
import { ApiError, uuid, now, type HonoEnv } from '../types';
import { getDb } from '../db';
import { authMiddleware, adminOnly } from '../middleware/auth';
import { 
  TagResponse, 
  TagListResponse, 
  CreateTagBody, 
  ErrorResponse 
} from '../schemas';

const publicApp = new OpenAPIHono<HonoEnv>();
const adminApp = new OpenAPIHono<HonoEnv>();

// PUBLIC: List Tags
const listTags = createRoute({
  method: 'get',
  path: '/',
  tags: ['Tags'],
  summary: 'Retrieve all product tags',
  responses: {
    200: { 
      content: { 'application/json': { schema: TagListResponse } },
      description: 'A list of tags' 
    },
  },
});

publicApp.openapi(listTags, async (c) => {
  const db = getDb(c.var.db);
  const items = await db.query<any>('SELECT * FROM tags ORDER BY name ASC');
  return c.json({ items }, 200);
});

// ADMIN: Create Tag
adminApp.use('*', authMiddleware);
const createTag = createRoute({
  method: 'post',
  path: '/',
  tags: ['Tags Admin'],
  summary: 'Create a tag',
  security: [{ bearerAuth: [] }],
  middleware: [adminOnly] as const,
  request: {
    body: { content: { 'application/json': { schema: CreateTagBody } } },
  },
  responses: {
    201: { content: { 'application/json': { schema: TagResponse } }, description: 'Created' },
    409: { content: { 'application/json': { schema: ErrorResponse } }, description: 'Duplicate' },
  },
});

adminApp.openapi(createTag, async (c) => {
  const { name } = c.req.valid('json');
  const db = getDb(c.var.db);

  const [existing] = await db.query<{id: string}>('SELECT id FROM tags WHERE name = ?', [name]);
  if (existing) throw ApiError.conflict('Tag already exists');

  const id = uuid();
  await db.run(
    'INSERT INTO tags (id, name, created_at) VALUES (?, ?, ?)',
    [id, name, now()]
  );

  return c.json({ id, name, created_at: now() }, 201);
});

export { publicApp as publicTags, adminApp as adminTags };
```

### 2. Schema Definition (`apps/merchant/src/schemas/tags.ts`)

```typescript
export const TagResponse = z.object({
  id: z.string().uuid(),
  name: z.string().min(1),
  created_at: z.string().datetime(),
}).openapi('Tag');

export const TagListResponse = z.object({
  items: z.array(TagResponse),
}).openapi('TagList');

export const CreateTagBody = z.object({
  name: z.string().min(1).max(50),
}).openapi('CreateTagRequest');
```

### Summary of Rules
-   **Public Keys (`pk_`)** are valid for `publicApp` routes if configured in `index.ts`.
-   **Secret Keys (`sk_`)** and **Auth0 Tokens** require `authMiddleware`.
-   **Validation** is mandatory via Zod schemas; never use unvalidated request data.
-   **Caching** should be applied to public GET routes using `kvCacheMiddleware` to reduce Durable Object compute costs.
