## How to Add a New API Route
To add a new API route, you'll need to create a new file in the `apps/merchant/src/routes` directory. For this example, let's create a `my-feature.ts` file.

### Minimal Boilerplate
The minimal boilerplate for a new API route includes the necessary imports, an OpenAPIHono instance, and a route handler.
```typescript
import { OpenAPIHono, createRoute } from '@hono/zod-openapi';
import { z } from 'zod';
import { getDb } from '../db';
import { authMiddleware, adminOnly } from '../middleware/auth';
import { TagResponse, CreateTagBody } from '../schemas';

const publicApp = new OpenAPIHono();
const adminApp = new OpenAPIHono();

// Public route: GET /tags
const listTagsRoute = createRoute({
  method: 'get',
  path: '/',
  tags: ['Tags'],
  summary: 'List all tags',
  responses: {
    200: {
      content: { 'application/json': { schema: z.array(TagResponse) } },
      description: 'List of tags',
    },
  },
});

publicApp.openapi(listTagsRoute, async (c) => {
  const db = getDb(c.var.db);
  try {
    const rows = await db.query<TagResponse[]>('SELECT * FROM tags');
    return c.json(rows, 200);
  } catch (error) {
    throw ApiError.internalServerError(error instanceof Error ? error.message : 'Failed to fetch tags');
  }
});

// Admin route: POST /tags
const createTagRoute = createRoute({
  method: 'post',
  path: '/',
  tags: ['Tags'],
  summary: 'Create a new tag',
  security: [{ bearerAuth: ['admin:store'] }],
  middleware: [adminOnly] as const,
  request: {
    body: {
      content: { 'application/json': { schema: CreateTagBody } },
    },
  },
  responses: {
    201: {
      content: { 'application/json': { schema: TagResponse } },
      description: 'Tag created',
    },
  },
});

adminApp.openapi(createTagRoute, async (c) => {
  const body = c.req.valid('json');
  const db = getDb(c.var.db);
  try {
    const result = await db.run('INSERT INTO tags (name) VALUES (?)', [body.name]);
    const tag = await db.query<TagResponse[]>('SELECT * FROM tags WHERE id = ?', [result.lastInsertRowId]);
    return c.json(tag[0], 201);
  } catch (error) {
    throw ApiError.internalServerError(error instanceof Error ? error.message : 'Failed to create tag');
  }
});

export { publicApp as publicTags, adminApp as adminTags };
```

### Splitting Public vs Admin Endpoints
To split public vs admin endpoints, you can use the `publicApp` and `adminApp` export pattern. This allows you to define separate routes for public and admin endpoints.

### Using getDb() to Run Queries
To run queries, you can use the `getDb()` function to get a reference to the database. You can then use the `query()` or `run()` methods to execute SQL queries.

### Using ApiError for Error Responses
To use `ApiError` for error responses, you can import the `ApiError` class and throw instances of it in your route handlers.

### Registering the Route in index.ts
To register the route in `index.ts`, you need to import the `publicApp` and `adminApp` instances and register them with the main app.
```typescript
import { publicTags, adminTags } from './routes/my-feature';

// Register public routes BEFORE authMiddleware
app.route('/v1/tags', publicTags);

// Register admin routes AFTER authMiddleware
app.use('/v1/*', rateLimitMiddleware());
app.use('/v1/*', authMiddleware);
app.route('/v1/tags', adminTags);
```

### Available RBAC Guards
The available RBAC guards are:
* `adminOnly`: Requires the `admin:store` permission.
* `superAdminOnly`: Requires the `super:admin` permission.
* `databaseAdminOnly`: Requires the `admin:database` permission.
* `aiAccessOnly`: Requires the `ai:access` permission.
* `mailAccessOnly`: Requires the `mail:access` permission.
* `validJwtAuthOnly`: Requires a valid JWT authentication token.

These guards can be used to protect routes and ensure that only authorized users can access them.
