## Layout Architecture: Default vs. Luxury

Fufuni provides two primary layout wrappers found in `apps/client/src/layouts/`. Choosing between them defines the high-level visual structure and spacing of the storefront.

### Default Layout
The `DefaultLayout` is designed for standard e-commerce operations. It utilizes a fixed-height flex container (`h-screen`) to keep the footer at the bottom of the viewport even with minimal content. It enforces a strict horizontal constraint using the HeroUI `container` class with `max-w-7xl` and `px-6`.

Key characteristics:
- **Spacing:** `pt-16` on the main element to account for the fixed navbar.
- **Footer:** A complex 5-column grid footer containing newsletter subscription, multi-category links, and payment method badges.
- **Auth Integration:** Automatically decodes and manages the Auth0 access token for technical debugging (via `UserTechnicalInfoModal`).

### Luxury Layout
The `LuxuryLayout` is intended for editorial-style pages, brand storytelling, or high-end product showcases. It switches to `min-h-screen` and removes horizontal padding from the `<main>` tag.

Key characteristics:
- **Full-Bleed:** The `<main>` element is `w-full` without a max-width container, allowing components (like hero sections) to span the entire screen width.
- **Footer:** Uses a dedicated, simplified, and typically dark-themed `<Footer>` component from `@/components/footer`.
- **Minimalism:** Does not include the technical token decoding logic present in the default layout.

```typescript
// Example: Switching layouts in a React Router configuration
import { Routes, Route } from "react-router-dom";
import DefaultLayout from "@/layouts/default";
import LuxuryLayout from "@/layouts/luxury";
import HomePage from "@/pages/home";
import AboutPage from "@/pages/about";

export function AppRoutes() {
  return (
    <Routes>
      {/* Standard shop pages use DefaultLayout */}
      <Route
        path="/"
        element={
          <DefaultLayout>
            <HomePage />
          </DefaultLayout>
        }
      />

      {/* Editorial/Brand pages use LuxuryLayout */}
      <Route
        path="/brand-story"
        element={
          <LuxuryLayout>
            <AboutPage />
          </LuxuryLayout>
        }
      />
    </Routes>
  );
}
```

## Theme Management and Auth0 Synchronization

Themes in Fufuni are not simply CSS classes; they are controlled via the `data-theme` attribute on the `<html>` element. The framework supports multiple slugs: `default`, `luxury`, and `luxury-dark`.

### Theme Storage Strategy
1. **Authenticated Users:** The active theme is stored in Auth0 `user_metadata`. Specifically, it is scoped to the store URL within the metadata object. This preference is injected into the JWT Access Token under the `extra_user_info/user_metadata` claim.
2. **Guest Users:** Preferences are persisted in the browser's `localStorage` using the key `ui-theme`.

### The StoreThemeProvider
The `StoreThemeProvider` (in `apps/client/src/providers/theme-provider.tsx`) lives at the top of the React tree, often outside the `AuthenticationProvider`. It performs a "pre-flight" check on mount to apply the `localStorage` theme immediately, preventing a Flash of Unstyled Content (FOUC).

### Cross-Component Synchronization
Since the theme can be changed from deep within the UI (e.g., a settings page or a navbar toggle), Fufuni uses a `CustomEvent` named `fufuni:theme-updated` to broadcast changes globally. When `setTheme` is called, it updates the backend (or local storage) and dispatches this event.

```typescript
// Functional Example: Creating a Theme Toggle Component
import { Button } from "@heroui/react";
import { useStoreTheme } from "@/providers/theme-provider";

export const ThemeToggle = () => {
  const { theme, setTheme, isLoading } = useStoreTheme();

  const toggleTheme = () => {
    const nextTheme = theme === "luxury-dark" ? "default" : "luxury-dark";
    setTheme(nextTheme);
  };

  return (
    <Button 
      isLoading={isLoading} 
      onPress={toggleTheme}
      variant="flat"
    >
      Current Theme: {theme ?? "Default"}
    </Button>
  );
};
```

### JWT Extraction Logic
The system uses the `jose` library to decode the token without a backend round-trip. The `getThemeFromToken` utility navigates the nested metadata structure:

```typescript
import { decodeJwt } from "jose";

export function getThemeFromToken(token: string | null): string | null {
  if (!token) return null;
  try {
    const payload = decodeJwt(token) as any;
    const userMetadata = payload["extra_user_info/user_metadata"];
    // Logic inside getStoreMetadata handles the STORE_URL scoping
    return userMetadata?.theme ?? null;
  } catch {
    return null;
  }
}
```

## Static CMS Content (cms-content.ts)

Fufuni avoids the overhead of a headless CMS for static informational pages (About, FAQ, Privacy Policy). Instead, it uses a typed, localized configuration file: `apps/client/src/config/cms-content.ts`.

### Content Structure
The `CMS_CONTENT` object is indexed by a "handle" (slug) and then by locale. This structure allows for multi-paragraph text blocks that are too large for standard i18n JSON files.

```typescript
// Example: Adding a new CMS page
export const CMS_CONTENT: Record<string, Record<string, CmsPageContent>> = {
  "shipping-info": {
    "en-US": {
      title: "Shipping Information",
      lead: "Fast delivery to your doorstep.",
      sections: [
        {
          heading: "Processing Times",
          body: "Orders are shipped within 24 hours."
        }
      ]
    },
    "fr-FR": {
      title: "Informations de livraison",
      lead: "Livraison rapide à votre porte.",
      sections: [
        {
          heading: "Délais de traitement",
          body: "Les commandes sont expédiées sous 24 heures."
        }
      ]
    }
  }
};
```

### Retrieval and Fallbacks
The `getCmsPage` function implements a robust fallback mechanism:
1. Exact locale match (e.g., `en-US`).
2. Language code match (e.g., `en` from `en-GB`).
3. Default fallback to `en-US`.
4. Returns `null` if the handle does not exist.

### Rendering CMS Pages
To render these blocks, components should utilize the `getCmsPage` helper in conjunction with the current locale from `i18next`.

```typescript
import { useParams } from "react-router-dom";
import { useTranslation } from "react-i18next";
import { getCmsPage } from "@/config/cms-content";

export const CmsPageRenderer = () => {
  const { handle } = useParams();
  const { i18n } = useTranslation();
  
  const content = getCmsPage(handle || "about", i18n.language);

  if (!content) return <div>Page not found</div>;

  return (
    <article className="prose dark:prose-invert max-w-none">
      <h1>{content.title}</h1>
      <p className="text-xl text-default-500">{content.lead}</p>
      {content.sections.map((section, idx) => (
        <section key={idx} className="mt-8">
          <h2 className="text-2xl font-bold">{section.heading}</h2>
          <p className="mt-2 leading-relaxed">{section.body}</p>
        </section>
      ))}
    </article>
  );
};
```

## Backend Persistence

When a user changes their theme via `setTheme`, the client makes a `PATCH` request to the backend. The backend does not store this in the local SQLite database. Instead, it acts as a proxy to the Auth0 Management API to update the user's `user_metadata`.

### The API Flow
1. **Frontend:** `auth.patchJson('/v1/me/preferences', { theme: 'luxury' })`.
2. **Backend (Hono):** Validates the request with Zod, extracts the Auth0 User ID from the JWT, and calls the Auth0 Management API.
3. **Frontend Sync:** After a successful PATCH, the frontend calls `refreshToken()` to get a fresh JWT containing the updated metadata, then broadcasts the change via `THEME_UPDATED_EVENT`.

```typescript
// Simplified view of the PATCH logic in useStoreTheme hook
const setTheme = useCallback(
  async (slug: string | null) => {
    if (auth.isAuthenticated) {
      // 1. Persist to Auth0 via Fufuni Backend
      await auth.patchJson(`${apiBase}/v1/me/preferences`, { theme: slug });
      
      // 2. Force token refresh to get updated user_metadata
      const newToken = await refreshToken();
      
      // 3. Extract new theme from the new token
      const newTheme = getThemeFromToken(newToken ?? null);
      
      // 4. Sync UI state
      setThemeData(newTheme);
      window.dispatchEvent(new CustomEvent(THEME_UPDATED_EVENT, { detail: newTheme }));
    }
  },
  [auth, apiBase, refreshToken]
);
```

This architecture ensures that the theme follows the user across devices without requiring Fufuni to maintain a separate user preferences table in its edge database, leveraging Auth0 as the single source of truth for identity and profile metadata.
