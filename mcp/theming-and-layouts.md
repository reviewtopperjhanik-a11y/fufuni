## Layout Architecture

Fufuni provides two primary layout patterns: `DefaultLayout` and `LuxuryLayout`. These are not just visual differences; they dictate how child components handle their own constraints and scrolling behavior.

### Default vs Luxury Comparison

The `DefaultLayout` is designed for standard e-commerce views (product listings, account management). It uses a fixed height viewport (`h-screen`) and forces the `<main>` content into a centered container with standard padding.

In contrast, the `LuxuryLayout` is intended for editorial-style pages or landing screens. It uses `min-h-screen` to allow the page to grow naturally with long content and removes the `<main>` container constraints. This "full-bleed" approach means individual sections (like hero banners or carousels) are responsible for their own max-width logic.

```typescript
// apps/client/src/layouts/luxury.tsx
import type React from "react";
import { useState } from "react";
import { Navbar } from "@/components/navbar";
import { CartDrawer } from "@/components/cart-drawer";
import { ThemeSwitcher } from "@/components/ui/theme-switcher";
import { Footer } from "@/components/footer";

/**
 * LuxuryLayout — full-bleed layout for luxury/editorial pages.
 * No horizontal padding on <main>: components manage their own max-width.
 */
export default function LuxuryLayout({
  children,
}: {
  children: React.ReactNode;
}) {
  const [isCartOpen, setIsCartOpen] = useState(false);

  return (
    <div className="relative flex flex-col min-h-screen">
      <Navbar onCartOpen={() => setIsCartOpen(true)} />
      <CartDrawer isOpen={isCartOpen} onClose={setIsCartOpen} />
      <main className="w-full grow pt-16">
        {/* Children fill 100% width unless they use .container mx-auto */}
        {children}
      </main>
      <Footer />
      <ThemeSwitcher />
    </div>
  );
}
```

### Layout Data Fetching

Both layouts share a critical responsibility: ensuring the Auth0 Access Token is valid and decoded. The `DefaultLayout` implements a `decodeAndStoreToken` logic using the `jose` library to verify the JWT against local JWKS. This allows the UI to react to user permissions or technical info stored in the token without making additional round-trips to the backend.

## Theme Management and Injection

Fufuni uses a hybrid approach to theme storage. Authenticated users have their theme preference stored in Auth0 `user_metadata`, while guests rely on `localStorage`.

### Theme State and Persistence

The `StoreThemeProvider` is a specialized provider that lives outside the main `AuthenticationProvider` tree. This separation is vital to prevent a "Flash of Unstyled Content" (FOUC). On initial mount, it immediately reads from `localStorage` before the Auth0 SDK even initializes.

1.  **Guest Logic**: Theme is stored in `localStorage` under the key `ui-theme`.
2.  **Auth Logic**: Theme is injected into the JWT payload by the Auth0 Action on the backend. The frontend extracts it using `decodeJwt`.
3.  **Synchronization**: When a user changes their theme via the `useStoreTheme` hook, a `CustomEvent` named `fufuni:theme-updated` is dispatched globally. This ensures that even components outside the current React tree update their visual state.

```typescript
// apps/client/src/providers/theme-provider.tsx - Implementation of Sync
import { decodeJwt } from "jose";
import { getStoreMetadata } from "@/lib/store-metadata";

export const THEME_UPDATED_EVENT = "fufuni:theme-updated";
const STORE_URL = import.meta.env.STORE_URL;

/**
 * Extracts theme from the JWT user_metadata.
 * Note: metadata is often scoped to the specific STORE_URL.
 */
export function getThemeFromToken(token: string | null): string | null {
  if (!token) return null;
  try {
    const payload = decodeJwt(token) as any;
    const userMetadata = payload["extra_user_info/user_metadata"];
    // Resolve metadata specific to this Fufuni instance
    const storeMetadata = getStoreMetadata(userMetadata, STORE_URL);

    return storeMetadata?.theme ?? userMetadata?.theme ?? null;
  } catch {
    return null;
  }
}

/**
 * Global applier that touches the DOM.
 * HeroUI v3 uses the data-theme attribute on <html> to switch Tailwind variables.
 */
function applyTheme(slug: string | null) {
  const root = document.documentElement;
  if (!slug || slug === "default") {
    root.removeAttribute("data-theme");
  } else {
    root.setAttribute("data-theme", slug);
  }
}
```

### Mutating Preferences

To persist a theme change for an authenticated user, the frontend calls the `PATCH /v1/me/preferences` endpoint. This backend route interacts with the Auth0 Management API to update the user's permanent metadata. After the patch, the frontend triggers a silent token refresh to get a new JWT containing the updated theme.

```typescript
// Example usage of useStoreTheme in a component
import { useStoreTheme, AVAILABLE_THEMES } from "@/providers/theme-provider";
import { Button } from "@heroui/react";

export const ThemeToggle = () => {
  const { theme, setTheme } = useStoreTheme();

  return (
    <div className="flex gap-2">
      {AVAILABLE_THEMES.map((t) => (
        <Button 
          key={t} 
          variant={theme === t ? "solid" : "flat"}
          onPress={() => setTheme(t)}
        >
          {t}
        </Button>
      ))}
    </div>
  );
};
```

## Static CMS Content System

Fufuni avoids the latency of a database-driven CMS for standard informational pages (About, Privacy, FAQ). Instead, it uses `cms-content.ts`, a structured TypeScript configuration that supports multi-locale content blocks.

### Content Structure

Content is organized by **handle** (the page identifier) and **locale**. This ensures that the framework remains "Edge-Native" — all text content is bundled with the application code and available instantly without an additional network hop to a database or headless CMS.

```typescript
// apps/client/src/config/cms-content.ts
export type CmsSection = {
  heading: string;
  body: string;
};

export type CmsPageContent = {
  title: string;
  lead: string;
  sections: CmsSection[];
};

export const CMS_CONTENT: Record<string, Record<string, CmsPageContent>> = {
  about: {
    "en-US": {
      title: "About Fufuni",
      lead: "Fufuni is an open-source e-commerce platform built on Cloudflare's edge.",
      sections: [
        { heading: "Our Story", body: "Fufuni was born from a simple frustration..." }
      ],
    },
    "fr-FR": {
      title: "À propos de Fufuni",
      lead: "Fufuni est une plateforme e-commerce open source construite sur le réseau edge de Cloudflare.",
      sections: [
        { heading: "Notre histoire", body: "Fufuni est né d'une frustration simple..." }
      ],
    }
  }
};
```

### Fetching and Locale Fallbacks

The `getCmsPage` utility function provides a robust resolution strategy. It first attempts an exact locale match (e.g., `fr-FR`). If that fails, it tries a language-only match (e.g., `fr`), and finally falls back to `en-US`.

```typescript
/**
 * Resolves CMS content with locale fallback logic.
 * Used in dynamic routes like /pages/:handle
 */
export function getCmsPage(
  handle: string,
  locale: string,
): CmsPageContent | null {
  const page = CMS_CONTENT[handle];
  if (!page) return null;

  return (
    page[locale] ??
    page[Object.keys(page).find((k) => k.startsWith(locale.split("-")[0])) ?? ""] ??
    page["en-US"] ??
    null
  );
}
```

### Rendering CMS Pages

When building a page that consumes this content, use the `sections` array to map over the content. This structure is perfectly suited for HeroUI's layout components or simple typography blocks.

```typescript
import { useParams } from "react-router-dom";
import { useTranslation } from "react-i18next";
import { getCmsPage } from "@/config/cms-content";

export const DynamicCmsPage = () => {
  const { handle } = useParams();
  const { i18n } = useTranslation();
  const content = getCmsPage(handle || "", i18n.language);

  if (!content) return <div>Page not found</div>;

  return (
    <article className="prose dark:prose-invert max-w-none">
      <h1 className="text-4xl font-bold">{content.title}</h1>
      <p className="text-xl text-default-500">{content.lead}</p>
      
      <div className="mt-8 space-y-12">
        {content.sections.map((section, idx) => (
          <section key={idx}>
            <h2 className="text-2xl font-semibold">{section.heading}</h2>
            <p className="mt-2 leading-relaxed text-default-600">
              {section.body}
            </p>
          </section>
        ))}
      </div>
    </article>
  );
};
```

## Styling Conventions with HeroUI

Fufuni relies on **HeroUI v3** (formerly NextUI) for its component primitive library. When creating new layout elements:

1.  **Semantic Colors**: Always use semantic tokens like `primary`, `secondary`, `default-500`, and `background` instead of hardcoded hex codes. This ensures your component respects the active theme (e.g., switching from `luxury` to `luxury-dark`).
2.  **Dark Mode**: Dark mode is handled via the `luxury-dark` theme slug or the HeroUI default dark class. Use `dark:` variants in Tailwind classes for specific overrides.
3.  **Separators**: Use the `border-separator` class for consistent borders across the header, footer, and cards.
4.  **Responsive Containers**: In the `DefaultLayout`, use `max-w-7xl px-6 mx-auto` to align with the framework's standard grid. In `LuxuryLayout`, allow sections to reach `w-full` for high-impact visual elements.
