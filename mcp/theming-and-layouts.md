## Theming and Layouts
In Fufuni, theming and layouts play a crucial role in providing a visually appealing and consistent user experience across the application. The framework offers two distinct layouts: default and luxury, each serving a unique purpose.

### Layout Differences
The primary differences between the default and luxury layouts lie in their visual presentation:

* **Default Layout**: This is the standard layout used throughout the application. It features a container with padding, which wraps the main content, and uses the `h-screen` class for flexibility.
* **Luxury Layout**: Designed for specific pages or sections that require a more premium look, the luxury layout is a complete visual variant. It features:
	+ Full-bleed main content (no container padding)
	+ A dedicated `<Footer>` component
	+ `min-h-screen` instead of `h-screen` for flexibility

The luxury layout is ideal for pages that need to make a bold statement, such as editorial or product showcase pages.

### Custom Theme Storage and Injection
Fufuni stores per-user theme preferences in Auth0's `user_metadata`. This allows for seamless theme switching and persistence across sessions. When a user authenticates, the `StoreThemeProvider` reads the theme preference from the JWT payload using `decodeJwt()` from the `jose` library. It then applies the selected theme as a `data-theme` attribute on the `<html>` element.

For unauthenticated users, the theme preference is stored in `localStorage` under the key `"ui-theme"`.

### Using CMS Content
The `cms-content.ts` file defines editable content blocks, such as hero banners, carousels, and other CMS-related content. These blocks can be easily managed and updated without requiring an external CMS database. By leveraging this approach, developers can create and edit content blocks directly within the codebase, streamlining the development and maintenance process.

### Theme Changes and Propagation
When a user updates their theme preference, the change is propagated across components using a custom DOM event, `THEME_UPDATED_EVENT = "fufuni:theme-updated"`. This ensures that all components, including those outside the authentication tree, are notified and updated with the new theme.

To persist a theme preference, you can call `PATCH /v1/me/preferences`, which updates the Auth0 `user_metadata` via the Management API.

### Example Usage
To switch to a different theme, you can use the `setTheme` function provided by the `useStoreTheme` hook:
```typescript
import { useStoreTheme } from '@/providers/theme-provider';

function MyComponent() {
  const { setTheme } = useStoreTheme();

  const handleThemeSwitch = async () => {
    await setTheme('luxury');
  };

  return (
    <div>
      <button onClick={handleThemeSwitch}>Switch to Luxury Theme</button>
    </div>
  );
}
```
In this example, the `handleThemeSwitch` function updates the theme to `'luxury'` when the button is clicked. The `setTheme` function takes care of persisting the theme preference and propagating the change across components.
