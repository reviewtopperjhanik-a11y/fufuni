## Core Layout Architecture

Fufuni provides two primary layout wrappers in `apps/client/src/layouts/`. Choosing the correct layout is critical for SEO and user experience, as they dictate the navigation structure and container constraints.

### 1. DefaultLayout
The `DefaultLayout` is the standard e-commerce wrapper. It is used for the storefront, category listings, and account pages. 

- **Components provided:** `Navbar`, `CartDrawer`, `Footer`, and `ThemeSwitcher`.
- **Constraint:** Uses a centered container (`max-w-7xl px-6`) for the `<main>` element.
- **Auth Integration:** This layout is responsible for managing Auth0 token lifecycle and decoding. It listens for the `TOKEN_REFRESHED_EVENT` to keep the UI in sync with the latest session data.

```typescript
// Example usage in a router configuration
import DefaultLayout from "@/layouts/default";
import HomePage from "@/pages/index";

export const routes = [
  {
    path: "/",
    element: (
      <DefaultLayout>
        <HomePage />
      </DefaultLayout>
    ),
  },
];
```

### 2. LuxuryLayout
The `LuxuryLayout` is designed for editorial content and premium product landing pages.

- **Components provided:** `Navbar`, `CartDrawer`, `LuxuryFooter`, and `ThemeSwitcher`.
- **Constraint:** Full-bleed (`w-full`). It removes horizontal padding from the `<main>` element, allowing components like `Hero` sections to span the entire viewport width.
- **Header Behavior:** Typically used with a minimal or transparent header configuration to emphasize high-quality imagery.

```typescript
// apps/client/src/layouts/luxury.tsx implementation detail
export default function LuxuryLayout({ children }: { children: React.ReactNode }) {
  const [isCartOpen, setIsCartOpen] = useState(false);

      <main className="w-full grow pt-16">{children}</main>

}
```

## StoreThemeProvider and CSS Variables

The `StoreThemeProvider` is the engine behind Fufuni's white-labeling capabilities. It dynamically applies brand-specific aesthetics by injecting CSS variables into the `:root` or a `data-theme` attribute on the `<html>` element.

### Theme Resolution Logic
The provider handles three distinct states for theme resolution:
1. **Authenticated Users:** The theme is extracted from the `user_metadata` within the Auth0 JWT.
2. **Guest Users:** The theme is read from `localStorage` under the `ui-theme` key.
3. **Initialization:** On mount, it fetches the active store configuration from `GET /v1/store-themes/active` to ensure the runtime reflects the database state.

### Broadcast Mechanism
Because the `StoreThemeProvider` often lives outside the primary `AuthenticationProvider` tree (to prevent re-renders of the whole app on auth state changes), it uses a `CustomEvent` (`fufuni:theme-updated`) to synchronize state changes across the component tree.

```typescript
// Broadcasting a theme change from a settings component
const handleThemeChange = (newTheme: string) => {
  window.dispatchEvent(
    new CustomEvent("fufuni:theme-updated", { detail: newTheme })
  );
};
```

## Adding a New CSS Variable

To introduce a new global style property (e.g., a custom border radius or a specific accent color), you must synchronize the backend schema with the frontend application.

### Step 1: Update the Database Schema
Add the new field to the `store_themes` table in the SQLite D1 database.
```sql
ALTER TABLE store_themes ADD COLUMN border_radius_card TEXT DEFAULT '8px';
```

### Step 2: Apply in Theme Provider
Update `applyTheme` in `apps/client/src/providers/theme-provider.tsx` to set the CSS variable on the document root.
```typescript
function applyTheme(config: any) {
  const root = document.documentElement;
  // ... existing logic
  if (config.border_radius_card) {
    root.style.setProperty('--card-radius', config.border_radius_card);
  }
}
```

### Step 3: Use in Tailwind or Components
Reference the variable in your CSS files or Tailwind configuration.
```css
/* apps/client/src/styles/globals.css */
.fufuni-card {
  border-radius: var(--card-radius, 8px);
  @apply border border-separator bg-background;
}
```

## ThemeSwitch vs StoreTheme

It is important to distinguish between **User Mode** and **Store Theme**.

| Feature | ThemeSwitch (HeroUI) | StoreTheme (Fufuni) |
| :--- | :--- | :--- |
| **Scope** | Light vs Dark mode | Brand identity (Primary colors, fonts) |
| **Persistence** | Local browser preference | Database (`store_themes` table) |
| **Mechanism** | Toggles `.dark` class on `<html>` | Sets `data-theme="luxury"` or CSS vars |
| **Override** | Users can toggle anytime | Set by store admin in dashboard |

## CMS Content Structure

Fufuni uses a hybrid CMS approach. Static, multi-paragraph content for informational pages (About, FAQ, Policies) is managed in `cms-content.ts`, while dynamic runtime configurations (banners, categories) are managed via the `siteConfig()` utility.

### The CMS_CONTENT Map
The `CMS_CONTENT` object is indexed by a `handle` (URL slug) and a `locale`. This avoids bloating the i18n JSON files with large blocks of text that require structured rendering.

```typescript
// apps/client/src/config/cms-content.ts
export const CMS_CONTENT: Record<string, Record<string, CmsPageContent>> = {
  "shipping-policy": {
    "en-US": {
      title: "Shipping Policy",
      lead: "Fast delivery globally.",
      sections: [
        { heading: "Rates", body: "Flat $5 for all orders." }
      ]
    }
  }
};
```

### Fetching and siteConfig()
The `siteConfig()` function acts as the bridge between hardcoded defaults and values fetched from the backend `GET /v1/cms/content`. This includes:
- Global social media links.
- Promotional banner text.
- Featured product category IDs.

## Adding a New CMS Section

When the business requirements change (e.g., adding a "Sustainability" section to the footer and a corresponding page), follow these steps:

### 1. Define the Type
Add the field to the `CmsPageContent` or a new specific type in `cms-content.ts`.

### 2. Implement the Admin Editor
In the `apps/admin` workspace, add a form field to the CMS management page. This allows administrators to input content for different locales.

### 3. API Persistence
Ensure the admin panel calls `PUT /v1/cms/content` to save the new section data into the SQLite database.

### 4. Render the Content
Use the `getCmsPage` helper to fetch and display the data in your React component.

```typescript
import { getCmsPage } from "@/config/cms-content";
import { useTranslation } from "react-i18next";

export function SustainabilityPage() {
  const { i18n } = useTranslation();
  const content = getCmsPage("sustainability", i18n.language);

  if (!content) return null;

  return (
    <article className="prose dark:prose-invert">
      <h1>{content.title}</h1>
      <p className="lead">{content.lead}</p>
      {content.sections.map(s => (
        <section key={s.heading}>
          <h3>{s.heading}</h3>
          <p>{s.body}</p>
        </section>
      ))}
    </article>
  );
}
```

## HeroUI Color Overrides

Fufuni leverages HeroUI's design system but forces overrides via the `StoreThemeProvider`. When a theme like `luxury` is active, HeroUI components (Buttons, Inputs, Modals) will look for CSS variables defined under that theme's scope.

To customize HeroUI colors via the Fufuni theme system, you map the Fufuni variables to the HeroUI semantic tokens in your tailwind config:

```typescript
// tailwind.config.js (conceptual mapping)
const { heroui } = require("@heroui/react");

module.exports = {
  plugins: [
    heroui({
      themes: {
        luxury: {
          colors: {
            primary: {
              DEFAULT: "var(--color-primary-luxury)",
              foreground: "var(--color-primary-luxury-fg)",
            },
            focus: "var(--color-accent-luxury)",
          },
        },
      },
    }),
  ],
};
```

By using `var()` references in the Tailwind configuration, Fufuni ensures that a single change in the Database/StoreThemeProvider instantly propagates through all HeroUI components without requiring a rebuild of the frontend assets.
