## Theming and Layouts
Theming and layouts are crucial components of the Fufuni e-commerce framework, allowing for customization and flexibility in the user interface. This reference will cover the differences between the default and luxury layouts, custom theme storage, and the use of `cms-content.ts` for editable CMS blocks.

### Layouts
Fufuni provides two primary layouts: default and luxury. The main differences between these layouts are:

* **Default Layout**: This is the standard layout used throughout the application. It features a container with padding, a standard footer, and a flex-based height.
* **Luxury Layout**: This is a visually distinct layout used for specific pages, such as the home page or landing pages. It features a full-bleed main section (no container padding), a dedicated `<Footer>` component, and a `min-h-screen` instead of `h-screen` flex.

The luxury layout is implemented in `apps/client/src/layouts/luxury.tsx`, while the default layout is defined in `apps/client/src/layouts/default.tsx`.

### Custom Theme Storage
Fufuni stores custom theme preferences in the user's Auth0 `user_metadata`. This data is not stored directly in the database but rather in the Auth0 user management system. When a user logs in, their theme preference is read from the JWT payload using the `decodeJwt()` function from the `jose` library.

For unauthenticated users, the theme preference is stored in local storage using the key `ui-theme`. The `StoreThemeProvider` reads this value and applies it as a `data-theme` attribute on the `<html>` element.

### Using cms-content.ts
The `cms-content.ts` file defines editable content blocks, such as hero banners and carousels, without requiring an external CMS database. This file contains a map of handle-locale-content, where each content block is defined as a `CmsPageContent` object.

To use these content blocks, simply import the `CMS_CONTENT` map and access the desired content block by its handle and locale.

### Theme Changes and Propagation
When a user updates their theme preference, the change is propagated across components via a custom DOM event called `THEME_UPDATED_EVENT` (`"fufuni:theme-updated"`). This event is dispatched after a theme mutation, allowing all providers to sync without requiring a page reload.

To persist a theme preference, a `PATCH /v1/me/preferences` request is sent to the API, updating the Auth0 user metadata via the Management API.

### Example Code
Here's an example of how to use the `cms-content.ts` file to access a content block:
```typescript
import { CMS_CONTENT } from '@/config/cms-content';

const currentPageContent = CMS_CONTENT['about']['en-US'];
console.log(currentPageContent.title); // Output: "About Fufuni"
```
And here's an example of how to dispatch the `THEME_UPDATED_EVENT` after updating the theme preference:
```typescript
import { THEME_UPDATED_EVENT } from '@/providers/theme-provider';

// Update theme preference
const newTheme = 'luxury';
// ...

// Dispatch THEME_UPDATED_EVENT
window.dispatchEvent(new CustomEvent(THEME_UPDATED_EVENT, { detail: newTheme }));
```
