## Theming and Layouts
Theming and layouts are crucial aspects of the Fufuni e-commerce framework, providing a visually appealing and user-friendly experience. This reference will cover the differences between the default and luxury layouts, custom theme storage, and the use of `cms-content.ts` for editable CMS blocks.

### Layouts
Fufuni offers two primary layouts: default and luxury. The main differences between these layouts are:

*   **Default Layout**: The default layout features a container with padding on the main content area, a standard footer component, and a `h-screen` flex container.
*   **Luxury Layout**: In contrast, the luxury layout is a complete visual variant with a full-bleed main area (no container padding), a dedicated `<Footer>` component, and a `min-h-screen` instead of `h-screen` flex container. This layout is designed for luxury or editorial pages and provides a more immersive experience.

Here's an example of how to use the luxury layout:
```typescript
import LuxuryLayout from "@/layouts/luxury";

function LuxuryPage() {
  return (
    <LuxuryLayout>
      {/* Page content */}
    </LuxuryLayout>
  );
}
```

### Custom Theme Storage
Custom theme preferences are stored in the `user_metadata` section of the Auth0 user profile, not directly in the database. The `StoreThemeProvider` reads the theme preference from the JWT payload using the `decodeJwt()` function from the `jose` library and applies it as a `data-theme` attribute on the `<html>` element.

For unauthenticated users, the theme preference is stored in `localStorage` using the key `"ui-theme"`.

To persist a theme preference, you need to call the `PATCH /v1/me/preferences` endpoint, which updates the Auth0 `user_metadata` via the Management API.

Here's an example of how to update the theme preference:
```typescript
import { patchJson } from "@/lib/api";

const updateTheme = async (theme: string | null) => {
  try {
    await patchJson(`${apiBase}/v1/me/preferences`, {
      theme: theme || "",
    });
  } catch (err) {
    console.error("[updateTheme] Failed to update theme:", err);
  }
};
```

### Using `cms-content.ts` for Editable CMS Blocks
The `cms-content.ts` file defines editable content blocks, such as hero banners and carousels, without relying on an external CMS database. This approach allows for easy management of CMS content within the Fufuni framework.

Here's an example of how to use the `cms-content.ts` file:
```typescript
import { CMS_CONTENT } from "@/config/cms-content";

function AboutPage() {
  const aboutContent = CMS_CONTENT.about["en-US"];

  return (
    <div>
      <h1>{aboutContent.title}</h1>
      <p>{aboutContent.lead}</p>
      {aboutContent.sections.map((section, index) => (
        <div key={index}>
          <h2>{section.heading}</h2>
          <p>{section.body}</p>
        </div>
      ))}
    </div>
  );
}
```

### Propagating Theme Changes
Theme changes are propagated across components using a custom DOM event named `THEME_UPDATED_EVENT` (`"fufuni:theme-updated"`). After a theme mutation, dispatch this event to sync all providers without a page reload.

Here's an example of how to dispatch the `THEME_UPDATED_EVENT`:
```typescript
import { THEME_UPDATED_EVENT } from "@/providers/theme-provider";

const handleThemeChange = (newTheme: string | null) => {
  window.dispatchEvent(new CustomEvent(THEME_UPDATED_EVENT, { detail: newTheme }));
};
```

By following these guidelines and using the provided examples, you can effectively implement theming and layouts in your Fufuni e-commerce application.
