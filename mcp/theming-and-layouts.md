## Core Layouts

Fufuni provides two distinct layout components to handle different visual requirements: the **DefaultLayout** for standard store interactions and the **LuxuryLayout** for high-impact, editorial-style pages.

### DefaultLayout
The `DefaultLayout` is the standard shell for the storefront. It includes the global `Navbar`, `CartDrawer`, `Footer`, and a toast notification provider. This layout wraps children in a container with a maximum width of `7xl` and standard horizontal padding. 

**Usage Rules:**
- Use for Category pages, Account pages, and general Information pages.
- The `Navbar` is automatically included; pages using this layout must not define their own navigation.
- Managed components like `CartDrawer` and `ThemeSwitcher` are pre-integrated.

```typescript
import DefaultLayout from "@/layouts/default";

export default function AboutPage() {
  return (
    <DefaultLayout>
      <div className="py-10">
        <h1 className="text-4xl font-bold">About Our Store</h1>
        <p className="mt-4">General content goes here.</p>
      </div>
    </DefaultLayout>
  );
}
```

### LuxuryLayout
The `LuxuryLayout` provides a full-bleed canvas. It removes the standard `Navbar` in favor of a minimal, transparent header and uses a specialized dark luxury footer.

**Usage Rules:**
- Use specifically for product landing pages or promotional "Hero" pages.
- Provides a `w-full` main container without predefined horizontal padding, allowing components to span the entire screen width.

```typescript
import LuxuryLayout from "@/layouts/luxury";
import { HeroSection } from "@/components/hero";

export default function ProductLanding() {
  return (
    <LuxuryLayout>
      {/* This component can now be truly full-width */}
      <HeroSection 
        title="The New Collection" 
        image="/assets/luxury-bg.jpg" 
      />
    </LuxuryLayout>
  );
}
```

## StoreThemeProvider and CSS Variables

The `StoreThemeProvider` is the architectural bridge between the backend configuration and the frontend CSS. Unlike standard theme providers that only toggle light/dark modes, this provider injects store-specific branding.

At runtime, the provider fetches the active theme configuration from the API (`GET /v1/store-themes/active`). It then maps database values to CSS variables (e.g., `--color-primary`, `--color-secondary`) and applies them to the `:root` element.

### Active Theme Application
The following example demonstrates how the provider listens for theme updates and applies them to the DOM.

```typescript
// apps/client/src/providers/theme-provider.tsx (Conceptual logic)

export function applyStoreTheme(config: Record<string, string>) {
  const root = document.documentElement;
  // Apply database values to CSS variables
  root.style.setProperty('--color-primary', config.primaryColor);
  root.style.setProperty('--color-secondary', config.secondaryColor);
  root.style.setProperty('--radius-ui', `${config.borderRadius}px`);
  
  // Set the data-theme attribute for scoped CSS
  root.setAttribute("data-theme", config.slug);
}
```

### Supported CSS Variable List
| Variable | Purpose | HeroUI Override |
| :--- | :--- | :--- |
| `--color-primary` | Main brand color | `primary` |
| `--color-secondary` | Accent color | `secondary` |
| `--color-background` | Site-wide background | `background` |
| `--radius-ui` | Corner rounding for buttons/inputs | `radius` |

## Adding a New CSS Variable

To extend the theme system with a new design token, follow these three steps:

1.  **Database Schema**: Add the field to the `store_themes` table in the backend SQLite schema.
2.  **Provider Integration**: Update `theme-provider.tsx` to read the new field from the API response and apply it using `root.style.setProperty`.
3.  **Tailwind/Component Usage**: Reference the variable in your CSS or Tailwind config.

```typescript
// Step 3: Tailwind usage in a component
export const CustomButton = () => {
  return (
    <button className="bg-[var(--color-accent)] rounded-[var(--radius-ui)] p-4">
      Click Me
    </button>
  );
}
```

## ThemeSwitch vs. StoreTheme

It is critical to distinguish between **ThemeSwitch** and **StoreTheme**, as they control different layers of the UI.

1.  **ThemeSwitch (Light/Dark Mode)**: This component toggles the HeroUI color mode. It adds the `.dark` or `.light` class to the `<html>` element. It primarily affects semantic colors like `text-foreground` or `bg-content1`.
2.  **StoreTheme (Branding)**: This is the merchant-defined visual identity. It controls specific hex codes for primary actions and layout variables via `StoreThemeProvider`.

```typescript
// Combining both concepts
import { ThemeSwitcher } from "@/components/ui/theme-switcher"; // Light/Dark
import { useStoreTheme } from "@/providers/theme-provider"; // Branding

export const BrandControls = () => {
  const { theme, setTheme } = useStoreTheme();
  
  return (
    <div className="flex gap-4">
      <ThemeSwitcher /> {/* Standard Light/Dark Toggle */}
      <button onClick={() => setTheme('luxury')}>
        Switch to Luxury Branding
      </button>
    </div>
  );
}
```

## CMS Content Architecture

The CMS data layer is defined in `apps/client/src/config/cms-content.ts`. While it contains type definitions, the actual content is dynamic and fetched from the backend.

### siteConfig() and Data Fetching
The `siteConfig()` utility returns structured content like hero banners, featured categories, and promotional text. At runtime, the application calls `GET /v1/cms/content`. This ensures that changes made in the Admin Dashboard are reflected instantly without a site rebuild.

### cms-content.ts Structure
The file defines the shape of the content expected by the frontend:

```typescript
export type CmsSection = {
  heading: string;
  body: string;
  cta_text?: string;
  cta_link?: string;
};

export type CmsPageContent = {
  title: string;
  lead: string;
  sections: CmsSection[];
};

// Content is usually organized by Handle -> Locale
export type CmsDataMap = Record<string, Record<string, CmsPageContent>>;
```

## Adding a New CMS Content Section

To add a new dynamic section (e.g., a "Promotion Banner") to the storefront, follow these four steps:

1.  **Type Definition**: Add the field to the `CmsPageContent` or `CmsSection` type in `cms-content.ts`.
2.  **Admin Editor**: Create an input field in the `apps/admin` CMS management page to allow merchants to edit the text/links.
3.  **API Update**: Ensure the Admin page calls `PUT /v1/cms/content` to persist the new data to the SQLite database.
4.  **Component Rendering**: Fetch the field in your layout or page component and render it.

```typescript
// Step 4: Rendering the new CMS field in a component
import { useTranslation } from "react-i18next";
import { getCmsPage } from "@/config/cms-content";

export const PromoBanner = () => {
  const { i18n } = useTranslation();
  // Fetch 'home-promo' handle for the current language
  const content = getCmsPage("home-promo", i18n.language);

  if (!content) return null;

  return (
    <div className="bg-primary text-white p-2 text-center">
      <p>{content.lead}</p>
    </div>
  );
}
```

## HeroUI Color Override Mechanism

Fufuni overrides HeroUI's default palette to allow merchant customization. HeroUI v3 uses CSS variables for its color system (e.g., `--heroui-primary`). 

When `StoreThemeProvider` sets `--color-primary`, we map the HeroUI semantic variables to our custom store variables in the global CSS file. This ensures that all HeroUI components (`Button`, `Navbar`, `Tabs`) automatically adopt the merchant's brand colors.

```css
/* apps/client/src/styles/globals.css */
@layer base {
  :root {
    /* Map HeroUI primary to our dynamic store primary */
    --heroui-primary: var(--color-primary);
    --heroui-primary-50: var(--color-primary-light);
    
    /* Map Radius */
    --heroui-radius-medium: var(--radius-ui);
  }
}
```

By using this mapping, a developer can simply use the standard HeroUI components:
```typescript
import { Button } from "@heroui/react";

// This button will automatically use the merchant's 
// defined primary color from the database.
export const StandardButton = () => (
  <Button color="primary">
    Brand Action
  </Button>
);
```
