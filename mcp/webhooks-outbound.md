## Outbound Webhooks Reference
Outbound webhooks in Fufuni enable merchants to receive notifications about events occurring within the platform. This reference guide explains how webhook payloads are secured, the retry mechanism, and how developers can register new webhook events and view logs in the Admin UI.

### Securing Webhook Payloads
Webhook payloads are secured using the following headers:

* `X-Fufuni-Signature`: A cryptographically secure signature generated using HMAC-SHA256. This signature is calculated over the JSON payload and a secret key unique to each webhook.
* `X-Fufuni-Timestamp`: A timestamp representing the time at which the webhook was triggered.
* `X-Fufuni-Delivery-Id`: A unique identifier for the webhook delivery.

The `X-Fufuni-Signature` header allows the receiving server to verify the authenticity of the webhook payload. This is done by recalculating the signature using the same secret key and comparing it with the provided signature.

### Retry Mechanism
Webhook deliveries are tracked in the `webhook_deliveries` table, which stores information about each attempt, including:

* HTTP status code
* Timestamp
* Payload

If a webhook delivery fails (e.g., due to a network error or a 4xx/5xx response), Fufuni will retry the delivery using a backoff strategy. Retries are managed by a Cloudflare cron job that runs periodically to check for failed deliveries.

### Registering New Webhook Events
To register a new webhook event, developers can use the Admin UI. The following events are currently supported:

* `order.created`
* `order.updated`
* `order.shipped`
* `order.refunded`
* `inventory.low`
* `order.*` (wildcard for all order events)
* `*` (wildcard for all events)

When creating a new webhook, developers can select the events they want to subscribe to.

### Viewing Logs in the Admin UI
The Admin UI provides a detailed view of webhook deliveries, including:

* Delivery status (success, failed, pending)
* Event type
* HTTP status code
* Response body
* Attempts

Developers can also manually retry failed deliveries and rotate webhook secrets from within the Admin UI.

### Verifying the Webhook Signature
```typescript
import crypto from 'crypto';

const verifySignature = (payload: string, signature: string, secret: string) => {
  const encoder = new TextEncoder();
  const key = encoder.encode(secret);
  const hmac = crypto.createHmac('sha256', key);
  hmac.update(encoder.encode(payload));
  const expectedSignature = hmac.digest('hex');
  return crypto.timingSafeEqual(Buffer.from(signature), Buffer.from(expectedSignature));
};

// Example usage
const payload = '{"id":"whdel_1234567890abcdef","type":"order.created","created_at":"2022-02-01T12:00:00Z","data":{"order_id":"ord_1234567890abcdef","customer_id":"cust_1234567890abcdef","total":100.00}}';
const signature = 'whsec_1234567890abcdef';
const secret = 'your_webhook_secret';

if (verifySignature(payload, signature, secret)) {
  console.log('Signature verified');
} else {
  console.log('Signature invalid');
}
```
