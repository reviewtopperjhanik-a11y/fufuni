## Outbound Webhooks Reference
Outbound webhooks are a crucial component of the Fufuni e-commerce framework, enabling real-time notifications to external services about specific events within the system. This reference guide covers the security, retry mechanisms, and registration process for outbound webhooks.

### Webhook Payload Security
Fufuni secures webhook payloads using a cryptographic signature and timestamp to prevent tampering and ensure authenticity. Each outbound event triggers a fetch request with the following headers:
- `X-Fufuni-Signature`: A hexadecimal HMAC-SHA256 signature of the payload, using the webhook's secret key.
- `X-Fufuni-Timestamp`: A Unix timestamp (in seconds) of when the request was sent.
- `X-Fufuni-Delivery-Id`: A unique UUID for the delivery attempt.
- `User-Agent`: Set to `Fufuni-Webhook/1.0` for identification purposes.

### Retry Mechanism
In case of failures, Fufuni employs an exponential backoff retry mechanism for outbound webhooks. The specifics are as follows:
- Maximum attempts (`MAX_ATTEMPTS`): 3
- Backoff interval: `2^attempt × 1000` milliseconds (e.g., 2 seconds, 4 seconds, 8 seconds)
- Retries are triggered on network errors, 5xx status codes, and 429 status codes. Other 4xx status codes do not trigger retries.

The `webhook_deliveries` table tracks each delivery attempt, with columns for:
- `id`: Unique delivery ID
- `webhook_id`: The ID of the webhook configuration
- `event_type`: The type of event that triggered the webhook
- `payload`: The JSON payload sent with the request
- `status`: The current status of the delivery (pending, success, or failed)
- `attempts`: The number of attempts made so far
- `response_code`: The HTTP status code from the last attempt
- `response_body`: The response body from the last attempt (up to 1000 characters)
- `created_at`: The timestamp when the delivery was first attempted
- `last_attempt_at`: The timestamp of the most recent attempt

### Registering New Webhook Events and Viewing Logs
Developers can register new webhook events and view delivery logs through the Admin UI (`/admin/webhooks`). The available built-in event types include:
- `order.created`
- `order.updated`
- `order.shipped`
- `order.refunded`
- `inventory.low` (triggered when available stock falls to or below the `LOW_INVENTORY_THRESHOLD` of 5)

To secure webhooks, use the `generateWebhookSecret()` function to produce a `whsec_` prefixed 64-character lowercase hexadecimal secret. Store this secret server-side and share it with the third-party service to verify the `X-Fufuni-Signature` header.

Example usage of `generateWebhookSecret()` in TypeScript:
```typescript
import { generateWebhookSecret } from '../lib/webhooks';

const secret = generateWebhookSecret();
console.log(secret); // Output: whsec_<64-character_hex_string>
```

### Example of Signing a Webhook Payload
To sign a webhook payload, use the `signPayload()` function from `../lib/webhooks`. Here's an example:
```typescript
import { signPayload } from '../lib/webhooks';

const payload = { id: 'event-id', type: 'order.created', data: { order: 'example-order' } };
const secret = 'whsec_your_secret_key';

signPayload(JSON.stringify(payload), secret).then((signature) => {
  console.log(signature); // Output: hexadecimal HMAC-SHA256 signature
});
```
