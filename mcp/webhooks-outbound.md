## Outbound Webhooks Reference

### Introduction

Outbound webhooks are a crucial part of the Fufuni e-commerce framework, allowing merchants to receive real-time notifications about events occurring within their store. This reference guide provides an overview of how webhooks are secured, the retry mechanism, and how developers can register new webhook events and view logs in the Admin UI.

### Webhook Payload Security

To ensure the authenticity and integrity of webhook payloads, Fufuni employs several security measures:

* **X-Fufuni-Signature**: Each webhook payload is signed with an HMAC-SHA256 hex digest of the payload, using a secret key generated by `generateWebhookSecret()`. The signature is included in the `X-Fufuni-Signature` header.
* **X-Fufuni-Timestamp**: A Unix timestamp (in seconds) is included in the `X-Fufuni-Timestamp` header to prevent replay attacks.
* **X-Fufuni-Delivery-Id**: A unique delivery ID is included in the `X-Fufuni-Delivery-Id` header to identify the specific delivery attempt.
* **User-Agent**: The `User-Agent` header is set to `Merchant-Webhook/1.0` to identify the webhook client.

### Retry Mechanism

To ensure reliable delivery of webhooks, Fufuni employs a retry mechanism using Cloudflare cron and tracking of webhook deliveries in the `webhook_deliveries` table. Here's how it works:

* **MAX_ATTEMPTS**: Each webhook delivery is attempted up to 3 times, with exponential backoff (2^attempt × 1000 ms).
* **Retry conditions**: Retries occur on network errors, 5xx, and 429 status codes. No retries occur for other 4xx status codes.
* **webhook_deliveries table**: The `webhook_deliveries` table tracks each delivery attempt, including the webhook ID, event type, payload, status, attempts, response code, response body, created at, and last attempt at.

### Registering New Webhook Events and Viewing Logs

Developers can register new webhook events and view logs in the Admin UI as follows:

* **Built-in event types**: Fufuni supports the following built-in event types: `order.created`, `order.updated`, `order.shipped`, `order.refunded`, and `inventory.low`. The `inventory.low` event is triggered when the available stock falls below the `LOW_INVENTORY_THRESHOLD` (5).
* **Admin UI**: The Admin UI (/admin/webhooks) displays a list of webhooks, including their deliveries, statuses, and allows manual retries and secret rotation.
* **Registering new events**: Developers can register new webhook events by creating a new webhook in the Admin UI and specifying the desired event types.

### Example Code

Here's an example of how to create a new webhook using the `createWebhook` function:
```typescript
const createWebhook = async (url: string, events: string[]) => {
  try {
    const response = await fetch(`${apiBase}/v1/webhooks`, {
      method: 'POST',
      headers: {
        'Content-Type': 'application/json',
      },
      body: JSON.stringify({ url, events }),
    });
    const webhook = await response.json();
    console.log(`Webhook created: ${webhook.id}`);
  } catch (error) {
    console.error(`Error creating webhook: ${error.message}`);
  }
};
```
In this example, we create a new webhook with the specified `url` and `events` using the `createWebhook` function. The `createWebhook` function returns a promise that resolves with the created webhook object.
