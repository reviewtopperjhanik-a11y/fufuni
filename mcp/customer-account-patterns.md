## Customer Authentication Middleware

The Fufuni framework uses a specialized middleware for customer-facing routes located under the `/v1/me/*` prefix. Unlike admin routes which might use API keys or session cookies, customer routes rely exclusively on **Auth0 JWTs (JSON Web Tokens)**.

The `customerAuthMiddleware` performs three critical tasks:
1.  **JWT Verification**: Validates the token against the configured Auth0 domain and audience using the `jose` library.
2.  **Identity Extraction**: Extracts the `sub` (subject identifier), `email`, and custom metadata.
3.  **Context Injection**: Populates the Hono context (`c.set('auth', ...)`), making the customer's identity available to all downstream handlers.

```typescript
import { createMiddleware } from 'hono/factory';
import { ApiError, type HonoEnv } from '../types';
import { verifyAuth0Jwt } from '../lib/auth0';

/**
 * Middleware to protect customer-specific routes.
 * Ensures the request has a valid Auth0 Bearer token.
 */
export const customerAuthMiddleware = createMiddleware<HonoEnv>(
  async (c, next) => {
    const authHeader = c.req.header('Authorization');

    if (!authHeader?.startsWith('Bearer ')) {
      throw ApiError.unauthorized('Missing or invalid Authorization header');
    }

    const token = authHeader.slice(7);
    const domain = c.env.AUTH0_DOMAIN;
    const audience = c.env.AUTH0_AUDIENCE;

    try {
      const payload = await verifyAuth0Jwt(token, domain, audience);
      
      const sub = payload.sub as string;
      const email = payload.email as string | undefined;

      if (!sub) {
        throw ApiError.unauthorized('Invalid token: missing sub claim');
      }

      // Store in context for use in route handlers
      c.set('auth', {
        role: 'customer',
        sub: sub,
        email: email,
        permissions: (payload.permissions as string[]) || []
      });

      await next();
    } catch (err) {
      console.error('JWT Verification Error:', err);
      throw ApiError.unauthorized('Invalid Auth0 JWT');
    }
  }
);
```

### Identity Resolution and Auto-Creation

Fufuni follows a "Lazy Creation" pattern. A customer record in the `customers` table is not necessarily created when they sign up on Auth0, but rather on their first authenticated API request. 

The `resolveCustomer` helper (often called within `/v1/me` handlers) performs a lookup. If the `auth_provider_id` (the Auth0 `sub`) isn't found, it attempts to link via email or creates a new row entirely.

```typescript
/**
 * Resolves or creates a customer record based on the JWT payload.
 */
async function resolveCustomer(db: any, jwtSub: string, email?: string) {
    // 1. Try lookup by Auth0 sub
    let customer = await db.query(
        `SELECT * FROM customers WHERE auth_provider_id = ? AND auth_provider = 'auth0' LIMIT 1`,
        [jwtSub]
    );

    if (customer.length > 0) return customer[0];

    // 2. Try lookup by email (for legacy account linking)
    if (email) {
        const emailResult = await db.query(
            `SELECT * FROM customers WHERE email = ? LIMIT 1`,
            [email.toLowerCase()]
        );
        if (emailResult.length > 0) {
            const existing = emailResult[0];
            await db.run(
                `UPDATE customers SET auth_provider = 'auth0', auth_provider_id = ?, updated_at = ? WHERE id = ?`,
                [jwtSub, new Date().toISOString(), existing.id]
            );
            return { ...existing, auth_provider_id: jwtSub };
        }
    }

    // 3. Create new customer record
    const newId = crypto.randomUUID();
    const now = new Date().toISOString();
    await db.run(
        `INSERT INTO customers (id, email, auth_provider, auth_provider_id, created_at, updated_at)
         VALUES (?, ?, 'auth0', ?, ?, ?)`,
        [newId, email?.toLowerCase() || '', jwtSub, now, now]
    );

    return { id: newId, email, auth_provider_id: jwtSub };
}
```

## Address Book Patterns

Addresses are scoped to the `customer_id`. The API ensures that a customer can only read, update, or delete addresses they own.

### Address Schema
Fufuni enforces ISO 3166-1 alpha-2 for country codes and standardized labels.

| Field | Type | Description |
| :--- | :--- | :--- |
| `id` | UUID | Primary Key |
| `label` | String | 'Home', 'Work', or 'Other' |
| `first_name` | String | Recipient first name |
| `last_name` | String | Recipient last name |
| `line1` | String | Street address |
| `line2` | String | Apartment, suite, etc. (Optional) |
| `city` | String | City |
| `postal_code` | String | ZIP / Postal Code |
| `country_code`| String | **ISO 3166-1 alpha-2** (e.g., "US", "FR") |
| `is_default` | Boolean| If true, this is the default shipping address |

### Address CRUD Implementation Example

```typescript
const getAddressesRoute = createRoute({
  method: 'get',
  path: '/v1/me/addresses',
  responses: {
    200: { 
      description: 'List of customer addresses',
      content: { 'application/json': { schema: z.array(AddressSchema) } } 
    }
  }
});

adminApp.openapi(getAddressesRoute, async (c) => {
  const db = getDb(c.env);
  const auth = c.get('auth');
  const customer = await resolveCustomer(db, auth.sub);

  const addresses = await db.query(
    `SELECT * FROM customer_addresses WHERE customer_id = ? ORDER BY is_default DESC, created_at DESC`,
    [customer.id]
  );

  return c.json(addresses);
});
```

## Saved Cart and Preferences

Fufuni allows customers to persist their cart across devices.

## Adding a New Customer Route

To extend the `/v1/me` namespace, follow these steps:

1.  **Define the Schema**: Create a Zod schema for input and output.
2.  **Create the Route**: Use `createRoute` from `@hono/zod-openapi`.
3.  **Register and Protect**: Add the route to the router using `adminApp.openapi()`. The `customerAuthMiddleware` is already applied via `adminApp.use('*', ...)`.
4.  **Resolve Customer**: Always call `resolveCustomer` inside the handler to get the internal `customers.id`.

### Example: Adding a "Wishlist" Route

```typescript
// 1. Define schema
const WishlistSchema = z.object({
  product_ids: z.array(z.string().uuid())
});

// 2. Create route definition
const putWishlistRoute = createRoute({
  method: 'put',
  path: '/v1/me/wishlist',
  request: {
    body: { content: { 'application/json': { schema: WishlistSchema } } }
  },
  responses: {
    200: { description: 'Wishlist updated', content: { 'application/json': { schema: z.object({ success: z.boolean() }) } } }
  }
});

// 3. Implement handler
adminApp.openapi(putWishlistRoute, async (c) => {
  const db = getDb(c.env);
  const auth = c.get('auth');
  const { product_ids } = c.req.valid('json');
  
  // 4. Resolve internal ID
  const customer = await resolveCustomer(db, auth.sub);
  
  await db.run(
    `UPDATE customers SET wishlist = ?, updated_at = ? WHERE id = ?`,
    [JSON.stringify(product_ids), new Date().toISOString(), customer.id]
  );

  return c.json({ success: true });
});
```
