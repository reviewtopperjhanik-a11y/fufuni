## Customer Account Portal Patterns
The customer account portal is a crucial part of the Fufuni e-commerce framework, providing users with a centralized location to manage their account information, orders, addresses, and preferences. This reference outlines the key patterns and endpoints used in the customer account portal.

### Customer Authentication Middleware
The `customerAuthMiddleware` is used to authenticate customers via Auth0 JWTs. It validates the following:

* The presence of an `Authorization` header with a `Bearer` token
* The token is a valid Auth0 JWT with the correct domain and audience
* The token contains the required claims, including `sub` (Auth0 user identifier)

The `customerAuthMiddleware` differs from the `authMiddleware` in that it:

* Only accepts Auth0 JWTs
* Sets the role to "customer"
* Does not require the `admin:store` permission

### Auto-Customer Creation on First Login
When a customer logs in for the first time, the backend auto-creates a customer row from the JWT `sub` claim. If a customer already exists with the same email, the Auth0 `sub` is linked to that row (no duplicate). If Auth0 does not provide an email, a placeholder email is generated: `<sub_hash>@auth0.local`. This email should never be displayed to the user.

```typescript
async function resolveCustomer(db: any, jwtSub: string, email?: string, name?: string) {
  // Try to find customer by Auth0 sub first (fastest lookup)
  let customer = await db.query(
    `SELECT * FROM customers WHERE auth_provider_id = ? AND auth_provider = 'auth0' LIMIT 1`,
    [jwtSub]
  );

  // Fallback: try to find by email (handles accounts created before Auth0 sub linking)
  if (email) {
    const emailResult = await db.query(
      `SELECT * FROM customers WHERE email = ? LIMIT 1`,
      [email.toLowerCase()]
    );

    if (emailResult.length > 0) {
      const existingCustomer = emailResult[0];
      // Link the existing customer to their Auth0 sub
      await db.run(
        `UPDATE customers SET auth_provider = 'auth0', auth_provider_id = ?, updated_at = ? WHERE id = ?`,
        [jwtSub, now(), existingCustomer.id]
      );
      existingCustomer.auth_provider = 'auth0';
    }
  }

  // Create a new customer if none exist
  if (!customer.length) {
    const newCustomer = {
      id: uuid(),
      auth_provider: 'auth0',
      auth_provider_id: jwtSub,
      email: email || `<${jwtSub}>@auth0.local`,
      created_at: now(),
      updated_at: now(),
    };

    await db.run(
      `INSERT INTO customers (id, auth_provider, auth_provider_id, email, created_at, updated_at) VALUES (?, ?, ?, ?, ?, ?)`,
      [newCustomer.id, newCustomer.auth_provider, newCustomer.auth_provider_id, newCustomer.email, newCustomer.created_at, newCustomer.updated_at]
    );

    customer = [newCustomer];
  }

  return customer[0];
}
```

### /v1/me/profile
The `/v1/me/profile` endpoint allows customers to read and update their profile information. The readable fields include:

* `id`
* `email`
* `name`

The updatable fields include:

* `email`
* `name`

```typescript
adminApp.get('/v1/me/profile', {
  validation: z.object({
    // No input validation needed
  }),
  handler: async (c) => {
    const customer = await resolveCustomer(getDb(c), c.get('auth').sub, c.get('auth').email);
    return c.json({
      id: customer.id,
      email: customer.email,
      name: customer.name,
    });
  },
});

adminApp.patch('/v1/me/profile', {
  validation: z.object({
    email: z.string().optional(),
    name: z.string().optional(),
  }),
  handler: async (c) => {
    const customer = await resolveCustomer(getDb(c), c.get('auth').sub, c.get('auth').email);
    const updates = c.req.body();

    if (updates.email) {
      customer.email = updates.email;
    }

    if (updates.name) {
      customer.name = updates.name;
    }

    await getDb(c).run(
      `UPDATE customers SET email = ?, name = ?, updated_at = ? WHERE id = ?`,
      [customer.email, customer.name, now(), customer.id]
    );

    return c.json({
      message: 'Profile updated successfully',
    });
  },
});
```

### /v1/me/orders
The `/v1/me/orders` endpoint allows customers to view their order history. The endpoint returns a list of orders with the following information:

* `order_number`
* `created_at`
* `total`
* `items` (list of order items with `id`, `name`, `quantity`, and `price`)
* `taxes_json` (JSON object containing tax breakdown)

The `/v1/me/orders/:number` endpoint returns a single order with the same information.

```typescript
adminApp.get('/v1/me/orders', {
  validation: z.object({
    // No input validation needed
  }),
  handler: async (c) => {
    const customer = await resolveCustomer(getDb(c), c.get('auth').sub, c.get('auth').email);
    const orders = await getDb(c).query(
      `SELECT * FROM orders WHERE customer_id = ? ORDER BY created_at DESC`,
      [customer.id]
    );

    return c.json(
      orders.map((order) => ({
        order_number: order.order_number,
        created_at: order.created_at,
        total: order.total,
        items: JSON.parse(order.items),
        taxes_json: JSON.parse(order.taxes_json),
      }))
    );
  },
});

adminApp.get('/v1/me/orders/:number', {
  validation: z.object({
    number: z.string(),
  }),
  handler: async (c) => {
    const customer = await resolveCustomer(getDb(c), c.get('auth').sub, c.get('auth').email);
    const order = await getDb(c).query(
      `SELECT * FROM orders WHERE customer_id = ? AND order_number = ? LIMIT 1`,
      [customer.id, c.req.param('number')]
    );

    if (!order.length) {
      return c.json({ message: 'Order not found' }, 404);
    }

    return c.json({
      order_number: order[0].order_number,
      created_at: order[0].created_at,
      total: order[0].total,
      items: JSON.parse(order[0].items),
      taxes_json: JSON.parse(order[0].taxes_json),
    });
  },
});
```

### /v1/me/addresses
The `/v1/me/addresses` endpoint allows customers to manage their addresses. The endpoint returns a list of addresses with the following information:

* `id`
* `name`
* `address`
* `default` (boolean indicating whether the address is the default)

The `/v1/me/addresses/:id` endpoint allows customers to update or delete an address.

```typescript
    if (updates.name) {
      address[0].name = updates.name;
    }

    if (updates.address) {
      address[0].address = updates.address;
    }

    await getDb(c).run(
      `UPDATE addresses SET name = ?, address = ?, updated_at = ? WHERE id = ?`,
      [address[0].name, address[0].address, now(), address[0].id]
    );

    return c.json({
      message: 'Address updated successfully',
    });
  },

adminApp.delete('/v1/me/addresses/:id', {
  validation: z.object({
    id: z.string(),
  }),
  handler: async (c) => {
    const customer = await resolveCustomer(getDb(c), c.get('auth').sub, c.get('auth').email);
    const address = await getDb(c).query(
      `SELECT * FROM addresses WHERE customer_id = ? AND id = ? LIMIT 1`,
      [customer.id, c.req.param('id')]
    );

    if (!address.length) {
      return c.json({ message: 'Address not found' }, 404);
    }

    await getDb(c).run(
      `DELETE FROM addresses WHERE id = ?`,
      [address[0].id]
    );

    // Set the most recently created remaining address as the new default
    const remainingAddresses = await getDb(c).query(
      `SELECT * FROM addresses WHERE customer_id = ? ORDER BY created_at DESC`,
      [customer.id]
    );

    if (remainingAddresses.length) {
      await getDb(c).run(
        `UPDATE addresses SET default = ? WHERE id = ?`,
        [true, remainingAddresses[0].id]
      );
    }

    return c.json({
      message: 'Address deleted successfully',
    });
  },
});
```

### /v1/me/preferences
The `/v1/me/preferences` endpoint allows customers to manage their preferences. The endpoint returns a list of preferences with the following information:

* `locale`
* `theme`
* `marketing_consent`

The endpoint also allows customers to update their preferences.

```typescript

    // No input validation needed
  }),

      marketing_consent: preferences[0].marketing_consent,

adminApp.patch('/v1/me/preferences', {
  validation: z.object({
    locale: z.string().optional(),
    theme: z.string().optional(),
    marketing_consent: z.boolean().optional(),
  }),
```

### Worked Example: Building a Preferences Page
To build a preferences page, you can create a form that allows customers to update their preferences. The form should include fields for `locale`, `theme`, and `marketing_consent`.

```typescript
import React, { useState, useEffect } from 'react';
import axios from 'axios';

const PreferencesPage = () => {
  const [locale, setLocale] = useState('');
  const [theme, setTheme] = useState('');
  const [marketingConsent, setMarketingConsent] = useState(false);

  useEffect(() => {
    axios.get('/v1/me/preferences')
      .then((response) => {
        setLocale(response.data.locale);
        setTheme(response.data.theme);
        setMarketingConsent(response.data.marketing_consent);
      })
      .catch((error) => {
        console.error(error);
      });
  }, []);

  const handleSubmit = (event) => {
    event.preventDefault();
    axios.patch('/v1/me/preferences', {
      locale,
      theme,
      marketing_consent: marketingConsent,
    })
      .then((response) => {
        console.log(response.data);
      })
      .catch((error) => {
        console.error(error);
      });
  };

  return (
    <form onSubmit={handleSubmit}>
      <label>
        Locale:
        <select value={locale} onChange={(event) => setLocale(event.target.value)}>
          <option value="en">English</option>
          <option value="fr">French</option>
        </select>
      </label>
      <br />
      <label>
        Theme:
        <select value={theme} onChange={(event) => setTheme(event.target.value)}>
          <option value="light">Light</option>
          <option value="dark">Dark</option>
        </select>
      </label>
      <br />
      <label>
        Marketing Consent:
        <input type="checkbox" checked={marketingConsent} onChange={(event) => setMarketingConsent(event.target.checked)} />
      </label>
      <br />
      <button type="submit">Save Changes</button>
    </form>
  );
};

export default PreferencesPage;
```

This example demonstrates how to create a preferences page that allows customers to update their preferences. The page includes a form with fields for `locale`, `theme`, and `marketing_consent`, and uses Axios to send a PATCH request to the `/v1/me/preferences` endpoint to update the customer's preferences.
