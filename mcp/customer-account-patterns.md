## Customer Authentication Middleware

The `customerAuthMiddleware` is the entry point for all customer-scoped operations. Unlike merchant administration which often uses API keys, the customer context relies exclusively on Auth0-issued JSON Web Tokens (JWT). This middleware ensures that the `sub` (Subject) claim from Auth0 is mapped to a local SQLite record in the `customers` table.

The middleware performs the following operations:
1.  **JWT Verification**: Validates the token signature and expiration against the configured `AUTH0_DOMAIN` and `AUTH0_AUDIENCE`.
2.  **Context Injection**: Injects an `auth` object into the Hono context containing the `sub`, `email`, and `role`.
3.  **Customer Resolution**: Downstream handlers use these claims to identify or create the database record.

```typescript
import { createMiddleware } from 'hono/factory';
import { ApiError, type HonoEnv } from '../types';
import { verifyAuth0Jwt } from '../lib/auth0';

/**
 * Validates Auth0 Bearer tokens and sets the 'auth' context.
 */
export const customerAuthMiddleware = createMiddleware<HonoEnv>(
  async (c, next) => {
    const authHeader = c.req.header('Authorization');

    if (!authHeader?.startsWith('Bearer ')) {
      throw ApiError.unauthorized('Missing or invalid Authorization header');
    }

    const token = authHeader.slice(7);
    const domain = c.env.AUTH0_DOMAIN;
    const audience = c.env.AUTH0_AUDIENCE;

    try {
      const payload = await verifyAuth0Jwt(token, domain, audience);
      
      c.set('auth', {
        role: 'customer',
        sub: payload.sub as string,
        email: (payload.email as string) || undefined,
        permissions: Array.isArray(payload.permissions) ? payload.permissions : [],
      });
      
      await next();
    } catch (err) {
      throw ApiError.unauthorized('Invalid Auth0 JWT');
    }
  }
);
```

## Customer Auto-creation Flow

Fufuni follows a "Lazy Creation" pattern. A customer record is not required to exist before their first authenticated request. The `resolveCustomer` logic (often called during the first access to `/v1/me`) ensures that the `auth_provider_id` (Auth0 `sub`) is linked to a customer row.

The resolution priority is:
1.  **Lookup by Sub**: If a customer has the matching `auth_provider_id`, return it.
2.  **Lookup by Email**: If no sub matches but the email from the JWT exists in the DB, link the sub to that record.
3.  **Create New**: If neither matches, insert a new row into the `customers` table.

```typescript
/**
 * Ensures a customer record exists for the given Auth0 identity.
 */
async function getOrCreateCustomer(db: any, sub: string, email?: string, name?: string) {
  // 1. Check by Auth0 ID
  let customer = await db.query(
    `SELECT * FROM customers WHERE auth_provider_id = ? LIMIT 1`,
    [sub]
  );

  if (customer.length > 0) return customer[0];

  // 2. Check by Email to link existing guest accounts
  if (email) {
    const byEmail = await db.query(
      `SELECT * FROM customers WHERE email = ? LIMIT 1`,
      [email.toLowerCase()]
    );
    if (byEmail.length > 0) {
      await db.run(
        `UPDATE customers SET auth_provider_id = ?, auth_provider = 'auth0' WHERE id = ?`,
        [sub, byEmail[0].id]
      );
      return { ...byEmail[0], auth_provider_id: sub };
    }
  }

  // 3. Create new record
  const id = `cust_${crypto.randomUUID()}`;
  await db.run(
    `INSERT INTO customers (id, email, name, auth_provider, auth_provider_id, created_at) 
     VALUES (?, ?, ?, 'auth0', ?, ?)`,
    [id, email?.toLowerCase() || '', name || '', sub, Date.now()]
  );
  
  return { id, email, name };
}
```

## Adding a New Customer Route

To add a new sub-route under `/v1/me/*`, follow these steps:

1.  **Define the Route**: Use `createRoute` from `@hono/zod-openapi`.
2.  **Register in `me.ts`**: Attach the route to the `adminApp` instance.
3.  **Enforce Customer Scope**: Always filter SQL queries by `customer_id` extracted from the auth context.

```typescript
// 1. Define the schema
const WishlistSchema = z.object({
  product_ids: z.array(z.string()),
});

// 2. Define the route
const getWishlistRoute = createRoute({
  method: 'get',
  path: '/v1/me/wishlist',
  responses: {
    200: {
      description: 'Customer wishlist',
      content: { 'application/json': { schema: WishlistSchema } },
    },
  },
});

// 3. Implement the handler
adminApp.openapi(getWishlistRoute, async (c) => {
  const db = getDb(c.env);
  const auth = c.get('auth');
  
  // Resolve the internal ID
  const customer = await getOrCreateCustomer(db, auth.sub);
  
  const items = await db.query(
    `SELECT product_id FROM customer_wishlists WHERE customer_id = ?`,
    [customer.id]
  );
  
  return c.json({ product_ids: items.map(i => i.product_id) });
});
```
