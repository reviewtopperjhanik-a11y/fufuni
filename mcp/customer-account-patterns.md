## The customerAuthMiddleware Logic

The Fufuni framework distinguishes between administrative access (API keys or admin JWTs) and shopper access (Auth0 JWTs). While `authMiddleware` handles store managers and programmatic access via API keys, `customerAuthMiddleware` is dedicated to the `/v1/me/*` routes.

Key characteristics of `customerAuthMiddleware`:
1. **Exclusively JWT**: It rejects API keys (tokens starting with `pk_` or `sk_`).
2. **Permission-less**: It does not require the `admin:store` permission. Any valid Auth0 user for the configured domain/audience is permitted.
3. **Identity Extraction**: It extracts the `sub` (Auth0 ID), `email`, and `user_metadata` from the JWT.
4. **Context Injection**: It sets the Hono context `auth` object with `role: 'customer'`.

```typescript
import { createMiddleware } from 'hono/factory';
import { ApiError, type HonoEnv } from '../types';

export const customerAuthMiddleware = createMiddleware<HonoEnv>(
  async (c, next) => {
    const authHeader = c.req.header('Authorization');
    if (!authHeader?.startsWith('Bearer ')) {
      throw ApiError.unauthorized('Missing Authorization header');
    }

    const token = authHeader.slice(7);
    // Strict JWT check
    if (token.split('.').length !== 3) {
      throw ApiError.unauthorized('Invalid customer token format');
    }

    const { verifyAuth0Jwt } = await import('../lib/auth0');
    try {
      const payload = await verifyAuth0Jwt(token, c.env.AUTH0_DOMAIN, c.env.AUTH0_AUDIENCE);
      
      // Store identity in context
      c.set('auth', {
        role: 'customer',
        sub: payload.sub!,
        email: (payload.email as string) || undefined,
        permissions: [],
        user_metadata: (payload.user_metadata as Record<string, any>) || {}
      });
      
      await next();
    } catch (err) {
      throw ApiError.unauthorized('Invalid Auth0 JWT');
    }
  }
);
```

## Auto-Customer Creation and Linking

Fufuni follows a "just-in-time" provisioning pattern. When a user logs into the storefront for the first time, the backend automatically reconciles their Auth0 identity with the SQLite `customers` table.

### The Resolution Strategy
1. **Lookup by Sub**: Check if a customer exists with `auth_provider_id = sub`.
2. **Lookup by Email**: If no sub match, check for a matching `email`. If found, "link" the record by updating its `auth_provider_id`.
3. **Create New**: If neither exists, create a new row.
4. **Placeholder Emails**: If Auth0 provides no email (e.g., some social logins), Fufuni generates `<hash>@auth0.local`. **Note**: Frontend components must detect this suffix and treat the email as "unset".

```typescript
async function resolveCustomer(db: any, jwtSub: string, email?: string) {
  // 1. Try Provider ID
  let customer = await db.query(
    `SELECT * FROM customers WHERE auth_provider_id = ? LIMIT 1`, [jwtSub]
  );

  if (customer.length > 0) return customer[0];

  // 2. Try Email Linking
  if (email) {
    const byEmail = await db.query(
      `SELECT * FROM customers WHERE email = ? LIMIT 1`, [email.toLowerCase()]
    );
    if (byEmail.length > 0) {
      await db.run(
        `UPDATE customers SET auth_provider = 'auth0', auth_provider_id = ? WHERE id = ?`,
        [jwtSub, byEmail[0].id]
      );
      return { ...byEmail[0], auth_provider_id: jwtSub };
    }
  }

  // 3. Create (Handling placeholders)
  const finalEmail = email || `${jwtSub.replace('|', '_')}@auth0.local`;
  const newId = crypto.randomUUID();
  await db.run(
    `INSERT INTO customers (id, email, auth_provider, auth_provider_id, created_at) VALUES (?, ?, ?, ?, ?)`,
    [newId, finalEmail.toLowerCase(), 'auth0', jwtSub, Date.now()]
  );
  
  return { id: newId, email: finalEmail };
}
```

## Order History and Details

In the customer portal, orders are identified by their `order_number` (e.g., `ORD-9921`) rather than their internal UUID `id`. This prevents ID enumeration and provides a more user-friendly reference.

### Tax Breakdown
Taxes are not calculated on the fly for history; they are read from `taxes_json` stored in the `orders` table. This ensures that the tax rates applied at the time of purchase remain visible even if the store's tax configuration changes later.

```typescript
// GET /v1/me/orders/:number
const getOrderRoute = createRoute({
  method: 'get',
  path: '/{number}',
  request: {
    params: z.object({ number: z.string() })
  },
  responses: {
    200: {
      content: { 'application/json': { schema: OrderWithItemsSchema } }
    }
  }
});

adminApp.openapi(getOrderRoute, async (c) => {
  const { number } = c.req.valid('param');
  const customer = await resolveCustomer(getDb(c), c.get('auth').sub);
  
  const order = await getDb(c).query(
    `SELECT * FROM orders WHERE order_number = ? AND customer_id = ?`,
    [number, customer.id]
  );
  
  if (!order[0]) throw ApiError.notFound('Order not found');

  // Parse stored taxes
  const taxes = JSON.parse(order[0].taxes_json || '[]');
  const items = await getDb(c).query(
    `SELECT * FROM order_items WHERE order_id = ?`, [order[0].id]
  );

  return c.json({ ...order[0], items, taxes }, 200);
});
```

## Address Management and Defaulting

Fufuni manages multiple shipping/billing addresses for customers. A critical piece of logic is the **Auto-Default Reassignment**: if a customer deletes the address marked as `is_default`, the system must automatically promote another address to maintain a valid checkout flow.

```typescript
// Logic within DELETE /v1/me/addresses/:id
async function deleteAddress(db: any, customerId: string, addressId: string) {
  const addr = await db.query(
    `SELECT is_default FROM customer_addresses WHERE id = ? AND customer_id = ?`,
    [addressId, customerId]
  );

  if (addr.length === 0) return;

  await db.run(`DELETE FROM customer_addresses WHERE id = ?`, [addressId]);

  if (addr[0].is_default) {
    // Promote the most recently created remaining address
    await db.run(`
      UPDATE customer_addresses 
      SET is_default = 1 
      WHERE id = (
        SELECT id FROM customer_addresses 
        WHERE customer_id = ? 
        ORDER BY created_at DESC 
        LIMIT 1
      )
    `, [customerId]);
  }
}
```

## Synchronizing Preferences

Fufuni implements a dual-sync strategy for preferences like `locale`, `theme`, and `marketing_consent`. These values are stored in the SQLite `customers` table for backend processing (e.g., sending emails in the correct language) and pushed to Auth0 `user_metadata` for frontend availability upon login.

| Field | SQLite Column | Auth0 user_metadata | Purpose |
| :--- | :--- | :--- | :--- |
| **locale** | `locale` | `locale` | i18n for emails and UI |
| **theme** | `theme` | `theme` | UI Appearance (light/dark) |
| **marketing** | `marketing_consent` | `marketing_consent` | Newsletter eligibility |

```typescript
// PATCH /v1/me/preferences
const updatePrefs = async (c: any) => {
  const { locale, theme, marketing_consent } = await c.req.json();
  const auth = c.get('auth');
  const db = getDb(c);

  // 1. Update SQLite
  await db.run(
    `UPDATE customers SET locale = ?, theme = ?, marketing_consent = ?, updated_at = ? WHERE auth_provider_id = ?`,
    [locale, theme, marketing_consent ? 1 : 0, Date.now(), auth.sub]
  );

  // 2. Update Auth0 (via Management API)
  const { updateUserMetadata } = await import('../lib/auth0');
  await updateUserMetadata(auth.sub, {
    locale,
    theme,
    marketing_consent
  }, c.env.AUTH0_DOMAIN, c.env.AUTH0_MANAGEMENT_TOKEN);

  return c.json({ success: true });
};
```

## Worked Example: Preferences Page

The following React 19 component demonstrates how to build a preference management interface that interacts with the dual-sync backend. It uses HeroUI components for a consistent Fufuni look and feel.

```typescript
import React, { useState } from 'react';
import { Select, SelectItem, Switch, Button, Card, CardBody } from "@heroui/react";
import { useAuth0 } from "@auth0/auth0-react";

export const PreferencesPage = () => {
  const { user, getAccessTokenSilently } = useAuth0();
  // Initialize from Auth0 user_metadata synced by the backend
  const [locale, setLocale] = useState(user?.['user_metadata']?.locale || 'en-US');
  const [theme, setTheme] = useState(user?.['user_metadata']?.theme || 'light');
  const [marketing, setMarketing] = useState(!!user?.['user_metadata']?.marketing_consent);
  const [loading, setLoading] = useState(false);

  const savePreferences = async () => {
    setLoading(true);
    try {
      const token = await getAccessTokenSilently();
      const response = await fetch('/api/v1/me/preferences', {
        method: 'PATCH',
        headers: { 
          'Authorization': `Bearer ${token}`,
          'Content-Type': 'application/json'
        },
        body: JSON.stringify({ locale, theme, marketing_consent: marketing })
      });
      
      if (response.ok) alert('Preferences updated!');
    } finally {
      setLoading(false);
    }
  };

  return (
    <Card className="max-w-md mx-auto mt-10">
      <CardBody className="gap-6">
        <h2 className="text-xl font-bold">Account Preferences</h2>
        
        <Select 
          label="Language" 
          selectedKeys={[locale]} 
          onSelectionChange={(keys) => setLocale(Array.from(keys)[0] as string)}
        >
          <SelectItem key="en-US">English</SelectItem>
          <SelectItem key="fr-FR">Français</SelectItem>
        </Select>

        <Select 
          label="Interface Theme" 
          selectedKeys={[theme]} 
          onSelectionChange={(keys) => setTheme(Array.from(keys)[0] as string)}
        >
          <SelectItem key="light">Light Mode</SelectItem>
          <SelectItem key="dark">Dark Mode</SelectItem>
        </Select>

        <div className="flex items-center justify-between">
          <span>Receive marketing emails</span>
          <Switch isSelected={marketing} onValueChange={setMarketing} color="primary" />
        </div>

        <Button 
          color="primary" 
          isLoading={loading} 
          onPress={savePreferences}
        >
          Save Changes
        </Button>
      </CardBody>
    </Card>
  );
};
```

### Summary of Best Practices
- **Hide Placeholders**: When rendering the profile, always check if `email.endsWith('@auth0.local')`. If it does, show an empty input field or a "Set your email" prompt.
- **Atomic Deletions**: When deleting addresses, always wrap the "delete" and "promote new default" in a transaction or ensure they execute sequentially to prevent a customer from having zero default addresses while active ones exist.
- **JWT Freshness**: Encourage the frontend to call `getAccessTokenSilently({ ignoreCache: true })` after updating preferences to ensure the local JWT claims reflect the new `user_metadata`.
