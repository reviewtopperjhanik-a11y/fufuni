## customerAuthMiddleware and Identity

Fufuni separates administrative access from customer access via distinct middleware. While `authMiddleware` handles API keys and admin-level JWTs (requiring `admin:store` permissions), the `customerAuthMiddleware` is designed specifically for the `/v1/me/*` routes. It validates Auth0 JWTs, sets the context role to `customer`, and extracts metadata from the `extra_user_info` claim populated by Auth0 Actions.

### Key differences
- **Target**: Only accepts 3-part JWTs from the configured Auth0 domain.
- **Permissions**: Does not require `admin:store`. It is scoped to the individual customer.
- **Payload**: Automatically extracts `user_metadata` from the JWT to sync with the local database.

```typescript
// apps/merchant/src/middleware/customer-auth.ts
import { createMiddleware } from 'hono/factory';
import { ApiError, type HonoEnv } from '../types';

export const customerAuthMiddleware = createMiddleware<HonoEnv>(
  async (c, next) => {
    const authHeader = c.req.header('Authorization');
    if (!authHeader?.startsWith('Bearer ')) {
      throw ApiError.unauthorized('Missing Authorization header');
    }

    const token = authHeader.slice(7);
    // Block API keys (pk_ or sk_) from customer routes
    if (token.startsWith('pk_') || token.startsWith('sk_')) {
      throw ApiError.unauthorized('API keys not permitted on customer routes');
    }

    const { verifyAuth0Jwt } = await import('../lib/auth0');
    const payload = await verifyAuth0Jwt(token, c.env.AUTH0_DOMAIN, c.env.AUTH0_AUDIENCE);

    c.set('auth', {
      role: 'customer',
      sub: payload.sub as string,
      email: (payload.email as string) || (payload.extra_user_info as any)?.email,
      permissions: [],
      userMetadata: payload.user_metadata || (payload.extra_user_info as any)?.user_metadata || {}
    });

    await next();
  }
);
```

## Auto-customer Creation and Linking

Fufuni employs a "Just-In-Time" (JIT) provisioning strategy for customers. When a user logs in via Auth0 for the first time, the backend resolves their identity using the `sub` claim. If no match exists, it attempts to link via email to prevent duplicate accounts for users who might have previously checked out as guests.

### Identity Resolution Logic
1.  **Check `auth_provider_id`**: If the `sub` matches, use that record.
2.  **Check `email`**: If the email matches but has no `auth_provider_id`, link the Auth0 `sub` to the existing record.
3.  **Create New**: If neither matches, create a new row.
4.  **Placeholder Emails**: If the social provider provides no email, a hash-based placeholder is generated: `<sub_hash>@auth0.local`.

```typescript
async function resolveCustomer(db: any, jwtSub: string, email?: string) {
    // 1. Primary lookup via Auth0 ID
    let customer = await db.query(
        `SELECT * FROM customers WHERE auth_provider_id = ? AND auth_provider = 'auth0' LIMIT 1`,
        [jwtSub]
    );

    if (customer.length > 0) return customer[0];

    // 2. Fallback to email linking
    if (email && !email.endsWith('@auth0.local')) {
        const existing = await db.query(`SELECT * FROM customers WHERE email = ? LIMIT 1`, [email]);
        if (existing.length > 0) {
            await db.run(
                `UPDATE customers SET auth_provider = 'auth0', auth_provider_id = ? WHERE id = ?`,
                [jwtSub, existing[0].id]
            );
            return { ...existing[0], auth_provider_id: jwtSub };
        }
    }

    // 3. Create new record
    const id = uuid();
    const finalEmail = email || `${jwtSub.replace('|', '_')}@auth0.local`;
    await db.run(
        `INSERT INTO customers (id, email, auth_provider, auth_provider_id, created_at) VALUES (?, ?, 'auth0', ?, ?)`,
        [id, finalEmail, jwtSub, now()]
    );
    return { id, email: finalEmail };
}
```

## Profile and Preference Management

Customer preferences are dual-homed. Fields like `locale`, `theme`, and `marketing_consent` are stored in the local SQLite database for fast queries and synced to Auth0's `user_metadata` to ensure they persist across different store instances or Fufuni apps.

### Data Synchronization
When updating preferences, the framework updates the local `customers` table first, then asynchronously (or sequentially) calls the Auth0 Management API.

```typescript
// apps/merchant/src/routes/me.ts
adminApp.patch('/preferences', async (c) => {
    const db = getDb(c.env);
    const auth = c.get('auth');
    const { locale, theme, marketing_consent } = await c.req.json();

    // 1. Update local database
    await db.run(
        `UPDATE customers SET locale = ?, theme = ?, marketing_consent = ?, updated_at = ? WHERE auth_provider_id = ?`,
        [locale, theme, marketing_consent, now(), auth.sub]
    );

    // 2. Sync to Auth0 metadata
    await updateUserMetadata(c.env, auth.sub, {
        locale,
        theme,
        marketing_consent
    });

    return c.json({ success: true });
});
```

## Order History and Tax Breakdown

The `/v1/me/orders` endpoints filter records by the resolved `customer_id`. While the database uses UUIDs for primary keys, public URLs and customer communications must use the `order_number` (e.g., `ORD-7721`).

### Tax Breakdown
Taxes are not recalculated on the fly for history. They are retrieved from the `taxes_json` column, which stores the snapshot of taxes applied at the moment of checkout.

```typescript
// GET /v1/me/orders/:number
const orderRoute = createRoute({
  method: 'get',
  path: '/{number}',
  request: {
    params: z.object({ number: z.string() })
  },
  responses: {
    200: { description: 'Detailed order view' }
  }
});

adminApp.openapi(orderRoute, async (c) => {
    const db = getDb(c.env);
    const { number } = c.req.valid('param');
    const customer = await resolveCustomer(db, c.get('auth').sub);

    const order = await db.query(
        `SELECT o.*, 
        (SELECT json_group_array(json_object('id', oi.id, 'sku', oi.sku, 'quantity', oi.quantity)) 
         FROM order_items oi WHERE oi.order_id = o.id) as items
        FROM orders o WHERE o.order_number = ? AND o.customer_id = ? LIMIT 1`,
        [number, customer.id]
    );

    if (!order[0]) throw ApiError.notFound('Order not found');

    const orderData = order[0];
    return c.json({
        ...orderData,
        items: JSON.parse(orderData.items),
        taxes: JSON.parse(orderData.taxes_json || '[]') // Essential for regional compliance
    });
});
```

## Address Book Management

Address management includes logic to ensure exactly one "default" address exists. If a customer deletes their default address, the system must automatically promote another address.

### Default Address Logic
1.  **Mark Default**: When setting an address as default, the backend clears the `is_default` flag on all other addresses for that customer.
2.  **Auto-Promotion**: Upon deletion of a default address, the most recently created remaining address is promoted.

```sql
-- Step 1: Deletion
DELETE FROM customer_addresses WHERE id = ? AND customer_id = ?;

-- Step 2: Check if we need to promote a new default (if the deleted one was default)
UPDATE customer_addresses 
SET is_default = 1 
WHERE id = (
    SELECT id FROM customer_addresses 
    WHERE customer_id = ? 
    ORDER BY created_at DESC 
    LIMIT 1
) 
AND (SELECT COUNT(*) FROM customer_addresses WHERE customer_id = ? AND is_default = 1) = 0;
```

## Worked Example: Preferences Page

This example demonstrates a React 19 component using HeroUI v3 and the Fufuni client to manage user preferences.

### Frontend implementation
```typescript
// apps/storefront/src/components/account/PreferencesForm.tsx
import { useState } from 'react';
import { Button, Select, SelectItem, Switch } from "@heroui/react";
import { useAuth } from "../../hooks/use-auth";

export const PreferencesForm = ({ initialData }: { initialData: any }) => {
  const [theme, setTheme] = useState(initialData.theme || 'light');
  const [locale, setLocale] = useState(initialData.locale || 'en-US');
  const [loading, setLoading] = useState(false);

  const savePreferences = async () => {
    setLoading(true);
    try {
      await fetch('/api/v1/me/preferences', {
        method: 'PATCH',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ theme, locale })
      });
      // Update local state or notify user
    } finally {
      setLoading(false);
    }
  };

  return (
    <div className="space-y-6 max-w-md">
      <Select 
        label="Preferred Language" 
        selectedKeys={[locale]} 
        onChange={(e) => setLocale(e.target.value)}
      >
        <SelectItem key="en-US">English (US)</SelectItem>
        <SelectItem key="fr-FR">Français</SelectItem>
      </Select>

      <Select 
        label="Interface Theme" 
        selectedKeys={[theme]} 
        onChange={(e) => setTheme(e.target.value)}
      >
        <SelectItem key="light">Light Mode</SelectItem>
        <SelectItem key="dark">Dark Mode</SelectItem>
      </Select>

      <Button 
        color="primary" 
        isLoading={loading} 
        onPress={savePreferences}
      >
        Save Preferences
      </Button>
    </div>
  );
};
```
