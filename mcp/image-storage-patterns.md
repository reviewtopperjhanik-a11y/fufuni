## Image Storage Patterns

The Fufuni framework provides three storage methods for images: base64, R2, and external URL. Each method is used in different scenarios to balance storage efficiency, performance, and security.

### Storage Methods

*   **Base64**: Small images (< 1 MB) are stored directly in the SQLite database as WebP data URIs. This method reduces the number of requests to the database and is suitable for small images.
*   **R2**: Larger images are uploaded to Cloudflare R2 buckets via the `POST /v1/images` endpoint. This method is suitable for larger images that require a content delivery network (CDN) for efficient distribution.
*   **External URL**: External URLs are stored as-is, without any processing or storage by Fufuni. This method is suitable for images that are already hosted on a CDN or other external services.

### Automatic Size-Based Selection Logic

The `uploadImageFile()` function automatically selects the storage method based on the file size. The thresholds for selecting the storage method are:

*   **Base64**: Files smaller than 1 MB (after WebP conversion) are stored using the base64 method.
*   **R2**: Files larger than 1 MB (after WebP conversion) are stored using the R2 method.

The `forceR2` flag can be used to force the use of the R2 method regardless of the file size.

### WebP Conversion

All uploaded images are converted to WebP format with a maximum size of 1200 pixels and a quality of 0.8. This conversion is applied to improve image compression and reduce storage requirements. Thumbnails are generated separately at a size of 300 pixels.

### Upload Image File Function

The `uploadImageFile()` function is used to upload images to Fufuni. Its signature is:
```typescript
async function uploadImageFile(
  file: File,
  apiBaseUrl: string,
  postForm: PostFormFunction,
  forceR2 = false,
): Promise<ImageUploadResult>
```
Here's an example usage of the `uploadImageFile()` function with `useSecuredApi().postForm`:
```typescript
import { useSecuredApi } from '@/authentication';
import { uploadImageFile } from '@/utils/image-upload';

const apiBaseUrl = 'https://example.com/api';
const file = new File(['image data'], 'image.jpg', { type: 'image/jpeg' });

const { postForm } = useSecuredApi();
const result = await uploadImageFile(file, apiBaseUrl, postForm);
console.log(result.url); // The URL of the uploaded image
```
### ImageUploadInput Component

The `ImageUploadInput` component is a reusable UI component for managing image uploads. Its props are:

| Prop | Type | Description |
| --- | --- | --- |
| value | string | The current URL or data URI of the image |
| onChange | function | The callback function to update the image URL |
| onThumbnailChange | function | The callback function to update the thumbnail URL |
| apiBaseUrl | string | The base URL of the API |
| disabled | boolean | Whether the input is disabled |
| forceR2 | boolean | Whether to force the use of the R2 method |
| postForm | function | The POST function to use for uploading images (optional) |

Here's an example usage of the `ImageUploadInput` component in an admin form:
```typescript
import ImageUploadInput from '@/components/image-upload-input';

const AdminForm = () => {
  const [imageUrl, setImageUrl] = useState(null);
  const apiBaseUrl = 'https://example.com/api';

  const handleImageChange = (url) => {
    setImageUrl(url);
  };

  return (
    <div>
      <ImageUploadInput

        onChange={handleImageChange}

      />
    </div>
  );
```

### isValidImageUrl Security Guard

The `isValidImageUrl()` function is used to guard against invalid or malicious image URLs. It only allows HTTP(S) and data URLs. You should call this function before passing any user-input URL to the `<img src>` attribute.

### R2 Backend Endpoints

The R2 backend endpoints are:

*   `POST /v1/images`: Upload an image to the R2 bucket. Requires `admin:store` permission. Returns `{ url, key }`.
*   `DELETE /v1/images/:key`: Delete an image from the R2 bucket and purge the CDN cache entry. Requires `admin:store` permission.

### CDN Caching

Images served from R2 go through the KV CDN cache layer. When an image is updated or deleted, the CDN cache entry is purged to ensure that the latest version of the image is served. You can use the `DELETE /v1/images/:key` endpoint to purge the CDN cache entry for an image.
