## Triple-Layer Storage Architecture

Fufuni employs a hybrid image storage strategy designed to balance database performance with content delivery efficiency. Instead of forcing a single storage provider, the framework evaluates every image upload against three distinct methods.

### 1. Base64 Local Storage
Small images (typically under 1MB) are stored as WebP-encoded data URIs directly within the SQLite columns of the Durable Objects. This eliminates extra network requests and simplifies database portability.
- **Limit:** `BASE64_SIZE_LIMIT = 1024 * 1024` (1MB).
- **Best for:** Icons, product thumbnails, and small avatars.

### 2. Cloudflare R2 Remote Storage
Large images or those requiring high-performance CDN delivery are uploaded to a Cloudflare R2 bucket. The database stores the resulting R2 URL.
- **Limit:** `FILE_SIZE_LIMIT = 5 * 1024 * 1024` (5MB).
- **Best for:** Main product hero images and banner graphics.

### 3. External URLs
Direct URL references (e.g., from Cloudinary or an existing legacy CDN) can be stored as-is without re-uploading.

```typescript
// Example: Detecting storage method from a URL string
import { detectImageMethod, ImageStorageMethod } from '@/utils/image-upload';

const url1 = "data:image/webp;base64,UklGR...";
const url2 = "https://api.fufuni.store/v1/images/prod_123.webp";
const url3 = "https://images.unsplash.com/photo-123";

console.log(detectImageMethod(url1)); // "base64"
console.log(detectImageMethod(url2)); // "r2"
console.log(detectImageMethod(url3)); // "url"
```

## Automatic Size-Based Selection

The `uploadImageFile` utility implements a logic gate that determines whether an image should stay in the database or move to the cloud. This logic occurs after the image has been optimized and converted to WebP.

### Selection Logic
- If `forceR2` is `true`: Always upload to R2.
- If file size <= 1MB: Store as `base64`.
- If file size > 1MB: Upload to `r2`.

```typescript
/**
 * Logic implemented in image-upload.ts
 */
function getOptimalStorageMethod(
  fileSize: number,
  forceR2 = false,
): ImageStorageMethod {
  if (forceR2) return "r2";
  return fileSize <= 1024 * 1024 ? "base64" : "r2";
}
```

### Usage with uploadImageFile
The following example demonstrates how to use the core utility. It requires the `postForm` function from the Fufuni authentication hook to ensure the `admin:store` permission headers are attached.

```typescript

import { uploadImageFile } from '@/utils/image-upload';
```

## Mandatory WebP Conversion

Fufuni enforces image optimization on the client side before any upload occurs. This reduces bandwidth and storage costs. All files (JPEG, PNG, GIF) are converted using the `convertToWebp` utility.

### Optimization Parameters
- **Format:** `image/webp`
- **Max Width/Height:** 1200px (aspect ratio preserved)
- **Quality:** 0.8
- **Thumbnails:** If a thumbnail is required, a separate 300px WebP is generated.

```typescript
import { convertToWebp, blobToBase64 } from '@/utils/image-utils';

async function processImage(file: File) {
  // 1. Create main optimized image
  const mainBlob = await convertToWebp(file, 1200, 0.8);
  
  // 2. Create small thumbnail for quick previews
  const thumbBlob = await convertToWebp(file, 300, 0.8);
  const thumbBase64 = await blobToBase64(thumbBlob);

  return { mainBlob, thumbBase64 };
}
```

## Security Guard: isValidImageUrl

To prevent Cross-Site Scripting (XSS) via `javascript:` protocols or malformed data URIs, Fufuni provides the `isValidImageUrl` validator. This should be used whenever a URL string is passed into an `<img>` tag's `src` attribute.

### Supported Protocols
- `http:`
- `https:`
- `data:image/` (Data URIs)

```typescript
import { isValidImageUrl } from '@/utils/image-upload';

function SafeImage({ src }: { src: string }) {
  // Guard against injection or invalid schemes
  const safeSrc = isValidImageUrl(src) ? src : '/placeholder.png';

  return (
    <img 
      src={safeSrc} 
      alt="Validated Content" 
      className="rounded-lg shadow"
    />
  );
}
```

## Backend R2 Integration

The backend provides specific endpoints for managing R2 assets. These endpoints are protected by the `admin:store` permission.

### Upload: `POST /v1/images`
Accepts `multipart/form-data` with a `file` field.
- **Success Response:** `{ url: string, key: string }`
- **Key Format:** Usually a UUID or hash with a `.webp` extension.

### Delete: `DELETE /v1/images/:key`
Removes the object from the R2 bucket and triggers a cache purge.

## CDN Caching and Purging

Fufuni leverages Cloudflare's edge network to cache R2 images.

1.  **Cache Layer:** When an image is requested via the R2 URL, it is cached at the edge (KV or Cache API).
2.  **Naming Convention:** Images are immutable by convention. If a product image changes, a new key is generated.
3.  **Purging:** When a user deletes an image via the admin panel, Fufuni sends a request to the backend. The backend deletes the file from the R2 bucket and simultaneously invalidates the CDN cache for that specific key.

### Backend Implementation Detail (Reference)
In the Hono backend, the purge logic looks like this:

```typescript
// Conceptual backend logic
app.delete('/v1/images/:key', adminMiddleware('admin:store'), async (c) => {
  const key = c.req.param('key');
  
  // 1. Delete from R2 Bucket
  await c.env.IMAGE_BUCKET.delete(key);
  
  // 2. Invalidate CDN cache entry
  const cache = caches.default;
  const url = new URL(c.req.url);
  await cache.delete(new Request(url.toString()));

  return c.json({ success: true });
});
```
