## Image Storage Strategies

Fufuni employs a hybrid storage architecture to balance database performance with cost-efficiency. Every image in the framework is categorized into one of three storage methods based on its source and file size. This logic is encapsulated within `apps/client/src/utils/image-upload.ts`.

### 1. Base64 (Local SQLite Storage)
Small images (under 1MB after WebP conversion) are stored directly as WebP-encoded data URIs in the SQLite database. This strategy is ideal for icons, favicons, or small product thumbnails.
*   **Pros**: Zero latency from external storage fetches; atomic backups with the database.
*   **Cons**: Increases SQLite `.sqlite` file size; not suitable for large assets.

### 2. R2 (Cloudflare Object Storage)
Images exceeding 1MB or those explicitly marked for cloud storage are uploaded to a Cloudflare R2 bucket. The database stores the resulting URL (or R2 key).
*   **Pros**: CDN-backed performance; handles large files (up to 5MB limit).
*   **Cons**: Requires an HTTP request to fetch the asset.

### 3. External URL
Direct references to third-party providers (like Cloudinary, Unsplash, or Amazon S3) are stored as-is.
*   **Security**: These are guarded by the `isValidImageUrl` utility to prevent XSS or protocol-based attacks.

```typescript
import { ImageStorageMethod, detectImageMethod } from '@/utils/image-upload';

/**
 * Example: Determining storage method from a stored string
 */
const productImageUrl = "data:image/webp;base64,UklGR..."; // From SQLite
const storageType = detectImageMethod(productImageUrl); 

if (storageType === 'base64') {
  console.log("Image is stored locally in the database row.");
} else if (storageType === 'r2') {
  console.log("Image is served from Cloudflare R2.");
}
```

## Automatic Selection and Thresholds

The choice between Base64 and R2 is handled automatically by the `uploadImageFile` utility. Developers rarely need to decide manually, though they can override the behavior using the `forceR2` flag.

### Size Thresholds
*   **`BASE64_SIZE_LIMIT` (1MB)**: The maximum size of a WebP file that will be converted to a data URI and stored in the database.
*   **`FILE_SIZE_LIMIT` (5MB)**: The hard cap for any image upload. Files exceeding this are rejected by the client utility before reaching the network.

### Storage Logic Flow
1.  The file is validated for MIME type (`jpeg`, `png`, `webp`, `gif`).
2.  The file is converted to WebP (see next section).
3.  If `forceR2` is `true` OR the resulting WebP blob size > `BASE64_SIZE_LIMIT`, the file is sent to the `/v1/images` R2 endpoint.
4.  Otherwise, the file is converted to a Base64 string.

```typescript
import { uploadImageFile } from '@/utils/image-upload';
import { useSecuredApi } from '@/authentication';

const MyUploader = () => {
  const { postForm } = useSecuredApi();
  const apiBaseUrl = "https://api.fufuni.store";

  const handleUpload = async (file: File) => {
    try {
      // Automatic selection logic
      const result = await uploadImageFile(
        file, 
        apiBaseUrl, 
        postForm, 
        false // forceR2 = false
      );
      
      console.log(`Saved via ${result.method}: ${result.url}`);
    } catch (error) {
      console.error("Upload failed:", error);
    }
  };
};
```

## Mandatory WebP Transformation

To ensure consistent performance and storage efficiency, Fufuni forces all uploaded images into the WebP format. This happens client-side using a canvas-based processing utility before the network request is initiated.

### Parameters
*   **Max Dimensions**: 1200px (width or height). Larger images are scaled down proportionally.
*   **Quality**: 0.8 (balanced compression).
*   **Thumbnails**: When using the `ImageUploadInput` component, a secondary 300px thumbnail is generated. Thumbnails are **always** stored as Base64 because their small size (~10KB-30KB) is negligible for SQLite overhead.

```typescript
import { convertToWebp, blobToBase64 } from '@/utils/image-utils';

/**
 * Manual WebP transformation workflow
 */
async function processImage(file: File) {
  // 1. Transform to optimized WebP for main storage
  const mainBlob = await convertToWebp(file, 1200, 0.8);
  
  // 2. Transform to small thumbnail for previews
  const thumbBlob = await convertToWebp(file, 300, 0.8);
  const thumbBase64 = await blobToBase64(thumbBlob);
  
  return { mainBlob, thumbBase64 };
}
```

## ImageUploadInput Component

The `ImageUploadInput` component is the canonical UI element for handling image fields in the Fufuni admin dashboard. It provides a visual preview, storage method labeling, and controls for both file uploads and manual URL entry.

### Component Props
| Prop | Type | Description |
| :--- | :--- | :--- |
| `value` | `string \| null` | The current image URL or Base64 string. |
| `onChange` | `(url: string \| null) => void` | Callback when the main image is updated/removed. |
| `onThumbnailChange` | `(url: string \| null) => void` | (Optional) Callback to store a 300px base64 thumbnail. |
| `apiBaseUrl` | `string` | The base URL of the Hono backend. |
| `forceR2` | `boolean` | If true, disables Base64 storage and forces R2 uploads. |
| `disabled` | `boolean` | Disables all interactions. |

### Usage in Admin Form
The component is designed to work seamlessly within a controller-based form (like React Hook Form) or simple state management.

```typescript
import { useState } from 'react';
import { ImageUploadInput } from '@/components/image-upload-input';
import { Card, CardBody } from '@heroui/react';

export const ProductImageSection = () => {
  const [mainImage, setMainImage] = useState<string | null>(null);
  const [thumbImage, setThumbImage] = useState<string | null>(null);

  return (

      <CardBody className="gap-4">
        <h3>Product Media</h3>
```

## Security and URL Validation

Fufuni strictly validates image URLs to prevent malicious data entry. The `isValidImageUrl` utility acts as a security guard for the `<img>` tag's `src` attribute.

### Valid Protocols
1.  **`https:`**: Secure remote images.
2.  **`http:`**: Standard remote images (discouraged but allowed).
3.  **`data:image/`**: Base64 encoded images.

Any string failing this check is treated as potentially dangerous and is not rendered in the `ImageUploadInput` preview.

```typescript
import { isValidImageUrl } from '@/utils/image-upload';

const externalInput = "javascript:alert('XSS')";
const safeInput = "https://images.unsplash.com/photo-123";

console.log(isValidImageUrl(externalInput)); // false
console.log(isValidImageUrl(safeInput));     // true

// Usage in JSX
const Preview = ({ src }: { src: string }) => (
  <img 
    src={isValidImageUrl(src) ? src : '/placeholder.png'} 
    alt="Validated source" 
  />
);
```

## Backend Integration and R2 Endpoints

The backend logic for image management is located in the Hono API routes. Access to these endpoints requires a token with the `admin:store` permission.

### Upload Endpoint: `POST /v1/images`
*   **Input**: `multipart/form-data` containing a `file` field.
*   **Behavior**: Saves the file to the Cloudflare R2 bucket.
*   **Response**: `{ "key": "abc-123.webp", "url": "https://pub-xyz.r2.dev/abc-123.webp" }`.

### Delete and Purge: `DELETE /v1/images/:key`
*   **Behavior**: 
    1.  Removes the object from the R2 bucket.
    2.  Immediately purges the entry from the Cloudflare KV CDN cache layer.
*   **Purpose**: Ensures that when an admin deletes an image, it doesn't persist on edge nodes for the remainder of the TTL.

## CDN Caching and Performance

Images served via R2 are fronted by a caching layer. 

1.  **Cache-Control**: Images are served with a long `public, max-age=31536000` header by default.
2.  **CDN Layer**: Cloudflare's edge network caches these assets.
3.  **Invalidation**: Because images in Fufuni are effectively immutable (new uploads get new UUID keys), invalidation is only necessary during hard deletion via the `DELETE /v1/images/:key` endpoint.

When an image is stored as **Base64** in SQLite, it benefits from the same caching as the API response that delivers the product data. This makes Base64 ideal for performance-critical path items like navigation icons or small "buy now" badges that appear on every page load.
