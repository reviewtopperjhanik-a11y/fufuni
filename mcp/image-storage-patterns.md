# Image Storage Patterns

> The Fufuni e‑commerce stack stores images in three ways:
> 1. **Base64** – tiny images (≤ 1 MiB after WebP conversion) are kept as data URIs in SQLite.
> 2. **R2** – larger files (or forced) are uploaded to a Cloudflare R2 bucket and referenced by URL.
> 3. **URL** – an external image link (Cloudinary, CDN, etc.) is stored verbatim.

The following reference explains how and when each method is chosen, the WebP conversion strategy, the public APIs, and the CDN interaction.

---

## 1. Storage Methods & When They’re Used

| Method | Storage | Trigger | Typical Use‑Case |
|--------|---------|---------|------------------|
| **base64** | SQLite column (`image_data`) | File size ≤ 1 MiB after WebP conversion | Avatars, small icons, product thumbnails |
| **r2** | Cloudflare R2 bucket | File size > 1 MiB *or* `forceR2=true` | High‑res product photos, banners |
| **url** | Plain URL string | User supplies a URL | External hosting (Cloudinary, image‑CDN) |

> **Important** – All uploads are converted to WebP before deciding the method.  
> The 1 MiB limit refers to the *encoded* size after conversion, not the original file size.

## 2. Automatic Size‑Based Selection

```ts
const BASE64_SIZE_LIMIT = 1 * 1024 * 1024; // 1 MiB
const FILE_SIZE_LIMIT   = 5 * 1024 * 1024; // 5 MiB

function getOptimalStorageMethod(
  fileSize: number,
  forceR2 = false,
): ImageStorageMethod {
  if (forceR2) return "r2";
  return fileSize <= BASE64_SIZE_LIMIT ? "base64" : "r2";
}
```

* `FILE_SIZE_LIMIT` is a guard for the upload endpoint – the UI will reject files > 5 MiB.
* `forceR2` (prop on `ImageUploadInput`) bypasses the size check and always uploads to R2.

## 6. `isValidImageUrl()` – Security Guard

```ts
export function isValidImageUrl(url: string): boolean {
  try {
    const urlObj = new URL(url);
    return (
      urlObj.protocol === 'http:' ||
      urlObj.protocol === 'https:' ||
      url.startsWith('data:image/')
    );
  } catch {
    return url.startsWith('data:image/');
  }
}
```

* **What it accepts** – `http:`, `https:`, or `data:image/` URLs.  
* **When to use** – Before rendering any user‑supplied URL in `<img src={...}>` or passing it to a component that will render it.  
* **Why** – Prevents dangerous schemes (`javascript:`, `data:text/html`) that could lead to XSS.

## 7. R2 Backend Endpoints

| Method | Path | Description | Required Permission | Response |
|--------|------|-------------|----------------------|----------|
| **POST** | `/v1/images` | Upload an image; returns `{ url, key }` | `admin:store` | `201 Created` with JSON body |
| **DELETE** | `/v1/images/:key` | Delete image *and* purge CDN cache | `admin:store` | `204 No Content` |
| **GET** (implicit) | `/v1/images/:key` | Serve the image (served via CDN) | — | `200 OK` with image binary |

*The server side (`durable object`) enforces the `admin:store` permission before performing any action.*

---

## 8. CDN Caching & Purging

* **Caching** – R2 objects are automatically cached by Cloudflare’s KV CDN layer. The cache key is the object key (e.g., `images/abc123.webp`).
* **When the cache is stale** – If you delete or overwrite an image, the CDN might still serve the old version.
* **Purging** – Call the **DELETE** endpoint (`/v1/images/:key`). It deletes the object and *purges* the CDN entry atomically.
  ```ts
  await fetch(`https://api.example.com/v1/images/${imageKey}`, {
    method: 'DELETE',
    headers: { Authorization: `Bearer ${token}` },
  });
  ```
* **Best practice** – Always use the DELETE endpoint instead of a separate CDN‑purge API. It guarantees that the CDN never serves a deleted or updated image.

## Summary

1. **Upload Flow**  
   * Convert file → WebP (1200 px, 0.8) → decide method → base64 (≤ 1 MiB) or R2.  
   * If `forceR2=true`, skip the size check.  
2. **UI** – `ImageUploadInput` encapsulates all logic; just plug it into your admin forms.  
3. **Security** – `isValidImageUrl()` must guard any user‑supplied URL before rendering.  
4. **Backend** – POST `/v1/images` (upload), DELETE `/v1/images/:key` (delete + purge).  
5. **CDN** – Purge automatically when deleting; no separate purge API needed.  

Follow these patterns to keep image handling consistent, efficient, and secure across the Fufuni stack.
