## Core Storage Strategies

Fufuni implements a hybrid image storage strategy designed to balance database performance with external bucket costs. Every image in the system follows one of three storage methods, determined by its origin and size.

| Method | Storage Location | Use Case | Limit |
| :--- | :--- | :--- | :--- |
| **base64** | SQLite Column | Small assets (icons, thumbnails) | < 1MB |
| **r2** | Cloudflare R2 | Large product images, banners | < 5MB |
| **url** | Remote Server | External CDNs (Cloudinary, Unsplash) | N/A |

### Detecting Storage Methods

The `detectImageMethod` utility allows the frontend to determine how an image is stored based on its URL pattern. This is critical for UI feedback, such as showing size estimates for local base64 strings.

```typescript
import { detectImageMethod, type ImageStorageMethod } from '@/utils/image-upload';

const imageUrl = "data:image/webp;base64,UklGR...";
const method: ImageStorageMethod = detectImageMethod(imageUrl);

if (method === 'base64') {
  console.log("Image is stored directly in the database.");
} else if (method === 'r2') {
  console.log("Image is hosted on our Cloudflare R2 bucket.");
}
```

## Automatic Size-Based Selection

The framework automates the decision between base64 and R2 storage. This logic resides in the `uploadImageFile` utility. By default, the threshold is **1MB** (`BASE64_SIZE_LIMIT`).

1.  **Local Storage (base64):** If the file is smaller than 1MB after WebP conversion, it is converted to a Data URI. This reduces HTTP requests for small UI elements.
2.  **Remote Storage (r2):** If the file exceeds 1MB, or if the `forceR2` flag is true, it is sent to the `/v1/images` endpoint to be stored in a Cloudflare R2 bucket.

### Implementation Logic

```typescript
// excerpt from apps/client/src/utils/image-upload.ts
const BASE64_SIZE_LIMIT = 1024 * 1024; // 1MB

function getOptimalStorageMethod(
  fileSize: number,
  forceR2 = false,
): ImageStorageMethod {
  if (forceR2) return "r2";
  return fileSize <= BASE64_SIZE_LIMIT ? "base64" : "r2";
}
```

## Mandatory WebP Conversion

To ensure optimal performance and SEO, Fufuni converts **all** uploaded images to WebP format before storage. This happens on the client side using the `convertToWebp` utility.

### Conversion Parameters
-   **Maximum Width:** 1200px (higher resolutions are downscaled).
-   **Quality:** 0.8 (balanced compression).
-   **Thumbnails:** Generated at 300px width.

```typescript
import { convertToWebp, blobToBase64 } from '@/utils/image-utils';

async function processImage(file: File) {
  // Main product image (1200px max)
  const mainBlob = await convertToWebp(file, 1200, 0.8);
  
  // Separate thumbnail (300px max)
  const thumbBlob = await convertToWebp(file, 300, 0.8);
  const thumbBase64 = await blobToBase64(thumbBlob);
  
  return { mainBlob, thumbBase64 };
}
```

## Security Guard: isValidImageUrl

To prevent XSS (Cross-Site Scripting) and protocol injection (like `javascript:` URLs), Fufuni uses `isValidImageUrl`. This guard must be used whenever rendering an image URL provided by user input or an external API.

### Validation Rules
-   **Allowed Protocols:** `http:`, `https:`, and `data:image/`.
-   **Malformed URLs:** Catch-block returns false for non-standard strings that aren't data URIs.

```typescript
import { isValidImageUrl } from '@/utils/image-upload';

const unsafeInput = "javascript:alert('xss')";
const safeInput = "https://cdn.fufuni.com/logo.webp";

console.log(isValidImageUrl(unsafeInput)); // false
console.log(isValidImageUrl(safeInput));   // true

// Usage in JSX
<img 
  src={isValidImageUrl(value) ? value : '/fallback.png'} 
  alt="Secure Preview" 
/>
```

## Backend Integration & R2 Management

The backend handles R2 interactions through dedicated Hono routes. Access to these endpoints is restricted to users with the `admin:store` permission.

### Endpoints

1.  **POST `/v1/images`**: Receives `multipart/form-data`.
    -   Uploads the file to the R2 bucket.
    -   Returns `{ url, key }`.
2.  **DELETE `/v1/images/:key`**: Deletes the object from R2.
    -   **Crucial:** This also purges the object from the KV CDN cache layer.

### CDN Caching Logic

Fufuni uses a Cloudflare Worker as a proxy/CDN for R2 images. Images are cached at the edge for high performance.

-   **Cache-Control:** Images are served with immutable cache headers.
-   **Cache Purging:** When an image is deleted via the API, the backend explicitly calls `caches.default.delete()` or purges the specific KV entry associated with that R2 key to ensure no stale assets are served.

```typescript
// Example Backend Route (Hono)
app.post('/v1/images', adminMiddleware('admin:store'), async (c) => {
  const body = await c.req.parseBody();
  const file = body.file as File;
  
  const key = `products/${crypto.randomUUID()}.webp`;
  await c.env.R2_BUCKET.put(key, file.stream(), {
    httpMetadata: { contentType: 'image/webp' }
  });

  return c.json({
    key,
    url: `${c.env.CDN_BASE_URL}/${key}`
  });
});
```

### Manual Purge via Utility

In scenarios where an external URL is updated but the filename remains the same, the framework provides a hook to purge the CDN cache programmatically by the image key.

