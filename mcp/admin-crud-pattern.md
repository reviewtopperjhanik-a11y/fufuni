## Standardized Admin CRUD Architecture

Fufuni enforces a strict three-part pattern for all administrative resource management pages. This consistency ensures that features like search, status filtering, optimistic updates, and permission-based access behave identically across the dashboard.

The architecture consists of:
1.  **`useAdminCrud<T>` Hook**: Manages the state machine for data fetching (TanStack Query), modal visibility, and mutations (Create/Update/Delete).
2.  **`AdminCrudLayout` Component**: The structural shell providing the page header, "Add" button, search/filter inputs, and the data table.
3.  **`RowActions` Component**: A standardized action group for table rows that handles edit triggers and inline delete confirmations.

### Component Composition

In a typical implementation, the hook orchestrates the logic, while the layout wraps the visual elements. The modal logic is passed as a render prop to ensure it stays in the React tree only when needed.

```typescript
import { AdminCrudLayout } from "@/shared/ui/admin/admin-crud-layout";
import { useAdminCrud } from "@/hooks/use-admin-crud";
import { RowActions } from "@/shared/ui/admin/row-actions";

// Logic flow:
// 1. Hook fetches data and manages 'selectedItem'
// 2. Layout renders the 'items' in a table
// 3. RowActions in the table call 'openModal(item)'
// 4. Layout renders the Modal if 'isModalOpen' is true
```

## The useAdminCrud Hook

The `useAdminCrud` hook abstracts the boilerplate of TanStack Query and state management for modals. It is generic, accepting a type `T` that represents the entity (e.g., `ProductTag`).

### Parameters and Options

The hook requires a configuration object defining the API endpoints and the query key for cache invalidation.

| Property | Type | Description |
| :--- | :--- | :--- |
| `queryKey` | `string[]` | Unique key for TanStack Query caching. |
| `listUrl` | `string` | API endpoint for fetching the collection. |
| `createUrl` | `string` | API endpoint for POST requests. |
| `updateUrl` | `string` | API endpoint for PATCH/PUT requests (appends ID). |
| `deleteUrl` | `string` | API endpoint for DELETE requests (appends ID). |
| `zodSchema` | `ZodSchema` | Used for client-side validation before mutation. |

### Return Values

```typescript
const {
  items,          // Array of T: the fetched data
  isLoading,      // Boolean: loading state for the list
  create,         // Function: trigger POST mutation
  update,         // Function: trigger PATCH mutation
  remove,         // Function: trigger DELETE mutation
  selectedItem,   // T | null: the item currently being edited
  setSelectedItem,// Function: manually set the active item
  isModalOpen,    // Boolean: controlled state for the HeroUI Modal
  openModal,      // Function: opens modal (resets selectedItem if no arg)
  closeModal      // Function: closes modal and clears selectedItem
} = useAdminCrud<ProductTag>({ 
  queryKey: ['tags'],
  listUrl: '/api/v1/admin/tags'
  /* ... */ 
});
```

## AdminCrudLayout and Table Columns

`AdminCrudLayout` integrates HeroUI components with TanStack Table. It expects a `columns` definition array following the `ColumnDef<T>` format.

### Column Definition with RowActions

The action column is where `RowActions` is typically injected.

```typescript
import { ColumnDef } from "@tanstack/react-table";

const getColumns = (
  onEdit: (item: ProductTag) => void,
  onDelete: (item: ProductTag) => void
): ColumnDef<ProductTag>[] => [
  {
    accessorKey: "name",
    header: "Tag Name",
  },
  {
    id: "actions",
    cell: ({ row }) => (
      <RowActions
        onEdit={() => onEdit(row.original)}
        onDelete={() => onDelete(row.original)}
        deleteConfirmMessage={`Are you sure you want to delete "${row.original.name}"?`}
      />
    ),
  },
];
```

### Layout Props

The layout handles the visual hierarchy and filtering UI:

- **title / addLabel**: Localized strings for the header.
- **renderModal**: A function or JSX block containing the `HeroUI` Modal.
- **onAdd**: Callback triggered by the primary header button (usually `() => openModal()`).
- **globalFilter / onGlobalFilterChange**: Controlled state for the search bar.

## RowActions and Delete Confirmation

The `RowActions` component encapsulates the "Edit" and "Delete" icons. It uses HeroUI's `Popover` internally to provide a "Confirm Delete" step without requiring a global dialog manager.

```typescript
export function RowActions({ onEdit, onDelete, deleteConfirmMessage }: RowActionsProps) {
  // Internal state handles the Popover for deletion confirmation
  // The 'onDelete' callback is only fired if the user confirms in the popover.

    <div className="flex gap-2">

            <p>{deleteConfirmMessage}</p>
            <Button onPress={onDelete}>Confirm</Button>
          </div>
        </Popover.Content>
      </Popover>
    </div>
  );
}
```

## Form Validation and Modal Pattern

The CRUD pattern uses a single modal for both **Create** and **Update** operations. The distinction is made by the presence of `selectedItem`.

1.  **Create**: `selectedItem` is `null`. The form starts with default values.
2.  **Edit**: `selectedItem` contains the object. The form is pre-populated via `react-hook-form`'s `reset()` or `defaultValues`.

### Integration with Zod

Validation must be defined via Zod and passed to `useAdminCrud` to ensure the hook can validate data before sending it to the backend.

```typescript
import { z } from "zod";
import { useForm } from "react-hook-form";
import { zodResolver } from "@hookform/resolvers/zod";

const tagSchema = z.object({
  name: z.string().min(2, "Name is required"),
  slug: z.string().min(2, "Slug is required"),
  status: z.enum(["active", "inactive"]),
});

type TagFormValues = z.infer<typeof tagSchema>;

// Inside the Modal Component:
const { register, handleSubmit, formState: { errors } } = useForm<TagFormValues>({
  resolver: zodResolver(tagSchema),
  values: selectedItem ?? { name: "", slug: "", status: "active" }
});
```

## Route Protection

Admin management pages must be protected at the route level in `app.tsx`. Use the `AuthenticationGuardWithPermission` component to wrap the admin routes. This prevents unprivileged users from even mounting the CRUD components.

```typescript
// apps/client/src/app.tsx
import { AuthenticationGuardWithPermission } from "@/components/auth/guard";

const adminRoutes = {
  path: "/admin/tags",
  element: (
    <AuthenticationGuardWithPermission permission="admin:store">
      <ProductTagsPage />
    </AuthenticationGuardWithPermission>
  ),
};
```

## Worked Example: ProductTags Admin

This example demonstrates a complete implementation of a "Product Tags" management interface.

```typescript
/**
 * apps/client/src/pages/admin/product-tags.tsx
 */
import { useMemo } from "react";
import { Modal, ModalContent, ModalHeader, ModalBody, ModalFooter, Button, Input } from "@heroui/react";
import { useForm } from "react-hook-form";
import { z } from "zod";
import { zodResolver } from "@hookform/resolvers/zod";
import { useAdminCrud } from "@/hooks/use-admin-crud";
import { AdminCrudLayout } from "@/shared/ui/admin/admin-crud-layout";
import { RowActions } from "@/shared/ui/admin/row-actions";

const tagSchema = z.object({
  id: z.string().optional(),
  name: z.string().min(1, "Name required"),
  status: z.string().default("active"),
});

type Tag = z.infer<typeof tagSchema>;

export default function ProductTagsPage() {
  const {
    items,
    isLoading,
    create,
    update,
    remove,
    selectedItem,
    isModalOpen,
    openModal,
    closeModal,
  } = useAdminCrud<Tag>({
    queryKey: ["product-tags"],
    listUrl: "/api/v1/admin/tags",
    createUrl: "/api/v1/admin/tags",
    updateUrl: "/api/v1/admin/tags",
    deleteUrl: "/api/v1/admin/tags",
    zodSchema: tagSchema,
  });

  const { register, handleSubmit, reset } = useForm<Tag>({
    resolver: zodResolver(tagSchema),
  });

  // Handle form submission for both create and update
  const onSubmit = (data: Tag) => {
    if (selectedItem) {
      update.mutate({ ...data, id: selectedItem.id }, {
        onSuccess: () => closeModal()
      });
    } else {
      create.mutate(data, {
        onSuccess: () => {
          closeModal();
          reset();
        }
      });
    }
  };

  const columns = useMemo(() => [
    { accessorKey: "name", header: "Name" },
    { accessorKey: "status", header: "Status" },
    {
      id: "actions",
      cell: ({ row }) => (
        <RowActions
          onEdit={() => openModal(row.original)}
          onDelete={() => remove.mutate(row.original.id!)}
          deleteConfirmMessage={`Delete tag "${row.original.name}"?`}
        />
      ),
    },
  ], [openModal, remove]);

  return (
    <AdminCrudLayout
      title="Product Tags"
      addLabel="Add Tag"
      onAdd={() => openModal()}
      columns={columns}
      data={items}
      isLoading={isLoading}
      globalFilter=""
      onGlobalFilterChange={() => {}}
      statusFilter=""
      onStatusFilterChange={() => {}}
    >
      <Modal isOpen={isModalOpen} onClose={closeModal}>
        <ModalContent>
          <form onSubmit={handleSubmit(onSubmit)}>
            <ModalHeader>
              {selectedItem ? `Edit ${selectedItem.name}` : "Create New Tag"}
            </ModalHeader>
            <ModalBody className="gap-4">
              <Input
                {...register("name")}
                label="Tag Name"
                placeholder="e.g. Summer Collection"
                defaultValue={selectedItem?.name}
              />
            </ModalBody>
            <ModalFooter>
              <Button variant="ghost" onPress={closeModal}>Cancel</Button>
              <Button color="primary" type="submit" isLoading={create.isPending || update.isPending}>
                {selectedItem ? "Update" : "Create"}
              </Button>
            </ModalFooter>
          </form>
        </ModalContent>
      </Modal>
    </AdminCrudLayout>
  );
}
```

### Key Logic Checklist for Developers:
- Ensure the `queryKey` matches exactly across all hooks interacting with the same resource to ensure cache invalidation works.
- Always include the `id` in the `update.mutate` call; the hook uses this to construct the correct URL.
- Use `isLoading` from `useAdminCrud` to show skeleton states in the `AdminCrudLayout`.
- Standardize your translation keys (e.g., `admin.tags.title`) even if not shown in the basic code example above.
