## The Unified Admin CRUD Pattern

Fufuni enforces a standardized architectural pattern for all administrative Create, Read, Update, and Delete (CRUD) interfaces. This consistency ensures that management screens—ranging from product catalogs to user lists—behave identically, share the same filtering logic, and utilize a common visual language.

The pattern relies on three primary building blocks:
1.  **`useAdminCrud`**: A custom React hook that manages the local state for filtering, searching, and modal visibility.
2.  **`AdminCrudLayout`**: A layout component that renders the standardized header (title, add button) and the filter toolbar.
3.  **`RowActions`**: A utility component for table rows providing consistent "Edit" and "Delete" triggers.

### Core Architectural Principles

- **Local State Management**: The `useAdminCrud` hook handles the heavy lifting of client-side filtering and modal orchestration.
- **Filtering Logic**: Search is performed via a user-defined `filterFn` passed to the hook. Status filtering is built-in, supporting `""` (All), `active`, and `inactive` states.
- **Stateless Layout**: The `AdminCrudLayout` does not hold state; it receives its values and callbacks from the hook, ensuring a unidirectional data flow.
- **No Reinvention**: Developers must not build custom filter bars or modal state machines for standard CRUD pages.

## Managing State with useAdminCrud

The `useAdminCrud` hook is the engine of the admin interface. It expects a generic type `T` that extends `HasIdAndStatus` (requiring an `id: string` and optional `status?: string`).

### Hook Implementation Example

When initializing the hook, you must provide a `filterFn`. This function is executed against every item in the `items` array whenever the `globalFilter` (search text) changes.

```typescript
import { useAdminCrud } from "@/hooks/use-admin-crud";

interface Brand {
  id: string;
  name: string;
  code: string;
  status: "active" | "inactive";
}

export function BrandManagement() {
  const {
    items,
    setItems,
    displayedItems,
    globalFilter,
    setGlobalFilter,
    statusFilter,
    setStatusFilter,
    openCreate,
    openEdit,
    isModalOpen,
    isEditMode,
    editingItem,
    closeModal,
  } = useAdminCrud<Brand>({
    filterFn: (brand, term) =>
      brand.name.toLowerCase().includes(term) ||
      brand.code.toLowerCase().includes(term),
  });

  // Items are typically populated via a useEffect or TanStack Query
  // setItems(fetchedData);

  return (
    <div>
      {/* Layout and Table go here */}
    </div>
  );
}
```

### Key Hook Outputs

| Property | Description |
| :--- | :--- |
| `displayedItems` | The subset of data to be rendered in the table after applying search and status filters. |
| `openCreate` | Resets `editingItem` and `isEditMode` before opening the modal. |
| `openEdit(item)` | Sets the `editingItem`, enables `isEditMode`, and opens the modal. |
| `statusFilter` | Managed string state: `""`, `"active"`, or `"inactive"`. |

## Structuring the Layout with AdminCrudLayout

The `AdminCrudLayout` component provides the visual shell. It expects the main data table to be passed as `children`. This component handles the positioning of the "Add" button and the standard HeroUI `Card` containing the search and status inputs.

### Layout Implementation Example

This example demonstrates how to wire the `useAdminCrud` state directly into the `AdminCrudLayout` props.

## Full Integration Pattern

Below is a complete, functional example of a standard Fufuni Admin CRUD page. It demonstrates the coordination between the state hook, the layout wrapper, and the interaction components.

```typescript
/**

import { useEffect } from "react";
import { useTranslation } from "react-i18next";
import { Table, TableHeader, TableColumn, TableBody, TableRow, TableCell, Chip } from "@heroui/react";
import { Globe } from "lucide-react";
import { useAdminCrud } from "@/hooks/use-admin-crud";
import { AdminCrudLayout } from "@/shared/ui/admin/admin-crud-layout";
import { RowActions } from "@/shared/ui/admin/row-actions";

interface Country {
  id: string;
  display_name: string;
  iso_code: string;
  status: "active" | "inactive";
}

export function CountryAdminPage() {
  const { t } = useTranslation();
  
  const {
    setItems,
    displayedItems,
    globalFilter,
    setGlobalFilter,
    statusFilter,
    setStatusFilter,
    openCreate,
    openEdit,
  } = useAdminCrud<Country>({
    filterFn: (item, term) => 
      item.display_name.toLowerCase().includes(term) || 
      item.iso_code.toLowerCase().includes(term),
  });

  // Mock data simulation
  useEffect(() => {
    const data: Country[] = [
      { id: "1", display_name: "France", iso_code: "FR", status: "active" },
      { id: "2", display_name: "Germany", iso_code: "DE", status: "active" },
      { id: "3", display_name: "Untrusted Region", iso_code: "XX", status: "inactive" },
    ];
    setItems(data);
  }, [setItems]);

  const handleDelete = (id: string) => {
    // API Call: deleteCountry(id)
    setItems(prev => prev.filter(i => i.id !== id));
  };

  return (
    <AdminCrudLayout
      title={t("admin-countries-title")}
      icon={<Globe className="w-8 h-8" />}
      addLabel={t("admin-countries-add")}
      onAdd={openCreate}
      globalFilter={globalFilter}
      onGlobalFilterChange={setGlobalFilter}
      statusFilter={statusFilter}
      onStatusFilterChange={setStatusFilter}
    >
      <Table aria-label="Countries collection">
        <TableHeader>
          <TableColumn>{t("admin-countries-col-name")}</TableColumn>
          <TableColumn>{t("admin-countries-col-code")}</TableColumn>
          <TableColumn>{t("admin-countries-col-status")}</TableColumn>
          <TableColumn align="end">{t("admin-common-actions")}</TableColumn>
        </TableHeader>
        <TableBody items={displayedItems} emptyContent={t("admin-common-no-results")}>
          {(item) => (
            <TableRow key={item.id}>
              <TableCell className="font-medium">{item.display_name}</TableCell>
              <TableCell>
                <code className="bg-default-100 px-1 rounded">{item.iso_code}</code>
              </TableCell>
              <TableCell>
                <Chip 
                  size="sm" 
                  variant="flat" 
                  color={item.status === "active" ? "success" : "default"}
                >
                  {item.status}
                </Chip>
              </TableCell>
              <TableCell>
                <RowActions 
                  onEdit={() => openEdit(item)} 
                  onDelete={() => handleDelete(item.id)} 
                />
              </TableCell>
            </TableRow>
          )}
        </TableBody>
      </Table>
      
      {/* 
         Modal component would go here, using:
         isOpen={isModalOpen} 
         onClose={closeModal}
         initialData={editingItem}
      */}
    </AdminCrudLayout>
  );
}
```

### Key Implementation Constraints

- **Pagination**: The `useAdminCrud` hook does **not** handle pagination or server-side sorting. If your dataset is large, you must implement server-side pagination manually using `Table`'s pagination props and handle the data fetching state independently of the hook's `items` array.
- **Form State**: Do not attempt to store form field values (like `name` or `description`) inside `useAdminCrud`. The hook only tracks which item is being edited. Use a dedicated form library (like `react-hook-form` with `zod`) inside your modal component.
- **Status Values**: The status filter is hardcoded to look for the property `status` on your objects. If your data uses a different key (e.g., `is_enabled`), you must map your data or extend the hook logic. The standard Fufuni schema uses `status` with values `"active"` or `"inactive"`.
