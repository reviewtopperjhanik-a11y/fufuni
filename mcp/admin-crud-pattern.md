## Standardized Admin CRUD Architecture

The Fufuni framework mandates a unified pattern for all administrative resource management. This architecture ensures UI consistency across the dashboard while significantly reducing boilerplate code. The pattern relies on three core pillars: the `AdminCrudLayout` component for the visual shell, the `useAdminCrud` hook for state synchronization, and `RowActions` for consistent table interactions.

Adhering to this pattern is mandatory for all new admin features. It centralizes filter logic, modal state management, and the responsive layout grid. By using these primitives, developers only need to focus on the specific data schema and form logic of their entity.

### The useAdminCrud Hook

The `useAdminCrud` hook is the engine of the pattern. it manages the lifecycle of the data list, the visibility of the creation/edition modal, and the filtering logic. It requires a `filterFn` to define how the global search bar interacts with your data type.

```typescript
import { useAdminCrud, type HasIdAndStatus } from "@/shared/ui/admin/use-admin-crud";

interface Brand extends HasIdAndStatus {
  id: string;
  name: string;
  slug: string;
  status: "active" | "inactive";
}

export function useBrandManager() {
  const {
    items,
    setItems,
    displayedItems,
    globalFilter,
    setGlobalFilter,
    statusFilter,
    setStatusFilter,
    isModalOpen,
    openCreate,
    openEdit,
    closeModal,
    isEditMode,
    editingItem,
  } = useAdminCrud<Brand>({
    filterFn: (brand, term) => 
      brand.name.toLowerCase().includes(term) || 
      brand.slug.toLowerCase().includes(term),
  });

  return {
    // Return all standard properties to the component
    state: { items, displayedItems, globalFilter, statusFilter, isModalOpen, isEditMode, editingItem },
    actions: { setItems, setGlobalFilter, setStatusFilter, openCreate, openEdit, closeModal }
  };
}
```

This hook handles the `displayedItems` memoization automatically based on `globalFilter` and `statusFilter`. It specifically expects status values to be either an empty string (all), `"active"`, or `"inactive"`. Note that sorting and pagination are not handled by this hook; if your dataset exceeds standard dashboard sizes, you must implement server-side pagination separately.

## Implementing the AdminCrudLayout

The `AdminCrudLayout` provides the structural container for admin pages. It includes a header with a title and action button, a filter card with a search input and status dropdown, and a main content area usually occupied by a HeroUI `Table`.

### Layout Configuration

When implementing the layout, you should pass the filtering states and setters provided by the `useAdminCrud` hook directly to the layout props. This wires up the search bar and status picker to the data transformation logic.

```tsx
import { AdminCrudLayout } from "@/shared/ui/admin/admin-crud-layout";
import { Table, TableHeader, TableColumn, TableBody, TableRow, TableCell } from "@heroui/react";
import { Tag } from "lucide-react";

// Inside your Component:
const { state, actions } = useBrandManager();

return (
  <AdminCrudLayout
    title="Product Brands"
    subtitle="Manage your inventory manufacturers and brands"
    icon={<Tag className="w-8 h-8 text-primary" />}
    addLabel="Add Brand"
    onAdd={actions.openCreate}
    globalFilter={state.globalFilter}
    onGlobalFilterChange={actions.setGlobalFilter}
    statusFilter={state.statusFilter}
    onStatusFilterChange={actions.setStatusFilter}
  >
    <Table aria-label="Brands list table">
      <TableHeader>
        <TableColumn>NAME</TableColumn>
        <TableColumn>SLUG</TableColumn>
        <TableColumn>STATUS</TableColumn>
        <TableColumn align="end">ACTIONS</TableColumn>
      </TableHeader>
      <TableBody items={state.displayedItems}>
        {(item) => (
          <TableRow key={item.id}>
            <TableCell>{item.name}</TableCell>
            <TableCell>{item.slug}</TableCell>
            <TableCell>{item.status}</TableCell>
            <TableCell>
              {/* RowActions will be placed here */}
            </TableCell>
          </TableRow>
        )}
      </TableBody>
    </Table>
  </AdminCrudLayout>
);
```

The `AdminCrudLayout` also supports a `headerExtra` prop. This is the designated slot for informational banners, alerts, or bulk action toolbars that need to appear above the filter controls but below the main title.

## Row Actions and Table Integration

To maintain a consistent look for action buttons within tables, use the `RowActions` component. This component standardizes the "Edit" and "Delete" icons, their tooltips, and their accessibility labels. It uses the `tertiary` button variant by default to remain visually subtle within dense data tables.

### Implementing Row Interactions

`RowActions` should be used in the final column of your table. It encapsulates the repetitive pattern of Lucide icons and HeroUI Tooltips.

```tsx
import { RowActions } from "@/shared/ui/admin/row-actions";
import { Chip } from "@heroui/react";

// Inside your TableBody mapping:
<TableRow key={item.id}>
  <TableCell className="font-medium">{item.name}</TableCell>
  <TableCell>
    <Chip 
      color={item.status === "active" ? "success" : "default"} 
      variant="flat" 
      size="sm"
    >
      {item.status}
    </Chip>
  </TableCell>
  <TableCell>
    <div className="flex justify-end">
      <RowActions 
        onEdit={() => actions.openEdit(item)} 
        onDelete={() => handleDelete(item.id)} 
      />
    </div>
  </TableCell>
</TableRow>
```

The `onEdit` callback usually triggers the `openEdit(item)` method from `useAdminCrud`, which populates the `editingItem` state and opens the modal. The `onDelete` callback should trigger your API deletion logic (usually through a TanStack Query mutation).

```tsx
import { useState, useEffect } from "react";
import { useTranslation } from "react-i18next";
import { Table, TableHeader, TableColumn, TableBody, TableRow, TableCell, Chip } from "@heroui/react";
import { Truck } from "lucide-react";
import { AdminCrudLayout } from "@/shared/ui/admin/admin-crud-layout";
import { RowActions } from "@/shared/ui/admin/row-actions";
import { useAdminCrud, type HasIdAndStatus } from "@/hooks/use-admin-crud";

interface ShippingZone extends HasIdAndStatus {
  id: string;
  name: string;
  region: string;
  status: "active" | "inactive";
}

export default function ShippingZonesPage() {
  const { t } = useTranslation();
  
  // 1. Initialize CRUD logic
  const {
    displayedItems,
    setItems,
    globalFilter,
    setGlobalFilter,
    statusFilter,
    setStatusFilter,
    openCreate,
    openEdit,
    isModalOpen,
    isEditMode,
    editingItem,
    closeModal
  } = useAdminCrud<ShippingZone>({
    filterFn: (zone, term) => 
      zone.name.toLowerCase().includes(term) || 
      zone.region.toLowerCase().includes(term),
  });

  // 2. Simulate data fetching
  useEffect(() => {
    const mockData: ShippingZone[] = [
      { id: "1", name: "Domestic", region: "France", status: "active" },
      { id: "2", name: "Europe West", region: "EU", status: "active" },
      { id: "3", name: "Global", region: "World", status: "inactive" },
    ];
    setItems(mockData);
  }, [setItems]);

  const handleDelete = (id: string) => {
    if (confirm(t("admin-common-confirm-delete"))) {
      setItems(prev => prev.filter(i => i.id !== id));
    }
  };

  return (
    <>
      <AdminCrudLayout
        title={t("admin-shipping-zones-title")}
        subtitle={t("admin-shipping-zones-subtitle")}
        icon={<Truck className="w-8 h-8" />}
        addLabel={t("admin-shipping-zones-add")}
        onAdd={openCreate}
        globalFilter={globalFilter}
        onGlobalFilterChange={setGlobalFilter}
        statusFilter={statusFilter}
        onStatusFilterChange={setStatusFilter}
      >
        <Table aria-label="Shipping zones table" selectionMode="none">
          <TableHeader>
            <TableColumn>{t("admin-common-name")}</TableColumn>
            <TableColumn>{t("admin-common-region")}</TableColumn>
            <TableColumn>{t("admin-common-status")}</TableColumn>
            <TableColumn align="end">{t("admin-common-actions")}</TableColumn>
          </TableHeader>
          <TableBody items={displayedItems} emptyContent={t("admin-common-no-results")}>
            {(item) => (
              <TableRow key={item.id}>
                <TableCell className="font-semibold">{item.name}</TableCell>
                <TableCell>{item.region}</TableCell>
                <TableCell>
                  <Chip
                    size="sm"
                    variant="flat"
                    color={item.status === "active" ? "success" : "default"}
                  >
                    {item.status === "active" ? t("admin-common-active") : t("admin-common-inactive")}
                  </Chip>
                </TableCell>
                <TableCell>
                  <div className="flex justify-end">
                    <RowActions
                      onEdit={() => openEdit(item)}
                      onDelete={() => handleDelete(item.id)}
                    />
                  </div>
                </TableCell>
              </TableRow>
            )}
          </TableBody>
        </Table>
      </AdminCrudLayout>

      {/* 
        The Modal/Form would go here, 
        using isModalOpen, isEditMode, and editingItem 
      */}
    </>
  );
}
```

### Pattern Constraints and Best Practices

1.  **Do Not Reinvent State**: Avoid creating local `useState` for search terms or modal visibility if `useAdminCrud` provides them. The hook's implementation of `displayedItems` uses `useMemo` for performance; duplicating this logic elsewhere is prone to bugs.
2.  **Strict Status Values**: The `statusFilter` logic in `useAdminCrud` expects items to have a `status` property. If your entity uses different terminology (e.g., `published`, `draft`), map these to the `active`/`inactive` paradigm or extend the hook.
3.  **Table Semantics**: Always provide an `aria-label` to the HeroUI `Table` component for accessibility.
4.  **Filter Persistence**: The standard pattern does not persist filter state in the URL. If a specific page requires "deep linking" to search results, you must replace the `useState` inside `useAdminCrud` with a URL-syncing hook (like `useQueryState`).
5.  **Modal Placement**: Place your creation/edition Modals outside the `AdminCrudLayout` but within the same page component. This keeps the layout logic clean and prevents unnecessary re-renders of the data table when form fields change.
6.  **I18n**: Never hardcode strings in the layout props. Use the `useTranslation` hook and standard keys (e.g., `admin-common-status`, `admin-common-edit`).
