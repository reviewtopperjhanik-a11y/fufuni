## Admin CRUD Architecture

Fufuni enforces a standardized three-part pattern for all administrative management interfaces. This consistency ensures that features like search, status filtering, optimistic UI updates, and permission handling behave identically across the entire dashboard.

The pattern consists of:
1.  **`useAdminCrud<T>()` Hook**: Orchestrates data fetching (TanStack Query), local state for filters, and modal visibility logic.
2.  **`AdminCrudLayout` Component**: The structural shell containing the header, "Add" button, search/filter inputs, and the data table.
3.  **`RowActions` Component**: A standardized action cell for the table that handles edit triggers and inline delete confirmation.

## The useAdminCrud Hook

The `useAdminCrud` hook encapsulates the boilerplate for interacting with Fufuni's Hono-based backend. It integrates with `react-hook-form` and `zod` for client-side validation before submission.

### Hook Options and Parameters
The hook accepts a generic type `T` representing the entity (e.g., `ProductTag`) and an options object:

| Field | Type | Description |
| :--- | :--- | :--- |
| `queryKey` | `string[]` | The TanStack Query key for caching and invalidation. |
| `listUrl` | `string` | The API endpoint for fetching the collection. |
| `createUrl` | `string` | The API endpoint for POST requests. |
| `updateUrl` | `string` | The API endpoint for PATCH/PUT requests. |
| `deleteUrl` | `string` | The API endpoint for DELETE requests. |
| `zodSchema` | `ZodSchema` | Used for validating the form data before API submission. |

### Return Values
The hook returns an object that must be spread or destructured into the `AdminCrudLayout`:

```typescript
const {
  items,          // The filtered and searched data array
  isLoading,      // Loading state for the initial fetch
  create,         // Function to trigger the creation mutation
  update,         // Function to trigger the update mutation
  remove,         // Function to trigger the deletion mutation
  selectedItem,   // The item currently being edited (null if creating)
  setSelectedItem,// Manually update the active item
  isModalOpen,    // Boolean for the HeroUI Modal state
  openModal,      // Opens the modal (resets selectedItem if no arg)
  closeModal      // Closes the modal and resets form state
} = useAdminCrud<ProductTag>({ ...options });
```

## AdminCrudLayout and Table Definitions

The `AdminCrudLayout` uses TanStack Table under the hood for the `columns` definition. Columns are defined as an array of `ColumnDef<T>`.

### Column Definition Format
Standard practice in Fufuni is to define columns in the same file as the component, usually outside the component function to prevent re-renders.

```typescript
import { ColumnDef } from "@tanstack/react-table";
import { RowActions } from "@/shared/ui/admin/row-actions";

export const getColumns = (
  onEdit: (item: ProductTag) => void,
  onDelete: (item: ProductTag) => void
): ColumnDef<ProductTag>[] => [
  {
    accessorKey: "name",
    header: "Tag Name",
  },
  {
    id: "actions",
    cell: ({ row }) => (
      <RowActions
        onEdit={() => onEdit(row.original)}
        onDelete={() => onDelete(row.original)}
        deleteConfirmMessage={`Are you sure you want to delete "${row.original.name}"?`}
      />
    ),
  },
];
```

## Security and Route Protection

Admin routes must never be exposed without permission checks. In Fufuni, this is handled at the routing layer in `apps/client/src/app.tsx` using the `AuthenticationGuardWithPermission` component.

```typescript
// apps/client/src/app.tsx example
<Route
  path="/admin/tags"
  element={
    <AuthenticationGuardWithPermission permission="admin:store">
      <ProductTagsPage />
    </AuthenticationGuardWithPermission>
  }
/>
```

## Worked Example: ProductTags Management

This example demonstrates a complete administrative page for managing product tags, including the list view, creation/edit modal, and form validation.

### 1. Schema and Types
```typescript
import { z } from "zod";

export const ProductTagSchema = z.object({
  id: z.string().optional(),
  name: z.string().min(2, "Name must be at least 2 characters"),
  slug: z.string().min(2).regex(/^[a-z0-9-]+$/, "Invalid slug format"),
  status: z.enum(["active", "inactive"]).default("active"),
});

export type ProductTag = z.infer<typeof ProductTagSchema>;
```

### 2. The Implementation Component
```typescript
import { useForm } from "react-hook-form";
import { zodResolver } from "@hookform/resolvers/zod";
import { 
  Modal, ModalContent, ModalHeader, ModalBody, ModalFooter,
  Button, Input, Select, SelectItem 
} from "@heroui/react";
import { AdminCrudLayout } from "@/shared/ui/admin/admin-crud-layout";
import { useAdminCrud } from "@/hooks/use-admin-crud";
import { ProductTag, ProductTagSchema } from "./types";
import { getColumns } from "./columns";

export function ProductTagsPage() {
  const {
    items,
    isLoading,
    create,
    update,
    remove,
    selectedItem,
    isModalOpen,
    openModal,
    closeModal,
  } = useAdminCrud<ProductTag>({
    queryKey: ["product-tags"],
    listUrl: "/api/v1/admin/tags",
    createUrl: "/api/v1/admin/tags",
    updateUrl: "/api/v1/admin/tags/:id",
    deleteUrl: "/api/v1/admin/tags/:id",
    zodSchema: ProductTagSchema,
  });

  const { register, handleSubmit, reset, formState: { errors } } = useForm<ProductTag>({
    resolver: zodResolver(ProductTagSchema),
    values: selectedItem ?? { name: "", slug: "", status: "active" },
  });

  const onSubmit = (data: ProductTag) => {
    if (selectedItem) {
      update.mutate(data, { onSuccess: closeModal });
    } else {
      create.mutate(data, { onSuccess: closeModal });
    }
  };

  const columns = getColumns(
    (item) => openModal(item), // Edit
    (item) => remove.mutate(item.id) // Delete
  );

  return (
    <AdminCrudLayout
      title="Product Tags"
      addLabel="Add Tag"
      onAdd={() => { reset(); openModal(); }}
      data={items}
      isLoading={isLoading}
      columns={columns}
      renderModal={
        <Modal isOpen={isModalOpen} onClose={closeModal}>
          <ModalContent>
            <form onSubmit={handleSubmit(onSubmit)}>
              <ModalHeader>
                {selectedItem ? `Edit ${selectedItem.name}` : "Create New Tag"}
              </ModalHeader>
              <ModalBody className="gap-4">
                <Input
                  label="Name"
                  {...register("name")}
                  isInvalid={!!errors.name}
                  errorMessage={errors.name?.message}
                />
                <Input
                  label="Slug"
                  {...register("slug")}
                  isInvalid={!!errors.slug}
                  errorMessage={errors.slug?.message}
                />
                <Select
                  label="Status"
                  {...register("status")}
                  defaultSelectedKeys={[selectedItem?.status ?? "active"]}
                >
                  <SelectItem key="active" value="active">Active</SelectItem>
                  <SelectItem key="inactive" value="inactive">Inactive</SelectItem>
                </Select>
              </ModalBody>
              <ModalFooter>
                <Button variant="light" onPress={closeModal}>Cancel</Button>
                <Button color="primary" type="submit" isLoading={create.isPending || update.isPending}>
                  Save Tag
                </Button>
              </ModalFooter>
            </form>
          </ModalContent>
        </Modal>
      }
    />
  );
}
```

## Row Actions and Delete Confirmation

The `RowActions` component encapsulates the UI for editing and deleting. It utilizes HeroUI's internal Popover logic to confirm deletions without requiring a global dialog manager.

### Prop Details
- `onEdit`: Callback triggered when the edit pencil is clicked.
- `onDelete`: Callback triggered after the user confirms deletion in the popover.
- `deleteConfirmMessage`: The text displayed inside the confirmation bubble.

```typescript
/** Standard implementation within a TanStack column definition */
{
  id: "actions",
  cell: ({ row }) => (
    <RowActions
      onEdit={() => openModal(row.original)}
      onDelete={() => {
        // Typically a mutation from useAdminCrud
        remove.mutate(row.original.id);
      }}
      deleteConfirmMessage="This will permanently remove the tag from all products."
    />
  ),
}
```

## Form Logic Integration

The distinction between **Create** and **Update** modes is handled by the presence of `selectedItem` from the hook.

1.  **Creation**: Clicking the "Add" button (provided by `AdminCrudLayout`) should call `reset()` from `react-hook-form` and then `openModal()` with no arguments. This sets `selectedItem` to `null`.
2.  **Editing**: Clicking the edit action in `RowActions` calls `openModal(item)`. The hook sets `selectedItem` to that specific record.
3.  **Form Reset**: Use the `values` property in `useForm` to automatically populate the form when `selectedItem` changes.

```typescript
const { register, handleSubmit } = useForm<T>({
  resolver: zodResolver(schema),
  // React Hook Form will re-sync when selectedItem changes
  values: selectedItem || defaultValues, 
});
```
