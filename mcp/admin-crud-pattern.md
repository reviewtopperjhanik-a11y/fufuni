## Admin CRUD Pattern

The framework provides a standardized pattern for building admin CRUD pages through two core components: `AdminCrudLayout` for the UI shell and `useAdminCrud` hook for state management. Every admin page must follow this pattern—no custom implementations are allowed.

### Creating a New Admin Page

Start by creating a new route component that follows the established structure. Here's a complete example for managing product categories:

### Defining Columns and Data Flow

The column definition uses HeroUI v3's table system with TypeScript safety. Each column specifies how to render and filter data:

```typescript
// apps/client/src/routes/admin/products/columns.tsx
import { ColumnDef } from "@tanstack/react-table";
import { Product } from "@/types/api";
import { formatCurrency } from "@/utils/format";
import { RowActions } from "@/shared/ui/admin/row-actions";
import { useTranslation } from "react-i18next";

export const useProductColumns = (
  onEdit: (product: Product) => void,
  onDelete: (product: Product) => void
): ColumnDef<Product>[] => {
  const { t } = useTranslation();

  return [
    {
      accessorKey: "sku",
      header: t("admin-products-sku"),
      enableSorting: true,
    },
    {
      accessorKey: "name",
      header: t("admin-products-name"),
      cell: ({ getValue, row }) => (
        <div className="flex items-center gap-3">
          <img 
            src={row.original.thumbnail_url} 
            alt={getValue() as string}
            className="w-10 h-10 rounded-lg object-cover"
          />
          <span className="font-medium">{getValue() as string}</span>
        </div>
      ),
    },
    {
      accessorKey: "price",
      header: t("admin-products-price"),
      cell: ({ getValue }) => formatCurrency(getValue() as number),
      enableSorting: true,
    },
    {
      accessorKey: "stock_quantity",
      header: t("admin-products-stock"),
      cell: ({ getValue }) => {
        const quantity = getValue() as number;
        return (
          <span className={quantity < 10 ? "text-danger" : ""}>
            {quantity}
          </span>
        );
      },
    },
    {
      id: "actions",
      header: "",
      cell: ({ row }) => (
        <RowActions
          onEdit={() => onEdit(row.original)}
          onDelete={() => onDelete(row.original)}
          editLabel={t("admin-products-edit")}
          deleteLabel={t("admin-products-delete")}
        />
      ),
    },
  ];
};
```

### Wiring Up useAdminCrud

The hook centralizes all CRUD state management. Here's how to integrate it with API calls:

```typescript
// apps/client/src/routes/admin/users/page.tsx
import { useAdminCrud } from "@/hooks/use-admin-crud";
import { api } from "@/services/api";
import { toast } from "@/utils/toast";
import { User } from "@/types/api";

export default function AdminUsersPage() {
  const queryClient = useQueryClient();
  
  const {
    items,
    setItems,
    displayedItems,
    globalFilter,
    setGlobalFilter,
    statusFilter,
    setStatusFilter,
    isModalOpen,
    isEditMode,
    editingItem,
    openCreate,
    openEdit,
    closeModal,
  } = useAdminCrud<User>({
    filterFn: (user, term) =>
      user.email.toLowerCase().includes(term) ||
      user.first_name.toLowerCase().includes(term) ||
      user.last_name.toLowerCase().includes(term),
  });

  // Fetch users
  const { data: users } = useQuery({
    queryKey: ["admin-users"],
    queryFn: () => api.getUsers(),
  });

  useEffect(() => {
    setItems(users || []);
  }, [users, setItems]);

  // Handle create
  const handleCreate = async (data: CreateUserDto) => {
    try {
      const newUser = await api.createUser(data);
      setItems([newUser, ...items]);
      closeModal();
      toast.success(t("admin-users-created"));
    } catch (error) {
      toast.error(t("admin-users-create-error"));
    }
  };

  // Handle update
  const handleUpdate = async (data: UpdateUserDto) => {
    if (!editingItem) return;
    
    try {
      const updated = await api.updateUser(editingItem.id, data);
      setItems(items.map(u => u.id === updated.id ? updated : u));
      closeModal();
      toast.success(t("admin-users-updated"));
    } catch (error) {
      toast.error(t("admin-users-update-error"));
    }
  };

  // Handle delete
  const handleDelete = async (user: User) => {
    if (!confirm(t("admin-users-delete-confirm", { name: user.email }))) {
      return;
    }
    
    try {
      await api.deleteUser(user.id);
      setItems(items.filter(u => u.id !== user.id));
      toast.success(t("admin-users-deleted"));
    } catch (error) {
      toast.error(t("admin-users-delete-error"));
    }
  };

  const columns = useUserColumns(
    (user) => openEdit(user),
    handleDelete
  );

  return (
    <AdminCrudLayout
      title={t("admin-users-title")}
      addLabel={t("admin-users-add")}
      onAdd={openCreate}
      globalFilter={globalFilter}
      onGlobalFilterChange={setGlobalFilter}
      statusFilter={statusFilter}
      onStatusFilterChange={setStatusFilter}
    >
      <HeroUITable
        columns={columns}
        data={displayedItems}
      />
      
      <UserModal
        isOpen={isModalOpen}
        onClose={closeModal}
        isEditMode={isEditMode}
        user={editingItem}
        onSubmit={isEditMode ? handleUpdate : handleCreate}
      />
    </AdminCrudLayout>
  );
}
```

### Key Conventions

1. **No Custom CRUD Implementations**: Always use `AdminCrudLayout` + `useAdminCrud`. The pattern enforces consistency across all admin pages.

2. **Filter Function**: The `filterFn` must handle case-insensitive matching and should check all searchable fields.

3. **Status Filter**: The status dropdown automatically filters items where `item.status === selectedValue`. Items without a status property are included when "All" is selected.

4. **Modal Integration**: The modal component receives `isEditMode` and the editing item. Form submission callbacks handle API calls and state updates.

5. **Table Integration**: Use HeroUI v3's table components with the column definitions. The `displayedItems` from `useAdminCrud` already contains filtered and searched results.

6. **Loading States**: Handle loading states at the query level, not in the CRUD layout. The table component should receive an `isLoading` prop.

7. **Translations**: Use translation keys following the pattern `admin-{entity}-{action}` for consistency across admin pages.
