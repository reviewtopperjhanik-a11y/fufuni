## The ApiError Architecture

Fufuni uses a centralized error handling strategy based on the `ApiError` class located in `apps/merchant/src/types.ts`. This class extends the native JavaScript `Error` object to provide structured metadata required by the Hono middleware and the frontend React application. By throwing `ApiError` instead of generic errors, developers ensure that the API response follows a consistent JSON schema: `{ error: { code, message, details } }`.

### Static Helpers Reference

The `ApiError` class provides several static methods to simplify common HTTP failure scenarios. Using these methods ensures the correct HTTP status codes are returned to the client.

| Method | HTTP Status | Use Case |
| :--- | :--- | :--- |
| `badRequest(msg, details)` | 400 | Generic client-side error or malformed syntax. |
| `invalidRequest(msg, details)` | 400 | Validation failures (e.g., Zod schema mismatches). |
| `unauthorized(msg)` | 401 | Missing or invalid authentication credentials. |
| `forbidden(msg)` | 403 | Authenticated but lacks required permissions/roles. |
| `notFound(msg)` | 404 | The requested resource (Product, Order) does not exist. |
| `conflict(msg)` | 409 | Resource already exists (e.g., duplicate SKU). |
| `insufficientInventory(sku)` | 409 | Specific conflict error for stock management. |
| `stripeError(msg)` | 502 | Upstream failure when communicating with Stripe API. |
| `internalServerError(msg)`| 500 | Unhandled exceptions or server-side logic crashes. |

## Backend Error Conversion

Fufuni's Hono application is configured with a global `onError` handler. This handler intercepts any thrown `ApiError` and transforms it into a standard JSON response. If an error is thrown that is *not* an instance of `ApiError`, the handler wraps it in an `internal_server_error` wrapper to prevent leaking sensitive stack traces in production.

### Global Error Handler Logic

In the main application entry point (e.g., `apps/merchant/src/index.ts`), the handler typically follows this pattern:

```typescript
import { Hono } from 'hono';
import { ApiError, HonoEnv } from './types';

const app = new Hono<HonoEnv>();

app.onError((err, c) => {
  if (err instanceof ApiError) {
    return c.json(
      {
        error: {
          code: err.code,
          message: err.message,
          details: err.details,
        },
      },
      err.statusCode as any
    );
  }

  // Fallback for unhandled native Errors
  console.error(`[Unhandled Error]: ${err.message}`, err.stack);
  return c.json(
    {
      error: {
        code: 'internal_server_error',
        message: 'An unexpected error occurred',
      },
    },
    500
  );
});
```

Used when a specific ID or slug does not correspond to a record in the Durable Object SQLite database.


### Validation and Conflicts (invalidRequest/conflict)
Use `invalidRequest` for payload errors and `conflict` for state-related collisions (like a non-unique SKU).

```typescript
app.post('/v1/products', async (c) => {
  const body = await c.req.json();
  
  if (!body.sku) {
    throw ApiError.invalidRequest('SKU is required', { field: 'sku' });
  }

  const [existing] = await c.var.db.query(
    'SELECT id FROM products WHERE sku = ?', 
    [body.sku]
  );
  
  if (existing) {
    throw ApiError.conflict(`SKU "${body.sku}" is already assigned to another product`);
  }
  
  // logic...
});
```

## Frontend Error Handling

In the React 19 frontend, requests are typically made via the `useSecuredApi()` hook. This hook returns a fetcher that automatically includes the Auth0 bearer token and handles base URL configuration. When the backend returns a non-2xx status code, the fetcher (or the underlying helper) throws an error that includes the structured `ApiError` JSON body.

### Catching API Errors with HeroUI

When performing mutations (like saving a product), use `try/catch` blocks paired with HeroUI's `addToast` (or notification system) to display the `message` from the error.

```typescriptok
import React, { useState } from 'react';
import { Button, Input, addToast } from '@heroui/react';
import { useSecuredApi } from '@/hooks/useSecuredApi';

export const ProductCreateForm = () => {
  const [sku, setSku] = useState('');
  const [isLoading, setIsLoading] = useState(false);
  const api = useSecuredApi();

  const handleCreate = async () => {
    setIsLoading(true);
    try {
      const response = await api.post('/v1/products', { sku });
      addToast({
        title: "Success",
        description: "Product created successfully",
        color: "success"
      });
    } catch (err: any) {
      // API errors usually nested under err.response.data.error 
      // or err.error depending on fetcher implementation.
      const apiErrorMessage = err.error?.message || err.message || "Unknown error";
      const apiErrorCode = err.error?.code;

      addToast({
        title: `Error: ${apiErrorCode}`,
        description: apiErrorMessage,
        color: "danger"
      });

      if (apiErrorCode === 'invalid_request' && err.error?.details?.field === 'sku') {
        // Handle field-specific highlighting logic
        console.error("SKU field error detected");
      }
    } finally {
      setIsLoading(false);
    }
  };

  return (
    <div className="flex flex-col gap-4">
      <Input 
        label="Product SKU" 
        value={sku} 
        onChange={(e) => setSku(e.target.value)} 
      />
      <Button 
        isLoading={isLoading} 
        onPress={handleCreate}
        color="primary"
      >
        Create Product
      </Button>
    </div>
  );
};
```
