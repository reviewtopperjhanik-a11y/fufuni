## ApiError Class Reference

In the Fufuni framework, error handling is standardized through the `ApiError` class. Instead of returning manual JSON responses with error statuses, developers throw instances of `ApiError`. This ensures that the frontend receives a consistent error envelope and that the backend logic remains clean and declarative.

### Static Helper Methods

The following table summarizes the available static helpers within the `ApiError` class located in `apps/merchant/src/types.ts`.

| Method | HTTP Status | Code | Typical Use Case |
| :--- | :--- | :--- | :--- |
| `unauthorized(msg?)` | 401 | `unauthorized` | Missing or invalid Auth0 token / API key. |
| `forbidden(msg?)` | 403 | `forbidden` | Authenticated user lacks required permissions (e.g., `admin:store`). |
| `notFound(msg?)` | 404 | `not_found` | Resource (Product, Order, Category) does not exist in SQLite. |
| `invalidRequest(msg, details?)` | 400 | `invalid_request` | Validation failed or business logic constraint violated. |
| `badRequest(msg, details?)` | 400 | `bad_request` | Generic client-side error, often used for malformed syntax. |
| `conflict(msg)` | 409 | `conflict` | Resource already exists or state conflict (e.g., duplicate SKU). |
| `insufficientInventory(sku)` | 409 | `insufficient_inventory` | Attempting to purchase more items than available in stock. |
| `stripeError(msg)` | 502 | `stripe_error` | External call to Stripe API failed or returned an error. |
| `internalServerError(msg?)` | 500 | `internal_server_error` | Unexpected server-side crashes or unhandled exceptions. |

## Backend Implementation and Hono Integration

Fufuni uses a central Hono error handler. When any route handler or middleware throws an `ApiError`, Hono catches it and uses the `statusCode` property to set the HTTP response header.

### Global Error Handler Logic

While the framework handles this internally, understanding the transformation is vital. The handler checks if the caught error is an instance of `ApiError`. If it is not (e.g., a native JS `TypeError`), it wraps it in an `internalServerError` to prevent leaking sensitive stack traces to the client.

```typescript
// Example of the conceptual logic inside Fufuni's app setup
app.onError((err, c) => {
  if (err instanceof ApiError) {
    return c.json(
      {
        error: {
          code: err.code,
          message: err.message,
          details: err.details,
        },
      },
      err.statusCode as any
    );
  }

  // Fallback for unknown errors
  console.error(err);
  return c.json(
    {
      error: {
        code: 'internal_server_error',
        message: 'An unexpected error occurred',
      },
    },
    500
  );
});
```

### Practical Route Examples

Below is a Hono router demonstrating the usage of various `ApiError` helpers within a Merchant Durable Object context.

```typescript
import { Hono } from 'hono';
import { ApiError, type HonoEnv } from '../types';

const productRouter = new Hono<HonoEnv>();

productRouter.get('/:id', async (c) => {
  const { id } = c.req.param();
  const db = c.get('db');

  const products = await db.query('SELECT * FROM products WHERE id = ?', [id]);
  
  if (products.length === 0) {
    // 1. Not Found Example
    throw ApiError.notFound(`Product with ID ${id} not found`);
  }

  return c.json(products[0]);
});

productRouter.post('/:id/purchase', async (c) => {
  const auth = c.get('auth');
  const { id } = c.req.param();
  const { quantity } = await c.req.json();

  // 2. Unauthorized Example (usually handled by middleware, but can be manual)
  if (!auth.sub) {
    throw ApiError.unauthorized('You must be logged in to purchase');
  }

  // 3. Forbidden Example
  if (auth.role === 'public') {
     throw ApiError.forbidden('Public users cannot perform direct purchases');
  }

  const [product] = await c.get('db').query<{sku: string, stock: number}>(
    'SELECT sku, stock FROM products WHERE id = ?', 
    [id]
  );

  // 4. Insufficient Inventory Example
  if (product.stock < quantity) {
    throw ApiError.insufficientInventory(product.sku);
  }

  // 5. Conflict Example
  const existingOrder = await c.get('db').query(
    'SELECT id FROM orders WHERE product_id = ? AND status = "pending"', 
    [id]
  );
  if (existingOrder.length > 0) {
    throw ApiError.conflict('You already have a pending order for this item');
  }

  return c.json({ success: true });
});
```

## Custom and Validation Errors

Sometimes standard helpers do not cover specific business constraints. You can instantiate `ApiError` directly or provide a `details` object to `invalidRequest` to assist the frontend in rendering field-specific error messages.

### Custom Error Messages

```typescript
import { ApiError } from '../types';

/**
 * Example: Custom validation for a complex configuration object
 */
function validateAisettings(settings: any) {
  if (!settings.apiKey && settings.enabled) {
    // Direct instantiation for specific status codes
    throw new ApiError(
      'missing_configuration',
      422, // Unprocessable Entity
      'AI features enabled but API key is missing',
      { field: 'apiKey', provider: settings.provider }
    );
  }

  if (settings.temperature > 2 || settings.temperature < 0) {
    // Using invalidRequest with details for form binding
    throw ApiError.invalidRequest('Temperature must be between 0 and 2', {
      field: 'temperature',
      value: settings.temperature
    });
  }
}
```

## Frontend: Handling Errors in React 19

The Fufuni frontend uses a custom hook `useSecuredApi()` which wraps the standard `fetch` API. It automatically handles Auth0 token injection and response parsing. When a non-2xx response is received, it parses the JSON and throws a client-side error object containing the `ApiError` structure.

### Using useSecuredApi with Error Handling

In Fufuni components, wrap your API calls in `try/catch` blocks or use the error state from React Query.

```tsx
import React, { useState } from 'react';
import { useSecuredApi } from '../../hooks/useSecuredApi';
import { Button, Input, Alert } from '@heroui/react';

export const ProductStockManager = ({ productId }: { productId: string }) => {
  const api = useSecuredApi();
  const [loading, setLoading] = useState(false);
  const [errorMsg, setErrorMsg] = useState<string | null>(null);
  const [fieldErrors, setFieldErrors] = useState<Record<string, string>>({});

  const handleUpdateStock = async (newStock: number) => {
    setLoading(true);
    setErrorMsg(null);
    setFieldErrors({});

    try {
      await api.post(`/api/products/${productId}/stock`, { stock: newStock });
      alert('Stock updated successfully');
    } catch (err: any) {
      // err usually contains the parsed JSON body: { error: { code, message, details } }
      const apiError = err.error;

      if (apiError?.code === 'insufficient_inventory') {
        setErrorMsg(`Critical: Stock cannot be negative for SKU ${apiError.details?.sku}`);
      } else if (apiError?.code === 'invalid_request' && apiError.details?.field) {
        setFieldErrors({ [apiError.details.field]: apiError.message });
      } else {
        setErrorMsg(apiError?.message || 'An unexpected error occurred');
      }
    } finally {
      setLoading(false);
    }
  };

  return (
    <div className="flex flex-col gap-4 p-4">
      {errorMsg && (
        <Alert color="danger" title="Error">
          {errorMsg}
        </Alert>
      )}
      
      <Input
        label="New Stock Quantity"
        type="number"
        isInvalid={!!fieldErrors.stock}
        errorMessage={fieldErrors.stock}
        onChange={(e) => handleUpdateStock(Number(e.target.value))}
      />

      <Button 
        isLoading={loading} 
        onPress={() => handleUpdateStock(10)}
        color="primary"
      >
        Reset to 10 Units
      </Button>
    </div>
  );
};
```

### Standardizing External Errors (Stripe)

When interacting with external services like Stripe, use the `ApiError.stripeError()` helper. This signals to the frontend that the issue is not with Fufuni's logic or database, but with the payment processor, allowing for specific UI instructions (e.g., "Please check your card details with your bank").

```typescript
// Inside a Hono route in apps/merchant/src/index.ts
try {
  const paymentIntent = await stripe.paymentIntents.create({
    amount: total,
    currency: 'usd',
  });
  return c.json({ clientSecret: paymentIntent.client_secret });
} catch (e: any) {
  // Wrap Stripe's error message into our standard ApiError
  throw ApiError.stripeError(e.message || 'Payment gateway communication failure');
}
```

By strictly adhering to the `ApiError` class, developers ensure that the merchant dashboard and storefront remain resilient and provide helpful feedback to users, even when operations fail.
