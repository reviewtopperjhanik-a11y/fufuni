## API Error Handling Reference

### 1. ApiError Static Helpers

| Method | HTTP Status | Use Case |
|--------|------------|----------|
| `unauthorized()` | 401 | Missing or invalid credentials |
| `forbidden()` | 403 | Valid credentials but insufficient permissions |
| `notFound()` | 404 | Resource does not exist |
| `conflict()` | 409 | Resource already exists (duplicate SKU, email) |
| `invalidRequest()` | 400 | Validation errors, missing required fields |
| `insufficientInventory()` | 409 | Stock too low to complete order |
| `internalServerError()` | 500 | Unexpected server failure |

### 2. Hono Error Conversion

Thrown `ApiError` instances are automatically converted to JSON responses by the global error handler:

```typescript
// Backend route handler
throw ApiError.notFound('Product 123 not found');

// Frontend receives
{
  "error": {
    "code": "not_found",
    "message": "Product 123 not found",
    "details": {}
  }
}
```

### 3. Common Error Examples

```typescript
// 404 Not Found
throw ApiError.notFound('Product not found');

// 401 Unauthorized
throw ApiError.unauthorized('Invalid API key');

// 403 Forbidden
throw ApiError.forbidden('Admin permission required');

// 409 Conflict
throw ApiError.conflict('SKU already exists');

// 400 Bad Request
throw ApiError.invalidRequest('SKU is required', { field: 'sku' });

// 409 Insufficient Inventory
throw ApiError.insufficientInventory('Only 2 units left', { available: 2 });

// 500 Internal Server Error
throw ApiError.internalServerError('Database connection failed');
```

### 4. Custom Error Messages

```typescript
// Simple custom message
throw ApiError.notFound(`Product ${sku} not found`);

// With details for debugging
throw ApiError.invalidRequest('Invalid email format', {
  field: 'email',
  value: 'user@invalid',
  pattern: '^[\\w\\.-]+@[\\w\\.-]+\\.\\w+$'
});

// Dynamic status based on condition
const status = stock < quantity ? 'insufficient' : 'available';
throw ApiError.conflict(`Product ${sku} is ${status}`, { sku, stock, quantity });
```

### 5. Frontend Error Handling

```typescript
import { useSecuredApi } from '@/hooks/useSecuredApi';

function ProductEdit() {
  const api = useSecuredApi();

  const handleSave = async () => {
    try {
      await api.put(`/api/products/${sku}`, { name, price });
    } catch (error: any) {
      // error.response.data contains the API error
      const apiError = error.response?.data?.error;
      
      switch (apiError?.code) {
        case 'not_found':
          toast.error('Product not found');
          navigate('/products');
          break;
          
        case 'conflict':
          toast.error('SKU already exists');
          setFieldError('sku', 'This SKU is already taken');
          break;
          
        case 'invalid_request':
          // Display field-specific errors
          Object.entries(apiError.details).forEach(([field, message]) => {
            setFieldError(field, String(message));
          });
          break;
          
        default:
          toast.error(apiError?.message || 'Save failed');
      }
    }
  };
}
```
