## Introduction to Database Migrations
To manage schema changes in the Fufuni e-commerce framework, we use database migrations. A migration is a set of changes to the database schema, applied in a specific order to ensure data consistency.

## When to Use a Migration
Use a migration when you need to make changes to the database schema, such as adding or removing tables, columns, or indexes. This approach ensures that all schema changes are tracked, versioned, and applied in a predictable order.

Do not edit the `SCHEMA` constant directly, unless you are making a minor change that does not affect the overall database structure. Instead, create a new migration to ensure that the change is properly tracked and applied.

## Steps to Add a Database Migration
To add a database migration, follow these steps:

1. **Create the SQL file**: In the `apps/merchant/migrations/` directory, create a new SQL file with the correct numbering convention (e.g., `034-add-tags.sql`). The file name should match the migration record name stored in the `migrations` table.
2. **Add the migration block**: In the `ensureInitialized()` function inside `do.ts`, add a migration block using the following template:
   ```typescript
// Migration 034: Add tags table
this.sql.exec(`
  -- DDL statement here
`);
const migrationName = '034-add-tags';
if (!(await this.getMigration(migrationName))) {
  this.sql.exec(`INSERT INTO migrations (name) VALUES ('${migrationName}')`);
}
```
   Replace the `-- DDL statement here` comment with the actual DDL statement for your migration.

3. **Add the full DDL to the SCHEMA constant**: In the `SCHEMA` constant in `do.ts`, add the full DDL statement for your migration, including the `CREATE TABLE IF NOT EXISTS` statement.

CREATE TABLE IF NOT EXISTS tags (
  id          TEXT PRIMARY KEY,
  name        TEXT NOT NULL,
  description TEXT,
  status      TEXT NOT NULL DEFAULT 'active' CHECK (status IN ('active', 'inactive')),
  created_at  TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at  TEXT NOT NULL DEFAULT (datetime('now'))

CREATE INDEX IF NOT EXISTS idx_tags_name

AFTER UPDATE ON tags
FOR EACH ROW
BEGIN
  UPDATE tags SET updated_at = datetime('now') WHERE id = NEW.id;
END;

## Common Pitfalls
When creating database migrations, be aware of the following common pitfalls:

* Use `IF NOT EXISTS` on `CREATE TABLE` and `CREATE INDEX` statements to make migrations idempotent.
* Ensure that the migration record name stored in the `migrations` table matches the SQL file stem exactly.
* Use the correct column types, such as `TEXT` for UUIDs and ISO dates, `INTEGER` for booleans and cents, and `REAL` for percentages and ratings.
* Never retroactively modify a migration that has already been deployed to production. Instead, create a new migration to apply the changes.
