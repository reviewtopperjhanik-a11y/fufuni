## How to Add a Database Migration
When to use a migration: whenever you need to make a schema change to the database, such as adding a new table, column, or index. This is in contrast to editing the `SCHEMA` constant directly, which should only be done for initial setup or when backporting changes from a migration.

## Common Pitfalls
* Always use `IF NOT EXISTS` on `CREATE TABLE` and `CREATE INDEX` to make migrations idempotent.
* Ensure that the migration record name stored in the `migrations` table matches the SQL file stem exactly.
* Column types: use `TEXT` for UUIDs and ISO dates, `INTEGER` for booleans (0/1) and cents, and `REAL` for percentages and ratings.
* Never retroactively modify a migration that has already been deployed to production — always create a new migration instead.
* Migration files are named `NNN-description.sql` where `NNN` is a zero-padded 3-digit integer.
* The `ensureInitialized()` function is synchronous, so use `this.sql.exec()` directly instead of `db.run()`.
