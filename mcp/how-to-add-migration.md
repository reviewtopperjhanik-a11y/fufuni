## The Triple-Update Requirement

In the Fufuni framework, the Durable Object (DO) serves as the source of truth for merchant data, utilizing SQLite-based `ctx.storage.sql`. Unlike traditional environments where you might run a CLI migration tool once, Fufuni requires a "Triple-Update" approach to ensure schema consistency for both brand-new merchant instances and existing production instances.

Every schema change must be implemented in three specific locations:

1.  **The `SCHEMA` Constant (`apps/merchant/src/do.ts`):** This is the full DDL used to initialize a brand-new Durable Object from scratch. It ensures that any new merchant created after your change has the latest schema immediately.
2.  **The `ensureInitialized()` Migration Block (`apps/merchant/src/do.ts`):** This is the imperative logic that migrates existing Durable Objects. It checks the `migrations` table and applies only the delta (the new SQL) if it hasn't been run before.
3.  **The Numbered Migration File (`apps/merchant/migrations/NNN-description.sql`):** These files provide a historical record and forward-compatibility for external tooling (like Cloudflare D1 or local development scripts).

## Step-by-Step Migration Process

Follow these steps exactly to ensure your database changes are safely deployed and documented.

### 1. Create the SQL Migration File
Identify the next available migration number by checking the `apps/merchant/migrations/` directory. If the last file is `033-...`, your new file must be `034-...`.

```sql
-- apps/merchant/migrations/034-product-tags.sql
-- Migration 034: Adds support for product tagging and filtering.

PRAGMA foreign_keys = ON;

CREATE TABLE IF NOT EXISTS product_tags (
  id          TEXT PRIMARY KEY,
  name        TEXT NOT NULL,
  slug        TEXT NOT NULL UNIQUE,
  color_hex   TEXT DEFAULT '#3B82F6',
  created_at  TEXT NOT NULL DEFAULT (datetime('now'))
);

CREATE TABLE IF NOT EXISTS product_tag_assignments (
  product_id  TEXT NOT NULL REFERENCES products(id) ON DELETE CASCADE,
  tag_id      TEXT NOT NULL REFERENCES product_tags(id) ON DELETE CASCADE,
  PRIMARY KEY (product_id, tag_id)
);

CREATE INDEX IF NOT EXISTS idx_tag_assignments_tag ON product_tag_assignments(tag_id);
CREATE INDEX IF NOT EXISTS idx_product_tags_slug ON product_tags(slug);
```

### 2. Update the SCHEMA Constant
Append the DDL from your migration file to the `SCHEMA` constant in `apps/merchant/src/do.ts`. This ensures that when a new merchant DO is instantiated, it skips the migration loop and builds the table immediately.

```typescript
// apps/merchant/src/do.ts

const SCHEMA = `
-- ... existing tables ...

-- ============================================================
-- PRODUCT TAGS (migration 034)
-- ============================================================

CREATE TABLE IF NOT EXISTS product_tags (
  id          TEXT PRIMARY KEY,
  name        TEXT NOT NULL,
  slug        TEXT NOT NULL UNIQUE,
  color_hex   TEXT DEFAULT '#3B82F6',
  created_at  TEXT NOT NULL DEFAULT (datetime('now'))
);

CREATE TABLE IF NOT EXISTS product_tag_assignments (
  product_id  TEXT NOT NULL REFERENCES products(id) ON DELETE CASCADE,
  tag_id      TEXT NOT NULL REFERENCES product_tags(id) ON DELETE CASCADE,
  PRIMARY KEY (product_id, tag_id)
);

CREATE INDEX IF NOT EXISTS idx_tag_assignments_tag ON product_tag_assignments(tag_id);
CREATE INDEX IF NOT EXISTS idx_product_tags_slug ON product_tags(slug);
`;
```

### 3. Add to ensureInitialized() Migration Loop
Locate the `migrations` array inside the `ensureInitialized()` method of the `MerchantDO` class. Append a new object containing the migration name (which must match the file stem) and the SQL to execute.

```typescript
// apps/merchant/src/do.ts

private ensureInitialized(): void {
  if (this.initialized) return;
  // ... initial SCHEMA execution ...

  const migrations: Array<{ name: string; sql: string }> = [
    // ... existing migrations ...
    {
      name: '034-product-tags', // Must match apps/merchant/migrations/034-product-tags.sql
      sql: `
        CREATE TABLE IF NOT EXISTS product_tags (
          id          TEXT PRIMARY KEY,
          name        TEXT NOT NULL,
          slug        TEXT NOT NULL UNIQUE,
          color_hex   TEXT DEFAULT '#3B82F6',
          created_at  TEXT NOT NULL DEFAULT (datetime('now'))
        );
        CREATE TABLE IF NOT EXISTS product_tag_assignments (
          product_id  TEXT NOT NULL REFERENCES products(id) ON DELETE CASCADE,
          tag_id      TEXT NOT NULL REFERENCES product_tags(id) ON DELETE CASCADE,
          PRIMARY KEY (product_id, tag_id)
        );
        CREATE INDEX IF NOT EXISTS idx_tag_assignments_tag ON product_tag_assignments(tag_id);
        CREATE INDEX IF NOT EXISTS idx_product_tags_slug ON product_tags(slug);
      `,
    },
  ];

  for (const migration of migrations) {
    if (!appliedMigrations.has(migration.name)) {
      try {
        this.sql.exec(migration.sql);
        this.sql.exec('INSERT INTO migrations (name) VALUES (?)', migration.name);
      } catch (e) {
        // Fallback for idempotent retry
        try {
          this.sql.exec('INSERT INTO migrations (name) VALUES (?)', migration.name);
        } catch {}
      }
    }
  }
  this.initialized = true;
}
```

## SQLite Data Type Conventions

Fufuni uses standard SQLite types with specific conventions to maintain consistency across the API (Hono) and the Frontend (React/HeroUI).

| Logical Type | SQLite Type | Notes |
| :--- | :--- | :--- |
| **UUIDs / IDs** | `TEXT` | Use `crypto.randomUUID()` in TypeScript. |
| **Booleans** | `INTEGER` | Use `0` for false and `1` for true. |
| **Currency / Cents** | `INTEGER` | Always store money as integers (cents) to avoid floating-point errors. |
| **Dates / Timestamps**| `TEXT` | Store as ISO-8601 strings. Use `(datetime('now'))` for defaults. |
| **Decimals / Rates** | `REAL` | Use for percentages (e.g., `20.0`) or ratings (e.g., `4.5`). |
| **JSON** | `TEXT` | Use for complex objects (e.g., `taxes_json`). Parse with `JSON.parse` in TS. |

### Example: Adding a Column to an Existing Table
Adding a column requires using `ALTER TABLE`. Note that SQLite has limitations on `ALTER TABLE` (e.g., you cannot add a `UNIQUE` constraint or a `NOT NULL` constraint without a default value in a single step).

```sql
-- apps/merchant/migrations/035-add-internal-note-to-orders.sql
ALTER TABLE orders ADD COLUMN internal_note TEXT;
```

In `ensureInitialized()`:
```typescript
{
  name: '035-add-internal-note-to-orders',
  sql: 'ALTER TABLE orders ADD COLUMN internal_note TEXT',
}
```

## Idempotency and Safety Rules

### Use IF NOT EXISTS
Always use `CREATE TABLE IF NOT EXISTS` and `CREATE INDEX IF NOT EXISTS`. If a migration fails halfway through or is accidentally re-run, these keywords prevent the DO from crashing.

### DO SQL is Synchronous
Unlike the Cloudflare D1 `db.prepare().run()` which is asynchronous, the `ctx.storage.sql` interface in Durable Objects is **synchronous**. Do not use `await` when calling `this.sql.exec()`.

### The Migration Name Link
The `name` property in the `migrations` array inside `do.ts` must match the file stem in the `migrations/` folder. This is critical for developers using CLI tools to audit the database state.

### Never Modify Existing Migrations
If a migration has been merged into the `main` branch or deployed to production, it is immutable. If you made a mistake (e.g., wrong column name), do not edit the old migration file. Instead, create a new numbered migration (e.g., `036-fix-column-name.sql`) to correct it.

## Verification Checklist

Before submitting a PR with a new migration, verify the following:

- [ ] Does the new file in `apps/merchant/migrations/` follow the `NNN-description.sql` naming?
- [ ] Is the `SCHEMA` constant updated with the full table definition?
- [ ] Is the migration block added to `ensureInitialized()`?
- [ ] Does the migration block record its success in the `migrations` table?
- [ ] Are you using `INTEGER` for money/booleans and `TEXT` for IDs/dates?
- [ ] Did you include `IF NOT EXISTS` for all new tables and indexes?
- [ ] If using `ALTER TABLE`, have you tested it against a local DO instance?
