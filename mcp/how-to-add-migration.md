## How to Add a Database Migration

### When to Use a Migration

Use a migration when making changes to the database schema. This approach allows for:

* Version control of schema changes
* Safe rollbacks in case of issues
* Forward compatibility with existing data

Avoid editing the `SCHEMA` constant directly, as this bypasses the migration system.

### Exact Numbered Steps

#### Step 1: Create the SQL File

Create a new SQL file in `apps/merchant/migrations/` with a zero-padded 3-digit integer prefix (e.g., `034-add-tags.sql`). The file name should describe the changes made.

```sql

-- Migration 034: Add tags table
CREATE TABLE IF NOT EXISTS tags (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL UNIQUE,
  description TEXT,
  created_at TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at TEXT NOT NULL DEFAULT (datetime('now'))
);

CREATE INDEX IF NOT EXISTS idx_tags_name ON tags (name);
```

### Common Pitfalls

* **IF NOT EXISTS**: Always use `IF NOT EXISTS` on `CREATE TABLE` and `CREATE INDEX` to make migrations idempotent.
* **Idempotency**: Ensure that applying a migration multiple times has the same effect as applying it once.
* **Column types**: Use `TEXT` for UUIDs and ISO dates, `INTEGER` for booleans (0/1) and cents, `REAL` for percentages and ratings.
* **Migration name**: The migration record name stored in the `migrations` table must match the SQL file stem exactly.
