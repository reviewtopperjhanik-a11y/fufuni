## How to Add a Database Migration
When making changes to the database schema, it's essential to use a migration instead of editing the `SCHEMA` constant directly. This approach ensures that the schema changes are applied consistently across all environments and can be easily rolled back if needed.

Use a migration when:
- You need to add or modify tables, indexes, or relationships between tables.
- You want to ensure that schema changes are applied idempotently, meaning that running the same migration multiple times will have the same effect as running it once.

Here are the exact numbered steps to create a migration:

1. **Create the SQL file**: Create a new SQL file in the `apps/merchant/migrations/` directory with the correct numbering convention (e.g., `034-add-tags.sql`). The file name should match the migration record name stored in the `migrations` table.
2. **Add the migration block**: In the `do.ts` file, add a migration block in the `ensureInitialized()` function using the following template:
    ```typescript
// Add this block to the ensureInitialized() function
if (!migrationsApplied.includes('034-add-tags')) {
  // Apply the migration
  this.sql.exec(`
    -- Your migration SQL here
  `);
  // Record the migration as applied
  this.sql.exec('INSERT INTO migrations (name) VALUES ("034-add-tags")');
  migrationsApplied.push('034-add-tags');
}
```
    Replace the comment with your actual migration SQL.
3. **Add the full DDL to the SCHEMA constant**: In the `do.ts` file, add the full DDL (Data Definition Language) for your migration to the `SCHEMA` constant.

## Common Pitfalls

* Always use `IF NOT EXISTS` on `CREATE TABLE` and `CREATE INDEX` to make migrations idempotent.
* Ensure that the migration record name stored in the `migrations` table matches the SQL file stem exactly.
* Use the correct column types:
	+ `TEXT` for UUIDs and ISO dates.
	+ `INTEGER` for booleans (0/1) and cents.
	+ `REAL` for percentages and ratings.
* Never retroactively modify a migration that has already been deployed to production. Instead, create a new migration to make the necessary changes.
