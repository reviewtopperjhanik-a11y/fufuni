## Database Migration Lifecycle

In the Fufuni framework, database migrations follow a dual-track system. While SQL files are stored in `apps/merchant/migrations/` for version control and developer reference, the **single source of truth** is the `ensureInitialized` method within the `MerchantDO` class in `do.ts`. 

When the Durable Object wakes up, it executes the schema definitions and migration blocks against its internal SQLite database. This ensures that every merchant instance is automatically up-to-date without requiring external orchestration.

### Implementation Pattern for New Migrations

When adding a new feature that requires a schema change, you must:
1.  Create a reference `.sql` file in `apps/merchant/migrations/` (e.g., `035-add-loyalty-points.sql`).
2.  Add the logic to `ensureInitialized()` in `do.ts` using `IF NOT EXISTS` or `try-catch` blocks for `ALTER TABLE` statements.

```typescript
// apps/merchant/src/do.ts example of adding a migration
async ensureInitialized() {
  const sql = this.ctx.storage.sql;
  
  // 1. Initial Schema (Baseline)
  sql.exec(SCHEMA);

  // 2. Incremental Migrations
  // Migration 034: Enrich refunds
  try {
    sql.exec(`ALTER TABLE refunds ADD COLUMN currency TEXT NOT NULL DEFAULT 'EUR'`);
    sql.exec(`ALTER TABLE refunds ADD COLUMN reason TEXT`);
    sql.exec(`CREATE INDEX IF NOT EXISTS idx_refunds_order_id_created ON refunds(order_id, created_at DESC)`);
  } catch (e) {
    // Column might already exist if migration previously ran
  }

  // Migration 035: Loyalty (Example)
  sql.exec(`
    CREATE TABLE IF NOT EXISTS loyalty_points (
      id TEXT PRIMARY KEY,
      customer_id TEXT NOT NULL REFERENCES customers(id),
      points INTEGER NOT NULL DEFAULT 0,
      updated_at TEXT DEFAULT (datetime('now'))
    )
  `);
}
```

### Functional Example: Querying Regional Pricing
Since prices can vary by region (currency), querying a product requires joining the `variant_prices` table based on the user's active currency.

```typescript
// Example: Fetching variants with regional pricing
const currencyCode = 'EUR';
const productId = 'prod_123';

const query = `
  SELECT 
    v.*, 
    COALESCE(vp.price_cents, v.price_cents) as active_price,
    c.symbol as currency_symbol
  FROM variants v
  LEFT JOIN variant_prices vp ON v.id = vp.variant_id
  LEFT JOIN currencies c ON vp.currency_id = c.id
  WHERE v.product_id = ? AND (c.code = ? OR c.code IS NULL)
  ORDER BY v.position ASC
`;

const variants = this.ctx.storage.sql.exec(query, productId, currencyCode).toArray();
```

  // We store the SHA-256 hash of the token
  const order = this.ctx.storage.sql.exec(
    `SELECT * FROM orders WHERE viewtoken = ? LIMIT 1`,
    tokenHash
  ).one();

  if (!order) throw new Error("Order not found");
  return order;

const availableRates = this.ctx.storage.sql.exec(`

  FROM shipping_rates sr

### Table Column Detail Specification (SQLite Types)

Fufuni uses standard SQLite types with the following conventions:
- **`id`**: `TEXT PRIMARY KEY` (UUID or nanoid).
- **`created_at`/`updated_at`**: `TEXT` storing ISO strings, default `(datetime('now'))`.
- **`cents`**: Always `INTEGER` to avoid floating point errors in currency.
- **`JSON`**: Stored as `TEXT`.
- **`BOOLEAN`**: Stored as `INTEGER` (0 or 1).

### Indexing Standards
Every foreign key and frequently filtered column (like `handle`, `sku`, or `status`) must have an index. Use the naming convention `idx_[table]_[column]`.

```sql
-- Example of standard performance indexing
CREATE INDEX IF NOT EXISTS idx_variants_product_id ON variants(product_id);
CREATE INDEX IF NOT EXISTS idx_orders_customer_id ON orders(customer_id);
CREATE INDEX IF NOT EXISTS idx_products_handle ON products(handle);
```
