## The Fufuni Migration Architecture

The Fufuni framework uses a "Code-First Migration" approach within its Durable Objects. While the `apps/merchant/migrations/` directory contains `.sql` files for D1 reference and local development, the **Durable Object (DO) is the source of truth**. When a Merchant DO starts up, the `ensureInitialized()` method executes the base `SCHEMA` and then sequentially runs logic-wrapped migrations.

This ensures that every merchant instance, regardless of when it was created, eventually converges to the same schema version. If you add a new column, you must add it to the `SCHEMA` constant (for new DOs) **and** create an entry in the `migrations` array inside `ensureInitialized` (for existing DOs).

### Adding a New Migration to do.ts

To add a column or table, follow this pattern within the `ensureInitialized` function. Note that SQLite's `ALTER TABLE` is limited; you cannot add `UNIQUE` constraints or `CHECK` constraints to existing tables without recreating them.

```typescript
// Inside MerchantDO.ensureInitialized()
const migrations: Array<{ name: string; sql: string }> = [
  // ... existing migrations
  {
    name: '035_add_product_subtitle',
    sql: 'ALTER TABLE products ADD COLUMN subtitle TEXT',
  },
  {
    name: '036_new_settings_table',
    sql: `
      CREATE TABLE IF NOT EXISTS merchant_settings (
        key TEXT PRIMARY KEY,
        value TEXT NOT NULL,
        updated_at TEXT DEFAULT (datetime('now'))
      )
    `,
  }
];

for (const migration of migrations) {
  if (!appliedMigrations.has(migration.name)) {
    try {
      this.sql.exec(migration.sql);
      this.sql.exec('INSERT INTO migrations (name) VALUES (?)', migration.name);
    } catch (e) {
      // Mark as applied even on error to prevent infinite loops 
      // if the column already exists (common in edge environments)
      this.sql.exec('INSERT OR IGNORE INTO migrations (name) VALUES (?)', migration.name);
    }
  }
}
```

## Catalog Domain

These tables manage the product lifecycle, including physical attributes, SEO handles, and hierarchical categorization.

### products
Primary table for high-level product data.
- **Migration Source**: `SCHEMA`, 018, 019, 028
- **Columns**:
  - `id` (TEXT, PK): UUID.
  - `title` (TEXT): Required.
  - `description` (TEXT): Default empty string.
  - `image_url` (TEXT, Nullable): Main product image.
  - `shipping_class_id` (TEXT, Nullable): Links to `shipping_classes`.
  - `vendor` (TEXT, Nullable): Brand/Manufacturer name.
  - `tags` (TEXT, Nullable): JSON array of keywords.
  - `handle` (TEXT, Unique): SEO-friendly slug.
  - `status` (TEXT): 'active' or 'draft'.
  - `review_count` (INTEGER): Cached count for performance.
  - `average_rating` (REAL): Cached aggregate.
  - `created_at` (TEXT): Default now().

### variants
Specific SKUs under a product (e.g., Size, Color).
- **Migration Source**: `SCHEMA`, 018, 019, 029
- **Columns**:
  - `id` (TEXT, PK): UUID.
  - `product_id` (TEXT, FK): Reference to `products.id`.
  - `sku` (TEXT, Unique): Merchant identifier.
  - `price_cents` (INTEGER): Price in smallest currency unit.
  - `weight_g` (INTEGER): Weight in grams.
  - `requires_shipping` (INTEGER): 0 or 1.
  - `barcode` (TEXT, Nullable): GTIN/UPC.
  - `tax_code` (TEXT, Nullable): Stripe Tax code.
  - `thumbnail_url` (TEXT, Nullable): Small WebP variant (Mig 029).

### categories & product_categories
- **Migration Source**: 027, 031
- **Columns (categories)**: `id`, `handle`, `name`, `description`, `parent_id`, `image_url`, `thumbnail_url`, `position`, `status`.
- **Columns (product_categories)**: `product_id`, `category_id`, `position`.

### Catalog Relationship Query Example
```sql
-- Fetch products in a specific category with their primary variant price
SELECT 
  p.title, 
  p.handle, 
  v.price_cents, 
  c.name as category_name
FROM products p
JOIN product_categories pc ON p.id = pc.product_id
JOIN categories c ON pc.category_id = c.id
JOIN variants v ON p.id = v.product_id
WHERE c.handle = 'summer-collection' 
  AND p.status = 'active'
GROUP BY p.id;
```

## Orders & Checkout Domain

Handles the transition from shopping activity to finalized transactions.

### carts & cart_items
Temporary storage for customer intent.
- **Migration Source**: `SCHEMA`, 015, 017, 022
- **Key Columns (carts)**:
  - `id` (TEXT, PK): UUID.
  - `customer_email` (TEXT).
  - `region_id` (TEXT, FK): Determines pricing/taxes.
  - `shipping_country` (TEXT): ISO 2-letter code.
  - `taxes_json` (TEXT, Nullable): Detailed tax breakdown (Mig 022).
  - `expires_at` (TEXT): Used by cleanup jobs.

### orders & order_items
Permanent transaction records.
- **Migration Source**: `SCHEMA`, 001, 016, 022, 032
- **Key Columns (orders)**:
  - `number` (TEXT, Unique): Human-readable order ID.
  - `status` (TEXT): 'pending', 'paid', 'processing', 'shipped', 'delivered', 'refunded', 'canceled'.
  - `viewtoken` (TEXT, Unique): Hashed JWT for guest order tracking (Mig 016).
  - `total_cents` (INTEGER): Final amount paid.
  - `locale` (TEXT): Customer language for notifications (Mig 032).

## Shipping & Regional Logistics

Fufuni is designed for multi-region scale, using `regions` to group `countries`, `currencies`, and `warehouses`.

### regions & region_relationships
- **Migration Source**: 007, 008, 011
- **Relationships**:
  - `region_countries`: Links a region to ISO country codes.
  - `region_warehouses`: Links a region to fulfillment centers.
  - `region_shipping_rates`: Links available shipping methods to the region.

### warehouse_inventory
Tracks stock levels per physical location.
- **Migration Source**: 012
- **Columns**:
  - `sku` (TEXT): The product identifier.
  - `warehouse_id` (TEXT, FK).
  - `on_hand` (INTEGER): Total physical stock.
  - `reserved` (INTEGER): Stock in open carts or unpaid orders.

### Shipping Class Logic Example
Shipping classes allow grouping products with special needs (e.g., Heavy Goods).
```sql
-- Check if a cart requires exclusive shipping rates
SELECT DISTINCT sc.resolution, sc.code
FROM cart_items ci
JOIN variants v ON ci.sku = v.sku
JOIN shipping_classes sc ON v.shipping_class_id = sc.id
WHERE ci.cart_id = 'cart_123' AND sc.resolution = 'exclusive';
```

## System & Infrastructure

### store_themes

- **Migration Source**: 030
- **Columns**:

  - `is_active` (INTEGER): 1 if currently live.

### order_email_settings
Configuration for automated notifications.
- **Migration Source**: 032, 033
- **Columns**:
  - `event` (TEXT, Unique): 'paid', 'shipped', etc.
  - `subject` (TEXT): Supports locale maps.
  - `html_body` (TEXT): Handlebars-style template.

### Theme Configuration Update
```sql
-- Switching the active theme
BEGIN TRANSACTION;
  UPDATE store_themes SET is_active = 0;
  UPDATE store_themes SET is_active = 1 WHERE id = 'theme_luxury';

```

### api_keys
Manages access control for the Hono backend.
- **Migration Source**: `SCHEMA`
- **Columns**:
  - `key_hash` (TEXT, Unique): SHA-256 hash of the API key.
  - `key_prefix` (TEXT): First few chars for identification (e.g., 'sk_live_').
  - `role` (TEXT): 'public' or 'admin'.

### Webhooks & Deliveries
- **Migration Source**: 002
- **Tables**: `webhooks` (targets), `webhook_deliveries` (logs/retry state).
