## Product Data Model and Multilingual Storage

Fufuni handles internationalization at the database level by storing localized text fields as JSON objects within SQLite columns. This approach, used for `title`, `description`, `vendor`, and `tags`, allows the framework to scale to any number of languages without requiring schema changes for new locales.

### Multilingual JSON Pattern
Every text field intended for display must follow the locale-keyed object structure. The `en-US` key is mandatory as it serves as the source for the product `handle` (URL slug).

```typescript
// apps/merchant/src/schemas.ts
import { z } from '@hono/zod-openapi';

/** 
 * Standard Multilingual Schema 
 * Maps locale codes (e.g., 'en-US', 'fr-FR') to their translated strings.
 */
export const LocalizedStringSchema = z.record(
  z.string().describe('Locale code (e.g., en-US, fr-FR)'),
  z.string()
).openapi({
  example: {
    'en-US': 'Organic Cotton T-Shirt',
    'fr-FR': 'T-shirt en coton biologique'
  }
});

export const ProductSchema = z.object({
  id: z.string().uuid(),
  handle: z.string().regex(/^[a-z0-9-]+$/),
  title_json: LocalizedStringSchema,
  description_json: LocalizedStringSchema,
  status: z.enum(['active', 'draft', 'archived']),
  vendor_json: LocalizedStringSchema.optional(),
});
```

### The Product Handle
The `handle` is the unique URL-safe identifier for a product. It is derived from the `en-US` title during creation. In Fufuni, public-facing routes should always resolve products by `handle` rather than `id` to optimize for SEO and human-readable URLs.

```typescript
// Example logic for generating a handle from the title object
function generateHandle(titleObj: Record<string, string>): string {
  const base = titleObj['en-US'] || Object.values(titleObj)[0] || 'product';
  return base
    .toLowerCase()
    .replace(/[^a-z0-9]+/g, '-')
    .replace(/(^-|-$)/g, '');
}
```

## Variant Properties and Physical Specs

A product in Fufuni is a container for one or more **Variants**. While the product holds general metadata, the variants hold specific stock, physical, and pricing data.

### Physical Attributes (Dimensions & Weight)
Fufuni uses a specific JSON format for dimensions to simplify shipping calculations within Cloudflare Workers. 

- **Weight**: Stored as `weight_g` (integer, grams).
- **Dimensions**: Stored as `dims_cm` (JSON object).

### Pricing Architecture
Fufuni distinguishes between **Display Pricing** and **Transaction Pricing**:
1.  **Display Price**: Stored in the `variants` table (`price_cents`). This is used for quick rendering in catalogs.
2.  **Transaction Price**: Stored in the `variant_prices` table. This is the **source of truth** for checkouts, supporting multiple currencies and regional tax overrides.

## Implementation: Multilingual Read/Write Patterns

When interacting with localized fields, you must avoid treating columns as simple strings. SQLite stores these as text, which Hono/Zod must parse into objects.

### Correct vs. Incorrect Patterns

| Action | ❌ Wrong Pattern (String) | ✅ Correct Pattern (JSON) |
| :--- | :--- | :--- |
| **Storage** | `'Red T-Shirt'` | `'{"en-US": "Red T-Shirt", "fr-FR": "T-shirt rouge"}'` |
| **SQL Insert** | `INSERT INTO products (title_json) VALUES (?)` | `INSERT INTO products (title_json) VALUES (json(?))` |
| **Reading** | `row.title_json` | `JSON.parse(row.title_json)` |

### Helper for Parsing Locales
```typescript
/**
 * Extract a specific locale or fallback to the first available translation.
 */
export function getLocaleString(
  jsonField: string | Record<string, string> | null, 
  targetLocale: string = 'en-US'
): string {
  if (!jsonField) return '';
  const data = typeof jsonField === 'string' ? JSON.parse(jsonField) : jsonField;
  return data[targetLocale] || data['en-US'] || Object.values(data)[0] || '';
}
```

## Product Search and Lifecycle

### Lifecycle States
Fufuni enforces a strict lifecycle to ensure customer-facing consistency:
- **`draft`**: Visible only to admins. Cannot be added to carts.
- **`active`**: Visible in the public catalog and searchable.
- **`archived`**: Hidden from catalog and search, but preserved for historical order reference.

### Search Implementation
The `/v1/products/search` endpoint performs a fuzzy search using SQLite `LIKE` operators across localized fields and the handle.

```typescript
// apps/merchant/src/routes/catalog.ts (Search Implementation)
adminApp.get('/search', async (c) => {
  const { q, limit = '20' } = c.req.query();
  const db = getDb(c.env);
  const searchTerm = `%${q}%`;

  const { results } = await db.prepare(`
    SELECT * FROM products 
    WHERE (
      title_json LIKE ? OR 
      vendor_json LIKE ? OR 
      handle LIKE ?
    )
    AND status != 'archived'
    LIMIT ?
  `)
  .bind(searchTerm, searchTerm, searchTerm, parseInt(limit))
  .all();

  return c.json({ products: results.map(p => ({
    ...p,
    title_json: JSON.parse(p.title_json as string)
  }))});
});
```

### 3. Frontend Implementation (React 19 + HeroUI)
A component to display the localized color name based on the user's current locale.

```tsx
// apps/admin/src/components/ProductColorBadge.tsx
import { Chip } from "@heroui/react";
import { getLocaleString } from "../utils/i18n";

interface Props {
  colorJson: string; // The raw JSON string from the API
}

export const ProductColorBadge = ({ colorJson }: Props) => {
  const currentLocale = "fr-FR"; // Usually from a Context/I18n hook
  const colorName = getLocaleString(colorJson, currentLocale);

  if (!colorName) return null;

  return (
    <Chip variant="flat" color="primary" size="sm">
      Color: {colorName}
    </Chip>
  );
};
```
