## Product Model and Data Structure

The Fufuni product model is designed for high performance on Cloudflare Workers by balancing structured relational data (SQL) with flexible document-style fields (JSON). The core identity of a product resides in the `products` table, while complex or variable data like images and package dimensions are stored as JSON blobs.

### Core Product Schema
A product is the parent entity for variants. It defines the default categorization, base currency, and shared metadata.

```typescript
import { z } from '@hono/zod-openapi';

export const ProductImageSchema = z.object({
  url: z.string().url(),
  alt: z.string().optional(),
  isPrimary: z.boolean().default(false),
});

export const ProductResponse = z.object({
  id: z.string().uuid(),
  category_id: z.string().uuid(),
  base_currency: z.string().length(3), // ISO 4217 (e.g., 'USD')
  name: z.string().openapi({ example: 'Wireless Headphones' }),
  description: z.string().nullable(),
  images: z.array(ProductImageSchema).openapi({ 
    description: 'Ordered list of product images. The first image with isPrimary: true is the thumbnail.' 
  }),
  tags: z.array(z.string()).openapi({ example: ['electronics', 'audio'] }),
  created_at: z.string().datetime(),
  updated_at: z.string().datetime(),
});

export type Product = z.infer<typeof ProductResponse>;
export type ProductImage = z.infer<typeof ProductImageSchema>;
```

### Image Array Logic
Images are stored as an ordered JSON array in the `product.images` column. This eliminates the need for a separate `product_images` join table, reducing JOIN overhead in SQLite.
- **isPrimary**: Indicates the main image for listings.
- **Ordering**: The array index determines the display order in the gallery.
- **Thumbnail**: UI components should prioritize the first object where `isPrimary === true`.

## Category Tree Management

Categories follow a hierarchical tree structure using a `parent_id` self-reference. Slugs must be unique within the same level of the tree.

### Category Structure
```typescript
export const CategorySchema = z.object({
  id: z.string().uuid(),
  parent_id: z.string().uuid().nullable(),
  slug: z.string().openapi({ example: 'electronics' }),
  name: z.string().openapi({ example: 'Electronics' }),
  level: z.number().int().default(0),
});

/**
 * Example recursive function to build a tree from a flat array
 */
export function buildCategoryTree(categories: any[], parentId: string | null = null): any[] {
  return categories
    .filter(cat => cat.parent_id === parentId)
    .map(cat => ({
      ...cat,
      children: buildCategoryTree(categories, cat.id)
    }));
}
```

### Nested Navigation
When fetching products by category (`GET /v1/products?category=computing`), the framework includes products from all sub-categories (e.g., `computing/laptops`, `computing/peripherals`). This is handled via a recursive Common Table Expression (CTE) in the SQLite layer.

## Localization Strategy

Fufuni uses a "Fallback-to-Base" localization pattern. The primary `products` and `categories` tables store the system ID and base configuration, while translated content lives in `product_locales` and `category_locales`.

### Locale Tables
- `product_locales`: `(product_id, locale, name, description)`
- `category_locales`: `(category_id, locale, name)`

### Fallback Logic in SQL
When querying for a specific locale (e.g., `fr-FR`), the backend attempts to JOIN the locale table. If the row is missing, it falls back to the `en-US` record.

```sql
-- Example logic for localized product fetch
SELECT 
    p.id,
    COALESCE(l_req.name, l_base.name) AS name,
    COALESCE(l_req.description, l_base.description) AS description
FROM products p
LEFT JOIN product_locales l_req ON p.id = l_req.product_id AND l_req.locale = ?1
LEFT JOIN product_locales l_base ON p.id = l_base.product_id AND l_base.locale = 'en-US'
WHERE p.id = ?2;
```

## Variant Management

Every product must have at least one variant. Variants handle the "physical" attributes of the item: SKU, pricing, and stock.

### Variant Attributes JSON
The `attributes` column in the `product_variants` table stores arbitrary key-value pairs (e.g., `{ "color": "Red", "size": "XL" }`). This allows different product types (clothing vs. electronics) to exist in the same table without schema migrations.

### Creating a Variant
```typescript
import { createRoute, z } from '@hono/zod-openapi';

const CreateVariantBody = z.object({
  sku: z.string().min(3),
  price_cents: z.number().int().positive(),
  currency: z.string().length(3).default('USD'),
  stock_quantity: z.number().int().nonnegative(),
  attributes: z.record(z.string(), z.string()).openapi({
    example: { color: 'Midnight Blue', size: 'Large' }
  }),
});

// Admin Route Definition
const createVariant = createRoute({
  method: 'post',
  path: '/v1/products/{id}/variants',
  request: {
    params: z.object({ id: z.string().uuid() }),
    body: { content: { 'application/json': { schema: CreateVariantBody } } },
  },
  responses: {
    201: { description: 'Variant created successfully', content: { 'application/json': { schema: z.any() } } },
  },
});
```

## Product Tags and Filtering

Tags provide a flat classification system. Unlike categories, a product can have an unlimited number of tags.

### Tag Logic
- **Storage**: Tags are linked via the `product_tags` join table.
- **Filtering**: When a user provides multiple tags (`?tags=summer,shoes`), the API returns products that have **at least one** of these tags (Boolean OR logic).

### Implementation Example
```typescript
/**
 * Helper to generate tag filter SQL
 * @param tags Array of tag strings from query params
 */
function getTagFilterSql(tags: string[]): string {
  if (tags.length === 0) return '';
  
  const placeholders = tags.map(() => '?').join(',');
  return `AND p.id IN (
    SELECT product_id FROM product_tags 
    WHERE tag_name IN (${placeholders})
  )`;
}
```

## Image Reordering and Primary Selection

Since images are stored as a JSON array, reordering or changing the primary image is an atomic update to the `products.images` column.

### Reordering Logic
To reorder images or change the primary thumbnail, the admin client sends the full array in the desired order.

```typescript
// Example frontend request to update image order
async function updateProductImages(productId: string, newImages: ProductImage[]) {
  const response = await fetch(`/v1/products/${productId}`, {
    method: 'PUT',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      images: newImages.map((img, index) => ({
        ...img,
        // Ensure only one image is primary if needed, 
        // or let the backend validate the array.
        isPrimary: index === 0 
      }))
    })
  });
  return response.json();
}
```

The backend validates that the `images` field is a valid JSON array matching the `ProductImageSchema` before persisting to SQLite via the Durable Object.
