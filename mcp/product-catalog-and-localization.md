## Product Data Model
The product data model includes key fields such as `id`, `title_json`, `description_json`, `vendor_json`, `tags_json`, and `handle`. The `title_json`, `description_json`, `vendor_json`, and `tags_json` fields are stored as JSON objects keyed by locale code, following the pattern:
```json
{
  "en-US": "T-shirt",
  "fr-FR": "T-shirt"
}
```
The `handle` field is a URL-safe slug auto-generated from the `en-US` title and must match the pattern `^[a-z0-9-]+$`.

## Variant Model
The variant model includes fields such as `id`, `sku`, `price_cents`, `currency`, `weight_g`, and `dims_cm`. The `price_cents` field is used for display purposes only, while the `variant_prices` table stores the source of truth for multi-region pricing. The `dims_cm` field is stored as a JSON object with the pattern:
```json
{
  "l": 30,
  "w": 20,
  "h": 10
}
```
representing the length, width, and height in centimeters.

## Product Search
The product search endpoint is `/v1/products/search` and supports the following query parameters:
* `q`: search query
* `category_id`: category ID

The search uses full-text LIKE queries across `title_json`, `vendor_json`, `tags_json`, and `handle`. Only "active" products appear in the public catalog.

## Status Lifecycle
The status lifecycle for products and variants is:
1. `draft`: initial state
2. `active`: published and visible in the public catalog
3. `archived`: removed from the public catalog
