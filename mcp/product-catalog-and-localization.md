## Product Data Model and Structure

The Fufuni framework uses a hybrid approach for product data: structured relational tables for core attributes and JSON columns for flexible metadata like images and dimensions. Every product exists as a record in the `products` table, serving as a container for its variants and localized content.

### Product Schema
A core product entry defines the global configuration, including the base currency and the category association.

```typescript
import { z } from '@hono/zod-openapi';

// Core Product structure as stored/returned by the API
export const ProductSchema = z.object({
  id: z.string().uuid(),
  category_id: z.string().uuid(),
  base_currency: z.string().length(3).default('USD'),
  images: z.array(z.object({
    url: z.string().url(),
    alt: z.string(),
    isPrimary: z.boolean()
  })).openapi({ description: 'Ordered JSON array of product images' }),
  created_at: z.string().datetime(),
  updated_at: z.string().datetime(),
});

export type Product = z.infer<typeof ProductSchema>;
```

### Variant Model
Fufuni requires every product to have at least one variant. Inventory and pricing are managed at the variant level.

| Field | Type | Description |
| :--- | :--- | :--- |
| `sku` | String | Unique Stock Keeping Unit identifier |
| `price_cents` | Integer | Price in the smallest currency unit (e.g., 2999 for $29.99) |
| `currency` | String | ISO 4217 code (e.g., "USD", "EUR") |
| `stock_quantity`| Integer | Current units available in warehouse |
| `attributes` | JSON | Key-value pairs for options (e.g., `{"color": "Red", "size": "XL"}`) |

```sql
-- SQLite schema for variants
CREATE TABLE product_variants (
    id TEXT PRIMARY KEY,
    product_id TEXT NOT NULL,
    sku TEXT UNIQUE NOT NULL,
    price_cents INTEGER NOT NULL,
    currency TEXT NOT NULL DEFAULT 'USD',
    stock_quantity INTEGER NOT NULL DEFAULT 0,
    attributes TEXT NOT NULL, -- JSON string: {"color": "Blue"}
    weight_g INTEGER,
    requires_shipping BOOLEAN DEFAULT 1,
    FOREIGN KEY (product_id) REFERENCES products(id) ON DELETE CASCADE
);
```

## Category Tree and Hierarchy

Categories in Fufuni utilize an Adjacency List model with a `parent_id` reference to build recursive trees. This allows for infinite nesting. Slugs are unique identifiers used for SEO-friendly URLs.

### Nested Category Management
To create a sub-category, the `parent_id` must point to an existing category UUID. When fetching products by a category slug, Fufuni recursively includes products from all child categories.

```typescript
// Example: Creating a nested "Running Shoes" category under "Footwear"
const createSubCategory = async (parentId: string) => {
  const payload = {
    parent_id: parentId,
    slug: 'running-shoes',
    name: 'Running Shoes', // This goes to category_locales (en-US)
    is_active: true
  };
  
  const response = await fetch('/v1/categories', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(payload)
  });
  return response.json();
};
```

## Query Parameters for Product Discovery

The `GET /v1/products` endpoint supports advanced filtering. Most parameters can be combined to refine results.

| Parameter | Type | Example | Description |
| :--- | :--- | :--- | :--- |
| `category` | string | `?category=sneakers` | Filter by category slug (recursive) |

| `locale` | string | `?locale=fr-FR` | Preferred language for content |
| `currency` | string | `?currency=EUR` | Filter variants by specific currency |
| `tags` | string | `?tags=summer,sale` | Filter by tags (OR logic) |

## Localization and Fallback Logic

Fufuni separates translatable strings from the core product record using `product_locales` and `category_locales` tables. This allows the system to support any number of languages without altering the main table schema.

### Fallback Mechanism
1. The API checks if a record exists for the requested `locale` (e.g., `pt-BR`).
2. If not found, it attempts to find the base language record (default `en-US`).
3. If the base language is missing (highly unlikely for valid products), the system returns the first available locale or an empty string.

```sql
-- Localization Table Structure
CREATE TABLE product_locales (
    product_id TEXT NOT NULL,
    locale TEXT NOT NULL, -- e.g., 'en-US', 'fr-FR'
    name TEXT NOT NULL,
    description TEXT,
    PRIMARY KEY (product_id, locale),
    FOREIGN KEY (product_id) REFERENCES products(id) ON DELETE CASCADE
);
```

### Implementing Localized Retrieval in Hono
```typescript
async function getLocalizedProduct(db: D1Database, id: string, locale: string) {
  const query = `
    SELECT p.*, 
           COALESCE(l.name, b.name) as name, 
           COALESCE(l.description, b.description) as description
    FROM products p
    LEFT JOIN product_locales l ON p.id = l.product_id AND l.locale = ?1
    LEFT JOIN product_locales b ON p.id = b.product_id AND b.locale = 'en-US'
    WHERE p.id = ?2
  `;
  return await db.prepare(query).bind(locale, id).first();
}
```

## Image Array Structure

Images are stored in an ordered JSON array within the `products.images` column. This prevents the overhead of a separate join table for basic media retrieval while maintaining order.

### Image Object Schema
- `url`: The absolute path to the image (usually a Cloudflare R2 public URL).
- `alt`: Descriptive text for accessibility and SEO.
- `isPrimary`: Boolean flag. The system uses the first image where `isPrimary: true` as the catalog thumbnail.

```typescript
// Reordering images: move second image to first position
const reorderImages = async (product: Product) => {
  const newImages = [...product.images];
  const [movedItem] = newImages.splice(1, 1);
  newImages.unshift(movedItem);
  
  // Ensure only one is primary
  const updatedImages = newImages.map((img, idx) => ({
    ...img,
    isPrimary: idx === 0
  }));

  await updateProduct(product.id, { images: updatedImages });
};
```

## Product Tags and Filtering

Tags enable non-hierarchical organization. Fufuni implements tags using a many-to-many relationship via a `product_tags` join table.

### Tag Filtering Logic
When querying `?tags=tag1,tag2`, the framework applies **OR** logic. A product is returned if it is associated with *at least one* of the provided tags.

```sql
-- Many-to-Many Join Table
CREATE TABLE product_tags (
    product_id TEXT NOT NULL,
    tag_id TEXT NOT NULL,
    PRIMARY KEY (product_id, tag_id),
    FOREIGN KEY (product_id) REFERENCES products(id) ON DELETE CASCADE,
    FOREIGN KEY (tag_id) REFERENCES tags(id) ON DELETE CASCADE
);

-- Example Query for "summer" OR "sale"
SELECT DISTINCT p.* FROM products p
JOIN product_tags pt ON p.id = pt.product_id
JOIN tags t ON pt.tag_id = t.id
WHERE t.slug IN ('summer', 'sale');
```

### Adding Tags to a Product
To associate tags, the tags must first exist in the `tags` master table. The merchant dashboard typically handles this by searching for existing tags and creating new ones on the fly before updating the join table.
