## The useTokenUserData Hook

The `useTokenUserData` hook is the primary interface for accessing authenticated user information in the Fufuni frontend. Unlike basic authentication hooks that only track "is logged in," this hook focuses on parsing the JWT ID Token payload to retrieve granular user claims and synchronization of state across disparate components.

### Hook return type and claims

The hook returns a stateful object containing the parsed data, loading status, and error states. When used with the standard Fufuni Auth0 setup, the JWT payload typically includes:

| Claim | Type | Description |
| :--- | :--- | :--- |
| `sub` | `string` | The unique Auth0 user identifier (subject). |
| `email` | `string` | User's verified email address. |
| `name` | `string` | Full name of the user. |
| `picture` | `string` | URL to the user's profile image. |
| `permissions` | `string[]` | Array of RBAC permissions assigned to the user. |
| `roles` | `string[]` | Array of names of roles the user belongs to. |
| `user_metadata`| `Record<string, any>` | Arbitrary JSON object for client-side preferences. |

### Usage Example: Implementing a Wishlist

To ensure that adding an item to a wishlist in the Product Detail Page (PDP) updates the wishlist count in the Navbar, we utilize the hook's `CustomEvent` synchronization feature.

```typescript
import { jwtDecode } from "jwt-decode";
import { useTokenUserData } from "@/hooks/use-token-user-data";

interface UserData {
  wishlist: string[];
  roles: string[];
}

const WISHLIST_SYNC_EVENT = "fufuni:wishlist-sync";

/**
 * A specialized hook for managing the user's wishlist
 * persisted in Auth0 user_metadata.
 */
export function useWishlist() {
  const parseWishlist = (token: string | null): string[] => {
    if (!token) return [];
    try {
      const decoded = jwtDecode<any>(token);
      // Accessing the custom metadata claim (usually namespaced)
      const metadata = decoded["https://fufuni.com/user_metadata"] || {};
      return metadata.wishlist || [];
    } catch {
      return [];
    }
  };

  const { data: wishlist, setData, isLoading } = useTokenUserData<string[]>(
    parseWishlist,
    WISHLIST_SYNC_EVENT
  );

  const toggleWishlist = (productId: string) => {
    const nextWishlist = wishlist.includes(productId)
      ? wishlist.filter((id) => id !== productId)
      : [...wishlist, productId];

    // 1. Update local state
    setData(nextWishlist);

    // 2. Dispatch event for other components using this hook
    window.dispatchEvent(
      new CustomEvent(WISHLIST_SYNC_EVENT, { detail: nextWishlist })
    );

    // 3. Persist to Auth0 via API (implementation-specific)
    // fetch('/api/v1/user/metadata', { method: 'PATCH', body: JSON.stringify({ wishlist: nextWishlist }) });
  };

  return { wishlist, toggleWishlist, isLoading };
}
```

## Auth0 user_metadata Patterns

Auth0 `user_metadata` is an arbitrary JSON object stored per-user. In the Fufuni ecosystem, we use this for non-sensitive, client-side preferences that need to persist across sessions but don't require strict ACID compliance or complex relational queries.

### Normalizing Store URLs as Keys

Auth0 imposes restrictions on field names within `user_metadata`. Specifically, characters like dots (`.`), colons (`:`), and slashes (`/`) are disallowed. Since Fufuni is a multi-tenant framework, we often store data segmented by the store's domain. We must normalize these URLs before using them as keys.

```typescript
// From apps/client/src/lib/store-metadata.ts

/**
 * Converts a store URL into a safe Auth0 metadata key.
 * Example: "https://shop.fufuni.com/" -> "https___shop_fufuni_com"
 */
export const normalizeStoreUrl = (storeUrl?: string): string | undefined => {
  if (!storeUrl) return undefined;
  return storeUrl
    .replace(/\/$/, "") // Remove trailing slash
    .replace(/[:.\/]/g, "_"); // Replace problematic chars with underscores
};

/**
 * Retrieves the subset of user_metadata specific to the current store context.
 */
export const getStoreMetadata = (userMetadata: any, storeUrl?: string): any => {
  if (!userMetadata || typeof userMetadata !== "object") return undefined;

  const normalizedUrl = normalizeStoreUrl(storeUrl);

  if (
    normalizedUrl &&
    userMetadata[normalizedUrl] &&
    typeof userMetadata[normalizedUrl] === "object"
  ) {
    return userMetadata[normalizedUrl];
  }

  // Fallback to root for global settings
  return userMetadata;
};
```

### What to store vs. what NOT to store

- **DO STORE:** Wishlist item IDs, UI theme preference (dark/light), recently viewed products, dismissed notification IDs.
- **DO NOT STORE:** User's home address (PII), credit card fragments, store inventory data, or admin-only flags like `is_banned`. `user_metadata` is visible to the user after decoding their JWT.

## Store Metadata (Merchant-Side)

Store Metadata refers to settings for the store itself (e.g., logo URL, primary color, shipping rules). This is stored in the `store_metadata` table in the SQLite database managed by the Durable Object.

### Server-Side Library

In the `apps/merchant` backend, we use helper functions to interact with the database.

```typescript
// apps/merchant/src/lib/store-metadata.ts
import { DrizzleD1Database } from "drizzle-orm/d1";
import { storeMetadata } from "@/db/schema";
import { eq } from "drizzle-orm";

export const getMetadata = async (
  db: DrizzleD1Database<any>,
  key: string
): Promise<any> => {
  const result = await db
    .select()
    .from(storeMetadata)
    .where(eq(storeMetadata.metadata_key, key))
    .get();

  return result ? JSON.parse(result.metadata_value) : null;
};

export const setMetadata = async (
  db: DrizzleD1Database<any>,
  key: string,
  value: any
): Promise<void> => {
  const jsonValue = JSON.stringify(value);
  await db
    .insert(storeMetadata)
    .values({
      metadata_key: key,
      metadata_value: jsonValue,
      updated_at: new Date().toISOString(),
    })
    .onConflictDoUpdate({
      target: storeMetadata.metadata_key,
      set: { metadata_value: jsonValue, updated_at: new Date().toISOString() },
    });
};
```

### HTTP Endpoints for Store Metadata

Merchant settings are exposed via protected admin routes. These routes act as the bridge between the React dashboard and the SQLite storage.

```typescript
// apps/merchant/src/routes/store-metadata.ts
import { Hono } from "hono";
import { getMetadata, setMetadata } from "@/lib/store-metadata";
import { adminMiddleware } from "@/middleware/auth";

const app = new Hono();

// GET /v1/store-metadata/theme_config
app.get("/:key", adminMiddleware, async (c) => {
  const key = c.req.param("key");
  const db = c.get("db");
  const data = await getMetadata(db, key);
  return c.json(data || {});
});

// PUT /v1/store-metadata/theme_config
app.put("/:key", adminMiddleware, async (c) => {
  const key = c.req.param("key");
  const body = await c.req.json();
  const db = c.get("db");
  await setMetadata(db, key, body);
  return c.json({ success: true });
});
```

## JWT Permissions and Auth0 Actions

Permissions are not stored directly in the Auth0 user profile but are assigned via Roles or directly to the user. In Fufuni, these are injected into the JWT at login time using an **Auth0 Post-Login Action**.

### How permissions are injected

The Auth0 Action script looks similar to this (managed in the Auth0 Dashboard):

```javascript
exports.onExecutePostLogin = async (event, api) => {
  const namespace = 'https://fufuni.com/';
  if (event.authorization) {
    api.idToken.setCustomClaim(`${namespace}permissions`, event.authorization.permissions);
    api.accessToken.setCustomClaim(`${namespace}permissions`, event.authorization.permissions);
    api.idToken.setCustomClaim(`${namespace}roles`, event.authorization.roles);
  }
};
```

### Accessing permissions in the Frontend

To check if a user can access a specific feature (e.g., the Admin Dashboard), we use the `useTokenUserData` hook or the underlying `useAuth` state.

```typescript
import { useAuth } from "@/authentication";

export const AdminGuard = ({ children }: { children: React.ReactNode }) => {
  const { user, isAuthenticated } = useAuth();
  const namespace = "https://fufuni.com/";
  
  const permissions = user?.[`${namespace}permissions`] || [];
  const isAdmin = permissions.includes("access:admin_panel");

  if (!isAuthenticated || !isAdmin) {
    return <div>Access Denied</div>;
  }

  return <>{children}</>;
};
```

## Security and Compliance Note

The Fufuni framework follows the principle of **Client-Visible Metadata**.

1.  **Visibility:** Any data placed in `user_metadata` is encoded into the ID Token. This means any user can inspect their own metadata by pasting their token into a tool like `jwt.io`.
2.  **Integrity:** While users can read the data, they cannot modify it locally and have it persist on the server without going through your API, as the JWT is cryptographically signed.
3.  **Sensitivity:** Never store secrets (API keys for third-party services), internal system flags (like `is_internal_tester`), or sensitive personal data in the JWT.
4.  **Size Limits:** Auth0 limits `user_metadata` to 8KB. For large datasets (like a cart with 100 items), use the server-side `saved-carts` table instead of the JWT.

### Backend Verification Example

When the Merchant backend receives a request, it must verify the `permissions` claim from the Access Token, not the ID Token.

```typescript
// apps/merchant/src/middleware/auth.ts
import { verify } from "hono/jwt";

export const adminMiddleware = async (c, next) => {
  const authHeader = c.req.header("Authorization");
  const token = authHeader?.split(" ")[1];
  
  if (!token) return c.json({ error: "Unauthorized" }, 401);

  const payload = await verify(token, process.env.AUTH0_SECRET);
  const permissions = payload["https://fufuni.com/permissions"] as string[];

  if (!permissions.includes("write:store_settings")) {
    return c.json({ error: "Forbidden" }, 403);
  }

  await next();
};
```
