## Introduction to JWT User Metadata Patterns
The Fufuni framework utilizes Auth0 user metadata to store per-user preferences and data. This reference will guide you through the patterns and best practices for working with JWT user metadata in the Fufuni ecosystem.

## Embedding User Metadata in the JWT
Auth0 user metadata is embedded in the JWT access token by a post-login Action under the namespace "extra_user_info/user_metadata". This allows client-side applications to access user metadata without requiring an extra API call.

```typescript
import { decodeJwt } from 'jose';

const token = await getAccessTokenSilently();
const decodedToken = decodeJwt(token);
const userMetadata = decodedToken.extra_user_info.user_metadata;
```

## Multi-Store Scoping
To support multiple Fufuni instances sharing one Auth0 tenant, all per-user store data is namespaced under a store-scoped key. This key is derived from the `STORE_URL` using the `normalizeStoreUrl()` function.

```typescript
// apps/client/src/lib/store-metadata.ts
export const normalizeStoreUrl = (storeUrl?: string): string | undefined => {
  if (!storeUrl) return undefined;
  const normalized = storeUrl
    .replace(/\/$/, '') // Remove trailing slash
    .replace(/[:.\/]/g, '_'); // Replace dots, colons, and slashes with underscores
  return normalized || undefined;
};
```

The `normalizeStoreUrl()` function replaces characters not allowed in Auth0 metadata keys (., :, /) with underscores. For example, "https://shop.example.com" becomes "https___shop_example_com". Both the frontend and backend must use the same normalization.

## Cross-Component Reactivity
Cross-component sync uses the `window.dispatchEvent()` function to dispatch a `CustomEvent` with the new value. Components listen on the `window` object and call `getAccessTokenSilently()` + `decodeJwt()` to refresh their view of user metadata.


## Adding a New Per-User Preference Field
To add a new per-user preference field, follow these steps:

1. Update the type in `use-token-user-data.ts` to include the new field.
2. Read the new field using `useTokenUserData` with a new selector function.
3. Persist the new field via a `PATCH` request to `/v1/me/preferences`.
4. Dispatch a `CustomEvent` to sync other components.

Example:
```typescript
// Add a new field to the user metadata type
interface UserMetadata {
  theme: string;
  wishlist: string[];
  // Add a new field
  language: string;
}

// Read the new field using useTokenUserData
const language = useTokenUserData(
  (token) => token.extra_user_info.user_metadata.language,
  'languageChange'
);

// Persist the new field via a PATCH request
fetch('/v1/me/preferences', {
  method: 'PATCH',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ language: 'fr' }),
});

// Dispatch a CustomEvent to sync other components
window.dispatchEvent(new CustomEvent('languageChange', { detail: 'fr' }));
```
