## JWT & User Metadata Patterns

In the Fufuni framework, user state and configuration are managed through three primary channels: **JWT Claims** (for identity and permissions), **Auth0 user_metadata** (for lightweight, cross-device user preferences like wishlists), and **Store Metadata** (for server-side persistent store configuration stored in SQLite).

### useTokenUserData Hook

The `useTokenUserData` hook is the primary interface for accessing and synchronizing user-specific data encoded within the Auth0 JWT. It provides a reactive state that automatically updates when the authentication status changes or when a global event is dispatched.

The hook parses the ID token payload which includes standard OIDC claims and Fufuni-specific namespaces:
- `sub`: The unique Auth0 user ID.
- `email`: User's email address.
- `name` / `picture`: Basic profile info.
- `permissions`: An array of strings representing RBAC permissions.
- `roles`: Assigned Auth0 roles.
- `user_metadata`: Arbitrary JSON object containing user preferences.

#### Usage Example: Wishlist Management

```typescript
import { useTokenUserData } from "@/hooks/use-token-user-data";
import { jwtDecode } from "jwt-decode";

interface UserData {
  wishlist: string[];
}

// Helper to extract data from the namespaced claim in the JWT
const parseWishlist = (token: string | null): UserData => {
  if (!token) return { wishlist: [] };
  try {
    const decoded: any = jwtDecode(token);
    // Note: Fufuni uses a custom namespace for metadata in the JWT
    const metadata = decoded["https://fufuni.com/user_metadata"] || {};
    return {
      wishlist: metadata.wishlist || []
    };
  } catch {
    return { wishlist: [] };
  }
};

export const WishlistCount = () => {
  const { data, isLoading } = useTokenUserData(parseWishlist, "fufuni:wishlist-sync");

  if (isLoading) return <span>...</span>;

  return <div>Items in wishlist: {data.wishlist.length}</div>;
};

// To update data across components without a full page reload:
// window.dispatchEvent(new CustomEvent("fufuni:wishlist-sync", { detail: { wishlist: ['p1', 'p2'] } }));
```

### Auth0 user_metadata Patterns

`user_metadata` is intended for non-sensitive information that should follow the user across sessions and devices. Fufuni uses this for frontend-driven state that doesn't require complex server-side validation.

**Normalization Logic:**
Auth0 restricts field names in `user_metadata` (no dots or slashes). Fufuni provides normalization helpers to store data scoped to specific store URLs.

```typescript
import { normalizeStoreUrl, getStoreMetadata } from "@/lib/store-metadata";

const rawMetadata = {
  "https___shop_fufuni_com": { theme: "dark" },
  "global_pref": "enabled"
};

const storeUrl = "https://shop.fufuni.com/";
const config = getStoreMetadata(rawMetadata, storeUrl); 
// Returns: { theme: "dark" }
```

**What to store in user_metadata:**
- Wishlists (product IDs).
- Saved cart identifiers.
- UI preferences (language, theme, layout density).
- Marketing opt-in flags (non-sensitive).

### Store Metadata (Server-Side SQLite)

Unlike `user_metadata` (which belongs to the user), **Store Metadata** belongs to the store instance. It is stored in the `store_metadata` table within the Durable Object's SQLite database. This is managed via the `apps/merchant` service.

#### Server-Side Implementation (Merchant API)

The server-side library provides direct access to the SQLite backend.

```typescript
// apps/merchant/src/lib/store-metadata.ts usage in a Hono route
import { Hono } from "hono";
import { getMetadata, setMetadata } from "@/lib/store-metadata";
import { Bindings } from "@/types";

const app = new Hono<{ Bindings: Bindings }>();

app.get("/v1/store-metadata/:key", async (c) => {
  const key = c.req.param("key");
  const db = c.env.DB; // SQLite D1 or Durable Object bridge
  
  const value = await getMetadata(db, key);
  return c.json({ key, value });
});

app.put("/v1/store-metadata/:key", async (c) => {
  const key = c.req.param("key");
  const body = await c.req.json();
  const db = c.env.DB;

  await setMetadata(db, key, body.value);
  return c.json({ success: true });
});
```

The merchant dashboard (Frontend) interacts with these settings using dedicated helpers.

### JWT Permissions & RBAC

Permissions in Fufuni are not managed in the local database but are injected into the JWT by an **Auth0 Post-Login Action**. This ensures that the frontend can immediately hide or show UI elements based on the token payload without making an additional "whoami" request.

**Accessing permissions:**

```typescript
import { useAuth } from "@/authentication";

export const AdminButton = () => {
  const { user } = useAuth();
  
  // The namespace is usually defined in your environment config
  const namespace = "https://fufuni.com/";
  const permissions = user?.[`${namespace}permissions`] || [];
  
  const canEdit = permissions.includes("write:products");

  if (!canEdit) return null;

  return <button>Edit Product</button>;
};
```

### Security Considerations

When working with these metadata patterns, strictly adhere to the following security boundaries:

| Feature | Read Access | Write Access | Security Level |
| :--- | :--- | :--- | :--- |
| **JWT Claims** | Client (decoded) | Auth0 Server Only | High (Integrity checked) |
| **user_metadata** | Client & Server | Auth0 Management API | Medium (Visible to user) |
| **Store Metadata** | Server (Admin) | Server (Admin) | High (Private DB) |

#### Critical Security Note:
**NEVER** store sensitive data in `user_metadata`. 
- **Forbidden**: API keys, internal customer loyalty points (if they can be exploited), hashed passwords, or private PII.
- **Why**: The `user_metadata` claim is included in the JWT. Since JWTs are Base64 encoded strings, any user can decode their own token via the browser console or tools like `jwt.io` to see the contents. 

For sensitive per-customer state (e.g., credit balance), create a dedicated SQLite table in the backend and access it through authorized Hono routes.

### Schema: store_metadata table

The underlying SQLite schema for store-wide settings:

```sql
CREATE TABLE IF NOT EXISTS store_metadata (
  metadata_key TEXT PRIMARY KEY,
  metadata_value TEXT NOT NULL, -- JSON stringified
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

To update this via the Merchant library:
```typescript
import { setMetadata } from "@/lib/store-metadata";

// Inside a Hono route
await setMetadata(c.env.DB, "ui_customization", {
  primaryColor: "#ff0000",
  logoUrl: "https://cdn.fufuni.com/logo.png"
});
```
