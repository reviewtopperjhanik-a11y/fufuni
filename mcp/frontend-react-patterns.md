## Frontend React Patterns
The Fufuni frontend is built using React 19, HeroUI v3, and React Router. This guide covers the key patterns and conventions for building and extending the frontend.

### React Router Setup
React Router is used to declare routes in the application. The routes are declared in the `app.tsx` file, and protected routes are wrapped with the `AuthenticationGuard` or `AuthenticationGuardWithPermission` component. Here's an example of a protected route:
```typescript
import { Route, Routes } from "react-router-dom";
import { AuthenticationGuardWithPermission } from "./authentication";
import UsersAndPermissionsPage from "@/pages/admin/users-and-permissions";

// ...
<Routes>
  <Route
    element={<AuthenticationGuardWithPermission permission={import.meta.env.ADMIN_AUTH0_PERMISSION}><UsersAndPermissionsPage /></AuthenticationGuardWithPermission>}
    path="/admin/users"
  />
</Routes>
```
### Adding a New Page
To add a new page, follow these three steps:

1. Create the page component in `apps/client/src/pages/`. For example, `product-tags.tsx`:
```typescript
import React from "react";

const ProductTagsPage = () => {
  return <h1>Product Tags Page</h1>;
};

export default ProductTagsPage;
```
2. Add the page to the router in `app.tsx`. Wrap with `AuthenticationGuard` or `AuthenticationGuardWithPermission` if the page is protected:
```typescript
import { Route, Routes } from "react-router-dom";
import { AuthenticationGuardWithPermission } from "./authentication";
import ProductTagsPage from "@/pages/admin/product-tags";

// ...
<Routes>
  <Route
    element={<AuthenticationGuardWithPermission permission={import.meta.env.ADMIN_STORE_PERMISSION}><ProductTagsPage /></AuthenticationGuardWithPermission>}
    path="/admin/product-tags"
  />
</Routes>
```
3. Optionally, add a `navItem` entry in `apps/client/src/config/site.ts` to control navbar visibility:
```typescript
export const siteConfig = () => ({
  // ...
  navItems: [
    // ...
    {
      label: i18next.t("product-tags"),
      href: "/admin/product-tags",
      permissions: ["admin:store"], // Only visible to users with "admin:store" permission
    },
  ],
});
```
### Navbar Auto-Show/Hide Items
The navbar auto-shows/hides items based on Auth0 permissions. Public items (permissions: []) are always shown. The admin dropdown is wrapped with `<AuthenticationGuardWithPermission permission="admin:store">` and only shows items whose permissions include "admin:store".

### HeroUI v3
HeroUI v3 is used for UI components. It uses a compound component pattern, where components are composed of smaller sub-components. For example, the `Dropdown` component has `Trigger` and `Popover` sub-components:
```typescript
import { Dropdown } from "@heroui/react";

// ...
<Dropdown>
  <Dropdown.Trigger>Dropdown Trigger</Dropdown.Trigger>
  <Dropdown.Popover>
    <Dropdown.Menu>
      <Dropdown.Item>Menu Item 1</Dropdown.Item>
      <Dropdown.Item>Menu Item 2</Dropdown.Item>
    </Dropdown.Menu>
  </Dropdown.Popover>
</Dropdown>
```
Key HeroUI v3 components include `Button`, `Card`, `Modal`, `Table`, and `Form`.

### ThemeSwitch
The `ThemeSwitch` component is used to switch between light/dark and custom themes. It is already included in the navbar:
```typescript
import { ThemeSwitch } from "@/shared/ui/navigation/theme-switch";

// ...
<ThemeSwitch />
```
Theme config is stored in the `store_themes` DB table.

### Feature Folder Structure and Hook Placement Conventions
Features are organized in a folder structure:
```
apps/client/src/features/<feature-name>/
  components/
  hooks/
  index.ts
```
New React hooks go in `apps/client/src/hooks/` if they are page-agnostic, or in the feature folder if feature-specific.
