## React Router and Protected Routes

Fufuni uses `react-router-dom` v6 for client-side routing. The main entry point is `apps/client/src/app.tsx`. Routes are defined using a centralized `<Routes>` component wrapped in a `<Suspense>` boundary to handle code-splitting and lazy loading of page components.

Protection of routes is handled via two specialized higher-order components (HOCs) within the authentication module:
1.  `AuthenticationGuard`: Ensures the user is logged in before rendering the component.
2.  `AuthenticationGuardWithPermission`: Ensures the user is logged in AND possesses a specific Auth0 permission (e.g., `admin:store`).

### Implementing a Protected Route

When adding a route that requires administrative access, wrap the element in the `AuthenticationGuardWithPermission` component.

```typescript
// apps/client/src/app.tsx
import { Route } from "react-router-dom";
import { AuthenticationGuardWithPermission } from "./authentication";
import TagsPage from "@/pages/admin/tags";

// Inside the <Routes> component:
<Route
  element={
    <AuthenticationGuardWithPermission permission={import.meta.env.ADMIN_STORE_PERMISSION}>
      <TagsPage />
    </AuthenticationGuardWithPermission>
  }
  path="/admin/tags"
/>
```

## Adding a New Page: The Three-Step Workflow

To maintain consistency in the Fufuni framework, every new page follows a strict three-step registration process.

### Step 1: Create the Page Component
Create a new file in `apps/client/src/pages/`. Page components should typically be default exports.

```typescript
// apps/client/src/pages/admin/tags.tsx
import { useTranslation } from "react-i18next";
import { Card, Button } from "@heroui/react";

export default function TagsPage() {
  const { t } = useTranslation();
  
  return (
    <div className="p-6">
      <Card>
        <Card.Header className="flex justify-between">
          <h1 className="text-2xl font-bold">{t("admin-tags-title")}</h1>
          <Button color="primary">{t("add-tag")}</Button>
        </Card.Header>
        <Card.Body>
          <p>Tag management content goes here.</p>
        </Card.Body>
      </Card>
    </div>
  );
}
```

### Step 2: Register the Route
Add the route to `apps/client/src/app.tsx`. For admin pages, always use the permission-based guard.

### Step 3: Update Site Configuration
To make the page accessible via the navigation bar, add an entry to `apps/client/src/config/site.ts`.

```typescript
// apps/client/src/config/site.ts
export const siteConfig = () => ({
  // ... other config
  navItems: [
    // ...
    {
      label: i18next.t("admin-tags-title"),
      href: "/admin/tags",
      permissions: ["admin:store"], // Controls visibility in the Navbar
    },
  ],
});
```

## Permission-Based Navbar Visibility

The `Navbar` component (located in `apps/client/src/components/navbar.tsx`) dynamically filters items based on the `permissions` array defined in `siteConfig`. 

- **Public Items**: Items with `permissions: []` are always rendered for all visitors.
- **Admin Items**: The admin dropdown is conditionally rendered using `AuthenticationGuardWithPermission`. Within that dropdown, it filters `navItems` that include the `admin:store` permission.

### Filtering Logic in Navbar

The navbar uses standard array filtering to decide what the current user sees:

```typescript
// apps/client/src/components/navbar.tsx (Simplified)
const adminItems = siteConfig().navItems.filter(
  item => item.permissions && item.permissions.includes("admin:store")
);

return (
  <AuthenticationGuardWithPermission permission="admin:store">
    <Dropdown>
      <Dropdown.Trigger>
        {t("nav-admin")}
      </Dropdown.Trigger>
      <Dropdown.Menu>
        {adminItems.map((item) => (
          <Dropdown.Item key={item.href} onPress={() => navigate(item.href)}>
            {item.label}
          </Dropdown.Item>
        ))}
      </Dropdown.Menu>
    </Dropdown>
  </AuthenticationGuardWithPermission>
);
```

## HeroUI v3 Compound Component Pattern

Fufuni utilizes **HeroUI v3**, which emphasizes a compound component architecture. This improves readability and allows for better prop drilling within sub-components. Always import from `@heroui/react`.

### Common Compound Components

- **Card**: `<Card>`, `<Card.Header>`, `<Card.Body>`, `<Card.Footer>`
- **Dropdown**: `<Dropdown>`, `<Dropdown.Trigger>`, `<Dropdown.Menu>`, `<Dropdown.Item>`
- **Table**: `<Table>`, `<Table.Header>`, `<Table.Column>`, `<Table.Body>`, `<Table.Row>`, `<Table.Cell>`
- **Modal**: `<Modal>`, `<Modal.Content>`, `<Modal.Header>`, `<Modal.Body>`, `<Modal.Footer>`

### Example: Modal Implementation

```typescript
import { Modal, Button, useDisclosure } from "@heroui/react";

export function DeleteConfirmation({ onDelete }: { onDelete: () => void }) {
  const { isOpen, onOpen, onOpenChange } = useDisclosure();

  return (
    <>
      <Button onPress={onOpen} color="danger">Delete</Button>
      <Modal isOpen={isOpen} onOpenChange={onOpenChange}>
        <Modal.Content>
          {(onClose) => (
            <>
              <Modal.Header>Are you sure?</Modal.Header>
              <Modal.Body>This action cannot be undone.</Modal.Body>
              <Modal.Footer>
                <Button variant="light" onPress={onClose}>Cancel</Button>
                <Button color="danger" onPress={() => { onDelete(); onClose(); }}>Confirm</Button>
              </Modal.Footer>
            </>
          )}
        </Modal.Content>
      </Modal>
    </>
  );
}
```

## ThemeSwitch and Global Providers

The visual state of the application is managed through a specific provider hierarchy in `apps/client/src/provider.tsx`. 

### Provider Ordering
The order of providers is critical for context availability:
1.  `StoreThemeProvider`: Handles custom themes fetched from the `store_themes` database table.
2.  `Toast.Provider`: HeroUI's global notification system.
3.  `CartProvider`: Manages the shopping cart state.
4.  `CartDrawerProvider`: Controls the open/close state of the side cart drawer.

```typescript
// apps/client/src/provider.tsx
export function Provider({ children }: { children: React.ReactNode }) {
  return (
    <StoreThemeProvider>
      <Toast.Provider />
      <CartProvider>
        <CartDrawerProvider>
          {children}
        </CartDrawerProvider>
      </CartProvider>
    </StoreThemeProvider>
  );
}
```

The `ThemeSwitch` component is already integrated into the `Navbar`. It interacts with the `StoreThemeProvider` to toggle between light and dark modes or apply brand-specific styles.

## Feature Folder Structure

To ensure scalability, Fufuni follows a feature-based organization for non-page components and logic.

- `apps/client/src/features/<feature-name>/`:
    - `components/`: Internal components specific to the feature.
    - `hooks/`: Feature-specific hooks (e.g., `use-product-filters.ts`).
    - `index.ts`: The public API for the feature. **Only export what is needed outside the folder.**

General, page-agnostic hooks belong in `apps/client/src/hooks/`.

## Worked Example: Adding a "Product Tags" Admin Page

This example demonstrates adding a new administrative interface for managing product tags.

### 1. Create the Page
Create `apps/client/src/pages/admin/tags.tsx`.

```typescript
import { Table, Button, Badge } from "@heroui/react";
import { useTranslation } from "react-i18next";

const TagsPage = () => {
  const { t } = useTranslation();
  const tags = [{ id: 1, name: "Eco-friendly" }, { id: 2, name: "New Arrival" }];

  return (
    <div className="flex flex-col gap-4 p-8">

          <Table.Column>NAME</Table.Column>

              </Table.Cell>

  );
};

export default TagsPage;
```
