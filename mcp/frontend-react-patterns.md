## Frontend React Patterns
This guide covers the key patterns and best practices for building the Fufuni frontend with React.

### React Router Setup
The React Router is set up in `app.tsx`. Routes are declared using the `Route` component from `react-router-dom`. Protected routes are wrapped with `AuthenticationGuard` or `AuthenticationGuardWithPermission` to restrict access based on Auth0 permissions.

```typescript
// apps/client/src/app.tsx
import { Route, Routes } from "react-router-dom";
import { AuthenticationGuard, AuthenticationGuardWithPermission } from "./authentication";

// ...
<Routes>
  <Route element={<IndexPage />} path="/" />
  <Route
    element={<AuthenticationGuard component={ApiPage} />}
    path="/api"
  />
  <Route
    element={<AuthenticationGuardWithPermission permission={import.meta.env.ADMIN_AUTH0_PERMISSION}><UsersAndPermissionsPage /></AuthenticationGuardWithPermission>}
    path="/admin/users"
  />
  // ...
</Routes>
```

### Adding a New Page
To add a new page, follow these three steps:

1. Create the page component in `apps/client/src/pages/`.
2. Add a route for the page in `app.tsx`. Wrap the route with `AuthenticationGuard` or `AuthenticationGuardWithPermission` if the page requires authentication or specific permissions.
3. Optionally, add a navItem entry in `apps/client/src/config/site.ts` to control navbar visibility based on permissions.

```typescript
// apps/client/src/config/site.ts
export const siteConfig = () => ({
  // ...
  navItems: [
    {
      label: i18next.t("new-page"),
      href: "/new-page",
      permissions: ["admin:store"], // Optional permissions array
    },
    // ...
  ],
});
```

### Navbar Auto-Show/Hide Items
The navbar in `apps/client/src/components/navbar.tsx` reads the `siteConfig().navItems` array and auto-shows/hides items based on Auth0 permissions. Public items (permissions: []) are always shown, while items with permissions[] arrays are only shown if the user has the required permissions.

```typescript
// apps/client/src/components/navbar.tsx
import { siteConfig } from "@/config/site";
import { AuthenticationGuardWithPermission } from "@/authentication";

// ...
<ul>
  {siteConfig().navItems.filter(item => !item.permissions || item.permissions.length === 0).map((item) => (
    <li key={item.href}>
      <RouterLink to={item.href}>{item.label}</RouterLink>
    </li>
  ))}
  <AuthenticationGuardWithPermission permission="admin:store">
    <li>
      <Dropdown>
        {/* Admin dropdown items */}
      </Dropdown>
    </li>
  </AuthenticationGuardWithPermission>
</ul>
```

### HeroUI v3
HeroUI v3 is used for UI components. It uses a compound component pattern, where components are composed of smaller, reusable parts. Key components include `Button`, `Card`, `Modal`, `Table`, and `Form`.

```typescript
// Example usage of HeroUI v3 Button component
import { Button } from "@heroui/react";

// ...
<Button onPress={() => console.log("Button pressed!")}>
  Click me!
</Button>
```

### ThemeSwitch
The `ThemeSwitch` component is already included in the navbar and allows users to switch between light/dark and custom themes. Theme config is stored in the `store_themes` DB table.

```typescript
// apps/client/src/shared/ui/navigation/theme-switch.tsx
import { ThemeSwitch } from "./theme-switch";

// ...
<ThemeSwitch />
```

### Feature Folder Structure and Hook Placement Conventions
Features are organized into folders with the following structure:

* `apps/client/src/features/<feature-name>/components/`
* `apps/client/src/features/<feature-name>/hooks/`
* `apps/client/src/features/<feature-name>/index.ts`

New React hooks go in `apps/client/src/hooks/` if they are page-agnostic, or in the feature folder if feature-specific.

```typescript
// apps/client/src/features/product/hooks/use-product.ts
import { useState, useEffect } from "react";

// ...
export const useProduct = () => {
  const [product, setProduct] = useState({});

  useEffect(() => {
    // Fetch product data
  }, []);

  return product;
};
```
