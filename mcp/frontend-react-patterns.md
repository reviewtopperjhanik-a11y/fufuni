## React Router and Protected Routes

Fufuni uses `react-router-dom` for client-side navigation. The application entry point in `app.tsx` centralizes route definitions. To maintain security, Fufuni implements a custom guarding pattern using `AuthenticationGuard` and `AuthenticationGuardWithPermission`.

### Route Declaration

Routes are defined within the `<Routes>` component. Public routes (like the landing page) are declared directly, while protected routes wrap their components.

```typescript
// apps/client/src/app.tsx
import { Route, Routes } from "react-router-dom";
import { AuthenticationGuard, AuthenticationGuardWithPermission } from "./authentication";
import ProductsPage from "@/pages/admin/products";
import IndexPage from "@/pages/index";

export function AppRoutes() {
  return (
    <Routes>
      {/* Public Route */}
      <Route element={<IndexPage />} path="/" />

      {/* Protected Route: Requires any authenticated user */}
      <Route
        element={<AuthenticationGuard component={AccountLayout} />}
        path="/account"
      />

      {/* Permission-Protected Route: Requires specific Auth0 permission */}
      <Route
        element={
          <AuthenticationGuardWithPermission permission="admin:store">
            <ProductsPage />
          </AuthenticationGuardWithPermission>
        }
        path="/admin/products"
      />
    </Routes>
  );
}
```

### The Authentication Guards

- **AuthenticationGuard**: Checks if the user is logged in. If not, it triggers the login flow (usually via `LoginModal` or a redirect).
- **AuthenticationGuardWithPermission**: Checks both authentication status and whether the user's JWT contains the required permission string in the `permissions` array.

## Adding a New Page

Adding a new feature or view to the Fufuni frontend follows a strict three-step process to ensure consistency and proper navigation.

### Step 1: Create the Page Component
Create a new file in `apps/client/src/pages/`. If it's an admin page, place it in `apps/client/src/pages/admin/`. Use the `useSeoMeta` hook for SEO.

```typescript
// apps/client/src/pages/admin/tags.tsx
import { useTranslation } from "react-i18next";
import { useSeoMeta } from "@/hooks/use-seo-meta";

export default function TagsPage() {
  const { t } = useTranslation();
  
  useSeoMeta({
    title: t("admin-tags-title"),
    description: t("manage-product-tags"),
  });

  return (
    <div className="p-6">
      <h1 className="text-2xl font-bold">{t("admin-tags-title")}</h1>
      {/* Page content here */}
    </div>
  );
}
```

### Step 2: Register in the Router
Import and add the route to `apps/client/src/app.tsx`. Use `AuthenticationGuardWithPermission` for admin pages.

```typescript
// Add to imports
import TagsPage from "@/pages/admin/tags";

// Add to <Routes>
<Route
  element={
    <AuthenticationGuardWithPermission permission="admin:store">
      <TagsPage />
    </AuthenticationGuardWithPermission>
  }
  path="/admin/tags"
/>
```

### Step 3: Configure Navigation
Update `apps/client/src/config/site.ts` to add the item to the sidebar or navbar. This allows the UI to automatically handle visibility based on user permissions.

```typescript
// apps/client/src/config/site.ts
export const siteConfig = () => ({
  navItems: [
    // ... existing items
    {
      label: i18next.t("admin-tags-title"),
      href: "/admin/tags",
      permissions: ["admin:store"], 
    },
  ],
});
```

## Navbar and Permission Logic

The `Navbar` component (`apps/client/src/components/navbar.tsx`) is dynamic. It reads the configuration from `siteConfig()` and filters items based on the user's current session.

### Permission Filtering
The Navbar uses two strategies for visibility:
1. **Direct Filter**: For top-level links, it filters the `navItems` array to show only those where `permissions` is empty.
2. **Component Guarding**: For restricted sections (like the Admin Dropdown), it wraps the entire UI block in an `AuthenticationGuardWithPermission`.

```typescript
// apps/client/src/components/navbar.tsx snippet
const { navItems } = siteConfig();

{/* Desktop Navigation */}
<ul className="hidden lg:flex gap-6">
  {navItems.filter(item => !item.permissions || item.permissions.length === 0).map((item) => (
    <li key={item.href}>
      <RouterLink to={item.href}>{item.label}</RouterLink>
    </li>
  ))}
  
  <AuthenticationGuardWithPermission permission="admin:store">
    <li>
      <Dropdown>
        <Dropdown.Trigger>Admin <ChevronDown /></Dropdown.Trigger>
        <Dropdown.Menu>
          {navItems.filter(item => item.permissions?.includes("admin:store")).map(item => (
            <Dropdown.Item key={item.href} onPress={() => navigate(item.href)}>
              {item.label}
            </Dropdown.Item>
          ))}
        </Dropdown.Menu>
      </Dropdown>
    </li>
  </AuthenticationGuardWithPermission>
</ul>
```

## HeroUI v3 Compound Components

Fufuni utilizes **HeroUI v3**. Unlike older versions or other libraries that use flat props, HeroUI v3 relies heavily on the **Compound Component** pattern. This improves readability and provides finer control over the internal structure of UI elements.

### Example: Modal Pattern
When creating modals for forms or confirmations, always use the sub-component syntax.

```typescript
import { Modal, Button, Input } from "@heroui/react";

export function CreateTagModal({ isOpen, onClose }: { isOpen: boolean, onClose: () => void }) {
  return (
    <Modal isOpen={isOpen} onClose={onClose}>
      <Modal.Content>
        <Modal.Header>Create New Tag</Modal.Header>
        <Modal.Body>
          <Input label="Tag Name" placeholder="e.g. Summer Collection" />
        </Modal.Body>
        <Modal.Footer>
          <Button variant="flat" onPress={onClose}>Cancel</Button>
          <Button color="primary" onPress={() => console.log('Saved')}>Save</Button>
        </Modal.Footer>
      </Modal.Content>
    </Modal>
  );
}
```

### Key UI Components
- **Table**: Use for admin lists. Includes `Table.Header`, `Table.Column`, `Table.Body`, and `Table.Row`.
- **Card**: Use `Card.Header`, `Card.Body`, and `Card.Footer` for consistent layouts.
- **Dropdown**: Follow the `Dropdown.Trigger` -> `Dropdown.Popover` -> `Dropdown.Menu` hierarchy.

## Theme and Provider Management

The application state is wrapped in a specific sequence of providers in `apps/client/src/provider.tsx`. Order is critical because themes must be available to UI components, and the cart must be available to the global drawer.

### Provider Stack
1. **StoreThemeProvider**: Fetches and applies custom CSS variables from the `store_themes` database table.
2. **Toast.Provider**: Enables the HeroUI global toast notification system.
3. **CartProvider**: Manages the local shopping cart state (synced to local storage).
4. **CartDrawerProvider**: Manages the open/closed state of the side cart drawer.

```typescript
// apps/client/src/provider.tsx
export function Provider({ children }: { children: React.ReactNode }) {
  return (
    <StoreThemeProvider>
      <Toast.Provider />
      <CartProvider>
        <CartDrawerProvider>
          {children}
        </CartDrawerProvider>
      </CartProvider>
    </StoreThemeProvider>
  );
}
```

### ThemeSwitch
The `ThemeSwitch` component is already integrated into the `Navbar`. It interacts with the `StoreThemeProvider` to toggle between light and dark modes. It also supports custom brand colors defined in the admin dashboard.

## Folder Structure and Feature Patterns

Fufuni follows a **Feature-Based Architecture**. Code should be colocated based on the business domain it serves rather than its technical type.

### Directory Layout
- `apps/client/src/features/`: Contains domain-specific logic.
    - `<feature-name>/components/`: Feature-specific UI.
    - `<feature-name>/hooks/`: Feature-specific logic (e.g., `use-product-query.ts`).
    - `<feature-name>/index.ts`: The public API for the feature.
- `apps/client/src/hooks/`: Page-agnostic, reusable hooks (e.g., `use-cart.ts`, `use-seo-meta.ts`).
- `apps/client/src/components/`: Reusable display components like `ProductCard` or `ImageUploadInput`.

### Image Handling
For any admin form requiring images, use the `ImageUploadInput`. It automatically handles:
- Browser-side WebP conversion to save bandwidth.
- Logic to decide between sending a Base64 string or an R2 URL.
- Generating thumbnails.

```typescript
import { ImageUploadInput } from "@/components/image-upload-input";

// Inside a form
<ImageUploadInput
  label="Product Image"
  value={imageUrl}
  onChange={(newUrl) => setImageUrl(newUrl)}
/>
```
