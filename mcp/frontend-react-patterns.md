## React Router and Authentication Guards

Fufuni uses `react-router-dom` for client-side navigation. The routing architecture distinguishes between public routes, authenticated customer routes, and permission-restricted admin routes. Instead of blocking the entire application layout, we use **Guards** to wrap specific components or route branches.

### Authentication Guard Patterns

There are two primary guards used in `apps/client/src/app.tsx`:
1.  `AuthenticationGuard`: Ensures the user is logged in. Used for customer account pages (Dashboard, Orders).
2.  `AuthenticationGuardWithPermission`: Ensures the user is logged in AND possesses a specific Auth0 permission (e.g., `admin:store`).

```typescript
// apps/client/src/app.tsx example
import { Route, Routes } from "react-router-dom";
import { AuthenticationGuard, AuthenticationGuardWithPermission } from "./authentication";
import Dashboard from "@/pages/account/dashboard";
import ProductsPage from "@/pages/admin/products";

export function AppRoutes() {
  return (
    <Routes>
      {/* Public Route */}
      <Route path="/" element={<IndexPage />} />

      {/* Authenticated Customer Route */}
      <Route
        path="/account"
        element={<AuthenticationGuard component={Dashboard} />}
      />

      {/* Permission-Restricted Admin Route */}
      <Route
        path="/admin/products"
        element={
          <AuthenticationGuardWithPermission permission="admin:store">
            <ProductsPage />
          </AuthenticationGuardWithPermission>
        }
      />
    </Routes>
  );
}
```

## Adding a New Page to the Framework

Integrating a new page into Fufuni follows a strict three-step process to ensure consistent navigation and security.

### Step 1: Create the Page Component
Create your file in `apps/client/src/pages/`. Use the `@/` alias for shared components.

```typescript
// apps/client/src/pages/admin/settings.tsx
import { Card, Label } from "@heroui/react";

export default function AdminSettingsPage() {
  return (
    <div className="p-6">
      <Card className="max-w-md">
        <Card.Header>
          <Label className="text-xl font-bold">Store Settings</Label>
        </Card.Header>
        <Card.Body>
          <p>Configure your global store parameters here.</p>
        </Card.Body>
      </Card>
    </div>
  );
}
```

### Step 2: Register the Route
Add the route to the `<Routes>` block in `apps/client/src/app.tsx`. Wrap it in the appropriate guard if it is an admin or account page.

```typescript
// Inside apps/client/src/app.tsx
import AdminSettingsPage from "@/pages/admin/settings";

// ... inside <Routes>
<Route
  element={
    <AuthenticationGuardWithPermission permission="admin:store">
      <AdminSettingsPage />
    </AuthenticationGuardWithPermission>
  }
  path="/admin/settings"
/>
```

### Step 3: Update Site Configuration
To make the page visible in the Navbar or Sidebar, add an entry to `apps/client/src/config/site.ts`. The `permissions` array determines if the link is rendered for the current user.

```typescript
// apps/client/src/config/site.ts
export const siteConfig = () => ({
  navItems: [
    // ... other items
    {
      label: i18next.t("settings"),
      href: "/admin/settings",
      permissions: ["admin:store"], 
    },
  ],
});
```

## Permission-Based Navigation in the Navbar

The `Navbar` component (located in `apps/client/src/components/navbar.tsx`) dynamically renders links based on the user's authentication state and permissions. It utilizes `siteConfig().navItems` and filters them reactively.

### Navbar Visibility Logic
The Navbar uses a two-tier approach:
1.  **Public Items**: Items with an empty `permissions` array are mapped directly to the top-level horizontal menu.
2.  **Restricted Items**: The "Admin" dropdown is wrapped in an `AuthenticationGuardWithPermission`. Inside, it filters the `siteConfig` for items matching the `admin:store` permission.

```typescript
// apps/client/src/components/navbar.tsx logic snippet
const { isAuthenticated } = useAuth();

{/* Desktop Navigation */}
<ul className="hidden lg:flex gap-6">
  {/* Render Public Links */}
  {siteConfig().navItems
    .filter(item => !item.permissions || item.permissions.length === 0)
    .map((item) => (
      <li key={item.href}>
        <RouterLink to={item.href}>{item.label}</RouterLink>
      </li>
  ))}

  {/* Render Admin Dropdown if user has permission */}
  <AuthenticationGuardWithPermission permission="admin:store">
    <li>
      <Dropdown>
        <Dropdown.Trigger>Admin Actions</Dropdown.Trigger>
        <Dropdown.Popover>
          <Dropdown.Menu>
            {siteConfig().navItems
              .filter(item => item.permissions?.includes("admin:store"))
              .map(item => (
                <Dropdown.Item key={item.href} onPress={() => navigate(item.href)}>
                  {item.label}
                </Dropdown.Item>
            ))}
          </Dropdown.Menu>
        </Dropdown.Popover>
      </Dropdown>
    </li>
  </AuthenticationGuardWithPermission>
</ul>
```

## HeroUI v3 Compound Component Pattern

Fufuni adopts **HeroUI v3**, which moves away from flat prop-drilling in favor of the **Compound Component** pattern. This improves readability and provides finer control over the internal layout of complex UI elements like Modals, Tables, and Cards.

### Common Compound Components Example
Always import from `@heroui/react`. Note the dot notation (e.g., `Modal.Content`).

```typescript
import { Modal, Button, Form, Input } from "@heroui/react";
import { useState } from "react";

export const CreateCategoryModal = () => {
  const [isOpen, setIsOpen] = useState(false);

  return (
    <>
      <Button onPress={() => setIsOpen(true)}>New Category</Button>
      <Modal isOpen={isOpen} onClose={() => setIsOpen(false)}>
        <Modal.Content>
          {(onClose) => (
            <>
              <Modal.Header>Add Category</Modal.Header>
              <Modal.Body>
                <Form className="gap-4">
                  <Input label="Name" placeholder="e.g. Shoes" />
                  <Input label="Handle" placeholder="shoes" />
                </Form>
              </Modal.Body>
              <Modal.Footer>
                <Button color="danger" variant="light" onPress={onClose}>Cancel</Button>
                <Button color="primary" onPress={onClose}>Save</Button>
              </Modal.Footer>
            </>
          )}
        </Modal.Content>
      </Modal>
    </>
  );
};
```

## ThemeSwitch and Global Providers

The application state is initialized in `apps/client/src/provider.tsx`. The order of providers is critical to ensure that styling and feedback components (Toasts) have access to the theme context.

### Provider Hierarchy
1.  **StoreThemeProvider**: Handles CSS variables and theme selection (fetched from the Durable Object SQLite backend).
2.  **Toast.Provider**: HeroUI's global toast notification container.
3.  **CartProvider**: Managing the shopping cart state.

```typescript
// apps/client/src/provider.tsx
import { Toast } from "@heroui/react";
import { CartProvider } from "@/hooks/use-cart";
import { StoreThemeProvider } from "@/providers/theme-provider";

export function Provider({ children }: { children: React.ReactNode }) {
  return (
    <StoreThemeProvider>
      <Toast.Provider />
      <CartProvider>
        {children}
      </CartProvider>
    </StoreThemeProvider>
  );
}
```

The `ThemeSwitch` component is a pre-built toggle found in `apps/client/src/shared/ui/navigation/theme-switch.tsx`. It is integrated into the `Navbar` by default and interacts with the `StoreThemeProvider` to swap between light/dark modes or custom branding.

## Feature Folder Structure

Fufuni uses a modular "Feature" structure to prevent the `components/` and `hooks/` directories from becoming bloated.

### Convention
-   `apps/client/src/features/<feature-name>/`: Main directory.
-   `components/`: UI specific to this feature.
-   `hooks/`: Logic/Queries specific to this feature.
-   `index.ts`: The **Public API** for the feature. Only export components/hooks that should be used by the rest of the application.

If a hook is used by multiple features (like `use-cart` or `use-auth`), it stays in `apps/client/src/hooks/`.
