## Frontend React Patterns
This guide covers the essential patterns and conventions used in the Fufuni e-commerce frontend, built with React, HeroUI v3, and Auth0.

### 1. React Router Setup
In `app.tsx`, routes are declared using the `Route` component from `react-router-dom`. Protected routes are wrapped with `AuthenticationGuard` or `AuthenticationGuardWithPermission` components to ensure only authorized users can access them.

```typescript
import { Route, Routes } from "react-router-dom";
import { AuthenticationGuard, AuthenticationGuardWithPermission } from "./authentication";

// ...

<Routes>
  <Route element={<IndexPage />} path="/" />
  <Route
    element={<AuthenticationGuard component={ApiPage} />}
    path="/api"
  />
  <Route
    element={<AuthenticationGuardWithPermission permission="admin:store"><UsersAndPermissionsPage /></AuthenticationGuardWithPermission>}
    path="/admin/users"
  />
  {/* ... */}
</Routes>
```

### 2. Adding a New Page
To add a new page, follow these three steps:

1. Create the page component in `apps/client/src/pages/`.
2. Add the page to the router in `app.tsx`, wrapping it with `AuthenticationGuard` or `AuthenticationGuardWithPermission` if necessary.
3. Optionally, add a `navItem` entry in `apps/client/src/config/site.ts` with a `permissions` array to control navbar visibility.

```typescript
// apps/client/src/pages/new-page.tsx
import React from "react";

const NewPage = () => {
  return <div>New Page</div>;
};

export default NewPage;
```

```typescript
// app.tsx
import NewPage from "./pages/new-page";

// ...

<Routes>
  {/* ... */}
  <Route element={<NewPage />} path="/new-page" />
</Routes>
```

```typescript
// apps/client/src/config/site.ts
import { siteConfig } from "./site";

// ...

navItems: [
  {
    label: "New Page",
    href: "/new-page",
    permissions: [], // or ["admin:store"] for protected pages
  },
  // ...
],
```

### 3. Navbar Item Visibility
The navbar reads `siteConfig().navItems` and shows public items (with empty `permissions` arrays) by default. The admin dropdown is wrapped with `AuthenticationGuardWithPermission` and only shows items whose `permissions` arrays include `"admin:store"`.

```typescript
// apps/client/src/components/navbar.tsx
import { AuthenticationGuardWithPermission } from "@/authentication";
import { siteConfig } from "@/config/site";

// ...

<Dropdown>
  <Dropdown.Trigger>
    {t("nav-admin")}
    <ChevronDown className="w-4 h-4" />
  </Dropdown.Trigger>
  <Dropdown.Popover>
    <Dropdown.Menu aria-label="Admin actions" className="w-full">
      {siteConfig().navItems
        .filter((item) => item.permissions && item.permissions.includes("admin:store"))
        .map((item) => (
          <Dropdown.Item
            key={item.href}
            id={item.href}
            textValue={item.label}
            className="gap-4"
            onPress={() => navigate(item.href)}
          >
            {/* ... */}
          </Dropdown.Item>
        ))}
    </Dropdown.Menu>
  </Dropdown.Popover>
</Dropdown>
```

### 4. HeroUI v3
Use HeroUI v3 components by importing them from `@heroui/react`. Adopt the compound component pattern, where components have nested sub-components (e.g., `Dropdown.Trigger`, `Card.Header`).

```typescript
import { Dropdown, Card } from "@heroui/react";

// ...

<Dropdown>
  <Dropdown.Trigger>
    {t("nav-admin")}
    <ChevronDown className="w-4 h-4" />
  </Dropdown.Trigger>
  <Dropdown.Popover>
    {/* ... */}
  </Dropdown.Popover>
</Dropdown>

<Card>
  <Card.Header>
    {t("card-header")}
  </Card.Header>
  <Card.Body>
    {t("card-body")}
  </Card.Body>
</Card>
```

### 5. ThemeSwitch
The `ThemeSwitch` component is already included in the navbar. It allows users to switch between light/dark and custom themes. Theme configuration is stored in the `store_themes` DB table.

```typescript
import { ThemeSwitch } from "@/shared/ui/navigation/theme-switch";

// ...

<ThemeSwitch />
```

### 6. Feature Folder Structure
Organize feature-specific code in the following structure:

* `apps/client/src/features/<feature-name>/components/`
* `apps/client/src/features/<feature-name>/hooks/`
* `apps/client/src/features/<feature-name>/index.ts`

Export the public API from `index.ts` only.

```bash
features/
├── feature-name
│   ├── components
│   │   ├── component1.tsx
│   │   └── component2.tsx
│   ├── hooks
│   │   ├── hook1.ts
│   │   └── hook2.ts
│   └── index.ts
└── ...
```
