## Checkout and UCP Flow
The checkout and UCP (Universal Checkout Page) flow is a critical component of the Fufuni e-commerce framework. It enables customers to complete transactions securely and efficiently. Below is an overview of the architecture, step-by-step flow, differences between guest and authenticated user checkout, and handling of the Stripe webhook.

### Architecture: UCP Sessions and Stripe PaymentIntents

The UCP flow revolves around the creation of UCP sessions and Stripe PaymentIntents. When a customer initiates checkout, the `/ucp/v1/checkout-sessions` endpoint is called, which creates both a CartSession and a Stripe PaymentIntent. The UCP session stores the intermediate state between session creation and finalization, while the Stripe PaymentIntent manages the payment processing.

### Step-by-Step Flow from Cart to Completed Order

The following steps outline the checkout process:

1. **Cart Creation**: A customer adds items to their cart, and the cart is created with a unique ID.
2. **Checkout Initiation**: The customer initiates checkout, and the `/ucp/v1/checkout-sessions` endpoint is called.
3. **UCP Session Creation**: A UCP session is created, and a Stripe PaymentIntent is generated.
4. **Redirect to Stripe Checkout**: The customer is redirected to the Stripe checkout page to complete the payment.
5. **Payment Processing**: The customer completes the payment on the Stripe checkout page.
6. **Stripe Webhook**: Stripe sends a `checkout.session.completed` webhook to the backend.
7. **Order Finalization**: The backend receives the webhook and finalizes the order by updating the UCP session and creating an order record.

### Differences between Guest Checkout and Authenticated User Checkout

The main differences between guest checkout and authenticated user checkout are:

* **Guest Checkout**: No JWT is required; only the `order_token` is needed to view the order afterwards.
* **Authenticated User Checkout**: A JWT is required to authenticate the user and associate the order with their account.

### Handling the Stripe Webhook (checkout.session.completed)

The `checkout.session.completed` webhook is critical to finalizing the order on the backend. When received, the backend:

1. **Verifies the Webhook**: Verifies the webhook signature to ensure authenticity.
2. **Updates UCP Session**: Updates the UCP session to reflect the completed payment.
3. **Creates Order Record**: Creates an order record in the database.

```typescript
// Stripe webhook handler
app.post('/stripe', async (c) => {
  const event = c.req.valid('json');
  if (event.type === 'checkout.session.completed') {
    const { session } = event.data.object;
    // Update UCP session
    await db.run(`UPDATE ucp_checkout_sessions SET status = 'completed' WHERE id = ?`, [session]);
    // Create order record
    await createOrder(session);
  }
});
```
