## UCP Architecture and Session Lifecycle

The Universal Commerce Protocol (UCP) in Fufuni provides a standardized interface for AI agents and external platforms to interact with the store. Unlike the standard web checkout which relies on an ephemeral `carts` table, UCP uses the `ucp_checkout_sessions` table to maintain a persistent state between an agent's request and the final payment.

UCP sessions act as a state machine with the following transitions:
1.  **incomplete**: Session created but lacks valid items or buyer information.
2.  **ready_for_complete**: Items are resolved, prices are fetched, and inventory is available.
3.  **complete_in_progress**: The buyer has been redirected to the payment handler (Stripe).
4.  **completed**: The Stripe webhook has successfully processed the payment and created an order.
5.  **requires_escalation**: A manual step is needed (e.g., no payment handler configured or buyer input required).
6.  **canceled**: The session was manually deleted or expired.

### UCP Session Storage Schema
UCP sessions store line items and totals as JSON blobs to preserve the "snapshot" of prices at the time of session creation or update.

## Endpoint Inventory and Operations

Fufuni implements the full suite of UCP 2026-01-11 operations. All routes are defined using `@hono/zod-openapi` with the `{id}` path syntax required for correct OpenAPI specification generation.

### Session Management Endpoints
-   `POST /ucp/v1/checkout-sessions`: Creates a session. It resolves SKU prices using the `resolveVariantPrice` helper.
-   `GET /ucp/v1/checkout-sessions/{id}`: Retrieves the current state, including active payment handlers.
-   `PUT /ucp/v1/checkout-sessions/{id}`: Performs a **full replacement**. It re-resolves all prices and recomputes taxes. Rejects if status is `completed`.
-   `PATCH /ucp/v1/checkout-sessions/{id}`: Performs a **partial update**. It merges buyer fields or updates item quantities in place without full price re-resolution.
-   `DELETE /ucp/v1/checkout-sessions/{id}`: Sets status to `canceled`.
-   `POST /ucp/v1/checkout-sessions/{id}/complete`: Initiates the finalization flow.

### Implementation of Partial Updates (PATCH)
The PATCH endpoint is optimized for performance by avoiding a full catalog lookup. It recalculates the `total_price` of the specific line items and invokes `computeTax` for the new subtotal.

```typescript
// apps/merchant/src/routes/ucp.ts snippet
ucp.openapi(routePatchCheckoutSession, async (c) => {
  const sessionId = c.req.param('id');
  const body = c.req.valid('json');
  const db = getDb(c.var.db);

  const [session] = await db.query<any>(`SELECT * FROM ucp_checkout_sessions WHERE id = ?`, [sessionId]);
  if (!session || ['completed', 'canceled'].includes(session.status)) {
    throw ApiError.invalidRequest('Cannot update session');
  }

  // Merging buyer JSON blob
  const currentBuyer = JSON.parse(session.buyer || 'null') || {};
  const mergedBuyer = { ...currentBuyer, ...body.buyer };
  
  // Updating quantities and totals in place
  const currentItems = JSON.parse(session.line_items || '[]');
  const patchedItems = currentItems.map((item: any) => {
    const patch = body.line_items?.find((li: any) => li.id === item.id);
    if (!patch) return item;
    return {
      ...item,
      quantity: patch.quantity,
      total_price: { ...item.unit_price, amount: item.unit_price.amount * patch.quantity }
    };
  });

  // Recomputing tax based on default region
  const newSubtotal = patchedItems.reduce((s: number, i: any) => s + i.total_price.amount, 0);
  const { taxAmount, taxLabel } = await computeTax(db, newSubtotal);
  
  // Update DB and return 303 Redirect to the GET route
  return c.redirect(`/ucp/v1/checkout-sessions/${sessionId}`, 303);
});
```

## Catalog Browsing for Agents

The UCP Browse capability allows agents to discover products and categories using structured queries. These routes are heavily cached in KV to minimize Durable Object compute time.

### Product Discovery Logic
The `GET /ucp/v1/products` endpoint uses a complex `COALESCE` logic to ensure images are returned even if a variant doesn't have a specific thumbnail. It filters strictly by `status = 'active'`.

```sql
-- Logic used in GET /ucp/v1/products
SELECT p.id, p.title, 
       COALESCE(v.thumbnail_url, v.image_url, p.image_url) as thumbnail_url,
       COALESCE(v.image_url, p.image_url) as image_url,
       MIN(vp.price_cents) as min_price_cents
FROM products p
LEFT JOIN variants v ON v.product_id = p.id AND v.status = 'active'
LEFT JOIN variant_prices vp ON vp.variant_id = v.id
WHERE p.status = 'active'
GROUP BY p.id
ORDER BY p.created_at DESC;
```

### Flexible Product Lookup
The `GET /ucp/v1/products/{id}` endpoint is polymorphic. It accepts a Product UUID, a Product Handle, a Variant UUID, or a Variant SKU.

## The Completion Flow and Webhooks

Finalizing a UCP session involves escalating the session to a payment provider. Fufuni primarily uses Stripe Checkout.

### Step-by-Step Flow
1.  **Agent calls `/complete`**: The server checks if Stripe is configured.
2.  **Redirect**: If Stripe is active, Fufuni returns `status: "requires_escalation"` with a Stripe `url` in the `continue_url` field. The internal status moves to `complete_in_progress`.
3.  **Payment**: The buyer completes the payment on Stripe's hosted page.
4.  **Webhook**: Stripe sends a `checkout.session.completed` event to the Fufuni backend.
5.  **Finalization**: `handleUCPStripeWebhook()` creates the order, deducts inventory, and marks the UCP session as `completed`.

### Webhook Implementation Details
The webhook handler must extract the UCP session ID from the Stripe metadata to link the payment back to the session.

```typescript
export async function handleUCPStripeWebhook(
  db: Database,
  stripeSessionId: string,
  stripeSession: Stripe.Checkout.Session
): Promise<void> {
  const ucpSessionId = stripeSession.metadata?.ucp_checkout_session_id;
  if (!ucpSessionId) return;

  const [session] = await db.query<any>(
    `SELECT * FROM ucp_checkout_sessions WHERE id = ? AND stripe_session_id = ?`,
    [ucpSessionId, stripeSessionId]
  );

  if (!session || session.status === 'completed') return;

  // Extract totals independently for the order record
  const totals = JSON.parse(session.totals || '[]');
  const subtotal = totals.find((t: any) => t.type === 'subtotal')?.amount || 0;
  const tax = totals.find((t: any) => t.type === 'tax')?.amount || 0;
  const shipping = totals.find((t: any) => t.type === 'shipping')?.amount || 0;

  // Create order and decrement inventory
  await db.run(`INSERT INTO orders ...`);
  await db.run(`UPDATE ucp_checkout_sessions SET status = 'completed' ...`);
}
```

## Graceful Fallback (No Payment Handler)

If a merchant has not configured Stripe (missing API keys), the UCP flow does not break. Instead, it "escalates" to the standard Fufuni web checkout.

-   The `/complete` response still returns `200 OK`.
-   `status` is set to `requires_escalation`.
-   `continue_url` points to `${baseUrl}/checkout/${sessionId}` (the Fufuni React frontend).
-   A `warning` message is added to the `messages` array in the JSON response, notifying the agent that automated payment is unavailable.

## KV Caching and Performance

To handle high-frequency requests from AI agents, all public UCP discovery routes use `kvCacheMiddleware`.

### Cache Configuration
-   **Routes**: `/.well-known/ucp`, `/ucp/v1/products`, `/ucp/v1/categories`.
-   **Bypass**: Requests with an Admin JWT bypass the cache. Requests with a Public Key (`pk_...`) or no token are cached.
-   **Invalidation**: When a product or category is updated via the Admin API, `kvInvalidateMiddleware` purges all UCP prefixes.

### Cache Indicators
Fufuni uses the `X-KV-Cache` header to indicate cache status:
-   `X-KV-Cache: HIT`: The response was served from Cloudflare KV.
-   **Header Absent**: The response was generated live (Cache Miss or Bypass).


## OpenAPI and Zod Integration

The UCP router is built using `OpenAPIHono`, ensuring that the UCP specification is always in sync with the implementation.

### Schema Definition
All UCP-specific Zod schemas are isolated in `ucp-schemas.ts`. This allows the main `ucp.ts` file to remain focused on logic.

```typescript
import { UCPCheckoutSessionSchema, CreateCheckoutBodySchema } from './ucp-schemas';

const routePostCheckoutSession = createRoute({
  method: 'post',
  path: '/ucp/v1/checkout-sessions',
  request: {
    body: { content: { 'application/json': { schema: CreateCheckoutBodySchema } } },
  },
  responses: {
    201: { 
      content: { 'application/json': { schema: UCPCheckoutSessionSchema } },
      description: 'Session created' 
    },
  },
});
```

### Path Syntax Note
Junior developers must use `{id}` in `createRoute`. While Hono's native router accepts `:id`, the OpenAPI spec generator specifically looks for the brace syntax to produce valid Swagger/Redoc documentation. Using `:id` will result in a literal `:id` string appearing in the generated `openapi.json` paths.
