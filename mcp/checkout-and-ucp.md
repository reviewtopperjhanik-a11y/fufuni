## Architecture: The UCP and Stripe Relationship

Fufuni implements the **Universal Commerce Protocol (UCP)** to provide a standardized, agent-interoperable checkout experience. In the Fufuni architecture, the checkout process is a bridge between the internal state (SQLite via Durable Objects) and external payment processors (primarily Stripe).

The lifecycle involves three distinct session types:
1.  **Cart Session**: The initial collection of items, stored in the `carts` table.
2.  **UCP Checkout Session**: An intermediate state defined by the [UCP Specification](https://ucp.dev/), stored in the `ucp_checkout_sessions` table. This acts as the "Source of Truth" for agents and the frontend during the transition from cart to payment.
3.  **Stripe Checkout Session**: The hosted payment page and transaction state managed by Stripe.

When a client calls `POST /ucp/v1/checkout-sessions`, Fufuni validates the inventory, resolves multi-currency pricing, and calculates taxes before returning a `ready_for_complete` status.

### Example: UCP Session Discovery
Agents and frontends discover the checkout capabilities via the `.well-known/ucp` endpoint.

## The Checkout Lifecycle: From Cart to Order

The checkout flow follows a strict sequence to ensure inventory integrity and tax compliance.

### 1. Cart Preparation and Inventory Reservation
Before payment is initiated, the system must transition the cart from `open` to `checked_out`. During this transition, Fufuni performs a **soft reservation** of inventory. This prevents "overselling" while the customer is entering credit card details on the Stripe page.

### 2. Shipping and Tax Resolution
Shipping rates are fetched based on the `shipping_address` stored in the cart. Taxes are then calculated using the `calculateCartTaxes` helper, which accounts for `tax_inclusive` (TTC) or tax-exclusive (HT) settings defined at the Region level.

### 3. Stripe Session Initiation
The `checkoutCart` route (or the UCP completion route) creates a Stripe Session. Fufuni passes internal IDs (like `cart_id` or `ucp_checkout_session_id`) into the Stripe **metadata** to ensure the webhook can later map the payment back to the internal records.

### Example: Initiating a Checkout Session
```typescript

  // 1. Lock the cart status to prevent modifications
  await db.run(

    await reserveInventory(db, item.sku, item.qty);

  // 3. Create Stripe Session
  const stripe = new Stripe(c.get('auth').stripeSecretKey);
  const session = await stripe.checkout.sessions.create({
    mode: 'payment',
    customer_email: cart.customer_email,
    metadata: { cart_id: cartId },
    line_items: items.map(item => ({
      price_data: {
        currency: cart.currency.toLowerCase(),
        product_data: { name: item.title },
        unit_amount: item.unit_price_cents,
      },
      quantity: item.qty,
    })),
    success_url: c.req.valid('json').success_url,
    cancel_url: c.req.valid('json').cancel_url,
  });

  return c.json({ checkout_url: session.url, stripe_checkout_session_id: session.id });
});
```

## Guest vs. Authenticated Checkout

Fufuni supports both guest and registered user flows. The primary difference lies in identity resolution and post-purchase access.

### Guest Checkout
*   **Identification**: Only a `customer_email` is required.
*   **Security**: Upon order completion, Fufuni generates a cryptographically secure `order_token`. 
*   **Access**: Guests can view their order status via `GET /orders/{id}?token={order_token}` without a JWT.
*   **Stripe**: A new Stripe Customer is created automatically by the `customer_creation: 'always'` flag in the session creation.

### Authenticated Checkout
*   **Identification**: The `authMiddleware` injects the customer ID into the context.
*   **Persistence**: Shipping addresses can be pulled from the `customer_addresses` table and pre-filled into the `ShippingAddressInput`.
*   **Metadata**: The `customer_id` is passed to Stripe to ensure the payment is linked to the existing Stripe Customer object.

## Order Finalization via Stripe Webhooks

The most critical part of the flow is handling the `checkout.session.completed` event. This is the **finalization point** where the cart or UCP session is converted into a permanent Order.

### Webhook Responsibilities:
1.  **Verification**: Verify the Stripe signature.
2.  **Mapping**: Extract `cart_id` or `ucp_checkout_session_id` from metadata.
3.  **Persistence**: Create a record in the `orders` table.
4.  **Inventory**: Convert the "Reserved" inventory into a permanent deduction from "On Hand".
5.  **Clean-up**: Delete the cart or mark the UCP session as `completed`.

### Example: Webhook Order Creation
```typescript
// apps/merchant/src/routes/ucp.ts - Internal helper for Webhooks
export async function handleUCPStripeWebhook(
  db: Database,
  stripeSessionId: string,
  stripeSession: Stripe.Checkout.Session
): Promise<void> {
  const ucpSessionId = stripeSession.metadata?.ucp_checkout_session_id;
  if (!ucpSessionId) return;

  const [session] = await db.query<any>(
    `SELECT * FROM ucp_checkout_sessions WHERE id = ?`,
    [ucpSessionId]
  );

  if (!session || session.status === 'completed') return;

  // 1. Generate Order Record
  const orderId = uuid();
  const lineItems = JSON.parse(session.line_items);
  
  await db.run(
    `INSERT INTO orders (id, number, status, customer_email, total_cents, currency, items, created_at)
     VALUES (?, ?, 'paid', ?, ?, ?, ?, ?)`,
    [
      orderId,
      `ORD-${Date.now()}`, 
      stripeSession.customer_email,
      session.grand_total,
      session.currency,
      JSON.stringify(lineItems),
      now()
    ]
  );

  // 2. Permanent Inventory Deduction
  for (const item of lineItems) {
    await db.run(
      `UPDATE inventory 
       SET on_hand = on_hand - ?, reserved = reserved - ? 
       WHERE sku = ?`,
      [item.quantity, item.quantity, item.item.id]
    );
  }

  // 3. Mark session as done
  await db.run(
    `UPDATE ucp_checkout_sessions SET status = 'completed', order_id = ? WHERE id = ?`,
    [orderId, ucpSessionId]
  );
}
```

### Table Summary: Checkout States

| Table | Status | Meaning |
| :--- | :--- | :--- |
| `carts` | `open` | Active shopping; items can change. |
| `carts` | `checked_out` | User is at Stripe; inventory is reserved. |
| `ucp_checkout_sessions` | `ready_for_complete` | UCP session is validated and awaiting payment link. |
| `ucp_checkout_sessions` | `completed` | Payment confirmed; Order created. |
| `orders` | `paid` | Finalized transaction; ready for fulfillment. |

## Handling Edge Cases: Expiration and Release

If a customer initiates checkout but never completes payment (e.g., closes the browser on the Stripe page), the inventory remains reserved. Fufuni handles this via two mechanisms:
1.  **Cart Expiration**: Carts have an `expires_at` timestamp (default 30-60 minutes).
2.  **Inventory Release**: A background task (or a cron trigger in Cloudflare Workers) identifies expired carts and calls `releaseReservation(db, sku, qty)` to return the stock to the available pool.

```typescript
// Internal logic for inventory management
async function releaseExpiredReservations(db: Database) {
  const expiredCarts = await db.query<any>(
    `SELECT id FROM carts WHERE status = 'checked_out' AND expires_at < ?`,
    [now()]
  );

  for (const cart of expiredCarts) {
    const items = await db.query<any>(`SELECT sku, qty FROM cart_items WHERE cart_id = ?`, [cart.id]);
    for (const item of items) {
      await releaseReservation(db, item.sku, item.qty);
    }
    await db.run(`UPDATE carts SET status = 'expired' WHERE id = ?`, [cart.id]);
  }
}
```
