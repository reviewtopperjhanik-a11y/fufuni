## UCP Architecture and Session Management

Fufuni implements the **Universal Commerce Protocol (UCP)** to enable seamless interoperability between AI agents, headless frontends, and the commerce backend. The core of this system is the `ucp_checkout_sessions` table, which serves as a state machine bridging the gap between a user's intent and a finalized Stripe transaction.

Unlike the standard cart, a UCP session is highly structured according to the `dev.ucp.shopping.checkout` specification. When a session is initiated via `POST /ucp/v1/checkout-sessions`, the framework performs real-time inventory checks and multi-currency price resolution. This session does not immediately create a Stripe PaymentIntent; instead, it prepares a "Ready for Complete" state where all totals, including taxes and line items, are calculated and stored as a snapshot.

## Step-by-Step Checkout Lifecycle

The flow from a cart to a completed order follows a strict state transition model managed by Hono routes in `apps/merchant/src/routes/ucp.ts`.

1.  **Session Creation**: The `POST /ucp/v1/checkout-sessions` endpoint resolves SKUs to variants, checks inventory availability, and calculates the initial subtotal.
2.  **Shipping Estimation**: The agent or user calls `POST /ucp/v1/checkout-sessions/:id/estimate-shipping` providing a `country_code`. The system queries `shipping_rates` joined with `regions` to find compatible rates for that specific destination.
3.  **Tax Computation**: Fufuni uses a built-in `computeTax()` helper. It identifies the default region (`is_default = 1`), retrieves the associated tax rates, and applies them to the subtotal.
4.  **Completion**: The `POST /ucp/v1/checkout-sessions/:id/complete` endpoint is called. If the `handler_id` is `stripe_checkout`, Fufuni generates a Stripe Checkout URL. The session status moves to `complete_in_progress`.
5.  **Finalization**: The user completes payment on Stripe's hosted page. Stripe sends a `checkout.session.completed` webhook back to Fufuni.

## Tax Calculation and Total Validation

A critical verified fact in Fufuni's UCP implementation is the calculation of the `grand_total`. The system ensures that `grand_total = subtotal + taxAmount`. Tax amounts are derived by querying `tax_rates` linked to the store's default region.

The `computeTax` function performs a database lookup to ensure the tax rate is current before every session update or completion.

### Example: UCP Tax Logic implementation

This snippet reflects how the backend ensures the totals remain consistent within the UCP envelope.

```typescript
/**
 * Internal logic for UCP Total Calculation
 * grand_total = subtotal + taxAmount
 */
async function computeTax(db: Database, subtotalCents: number): Promise<TaxResult> {
  const [defaultTax] = await db.query<{ rate: number; name: string }>(
    `SELECT tr.rate, tr.name
     FROM tax_rates tr
     JOIN regions r ON r.id = tr.region_id
     WHERE r.is_default = 1
     LIMIT 1`
  );

  if (!defaultTax || defaultTax.rate === 0) {
    return { taxAmount: 0, taxRate: 0, taxLabel: '' };
  }

  // Rounding to nearest cent
  const taxAmount = Math.round(subtotalCents * (defaultTax.rate / 100));
  
  return {
    taxAmount,
    taxRate: defaultTax.rate,
    taxLabel: defaultTax.name || `VAT ${defaultTax.rate}%`,
  };
}
```

## Handling Guest vs. Authenticated Checkouts

Fufuni supports both guest and authenticated checkout flows through the UCP `identity_linking` capability.

*   **Guest Checkout**: Requires no JWT. The session is identified by the `ucp_checkout_session_id`. After the order is finalized, the customer receives an `order_token` (typically via email/webhook) which allows them to view their order status without a full account.
*   **Authenticated Checkout**: Uses OAuth 2.0 (`dev.ucp.common.identity_linking`). If an agent provides an identity token, the `customer_id` is linked during the session creation. This allows the order to appear in the user's account dashboard automatically.

In both cases, the `customer_email` is a mandatory field for Stripe session creation to ensure the merchant can track the buyer within the Stripe Dashboard.

## Finalizing Orders via Stripe Webhooks

The UCP flow is asynchronous. The order record is not created when the Stripe URL is generated; it is created only when Fufuni receives a verified webhook from Stripe. The `handleUCPStripeWebhook` function is responsible for this transition.

The function performs three critical tasks:
1.  **Atomically create the Order**: Maps UCP line items to the Fufuni `orders` table.
2.  **Status Transition**: Updates the `ucp_checkout_sessions` status to `completed`.
3.  **Inventory Deduction**: Decrements `on_hand` and `reserved` stock levels.

### Example: Webhook Order Finalization

```typescript
export async function handleUCPStripeWebhook(
  db: Database,
  stripeSessionId: string,
  stripeSession: Stripe.Checkout.Session
): Promise<void> {
  const ucpSessionId = stripeSession.metadata?.ucp_checkout_session_id;
  if (!ucpSessionId) return;

  // 1. Verify session exists and isn't already processed
  const [session] = await db.query<any>(
    `SELECT * FROM ucp_checkout_sessions WHERE id = ? AND stripe_session_id = ?`,
    [ucpSessionId, stripeSessionId]
  );
  if (!session || session.status === 'completed') return;

  // 2. Prepare Order Data
  const orderId = uuid();
  const lineItems = JSON.parse(session.line_items);
  const totals = JSON.parse(session.totals);
  const grandTotal = totals.find((t: any) => t.type === 'grand_total')?.amount || 0;

  // 3. Insert Order Record
  await db.run(
    `INSERT INTO orders (id, number, status, customer_email, total_cents, currency, items, created_at)
     VALUES (?, ?, ?, ?, ?, ?, ?, ?)`,
    [
      orderId,
      `ORD-${Date.now()}`,
      'paid',
      stripeSession.customer_email,
      grandTotal,
      session.currency,
      JSON.stringify(lineItems),
      new Date().toISOString()
    ]
  );

  // 4. Update UCP Session and Inventory
  await db.run(`UPDATE ucp_checkout_sessions SET status = 'completed', order_id = ? WHERE id = ?`, [orderId, ucpSessionId]);
  
  for (const item of lineItems) {
    await db.run(
      `UPDATE inventory SET on_hand = on_hand - ?, reserved = reserved - ? WHERE sku = ?`,
      [item.quantity, item.quantity, item.item.id]
    );
  }
}
```

## Catalog Discovery (UCP Browse)

To facilitate the checkout flow, AI agents must first discover products. The `dev.ucp.shopping.browse` and `dev.ucp.shopping.catalog` capabilities provide standardized endpoints for this purpose. These endpoints return localized strings and multi-currency pricing relative to the store's configuration.

### Example: Querying the Catalog

```typescript
// Example: Agent searching for 'T-Shirt' in a specific category
// GET /ucp/v1/products?q=T-Shirt&category=apparel&limit=5
async function searchCatalog(query: string, categoryHandle: string) {
  const params = new URLSearchParams({
    q: query,
    category: categoryHandle,
    limit: '5'
  });

  const response = await fetch(`/ucp/v1/products?${params.toString()}`);
  const data = await response.json();

  // Each item includes min_price_cents and currency_code
  return data.items.map((p: any) => ({
    name: p.title,
    price: `${p.min_price_cents / 100} ${p.currency_code}`
  }));
}
```
