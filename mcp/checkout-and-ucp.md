## Universal Commerce Protocol (UCP)

The Universal Commerce Protocol (UCP) in Fufuni acts as a generic, state-agnostic validation layer. While standard checkout routes handle the transition of a cart into a persistent order, the UCP endpoint provides the frontend with a "dry-run" of the cart's logic—calculating taxes, resolving multi-currency pricing, and verifying inventory—without initiating a payment or locking a checkout session.

### UCP Endpoint and Usage

Call `POST /v1/ucp` whenever the cart content changes (adding items, changing quantities, or applying a discount). This allows the UI to display an accurate order summary including tax and shipping before the user proceeds to the final checkout.

```typescript
import { OpenAPIHono, createRoute, z } from '@hono/zod-openapi';
import { ApiError, type HonoEnv } from '../types';
import { getDb } from '../db';
import { resolveVariantPrice, getCurrencyIdFromCode } from '../lib/pricing';
import { calculateCartTaxes } from '../lib/tax';

const UCPBody = z.object({
  items: z.array(z.object({
    sku: z.string(),
    qty: z.number().int().positive(),
  })),
  currency: z.string().length(3),
  shipping_country: z.string().length(2).optional(),
});

const ucpRoute = createRoute({
  method: 'post',
  path: '/v1/ucp',
  tags: ['UCP'],
  summary: 'Generic cart validation and price computation',
  request: {
    body: { content: { 'application/json': { schema: UCPBody } } },
  },
  responses: {
    200: {
      description: 'Computed cart totals and validated items',
      content: { 'application/json': { schema: z.object({
        items: z.array(z.any()),
        currency: z.string(),
        subtotal: z.number(),
        taxTotal: z.number(),
        total: z.number(),
      }) } },
    },
  },
});

const ucpApp = new OpenAPIHono<HonoEnv>();

ucpApp.openapi(ucpRoute, async (c) => {
  const { items, currency, shipping_country } = c.req.valid('json');
  const db = getDb(c.var.db);
  const currencyId = await getCurrencyIdFromCode(db, currency);

  if (!currencyId) throw ApiError.invalidRequest(`Currency ${currency} not supported`);

  let subtotal = 0;
  const resolvedItems = [];

  for (const entry of items) {
    const [variant] = await db.query<any>(
      `SELECT v.*, p.title as product_title FROM variants v 
       JOIN products p ON v.product_id = p.id WHERE v.sku = ?`, 
      [entry.sku]
    );

    if (!variant) throw ApiError.notFound(`SKU ${entry.sku} not found`);

    const unitPrice = await resolveVariantPrice(db, variant.id, currencyId);
    const itemSubtotal = unitPrice * entry.qty;
    subtotal += itemSubtotal;

    resolvedItems.push({
      sku: variant.sku,
      title: variant.product_title,
      quantity: entry.qty,
      unitPrice,
      subtotal: itemSubtotal,
    });
  }

  // Generic tax calculation (Dry run)
  const taxRate = 0.20; // Simplified for example
  const taxTotal = Math.round(subtotal * taxRate);

  return c.json({
    items: resolvedItems,
    currency,
    subtotal,
    taxTotal,
    total: subtotal + taxTotal,
  }, 200);
});
```

### When to call UCP
The frontend should call this endpoint:
1.  **On Mount**: To validate a persisted local cart against live prices/inventory.
2.  **On Update**: Immediately after a user changes quantities in the cart drawer.
3.  **On Address Change**: If the user enters a postal code or country, as this triggers tax and shipping re-calculation.

## Stripe Checkout Implementation

The `POST /v1/checkout` endpoint is the gateway to finalizing a purchase. Unlike UCP, this route is side-effect heavy: it creates a "Pending" order in the SQLite database, reserves inventory in the Durable Object, and communicates with Stripe to generate either a `clientSecret` (for embedded elements) or a `sessionId` (for Stripe-hosted checkout).

### Endpoint Specification and Auth

This endpoint requires the `customerAuthMiddleware`. The order will be automatically associated with the `sub` (Subject) found in the Auth0 JWT.

```typescript
import { createRoute, z } from '@hono/zod-openapi';
import { customerAuthMiddleware } from '../middleware/auth';

export const checkoutRoute = createRoute({
  method: 'post',
  path: '/v1/checkout',
  summary: 'Initiate Stripe checkout session',
  security: [{ bearerAuth: [] }],
  request: {
    body: {
      content: {
        'application/json': {
          schema: z.object({
            cartId: z.string().uuid(),
            success_url: z.string().url(),
            cancel_url: z.string().url(),
          }),
        },
      },
    },
  },
  responses: {
    200: {
      description: 'Checkout metadata',
      content: {
        'application/json': {
          schema: z.object({
            clientSecret: z.string().nullable(),
            sessionId: z.string().nullable(),
            orderId: z.string().uuid(),
          }),
        },
      },
    },
    409: { description: 'Inventory conflict' },
  },
});
```

### Success Flow Logic
When a request hits this endpoint:
1.  **Validation**: The system verifies the cart exists and belongs to the authenticated user.
2.  **Inventory Check**: A synchronous call is made to the Inventory Durable Object.
3.  **Order Creation**: An entry is created in the `orders` table with status `pending`.
4.  **Stripe Call**: The `stripe.ts` library calls the Stripe API.
5.  **Response**: The frontend receives the `orderId` and the Stripe redirect/element identifier.

## Inventory Validation

Inventory validation in Fufuni is strictly synchronous and occurs within a transaction. This prevents "overselling" in high-concurrency environments.

### The Conflict Mechanism
Inside `POST /v1/checkout`, the system loops through all cart items and attempts to reserve stock. If `on_hand - reserved < requested_qty`, the system throws an `ApiError.conflict`.

```typescript
// Example of the check inside the checkout logic
const available = await getAvailableQty(db, item.sku);
if (available < item.qty) {
  // If this fires, the entire HTTP request returns 409 Conflict
  throw ApiError.insufficientInventory(item.sku); 
}

// Logic inside lib/inventory.ts
export async function reserveInventory(db: Database, sku: string, qty: number) {
  const result = await db.run(
    `UPDATE inventory 
     SET reserved = reserved + ? 
     WHERE sku = ? AND (on_hand - reserved) >= ?`,
    [qty, sku, qty]
  );
  
  if (result.changes === 0) {
    throw new ApiError(409, 'insufficient_inventory', `Not enough stock for ${sku}`);
  }
}
```

## Internal Tax Computation

Fufuni uses an internal tax engine that calculates taxes line-by-line. This is necessary because Stripe requires precise amounts to match the checkout total exactly, especially when using tax-inclusive pricing.

### Calculation Logic
The `calculateCartTaxes` helper performs the following:
1.  Identifies the `region_id` from the cart.
2.  Fetches applicable `tax_rates` for the target country.
3.  Distinguishes between **Tax Inclusive** (TTC) and **Tax Exclusive** (HT).
4.  If inclusive, it "backs out" the tax from the unit price: `PriceHT = PriceTTC / (1 + Rate)`.

```typescript
// Internal logic for tax-inclusive balancing
const { taxes, itemRates } = await calculateCartTaxes(db, cartId, countryCode);

// When preparing Stripe line items:
const unitAmount = taxInclusive 
  ? Math.round(item.unit_price_cents / (1 + (itemRates.get(item.sku) || 0) / 100))
  : item.unit_price_cents;
```

## Stripe Integration: Sessions vs. Intents

Fufuni supports two flows through its `stripe.ts` REST wrapper:

1.  **Checkout Session Flow**: Returns a `sessionId`. Used for the standard redirect to `checkout.stripe.com`. This is the default for `POST /v1/checkout`.
2.  **PaymentIntent Flow**: Returns a `clientSecret`. Used when the frontend uses Stripe Elements (embedded credit card fields) directly on the Fufuni checkout page.

### The `stripe.ts` Wrapper
Since Fufuni runs on Cloudflare Workers, we avoid the heavy Stripe Node.js SDK and use a lightweight REST wrapper that uses `fetch`.

```typescript
// apps/merchant/src/lib/stripe.ts example logic
export async function createStripeSession(key: string, params: URLSearchParams) {
  const response = await fetch('https://api.stripe.com/v1/checkout/sessions', {
    method: 'POST',
    headers: {
      'Authorization': `Bearer ${key}`,
      'Content-Type': 'application/x-www-form-urlencoded',
    },
    body: params.toString(),
  });
  return response.json();
}
```

## Stripe Webhook Handling

Webhooks are critical for moving orders from `pending` to `paid`. Fufuni listens for events at `POST /v1/webhooks/stripe`.

### Handled Events and Side Effects

| Event | Side Effect |
| :--- | :--- |
| `payment_intent.succeeded` | Updates order status to `paid`. Triggers confirmation email. |
| `payment_intent.payment_failed` | Updates order status to `failed`. Releases inventory reservations. |
| `checkout.session.completed` | Used for 3DS or bank transfer flows. Validates the session and marks order `paid`. |
| `charge.refunded` | Updates order status to `refunded`. |

```typescript
// Webhook implementation snippet
app.post('/v1/webhooks/stripe', async (c) => {
  const signature = c.req.header('stripe-signature');
  const body = await c.req.text();
  
  // Verify signature using STRIPE_WEBHOOK_SECRET
  const event = verifyStripeEvent(body, signature, c.env.STRIPE_WEBHOOK_SECRET);

  if (event.type === 'payment_intent.succeeded') {
    const intent = event.data.object;
    await db.run(
      `UPDATE orders SET status = 'paid', updated_at = ? WHERE stripe_payment_intent_id = ?`,
      [now(), intent.id]
    );
    // Logic to move 'reserved' inventory to 'sold' (deduct from on_hand)
  }
});
```

## Required Wrangler Secrets

For Stripe integration to function, you must configure your environment using Wrangler secrets. These are encrypted at rest and injected into the Worker's environment at runtime. Do **not** store these in a `.dev.vars` or `.env` file for production.

Execute these commands in your terminal:

```bash
# The secret key from your Stripe Dashboard (starts with sk_live_ or sk_test_)
wrangler secret put STRIPE_SECRET_KEY

# The webhook signing secret from the Stripe Dashboard Webhooks section (starts with whsec_)
wrangler secret put STRIPE_WEBHOOK_SECRET

# Optional: The Public Key used by the frontend for Stripe Elements
wrangler secret put STRIPE_PUBLISHABLE_KEY
```

To verify the secrets are set for your current environment:
```bash
wrangler secret list
```
