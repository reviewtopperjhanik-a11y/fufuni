## Universal Commerce Protocol (UCP)

The Universal Commerce Protocol (UCP) serves as the interoperability layer between the Fufuni backend and external agents or the frontend's pre-checkout summary logic. Unlike the final checkout process, UCP is stateless regarding payment; it provides a generic validation and price-computation endpoint.

### Purpose and Usage
You should call the UCP endpoint whenever the cart contents change (e.g., item added, quantity updated, discount applied) but before the user initiates a final payment. It resolves multi-currency pricing, validates inventory availability, and estimates taxes based on the default region or provided location.

**Endpoint:** `POST /v1/ucp`
**Auth Required:** None (Public or Session-based)

```typescript
// Example UCP Request/Response shape for frontend integration
import { z } from '@hono/zod-openapi';

// The request body contains the raw cart state
const ucpRequest = {
  line_items: [
    { item: { id: "SKU-PRO-001" }, quantity: 2 }
  ],
  currency: "USD"
};

/**
 * UCP Response provides the authoritative price calculation.
 * It includes per-item tax and subtotal breakdowns.
 */
const ucpResponseExample = {
  items: [
    {
      sku: "SKU-PRO-001",
      title: "Classic Tee",
      quantity: 2,
      unitPrice: 2500, // Cents
      tax: 500,
      subtotal: 5500
    }
  ],
  currency: "USD",
  total: 5500,
```

### UCP Implementation in Hono
The implementation relies on `resolveVariantPrice` and `computeTax` to ensure that even if the base price is stored in EUR, a USD request is handled accurately via the multi-currency pricing table.

```typescript
import { OpenAPIHono, createRoute } from '@hono/zod-openapi';
import { getDb } from '../db';
import { resolveVariantPrice, getCurrencyIdFromCode } from '../lib/pricing';

const ucpRouter = new OpenAPIHono();

const ucpRoute = createRoute({
  method: 'post',
  path: '/v1/ucp',
  summary: 'Validate cart and compute prices',
  // Schema definitions omitted for brevity
  responses: {
    200: { description: 'Computation result' }
  }
});

ucpRouter.openapi(ucpRoute, async (c) => {
  const { line_items, currency } = c.req.valid('json');
  const db = getDb(c.var.db);
  
  const currencyId = await getCurrencyIdFromCode(db, currency);
  let grandTotal = 0;
  
  const resolved = await Promise.all(line_items.map(async (li) => {
    // resolveVariantPrice handles the logic of finding the specific
    // price for the currencyId or falling back to base price.
    const unitPrice = await resolveVariantPrice(db, li.item.id, currencyId);
    const subtotal = unitPrice * li.quantity;
    grandTotal += subtotal;
    
    return {
      sku: li.item.id,
      unitPrice,
      subtotal,
      // Tax estimation logic...
    };
  }));

  return c.json({
    items: resolved,
    currency,
    total: grandTotal
  });
});
```

## Checkout Implementation

The `POST /v1/checkout` endpoint is the terminal step of the shopping journey. It transitions a temporary cart into a persistent Order record and interfaces with Stripe to facilitate payment.

### Checkout Flow and Requirements
The checkout process is strictly protected by the `customerAuthMiddleware`. This ensures that every order is associated with a verified Auth0 customer ID.

1.  **Auth:** Validates the Auth0 JWT.
2.  **Inventory Check:** Performed inside a Durable Object transaction to prevent race conditions.
3.  **Order Creation:** A new record is inserted into the `orders` table with a `pending` status.
4.  **Stripe Initiation:** Depending on the region and metadata, it creates either a `PaymentIntent` or a `CheckoutSession`.
5.  **Response:** Returns the necessary identifiers for the frontend to mount the Stripe Element or redirect.

**Endpoint:** `POST /v1/checkout`
**Response Shape:** `{ clientSecret: string, sessionId: string, orderId: string }`

```typescript
// Example: Creating a Checkout Session in the route handler
import Stripe from 'stripe';
import { ApiError, now, uuid } from '../types';

adminApp.openapi(checkoutCart, async (c) => {
  const { cartId } = c.req.valid('param');
  const auth = c.get('auth'); // Provided by customerAuthMiddleware
  const db = getDb(c.var.db);

  // 1. Validate Inventory (Synchronous)
  const items = await db.query(`SELECT * FROM cart_items WHERE cart_id = ?`, [cartId]);
  for (const item of items) {
    const available = await getAvailableQty(db, item.sku);
    if (available < item.qty) {
      // Priority Fact: Throws 409 Conflict on stock error
      throw ApiError.conflict(`Insufficient inventory for ${item.sku}`);
    }
  }

  // 2. Pre-create Order in 'pending' status
  const orderId = uuid();
  await db.run(
    `INSERT INTO orders (id, customer_id, status, total_cents, created_at) VALUES (?, ?, 'pending', ?, ?)`,
    [orderId, auth.customerId, totalCents, now()]
  );

  // 3. Initiate Stripe
  const stripe = new Stripe(c.env.STRIPE_SECRET_KEY);
  const session = await stripe.checkout.sessions.create({
    customer_email: auth.email,
    payment_method_types: ['card'],
    line_items: items.map(i => ({ /* stripe line item mapping */ })),
    mode: 'payment',
    success_url: `${c.env.FRONTEND_URL}/success?id=${orderId}`,
    cancel_url: `${c.env.FRONTEND_URL}/cart`,
    metadata: { orderId }
  });

  return c.json({
    sessionId: session.id,
    clientSecret: session.payment_intent as string,
    orderId: orderId
  }, 200);
});
```

## Inventory Validation and Logic

Inventory in Fufuni is warehouse-aware and strictly validated during the checkout transaction.

### Synchronous Stock Checks
The framework does not allow "overselling." When a checkout request hits the server, the `reserveInventory` helper is called. This function operates within the SQLite environment of the Durable Object, ensuring that the `on_hand - reserved` calculation is atomic.

### Error Handling
If a user attempts to checkout with items that are no longer available (e.g., someone else finished their checkout a second earlier), the system must immediately abort.

*   **Trigger:** Inside `POST /v1/checkout` before calling Stripe.
*   **Status Code:** `409 Conflict`.
*   **Payload:** Includes the specific SKU that failed validation.

```typescript
/**
 * Internal logic for inventory reservation during checkout.
 * This should be used within a transaction.
 */
async function reserveInventory(db: Database, sku: string, qty: number) {
  const result = await db.run(
    `UPDATE inventory 
     SET reserved = reserved + ? 
     WHERE sku = ? AND (on_hand - reserved) >= ?`,
    [qty, sku, qty]
  );

  if (result.changes === 0) {
    // If no rows were updated, it means the condition (on_hand - reserved) >= qty failed
    throw ApiError.conflict(`SKU ${sku} is no longer available in the requested quantity.`);
  }
}
```

## Tax Computation inside Checkout

Fufuni uses an internal tax engine that calculates taxes based on the shipping address's country and the `tax_code` associated with the products.

### Tax Engine Logic
1.  **Identify Region:** The cart is linked to a `region_id`.
2.  **Look up Tax Rates:** The system queries `tax_rates` filtered by the cart's `shipping_country`.
3.  **Inclusive vs Exclusive:** 
    *   If the Region is `tax_inclusive = 1`, the system calculates the tax portion already inside the price (TTC).
    *   If not, it calculates the tax on top of the subtotal (HT).
4.  **Stripe Reporting:** Taxes are sent to Stripe as separate line items or by enabling Stripe Tax with specific `tax_code` metadata.

```sql
-- Querying tax rates for a checkout session
SELECT tr.rate_percentage, tr.display_name, tr.tax_inclusive
FROM tax_rates tr
JOIN regions r ON r.id = tr.region_id
WHERE (tr.country_code = ? OR tr.country_code IS NULL)
  AND r.id = ? 
  AND tr.status = 'active';
```

## Stripe Integration and Webhooks

Fufuni uses a thin wrapper for Stripe to maintain compatibility with the Cloudflare Workers environment, avoiding the heavy Node.js dependencies of some SDKs while providing full type safety for API calls.

### PaymentIntent vs Checkout Session
*   **Checkout Session:** Used for the standard redirect-based flow (Stripe-hosted page). It is the default for most 3DS and European payment method flows.
*   **PaymentIntent:** Used when the frontend implements a custom "Elements" UI. The `clientSecret` returned by the checkout endpoint allows the frontend to confirm the payment directly.

### Webhook Event Handling
The endpoint `POST /v1/webhooks/stripe` handles asynchronous status updates. This is critical for 3DS payments where the user might close the browser before the redirect finishes.

| Stripe Event | Side Effect in Fufuni |
| :--- | :--- |
| `payment_intent.succeeded` | Updates Order status to `paid`, captures inventory (decrements `on_hand` and `reserved`). |
| `payment_intent.payment_failed` | Updates Order status to `failed`. |
| `checkout.session.completed` | Triggers order fulfillment logic and sends confirmation emails. |
| `charge.refunded` | Updates Order status to `refunded`. |

```typescript
// Webhook processing logic
export async function handleStripeEvent(db: Database, event: Stripe.Event) {
  const orderId = (event.data.object as any).metadata?.orderId;
  
  switch (event.type) {
    case 'payment_intent.succeeded':
      await db.run(
        `UPDATE orders SET status = 'paid', updated_at = ? WHERE id = ?`,
        [now(), orderId]
      );
      // Logic to finalize inventory deduction...
      break;
    case 'payment_intent.payment_failed':
      await db.run(
        `UPDATE orders SET status = 'failed', updated_at = ? WHERE id = ?`,
        [now(), orderId]
      );
      break;
  }
}
```

## Configuration and Secrets

To enable checkout functionality, you must configure the following secrets in your Cloudflare environment. These secrets are accessed via `c.env` in Hono or the environment object in the Worker.

### Required Wrangler Secrets
Run these commands from your terminal to set up the production or staging environment:

```bash
# The Stripe Secret Key for API authentication (sk_...)
wrangler secret put STRIPE_SECRET_KEY

# The Webhook Secret for verifying incoming Stripe events (whsec_...)
wrangler secret put STRIPE_WEBHOOK_SECRET

# The Auth0 Domain for customer authentication validation
wrangler secret put AUTH0_DOMAIN
```

**Note:** Never place these in a `.env` file that gets committed to version control. Fufuni relies on the `STRIPE_SECRET_KEY` being available to the `stripe.ts` wrapper for every checkout-related request. If the secret is missing, the checkout initialization will throw a `500 Internal Server Error`.
