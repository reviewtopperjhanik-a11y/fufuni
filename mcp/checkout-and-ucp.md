## UCP and Checkout Architecture

Fufuni implements the **Universal Commerce Protocol (UCP)** to enable agent-to-commerce interoperability. While the standard checkout flow (found in `routes/checkout.ts`) is designed for traditional web frontends, the UCP flow (found in `routes/ucp.ts`) provides a standardized interface for AI agents and cross-platform clients to browse catalogs and initiate transactions.

The core of this architecture is the `ucp_checkout_sessions` table. Unlike the standard `carts` table which is volatile and tied to a web session, a UCP session acts as a persistent source of truth for the entire lifecycle of a transaction—from line item resolution to payment escalation.

### UCP Session State Machine
UCP sessions transition through the following statuses:
1.  **incomplete**: Session created but missing required info (e.g., valid line items).
2.  **ready_for_complete**: Items resolved, prices locked, and buyer info present.
3.  **complete_in_progress**: The buyer has been handed off to a payment handler (e.g., Stripe).
4.  **completed**: Payment confirmed via webhook, order created, and inventory deducted.
5.  **requires_escalation**: Automated completion failed or no payment handler is available; requires manual web intervention.
6.  **canceled**: Explicitly terminated by the client or expired.

## UCP Endpoint Inventory

The UCP implementation provides a full RESTful suite for session management, discovery, and browsing. All routes are defined using `@hono/zod-openapi` to ensure the `openapi.json` remains the single source of truth.

### Session Management
-   **POST `/ucp/v1/checkout-sessions`**: Creates a new session. Resolves SKUs into line items and performs initial pricing.
-   **GET `/ucp/v1/checkout-sessions/{id}`**: Returns the current session state, including totals and available payment handlers.
-   **PUT `/ucp/v1/checkout-sessions/{id}`**: Full replacement. Re-resolves all prices and taxes based on the new payload.
-   **PATCH `/ucp/v1/checkout-sessions/{id}`**: Partial update. Modifies buyer fields or item quantities **without** full SKU re-resolution.
-   **DELETE `/ucp/v1/checkout-sessions/{id}`**: Cancels an active session.

### Implementation: Partial Updates (PATCH)
The `PATCH` endpoint is optimized for speed. It merges JSON blobs for the buyer and performs in-place arithmetic for quantities. It returns a `303 See Other` redirecting to the `GET` endpoint to ensure the client receives the updated state.

## The Complete Checkout Flow

The flow bridges the gap between the UCP session and the physical Fufuni order system.

### 1. Estimation and Shipping
Before completion, agents call `POST /ucp/v1/checkout-sessions/{id}/estimate-shipping` with a `country_code`. This filters the `shipping_rates` table by region and country, returning a list of options ordered by price.

### 2. Initiation (`/complete`)
Calling `POST /.../{id}/complete` triggers the payment phase.
-   If Stripe is configured: The session status moves to `complete_in_progress`, and the response includes a Stripe Checkout URL in `continue_url` with status `requires_escalation`.
-   If No Handler: The system gracefully falls back by providing the Fufuni web checkout URL in `continue_url`.

### 3. Finalization (Stripe Webhook)
The order is not created until the `checkout.session.completed` webhook is received. The function `handleUCPStripeWebhook` performs the following:
-   Extracts `subtotal`, `tax`, and `shipping` amounts independently from the UCP session `totals` array.
-   Persists the `orders` record.
-   Sets `ucp_checkout_sessions.status = 'completed'`.
-   **Decrements Inventory**: It physically reduces `on_hand` and `reserved` stock in the `inventory` table.

```typescript
export async function handleUCPStripeWebhook(
  db: Database,
  stripeSessionId: string,
  stripeSession: Stripe.Checkout.Session
): Promise<void> {
  const ucpSessionId = stripeSession.metadata?.ucp_checkout_session_id;
  if (!ucpSessionId) return;

  const [session] = await db.query<any>(
    `SELECT * FROM ucp_checkout_sessions WHERE id = ?`, [ucpSessionId]
  );

  const totals = JSON.parse(session.totals || '[]');
  const subtotal = totals.find((t: any) => t.type === 'subtotal')?.amount || 0;
  const tax = totals.find((t: any) => t.type === 'tax')?.amount || 0;
  const shipping = totals.find((t: any) => t.type === 'shipping')?.amount || 0;

  // Create the final order row
  await db.run(
    `INSERT INTO orders (id, status, subtotal_cents, tax_cents, shipping_cents, total_cents ...) 
     VALUES (?, 'paid', ?, ?, ?, ...)`,
    [uuid(), subtotal, tax, shipping, ...]
  );

  // Mark session as completed
  await db.run(`UPDATE ucp_checkout_sessions SET status = 'completed' WHERE id = ?`, [ucpSessionId]);
}
```

## Agentic Browsing and Catalog Capabilities

UCP provides specialized endpoints for agents to discover products and categories. These routes strictly filter for `status = 'active'`.

### Product Search and Resolution
`GET /ucp/v1/products` supports full-text search (`q`) and category filtering. Image resolution is handled via `COALESCE` in SQL to ensure the most specific image is returned (Variant Thumbnail > Variant Image > Product Image).

```sql
SELECT p.id, p.title,
       COALESCE(v.thumbnail_url, v.image_url, p.image_url) as thumbnail_url,
       COALESCE(v.image_url, p.image_url) as image_url,
       MIN(vp.price_cents) as min_price_cents
FROM products p
LEFT JOIN variants v ON v.product_id = p.id AND v.status = 'active'
LEFT JOIN variant_prices vp ON vp.variant_id = v.id
WHERE p.status = 'active'
GROUP BY p.id
```

### Category Hierarchy
`GET /ucp/v1/categories` returns all active categories. Developers must use the `position` column for ordering (not `sort_order`).

## Performance and KV Caching

To handle high-frequency agent requests without overloading the SQLite (Durable Object) backend, UCP public routes utilize Cloudflare KV caching via `kvCacheMiddleware`.

### Cache Strategy
-   **Target Routes**: `/.well-known/ucp`, `/ucp/v1/products`, `/ucp/v1/categories`.
-   **Bypass**: Requests containing an Admin JWT bypass the cache. Requests with a `Bearer pk_...` (public key) or no token are cached.
-   **Headers**: When a response is served from the cache, the `X-KV-Cache: HIT` header is appended. If the header is absent, the response was generated fresh from the database.
-   **Invalidation**: Any successful `POST`, `PATCH`, or `DELETE` on products or categories triggers `kvInvalidateMiddleware`, purging the cached prefixes.

## OpenAPI Integration Conventions

Fufuni uses strict Zod-OpenAPI conventions to generate its documentation.

### Path Syntax
Always use OpenAPI-style braces `{id}` in the `path` property of `createRoute()`. 
-   **Correct**: `path: '/ucp/v1/checkout-sessions/{id}'`
-   **Incorrect**: `path: '/ucp/v1/checkout-sessions/:id'`

The Hono router internally converts `{id}` to `:id` for matching, but using the colon syntax directly results in malformed paths (e.g., `/:id`) appearing in the generated `openapi.json` spec, which breaks client SDK generation.

### Router Mounting
The UCP router must be mounted to the main app using `app.route('/', ucp)`. Mounting to an empty string `''` or a specific prefix like `app.route('/ucp', ucp)` while also defining `/ucp` inside the sub-router can cause "Double Slash" issues in the path resolution (e.g., `//ucp/v1/...`).
