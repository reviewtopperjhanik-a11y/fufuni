## Checkout and UCP Flow Reference
The Universal Commerce Protocol (UCP) is an open standard for agent-to-commerce interoperability. In the context of the Fufuni e-commerce framework, UCP is used to manage checkout sessions. This reference document outlines the architecture, step-by-step flow, and key differences between guest and authenticated user checkout.

### Architecture
The UCP checkout flow is closely tied to Stripe PaymentIntents. When a user initiates the checkout process, a UCP checkout session is created, which in turn creates a Stripe PaymentIntent. The PaymentIntent is used to manage the payment process, while the UCP checkout session manages the overall checkout flow.

The `ucp_checkout_sessions` table stores the intermediate state between session creation and finalization. This table is used to track the progress of the checkout session and ensure that the order is finalized correctly.

### Step-by-Step Flow
Here is the step-by-step flow from cart to completed order:

1. **Create Cart**: The user adds items to their cart, and a new cart session is created.
2. **Create UCP Checkout Session**: The user initiates the checkout process, and a new UCP checkout session is created. This creates a Stripe PaymentIntent and stores the intermediate state in the `ucp_checkout_sessions` table.
3. **Stripe PaymentIntent**: The Stripe PaymentIntent is used to manage the payment process. The user is redirected to the Stripe payment page to complete the payment.
4. **Stripe Webhook**: After the user completes the payment, Stripe sends a webhook notification to the Fufuni backend with the event `checkout.session.completed`.
5. **Finalize Order**: The Fufuni backend receives the webhook notification and finalizes the order. This involves updating the order status, sending confirmation emails, and completing any other necessary tasks.

### Differences between Guest Checkout and Authenticated User Checkout
The main difference between guest checkout and authenticated user checkout is the requirement for a JWT (JSON Web Token). Guest checkout does not require a JWT, while authenticated user checkout requires a valid JWT to complete the checkout process.

Here is an example of a guest checkout:
```typescript
// Create a new cart session
const cartSession = await createCartSession();

// Create a new UCP checkout session
const ucpCheckoutSession = await createUcpCheckoutSession(cartSession.id);

// Redirect the user to the Stripe payment page
return redirect(`https://stripe.com/${ucpCheckoutSession.paymentIntentId}`);
```

And here is an example of an authenticated user checkout:
```typescript
// Get the authenticated user's JWT
const jwt = getAuthenticatedUserJwt();

// Create a new cart session
const cartSession = await createCartSession();

// Create a new UCP checkout session
const ucpCheckoutSession = await createUcpCheckoutSession(cartSession.id, jwt);

// Redirect the user to the Stripe payment page
return redirect(`https://stripe.com/${ucpCheckoutSession.paymentIntentId}`);
```

### Handling the Stripe Webhook
The Stripe webhook is used to finalize the order after the user completes the payment. Here is an example of how to handle the Stripe webhook:
```typescript
// Set up the Stripe webhook endpoint
app.post('/stripe', async (req, res) => {
  const event = req.body;

  // Check if the event is a checkout.session.completed event
  if (event.type === 'checkout.session.completed') {
    // Get the order token from the event
    const orderToken = event.data.object.metadata.order_token;

    // Finalize the order
    await finalizeOrder(orderToken);

    // Return a success response
    return res.send('Order finalized successfully');
  }

  // Return an error response if the event is not a checkout.session.completed event
  return res.status(400).send('Invalid event type');
});
```
In this example, the Stripe webhook endpoint is set up to listen for the `checkout.session.completed` event. When this event is received, the order is finalized using the `finalizeOrder` function.
