## Overview
Fufuni is an e-commerce platform built on Cloudflare Workers, Durable Objects, and React, providing a free, production-ready solution for hosting online stores. With a focus on performance, security, and ease of use, Fufuni enables merchants to manage their stores without incurring additional costs, thanks to its optimized use of free tiers from Cloudflare, Auth0, and other services.

## Stack
| Layer | Technology | Notes |
| --- | --- | --- |
| Frontend | React 19, Vite, HeroUI v3 | Client-side rendering, responsive design |
| Backend | Cloudflare Workers, Hono, Zod-OpenAPI | Serverless API, automatic API documentation |
| Database | Durable Object SQLite | Serverless, globally consistent, no cold starts |
| Identity & Auth | Auth0 | RBAC permissions, secure authentication |
| Storage | Cloudflare R2 | Object storage for images and other assets |
| Caching | Cloudflare KV | Key-value store for caching frequently accessed data |
| Deployment | GitHub Actions, Cloudflare Workers | Automated deployment and rollback |

### Monorepo structure
The Fufuni monorepo is divided into three main workspaces:
* `apps/client`: React SPA frontend
* `apps/merchant`: Hono Worker and Durable Object backend
* `apps/mcp`: MCP server
Each workspace has its own specific purpose and is managed independently, while still being part of the larger Fufuni ecosystem.

### Request lifecycle
When a client sends a request to the Fufuni platform, it flows through the following stages:
1. Client → Cloudflare Worker: The client sends a request to the Cloudflare Worker, which acts as the entry point for the application.
2. Cloudflare Worker → Durable Object: The Worker forwards the request to the Durable Object, which handles the business logic and interacts with the database.
3. Durable Object → SQLite: The Durable Object executes SQL queries against the SQLite database, retrieving or updating data as needed.
4. SQLite → Durable Object → Cloudflare Worker → Client: The response flows back through the Durable Object, Worker, and finally reaches the client.

### Key conventions
Some key conventions to keep in mind when working with Fufuni:
* Naming: Consistent naming conventions are used throughout the codebase, with clear and descriptive variable and function names.
* Error handling: Errors are handled using a centralized error handling mechanism, with clear and descriptive error messages.
* Auth: Authentication is handled using Auth0, with RBAC permissions stored on the access token.
* i18n: Internationalization is supported through the use of JSON files for translations, with fallback resolution for missing translations.
* Database schema changes: All schema changes must be applied in three places simultaneously: the `SCHEMA` constant in `do.ts`, the `ensureInitialized()` function in `do.ts`, and a new numbered SQL file in `apps/merchant/migrations/`.
