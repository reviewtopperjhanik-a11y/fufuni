## Framework Overview
Fufuni is an open-source e-commerce framework built on top of Cloudflare Workers, Durable Objects, and React. It provides a production-ready commerce backend with a headless architecture, allowing for scalable and secure deployment of online stores.

## Stack
| Layer | Technology | Notes |
| --- | --- | --- |
| Frontend | React 19 + Vite + HeroUI v3 | Client-side rendering with server-side rendering (SSR) support |
| Backend | Cloudflare Workers + Durable Objects (SQLite) | Serverless API with a single Durable Object for data storage |
| Database | SQLite | Embedded database within the Durable Object |
| Image Storage | Cloudflare R2 | Object storage for product images |
| Caching | Cloudflare KV | Key-value store for caching frequently accessed data |
| Authentication | Auth0 | Identity and access management with Role-Based Access Control (RBAC) |
| Deployment | Cloudflare Workers, GitHub Pages | Automated deployment with GitHub Actions workflows |

### Monorepo structure
The Fufuni monorepo consists of three main workspaces:
* `apps/client`: React SPA frontend with Vite and HeroUI v3
* `apps/merchant`: Hono Worker and Durable Object backend with SQLite database
* `apps/mcp`: MCP server (not directly related to the Fufuni framework)

Key directories and their purpose:
* `apps/client/src`: Frontend source code with components, pages, and utilities
* `apps/merchant/src`: Backend source code with API routes, database schema, and utilities
* `apps/merchant/migrations`: Database schema migration files

### Request lifecycle
Here's an overview of how a request flows from the client to the backend:
1. Client (React SPA) sends a request to the Cloudflare Worker endpoint
2. Cloudflare Worker receives the request and forwards it to the Durable Object (MerchantDO)
3. MerchantDO executes the request, interacting with the SQLite database as needed
4. SQLite database stores and retrieves data for the MerchantDO
5. MerchantDO returns the response to the Cloudflare Worker
6. Cloudflare Worker returns the response to the client (React SPA)

### Key conventions
* Naming: Use camelCase for variable and function names, and PascalCase for component names
* Error handling: Use `ApiError` for backend errors, and `try`-`catch` blocks for error handling
* Authentication: Use Auth0 for identity and access management, with RBAC permissions on access tokens
* Internationalization (i18n): Use JSON locale maps for multilingual support, with fallback resolution for missing translations
* Database schema changes: Apply changes in three places simultaneously: `SCHEMA` constant in `do.ts`, `ensureInitialized()` in `do.ts`, and a new numbered SQL file in `apps/merchant/migrations/`
