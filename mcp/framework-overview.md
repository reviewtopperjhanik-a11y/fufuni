## Framework Overview

The Fufuni e-commerce framework is a production-ready, cloud-native application built on Cloudflare Workers, Durable Objects, and SQLite. It provides a scalable, secure, and highly customizable platform for hosting online stores.

## Stack

| Layer | Technology | Notes |
| --- | --- | --- |
| Frontend | React 19 + Vite + HeroUI v3 | Single-page application with Auth0 integration |
| Backend | Cloudflare Workers (Hono + Zod-OpenAPI) | Edge API with Durable Object (SQLite) storage |
| Database | Durable Object SQLite | 100% of store state, no external database required |
| Caching | Cloudflare KV + Cache API | KV for catalog caching, Cache API for image caching |
| Authentication | Auth0 | Sole identity provider with RBAC and permission management |
| Payments | Stripe Checkout | Integrated payment gateway with webhook reconciliation |

## Monorepo Structure

The Fufuni monorepo consists of the following key directories:

* `apps/client`: React SPA (storefront + admin)
* `apps/merchant`: Cloudflare Worker (Hono + Durable Object)
* `apps/mcp`: Model Context Protocol (MCP) Worker for AI-assisted knowledge base

## Request Lifecycle

Here's an overview of how a request flows through the Fufuni framework:

1. **Client → CF Worker**: The client sends a request to the Cloudflare Worker, which acts as the entry point for the application.
2. **CF Worker → Durable Object**: The Worker sends the request to the Durable Object (MerchantDO), which is responsible for handling business logic and database interactions.
3. **Durable Object → SQLite**: The Durable Object interacts with the SQLite database to retrieve or update data.

## Key Conventions

Here are some key conventions to keep in mind when working with Fufuni:

* **Naming conventions**:
	+ Public API keys: prefixed with `pk_`
	+ Admin/secret keys: prefixed with `sk_`
* **Error handling**: Errors are handled consistently throughout the application using standardized error codes and messages.
* **Authentication**: Auth0 is the sole identity provider, and RBAC is managed via Auth0 permissions on the access token.
* **Internationalization (i18n)**: The application supports multiple locales, with locale-aware price display and multilingual product titles and descriptions.
