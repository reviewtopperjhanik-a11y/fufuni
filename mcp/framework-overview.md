## Project Description

Fufuni is a 100% free-tier, AI-native e-commerce framework designed to run entirely on the Cloudflare edge. It leverages Cloudflare Workers for logic and Durable Objects with built-in SQLite for state, eliminating the need for traditional database servers or connection pools. Built with a focus on cost-efficiency and performance, Fufuni integrates natively with Auth0 for identity, Stripe for payments, and Mailgun for transactional emails. It is one of the first open-source frameworks to implement the Universal Commerce Protocol (UCP), allowing AI agents to browse products and initiate checkouts without a traditional user interface.

## Technical Stack

The Fufuni stack is selected to remain within the generous free tiers of modern cloud providers, ensuring a $0/month operational cost for small to medium stores.

## Monorepo Structure

Fufuni uses a Turborepo-managed monorepo structure. All development tasks are orchestrated from the root, and environmental variables are injected into workspaces via `npm run dev:env`.

- `apps/client/`: The React 19 frontend. It includes the storefront, the customer portal, and the extensive admin back-office.
- `apps/merchant/`: The Cloudflare Worker backend. This contains the Hono API routes, the Durable Object logic (`do.ts`), and the database migrations.
- `apps/mcp/`: A Model Context Protocol server that exposes Fufuni's documentation and codebase structure to AI assistants like Claude or VS Code Copilot.
- `scripts/`: Cross-application automation scripts, primarily for Auth0 resource deployment and database seeding.

### Task Orchestration Example

To start the entire stack locally with your `.env` variables and Stripe webhook forwarding, use the following root command:

```bash

npm run dev:env
```

## Request Lifecycle

Fufuni processes requests at the edge, ensuring minimal latency by keeping logic and data in the same Cloudflare PoP (Point of Presence).

1.  **Entry**: A request hits the Cloudflare Worker.
2.  **Global Middleware**: Hono executes global middleware such as CORS, rate-limiting, and `kvCacheMiddleware`.
3.  **DO Stubbing**: The Worker identifies the Durable Object ID (usually 'default') and creates a stub.
4.  **Routing**: The request is routed to a specific Hono sub-router (e.g., `/v1/products`).
5.  **Authorization**: `authMiddleware` validates the Auth0 JWT or API key (`pk_` or `sk_`).
6.  **DO Execution**: The Hono handler calls a method on the Durable Object stub. This transfers execution to the JS isolate where the SQLite database resides.
7.  **Database Ops**: The Durable Object executes SQL queries against its local SQLite file.
8.  **Response**: The result is serialized and returned through the Worker to the client.

### Route Implementation Example

The following demonstrates a typical authenticated admin route in `apps/merchant/src/routes/catalog.ts`:

```typescript
import { OpenAPIHono, createRoute, z } from '@hono/zod-openapi';
import { authMiddleware } from '../middleware/auth';

const adminCatalog = new OpenAPIHono();

// All routes in this router require admin permissions
adminCatalog.use('*', authMiddleware(['admin:store']));

adminCatalog.openapi(
  createRoute({
    method: 'post',
    path: '/',
    summary: 'Create a new product',
    request: {
      body: {
        content: {
          'application/json': { schema: ProductSchema },
        },
      },
    },
    responses: {
      200: { description: 'Product created', content: { 'application/json': { schema: ProductResponse } } },
    },
  }),
  async (c) => {
    const body = c.req.valid('json');
    const db = c.get('db');
    // Calling the Durable Object stub
    const result = await db.createProduct(body);
    return c.json(result);
  }
);
```

## Key Developer Conventions

### API Key Naming and Security
- **Public Keys (`pk_`)**: Used by the storefront for read-only catalog access and cart management. Safe to expose in the frontend.
- **Secret Keys (`sk_`)**: Legacy admin keys. While supported, Fufuni prioritizes **Auth0 RBAC** (Role-Based Access Control) via JWT claims for all admin operations.
- **Internal Secrets**: Sensitive keys like `STRIPE_SECRET_KEY` or `MAILGUN_API_KEY` must never be sent to the client.

### Database Migrations
Fufuni maintains strict consistency for schema updates. Every change must be reflected in three locations:
1.  **`SCHEMA` constant**: In `apps/merchant/src/do.ts`, update the base table definition.
2.  **`ensureInitialized()`**: Add the `ALTER TABLE` or `CREATE TABLE` logic to the startup check in `do.ts`.
3.  **Migration File**: Create a new numbered `.sql` file in `apps/merchant/migrations/` (e.g., `034_add_custom_field.sql`).

### Internationalization (i18n)
Product and category content (titles, descriptions) are stored as JSON locale maps. The framework supports six default locales: `en-US`, `fr-FR`, `es-ES`, `zh-CN`, `ar-SA`, and `he-IL`.

```typescript
// Example of a localized title in the database
const productTitle = {
  "en-US": "Luxury Watch",
  "fr-FR": "Montre de Luxe",
  "ar-SA": "ساعة فاخرة"
};
```

### Frontend Navigation and Permissions
The visibility of pages in the admin dashboard and storefront navbar is controlled centrally in `apps/client/src/config/site.ts`. Each item defines the permissions required to view it.

```typescript
// apps/client/src/config/site.ts
export const siteConfig = (permissions: string[]) => ({
  navItems: [
    {
      label: "Products",
      href: "/admin/products",
      // Only users with 'admin:store' claim see this
      permissions: ["admin:store"], 
    },
    {
      label: "Orders",
      href: "/account/orders",
      // Available to any logged-in user
      permissions: [], 
    }
  ]
});
```

### Error Handling
Always use the custom `ApiError` class in the backend. It ensures the response matches the OpenAPI specification and provides consistent error codes for the frontend to consume.

```typescript
import { ApiError } from '../types';

if (!product) {
  throw new ApiError('Product not found', 404, 'PRODUCT_NOT_FOUND');
}
```
