Fufuni is an AI-native, high-performance e-commerce framework architected to run 100% within the Cloudflare free tier. By leveraging Cloudflare Workers for logic and Durable Objects (SQLite) for state, Fufuni eliminates traditional database costs and connection pooling latency. It serves as a "sovereign commerce" solution where the merchant owns their data and infrastructure while providing native endpoints for AI shopping agents via the Universal Commerce Protocol (UCP).

## Technical Stack

The framework is built on a modern, type-safe stack that prioritizes developer velocity and zero-cost scaling.

| Layer | Technology | Purpose |
| :--- | :--- | :--- |

| **Automation** | Turborepo | Orchestration of monorepo tasks and environment variable injection. |

## Request Lifecycle

Requests in Fufuni follow a streamlined path designed for low latency. Unlike traditional architectures that hop between an app server and a managed database, Fufuni's database (SQLite) lives inside the same JavaScript isolate as the logic for a specific store instance.

1.  **Client Entry:** A request hits the Cloudflare Global Network.
2.  **Worker Middleware:** The `merchant` Worker intercepts the request.
    *   **CORS:** Handles pre-flight checks.
    *   **Rate Limiting:** Checks IP/Token consumption in KV.
    *   **Cache:** `kvCacheMiddleware` checks if the result is in KV (for public GETs).
3.  **Durable Object Routing:** Hono resolves the `MerchantDO` stub.
    *   If the request is for the "default" store, it obtains the ID via `c.env.MERCHANT.idFromName('default')`.
4.  **DO Execution:** The DO receives the request. Since the DO is a single-threaded isolate, it handles SQL queries against its local SQLite file without connection pools or network overhead.
5.  **Response:** The result flows back through the Worker (potentially being cached in KV on the way out) to the client.

### Lifecycle Implementation Example
```typescript
// apps/merchant/src/index.ts
app.use('*', async (c, next) => {
  // 1. Resolve the Durable Object instance
  const id = c.env.MERCHANT.idFromName('default');
  const stub = c.env.MERCHANT.get(id);
  
  // 2. Attach the stub to the context for route handlers
  c.set('db', stub as unknown as DOStub);
  await next();
});

// Example route calling the DO
app.get('/v1/products/:id', async (c) => {
  const db = c.get('db');
  // Proxies the request directly to the DO's fetch handler
  return db.fetch(c.req.raw);
});
```

## Key Development Conventions

### 1. Database Schema & Migrations
Fufuni maintains strict consistency by requiring database changes to be updated in **three places** simultaneously:
1.  The `SCHEMA` constant in `apps/merchant/src/do.ts`.
2.  The `ensureInitialized()` method in `do.ts` (for auto-application).
3.  A new numbered `.sql` file in `apps/merchant/migrations/` (for audit and local tooling).

```typescript
// apps/merchant/src/do.ts example
export const SCHEMA = `
  CREATE TABLE IF NOT EXISTS products (
    id TEXT PRIMARY KEY,
    title TEXT NOT NULL,
    status TEXT DEFAULT 'active'
  );
`;

async ensureInitialized() {
  // Applies SCHEMA via this.storage.sql.exec()
  // Also runs incremental logic for new columns
}
```

### 2. Authentication & RBAC
Authentication is handled via Auth0. Fufuni distinguishes between two types of API keys and JWT-based RBAC:
*   `pk_...`: Public keys for storefronts (browsing, cart creation).
*   `sk_...`: Secret admin keys (legacy, use sparingly).
*   **Auth0 Access Tokens:** The primary source of truth for admin actions. Permissions like `admin:store` or `ai:api` are checked within the `authMiddleware`.

### 3. Internationalization (i18n)
Fufuni supports 6 built-in locales (including RTL support for Arabic and Hebrew). Product fields like `title` and `description` are stored as JSON strings:

```json
{
  "en-US": "Luxury Watch",
  "fr-FR": "Montre de luxe",
  "ar-SA": "ساعة فاخرة"
}
```

### 4. AI-Native Architecture (UCP)
The framework implements the Universal Commerce Protocol (UCP), exposing standardized endpoints for AI agents.

```bash
# Check UCP capabilities
curl https://api.yourstore.com/.well-known/ucp

# AI-ready product catalog
curl https://api.yourstore.com/ucp/v1/products?limit=5
```

## CI/CD and Deployment

Fufuni includes production-ready GitHub Actions:
*   `deploy-cloudflare-worker.yaml`: Deploys the backend to Cloudflare. Requires `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID`.
*   `pages.yaml`: Builds and deploys the React SPA to GitHub Pages.
*   `reset-demo.yaml`: A utility workflow that wipes the database, re-initializes schema, and seeds demo data (products, categories, regions).
*   `ci.yml`: Runs `tsc` and `eslint` on PRs to ensure code quality without deploying.

To trigger a manual re-seed of the database during development:
```bash
# Resets local SQLite and adds demo data
npm run clean:seed:start
```
