## Project Description

Fufuni is an AI-native, 100% free-tier e-commerce framework designed to run entirely on the Cloudflare edge. It leverages Cloudflare Workers for its runtime environment and Durable Objects for stateful, ACID-compliant storage using the built-in SQLite engine. The framework is built to be "AI-native" by implementing the Universal Commerce Protocol (UCP), allowing LLM shopping agents to browse catalogs and create checkouts programmatically. By combining Auth0 for identity, Stripe for payments, and Mailgun for transactional emails, Fufuni provides a professional-grade retail experience with zero monthly fixed costs, making it ideal for developers and small businesses targeting the Cloudflare ecosystem.

## Request Lifecycle

Fufuni uses a unique "Single-Isolate Architecture." Unlike traditional apps where a server connects to a remote database, Fufuni's backend routes in Hono pass execution directly into a Durable Object (DO). Since the DO holds the SQLite database locally, the query happens in the same memory space as the JS execution.

### Typical Flow (e.g., GET /v1/products)
1.  **Cloudflare Edge:** The request hits the global Cloudflare network.
2.  **KV Cache Middleware:** Before reaching the DO, the Worker checks `KV_CACHE`. If a public key (`pk_`) is used and a hit is found, the response returns immediately.
3.  **Hono Router:** If it's a cache miss or an admin request, the Hono router in `apps/merchant/src/index.ts` executes.
4.  **Durable Object Stub:** The router obtains a "stub" for the `MerchantDO`.
5.  **DO Invocation:** The request is forwarded to the `MerchantDO.fetch()` method.
6.  **SQLite Execution:** The DO runs the SQL query against its local SQLite file.
7.  **Response:** The result is returned through the Worker to the client, potentially being cached in KV on the way out.

```typescript
// Example of a backend route defining this lifecycle
// apps/merchant/src/routes/catalog.ts

import { createRoute, z } from '@hono/zod-openapi';
import { OpenAPIHono } from '@hono/zod-openapi';
import { type Env, type DOStub } from '../types';

export const adminCatalog = new OpenAPIHono<{ Bindings: Env; Variables: { db: DOStub } }>();

const GetProductRoute = createRoute({
  method: 'get',
  path: '/{id}',
  summary: 'Get a product by ID',
  request: {
    params: z.object({ id: z.string().uuid() }),
  },
  responses: {
    200: { description: 'The product detail', content: { 'application/json': { schema: z.any() } } },
  },
});

adminCatalog.openapi(GetProductRoute, async (c) => {
  const { id } = c.req.valid('param');
  const db = c.get('db');
  
  // Execution jumps into the Durable Object isolate here
  const product = await db.query('SELECT * FROM products WHERE id = ?', [id]);
  
  return c.json(product[0]);
});
```

## Key Conventions

### 1. Database Migrations (The "Three Places" Rule)
Fufuni maintains strict data integrity. Every schema change **must** be implemented in three locations to ensure both local dev and production deployments are synchronized:
1.  **`apps/merchant/src/do.ts` (SCHEMA constant):** Updates the "source of truth" used for fresh installs.
2.  **`apps/merchant/src/do.ts` (ensureInitialized):** Logic to detect and apply the change if it's missing.
3.  **`apps/merchant/migrations/0XX_name.sql`:** A standalone SQL file used for audit trails and CI/CD.

### 2. API Key Prefixes
Authentication distinguishes between public and administrative access using prefixes:
-   `pk_`: Public Key. Used by the storefront for browsing, cart management, and checkout. Safe to expose in the frontend code.
-   `sk_`: Secret Key (Legacy). Used for administrative tasks. **Never** expose this to the browser.
-   **JWT (Auth0):** The primary method for RBAC. The backend verifies permissions within the JWT scope.

### 3. Frontend Navigation & Permissions
The visibility of pages and sidebar items in the Admin Panel is driven by a configuration file. You do not manually toggle visibility in components; you define permissions in the config.

```typescript
// apps/client/src/config/site.ts

export const siteConfig = (permissions: string[] = []) => ({
  navItems: [
    {
      label: "Products",
      href: "/admin/products",
      // This item only appears if the user has the 'admin:store' claim in their JWT
      permissions: ["admin:store"], 
    },
    {
      label: "Analytics",
      href: "/admin/analytics",
      permissions: ["admin:store", "admin:database"],
    }
  ],
});
```

### 4. Error Handling
The backend uses a standardized `ApiError` class. When thrown, it is caught by the global Hono `onError` handler, ensuring all error responses follow the same JSON structure.

```typescript
// Standard error format
// { "error": { "code": "not_found", "message": "Product not found" } }

import { ApiError } from '../types';

if (!product) {
  throw new ApiError('not_found', 'Product not found', 404);
}
```

### 5. Internationalization (i18n)
Product data is stored as "Localized JSON" strings. Instead of a simple string, fields like `title` or `description` store a JSON object mapping locale codes to content.

```sql
-- Database value example for products.title
{"en-US": "Luxury Watch", "fr-FR": "Montre de luxe"}
```

The frontend uses `resolveTitle(data, locale)` to extract the correct string, falling back to English if the requested locale is missing.

## Universal Commerce Protocol (UCP)

Fufuni is a reference implementation for UCP, enabling "Agentic Commerce." AI assistants can discover the store's capabilities at `/.well-known/ucp`. This allows agents like Claude or ChatGPT to interact with your store without needing a custom plugin for every single framework.

### Standardized Endpoints
-   `GET /ucp/v1/products`: AI-optimized product listing.
-   `POST /ucp/v1/checkout-sessions`: Direct checkout creation for agents.
-   `GET /ucp/v1/categories`: Hierarchical category browsing for crawlers.

## Deployment Workflows

Fufuni is fully automated via GitHub Actions.
1.  **`deploy-cloudflare-worker.yaml`**: Triggers on changes to `apps/merchant`. It builds the worker, decrypts secrets, and pushes the code to Cloudflare.
2.  **`pages.yaml`**: Triggers on changes to `apps/client`. It builds the Vite SPA and deploys it to GitHub Pages.
3.  **`reset-demo.yaml`**: A maintenance workflow that can be triggered manually to wipe the database and re-seed it with demo products and categories.
4.  **`ci.yml`**: Runs on every Pull Request to ensure type-safety and linting compliance across the monorepo.
