## Fufuni Framework Overview

Fufuni is a production-ready, Cloudflare-native headless e-commerce engine designed to run entirely within the Cloudflare ecosystem. By leveraging Cloudflare Workers for the API and Durable Objects (SQLite) for the stateful backend, Fufuni achieves zero cold starts and global consistency without the need for an external database or connection pooling. The framework follows a "headless-first" philosophy, exposing a strictly typed Zod-OpenAPI backend to a modern React 19 frontend styled with HeroUI v3, while targeting a 100% free-to-run cost model for small to medium-sized storefronts.

## The Fufuni Stack

Fufuni is built on a specific set of primitives to ensure high performance and zero infrastructure costs within free-tier limits. The entire backend runs inside a single Durable Object (`MerchantDO`) so that all SQL operations are executed within one JavaScript isolate, eliminating traditional database latency and connection management overhead.

| Layer | Technology | Role |
| :--- | :--- | :--- |
| **Frontend** | React 19 + Vite + HeroUI v3 | Modern SPA with Tailwind CSS and Framer Motion |
| **API Layer** | Hono + Zod-OpenAPI | Typed routing, validation, and auto-generated Swagger |
| **Compute** | Cloudflare Workers | Edge-side execution for zero-latency request handling |
| **Database** | Durable Objects (SQLite) | Single-instance stateful storage with ACID compliance |
| **Caching** | Cloudflare KV | High-speed global caching for catalog and categories |
| **Auth** | Auth0 | Identity management and Role-Based Access Control (RBAC) |
| **Images** | Cloudflare R2 | S3-compatible object storage for product assets |
| **Deployment** | GitHub Actions | Automated CI/CD for Workers, Pages, and demo resets |

## Monorepo Structure

Fufuni uses **Turborepo** for task orchestration across its three main workspaces. Developers should use `npm run dev:env` from the root to launch the full stack, which automatically injects `.env` variables into the environment.

### Workspace Breakdown

*   **`apps/client/`**: The React 19 storefront and admin dashboard. It uses Vite for bundling and HeroUI (formerly NextUI) for accessible components.
*   **`apps/merchant/`**: The "brain" of the operation. This workspace contains the Cloudflare Worker, the Durable Object definition, and all SQLite migrations.
*   **`apps/mcp/`**: A specialized Cloudflare Worker that serves as a Model Context Protocol (MCP) server, allowing AI assistants to understand and document the codebase.
*   **`mcp/`**: Static knowledge base files used by the MCP server to provide context to LLMs.

## Request Lifecycle

Understanding the flow of data is critical for Fufuni developers. Because the database is embedded in a Durable Object, the lifecycle differs from standard "Worker + External DB" architectures.

1.  **Client Request**: The React frontend sends an HTTP request. Public calls use a `pk_` (Public Key) prefix, while admin calls include an Auth0 JWT.
2.  **Edge Routing**: The Hono app in `apps/merchant/src/index.ts` receives the request at the nearest Cloudflare PoP.
3.  **Middleware Chain**:
    *   **CORS**: Handles cross-origin headers.
    *   **KV Cache**: Checks Cloudflare KV for `GET` requests to catalog/categories. If a hit occurs, the response is returned immediately, bypassing the Durable Object.
    *   **Rate Limiter**: Enforces limits based on the user's role (Admin vs Public).
4.  **Durable Object Forwarding**: If the cache misses or it's a mutation (`POST/PATCH`), Hono obtains a "Stub" for the `MerchantDO` and forwards the request.
5.  **SQLite Execution**: Inside `MerchantDO`, Hono (running inside the DO) executes SQL queries against the local SQLite file.
6.  **Response & Invalidation**: On successful mutations, the `kvInvalidateMiddleware` purges relevant keys from Cloudflare KV to ensure consistency.

### Example: Backend Request Handling

The entry point extracts the Durable Object stub and applies it to the context for use in all routes.

```typescript
// apps/merchant/src/index.ts snippet
app.use('*', async (c, next) => {
  // Every request is routed to the same 'default' DO instance
  const id = c.env.MERCHANT.idFromName('default');
  const stub = c.env.MERCHANT.get(id);
  
  // Cast as DOStub for typed SQL execution
  c.set('db', stub as unknown as DOStub);
  await next();
});

// Example route using the DO stub
app.get('/v1/products/:id', async (c) => {
  const db = c.get('db');
  const product = await db.sql`SELECT * FROM products WHERE id = ${c.req.param('id')}`;
  return c.json(product);
});
```

## Database Schema & Migrations

Fufuni enforces a strict "Three-Place Rule" for schema changes to maintain parity between the initial setup and incremental updates.

### The Three-Place Rule
When adding a column or table, you must update:
1.  **`SCHEMA` Constant**: Located in `apps/merchant/src/do.ts`, used for fresh installations.
2.  **`ensureInitialized()`**: Also in `do.ts`, performs basic "if not exists" checks.
3.  **Migration File**: A new `.sql` file in `apps/merchant/migrations/` (e.g., `032-add-product-tags.sql`).

```typescript
// apps/merchant/src/do.ts
export const SCHEMA = `
  CREATE TABLE IF NOT EXISTS products (
    id TEXT PRIMARY KEY,
    handle TEXT UNIQUE,
    title TEXT, -- Can be plain string or JSON locale map
    status TEXT DEFAULT 'draft'
  );
  -- ... other tables
`;

export class MerchantDO extends DurableObject {
  async ensureInitialized() {
    // Check if a specific column exists, if not, perform the alter
    const tableInfo = await this.storage.sql`PRAGMA table_info(products)`.toArray();
    if (!tableInfo.some(col => col.name === 'handle')) {
      await this.storage.sql`ALTER TABLE products ADD COLUMN handle TEXT UNIQUE`;
    }
  }
}
```

## Key Conventions

*   **API Keys**: Public keys begin with `pk_` and are safe for frontend use. Secret keys (admin) begin with `sk_`. While `sk_` keys are supported for legacy CLI tools, **Auth0 RBAC** is the primary source of truth for dashboard security.
*   **Error Handling**: Always use the `ApiError` class. The Hono `onError` handler catches these and transforms them into standardized JSON responses.
*   **Multilingual Data**: High-level fields like `title` or `description` are stored as JSON strings representing a map of locales (e.g., `{"en-US": "Shirt", "fr-FR": "Chemise"}`).
*   **Infrastructure**: Fufuni is strictly Cloudflare-native. Do not introduce dependencies on D1, external Postgres, or Redis. Use DO SQLite and KV respectively.

## Deployment Workflows

Fufuni utilizes three main GitHub Actions workflows located in `.github/workflows/`:

1.  **`deploy-cloudflare-worker.yaml`**: Triggers on pushes to `main` affecting the backend. Requires `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID`. It uses a shared encrypted `.env` artifact for security.
2.  **`pages.yaml`**: Deploys the React SPA to GitHub Pages. It builds the frontend using `npm run build:env` to ensure environment variables are baked into the static bundle.
3.  **`reset-demo.yaml`**: A maintenance workflow that wipes the hosted demo database and re-seeds it from `apps/merchant/scripts/seed-data.ts`. This is typically run manually or on a schedule to ensure the public demo remains clean.
