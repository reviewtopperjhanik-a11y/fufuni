The `useSecuredApi()` hook is the primary interface for frontend developers to interact with the Fufuni backend. It abstracts the complexities of Auth0 token management, header injection, and HTTP method handling. By using this hook, you ensure that every request to the Cloudflare Workers backend is authenticated and authorized according to the user's current session.

## Import and Setup

The hook is exported from the auth feature's component collection. It relies on the `AuthProvider` being higher up in the React component tree (usually wrapping the entire application in `App.tsx` or `main.tsx`).

```typescript
import { useSecuredApi } from "@/features/auth/components/auth-components";
```

## API Methods Reference

The following table details the methods returned by the hook. All methods are asynchronous and return a Promise.

| Method | Signature | When to Use |
| :--- | :--- | :--- |
| `getJson` | `(url: string) => Promise<any>` | Fetch protected resources (e.g., user profiles, order history). |
| `postJson` | `(url: string, body: any) => Promise<any>` | Create new resources using a JSON payload. |
| `putJson` | `(url: string, body: any) => Promise<any>` | Fully replace an existing resource with a new JSON payload. |
| `patchJson` | `(url: string, body: any) => Promise<any>` | Perform partial updates on a resource (e.g., updating a single field). |
| `deleteJson` | `(url: string) => Promise<any>` | Remove a resource from the database. |
| `postForm` | `(url: string, formData: FormData) => Promise<any>` | Upload files or send `multipart/form-data` requests. |
| `hasPermission`| `(permission: string) => Promise<boolean>` | Check if the current user has a specific scope (e.g., `write:products`). |

## Automatic Token Injection Logic

The core value of `useSecuredApi()` is its seamless integration with the Auth0 SDK. Under the hood, these methods perform the following sequence:

1.  **Token Retrieval**: It calls `getAccessTokenSilently()` (via the internal `useAuth` hook).
2.  **Header Construction**: It creates a `Headers` object and appends `Authorization: Bearer <token>`.
3.  **Content-Type Handling**: For JSON methods, it automatically sets `Content-Type: application/json`.
4.  **Fetch Execution**: It executes the native `fetch` command using the configured headers and the requested HTTP method.

This means you never have to manually manage JWT expiration or storage. If the token is expired, the hook handles the silent refresh automatically before the request is even sent.

## Implementation Examples

Below are standard patterns for using `useSecuredApi` within React 19 functional components.

### 1. GET: Fetching Private Data
This example demonstrates how to fetch a list of private user "Wishlist" items. Note that we combine the hook with `useEffect` for data fetching.

```typescript
import { useEffect, useState } from "react";
import { useSecuredApi } from "@/features/auth/components/auth-components";
import { getBaseURL } from "@/utils/base-url";
import { SiteLoading } from "@/shared/ui/feedback/site-loading";

interface WishlistItem {
  id: string;
  name: string;
  price: number;
}

export const MyWishlist = () => {
  const { getJson } = useSecuredApi();
  const [items, setItems] = useState<WishlistItem[]>([]);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    const fetchWishlist = async () => {
      try {
        const apiBase = getBaseURL();
        // The token is injected automatically here
        const data = await getJson(`${apiBase}/v1/wishlist`);
        setItems(data);
      } catch (error) {
        console.error("Failed to fetch wishlist:", error);
      } finally {
        setLoading(false);
      }
    };

    fetchWishlist();
  }, [getJson]);

  if (loading) return <SiteLoading />;

  return (
    <ul>
      {items.map((item) => (
        <li key={item.id}>{item.name} - ${item.price}</li>
      ))}
    </ul>
  );
};
```

### 2. POST: Creating a New Resource
This example shows how to handle a form submission to create a new product review.

```typescript
import { useSecuredApi } from "@/features/auth/components/auth-components";
import { Button, Input, Textarea } from "@heroui/react";
import { useForm } from "react-hook-form";

export const ReviewForm = ({ productId }: { productId: string }) => {
  const { postJson } = useSecuredApi();
  const { register, handleSubmit, reset } = useForm();

  const onSubmit = async (formData: any) => {
    try {
      const apiBase = import.meta.env.VITE_API_BASE_URL;
      await postJson(`${apiBase}/v1/products/${productId}/reviews`, {
        rating: Number(formData.rating),
        comment: formData.comment,
      });
      alert("Review submitted!");
      reset();
    } catch (err) {
      console.error("Submission error:", err);
    }
  };

  return (
    <form onSubmit={handleSubmit(onSubmit)} className="space-y-4">
      <Input {...register("rating")} label="Rating (1-5)" type="number" />
      <Textarea {...register("comment")} label="Your Feedback" />
      <Button type="submit" color="primary">Submit Review</Button>
    </form>
  );
};
```

### 3. DELETE: Removing a Resource
This implementation shows a simple delete action for a user's address.

```typescript
import { useSecuredApi } from "@/features/auth/components/auth-components";
import { Button } from "@heroui/react";

export const AddressItem = ({ id, label, onDeleteSuccess }: { id: string, label: string, onDeleteSuccess: () => void }) => {
  const { deleteJson } = useSecuredApi();

  const handleDelete = async () => {
    if (!confirm("Are you sure you want to delete this address?")) return;

    try {
      const apiBase = import.meta.env.VITE_API_BASE_URL;
      // Automatic Bearer token inclusion for the DELETE method
      await deleteJson(`${apiBase}/v1/user/addresses/${id}`);
      onDeleteSuccess();
    } catch (error) {
      alert("Failed to delete address.");
    }
  };

  return (
    <div className="flex justify-between items-center p-4 border rounded">
      <span>{label}</span>
      <Button color="danger" variant="flat" onPress={handleDelete}>
        Delete
      </Button>
    </div>
  );
};
```

## UI Guarding with hasPermission()

Permissions in Fufuni are managed via Auth0 Scopes. `hasPermission` is an asynchronous method because it may need to verify the decoded JWT claims or occasionally re-sync with the provider.

Use this to conditionally render UI elements that require specific administrative privileges.

```typescript
import { useEffect, useState } from "react";
import { useSecuredApi } from "@/features/auth/components/auth-components";
import { Button } from "@heroui/react";

export const AdminToolbar = () => {
  const { hasPermission } = useSecuredApi();
  const [canManageStock, setCanManageStock] = useState(false);

  useEffect(() => {
    const checkAuth = async () => {
      // Check for the specific permission string defined in Auth0
      const allowed = await hasPermission("products:write");
      setCanManageStock(allowed);
    };
    checkAuth();
  }, [hasPermission]);

  if (!canManageStock) return null;

  return (
    <div className="bg-warning-50 p-2 flex gap-2">
      <Button size="sm">Update Inventory</Button>
      <Button size="sm">Sync with ERP</Button>
    </div>
  );
};
```

## When NOT to use this hook

While `useSecuredApi()` is powerful, it is specifically designed for **authenticated** requests. 

1.  **Public Routes**: Do not use this hook for fetching public data like the general product catalog or site settings that do not require a login. For these, use the standard browser `fetch()` or a specialized hook like `useSWR` / `useQuery` with a basic fetcher.
2.  **Performance on Public Data**: Using `useSecuredApi()` for public data adds unnecessary overhead because the hook will attempt to verify a session and potentially trigger a redirect to the login page if the user is not signed in.
3.  **Static Assets**: Do not use this for loading images or CSS files.

## Auth0 Management Helpers

The `useSecuredApi()` hook also exposes specialized helpers for interacting with the Auth0 Management API. These methods are typically only used in the **Admin Dashboard** section of the Fufuni framework. 

**Requirements**: Using these helpers requires the user to have the `auth0:admin:api` permission.

### Exposed Helpers:
- `getAuth0ManagementToken()`: Retrieves a short-lived token for Management API calls (cached in KV via the worker backend).
- `listAuth0Users(token)`: Returns a list of all users registered in the Auth0 tenant.
- `getUserPermissions(token, userId)`: Fetches the specific permissions assigned to a specific user.
- `addPermissionToUser / removePermissionFromUser`: Modifies user access levels dynamically.
- `getResourceServers(token)`: Lists configured APIs (Resource Servers) in Auth0.
- `checkResourceServerScopes(token, id, scopes)`: Verifies if the backend API scopes are in sync with the Auth0 configuration.

### Example: Syncing API Scopes
This is a utility used by platform admins to ensure the frontend's understanding of permissions matches the Auth0 tenant settings.

```typescript
const syncScopes = async () => {
  const { getAuth0ManagementToken, checkResourceServerScopesWithAudience } = useSecuredApi();
  
  const tokenResp = await getAuth0ManagementToken();
  const mgmtToken = tokenResp.access_token;
  
  const isSynced = await checkResourceServerScopesWithAudience(
    mgmtToken,
    "https://api.fufuni.com",
    [{ value: "orders:read", description: "Read orders" }]
  );
  
  console.log(isSynced ? "Scopes are correct" : "Update required in Auth0 dashboard");
};
```

By adhering to these patterns, you ensure that the Fufuni frontend remains secure, maintainable, and correctly integrated with the Cloudflare Workers backend infrastructure.
