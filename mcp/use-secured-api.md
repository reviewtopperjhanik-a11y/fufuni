## useSecuredApi() Hook Reference

```typescript
import { useSecuredApi } from "@/features/auth/components/auth-components";
```

## Return values

| Method | Signature | When to use |
|--------|-----------|-------------|
| getJson | `(url: string) => Promise<T>` | Fetch protected JSON data (GET) |
| postJson | `(url: string, body: unknown) => Promise<T>` | Create a resource with JSON payload |
| putJson | `(url: string, body: unknown) => Promise<T>` | Full update of a resource |
| patchJson | `(url: string, body: unknown) => Promise<T>` | Partial update of a resource |
| deleteJson | `(url: string) => Promise<void>` | Delete a resource |
| postForm | `(url: string, formData: FormData) => Promise<T>` | Multipart upload (images, files) |
| hasPermission | `(permission: string) => Promise<boolean>` | Check user permission before rendering admin UI |

## Automatic JWT injection

Every method automatically attaches the current Auth0 access-token as:

```
Authorization: Bearer <access-token>
```

No manual header configuration is required; the hook reads the token from the same `useAuth()` context that powers the login/logout buttons.

## Usage examples

### GET example – load user cart

```typescript
import { useSecuredApi } from "@/features/auth/components/auth-components";
import { useEffect, useState } from "react";

export const CartWidget: FC = () => {
  const { getJson } = useSecuredApi();
  const [cart, setCart] = useState<CartItem[]>([]);

  useEffect(() => {
    getJson<CartItem[]>("/v1/cart")
      .then(setCart)
      .catch(console.error);
  }, [getJson]);

  return (
    <div>
      {cart.map(item => (
        <span key={item.sku}>{item.name}</span>
      ))}
    </div>
  );
};
```

### POST example – add review

```typescript
import { useSecuredApi } from "@/features/auth/components/auth-components";

export const ReviewForm: FC<{ productId: string }> = ({ productId }) => {
  const { postJson } = useSecuredApi();
  const [rating, setRating] = useState(5);
  const [comment, setComment] = useState("");

  const submit = async () => {
    await postJson("/v1/reviews", {
      productId,
      rating,
      comment,
    });
    alert("Review submitted!");
  };

  return (
    <form onSubmit={submit}>
      <input value={comment} onChange={e => setComment(e.target.value)} />
      <button type="submit">Send</button>
    </form>
  );
};
```

## Guarding admin UI with hasPermission()

```typescript
import { useSecuredApi } from "@/features/auth/components/auth-components";
import { useEffect, useState } from "react";

export const AdminPanelLink: FC = () => {
  const { hasPermission } = useSecuredApi();
  const [canView, setCanView] = useState(false);

  useEffect(() => {
    hasPermission("admin:panel").then(setCanView);
  }, [hasPermission]);

  return canView ? <a href="/admin">Admin</a> : null;
};
```

## When NOT to use the hook

Use plain `fetch` (or React-Query) for **public** endpoints that do not require authentication:

```typescript
// ✅ public product list – no token needed
const products = await fetch("/v1/products").then(r => r.json());
```

Calling `useSecuredApi()` on a public route wastes bandwidth (token exchange) and may trigger CORS pre-flight.

## Auth0 Management helpers

The same hook exposes low-level Auth0 Management API utilities. All require the `auth0:admin:api` permission (granted to `authadmin` role only).

| Helper | Use-case |
|--------|----------|
| `getAuth0ManagementToken()` | Obtain a short-lived M2M token cached in KV |
| `listAuth0Users(token)` | Paginated list of tenant users |
| `getUserPermissions(token, userId)` | Permissions array for a single user |
| `addPermissionToUser(token, userId, permission)` | Grant a new permission |
| `removePermissionFromUser(token, userId, permission)` | Revoke a permission |

Example guard:

```typescript
const { getAuth0ManagementToken, listAuth0Users } = useSecuredApi();

const token = await getAuth0ManagementToken();
const users = await listAuth0Users(token); // Auth0User[]
```

These helpers are intended for **admin dashboards** inside the `AuthenticationGuardWithPermission` boundary and should never be called from customer-facing flows.
