## Discount Types and Schema

Fufuni supports three primary discount strategies used to incentivize purchases. While the database schema stores these in a unified `discounts` table, their application logic varies significantly based on the `type` field.

### Supported Types
- **`percentage`**: Reduces the subtotal by a percentage (0-100%). It is often capped by `max_discount_cents`.
- **`fixed_amount`**: A specific value subtracted from the subtotal. These are currency-specific in intent, though the core logic applies them as raw integer units.
- **`free_shipping`**: Removes the cost of shipping rates during the checkout process.

### Core Discount Fields
The following TypeScript interface represents the internal structure used by both the Merchant API and the Cart validation logic:

```typescript
export type DiscountType = 'percentage' | 'fixed_amount' | 'free_shipping';

export interface Discount {
  id: string;               // UUID
  code: string | null;      // Unique human-readable code (e.g., "SUMMER20")
  type: DiscountType;       // Logic selector
  value: number;            // Percentage (20) or Cents (500)
  status: 'active' | 'inactive';
  min_purchase_cents: number;   // Threshold to activate
  max_discount_cents: number | null; // Ceiling for percentage types
  starts_at: string | null;     // ISO 8601 timestamp
  expires_at: string | null;    // ISO 8601 timestamp
  usage_limit: number | null;   // Total global uses allowed
  usage_count: number;          // Current global uses
  usage_limit_per_customer: number | null;
}
```

## Public Validation and Error Handling

The Fufuni frontend or Cart service must validate a discount code before applying it to the subtotal. The validation logic is rigorous to prevent fraud and ensure business rules (like minimum spend) are met.

### Endpoint: POST /v1/discounts/validate
This public endpoint consumes a code and the current cart state to determine applicability.

```typescript
/**
 * Validation Logic Flow:
 * 1. Check if status is 'active'
 * 2. Verify current time is within [starts_at, expires_at]
 * 3. Verify subtotal >= min_purchase_cents
 * 4. Verify usage_count < usage_limit
 */
export async function validateDiscount(
  db: Database,
  discount: Discount,
  subtotalCents: number,
  customerEmail?: string
): Promise<void> {
  const currentTime = new Date().toISOString();

  if (discount.status !== 'active') {
    throw ApiError.invalidRequest('Discount is not active');
  }

  if (discount.expires_at && currentTime > discount.expires_at) {
    throw ApiError.invalidRequest('Discount has expired');
  }

  if (subtotalCents < discount.min_purchase_cents) {
    throw ApiError.invalidRequest(
      `Minimum purchase of ${(discount.min_purchase_cents / 100).toFixed(2)} required`
    );
  }

  if (discount.usage_limit !== null && discount.usage_count >= discount.usage_limit) {
    throw ApiError.invalidRequest('Discount usage limit reached');
  }
}
```

If valid, the API returns a `200 OK` with the calculated deduction:
```json
{
  "discount": { "code": "SAVE20", "type": "percentage", "value": 20 },
  "applicableAmount": 400,
  "newTotal": 1600
}
```

## Atomic Usage and Quotas

To prevent "race condition" exploits where multiple customers use the last remaining discount slot simultaneously, Fufuni uses Durable Objects' SQLite transactions. The usage count is incremented atomically during the order finalization phase.

### Usage Increment Implementation
When an order is placed, the backend performs an atomic update. If the `usage_count` would exceed the `usage_limit` as a result of the update, the transaction fails.

```sql
-- Atomic check and increment inside a transaction
UPDATE discounts 
SET usage_count = usage_count + 1,
    updated_at = ?
WHERE id = ? 
  AND status = 'active'
  AND (usage_limit IS NULL OR usage_count < usage_limit);
```

If the `UPDATE` query affects 0 rows, the backend knows the discount has either been deactivated or reached its limit since the last validation check, and throws an error to the user before the payment is processed.

## The 4-Step Pricing Pipeline

Fufuni follows a strict, sequential pipeline to calculate the final price of a cart. This ensures that taxes are calculated correctly on the actual amount paid by the customer, and that tier pricing is applied before generic discounts.

1.  **Base Price**: Retrieve the raw `price_cents` from the `variant_prices` table for the specific variant and currency.
2.  **Tier Pricing**: Check if the customer qualifies for volume-based pricing (e.g., "Buy 5, get 10% off the unit price"). This modifies the unit price.
3.  **Discount Application**: Apply the global discount code (percentage or fixed amount) to the total subtotal generated in steps 1 and 2.
4.  **Tax Computation**: Calculate taxes (VAT/Sales Tax) based on the **discounted subtotal**.

### Pipeline Example Logic
```typescript
async function calculateFinalPrice(db: Database, cart: CartItem[], discount?: Discount) {
  // 1 & 2: Base & Tier Pricing
  let subtotal = 0;
  for (const item of cart) {
    const basePrice = await resolveVariantPrice(db, item.variantId, item.currencyId);
    const unitPrice = applyTierPricing(basePrice, item.quantity);
    subtotal += unitPrice * item.quantity;
  }

  // 3: Discount
  const discountAmount = discount ? calculateDiscount(discount, subtotal) : 0;
  const discountedSubtotal = subtotal - discountAmount;

  // 4: Tax (e.g., 20% VAT)
  const taxAmount = Math.floor(discountedSubtotal * 0.20);
  
  return discountedSubtotal + taxAmount;
}
```

## Pricing Helper Reference (`lib/pricing.ts`)

The `lib/pricing.ts` module is the single source of truth for currency and price resolution. It implements a **Strict Fallback** policy: if a price is not explicitly defined for a currency, the system throws an error rather than guessing a conversion rate.

### `resolveVariantPrice`
Fetches the price for a specific variant in a specific currency.
```typescript
export async function resolveVariantPrice(
  db: Database,
  variantId: string,
  currencyId: string | null
): Promise<number> {
  if (!currencyId) throw ApiError.notFound("No currency specified");

  const [row] = await db.query<{ price_cents: number }>(
    `SELECT price_cents FROM variant_prices WHERE variant_id = ? AND currency_id = ?`,
    [variantId, currencyId]
  );

  if (!row) throw ApiError.notFound("Price not configured for this currency");
  return row.price_cents;
}
```

### `getCurrencyIdForRegion`
Maps a region (e.g., "US-East") to its associated currency UUID.
```typescript
export async function getCurrencyIdForRegion(
  db: Database,
  regionId: string | null
): Promise<string | null> {
  if (!regionId) return null;
  const [region] = await db.query<{ currency_id: string }>(
    `SELECT currency_id FROM regions WHERE id = ? AND status = 'active'`,
    [regionId]
  );
  return region?.currency_id ?? null;
}
```

## Currency Handling and Storage

To avoid floating-point errors (e.g., `0.1 + 0.2 !== 0.3`), Fufuni stores all monetary values as **integers in the smallest currency unit** (cents for USD/EUR, yen for JPY).

### Data Storage
- **Database**: `INTEGER` or `BIGINT`.
- **API**: Numbers (representing cents).
- **ISO 4217**: Currency codes (USD, EUR, GBP) are used to look up the correct precision and symbols.

### Client-side Formatting
Formatting is performed on the frontend using the native `Intl.NumberFormat` API. Developers should never manually prepend `$` symbols.

```typescript
/**
 * Formats a cent-based integer into a localized string.
 * @param cents - 2999
 * @param currencyCode - "USD"
 * @returns "$29.99"
 */
export function formatCurrency(cents: number, currencyCode: string): string {
  return new Intl.NumberFormat('en-US', {
    style: 'currency',
    currency: currencyCode,
  }).format(cents / 100);
}

import { Chip } from "@heroui/react";

  <Chip variant="flat" color="success">
    {formatCurrency(amount, code)}
  </Chip>

```

### Key Rules for Developers
1.  **Never convert prices on the fly**: If a product is $20 USD, do not multiply by 0.9 to get EUR. You must fetch the explicit EUR price from the database.
2.  **Use `Math.floor` or `Math.round`**: When calculating percentages (discounts/taxes), always ensure the result is coerced back to an integer before saving or adding to totals.
3.  **Default to USD in Schema**: While the logic is multi-currency, the `shipping_rate_prices` and `variant_prices` should ideally have a USD entry as the baseline for global stores.
