## Discount Models and Types

Fufuni supports three primary discount types, which are stored in the `discounts` table. Each discount can be restricted by code, usage limits, and temporal constraints. The framework uses integer-based arithmetic (cents) for all monetary calculations to avoid floating-point errors.

### Supported Discount Types

1.  **Percentage**: Reduces the subtotal by a percentage (0-100%). It can optionally be capped by a `max_discount_cents` value.
2.  **Fixed Amount**: Reduces the subtotal by a specific integer amount in the active currency.
3.  **Free Shipping**: Specifically targets the shipping rate cost. (Note: Implementation often involves a 100% discount on shipping line items).

### Discount Schema and Fields

The `Discount` interface reflects the SQLite schema within the Durable Object.

```typescript
type DiscountType = 'percentage' | 'fixed_amount' | 'free_shipping';

export interface Discount {
  id: string; // UUID
  code: string | null; // Uppercase unique code (e.g., "SAVE20")
  type: DiscountType;
  value: number; // Percent (e.g., 20) or Cents (e.g., 500 for $5.00)
  status: 'active' | 'inactive';
  min_purchase_cents: number; // Minimum order subtotal required
  max_discount_cents: number | null; // Ceiling for percentage discounts
  starts_at: string | null; // ISO 8601 timestamp
  expires_at: string | null; // ISO 8601 timestamp
  usage_limit: number | null; // Total global uses allowed
  usage_limit_per_customer: number | null; // Limit per unique email
  usage_count: number; // Atomic counter of successful applications
}
```

## Admin Management Endpoint

Discounts are managed via the `adminDiscounts` sub-router. When a discount is created or updated, the framework attempts to synchronize the state with Stripe Coupons and Promotion Codes to ensure that checkouts handled by Stripe Checkout remain consistent with the internal database.

## Public Validation and Application

Public clients (frontend carts) use the validation logic to check if a code is applicable before proceeding to checkout. The validation process checks status, timing, minimum purchase requirements, and usage limits.

### The Validation Logic

The `validateDiscount` helper is used internally by the API to ensure a code is valid for the current cart state.

```typescript
import { ApiError, now } from '../types';
import type { Database } from '../db';

export async function validateDiscount(
  db: Database,
  discount: Discount,
  subtotalCents: number,
  customerEmail?: string
): Promise<void> {
  // 1. Status Check
  if (discount.status !== 'active') {
    throw ApiError.invalidRequest('Discount is not active');
  }

  // 2. Temporal Check
  const currentTime = now();
  if (discount.starts_at && currentTime < discount.starts_at) {
    throw ApiError.invalidRequest('Discount has not started yet');
  }
  if (discount.expires_at && currentTime > discount.expires_at) {
    throw ApiError.invalidRequest('Discount has expired');
  }

  // 3. Minimum Threshold
  if (discount.min_purchase_cents > 0 && subtotalCents < discount.min_purchase_cents) {
    throw ApiError.invalidRequest(
      `Minimum purchase of $${(discount.min_purchase_cents / 100).toFixed(2)} required`
    );
  }

  // 4. Global Usage Check
  if (discount.usage_limit !== null && discount.usage_count >= discount.usage_limit) {
    throw ApiError.invalidRequest('Discount usage limit reached');
  }
}
```

## Atomic Usage Counting

To prevent race conditions where a discount code with a limit of 1 is used by two people simultaneously, Fufuni performs usage increments within the Durable Object's transaction scope.

When an order is finalized, the `usage_count` is incremented. If the count exceeds the limit during the update, the transaction is rolled back, and the order fails.

```sql
-- Atomic update within the DO transaction
UPDATE discounts 
SET usage_count = usage_count + 1, 
    updated_at = ? 
WHERE id = ? 
  AND (usage_limit IS NULL OR usage_count < usage_limit);

-- If rows_affected is 0, the discount was exhausted between validation and checkout
```

## The Pricing Pipeline

Fufuni follows a strict 4-step pricing pipeline. Prices are resolved at the moment an item is added to the cart and are "frozen" to prevent price shifts during a session.

1.  **Base Price**: The raw price of the product variant in the specific currency.
2.  **Tier Pricing**: Volume-based discounts (e.g., "Buy 5, save 10%"). These are applied to the unit price based on the quantity in the cart.
3.  **Discount Application**: Global or coupon-based discounts applied to the calculated subtotal.
4.  **Tax Computation**: Taxes are calculated based on the **discounted subtotal** and the shipping address/region.

### Calculation Sequence Example

```typescript
function calculateFinalPrice(unitPrice: number, qty: number, discount: Discount | null, taxRate: number) {
  // 1 & 2: Base & Tier
  const subtotal = unitPrice * qty; 
  
  // 3: Discount
  const discountAmount = discount ? calculateDiscount(discount, subtotal) : 0;
  const discountedSubtotal = subtotal - discountAmount;
  
  // 4: Tax
  const taxAmount = Math.round(discountedSubtotal * taxRate);
  
  return {
    subtotal,
    discountAmount,
    taxAmount,
    total: discountedSubtotal + taxAmount
  };
}
```

## Multi-Currency Helpers (`lib/pricing.ts`)

Fufuni adopts a **Strict Fallback Policy**. Prices are not converted using exchange rates. Instead, every variant must have an explicit price defined for every currency the store supports in the `variant_prices` table.

### Resolving Prices

The following helpers in `apps/merchant/src/lib/pricing.ts` are essential for handling multi-currency environments.

## Currency Handling and Display

While the backend and database treat all money as integers (cents/smallest units), the frontend is responsible for localization and formatting.

### Storage Rules
- **ISO 4217 Codes**: Always stored in uppercase (e.g., `USD`, `EUR`, `JPY`).
- **Integers**: Always store `$10.50` as `1050`. For zero-decimal currencies like `JPY`, `100` remains `100`.

### Client-Side Formatting
Use the standard `Intl.NumberFormat` API in React components to display prices.

```typescript
/**
 * Formats a cent-based integer into a localized string.
 * @param amount - Price in cents (e.g. 1050)
 * @param currency - ISO code (e.g. "USD")
 */
export function formatPrice(amount: number, currency: string): string {
  return new Intl.NumberFormat('en-US', {
    style: 'currency',
    currency: currency,
  }).format(amount / 100);
}

// React 19 Usage Example
import { Card, Button } from "@heroui/react";

export const ProductPrice = ({ cents, currency }: { cents: number, currency: string }) => {
  return (
    <span className="text-xl font-bold">
      {formatPrice(cents, currency)}
    </span>
  );
};
```

### Stripe Synchronization
When creating a Fufuni discount, the framework automatically calls `syncDiscountToStripe`.
- **Percentage Discounts**: Synced as Stripe Coupons with `percent_off`.
- **Fixed Amount**: Synced as Stripe Coupons with `amount_off` and the specific currency code.
- **Promotion Codes**: If a Fufuni discount has a `code` (e.g. "SAVE10"), Fufuni creates a `Stripe.PromotionCode` object linked to the Coupon. This allows the same code to work if the user is redirected to a Stripe-hosted checkout page.
