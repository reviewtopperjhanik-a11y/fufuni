## Regional Pricing Architecture

Fufuni implements a **Strict Multi-Currency** model. Unlike simpler platforms that might store a single base price and perform real-time conversion via exchange rates, Fufuni requires explicit price definitions for every currency used in your storefront. This approach, defined as "Option A" in the framework's internal logic, ensures that price points remain psychologically attractive (e.g., $29.99 vs. €27.00) and protects margins from currency volatility.

### The Source of Truth

In a production context, you must **never** read a price directly from the `variants` or `shipping_rates` tables. While those tables may contain legacy or base price columns for metadata, the actual checkout logic queries the following relationship tables:

1.  `variant_prices`: Maps a `variant_id` and `currency_id` to a `price_cents` value.
2.  `shipping_rate_prices`: Maps a `shipping_rate_id` and `currency_id` to an `amount_cents` value.

This separation allows a single product variant to have different prices in the US (USD), UK (GBP), and EU (EUR) without complex mathematical conversion logic.

```typescript
import { getDb } from '../db';
import type { Database } from '../db';
import { ApiError } from '../types';

/**
 * Example of the internal SQL schema relationship for regional pricing.
 * Developers should use the helpers in lib/pricing.ts instead of writing raw SQL.
 */
async function getRawRegionalPrice(db: Database, variantId: string, currencyCode: string) {
  const query = `
    SELECT vp.price_cents, c.symbol 
    FROM variant_prices vp
    JOIN currencies c ON vp.currency_id = c.id
    WHERE vp.variant_id = ? AND c.code = ? AND c.status = 'active'
  `;
  
  const [row] = await db.query<{ price_cents: number; symbol: string }>(query, [variantId, currencyCode.toUpperCase()]);
  
  if (!row) {
    throw ApiError.notFound(`Price not configured for currency: ${currencyCode}`);
  }
  
  return row;
}
```

## The Pricing Resolver (lib/pricing.ts)

The `lib/pricing.ts` module is the single source of truth for price resolution. It handles the retrieval of currency IDs from regions and fetches the correct cent values for variants and shipping rates.

### Strict Fallback Behavior

If a price is missing for a requested currency, the resolver throws an `ApiError.notFound`. There is no default fallback to USD. This behavior forces administrators to explicitly define pricing for every region they activate, preventing accidental "free" items or incorrect pricing in the checkout flow.

### Resolving Prices in a Request

When processing a cart or checkout, the system first identifies the `region_id` (usually from the session or request headers), determines the associated `currency_id`, and then resolves all line item prices.

```typescript
import { 
  getCurrencyIdForRegion, 
  resolveVariantPrice, 
  resolveShippingPrice 
} from './lib/pricing';
import type { Database } from './db';

export async function calculateCartTotal(
  db: Database, 
  regionId: string, 
  variantIds: string[], 
  shippingRateId: string
): Promise<number> {
  // 1. Get the currency associated with the customer's region
  const currencyId = await getCurrencyIdForRegion(db, regionId);
  
  // 2. Resolve variant prices (totaling items)
  let subtotal = 0;
  for (const id of variantIds) {
    const price = await resolveVariantPrice(db, id, currencyId);
    subtotal += price;
  }
  
  // 3. Resolve shipping
  const shipping = await resolveShippingPrice(db, shippingRateId, currencyId);
  
  return subtotal + shipping;
}
```

## Discount and Promotion System

Discounts in Fufuni are managed through the `discounts` table. They can be applied as either a percentage of the subtotal or a fixed amount. Every discount is validated against several criteria before being applied to a cart.

### Discount Record Structure

The `Discount` interface defines the rules for a specific promotion:

*   `type`: Either `percentage` or `fixed_amount`.
*   `value`: The number (percentage integer or cent amount).
*   `min_purchase_cents`: The minimum subtotal required to trigger the discount.
*   `max_discount_cents`: A cap for `percentage` discounts (e.g., "20% off up to $50").
*   `usage_limit`: Total times this code can be used globally.
*   `usage_limit_per_customer`: Times a specific email address can use the code.

### Validating a Discount Code

Validation occurs in two phases: structural validity (is it active/expired?) and contextual validity (does the current cart meet requirements?).

```typescript
import { ApiError, now } from '../types';
import type { Database } from '../db';
import type { Discount } from '../routes/discounts';

export async function validateDiscount(
  db: Database,
  discount: Discount,
  subtotalCents: number,
  customerEmail?: string
): Promise<void> {
  // Basic status and time checks
  if (discount.status !== 'active') throw ApiError.invalidRequest('Discount is not active');
  
  const currentTime = now();
  if (discount.starts_at && currentTime < discount.starts_at) {
    throw ApiError.invalidRequest('Discount has not started yet');
  }
  if (discount.expires_at && currentTime > discount.expires_at) {
    throw ApiError.invalidRequest('Discount has expired');
  }

  // Value threshold checks
  if (discount.min_purchase_cents > 0 && subtotalCents < discount.min_purchase_cents) {
    throw ApiError.invalidRequest(
      `Minimum purchase of $${(discount.min_purchase_cents / 100).toFixed(2)} required`
    );
  }

  // Usage checks
  if (discount.usage_limit !== null && discount.usage_count >= discount.usage_limit) {
    throw ApiError.invalidRequest('Discount usage limit reached');
  }
}
```

## Calculating Final Discount Amounts

The calculation logic ensures that a discount never results in a negative total and respects the configured caps. Fixed amount discounts are capped at the subtotal, while percentage discounts are capped by the `max_discount_cents` field.

### Calculation Logic

```typescript
import type { Discount } from '../routes/discounts';

/**
 * Applies calculation rules to determine the actual reduction in cents.
 */
export function calculateDiscount(discount: Discount, subtotalCents: number): number {
  switch (discount.type) {
    case 'percentage': {
      // Use Math.floor to ensure we don't grant extra fractions of a cent
      let amount = Math.floor((subtotalCents * discount.value) / 100);
      
      // Apply the cap if defined
      if (discount.max_discount_cents !== null && amount > discount.max_discount_cents) {
        amount = discount.max_discount_cents;
      }
      return amount;
    }
    case 'fixed_amount': {
      // Cannot discount more than the subtotal itself
      return Math.min(discount.value, subtotalCents);
    }
    default:
      return 0;
  }
}
```

## Stripe Synchronization

Fufuni maintains a bi-directional relationship with Stripe for coupon handling. When a discount is created or updated in the Fufuni Merchant panel, the framework automatically attempts to sync this data to Stripe's API.

### How Syncing Works

1.  **Coupons**: Fufuni creates a Stripe `Coupon` object to represent the discount's value and type.
2.  **Promotion Codes**: If the discount has a user-facing code (e.g., "SAVE20"), Fufuni creates a Stripe `PromotionCode` linked to the Coupon.
3.  **Limitations**: Stripe does not natively support complex "max discount" caps on percentage coupons in the same way Fufuni's internal database does. If a `max_discount_cents` is set on a percentage discount, the sync logic handles this by creating a Stripe coupon that represents the value but may require additional logic during Checkout Session creation.

```typescript
import Stripe from 'stripe';

async function syncToStripe(stripeKey: string, discount: any) {
  const stripe = new Stripe(stripeKey);
  
  // Create the underlying coupon
  const coupon = await stripe.coupons.create({
    percent_off: discount.type === 'percentage' ? discount.value : undefined,
    amount_off: discount.type === 'fixed_amount' ? discount.value : undefined,
    currency: discount.type === 'fixed_amount' ? 'usd' : undefined,
    duration: 'once',
    metadata: { fufuni_id: discount.id }
  });

  // Create the redeemable code
  if (discount.code) {
    await stripe.promotionCodes.create({
      coupon: coupon.id,
      code: discount.code.toUpperCase(),
    });
  }
  
  return coupon.id;
}
```

### Displaying the Breakdown

When displaying the final price, always separate the subtotal, discount, and total. This transparency is vital for customer trust and debugging.

```tsx
/**
 * Component to display the checkout summary.
 * All inputs are in cents and formatted for the locale.
 */
export const OrderSummary = ({ 
  subtotalCents, 
  discountCents, 
  shippingCents 
}: { 
  subtotalCents: number, 
  discountCents: number, 
  shippingCents: number 
}) => {
  const totalCents = subtotalCents - discountCents + shippingCents;
  const format = (cents: number) => `$${(cents / 100).toFixed(2)}`;

  return (
    <div className="space-y-2 border-t pt-4">
      <div className="flex justify-between">
        <span>Subtotal</span>
        <span>{format(subtotalCents)}</span>
      </div>
      {discountCents > 0 && (
        <div className="flex justify-between text-success">
          <span>Discount</span>
          <span>-{format(discountCents)}</span>
        </div>
      )}
      <div className="flex justify-between">
        <span>Shipping</span>
        <span>{format(shippingCents)}</span>
      </div>
      <div className="flex justify-between font-bold text-lg border-t pt-2">
        <span>Total</span>
        <span>{format(totalCents)}</span>

    </div>
  );
};
```
