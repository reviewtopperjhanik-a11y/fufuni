## Regional Pricing vs. Direct Variant Prices

Fufuni implements a strict multi-currency architecture where prices are decoupled from the core product entities. While the `variants` table may contain a legacy or default price field, production environments must rely on regional price tables. This ensures that a single product can have distinct, non-converted prices for different markets (e.g., $29.99 USD vs €27.00 EUR).

### The Regional Price Tables

Pricing is distributed across two primary join tables:
1.  `variant_prices`: Maps a `variant_id` and `currency_id` to a `price_cents` value.
2.  `shipping_rate_prices`: Maps a `shipping_rate_id` and `currency_id` to an `amount_cents` value.

This "Option A: Strict Fallback" approach means the system will never attempt to perform live currency conversion using exchange rates. If a price is not explicitly defined for a region's currency in these tables, the framework will throw an error rather than guessing a price.

### Resolving Prices by Region

To get the correct price for a user, you must first identify their region, then the currency associated with that region, and finally the price linked to that currency.

```typescript
import { getDb } from '../db';
import { 
  getCurrencyIdForRegion, 
  resolveVariantPrice 
} from '../lib/pricing';
import { ApiError } from '../types';

// Example: Resolving a price during cart item addition
export async function getItemPrice(c: any, variantId: string, regionId: string) {
  const db = getDb(c.var.db);

  // 1. Get the currency UUID for the region
  const currencyId = await getCurrencyIdForRegion(db, regionId);
  if (!currencyId) {
    throw ApiError.notFound("Region or currency not found");
  }

  // 2. Resolve the specific price for this variant + currency combo
  // This will throw an error if the admin hasn't configured this specific price
  const priceInCents = await resolveVariantPrice(db, variantId, currencyId);
  
  return priceInCents;
}
```

## The Pricing Single Source of Truth

The file `apps/merchant/src/lib/pricing.ts` serves as the absolute authority for price resolution. No other part of the system should execute raw SQL to fetch `price_cents` unless it is inside this library. This centralization ensures that any changes to pricing logic (like introducing tax-inclusive pricing or fallback logic) only need to be modified in one place.

### Key Resolution Functions

The pricing library provides several helper functions to navigate the Region -> Currency -> Price relationship:

| Function | Purpose |
| :--- | :--- |
| `resolveVariantPrice` | Fetches the `price_cents` for a variant in a specific currency. |
| `resolveShippingPrice` | Fetches the `amount_cents` for a shipping rate in a specific currency. |
| `getCurrencyIdForRegion` | Retrieves the UUID of the currency assigned to a region. |
| `getCurrencyCodeForRegion` | Returns the ISO 4217 code (e.g., "USD") for a region. |

### Implementation of Strict Resolution

The following snippet demonstrates how `resolveVariantPrice` enforces the "explicit pricing only" rule.

```typescript
// From apps/merchant/src/lib/pricing.ts
export async function resolveVariantPrice(
  db: Database,
  variantId: string,
  currencyId: string | null
): Promise<number> {
  if (!currencyId) {
    throw ApiError.notFound("Cannot resolve variant price: no currency specified");
  }

  // We query variant_prices, NOT the variants table
  const [row] = await db.query<{ price_cents: number }>(
    `SELECT price_cents FROM variant_prices
     WHERE variant_id = ? AND currency_id = ?`,
    [variantId, currencyId]
  );

  if (!row) {
    // If it's not in the join table, we don't fall back to a default
    throw ApiError.notFound(`Price not configured for this variant in the requested currency.`);
  }

  return row.price_cents;
}
```

## Discounts and Promo Codes

Discounts in Fufuni are managed via the `discounts` table and validated using logic found in `apps/merchant/src/routes/discounts.ts`. Discounts can be of type `percentage` or `fixed_amount`.

### Discount Calculation Logic

The calculation logic handles two critical constraints:
1.  **Percentage Caps**: If a percentage discount has a `max_discount_cents`, the calculated amount will never exceed this cap.
2.  **Subtotal Floor**: Fixed amount discounts are capped at the subtotal (you cannot have a negative total).

```typescript
import { Discount } from '../routes/discounts';

export function calculateDiscount(discount: Discount, subtotalCents: number): number {
  switch (discount.type) {
    case 'percentage': {
      // Calculate percentage: (subtotal * percentage) / 100
      let amount = Math.floor((subtotalCents * discount.value) / 100);
      
      // Apply the cap if it exists
      if (discount.max_discount_cents !== null && amount > discount.max_discount_cents) {
        amount = discount.max_discount_cents;
      }
      return amount;
    }
    case 'fixed_amount': {
      // Return the smaller of the fixed value or the actual subtotal
      return Math.min(discount.value, subtotalCents);
    }
    default:
      return 0;
  }
}
```

### Validation Rules

Before a discount is applied to a cart, it undergoes several checks:
- **Status**: Must be `active`.
- **Temporal**: Current time must be between `starts_at` and `expires_at`.
- **Minimum Purchase**: The cart subtotal must meet `min_purchase_cents`.
- **Usage Limits**: Total usage must be below `usage_limit`.
- **Per-Customer Limits**: If an email is provided, it checks the `discount_usage` table to ensure the customer hasn't exceeded `usage_limit_per_customer`.

```typescript
// Usage example in a Cart route
import { validateDiscount } from '../routes/discounts';

async function applyCoupon(db: any, cart: any, couponCode: string) {
  const [discount] = await db.query<Discount>(
    `SELECT * FROM discounts WHERE code = ?`, 
    [couponCode.toUpperCase()]
  );

  if (!discount) throw ApiError.notFound("Invalid coupon code");

  // This will throw an ApiError with a descriptive message if invalid
  await validateDiscount(
    db, 
    discount, 
    cart.subtotal_cents, 
    cart.customer_email
  );

  return calculateDiscount(discount, cart.subtotal_cents);
}
```

## Stripe Synchronization

To ensure that Fufuni discounts work seamlessly with Stripe Checkout or Stripe-hosted invoices, the framework synchronizes internal discount records with Stripe's API.

### Coupons vs. Promotion Codes

- **Stripe Coupon**: Represents the actual reduction logic (e.g., 20% off). This is the "parent" object in Stripe.
- **Stripe Promotion Code**: The customer-facing string (e.g., "SUMMER2025"). This points to a Coupon.

When a discount is created or updated in Fufuni, the `syncDiscountToStripe` function is triggered.

### Sync Logic Flow

1.  **Creation**: If a discount has a code, Fufuni creates a Stripe Coupon first, then creates a Stripe Promotion Code tied to it.
2.  **Updating**: Stripe objects are largely immutable. If the value or type changes, Fufuni deletes the old Coupon/Promotion Code and creates new ones, updating the local `stripe_coupon_id` and `stripe_promotion_code_id` in the SQLite database.
3.  **Deactivation**: If the discount status is set to `inactive`, Fufuni updates the Stripe Promotion Code to `active: false`.

```typescript
// Snippet of Stripe sync logic during Discount update
const stripeRelevantFields = ['code', 'value', 'max_discount_cents', 'expires_at', 'status'];
const shouldSyncStripe = updates.some((update) =>
  stripeRelevantFields.some((field) => update.includes(field))
);

if (shouldSyncStripe && stripeSecretKey) {
  const stripeSync = await syncDiscountToStripe(stripeSecretKey, {
    ...discount, // updated local fields
  });

  if (stripeSync.couponId !== discount.stripe_coupon_id) {
    // Persist new Stripe IDs to local DB
    await db.run(
      `UPDATE discounts SET stripe_coupon_id = ?, stripe_promotion_code_id = ? WHERE id = ?`,
      [stripeSync.couponId, stripeSync.promotionCodeId, discount.id]
    );
  }
}
```

### Limitations of Stripe Sync

- **Percentage Caps**: Stripe Coupons do not natively support a "maximum discount amount" for percentage off. If a Fufuni discount uses `max_discount_cents` with a `percentage` type, the Stripe sync will return `null`. In these cases, the discount is handled purely within Fufuni's checkout logic and passed to Stripe as a manual line-item adjustment or a custom price.
- **Currency**: Fixed amount discounts synced to Stripe are currently hardcoded to `usd` in the sync helper. Multi-currency fixed discounts in Stripe require separate coupons per currency.

## Summary of Pricing Logic

When contributing to the framework, remember these three rules:
1.  **Never read `variants.price_cents`** for production cart logic; always join on `variant_prices` using the current region's currency.
2.  **Use `lib/pricing.ts`** for all calculations to maintain the single source of truth.
3.  **Validate before Calculating**: Always call `validateDiscount` before `calculateDiscount` to ensure usage limits and expiry dates are honored.
