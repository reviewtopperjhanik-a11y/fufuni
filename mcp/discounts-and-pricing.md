## Discount system architecture

The Fufuni discount engine is integrated into both the merchant administration API and the public-facing checkout flow. It utilizes SQLite within Durable Objects to ensure atomic updates to usage counters, preventing "over-redeeming" of limited-use coupons. Discounts can be global (coupon codes) or specific to customer tiers, and are synchronized with Stripe for external payment processing.

### Supported discount types and fields

Discounts are defined by their logic and constraints. While stored in the `discounts` table, they follow a specific schema for application:

| Type | Description |
| :--- | :--- |
| `percentage` | Reduces subtotal by a percent (0-100). Can be capped by `max_discount_cents`. |
| `fixed_amount` | Subtracts a specific integer amount (in cents). Usually currency-specific. |
| `free_shipping` | Negates the shipping rate cost. Often has a `min_purchase_cents` threshold. |

```typescript
// Internal representation of a Discount record
export interface Discount {
  id: string;
  code: string | null;           // The human-readable coupon code (e.g., SUMMER25)
  type: 'percentage' | 'fixed_amount' | 'free_shipping';
  value: number;                // Percentage (0-100) or Amount (in cents)
  status: 'active' | 'inactive';
  min_purchase_cents: number;   // Threshold required to apply the discount
  max_discount_cents: number | null; // Ceiling for percentage discounts
  starts_at: string | null;      // ISO 8601 timestamp
  expires_at: string | null;     // ISO 8601 timestamp
  usage_limit: number | null;    // Total number of times this code can be used
  usage_count: number;           // Current atomic count
  usage_limit_per_customer: number | null;
}
```

## Admin API: Creating discounts

Admin users manage discounts via the `/v1/discounts` endpoint. When a discount is created or updated, the system optionally synchronizes it with Stripe to allow for native Stripe Checkout coupon support.

### POST /v1/discounts (Admin)

Requires `admin:store` scope or a legacy secret key. The code is automatically normalized to uppercase and trimmed before storage.

```typescript
// Example Request Body
{
  "code": "WELCOME10",
  "type": "percentage",
  "value": 10,
  "min_purchase_cents": 5000, // Requires $50.00 minimum
  "usage_limit": 100,
  "starts_at": "2025-01-01T00:00:00Z",
  "expires_at": "2025-12-31T23:59:59Z"
}
```

The implementation ensures codes are unique and percentage values are within the valid 0-100 range:

```typescript
adminApp.openapi(createDiscount, async (c) => {
  const body = c.req.valid('json');
  const db = getDb(c.var.db);

  if (body.type === 'percentage' && (body.value < 0 || body.value > 100)) {
    throw ApiError.invalidRequest('Percentage must be between 0 and 100');
  }

  const id = uuid();
  const normalizedCode = body.code?.toUpperCase().trim() || null;

  // Atomic check for existing code
  if (normalizedCode) {
    const [existing] = await db.query(`SELECT id FROM discounts WHERE code = ?`, [normalizedCode]);
    if (existing) throw ApiError.conflict(`Code ${normalizedCode} is already taken`);
  }

  await db.run(
    `INSERT INTO discounts (id, code, type, value, min_purchase_cents, status, created_at)
     VALUES (?, ?, ?, ?, ?, 'active', ?)`,
    [id, normalizedCode, body.type, body.value, body.min_purchase_cents || 0, now()]
  );

  return c.json({ id, code: normalizedCode }, 201);
});
```

## Public validation and usage

The public validation endpoint allows customers to check if a coupon is valid for their current cart before proceeding to checkout.

### POST /v1/discounts/validate (Public)

This endpoint evaluates the cart against the discount's constraints. It returns the calculated reduction and the final total.

**Error conditions for 422 Unprocessable Entity:**
1.  **Inactive**: `status` is not 'active'.
2.  **Timing**: Current time is before `starts_at` or after `expires_at`.
3.  **Threshold**: `subtotal_cents` is less than `min_purchase_cents`.
4.  **Exhausted**: `usage_count` >= `usage_limit`.
5.  **Repeated**: `usage_limit_per_customer` exceeded for the provided email.

```typescript
export async function validateDiscount(
  db: Database,
  discount: Discount,
  subtotalCents: number,
  customerEmail?: string
): Promise<void> {
  const currentTime = now();
  
  if (discount.status !== 'active') throw ApiError.invalidRequest('Discount inactive');
  if (discount.expires_at && currentTime > discount.expires_at) {
    throw ApiError.invalidRequest('Discount expired');
  }
  
  if (subtotalCents < discount.min_purchase_cents) {
    throw ApiError.invalidRequest(`Minimum purchase of $${(discount.min_purchase_cents / 100).toFixed(2)} required`);
  }

  // Atomic usage check
  if (discount.usage_limit !== null && discount.usage_count >= discount.usage_limit) {
    throw ApiError.invalidRequest('Discount usage limit reached');
  }
}
```

## Atomic use counting

Fufuni leverages Durable Objects' serializable consistency to prevent race conditions during coupon redemption. When an order is finalized, the usage count is incremented within a single SQLite transaction.

```sql
-- Executed inside the Order creation transaction
UPDATE discounts 
SET usage_count = usage_count + 1, 
    updated_at = ? 
WHERE id = ? AND (usage_limit IS NULL OR usage_count < usage_limit);
```

If the `UPDATE` statement affects 0 rows, the transaction is rolled back, and the order is rejected because the discount reached its limit in the millisecond between validation and finalization.

## Pricing pipeline

The final price of an item in Fufuni is determined by a strict 4-step sequence. This pipeline ensures that taxes are correctly calculated on the actual amount paid by the customer, and that tiered pricing is respected.

1.  **Base Price**: Resolved from the `variant_prices` table based on the cart's currency.
2.  **Tier Pricing**: If the customer belongs to a specific group (e.g., VIP, Wholesale), the base price is overridden by the tier price.
3.  **Discount**: The applicable discount (coupon or automatic) is subtracted from the subtotal.
4.  **Tax**: Sales tax or VAT is computed based on the *discounted* subtotal.

```typescript
/**
 * Illustrative pricing pipeline calculation
 */
function calculateFinalPrice(
  basePrice: number, 
  tierPrice: number | null, 
  discount: Discount | null, 
  taxRate: number
): number {
  // 1 & 2: Base and Tier
  let price = tierPrice ?? basePrice;
  
  // 3: Apply Discount
  let discountAmount = 0;
  if (discount) {
    discountAmount = calculateDiscount(discount, price);
  }
  const discountedSubtotal = Math.max(0, price - discountAmount);
  
  // 4: Compute Tax
  const taxAmount = Math.round(discountedSubtotal * taxRate);
  
  return discountedSubtotal + taxAmount;
}
```

## Pricing resolution helpers

The `lib/pricing.ts` module provides high-level helpers for multi-currency support. Fufuni uses a "Strict Fallback" model: if a price is not explicitly defined for a currency, the system throws an error rather than guessing a conversion rate.

### resolveVariantPrice
Fetches the price for a specific variant and currency combination.

## Multi-currency and storage standards

### Integer Cents Storage
All monetary values in the database (prices, discounts, taxes, subtotals) are stored as **integers** representing the smallest unit of the currency.
-   USD $10.00 → `1000`
-   JPY ¥1000 → `1000` (zero-decimal currencies are handled by the currency configuration)
-   EUR €5.50 → `550`

### Client-side Formatting
The backend never sends formatted strings (like "$10.00"). It sends integers and the ISO 4217 currency code. Formatting is the responsibility of the frontend using the `Intl.NumberFormat` API.

```typescript
/**
 * Frontend formatting utility (React/HeroUI context)
 */
export function formatCurrency(amountCents: number, currencyCode: string = 'USD'): string {
  const formatter = new Intl.NumberFormat('en-US', {
    style: 'currency',
    currency: currencyCode,
  });
  
  // Note: Handle zero-decimal currencies if necessary based on code
  return formatter.format(amountCents / 100);
}

// Usage in HeroUI Component
// <Chip color="success">{formatCurrency(discount.value, 'USD')}</Chip>
```

By strictly separating the logic of **storage** (integers), **resolution** (explicit mapping), and **display** (locale-aware formatting), the Fufuni framework avoids floating-point rounding errors and ensures consistent pricing across different global regions.
