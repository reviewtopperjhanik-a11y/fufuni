## Regions: Geographic and Fiscal Grouping

In Fufuni, a **Region** is the top-level configuration entity that defines how customers in specific geographic areas are treated regarding currency, taxation, and shipping availability. A region is not necessarily a single country; it is a grouping of one or more countries (using ISO 3166-1 alpha-2 codes) that share identical fiscal rules.

### Data Model and Schema

A region consists of a unique identifier, a display name, an array of country codes, a primary currency, and settings for tax calculation. In the SQLite backend (Durable Objects), `country_codes` is stored as a JSON string.

### Region Resolution

During the checkout process, the framework resolves the active region based on the customer's billing address country code. If no specific region matches the country, the system falls back to the region marked `is_default: true`.

```typescript
// Example of region resolution logic in the backend
async function resolveRegion(db: Database, countryCode: string): Promise<Region> {
  const allRegions = await db.query<any>('SELECT * FROM regions');
  
  // Find region containing the country code
  const match = allRegions.find(r => {
    const codes = JSON.parse(r.country_codes);
    return codes.includes(countryCode.toUpperCase());
  });

  if (match) return match;

  // Fallback to default
  const defaultRegion = allRegions.find(r => r.is_default === 1);
  if (!defaultRegion) throw new ApiError('No default region configured', 500);
  
  return defaultRegion;
}
```

## Tax Rates and Logic

Tax rates in Fufuni are bound to regions. A region can have multiple tax rates (e.g., standard rate, reduced rate for food), which are applied to products based on the product's `tax_code`.

### Inclusive vs. Exclusive Taxes

Fufuni handles two primary tax calculation modes defined by the `is_inclusive` flag on the tax rate:

1.  **Inclusive (is_inclusive: true)**: The price displayed to the customer already includes the tax. The system must "extract" the tax amount from the gross price to determine the net value.
    *   *Formula*: `Tax = GrossPrice * (Rate / (1 + Rate))`
2.  **Exclusive (is_inclusive: false)**: The price displayed is the net price. The system adds the tax on top during checkout.
    *   *Formula*: `Tax = NetPrice * Rate`

### Data Model and Admin API

The `tax_rates` table stores the decimal rate (e.g., `0.20` for 20%) and the association with a region.

## Tax Calculation Library (`lib/tax.ts`)

The `lib/tax.ts` file provides the core mathematical functions for the framework. All monetary values are handled in **cents** (integers) to avoid floating-point precision issues.

### Implementation of `computeTax`

The calculation logic strictly follows the verified formulas to ensure accounting accuracy.

```typescript
/**
 * Computes tax amount in cents based on the rate and inclusion mode.
 * @param price - Amount in cents (either gross or net depending on inclusive flag)
 * @param rate - Decimal rate (e.g., 0.2 for 20%)
 * @param inclusive - Whether the price already includes tax
 */
export function computeTax(price: number, rate: number, inclusive: boolean): number {
  if (inclusive) {
    // Formula: Price * rate / (1 + rate)
    // Example: 120€ inclusive with 20% tax -> 120 * 0.2 / 1.2 = 20€
    return Math.round(price * (rate / (1 + rate)));
  } else {
    // Formula: Price * rate
    // Example: 100€ exclusive with 20% tax -> 100 * 0.2 = 20€
    return Math.round(price * rate);
  }
}

/**
 * Formats tax for display
 */
export function formatTaxAmount(amount: number, currency: string): string {
  return new Intl.NumberFormat('en-US', {
    style: 'currency',
    currency: currency,
  }).format(amount / 100);
}
```

## Shipping Zones and Methods

Shipping is managed through **Shipping Zones**. A zone acts as a bridge between one or more Regions and specific **Shipping Methods**.

### Data Model

*   **Shipping Zone**: A logical group (e.g., "North America", "Local Delivery"). Contains `region_ids[]`.
*   **Shipping Method**: A specific carrier service (e.g., "FedEx Ground") with pricing rules.

```sql
-- Creating a Shipping Method with a free threshold
CREATE TABLE shipping_methods (
    id TEXT PRIMARY KEY,
    zone_id TEXT NOT NULL,
    carrier TEXT NOT NULL, -- e.g., 'DHL'
    service TEXT NOT NULL, -- e.g., 'Express Worldwide'
    price_cents INTEGER NOT NULL,
    free_threshold_cents INTEGER, -- NULL if no free shipping available
    min_delivery_days INTEGER,
    max_delivery_days INTEGER,
    FOREIGN KEY (zone_id) REFERENCES shipping_zones(id)
);
```

### Free Shipping Logic

The `free_threshold_cents` field determines if the shipping cost should be waived. If the order subtotal (before shipping but after discounts) is greater than or equal to this threshold, the price for that method becomes `0`.

## Shipping Logic Library (`lib/shipping.ts`)

This library filters and prices shipping methods based on the current cart state.

### `getShippingMethods` Implementation

The following function retrieves all valid methods for a region and applies the free shipping logic.

```typescript
export async function getShippingMethods(
  db: Database, 
  regionId: string, 
  subtotalCents: number
): Promise<ShippingRateItem[]> {
  // 1. Find the zone that includes this region
  const zones = await db.query<any>(`
    SELECT sz.* FROM shipping_zones sz
    WHERE sz.region_ids LIKE ?
  `, [`%${regionId}%`]);

  if (zones.length === 0) return [];

  const zoneIds = zones.map(z => z.id);
  
  // 2. Get all methods for these zones
  const methods = await db.query<any>(`
    SELECT * FROM shipping_methods 
    WHERE zone_id IN (${zoneIds.map(() => '?').join(',')})
  `, zoneIds);

  // 3. Map and apply free shipping threshold
  return methods.map(method => {
    const isFree = method.free_threshold_cents !== null && 
                   subtotalCents >= method.free_threshold_cents;
    
    return {
      id: method.id,
      display_name: `${method.carrier} ${method.service}`,
      amount_cents: isFree ? 0 : method.price_cents,
      currency: method.currency,
      tax_code: method.tax_code,
      tax_inclusive: method.tax_inclusive === 1
    };
  }).sort((a, b) => a.amount_cents - b.amount_cents); // Cheapest first
}
```

## Checkout Integration Flow

The integration of regions, taxes, and shipping occurs in a specific sequence during the checkout lifecycle.

### 1. Region Detection
As soon as the customer provides their shipping/billing country code, the `POST /v1/carts/:id/shipping-address` endpoint triggers a region re-evaluation. This updates the cart's `region_id`.

### 2. Shipping Rate Generation
Once the region is known, the frontend calls `GET /v1/carts/:id/shipping-rates`. The backend uses `getShippingMethods` from `lib/shipping.ts`.

### 3. Auto-Selection Logic
If the customer has not yet selected a shipping method (e.g., on first load or after an address change), the system performs an **auto-selection**:
- It identifies all eligible methods.
- It selects the method with the lowest `amount_cents`.
- It updates the cart's `shipping_rate_id` automatically to ensure the total is always valid.

### 4. Final Tax Recalculation
With the `region_id`, `shipping_rate_id`, and items known, the `calculateCartTaxes` function (from `lib/tax.ts`) is called:
- It looks up the `tax_rate` for each item's `tax_code` in the resolved region.
- It calculates tax for each item.
- It calculates tax for the shipping cost itself (if the shipping rate has a `tax_code`).
- It sums everything into a final tax total.
