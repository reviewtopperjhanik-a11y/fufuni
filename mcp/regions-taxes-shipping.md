## The Region Architecture

In Fufuni, a **Region** is the central logical unit that defines the commercial and logistical boundaries of a store's operation. It is not merely a geographical label; it is a configuration object that binds together specific countries, inventory sources (warehouses), and available shipping methods.

### Region Associations

A single region acts as a parent for three primary sub-entities:
1.  **Countries (`region_countries`)**: Determines which shipping addresses are valid for this region.
2.  **Warehouses (`region_warehouses`)**: Defines which inventory locations are allowed to fulfill orders for this region.
3.  **Shipping Rates (`region_shipping_rates`)**: Determines the delivery options and costs available to the customer based on the region.

The following TypeScript example demonstrates how to associate a country with a region using the Fufuni `adminApp` patterns:

### Database Schema Overview

The relationship is enforced through join tables in the SQLite (Durable Object) storage. This ensures that a warehouse in the "EU Region" cannot accidentally fulfill an order destined for the "US Region" unless explicitly mapped.

```sql
-- Join table for Region and Warehouses
CREATE TABLE region_warehouses (
    region_id TEXT NOT NULL,
    warehouse_id TEXT NOT NULL,
    PRIMARY KEY (region_id, warehouse_id),
    FOREIGN KEY (region_id) REFERENCES regions(id) ON DELETE CASCADE,
    FOREIGN KEY (warehouse_id) REFERENCES warehouses(id) ON DELETE CASCADE
);

-- Join table for Region and Shipping Rates
CREATE TABLE region_shipping_rates (
    region_id TEXT NOT NULL,
    shipping_rate_id TEXT NOT NULL,
    PRIMARY KEY (region_id, shipping_rate_id),
    FOREIGN KEY (region_id) REFERENCES regions(id) ON DELETE CASCADE,
    FOREIGN KEY (shipping_rate_id) REFERENCES shipping_rates(id) ON DELETE CASCADE
);
```

## Tax Logic and `tax_inclusive` Behavior

Fufuni handles tax calculations through `lib/tax.ts`. The framework supports two primary tax modes defined at the **Region** level via the `tax_inclusive` boolean flag.

### Inclusive vs. Exclusive Taxes

*   **Tax Inclusive (`tax_inclusive: true`)**: Common in the EU (VAT). The `unit_price_cents` stored in the database and displayed to the user already includes the tax. The framework must "back-calculate" the tax amount to determine the net value.
*   **Tax Exclusive (`tax_inclusive: false`)**: Common in the US (Sales Tax). The `unit_price_cents` is the base price. The framework adds the calculated tax on top of this price at checkout.

### Implementation in `calculateCartTaxes`

The calculation logic retrieves the `tax_code` for each item and the `shipping_country` from the cart. It then finds the matching `tax_rates` to apply the correct percentage.

```typescript
// Simplified logic from lib/tax.ts showing the inclusive vs exclusive math
export function calculateTaxAmount(
  priceCents: number, 
  ratePercentage: number, 
  isInclusive: boolean
): number {
  if (isInclusive) {
    // Formula: Tax = TotalPrice - (TotalPrice / (1 + Rate))
    // Example: 120€ total, 20% tax -> 120 - (120 / 1.2) = 20€
    const divisor = 1 + (ratePercentage / 100);
    const netPrice = priceCents / divisor;
    return Math.round(priceCents - netPrice);
  } else {
    // Formula: Tax = BasePrice * Rate
    // Example: 100€ base, 20% tax -> 100 * 0.2 = 20€
    return Math.round(priceCents * (ratePercentage / 100));
  }
}
```

When processing a cart, the `calculateCartTaxes` function iterates through items, matches their `tax_code` (e.g., `standard`, `reduced`, `exempt`) against the active rates for the destination country, and aggregates the results.

### Applying Tax to Shipping Rates

Shipping is treated as a line item with its own specific tax rules. Every `shipping_rate` entity in Fufuni includes a `tax_code` field. This is vital because many jurisdictions apply different tax rates to shipping services than to physical goods.

For example, in some regions, if you ship a book (low tax) and a toy (standard tax), the shipping might be taxed at the standard rate regardless of the contents.

```typescript
/**
 * Resolves the shipping tax amount during cart calculation
 */
async function resolveShippingTax(db: Database, shippingRateId: string, countryCode: string) {
  const [rateData] = await db.query<any>(`
    SELECT sr.tax_code, sr.tax_inclusive, sr.amount_cents, tr.rate_percentage
    FROM shipping_rates sr
    LEFT JOIN tax_rates tr ON sr.tax_code = tr.tax_code AND tr.country_code = ?
    WHERE sr.id = ?
  `, [countryCode, shippingRateId]);

  if (!rateData || !rateData.rate_percentage) return 0;

  return calculateTaxAmount(
    rateData.amount_cents, 
    rateData.rate_percentage, 
    rateData.tax_inclusive === 1
  );
}
```

## Shipping Rate Resolution and Classes

Fufuni uses a priority-based system to determine which shipping rates apply to a cart. This involves filtering rates by region and then by "Shipping Classes."

### Shipping Class Filtering

Shipping classes allow you to restrict certain rates to specific products. For instance, a "Heavy Goods" class might only allow "Freight Shipping." 

The resolution logic in `lib/shipping.ts` follows these rules:
1.  **Variant Override**: If a product variant has a `shipping_class_id`, it overrides the parent product's class.
2.  **Exclusive Classes**: If any item in the cart belongs to a shipping class marked as `is_exclusive`, only shipping rates that explicitly support that class will be shown.
3.  **Default Rates**: If no exclusive classes are present, standard rates (those without class restrictions) are typically shown alongside class-specific rates.

### Example: Fetching Compatible Rates

This logic is typically called when the user reaches the shipping selection step in the React frontend.

```typescript
// lib/shipping.ts logic implementation
export async function getCompatibleShippingRates(
  db: DB,
  region_id: string,
  classResolution: CartClassResolution
): Promise<ShippingRateItem[]> {
  // 1. Get all rates associated with this region
  let query = `
    SELECT sr.* FROM shipping_rates sr
    JOIN region_shipping_rates rsr ON sr.id = rsr.shipping_rate_id
    WHERE rsr.region_id = ?
  `;
  
  const params: any[] = [region_id];
  const allRates = await db.query<any>(query, params);

  // 2. Filter based on classes present in the cart
  return allRates.filter(rate => {
    // If the cart has an exclusive item, the rate MUST match one of the cart's classes
    if (classResolution.has_exclusive) {
      return rate.shipping_class_id && classResolution.class_ids.has(rate.shipping_class_id);
    }
    
    // Otherwise, allow rates that match the classes OR rates with no class restriction
    return !rate.shipping_class_id || classResolution.class_ids.has(rate.shipping_class_id);
  });
}
```

## Practical Implementation: The Region Management UI

In the frontend (React 19 + HeroUI v3), managing these complex relationships requires a tabbed or multi-select interface. When an administrator updates a Region, the UI must handle the synchronization of `region_countries` and `region_warehouses`.

The following component snippet demonstrates how a junior developer might implement the "Add Country to Region" toggle using HeroUI:

```tsx
import { Button, Checkbox, CheckboxGroup } from "@heroui/react";
import { useState } from "react";

interface RegionCountryManagerProps {
  regionId: string;
  availableCountries: { code: string; name: string }[];
  initialSelected: string[];

  const [selected, setSelected] = useState<string[]>(initialSelected);
  const [isLoading, setIsLoading] = useState(false);

  const handleSave = async () => {
    setIsLoading(true);
    // In a real app, you would diff the 'selected' array

    <div className="flex flex-col gap-4">
      <CheckboxGroup
        label="Select countries for this region"

        onValueChange={setSelected}
      >

          <Checkbox key={c.code} value={c.code}>
            {c.name} ({c.code})
          </Checkbox>
        ))}
      </CheckboxGroup>
      <Button 
        color="primary" 
        isLoading={isLoading} 
        onPress={handleSave}
      >
        Save Region Boundaries
      </Button>
    </div>
  );
};
```

## Summary of Configuration Flow

To correctly set up a new market in Fufuni, follow this sequence:

1.  **Create Currencies and Countries**: Ensure the ISO codes exist in the database.
2.  **Define Tax Rates**: Create `tax_rates` for the target country (e.g., US-NY at 8.875% or FR at 20%).
3.  **Create Region**: Set the `tax_inclusive` flag based on local customs.
4.  **Map Entities**: Link the countries, warehouses, and shipping rates to the Region.
5.  **Assign Tax Codes**: Ensure all `variants` and `shipping_rates` have a `tax_code` that matches the keys defined in step 2.

This architecture ensures that Fufuni remains highly flexible for international commerce while maintaining strict data integrity within the SQLite-backed Durable Objects.
