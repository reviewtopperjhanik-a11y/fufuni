## Regions: Geographic Strategy
Regions in Fufuni serve as the foundational grouping for localization and logistics. A region aggregates multiple countries under a single currency and set of shipping/tax rules. While a country (ISO 3166-1 alpha-2) belongs to exactly one region, a region can contain many countries.

### Region Data Model
Regions are stored in the SQLite database managed by the Durable Object. The `country_codes` field is handled as a JSON array of strings.

| Field | Type | Description |
| :--- | :--- | :--- |
| `id` | UUID | Primary identifier. |
| `name` | String | Internal label (e.g., "European Union", "North America"). |
| `country_codes` | String[] | Array of ISO 3166-1 alpha-2 codes (e.g., `['FR', 'DE', 'BE']`). |
| `currency_code` | String | ISO 4217 code (e.g., `EUR`, `USD`). |
| `is_default` | Boolean | Fallback region if no mapping is found. |

### CRUD Endpoints
The admin API provides endpoints to manage these associations. When creating or updating a region, the framework ensures that country codes do not overlap between regions.

## Tax Rates: Inclusive vs. Exclusive Logic
Tax rates are defined per region. Fufuni supports two primary tax calculation modes: **Inclusive** (tax is already inside the displayed price) and **Exclusive** (tax is added on top of the price at checkout).

### Configuration
Tax rates are managed via `POST /v1/tax-rates`.

*   **rate**: A decimal value representing the percentage (e.g., `0.20` for 20%).
*   **is_inclusive**: If `true`, the store price (e.g., $120) includes the tax. If `false`, the tax is calculated and added to the subtotal.

### Formulae
1.  **Inclusive Tax**: $Tax = \text{Price} \times \frac{Rate}{1 + Rate}$
2.  **Exclusive Tax**: $Tax = \text{Price} \times Rate$

```typescript
// Example: Adding a 20% VAT rate to a European region
const createTaxRate = createRoute({
  method: 'post',
  path: '/v1/tax-rates',
  request: {
    body: {
      content: {
        'application/json': {
          schema: z.object({
            region_id: z.string().uuid(),
            rate: z.number().min(0).max(1),
            label: z.string(),
            is_inclusive: z.boolean(),
          })
        }
      }
    }
  },
  responses: {
    201: { description: 'Tax rate defined' }
  }
});
```

## lib/tax.ts: Calculation Utilities
The `lib/tax.ts` file centralizes all mathematical operations related to taxes. All price inputs and outputs must be in the smallest currency unit (cents).

### computeTax Signature
The `computeTax` function implements the verified math logic described above.

```typescript
/**
 * Computes the tax amount in cents based on the rate and inclusive flag.
 * @param price - Price in cents
 * @param rate - Decimal rate (0.2 for 20%)
 * @param inclusive - Whether price already includes tax
 */
export function computeTax(price: number, rate: number, inclusive: boolean): number {
  if (inclusive) {
    // Tax = Price * Rate / (1 + Rate)
    return Math.round(price * rate / (1 + rate));
  }
  // Tax = Price * Rate
  return Math.round(price * rate);
}

/**
 * Formats a cent amount into a human-readable string based on currency.
 */
export function formatTaxAmount(amountCents: number, currency: string): string {
  return new Intl.NumberFormat('en-US', {
    style: 'currency',
    currency: currency,
  }).format(amountCents / 100);
}

// Usage Example
const vatAmount = computeTax(12000, 0.20, true); // Result: 2000 cents ($20.00)
const salesTax = computeTax(10000, 0.08, false); // Result: 800 cents ($8.00)
```

## Shipping Zones & Methods
Shipping logic is decoupled into **Zones** and **Methods**. A Shipping Zone is a collection of Regions that share the same shipping availability.

### Data Relationship
- **Shipping Zone**: Contains one or more `region_ids`.
- **Shipping Method**: Belongs to a Zone. Defines the carrier, price, and free shipping thresholds.

| Field | Type | Description |
| :--- | :--- | :--- |
| `carrier` | String | e.g., "FedEx", "DHL", "Local Pickup". |
| `service` | String | e.g., "Express", "Standard Ground". |
| `price_cents` | Integer | Cost of shipping in cents. |
| `free_threshold` | Integer | Optional. Subtotal (cents) required for free shipping. |

### Creating a Shipping Zone
```typescript
// Example: Creating a Zone for North America with a free shipping threshold
const createShippingZone = async (db: Database) => {
  const zoneId = uuid();
  await db.query(
    `INSERT INTO shipping_zones (id, name) VALUES (?, ?)`,
    [zoneId, "North America"]
  );
  
  // Link regions to zone
  await db.query(
    `INSERT INTO shipping_zone_regions (zone_id, region_id) VALUES (?, ?)`,
    [zoneId, "usa-region-uuid"]
  );

  // Add a method with a $100 free shipping threshold
  await db.query(
    `INSERT INTO shipping_methods (id, zone_id, carrier, service, price_cents, free_threshold)
     VALUES (?, ?, ?, ?, ?, ?)`,
    [uuid(), zoneId, "FedEx", "Home Delivery", 1500, 10000]
  );
};
```

## lib/shipping.ts: Resolution Logic
The shipping library filters available methods based on the current cart state and the target region.

### getShippingMethods Logic
This function retrieves all methods available for the region and applies the `free_threshold` logic. If the `subtotal_cents` is equal to or greater than the threshold, the `price_cents` for that method is treated as `0` for the response.

```typescript
export interface ShippingMethodResult {
  id: string;
  carrier: string;
  service: string;
  price_cents: number;
  is_free: boolean;
}

/**
 * Resolves eligible shipping methods for a specific region and subtotal.
 */
export async function getShippingMethods(
  db: any, 
  regionId: string, 
  subtotalCents: number
): Promise<ShippingMethodResult[]> {
  const methods = await db.query<any>(`
    SELECT sm.* 
    FROM shipping_methods sm
    JOIN shipping_zone_regions szr ON sm.zone_id = szr.zone_id
    WHERE szr.region_id = ?
  `, [regionId]);

  return methods.map(m => {
    const eligibleForFree = m.free_threshold !== null && subtotalCents >= m.free_threshold;
    return {
      id: m.id,
      carrier: m.carrier,
      service: m.service,
      price_cents: eligibleForFree ? 0 : m.price_cents,
      is_free: eligibleForFree
    };
  }).sort((a, b) => a.price_cents - b.price_cents);
}
```

## Checkout Integration
The checkout flow orchestrates these modules to provide a seamless calculation experience.

### Region Resolution
The region is **not** determined by the user's IP or browser settings. It is strictly determined by the **billing address country code** provided during the checkout process. This ensures that the tax and currency rules match the financial jurisdiction of the transaction.

### Auto-Selection of Shipping
To reduce friction, the system automatically selects the cheapest eligible shipping method if the user has not explicitly chosen one.

```typescript
// High-level Checkout Logic Flow
async function processCheckout(cartId: string, billingCountry: string) {
  const db = getDb();
  
  // 1. Identify Region
  const region = await db.query(
    "SELECT id FROM regions WHERE country_codes LIKE ?", 
    [`%${billingCountry}%`]
  );
  const regionId = region[0]?.id || DEFAULT_REGION_ID;

  // 2. Calculate Subtotal
  const subtotal = await calculateCartSubtotal(cartId);

  // 3. Get Shipping
  const availableMethods = await getShippingMethods(db, regionId, subtotal);
  const selectedMethod = availableMethods[0]; // Auto-select cheapest

  // 4. Calculate Taxes
  const taxRate = await db.query(
    "SELECT rate, is_inclusive FROM tax_rates WHERE region_id = ?", 
    [regionId]
  );
  const taxAmount = computeTax(subtotal, taxRate[0].rate, taxRate[0].is_inclusive);

  return {
    regionId,
    shipping_cost: selectedMethod.price_cents,
    tax_total: taxAmount,
    grand_total: subtotal + (taxRate[0].is_inclusive ? 0 : taxAmount) + selectedMethod.price_cents
  };
}
```

### Key Implementation Constraints
- **Validation**: When an address is updated in the cart, the backend must re-trigger the region resolution and recalculate all shipping/tax fields.
- **Precision**: Always perform calculations in cents to avoid floating-point errors. Use `Math.round()` only at the final step of a specific calculation (e.g., `computeTax`).
- **Currency Locking**: Once a region is resolved, all prices displayed in the checkout must use the `currency_code` associated with that region. If the cart was initialized in USD but the billing address is FR (Europe Region - EUR), the framework handles the conversion or enforces region-specific pricing.
