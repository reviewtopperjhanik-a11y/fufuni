## Regional Architecture

In Fufuni, a **Region** is the top-level organizational unit for geographical commerce logic. It does not simply represent a "country," but rather a collection of logistical and financial rules applied to a specific set of territories. A single region serves as the glue between localized pricing (Currencies), physical fulfillment (Warehouses), and delivery options (Shipping Rates).

### Entity Grouping

A region acts as a container for three primary many-to-many associations. These relationships determine what a customer sees and how their order is processed based on their shipping address:

1.  **Countries (`region_countries`)**: Defines which ISO countries belong to this region. A country usually belongs to only one active region to avoid calculation conflicts.
2.  **Warehouses (`region_warehouses`)**: Specifies which physical locations are permitted to fulfill orders for this region. This is critical for inventory availability checks during checkout.
3.  **Shipping Rates (`region_shipping_rates`)**: Links specific shipping methods to the region. This allows a merchant to offer "Express Shipping" at different price points or with different providers depending on the region.

The following SQL schema illustrates how these associations are structured within the SQLite (Durable Object) environment:

```sql
-- The core region definition
CREATE TABLE regions (
    id TEXT PRIMARY KEY,
    name TEXT NOT NULL,
    currency_code TEXT NOT NULL,
    tax_inclusive INTEGER DEFAULT 0, -- 1 for inclusive, 0 for exclusive
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- Association: Region to Countries
CREATE TABLE region_countries (
    region_id TEXT NOT NULL,
    country_code TEXT NOT NULL, -- ISO 3166-1 alpha-2
    PRIMARY KEY (region_id, country_code),
    FOREIGN KEY (region_id) REFERENCES regions(id) ON DELETE CASCADE
);

-- Association: Region to Shipping Rates
CREATE TABLE region_shipping_rates (
    region_id TEXT NOT NULL,
    shipping_rate_id TEXT NOT NULL,
    PRIMARY KEY (region_id, shipping_rate_id),
    FOREIGN KEY (region_id) REFERENCES regions(id) ON DELETE CASCADE,
    FOREIGN KEY (shipping_rate_id) REFERENCES shipping_rates(id) ON DELETE CASCADE
);
```

## Tax Strategies: Inclusive vs. Exclusive

Fufuni handles taxation dynamically based on the `tax_inclusive` flag defined at the Region level. This boolean determines the mathematical relationship between the "Display Price" in the storefront and the "Tax Amount" calculated at checkout.

### Behavior of tax_inclusive

*   **Tax Inclusive (`tax_inclusive: 1`)**: Common in the EU (VAT) and UK. The price the customer sees on the product page (e.g., €120) already includes the tax. The framework must "back-calculate" the tax amount to show the breakdown.
    *   *Formula*: `Tax = Price - (Price / (1 + Rate))`
*   **Tax Exclusive (`tax_inclusive: 0`)**: Common in the US and Canada. The price the customer sees (e.g., $100) does not include tax. The tax is added on top during the final checkout step.
    *   *Formula*: `Tax = Price * Rate`

### Logic in `lib/tax.ts`

The `calculateCartTaxes` function is the core engine for these calculations. It retrieves the region's settings and iterates through cart items, applying the correct logic based on the item's `tax_code` and the shipping destination's `tax_rates`.

```typescript
// Simplified logic from apps/merchant/src/lib/tax.ts
export async function calculateItemTax(
  unitPriceCents: number, 
  taxRatePercentage: number, 
  isInclusive: boolean
) {
  const rate = taxRatePercentage / 100;

  if (isInclusive) {
    // Price is $120, Rate is 20% -> Net is $100, Tax is $20
    const netAmount = Math.round(unitPriceCents / (1 + rate));
    const taxAmount = unitPriceCents - netAmount;
    return { netAmount, taxAmount };
  } else {
    // Price is $100, Rate is 20% -> Net is $100, Tax is $20
    const taxAmount = Math.round(unitPriceCents * rate);
    return { netAmount: unitPriceCents, taxAmount };
  }
}
```

## Shipping Resolution and Taxation

Shipping in Fufuni is not a flat fee but a resolved entity based on the cart's content, the destination region, and specific tax rules.

### Applying Tax Codes to Shipping Rates

Every `shipping_rate` in the database has an optional `tax_code` and its own `tax_inclusive` override. This allows for complex scenarios where product taxes might be inclusive but shipping fees are exclusive, or where shipping is taxed at a different rate (e.g., "Reduced Rate" vs "Standard Rate").

The `tax_code` on a shipping rate is used by `lib/tax.ts` just like a product's tax code. If a shipping rate for "Priority Mail" has a `tax_code` of `SHIPPING_STANDARD`, the calculation engine looks for a corresponding entry in the `tax_rates` table for the customer's country that matches that code.

### Shipping Tax Calculation Example

In the following example, we see how the backend resolves the tax for a chosen shipping rate during the checkout flow:

```typescript
// apps/merchant/src/lib/tax.ts snippet for shipping
async function getShippingTax(db: Database, shippingRateId: string, countryCode: string) {
  const [rateData] = await db.query<any>(`
    SELECT amount_cents, tax_code, tax_inclusive 
    FROM shipping_rates WHERE id = ?
  `, [shippingRateId]);

  if (!rateData.tax_code) return { tax_amount: 0, ht_amount: rateData.amount_cents };

  // Look for a specific tax rate for this country and the shipping tax_code
  const [taxRule] = await db.query<any>(`
    SELECT rate_percentage FROM tax_rates 
    WHERE country_code = ? AND tax_code = ?
  `, [countryCode, rateData.tax_code]);

  const ratePercent = taxRule?.rate_percentage || 0;
  const isInclusive = rateData.tax_inclusive === 1;

  // Use the same math as item taxes
  const { netAmount, taxAmount } = await calculateItemTax(
    rateData.amount_cents, 
    ratePercent, 
    isInclusive
  );

  return {
    tax_amount: taxAmount,
    ht_amount: netAmount // The "Hors Taxe" (Net) amount
  };
}
```

1.  **Selection**: The user selects a country in the frontend. 
2.  **Region Identification**: The backend identifies the `region_id` based on `region_countries`.
