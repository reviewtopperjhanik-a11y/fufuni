## User Preferences & Wishlist Architecture

In the Fufuni framework, user data is categorized by its volatility and access frequency. We distinguish between **Wishlist** (high-read, low-write, stored in Auth0), **Saved Carts** (transient but persistent SQL storage), and **User Preferences** (structured SQL storage for localization and UI settings).

### Wishlist Storage and JWT Integration

Unlike standard e-commerce platforms that store wishlists in a `wishlist_items` SQL table, Fufuni stores the wishlist directly in the **Auth0 `user_metadata`**. 

**Why not SQL?**
1. **Zero Latency Reads:** The wishlist is injected into the user's JWT `access_token`. The frontend can extract the list of product IDs without making a single API call to the database.
2. **Cross-Service Availability:** Any microservice or worker validating the JWT instantly knows the user's favorites.
3. **Storage Format:** It is stored as a simple array of strings under the `wishlist` key.

```typescript
// Example of how the wishlist is structured in the JWT payload
{
  "sub": "auth0|65f123456789",
  "extra_user_info/user_metadata": {
    "wishlist": ["prod_01HGP", "prod_02XBT", "prod_09QWR"]
  },
  "iat": 1710336000,
  "exp": 1710340000
}
```

## The useWishlist Hook

The `useWishlist` hook is the primary interface for managing favorites. It uses `useTokenUserData` to listen for changes and `useTokenRefresh` to ensure the local state stays in sync with the Auth0 server after a mutation.

### Hook Return Values
The hook returns an object of type `UseWishlistReturn`:
- `wishlist: string[]`: Array of product IDs.
- `isLoading: boolean`: True if the token is being parsed or refreshed.
- `isFavorite: (productId: string) => boolean`: Helper to check if an item is favorited.
- `toggle: (productId: string) => Promise<void>`: Adds or removes the item and triggers a token refresh.

### Implementation Example: Heart Toggle Button

This component demonstrates how to use `isFavorite` to drive UI state and `toggle` to handle user interaction.

```tsx
import React from "react";
import { Button } from "@heroui/react";
import { Heart } from "lucide-react";
import { useWishlist } from "@/hooks/use-wishlist";
import { useAuth } from "@/authentication";

interface WishlistButtonProps {
  productId: string;
}

export const WishlistButton: React.FC<WishlistButtonProps> = ({ productId }) => {
  const { toggle, isFavorite, isLoading } = useWishlist();
  const { isAuthenticated, loginWithRedirect } = useAuth();

  const handleToggle = async () => {
    if (!isAuthenticated) {
      return loginWithRedirect();
    }
    await toggle(productId);
  };

  const active = isFavorite(productId);

  return (
    <Button
      isIconOnly
      variant="light"
      radius="full"
      isLoading={isLoading}
      onPress={handleToggle}
      aria-label={active ? "Remove from wishlist" : "Add to wishlist"}
    >
      <Heart 
        size={20} 
        fill={active ? "currentColor" : "none"} 
        className={active ? "text-danger" : "text-default-400"}
      />
    </Button>
  );
};
```

## Auth0 Management API Synchronization

When `toggle` is called, the backend must update the Auth0 database. This is handled by the `Hono` API which acts as a proxy to the Auth0 Management API.

1. **Mutation**: The backend calls `PATCH /api/v2/users/:userId/metadata`.
2. **Token Management**: The backend uses a specialized helper `getAuth0ManagementToken()`.
3. **Caching**: Management tokens are computationally expensive to fetch (Client Credentials Flow). Fufuni caches these tokens in memory for **60 seconds** to minimize overhead during rapid user updates.

```typescript
// backend/src/services/auth0.ts (Conceptual Backend Logic)
import { useSecuredApi } from "@/hooks/use-secured-api";

export async function updateAuth0Wishlist(userId: string, wishlist: string[]) {
  // getAuth0ManagementToken is cached for 60s
  const mgmtToken = await getAuth0ManagementToken(); 
  
  const response = await fetch(`https://${AUTH0_DOMAIN}/api/v2/users/${userId}`, {
    method: 'PATCH',
    headers: {
      Authorization: `Bearer ${mgmtToken}`,
      'Content-Type': 'application/json',
    },
    body: JSON.stringify({
      user_metadata: { wishlist }
    }),
  });
  
  return response.ok;
}
```

## Persistent Saved Carts

While the **Wishlist** is for long-term "likes", the **Saved Cart** ensures that a user's shopping session persists across devices. Unlike the wishlist, carts are stored in the SQLite database (Durable Objects) because they can contain complex metadata (quantities, variants, custom attributes).

### Data Schema
The `saved_carts` table stores exactly one cart per user.

```sql
CREATE TABLE saved_carts (
  user_id TEXT PRIMARY KEY,
  cart_data TEXT NOT NULL, -- JSON stringified cart object
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

### Endpoints
- `GET /v1/me/saved-cart`: Retrieves the JSON object.
- `PUT /v1/me/saved-cart`: Upserts the current cart state.
- `DELETE /v1/me/saved-cart`: Clears the saved cart (usually after successful checkout).

## CartProvider Integration

The `CartProvider` in `apps/client/src/contexts/cart-context.tsx` orchestrates the synchronization between local state and the API.

1. **Auto-Load**: When `isAuthenticated` changes to `true`, the provider fetches the saved cart from the API and merges it with the local (anonymous) cart.
2. **Auto-Save**: Any change to the cart triggers a **debounced (2 seconds)** `PUT` request to the backend. This prevents rate-limiting the SQLite database during rapid quantity adjustments.

```typescript
// apps/client/src/contexts/cart-context.tsx (Simplified Logic)
useEffect(() => {
  if (isAuthenticated && cartIsDirty) {
    const handler = setTimeout(() => {
      saveCartToBackend(items);
    }, 2000); // 2s Debounce
    
    return () => clearTimeout(handler);
  }
}, [items, isAuthenticated]);
```

## User Preferences

User preferences store UI-specific settings like `locale`, `currency_display`, and `theme`. These are stored in a dedicated SQL table and require the `customerAuthMiddleware`.

### Table Schema

```sql
CREATE TABLE user_preferences (
  user_id TEXT PRIMARY KEY,
  locale TEXT DEFAULT 'en-US',
  currency TEXT DEFAULT 'USD',
  marketing_opt_in BOOLEAN DEFAULT FALSE,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

### Accessing Preferences
The frontend interacts with preferences via standard fetch calls. These are typically loaded once at application bootstrap or when entering the "Account Settings" section.

```typescript
// Example PUT request to update preferences
async function updatePreferences(prefs: Partial<UserPreferences>) {
  const apiBase = getApiBase();
  const response = await fetch(`${apiBase}/v1/me/preferences`, {
    method: 'PUT',
    headers: {
      'Content-Type': 'application/json',
      'Authorization': `Bearer ${token}`
    },
    body: JSON.stringify(prefs),
  });
  
  if (!response.ok) throw new Error("Failed to save preferences");
  return response.json();
}
```

### Summary of Storage Strategy

| Feature | Storage Location | Auth Method | Latency Profile |
| :--- | :--- | :--- | :--- |
| **Wishlist** | Auth0 `user_metadata` | JWT Parsed | Ultra Low (Frontend) |
| **Saved Cart** | SQLite `saved_carts` | API + DB Query | Medium (Debounced) |
| **Preferences** | SQLite `user_preferences` | API + DB Query | Low (Cached in UI) |
