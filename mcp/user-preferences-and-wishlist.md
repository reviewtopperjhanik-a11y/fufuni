## Architecture and Design Choices
The Fufuni framework stores user preferences, including wishlist data, in the Auth0 `user_metadata` object. This decision is driven by the desire to minimize the number of database tables required for per-user preferences. By utilizing the existing Auth0 infrastructure, Fufuni avoids the need to create and manage an additional database table for storing user preferences.

The use of `user_metadata` also enables Fufuni to leverage the scalability and reliability of the Auth0 platform, which is designed to handle large volumes of user data. Additionally, by storing preferences in `user_metadata`, Fufuni can take advantage of Auth0's built-in support for user profile management and metadata storage.

### User Metadata Namespacing
To ensure multi-tenant safety and prevent collisions between different Fufuni instances sharing the same Auth0 tenant, the `user_metadata` object is namespaced under a key derived from the `STORE_URL`. This namespacing approach allows multiple Fufuni instances to coexist within the same Auth0 tenant without interfering with each other's user metadata.

## UseWishlist Hook
The `useWishlist` hook provides a lightweight and efficient way to manage the user's wishlist (product favorites) client-side. The hook uses the `decodeJwt` function from the `jose` library to decode the JWT access token and extract the wishlist data from the `user_metadata` object.

The `useWishlist` hook exposes several key functions and values:

* `wishlist`: an array of product IDs representing the user's current wishlist
* `isLoading`: a boolean indicating whether the wishlist data is currently being fetched or updated
* `isError`: a boolean indicating whether an error occurred while fetching or updating the wishlist data
* `toggle`: a function that allows the user to add or remove a product from their wishlist
* `isFavorite`: a function that checks whether a given product ID is currently in the user's wishlist

The `toggle` function flow is as follows:

1. Check if the user is authenticated; if not, log a warning and exit
2. Determine whether the product is currently in the wishlist (i.e., `isFav`)
3. If the product is in the wishlist, send a `DELETE` request to `/v1/me/wishlist/{productId}` to remove it; otherwise, send a `POST` request to `/v1/me/wishlist` to add it
4. Refresh the JWT token using the `refreshToken` function from the `useTokenRefresh` hook
5. Update the `wishlist` array with the new data and dispatch a `WISHLIST_UPDATED_EVENT` custom event to trigger a token refresh in other components

## Backend: PATCH /v1/me/preferences
The `PATCH /v1/me/preferences` endpoint is used to update the user's preferences, including the wishlist data. The payload shape for this endpoint is as follows:
```json
{
  "prefernces": {
    "wishlist": ["product-id-1", "product-id-2"]
  }
}
```
This endpoint is called when the user updates their wishlist data, and it persists the changes to the Auth0 `user_metadata` object via the Management API.

## Saved Carts
Saved carts differ from the wishlist in that they use a dedicated database table (`saved_carts`) to store cart rows by foreign key. This approach is necessary because saved carts require a more complex data structure to manage cart rows and their associated products.

Saved carts are managed via the `PATCH /v1/me/saved-carts` endpoint, which allows users to add, remove, or update saved carts.
