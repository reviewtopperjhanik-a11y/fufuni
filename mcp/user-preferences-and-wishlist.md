## 1. Architecture Overview

| Layer | Responsibility | Why this choice |
|-------|----------------|-----------------|
| **Auth0 `user_metadata`** | Stores per‑user preferences (wishlist, theme, locale, …) | No dedicated DB table is needed – the JWT already carries the data. |
| **SQLite** (Durable Objects) | Persists shopping cart rows, inventory, orders, etc. | Relational data needs ACID guarantees; `user_metadata` is only for small key/value pairs. |
| **CustomEvent (`fufuni:wishlist-updated`)** | Fast, low‑boilerplate cross‑component notification | Avoids heavy state managers (Redux, React Context) for a handful of UI updates. |

**Key point:**  
Storing the wishlist in `user_metadata` keeps the user’s preference tightly coupled to the authentication token. Whenever the token is refreshed, the UI automatically receives the latest data without querying the backend.

## 2. User‑Metadata Namespacing

Each Fufuni instance may share the same Auth0 tenant. To prevent clashes, the metadata key is namespaced using the store’s URL:

```ts
const STORE_URL = import.meta.env.STORE_URL; // e.g. "https://store1.example.com"

export function getStoreMetadata(userMeta: any, storeUrl: string) {
  const key = `fufuni:${storeUrl}`;
  return userMeta[key];
}
```

All custom fields (e.g., `wishlist`) are nested under that namespaced key:

```json
{
  "fufuni:https://store1.example.com": {
    "wishlist": ["prod_123", "prod_456"]
  }
}
```

## 3. `useWishlist()` Hook

### API

```ts
interface UseWishlistReturn {
  wishlist: string[];        // product IDs
  isLoading: boolean;       // token data fetching state
  isError: boolean;         // error state
  toggle: (productId: string) => Promise<void>;
  isFavorite: (productId: string) => boolean;
}
```

### How it reads the JWT

```ts
import { decodeJwt } from "jose";

/**
 * Decode the access token and extract the wishlist
 */
function getWishlistFromToken(token: string | null): string[] {
  if (!token) return [];
  try {
    const payload = decodeJwt(token) as any;
    const meta = payload["extra_user_info/user_metadata"];
    const storeMeta = getStoreMetadata(meta, import.meta.env.STORE_URL);

    return Array.isArray(storeMeta?.wishlist) ? storeMeta.wishlist : [];
  } catch (e) {
    console.error("[useWishlist] token decode error:", e);
    return [];
  }
}
```

The hook then uses a lightweight state hook (`useTokenUserData`) that reads the JWT once and keeps it in sync via the `WISHLIST_UPDATED_EVENT`.

### `toggle()` Flow

```ts
const toggle = useCallback(
  async (productId: string) => {
    if (!auth.isAuthenticated) return;

    const isFav = wishlist.includes(productId);

    try {
      // REST call to update Auth0 via our backend
      if (isFav) {
        await auth.deleteJson(`${apiBase}/v1/me/wishlist/${productId}`);
      } else {
        await auth.postJson(`${apiBase}/v1/me/wishlist`, { productId });
      }

      // 1️⃣ Force a token refresh so the new `user_metadata` lands in the JWT
      const newToken = await refreshToken();

      // 2️⃣ Re‑extract the wishlist from the new token
      const newWishlist = getWishlistFromToken(newToken || null);

      // 3️⃣ Update local state & notify other components
      setWishlist(newWishlist);
      window.dispatchEvent(
        new CustomEvent("fufuni:wishlist-updated", { detail: newWishlist })
      );
    } catch (e) {
      console.error("[useWishlist] Mutation error:", e);
    }
  },
  [auth, refreshToken, wishlist, apiBase]
);
```

## 4. `WISHLIST_UPDATED_EVENT`

| Step | What happens | Why |
|------|--------------|-----|
| **Dispatch** | `window.dispatchEvent(new CustomEvent("fufuni:wishlist-updated", …))` | Notify all listeners that the wishlist changed. |
| **Listen** | `window.addEventListener("fufuni:wishlist-updated", handler)` | Trigger UI updates or side‑effects. |
| **Token Refresh** | `await refreshToken()` | The JWT still contains the *old* metadata; we must refresh to get the new values. |

Example of listening in a component:

```tsx
useEffect(() => {
  const handler = () => {
    // e.g., show a toast, or re‑fetch the cart
  };
  window.addEventListener("fufuni:wishlist-updated", handler);
  return () => window.removeEventListener("fufuni:wishlist-updated", handler);
}, []);
```


### Payload Shape

```ts
type PreferencesPayload = {
  // All fields must be optional to allow partial updates
  wishlist?: string[];
  theme?: "light" | "dark";
  locale?: string;
  // … any other user preference
};
```

### When to call

* After any mutation that modifies the user’s preferences (e.g., adding a product to the wishlist, changing the theme).
* Client‑side code calls `auth.postJson`/`auth.putJson`/`auth.deleteJson` which internally forwards to this endpoint.

## 6. Saved Carts vs. Wishlist

| Feature | Wishlist | Saved Cart |
|---------|----------|------------|
| Storage | `user_metadata` (JWT) | SQLite table `saved_carts` |
| Data type | Array of product IDs | Table rows (`cart_id`, `product_id`, `quantity`) |
| Reason | Small, per‑user key/value; no relational queries | Needs relationships (FK to cart, product) and counts |
| API | `/v1/me/wishlist` (POST/DELETE) | `/v1/me/saved-carts` (PATCH) |

**SQL for `saved_carts`:**

```sql
CREATE TABLE IF NOT EXISTS saved_carts (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id TEXT NOT NULL,
  cart_id TEXT NOT NULL,
  product_id TEXT NOT NULL,
  quantity INTEGER NOT NULL DEFAULT 1,
  UNIQUE(user_id, cart_id, product_id),
  FOREIGN KEY(user_id) REFERENCES users(id)
);
```

## 7. Adding a New Preference Field – Step‑by‑Step

1. **Define the field in the front‑end hook (optional)**
   ```ts
   // e.g., a toggle for "show only in‑stock items"
   const toggleInStockOnly = async () => {
     const newValue = !isInStockOnly;
     await auth.patchJson(`${apiBase}/v1/me/preferences`, { showInStockOnly: newValue });
   };
   ```

2. **Update the Auth0 user_metadata type (docs / comments)**
   ```ts
   // user_metadata schema (for reference)
   interface UserMetadata {
     "fufuni:https://store1.example.com": {
       wishlist?: string[];
       showInStockOnly?: boolean;
     };
   }
   ```

3. **Persist via `/v1/me/preferences`**
   * The backend `PATCH /v1/me/preferences` receives the JSON payload `{ showInStockOnly: true }`.
   * It calls the Auth0 Management API to merge the new value into the existing metadata.

4. **Trigger a token refresh**
   * After the PATCH succeeds, the client should call `refreshToken()` (either manually or automatically via `useTokenRefresh`).
   * The refreshed JWT will contain the updated `user_metadata`.

5. **Notify listeners**
   ```ts
   window.dispatchEvent(new CustomEvent("fufuni:preferences-updated", { detail: updatedPrefs }));
   ```
   * Components can listen to `fufuni:preferences-updated` to update UI reactively.

6. **Optional: Add UI components**
   * A toggle switch that calls `toggleInStockOnly`.
   * A consumer hook (e.g., `usePreferences`) that decodes the JWT for `showInStockOnly`.
