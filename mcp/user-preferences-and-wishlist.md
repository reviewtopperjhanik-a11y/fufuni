## User Preferences & Wishlist Architecture

Fufuni separates user data into three distinct tiers based on frequency of access, synchronization requirements, and the nature of the data: **Wishlists** (stored in Auth0 metadata for instant JWT-based access), **Saved Carts** (stored in SQLite for transactional integrity), and **User Preferences** (stored in SQLite for configuration persistence).

This multi-tier approach ensures that "light" data like product favorites are available immediately upon token decoding without a database round-trip, while "heavy" or critical data like carts remain server-side and consistent across sessions.

## Wishlist Storage and Auth0 Synchronization

The wishlist is stored directly in the `user_metadata` of the user's Auth0 profile rather than a local SQL table. This design choice allows the wishlist to be embedded within the JWT `access_token`. When the client receives a refreshed token, the wishlist is already present in the claims, enabling zero-latency UI updates.

The wishlist is stored as a simple array of product ID strings.

```typescript
// Example of the user_metadata structure in Auth0
{
  "wishlist": [
    "prod_01J8K9",
    "prod_01J9X2"
  ],
  "theme_preference": "dark"
}
```

### Rationale for Metadata Storage
1.  **Read Performance**: By including the wishlist in the JWT, the frontend never needs to fetch `GET /v1/me/wishlist` on page load.
2.  **Global Availability**: If Fufuni is deployed across multiple Cloudflare regions, the Auth0 metadata acts as a globally distributed configuration.
3.  **Reduced SQL Load**: Frequently toggled items like "favorites" do not consume SQLite write cycles or Durable Object storage IO.

## useWishlist() Hook Reference

The `useWishlist` hook is the primary interface for managing product favorites in the React frontend. It requires the user to be authenticated and utilizes `useTokenRefresh` to ensure the local UI state matches the updated JWT after a mutation.

### Return Interface
The hook returns the following properties:
- `wishlist`: `string[]` - The array of product IDs.
- `isLoading`: `boolean` - True if the wishlist data is being initially resolved.
- `addToWishlist`: `(productId: string) => Promise<void>` - Adds an item.
- `removeFromWishlist`: `(productId: string) => Promise<void>` - Removes an item.
- `isInWishlist`: `(productId: string) => boolean` - Check if a product is favorited.
- `toggleWishlist`: `(productId: string) => Promise<void>` - The standard toggle utility.

### Implementation Example: Heart Button
This example demonstrates a standard HeroUI-based favorite toggle button.

```typescript
import React from "react";
import { Button } from "@heroui/react";
import { HeartIcon } from "@/components/icons";
import { useWishlist } from "@/hooks/use-wishlist";
import { useAuth } from "@/authentication";

export const FavoriteButton = ({ productId }: { productId: string }) => {
  const { isAuthenticated, loginWithRedirect } = useAuth();
  const { toggleWishlist, isInWishlist, isLoading } = useWishlist();

  const handlePress = async () => {
    if (!isAuthenticated) {
      return loginWithRedirect();
    }
    await toggleWishlist(productId);
  };

  const isFav = isInWishlist(productId);

  return (
    <Button
      isIconOnly
      radius="full"
      variant="light"
      isLoading={isLoading}
      onPress={handlePress}
      aria-label="Toggle Wishlist"
    >
      <HeartIcon 
        fill={isFav ? "currentColor" : "none"} 
        className={isFav ? "text-danger" : "text-default-400"} 
      />
    </Button>
  );
};
```

## Auth0 Management API Integration

Mutating the wishlist requires calling the Auth0 Management API from the Fufuni backend. Since the `access_token` held by the user cannot modify their own metadata directly for security reasons, the backend acts as a proxy using a Machine-to-Machine (M2M) token.

The `getAuth0ManagementToken()` helper facilitates this by fetching and caching the M2M token for 60 seconds to prevent hitting Auth0 rate limits.

```typescript
// Example: Backend logic (Hono) for updating wishlist
import { Hono } from "hono";
import { customerAuthMiddleware } from "@/middleware/auth";
import { getAuth0ManagementToken } from "@/lib/auth0-m2m";

const app = new Hono();

app.post("/v1/me/wishlist", customerAuthMiddleware, async (c) => {
  const user = c.get("user");
  const { productId } = await c.req.json();
  
  const m2mToken = await getAuth0ManagementToken();
  const userId = user.sub;

  // 1. Fetch current metadata
  const response = await fetch(`https://${process.env.AUTH0_DOMAIN}/api/v2/users/${userId}`, {
    headers: { Authorization: `Bearer ${m2mToken}` }
  });
  const profile = await response.json();
  const currentWishlist = profile.user_metadata?.wishlist || [];

  // 2. Update via PATCH
  const updatedWishlist = [...new Set([...currentWishlist, productId])];
  
  await fetch(`https://${process.env.AUTH0_DOMAIN}/api/v2/users/${userId}`, {
    method: "PATCH",
    headers: { 
      Authorization: `Bearer ${m2mToken}`,
      "Content-Type": "application/json" 
    },
    body: JSON.stringify({
      user_metadata: { wishlist: updatedWishlist }
    })
  });

  return c.json({ success: true });
});
```

## Saved Cart Management

Unlike the wishlist, the **Saved Cart** is stored in the local SQLite database. This allows for complex cart validation, inventory checking, and persistence of quantities/attributes that are too heavy for JWT claims.

### Database Schema
The `saved_carts` table maps a `user_id` to a JSON blob of the cart state.

```sql
CREATE TABLE saved_carts (
  user_id TEXT PRIMARY KEY,
  cart_data TEXT NOT NULL, -- JSON serialized Cart object
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

### Endpoints
- `GET /v1/me/saved-cart`: Retrieves the cart for the authenticated user.
- `PUT /v1/me/saved-cart`: Upserts the current cart state.
- `DELETE /v1/me/saved-cart`: Clears the saved cart (usually after successful checkout).

## CartProvider Synchronization

The `CartProvider` in `apps/client/src/contexts/cart-context.tsx` manages the lifecycle of the saved cart. It bridges the gap between local storage (for anonymous users) and the API (for logged-in users).

### Auto-Save Behavior
The framework implements an "Auto-Save" mechanism with a 2-second debounce. When a user is authenticated, any modification to the cart locally triggers a background sync to the `PUT /v1/me/saved-cart` endpoint.

```typescript
// Conceptual logic inside CartProvider
import { useEffect, useRef } from "react";
import { useAuth } from "@/authentication";
import { useCartStore } from "@/hooks/use-cart-store";

export const CartProvider = ({ children }: { children: React.ReactNode }) => {
  const { isAuthenticated, postJson } = useAuth();
  const { cart, setCart } = useCartStore();
  const debounceRef = useRef<Timer | null>(null);

  // 1. Load cart on login
  useEffect(() => {
    if (isAuthenticated) {
      fetch("/api/v1/me/saved-cart")
        .then(res => res.json())
        .then(data => {
          if (data.cart) setCart(data.cart);
        });
    }
  }, [isAuthenticated]);

  // 2. Auto-save on change
  useEffect(() => {
    if (!isAuthenticated) return;

    if (debounceRef.current) clearTimeout(debounceRef.current);

    debounceRef.current = setTimeout(async () => {
      await postJson("/api/v1/me/saved-cart", { cart });
    }, 2000);

    return () => clearTimeout(debounceRef.current);
  }, [cart, isAuthenticated]);

  return <>{children}</>;
};
```

## User Preferences

User Preferences cover non-essential UI and localization settings, such as the preferred locale and currency display formats. These are stored in the `user_preferences` table.

### Data Model and Endpoints
Access to preferences requires `customerAuthMiddleware`.

| Field | Type | Description |
| :--- | :--- | :--- |
| `locale` | `string` | BCP 47 language tag (e.g., `en-US`). |
| `currency` | `string` | ISO 4217 code (e.g., `USD`). |
| `marketing_opt_in` | `boolean` | Whether the user accepts newsletters. |

### API Usage Example

```typescript
// Fetching user preferences
async function fetchPreferences() {
  const response = await fetch("/api/v1/me/preferences", {
    headers: { Authorization: `Bearer ${token}` }
  });
  const prefs = await response.json();
  console.log(`User prefers ${prefs.currency}`);
}

// Updating preferences
async function updateCurrency(newCurrency: string) {
  await fetch("/api/v1/me/preferences", {
    method: "PUT",
    body: JSON.stringify({ currency: newCurrency }),
    headers: { "Content-Type": "application/json" }
  });
}
```

This structure ensures that the Fufuni framework remains performant by leveraging JWTs for highly accessed data (Wishlist) while maintaining strict consistency for transactional data (Carts) and persistent settings (Preferences).
