## Architecture
The Fufuni e-commerce framework utilizes AI-assisted features that run entirely in the browser, with no server-side inference. This design choice has significant security implications, as sensitive data is not transmitted to the server. Instead, the browser fetches credentials and then directly calls the AI provider. This approach minimizes potential security risks associated with handling sensitive information on the server-side.

## Backend
The backend provides a single endpoint, `GET /v1/ai/parameters`, which returns the necessary credentials for the AI provider. This endpoint requires the `ai:api` Auth0 permission, enforced by the `aiAccessOnly` middleware. The response shape is an object containing `apiKey`, `model`, and `url`. Notably, `apiKey` is randomly chosen from a pool of API keys specified in the `AI_API_KEY` environment variable. If any of the required environment variables (`AI_API_KEY`, `AI_MODEL`, or `AI_API_URL`) are missing, the endpoint returns a `503` error.

```typescript
// Example usage of GET /v1/ai/parameters
const response = await fetch('/v1/ai/parameters', {
  headers: {
    Authorization: 'Bearer YOUR_AUTH_TOKEN',
  },
});

if (response.ok) {
  const params = await response.json();
  console.log(params); // { apiKey: string, model: string, url: string }
} else {
  console.error('Error fetching AI parameters:', response.status);
}
```

## ai-client.ts
The `ai-client.ts` module is the central location for AI-related utilities. It exports several key interfaces and functions, including `AiParams`, `analyzeReviewWithAi`, and `translateWithAi`. The `AiParams` interface represents the configuration for an AI provider:

```typescript
interface AiParams {
  apiKey: string;
  model: string;
  url: string;
  provider?: 'openai' | 'groq' | 'anthropic' | 'auto';
}
```

The provider is auto-detected from the `url` field, with the following logic:

*   `url` containing "anthropic" → Anthropic Messages API
*   `url` containing "groq" → Groq (OAI-compatible)
*   default → OpenAI
