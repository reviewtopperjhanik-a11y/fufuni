## AI-Assisted Features Architecture

Fufuni employs a "client-side inference" architecture for all AI-driven features. To minimize backend latency and eliminate expensive server-side egress or specialized inference environments, the Fufuni backend acts strictly as a **credential provider**. 

The browser initiates a request to the Fufuni API to retrieve a temporary, short-lived API key and model configuration. Once received, the frontend communicates directly with the AI provider (OpenAI, Groq, or Anthropic).

### Security Implications
- **No Backend Inference**: Fufuni workers do not process LLM tokens. This prevents long-running HTTP requests that could hit Cloudflare Worker execution limits.
- **Credential Scoping**: Access to AI parameters is gated by Auth0 permissions. Only users with the `ai:api` permission can retrieve credentials.
- **Provider Multi-tenancy**: The system supports multiple keys with different tiers (Free, Paid, Premium), allowing the backend to load-balance or failover between keys.

```typescript
// Example: How the frontend retrieves AI parameters
import { useSecuredApi } from "@/hooks/use-secured-api";

async function getAiConfig() {
  const { fetchWithAuth } = useSecuredApi();
  const response = await fetchWithAuth("/v1/ai/parameters");
  if (!response.ok) throw new Error("AI not configured or unauthorized");
  
  // returns { apiKey: string, model: string, url: string }
  return await response.json();
}
```

## Backend: GET /v1/ai/parameters

The `/v1/ai/parameters` endpoint is the gateway for AI features. It determines which model and key to return based on a priority-weighted configuration stored in the `KV_CACHE`.

### Provider Selection Logic
1.  **Encrypted Config**: The backend looks for the `ai:config` key in KV.
2.  **Decryption**: It decrypts the content using the `CRYPTOKEN` environment variable via `decryptAiConfig` (using Web Crypto API).
3.  **Priority Sorting**: Models are sorted by their `priority` field (where `1` is the highest priority).
4.  **Key Selection**: A key is picked from the provider's key pool (load-balanced via `pickKey`).
5.  **Fallback**: If no KV config exists, it falls back to legacy environment variables (`AI_API_KEY`, `AI_MODEL`, `AI_API_URL`).

        apiKey: keyObj.key,

        url: provider.endpoint,

### Key Metadata Tiers
Keys can be tagged with tiers to assist in future quota management:
- `free`: Subject to aggressive rate limits.
- `paid`/`premium`: Higher throughput.
- `unlimited`: Enterprise-grade keys.
- `expired`: Automatically ignored by the selection helper.

## The AI Client (ai-client.ts)

The `ai-client.ts` utility is the single source of truth for AI inference in the frontend. It abstracts provider-specific differences (headers, payload shapes, URL structures).

### Provider Auto-Detection
The client uses the `detectProvider` function to handle different API schemas based on the URL or an explicit hint.

```typescript
// Internal logic of detectProvider in ai-client.ts
function detectProvider(url: string, explicit?: string) {
  if (explicit && ["openai", "groq", "anthropic"].includes(explicit)) {
    return explicit;
  }
  if (url.includes("anthropic")) return "anthropic";
  if (url.includes("groq")) return "groq";
  return "openai"; // Default fallback
}
```

## Gating AI Features

AI features consume credits and expose API keys to the browser. Access must be strictly gated using the `ai:api` Auth0 permission.

### React Component Gating

## Updating AI Keys and Configuration

Fufuni uses a CLI-based workflow to manage the encrypted configuration.

### Workflow
1.  **Edit**: Update the local `ai.json` with new keys or models.
2.  **Encrypt**: Run the encryption script. This uses OpenSSL with the `CRYPTOKEN` password.
    ```bash
    # Encrypts ai.json to ai.json.enc
    npm run ai:encrypt
    ```
3.  **Push to KV**: Upload the encrypted string to the Cloudflare production environment.
    ```bash
    # Pushes content to KV_CACHE under key "ai:config"
    npm run ai:kv:push
    ```

### Local Development
In development, if you don't want to use KV, you can set environment variables in your `wrangler.jsonc` or `.dev.vars`:
```bash
AI_API_KEY="your-key-here"
AI_MODEL="gpt-4o"
AI_API_URL="https://api.openai.com/v1"
```
The backend will automatically detect the absence of the KV config and use these as a fallback.
