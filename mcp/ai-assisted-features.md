# AI‑Assisted Features Reference

## 1. Architecture

| Layer | Role | Why it’s designed that way |
|-------|------|---------------------------|
| **Frontend** | Executes all AI inference | The browser calls the AI provider directly. No server‑side inference → lower latency, no heavy backend resources, easier scaling. |
| **Backend** | Only serves AI credentials | `GET /v1/ai/parameters` returns an `apiKey`, `model` and `url`. The client uses those to authenticate with the external provider. |
| **Security** | Credentials never leave the user’s browser | The API key is randomly selected from a pool stored as an environment variable. The backend never exposes the full key list to the client. |

*Result*: The user’s browser talks directly to OpenAI, Groq, or Anthropic. The server only gives the client a short‑lived key, preventing the server from acting as a relay or cache.

## 2. Backend: `GET /v1/ai/parameters`

```http
GET /v1/ai/parameters
Authorization: Bearer <Auth0‑Token>
```

| Requirement | Detail |
|-------------|--------|
| **Permission** | Requires the Auth0 permission `ai:api` (enforced by `aiAccessOnly`). |
| **Response** | 200 OK: `{ apiKey: string, model: string, url: string }`  <br>503 Service Unavailable if any value is missing. |
| **API Key Rotation** | `AI_API_KEY` can contain multiple comma‑separated keys. The handler picks one at random, balancing usage across the pool. |

## 3. `ai-client.ts`

```typescript
export interface AiParams {
  apiKey: string;          // Credential for the chosen provider
  model: string;           // Model id, e.g. "gpt-4o" or "claude-3-haiku-20240307"
  url: string;             // Base endpoint URL, e.g. "https://api.openai.com/v1"
  provider?: "openai" | "groq" | "anthropic" | "auto"; // Optional provider hint
}
```

**Supported providers**

| Provider | API | Auto‑detect criteria |
|----------|-----|----------------------|
| OpenAI | `chat/completions` | default if URL does not contain `anthropic` or `groq` |
| Groq   | `chat/completions` (OpenAI‑compatible) | URL includes `groq` |
| Anthropic | `messages` | URL includes `anthropic` |

**Auto‑detection logic**

```typescript
function detectProvider(url: string, explicit?: string): "openai" | "groq" | "anthropic" {
  if (explicit && ["openai", "groq", "anthropic"].includes(explicit)) {
    return explicit as "openai" | "groq" | "anthropic";
  }
  if (url.includes("anthropic")) return "anthropic";
  if (url.includes("groq")) return "groq";
  return "openai";
}
```

## 6. Gating AI Features

### Frontend Guard

```tsx
import { hasPermission } from '@/auth'; // helper that reads Auth0 claims

function AIActions() {
  if (!hasPermission('ai:api')) return null; // hide AI UI

  return (
    <button onClick={handleTranslate}>Translate</button>
  );
}
```

### Auth0 Permission

* Scope required: `ai:api`  
* Add the scope to the Auth0 application → user’s access token will contain it.  
* `authMiddleware` + `aiAccessOnly` in the backend enforce the same permission for `/v1/ai/parameters`.

2. **Expose the helper to components**  
   Import it in the UI component where the feature is needed and call it after retrieving AI credentials.


3. **Gate the UI**

That’s all—no new backend routes are required because the client still fetches the same AI credentials and talks directly to the provider.
