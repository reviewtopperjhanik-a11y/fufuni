## AI-Assisted Features Reference
### Architecture
The AI-assisted features in the Fufuni e-commerce framework run entirely in the browser, with no backend inference. This design choice has significant security implications, as sensitive AI credentials are never exposed to the backend. Instead, the browser fetches the necessary credentials from the backend and then calls the AI provider directly. This approach ensures that AI-related data is handled and processed on the client-side, reducing potential security risks associated with transmitting sensitive information to the server.

### Backend
The backend exposes a single endpoint, `GET /v1/ai/parameters`, which returns the AI configuration parameters. This endpoint requires the `ai:api` Auth0 permission, enforced by the `aiAccessOnly` middleware. The response shape is a JSON object containing the `apiKey`, `model`, and `url` for the AI provider. Notably, the `apiKey` is randomly chosen from a comma-separated pool of keys, enabling API key rotation. If any of the required environment variables (`AI_API_KEY`, `AI_MODEL`, or `AI_API_URL`) are missing, the endpoint returns a 503 error.

### ai-client.ts
The `ai-client.ts` module is the central utility for AI-related functionality. It defines the `AiParams` interface, which includes the following properties:
```typescript
interface AiParams {
  apiKey: string;
  model: string;
  url: string;
  provider?: "openai" | "groq" | "anthropic" | "auto";
}
```
The `provider` field is optional and can be auto-detected from the `url` field. The supported providers are:

*   "openai" (default)
*   "groq"
*   "anthropic"

The auto-detection logic is as follows:

*   If the `url` contains "anthropic", the provider is set to "anthropic" (using the Anthropic Messages API).
*   If the `url` contains "groq", the provider is set to "groq" (using the Groq API, which is compatible with OpenAI).
*   Otherwise, the provider is set to "openai" (using the OpenAI API).

The `analyzeReviewWithAi()` function analyzes a product review using the AI provider. Its signature is:
```typescript
async function analyzeReviewWithAi(
  review: ReviewInput,
  aiParams: AiParams,
): Promise<ReviewAnalysisResult>
```
The `ReviewAnalysisResult` type is:
```typescript
interface ReviewAnalysisResult {
  success: boolean;
  recommendation?: "approve" | "reject";
  reason?: string;
  error?: string;
```

Here's an example usage:
```typescript
const review: ReviewInput = {
  id: "review-123",
  rating: 5,
  title: "Great product!",
  body: "This product is amazing!",

const aiParams: AiParams = {
  apiKey: "your-api-key",

const result = await analyzeReviewWithAi(review, aiParams);
```

### Gating AI Features with Auth0 Permission
To gate AI features, use the `AuthenticationGuardWithPermission` component with the `permission` prop set to `"ai:api"`. Alternatively, you can use the `hasPermission()` function from `useSecuredApi()` to check if the user has the required permission.

### Adding a New AI Use Case
To add a new AI use case, follow these steps:

1.  Create a new typed helper function in `ai-client.ts` that follows the `AiParams` interface.
2.  Fetch the necessary credentials from the `GET /v1/ai/parameters` endpoint.
3.  Pass the fetched credentials to your new helper function.

For example, let's say you want to add a new function called `generateProductDescriptionWithAi()`:
```typescript
async function generateProductDescriptionWithAi(
  productId: string,
  aiParams: AiParams,
): Promise<GenerationResult> {
  // Implementation using the AI provider
}
```
You would then call this function in your component, fetching the credentials and passing them to the function:
```typescript
const credentials = await fetch('/v1/ai/parameters').then((res) => res.json());
const result = await generateProductDescriptionWithAi("product-123", credentials);
console.log(result); // { success: true, content: "..." }
```
