## Architecture: Browser-Side Inference

Fufuni adopts a "Thin Backend, Thick Client" approach for Artificial Intelligence. Unlike traditional frameworks that proxy AI requests through a server-side API, Fufuni performs **all AI inference directly in the browser**. This architecture significantly reduces Cloudflare Worker CPU time, avoids memory limits associated with processing large LLM responses in serverless functions, and provides a more responsive experience for the user.

Security is maintained by gating the AI credentials. The client must first authenticate with the Fufuni backend to receive temporary, scoped API keys and configuration parameters. Once the client has these credentials, it communicates directly with the AI provider (OpenAI, Groq, or Anthropic).

### Example: Consuming AI Credentials in a React Component

```typescript
import React, { useEffect, useState } from "react";
import { useAuth } from "../hooks/use-auth";
import { translateWithAi, type AiParams } from "../utils/ai-client";

export const AiTranslator: React.FC<{ text: string }> = ({ text }) => {
  const { fetchWithAuth } = useAuth();
  const [params, setParams] = useState<AiParams | null>(null);
  const [result, setResult] = useState("");

  useEffect(() => {
    // Fetch credentials from the backend
    fetchWithAuth("/v1/ai/parameters")
      .then((res) => res.json())
      .then((data: AiParams) => setParams(data));
  }, []);

  const handleTranslate = async () => {
    if (!params) return;
    const response = await translateWithAi(text, "French", params, false);
    if (response.success) {
      setResult(response.content || "");
    }
  };

  return (
    <div>
      <button onClick={handleTranslate} disabled={!params}>Translate to French</button>
      <p>{result}</p>
    </div>
  );
};
```

## Backend: The AI Parameters Endpoint

The endpoint `GET /v1/ai/parameters` is the single source of truth for AI configuration. It is protected by the `aiAccessOnly` middleware, which requires the `ai:api` permission from the Auth0 token.

The backend prioritizes configuration stored in `KV_CACHE` under the key `ai:config`. This key contains a base64-encoded, encrypted JSON blob (`ai.json.enc`). If the KV store is empty or the decryption key (`CRYPTOKEN`) is missing, the system falls back to legacy environment variables (`AI_API_KEY`, `AI_MODEL`, `AI_API_URL`).

## AI Configuration: Encryption and KV Storage

Fufuni uses an encrypted JSON configuration to manage multiple AI providers and keys securely. This file, `ai.json`, is encrypted using the **Web Crypto API** (compatible with OpenSSL AES-256-CBC) before being uploaded to Cloudflare KV.

### Example: Structure of `ai.json` (Source)

        { "key": "gsk_abc123", "owner": "admin", "type": "premium" },

      ],

The `priority` field in the model definition determines the selection order. A priority of `1` is the highest. If multiple providers offer models, the backend sorts all models by priority and selects the best available one.

## Key Metadata and Quota Management

The `AiKey` interface allows for granular management of keys. Every key can have an associated `owner` and a `type` (tier).

| Tier | Description |
| :--- | :--- |
| `free` | Subject to strict rate limits; used as last-resort fallback. |
| `paid` | Standard pay-as-you-go keys. |
| `premium` | High-priority keys with higher rate limits. |
| `unlimited` | Internal or enterprise keys without known caps. |

The `pickKey()` function implements uniform load-balancing by selecting a random key from the pool available for the chosen provider.

### Example: Random Key Selection with Metadata

```typescript
import { type AiProvider, pickKey } from '../lib/ai-enc';

const myProvider: AiProvider = {
  protocol: 'openai',
  endpoint: '...',
  keys: [
    { key: 'key_1', type: 'premium' },
    { key: 'key_2', type: 'premium' }
  ],
  models: []
};

// Returns either key_1 or key_2 with 50% probability
const selectedKey = pickKey(myProvider);
console.log(`Using key belonging to: ${selectedKey.owner || 'unknown'}`);
```

## Frontend Client: `ai-client.ts`

The `ai-client.ts` module is the central utility for all AI interactions in the frontend. It defines the `AiParams` interface and handles the complexity of different provider APIs (OpenAI vs. Anthropic).

### Auto-Detection Logic
The client automatically detects the required API format based on the `url` provided by the backend:
- If the URL contains `anthropic`: Uses the Anthropic Messages API (`/messages`).
- If the URL contains `groq`: Uses OpenAI-compatible Chat Completions with adjusted token defaults.
- Default: Uses the standard OpenAI Chat Completions API (`/chat/completions`).

```typescript
export interface AiParams {
  apiKey: string;
  model: string;
  url: string;
  provider?: "openai" | "groq" | "anthropic" | "auto";
}

function detectProvider(url: string, explicit?: string) {
  if (explicit && explicit !== "auto") return explicit;
  if (url.includes("anthropic")) return "anthropic";
  if (url.includes("groq")) return "groq";
  return "openai";
}
```

## Updating AI Keys

When rotating API keys or adding new models, follow this workflow to ensure zero downtime and security:

1.  **Edit local file**: Modify `apps/merchant/scripts/ai.json` (do NOT commit this file to git).
2.  **Encrypt**: Run the encryption script using your local `CRYPTOKEN`.
    ```bash
    # Encrypts ai.json to ai.json.enc
    npm run ai:encrypt
    ```
3.  **Deploy to KV**: Push the encrypted blob to the Cloudflare production environment.
    ```bash
    # Pushes ai.json.enc to KV under 'ai:config'
    npm run ai:kv:push
    ```
4.  **Verification**: The Workers will automatically pick up the new config (subject to the `_configCache` TTL in the isolate memory).
