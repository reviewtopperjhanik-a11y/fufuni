## AI Architecture and Browser-Based Inference

Fufuni adopts a "client-side inference" architecture for AI features. While the credentials and configuration are managed by the backend (Cloudflare Workers), the actual API requests to providers like OpenAI, Groq, or Anthropic are performed directly from the user's browser.

This approach offers several advantages for the framework:
1.  **Worker Resource Preservation**: AI requests are long-running (high latency). Executing them in the Worker would quickly exhaust the 30-second execution limit and consume unnecessary CPU time.
2.  **Streaming & UI Responsiveness**: The browser can handle streaming responses or parallelize multiple requests (e.g., translating multiple product fields) without bottlenecking the backend.
3.  **Cost Transparency**: API usage is tied directly to the administrative actions performed in the dashboard.

### Security Implementation
To maintain security while allowing client-side calls, the framework uses a "Just-In-Time" credential delivery system. The browser requests temporary access to the decrypted API key via a secure endpoint.


## Credential Storage and Encryption

AI credentials are never stored in plain text. Fufuni uses an encrypted file-based configuration (`ai.json.enc`) stored in Cloudflare KV (`KV_CACHE`).

### The Encryption Workflow
1.  **Preparation**: The administrator creates a JSON file containing providers, models, and keys.
2.  **Encryption**: The file is encrypted using OpenSSL (AES-256-CBC) with a PBKDF2 key derived from the `CRYPTOKEN` secret.
3.  **Deployment**: The encrypted string is uploaded to the backend.

### Decryption in Memory
The backend uses the Web Crypto API to decrypt the configuration in memory. It is cached at the Worker isolate level to avoid repeated decryption overhead.

```typescript
// apps/merchant/src/lib/ai-enc.ts
// Decrypts the configuration using the environment's CRYPTOKEN
export async function decryptAiConfig(
  base64Ciphertext: string,
  password: string,
): Promise<AiConfig> {
  const raw = Uint8Array.from(atob(base64Ciphertext.trim()), c => c.charCodeAt(0));
  const salt = raw.slice(8, 16);
  const ciphertext = raw.slice(16);

  const pwBytes = new TextEncoder().encode(password);
  const baseKey = await crypto.subtle.importKey('raw', pwBytes, 'PBKDF2', false, ['deriveBits']);
  const derived = new Uint8Array(
    await crypto.subtle.deriveBits(
      { name: 'PBKDF2', hash: 'SHA-256', salt, iterations: 100_000 },
      baseKey,
      384,
    ),
  );

  const aesKey = await crypto.subtle.importKey(
    'raw', derived.slice(0, 32), 'AES-CBC', false, ['decrypt'],
  );
  const plaintext = await crypto.subtle.decrypt(
    { name: 'AES-CBC', iv: derived.slice(32, 48) },
    aesKey,
    ciphertext,
  );

  return JSON.parse(new TextDecoder().decode(plaintext)) as AiConfig;
}
```

## The /parameters Endpoint

The `GET /parameters` endpoint (typically routed under `/v1/merchant/ai/parameters`) is the bridge between the backend security and frontend functionality.

### Access Control
- **Authentication**: Requires a valid Bearer token.
- **Permissions**: The user must have the `ai:api` permission.
- **Middleware**: Guarded by `aiAccessOnly`.

### Response Structure
The endpoint returns the necessary connection string for the frontend `ai-client.ts` to take over.

```json
{
  "apiKey": "sk-ant-api03-...",
  "model": "claude-3-5-sonnet-20241022",
  "url": "https://api.anthropic.com/v1"
}
```

## Review Moderation Workflow

Review moderation is integrated into the Merchant Dashboard's review management page.

1.  **Fetch Parameters**: When the page loads, the UI fetches AI parameters.
2.  **Batch Analysis**: The UI uses `analyzeReviewsBatchWithAi` to process visible reviews (limited to 5 concurrent requests to respect rate limits).
3.  **UI Feedback**:
    *   Reviews flagged as `approve` are shown with a subtle green highlight or "Safe" badge.
    *   Reviews flagged as `reject` are highlighted in red with the AI-provided reason displayed as a tooltip.
4.  **Final Decision**: The AI result is only a recommendation. The human administrator must still click "Approve" or "Reject" to persist the status change in the database.

## Auto-Translation Workflow

Auto-translation is primarily used in the Product Editor and Email Template editor.

### Target Locales
The system identifies the "Base Locale" (usually `en-US`) and the "Target Locales" configured for the store (e.g., `fr-FR`, `de-DE`, `ja-JP`).

### Execution Logic
1.  **Trigger**: User clicks the "Auto-translate all" button in the Product Form.
2.  **Source Extraction**: The system takes the content from the primary locale fields.
3.  **Parallel Translation**: One AI request is dispatched for each target locale.
4.  **Field Update**: As translations return, the corresponding localized fields in the React state are updated, triggering a UI refresh in the localized tabs.

## Admin Configuration and Setup

To enable AI features, the administrator must upload the encrypted configuration.

### Preparing the File
Create `ai.json`:
```json
{
  "version": 1,
  "providers": {
    "groq": {
      "protocol": "openai",
      "endpoint": "https://api.groq.com/openai/v1",
      "keys": [{ "key": "gsk_...", "type": "paid" }],
      "models": [
        { "id": "llama-3.3-70b-versatile", "priority": 1, "contextWindow": 128000 }
      ]
    }
  }
}
```

### Encrypting the Configuration
Use the following shell command (must match the library's PBKDF2 implementation):

```bash
openssl enc -aes-256-cbc -a -pbkdf2 -iter 100000 -salt \
  -in ai.json -out ai.json.enc -pass pass:"YOUR_CRYPTOKEN_HERE"
```

### Uploading to the Framework
The encrypted string is then sent to the Merchant API:

```typescript
// Call to POST /v1/merchant/ai/config
const uploadConfig = async (encryptedContent: string) => {
  const response = await fetch('/v1/merchant/ai/config', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ content: encryptedContent })
  });
  return await response.json();
};
```

## Graceful Degradation

Fufuni is designed to remain fully functional even without AI configuration. The framework handles missing AI capabilities as follows:

1.  **Backend Fallback**: If no encrypted configuration exists, the `/parameters` endpoint attempts to read legacy environment variables (`AI_API_KEY`, `AI_MODEL`, `AI_API_URL`). If those are also missing, it returns a `503 Service Unavailable` with a descriptive error.
2.  **UI Visibility**: 
    *   In the Product Editor, the "Auto-translate" buttons are hidden or disabled if the parameter fetch fails.
    *   In Review Management, the moderation badges simply do not appear.
3.  **Error Handling**: If an AI request fails (due to rate limiting or invalid keys), the `TranslationResult` or `ReviewAnalysisResult` returns `success: false`. The UI captures this error and allows the user to proceed with manual input, ensuring the core business logic is never blocked by an AI failure.
