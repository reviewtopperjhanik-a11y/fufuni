## Localized Content Patterns

Fufuni handles multilingualism by storing content in a specialized JSON format within SQLite text columns. This approach allows the framework to scale across multiple locales (English, French, Spanish, Chinese, Arabic, Hebrew) without requiring schema changes for every new language supported.

### JSON Storage Format

Localized fields in the database are stored as serialized `LocalizedDesc` objects. A legacy field might contain a plain HTML string, but the framework is designed to automatically migrate these to the JSON format upon the first edit in a specific locale.

The structure uses [ISO 639-1](https://en.wikipedia.org/wiki/List_of_ISO_639-1_codes) combined with regional identifiers as keys.

```typescript
/** 
 * Found in apps/client/src/utils/description.ts 
 * Example raw DB string: '{"en-US": "Blue Shirt", "fr-FR": "Chemise Bleue"}'
 */
export type LocalizedDesc = Record<string, string>;

// The fallback order used when a specific locale is missing content
export const DESCRIPTION_FALLBACK = [
  "en-US",
  "fr-FR",
  "es-ES",
  "zh-CN",
  "ar-SA",
  "he-IL",
] as const;
```

When reading from the database, the framework uses "Resolve" functions to determine the best string to show the user based on their current locale and the fallback chain.

```typescript
import { resolveTitle, resolveDescription } from "@/utils/description";

const rawDbTitle = '{"en-US": "Fufuni Pro", "zh-CN": "Fufuni 专业版"}';

// Returns "Fufuni 专业版"
const titleZh = resolveTitle(rawDbTitle, "zh-CN");

// Returns "Fufuni Pro" (fallback from en-US)
const titleFr = resolveTitle(rawDbTitle, "fr-FR");
```

## Core Utility Functions

The framework provides utility helpers to manage the transition from legacy plain-text fields to localized JSON objects. These are categorized by the type of content they handle (Title, Description, Vendor, Tags, Handle).

### Detection and Migration

The `parseDescription` and `isLocalized` helpers detect whether a string is legacy or modern.

| Function | Purpose |
| :--- | :--- |
| `parseDescription(raw)` | Returns a `LocalizedDesc` object if the string starts with `{`, otherwise returns the plain string. |
| `isLocalized(raw)` | Boolean check to see if the content has been migrated to JSON. |
| `mergeTitleLocale(raw, locale, text)` | Injects a new translation into the JSON. If the input is legacy plain-text, it migrates it to JSON, preserving the original text in `en-US`. |

### Safe Title Stripping

Titles, unlike descriptions, must never contain HTML. The `stripHtml` utility is embedded into all title-related helpers to prevent XSS and layout breakage.

```typescript
import { mergeTitleLocale } from "@/utils/description";

const existing = "My Product"; // Legacy plain string
const nextValue = "<b>Invalid Title</b>";

// Result: '{"en-US":"My Product","fr-FR":"Invalid Title"}'
// Note: <b> tags are stripped by the helper before merging.
const updatedJson = mergeTitleLocale(existing, "fr-FR", nextValue);
```

## The useLocalizedTextInput Hook

Managing state for a field that can exist in six different languages is complex. The `useLocalizedTextInput` hook encapsulates this logic, providing sync between the UI and the underlying JSON structure, as well as AI translation capabilities.

### Hook Capabilities
1.  **Locale Syncing**: Automatically switches the visible input value when the user changes the "Editing Locale" in the admin UI.
2.  **Auto-Migration**: If a user opens a legacy product and changes a field in a secondary locale, the hook automatically converts the state to a JSON object.
3.  **AI Permission Check**: Verifies the user has the `ai:api` permission before enabling translation features.
4.  **RTL Logic**: Detects if the current locale (e.g., `ar-SA`) requires Right-to-Left text direction.

### Implementation Example

```typescript
import { Input, Button } from "@heroui/react";
import { useLocalizedTextInput } from "@/hooks/use-localized-text-input";
import { 
  parseTitle, 
  mergeTitleLocale, 
  getTitleForLocale 
} from "@/utils/description";

export function LocalizedTitleField({ 
  value, 
  onChange, 
  selectedLocale 
}: { 
  value: string; 
  onChange: (v: string) => void;
  selectedLocale: string;
}) {
  const { 
    inputValue, 
    handleInputChange, 
    handleAiTranslate, 
    isTranslating, 
    canUseAi, 
    isRTL 
  } = useLocalizedTextInput({
    value,
    onChange,
    selectedLocale,
    parseFn: parseTitle,
    mergeFn: mergeTitleLocale,
    getFn: getTitleForLocale,
  });

  return (
    <div className="flex flex-col gap-2">
      <Input
        label="Product Title"
        value={inputValue}
        onValueChange={handleInputChange}
        dir={isRTL ? "rtl" : "ltr"}
      />
      {canUseAi && (
        <Button 
          isLoading={isTranslating} 
          onPress={handleAiTranslate}
          size="sm"
        >
          Translate with AI
        </Button>
      )}
    </div>
  );
}
```

## RTL Handling and Internationalization

Fufuni supports Right-to-Left (RTL) languages like Arabic (`ar-SA`) and Hebrew (`he-IL`). RTL support must be handled at two levels: the `dir` attribute on inputs and the layout of the UI components.

The hook extracts RTL settings from the central i18n configuration:

```typescript
// Internal logic of useLocalizedTextInput
const isRTL = availableLanguages.find((l) => l.code === selectedLocale)?.isRTL ?? false;
```

When building admin components, always apply the `dir` property to ensure the cursor and text alignment match the language expectations. HeroUI v3 components respect the `dir` attribute and mirror icons (like chevrons) automatically.

```tsx
<Input
  label={t('admin.fields.taxName')}
  placeholder={t('admin.fields.taxNamePlaceholder')}
  value={inputValue}
  onValueChange={handleInputChange}
  dir={isRTL ? "rtl" : "ltr"}
  // Use startContent/endContent carefully in RTL
  endContent={isTranslating ? <Spinner size="sm" /> : null}
/>
```

## AI Translation Integration

AI translation is an opt-in feature that requires a secure connection to the `/v1/ai/parameters` endpoint. 

### Translation Flow
1.  **Source Discovery**: The hook looks for existing content in the current JSON. It walks the `FALLBACK` chain to find the most suitable source text (usually English).
2.  **Context Injection**: The `translateWithAi` utility sends the source text and the name of the target language (e.g., "French" or "Traditional Chinese") to the LLM.
3.  **State Update**: Once the AI returns the translation, `mergeFn` is called to update the specific locale key within the JSON string, and `onChange` notifies the parent form.

```typescript
// AI parameters are fetched from the backend to ensure the client 
// has the latest model configuration and system prompts.
const params = (await getJson(
  `${import.meta.env.API_BASE_URL}/v1/ai/parameters`,
)) as AiParams;

const result = await translateWithAi(
  sourceText,
  targetLangName, // e.g. "Arabic"
  params,
  false // isHtml flag: false for titles/tags, true for descriptions
);
```

## Common Pitfall: Data Loss During Saves

The most common mistake junior developers make is saving only the *currently visible* string to the database instead of the *full JSON object*. 

Because the `useLocalizedTextInput` hook calls `onChange` with the result of the `mergeFn`, the `value` passed back up to the parent component is always the complete string (either a legacy plain string or a JSON object containing all locales). 

**Never attempt to strip the JSON before sending it to the backend.**

### Incorrect Implementation (Data Loss)
```typescript
// BAD: This strips all other languages!
const handleSave = () => {
  const dataToSave = {
    ...formData,
    title: currentDisplayValue // WRONG: currentDisplayValue is just "Chemise"
  };
  api.put('/products/1', dataToSave);
};
```

### Correct Implementation
```typescript
// GOOD: The hook handles the merge, so formData.title is already the JSON string
const handleSave = () => {
  api.put('/products/1', {
    ...formData,
    title: formData.title // CORRECT: '{"en-US": "Shirt", "fr-FR": "Chemise"}'
  });
};
```

### Manual Resolution in Custom Components
If you are building a component that doesn't use the hook but needs to display a localized value, always use the `resolve` helpers provided in `description.ts` rather than `JSON.parse` manually, as the helpers handle the fallback logic and legacy string detection automatically.

```typescript
// Usage in a Product Card component
import { resolveTitle } from "@/utils/description";

const ProductCard = ({ product, locale }) => {
  // resolveTitle handles: 
  // 1. Plain strings 
  // 2. JSON objects 
  // 3. Fallback to en-US if locale is missing
  const title = resolveTitle(product.title, locale);
  
  return <h3>{title}</h3>;
};
```
