## LocalizedText Definition and Storage Format

In the Fufuni framework, multi-language strings are stored as a single `TEXT` column in the SQLite database (Durable Objects). This column contains a JSON-serialized object where keys are BCP 47 locale codes and values are the content strings.

To maintain backward compatibility with legacy data, the framework handles both raw strings (plain text or HTML) and the modern JSON format. This type is referred to as `LocalizedText` (or `LocalizedDesc` in some utility files).

```typescript
/**
 * LocalizedText represents content translated into multiple languages.
 * Map: locale code (e.g., "en-US") → content string.
 */
export type LocalizedText = Record<string, string>;

// Example storage format in the DB (TEXT column):
// '{"en-US": "<p>Hello</p>", "fr-FR": "<p>Bonjour</p>"}'

/**
 * Validates and parses the raw DB string into a LocalizedText object.
 * Returns the original string if it is not valid JSON.
 */
export function parseLocalizedText(raw: string): LocalizedText | string {
  if (!raw || !raw.trim().startsWith("{")) return raw || "";
  try {
    return JSON.parse(raw) as LocalizedText;
  } catch {
    return raw;
  }
}
```

### Storage Migration Strategy
When the framework encounters a legacy plain-text string, it treats it as the default content for all locales. Upon the first save in the admin panel, the system automatically migrates this value into a JSON structure, preserving the original text under the default locale (usually `en-US`).

## Resolving Content with the Fallback Chain

The `getLocalizedText` function (and its variant `resolveDescription`) is the primary way to retrieve content for display. It follows a strict priority order:
1. The requested locale (e.g., `fr-FR`).
2. The hardcoded fallback chain.
3. The first available locale key found in the object.

```typescript
export const DESCRIPTION_FALLBACK = [
  "en-US",
  "fr-FR",
  "es-ES",
  "zh-CN",
  "ar-SA",
  "he-IL",
] as const;

/**
 * Picks the best available translation.
 * @param raw - The raw DB string (JSON or plain text)
 * @param locale - The preferred locale code
 */
export function getLocalizedText(raw: string, locale: string): string {
  const parsed = parseLocalizedText(raw);

  // If it's legacy plain text, return it directly
  if (typeof parsed === "string") return parsed;

  // 1. Try requested locale
  if (parsed[locale]) return parsed[locale];

  // 2. Try fallback chain
  for (const fallback of DESCRIPTION_FALLBACK) {
    if (parsed[fallback]) return parsed[fallback];
  }

  // 3. Last resort: first available key
  const keys = Object.keys(parsed);
  return keys.length > 0 ? parsed[keys[0]] : "";
}

// Usage in a component:
// const title = getLocalizedText(product.name, 'fr-FR');
```

## Rich-Text HTML vs. Plain-Text Safety

Fufuni distinguishes between fields that allow HTML (like product descriptions) and fields that must remain plain text (like product titles or tax names).

### renderDescription()
When rendering descriptions in the frontend, use `renderDescription`. It resolves the localized HTML and prepares it for injection. Since Fufuni backends pre-sanitize HTML via Zod-OpenAPI and server-side middleware, it is safe to use with React's `dangerouslySetInnerHTML`.

### stripHtml()
For SEO meta-tags, PDF generation, or text-only notifications, use `stripHtml`. This ensures angle brackets and tags do not break non-browser environments.

```typescript
/**
 * Removes all HTML tags and escapes remaining angle brackets.
 */
export function stripHtml(input: string): string {
  return input
    .replace(/<[^>]*>/g, "")
    .replace(/</g, "&lt;")
    .replace(/>/g, "&gt;")
    .trim();
}

/**
 * Example: Rendering a product description in React 19
 */
export function ProductDescription({ raw, locale }: { raw: string, locale: string }) {
  const htmlContent = getLocalizedText(raw, locale);

  return (
    <div 
      className="prose dark:prose-invert"
      dangerouslySetInnerHTML={{ __html: htmlContent }} 
    />
  );
}
```

## The useLocalizedTextInput Hook

The `useLocalizedTextInput` hook centralizes the logic for managing localized inputs in admin forms. It handles state synchronization, AI-powered translation, and RTL (Right-to-Left) detection.

### Hook Props
- `value`: The current raw DB string.
- `onChange`: Callback that receives the updated JSON string.
- `selectedLocale`: The locale currently being edited in the UI.
- `parseFn`, `mergeFn`, `getFn`: Format-specific helpers from `utils/description.ts`.

### Hook Return Values
- `inputValue`: The string to put into the `<Input>` or `<Textarea>` value prop.
- `handleInputChange`: Updater for the input.
- `handleAiTranslate`: Async function to populate the field using AI.
- `isRTL`: Boolean indicating if the current locale requires RTL layout.

```typescript
import { useLocalizedTextInput } from "@/hooks/use-localized-text-input";
import { parseTitle, mergeTitleLocale, getTitleForLocale } from "@/utils/description";

// Inside an Admin Form Component:
const { 
  inputValue, 
  handleInputChange, 
  handleAiTranslate, 
  isTranslating, 
  isRTL 
} = useLocalizedTextInput({
  value: product.name, // The raw string from DB
  onChange: (newRaw) => updateProduct({ name: newRaw }),
  selectedLocale: activeTabLocale,
  parseFn: parseTitle,
```

## Implementation in Admin Forms

Admin forms typically use HeroUI `Tabs` to allow switching between languages. Each tab content uses the hook to manage its specific locale.

```tsx
import React, { useState } from "react";
import { Tabs, Tab, Input, Button } from "@heroui/react";
import { useLocalizedTextInput } from "@/hooks/use-localized-text-input";
import { parseTitle, mergeTitleLocale, getTitleForLocale } from "@/utils/description";
import { availableLanguages } from "@/i18n";

export function LocalizedNameInput({ rawValue, onChange }: { rawValue: string, onChange: (v: string) => void }) {
  const [currentLocale, setCurrentLocale] = useState("en-US");

  const { 
    inputValue, 
    handleInputChange, 
    handleAiTranslate, 
    isTranslating 
  } = useLocalizedTextInput({
    value: rawValue,
    onChange,
    selectedLocale: currentLocale,
    parseFn: parseTitle,
    mergeFn: mergeTitleLocale,
    getFn: getTitleForLocale,
  });

  return (
    <div className="flex flex-col gap-4">
      <Tabs 
        selectedKey={currentLocale} 
        onSelectionChange={(key) => setCurrentLocale(key as string)}
      >
        {availableLanguages.map((lang) => (
          <Tab key={lang.code} title={lang.nativeName} />
        ))}
      </Tabs>

      <div className="flex gap-2">
        <Input
          label="Product Name"
          value={inputValue}
          onValueChange={handleInputChange}
          fullWidth
        />
        <Button 
          isLoading={isTranslating} 
          onPress={handleAiTranslate}
          variant="flat"
        >
          AI Translate
        </Button>
      </div>
    </div>
  );
}
```

## Adding Support for a New Locale

To introduce a new language to the Fufuni framework, follow these steps:

### 1. Update the i18n Configuration
Add the locale to `apps/client/src/i18n.ts`. This ensures it appears in language selectors and the `availableLanguages` array used by hooks.

```typescript
// apps/client/src/i18n.ts
export const availableLanguages = [
  { code: "en-US", name: "English", nativeName: "English", isRTL: false },
  { code: "fr-FR", name: "French", nativeName: "Français", isRTL: false },
  { code: "ja-JP", name: "Japanese", nativeName: "日本語", isRTL: false }, // New Locale
] as const;
```

### 2. Update the Fallback Chain
If the new locale should be used as a fallback for others (e.g., if a user requests `ja-JP` but content is missing, and you want them to see `en-US`), ensure `en-US` remains in `DESCRIPTION_FALLBACK`. If the new locale itself is a primary target, add it to the fallback array in `apps/client/src/utils/description.ts`.

### 3. Automated UI Updates
Because the admin components (like the example in the previous section) map over `availableLanguages`, the UI will automatically render a new Tab for the new locale. The `useLocalizedTextInput` hook will immediately handle the state for that locale key in the JSON object.

### 4. Database Impact
No database schema changes are required. The JSON-serialized `TEXT` column naturally expands to include the new key:
```json
{
  "en-US": "Shoes",
  "fr-FR": "Chaussures",
  "ja-JP": "靴"
}
```
