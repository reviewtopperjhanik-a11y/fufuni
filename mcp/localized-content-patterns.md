## LocalizedText Type and Storage Format

Fufuni uses a "JSON-in-Text" strategy for internationalization. Instead of creating separate database rows for every translation, we store a serialized JSON object within a standard `TEXT` column in SQLite. This allows the backend to remain performant with simple queries while providing the frontend with all necessary translations in a single fetch.

The core type is `LocalizedDesc` (often referred to as `LocalizedText` in documentation), which is a dictionary where keys are ISO locale codes and values are the translated content.

```typescript
/**
 * apps/client/src/utils/description.ts
 * Type definition for localized content.
 */
export type LocalizedDesc = Record<string, string>;

/**
 * Example of a raw string stored in the database:
 * '{"en-US": "Blue Suede Shoes", "fr-FR": "Chaussures en daim bleu"}'
 */
```

### Storage and Migration
The framework is designed to be backwards compatible. When the system encounters a plain string that does not start with `{`, it treats it as legacy plain-text (usually defaulting to `en-US`). Upon the first edit in a specific locale, the utility functions automatically migrate the column to the JSON format.

```typescript
import { parseDescription, type LocalizedDesc } from "@/utils/description";

const rawDbValue = "Legacy Product Name";
const parsed = parseDescription(rawDbValue);

if (typeof parsed === "string") {
  console.log("Legacy format detected:", parsed);
} else {
  console.log("Localized object:", parsed["en-US"]);
}
```

## Localized Resolution and Fallback Chain

When displaying content to a user, we use a resolution pattern. The framework attempts to find the exact match for the user's current locale. If missing, it traverses a predefined `DESCRIPTION_FALLBACK` chain.

### getLocalizedText Implementation
While specific helpers exist for titles and vendors, they all follow the `resolveDescription` pattern. The fallback chain ensures that a user never sees an empty page if a specific translation is missing.

```typescript
import { resolveDescription, DESCRIPTION_FALLBACK } from "@/utils/description";

/**
 * Logic equivalent to getLocalizedText(raw, locale):
 * 1. Try current locale
 * 2. Try DESCRIPTION_FALLBACK order: en-US, fr-FR, es-ES, zh-CN, ar-SA, he-IL
 * 3. Return empty string if nothing found
 */
const rawContent = '{"en-US": "Hello", "es-ES": "Hola"}';
const userLocale = "fr-FR";

const textToDisplay = resolveDescription(rawContent, userLocale); 
// Output: "Hello" (fell back to en-US because fr-FR was missing)
```

### Fallback Order
The fallback chain is hardcoded to ensure consistency across the marketplace:
1. `en-US` (Primary fallback)
2. `fr-FR`
3. `es-ES`
4. `zh-CN`
5. `ar-SA`
6. `he-IL`

## Rendering and Sanitization Patterns

Fufuni distinguishes between "Rich Text" (HTML descriptions) and "Plain Text" (Titles, Vendors, Tags).

### renderDescription() vs stripHtml()
- **`renderDescription`**: Used for product descriptions. It returns the raw HTML string. Because the backend (Hono + Zod) and the Admin rich-text editor sanitize input, it is safe to inject via `dangerouslySetInnerHTML`.
- **`stripHtml`**: Used for contexts where HTML is forbidden, such as SEO `<meta>` tags, plain-text email subjects, or PDF invoices.

```typescript
import { resolveDescription, stripHtml } from "@/utils/description";

interface ProductProps {
  description: string; // Raw JSON string from DB
  locale: string;
}

export function ProductView({ description, locale }: ProductProps) {
  const htmlContent = resolveDescription(description, locale);
  const plainText = stripHtml(htmlContent);

  return (
    <div>
      {/* SEO metadata uses stripped text */}
      <meta name="description" content={plainText.slice(0, 160)} />
      
      {/* Main content renders HTML */}
      <div 
        className="prose"
        dangerouslySetInnerHTML={{ __html: htmlContent }} 
      />
    </div>
  );
}
```

## The useLocalizedTextInput Hook

For Admin interfaces, managing multiple languages manually is complex. The `useLocalizedTextInput` hook abstracts the synchronization between the UI state (the input box) and the underlying JSON storage.

### Hook Signature
The hook requires "helper" functions (`parseFn`, `mergeFn`, `getFn`) to determine how to handle the specific data type (e.g., handles are lowercase, titles are stripped of HTML).

```typescript
import { useLocalizedTextInput } from "@/hooks/use-localized-text-input";
import { 
  parseTitle, 
  mergeTitleLocale, 
  getTitleForLocale 
} from "@/utils/description";

// Inside an Admin Component:
const { 
  inputValue, 
  handleInputChange, 
  handleAiTranslate, 
  isTranslating, 
  isRTL 
} = useLocalizedTextInput({
  value: product.title,       // Raw string from DB
  onChange: (v) => update(v), // Callback to save to DB/State
  selectedLocale: "fr-FR",
  parseFn: parseTitle,
  mergeFn: mergeTitleLocale,
  getFn: getTitleForLocale,
});
```

### Usage in Admin Forms
Admin forms typically use a tabbed interface or a locale selector. When the locale changes, the hook automatically refreshes the `inputValue`.

```tsx
import { Input, Button, Spinner } from "@heroui/react";

export function LocalizedTitleInput({ value, onChange, locale }) {
  const { 
    inputValue, 
    handleInputChange, 
    handleAiTranslate, 
    isTranslating,
    canUseAi 
  } = useLocalizedTextInput({
    value,
    onChange,
    selectedLocale: locale,
    parseFn: parseTitle,
    mergeFn: mergeTitleLocale,
    getFn: getTitleForLocale,
  });

  return (
    <div className="flex flex-col gap-2">
      <Input
        label={`Title (${locale})`}
        value={inputValue}
        onValueChange={handleInputChange}
      />
      {canUseAi && (
        <Button 
          onPress={handleAiTranslate} 
          isLoading={isTranslating}
          size="sm"
        >
          Translate with AI
        </Button>
      )}
    </div>
  );
}
```

## Rich-Text HTML Storage

Rich text (descriptions) follows the same JSON pattern as titles but preserves HTML tags. The `mergeLocale` function in `description.ts` handles the injection of HTML strings into the dictionary.

### Data Flow for Rich Text
1. **Editor**: Admin uses a Rich Text Editor (like TipTap or Quill).
2. **HTML Generation**: The editor outputs an HTML string.
3. **Merging**: `mergeLocale(rawJson, locale, newHtml)` creates the updated JSON.
4. **Storage**: The backend receives the JSON string and stores it in the `description` column.

```typescript
import { mergeLocale, getEditorContent } from "@/utils/description";

// 1. Loading content into editor
const rawDb = '{"en-US": "<p>Hello</p>"}';
const currentLocale = "fr-FR";
const initialContent = getEditorContent(rawDb, currentLocale); 
// returns "<p>Hello</p>" as fallback for the editor to start with

// 2. Saving content from editor
const editorHtml = "<h3>Bonjour</h3>";
const updatedDbValue = mergeLocale(rawDb, currentLocale, editorHtml);
// Result: '{"en-US": "<p>Hello</p>", "fr-FR": "<h3>Bonjour</h3>"}'
```

## Adding Support for a New Locale

To add a new locale to an existing Admin form or the storefront, you must update the configuration in the `i18n` utility and ensure the `DESCRIPTION_FALLBACK` supports it if necessary.

### 1. Register the Locale
Add the locale to the `availableLanguages` array in your i18n configuration.

```typescript
// apps/client/src/i18n/index.ts (Example configuration)
export const availableLanguages = [
  { code: "en-US", name: "English", isRTL: false },
  { code: "fr-FR", name: "Français", isRTL: false },
  { code: "jp-JP", name: "日本語", isRTL: false }, // New Locale
] as const;
```

### 2. Update the Admin Component
In components using `useLocalizedTextInput`, the UI logic often maps over `availableLanguages` to create tabs. No logic change is usually needed if the component follows the standard pattern.

```tsx
import { Tabs, Tab } from "@heroui/react";
import { availableLanguages } from "@/i18n";

export function ProductEditor({ product, onUpdate }) {
  return (
    <Tabs items={availableLanguages}>
      {(lang) => (
        <Tab key={lang.code} title={lang.name}>
          <LocalizedTitleInput 
            value={product.title} 
            onChange={(v) => onUpdate('title', v)} 
            locale={lang.code} 
          />
          {/* The hook inside LocalizedTitleInput handles the rest */}
        </Tab>
      )}
    </Tabs>
  );
}
```

### 3. Handle specific formatting (Optional)
If the new locale is Right-To-Left (RTL), ensure the `isRTL` flag is set correctly in `availableLanguages`. The `useLocalizedTextInput` hook detects this and returns an `isRTL` boolean that you should use to flip the `dir` attribute of your inputs.

```tsx
const { inputValue, isRTL } = useLocalizedTextInput({ ... });

return (
  <Input 
    value={inputValue} 
    dir={isRTL ? "rtl" : "ltr"} 
    className={isRTL ? "text-right" : "text-left"}
  />
);
```
