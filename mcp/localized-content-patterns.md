## Localized Storage Format

Fufuni handles multilingualism at the data layer by storing localized strings as JSON objects within SQLite text columns. This approach, rather than using separate translation tables, allows for efficient fetching of a product or category in a single query while maintaining all its linguistic variants.

The standard storage format is a `LocalizedDesc` object serialized as a string:

```typescript
// Standard JSON structure in the database
{
  "en-US": "Wireless Headphones",
  "fr-FR": "Casque sans fil",
  "es-ES": "Auriculares inalámbricos",
  "ar-SA": "سماعات لاسلكية"
}
```

### Fallback Mechanism

When a specific locale is requested but missing from the JSON object, the framework follows a strictly defined fallback chain. `en-US` is the primary fallback for all other languages.

```typescript
/**
 * Fallback chain: defined in apps/client/src/utils/description.ts
 * Order: requested -> en-US -> fr-FR -> es-ES -> zh-CN -> ar-SA -> he-IL
 */
export const DESCRIPTION_FALLBACK = [
  "en-US",
  "fr-FR",
  "es-ES",
  "zh-CN",
  "ar-SA",
  "he-IL",
] as const;
```

## Core Utility Functions

The `description.ts` utility provides the logic for detecting, reading, and migrating localized content. These functions handle the transition from legacy plain-text fields to the modern JSON format.

### Parsing and Type Detection

Use `isLocalized()` to determine if a value is already in the JSON format. The `parseTitle()` and `parseDescription()` functions are used to safely decode the DB string.

```typescript
import { isLocalized, parseTitle, resolveTitle } from "@/utils/description";

const rawValue = '{"en-US": "Old Title"}';
const isJson = isLocalized(rawValue); // true

// Safely getting a display value
const displayTitle = resolveTitle(rawValue, "fr-FR"); 
// Result: "Old Title" (falls back to en-US because fr-FR is missing)
```

### Migration and Merging

When updating a single locale, use the `merge` family of functions. These functions automatically handle "promotion": if the existing value is a plain string, they convert the entire field to JSON, preserving the old content in `en-US` as a fallback.

```typescript
import { mergeTitleLocale } from "@/utils/description";

// Scenario: Migrating an old plain-text product title "Legacy Pro" to JSON
const oldRaw = "Legacy Pro";
const updatedRaw = mergeTitleLocale(oldRaw, "fr-FR", "Le Pro Héritage");

// Resulting string stored in DB:
// '{"en-US": "Legacy Pro", "fr-FR": "Le Pro Héritage"}'
```

## The useLocalizedTextInput Hook

In the Admin interface, localized fields are managed via the `useLocalizedTextInput` hook. This hook synchronizes the UI state with the complex JSON structure while providing helpers for AI translation and RTL support.

### Hook Configuration

The hook requires format-specific functions (`parse`, `merge`, `get`) because titles, descriptions (HTML), and slugs (handles) have different validation rules (e.g., stripping HTML or lowercasing).

import {

// Inside a React component

## AI Translation Integration

Fufuni leverages Cloudflare AI (via the `/v1/ai/parameters` endpoint) to automate content localization. The hook manages the complexity of selecting a source language for the translation.

### How it works:
1. It identifies a "source" locale by checking the fallback chain for any existing content.
2. It calls the AI API with the source text and the target language's native name.
3. It updates the JSON object with the newly translated string for the current locale.

```typescript
// Example of the hook's internal AI logic
const handleAiTranslate = async () => {
  setIsTranslating(true);
  try {
    // 1. Get configuration from Cloudflare Worker
    const params = await getJson(`${API_BASE_URL}/v1/ai/parameters`);
    
    // 2. Resolve source text (prefers en-US if available)
    const sourceText = getSourceFromExistingLocales(fullValue);
    
    // 3. Request translation
    const result = await translateWithAi(sourceText, "French", params);
    
    if (result.success) {
      handleInputChange(result.content); // Merges into JSON
    }
  } finally {
    setIsTranslating(false);
  }
};
```

## RTL and Directionality

Localization in Fufuni includes layout direction. The `useLocalizedTextInput` hook detects RTL languages by looking up the `isRTL` property in the `availableLanguages` configuration.

When building localized inputs, you must apply the `dir` attribute to the wrapper or the input element to ensure correct cursor behavior and text alignment.

```tsx
import { Input } from "@heroui/react";

// Implementation inside an Admin form field
<Input
  label={`Title (${selectedLocale})`}
  value={inputValue}
  onValueChange={handleInputChange}
  dir={isRTL ? "rtl" : "ltr"}
  className={isRTL ? "text-right" : "text-left"}
  endContent={
    <Button 
      isLoading={isTranslating} 
      onClick={handleAiTranslate}
    >
      AI Translate
    </Button>
  }
/>
```

## Implementation Guide: Adding a Localized Field to an Admin Form

To add a localized field to an admin form, you need to manage the "Active Locale" of the editor separately from the application's UI locale. This allows an English-speaking admin to edit French content.

```tsx
import React, { useState } from "react";
import { Tabs, Tab, Input, Card } from "@heroui/react";
import { useLocalizedTextInput } from "@/hooks/use-localized-text-input";
import { parseTitle, mergeTitleLocale, getTitleForLocale } from "@/utils/description";

interface ProductFormProps {
  initialData: { title: string };
  onSave: (data: { title: string }) => void;
}

export const ProductTitleEditor: React.FC<ProductFormProps> = ({ initialData, onSave }) => {
  const [activeLocale, setActiveLocale] = useState("en-US");
  const [rawTitle, setRawTitle] = useState(initialData.title);

  const {
    inputValue,
    handleInputChange,
    handleAiTranslate,
    isRTL,
    isTranslating
  } = useLocalizedTextInput({
    value: rawTitle,
    onChange: (val) => {
       setRawTitle(val);
       onSave({ title: val });
    },
    selectedLocale: activeLocale,
    parseFn: parseTitle,
    mergeFn: mergeTitleLocale,
    getFn: getTitleForLocale,
  });

  return (
    <Card className="p-4">
      <Tabs 
        selectedKey={activeLocale} 
        onSelectionChange={(key) => setActiveLocale(key as string)}
      >
        <Tab key="en-US" title="English" />
        <Tab key="fr-FR" title="French" />
        <Tab key="ar-SA" title="Arabic" />
      </Tabs>

      <div className="mt-4">
        <Input
          label="Product Name"
          value={inputValue}
          onValueChange={handleInputChange}
          dir={isRTL ? "rtl" : "ltr"}
          description={`Editing content for ${activeLocale}`}
          endContent={
            <button 
              disabled={isTranslating}
              onClick={handleAiTranslate}
              className="text-tiny bg-primary-100 p-1 rounded"
            >
              {isTranslating ? "..." : "AI Auto-fill"}
            </button>
          }
        />
      </div>
    </Card>
  );
};
```

## Common Pitfall: Partial State Saving

A frequent error for junior developers is saving only the current `inputValue` back to the database.

**The Mistake:**
```typescript
// WRONG: This overwrites the entire DB column with just the French string, 
// deleting English, Spanish, and Arabic translations.
const handleSave = () => {
  saveToDb({ title: inputValue }); 
};
```

**The Correct Pattern:**
The `useLocalizedTextInput` hook's `onChange` callback provides the **full JSON string** containing all languages. You must store this full string.

```typescript
// CORRECT: The hook manages the merge logic internally.
// The value passed to onChange is already the stringified JSON object.
const { handleInputChange } = useLocalizedTextInput({
  value: rawDbValue,
  onChange: (fullJsonString) => {
    // fullJsonString looks like: '{"en-US":"...", "fr-FR":"..."}'
    api.products.update(id, { title: fullJsonString });
  },
  // ...
});
```

Always ensure your backend Zod schema validates the field as a string, but recognize that the string content should be valid JSON if multiple languages are present. In the frontend, never assume the database value is a simple string; always pass it through the `parse` and `resolve` utilities before rendering.
