## Multi-Warehouse Inventory Architecture

Fufuni employs a hybrid inventory system designed for high-availability and regional logistics. The system tracks stock across specific physical locations (`warehouses`) while maintaining an aggregated view for the checkout engine.

The source of truth for stock levels is the `warehouse_inventory` table. Every movement (adjustment, addition, or reduction) must be recorded in `warehouse_inventory_logs` to ensure a full audit trail.

### Inventory Data Model

Stock is partitioned by `sku` and `warehouse_id`. The framework calculates availability using two primary metrics:
- **on_hand**: The physical quantity currently present in the building.
- **reserved**: The quantity promised to pending orders (items in carts or awaiting payment).
- **available**: A calculated value (`on_hand - reserved`).

```typescript
// apps/merchant/src/lib/inventory.ts

import type { Database } from '../db';
import { ApiError, now, uuid } from '../types';

/**
 * Retrieves the aggregate availability for a SKU across all warehouses.
 * Used by the storefront to determine if a product can be added to cart.
 */
export async function getAvailableQty(db: Database, sku: string): Promise<number> {
  const result = await db.query<{ total_on_hand: number; total_reserved: number }>(
    `SELECT
       COALESCE(SUM(on_hand), 0)    AS total_on_hand,
       COALESCE(SUM(reserved), 0)   AS total_reserved
     FROM warehouse_inventory
     WHERE sku = ?`,
    [sku]
  );

  if (result && result.length > 0 && result[0].total_on_hand > 0) {
    return result[0].total_on_hand - result[0].total_reserved;
  }

  // Fallback to legacy single-table inventory if no warehouse rows exist
  const legacy = await db.query<{ on_hand: number; reserved: number }>(
    `SELECT on_hand, reserved FROM inventory WHERE sku = ?`,
    [sku]
  );

  return legacy.length > 0 ? legacy[0].on_hand - legacy[0].reserved : 0;
}
```

### Warehouse Allocation Strategy

When a reservation occurs, the framework must decide which warehouse "holds" the stock. The default strategy selects the warehouse with the highest available quantity (`on_hand - reserved`) to balance the load across the logistics network.

```sql
-- Internal query used during reservation to pick the best warehouse
SELECT warehouse_id
FROM warehouse_inventory
WHERE sku = 'PROD-123-BLUE'
ORDER BY (on_hand - reserved) DESC
LIMIT 1;
```

## Stock Reservation vs. Commitment

The inventory lifecycle follows a two-phase commit pattern to prevent overselling while ensuring customers don't lose items during the payment flow.

### 1. Reservation (Order Creation)
When a customer proceeds to checkout, `reserveInventory` is called. This increments the `reserved` column but leaves `on_hand` untouched. This "locks" the stock for a specific duration.

### 2. Commitment (Payment Success)
When the Stripe webhook confirms successful payment, `commitSale` is called. This decrements both `on_hand` (physical removal) and `reserved` (clearing the lock).

### 3. Release (Failure/Expiry)
If a payment fails or a cart expires, `releaseReservation` is called to decrement the `reserved` count, making the items available for other customers again.

```typescript
/**
 * Commits a sale after successful payment confirmation.
 * Decrements both physical stock and the reservation hold.
 */
export async function commitSale(
  db: Database,
  sku: string,
  qty: number
): Promise<void> {
  const timestamp = now();

  // 1. Update the warehouse that held the reservation
  const result = await db.run(
    `UPDATE warehouse_inventory
     SET on_hand    = MAX(on_hand - ?, 0),
         reserved   = MAX(reserved - ?, 0),
         updated_at = ?
     WHERE sku = ? AND reserved >= ?`,
    [qty, qty, timestamp, sku, qty]
  );

  // 2. Sync the legacy aggregated table for dashboard/legacy compatibility
  await db.run(
    `UPDATE inventory
     SET on_hand = (SELECT SUM(on_hand) FROM warehouse_inventory WHERE sku = ?),
         reserved = (SELECT SUM(reserved) FROM warehouse_inventory WHERE sku = ?),
         updated_at = ?
     WHERE sku = ?`,
    [sku, sku, timestamp, sku]
  );
}
```

## Inventory Adjustments and Logging

Admin users can manually adjust stock levels through the `Inventory - Warehouse` API. Every adjustment requires a `reason` (e.g., "Restock", "Damaged", "Return") which is persisted in the logs.

```typescript
// apps/merchant/src/routes/inventory.ts (Snippet)

const adjustWarehouseInventory = createRoute({
  method: 'post',
  path: '/{sku}/warehouse-adjust',
  tags: ['Inventory - Warehouse'],
  request: {
    params: SkuParam,
    body: { content: { 'application/json': { schema: AdjustWarehouseInventoryBody } } },
  },
  responses: {
    200: { content: { 'application/json': { schema: WarehouseInventoryItem } } },
    400: { description: 'Insufficient stock for reduction' }
  },
});

adminApp.openapi(adjustWarehouseInventory, async (c) => {
  const { sku } = c.req.valid('param');
  const { warehouse_id, delta, reason } = c.req.valid('json');
  const db = getDb(c.var.db);

  // Atomic update with safety check to prevent negative stock
  const result = await db.run(
    `UPDATE warehouse_inventory 
     SET on_hand = on_hand + ?, updated_at = ? 
     WHERE sku = ? AND warehouse_id = ? AND (on_hand + ?) >= 0`,
    [delta, now(), sku, warehouse_id, delta]
  );

  if (result.changes === 0) {
    throw ApiError.invalidRequest(`Cannot reduce stock below 0 for SKU: ${sku}`);
  }

  // Mandatory logging for every movement
  await db.run(
    `INSERT INTO warehouse_inventory_logs (id, sku, warehouse_id, delta, reason, created_at) 
     VALUES (?, ?, ?, ?, ?, ?)`,
    [uuid(), sku, warehouse_id, delta, reason, now()]
  );

  return c.json({ sku, warehouse_id, delta, status: 'success' }, 200);
});
```

## Error Handling for Insufficient Stock

Handling out-of-stock scenarios requires precision. The `lib/inventory.ts` utility functions perform the logic, but the API handlers are responsible for throwing the standardized `ApiError.insufficientInventory()`.

### Handling Concurrency
Because Fufuni runs on Cloudflare Durable Objects, requests for a specific merchant are processed in a single-threaded environment per DO instance. However, availability checks and reservations use SQL constraints (`AND (on_hand - reserved) >= ?`) to ensure atomicity even if multiple async operations are pending.

```typescript
// Example of a handler managing a stock reservation
async function handleCheckout(c: Context) {
  const db = getDb(c.var.db);
  const { items } = await c.req.json();

  try {
    for (const item of items) {
      // The lib function tries to update; if 0 rows changed, it fails
      await reserveInventory(db, item.sku, item.quantity);
    }
  } catch (error) {
    // Catch-all for inventory failures
    // Note: In a real flow, you would release any successful reservations 
    // made before the failure occurred.
    throw ApiError.insufficientInventory('One or more items are no longer available');
  }
}
```

## Regional Inventory Aggregation

Fufuni supports `Regions`, which are groups of warehouses. This allows the frontend to show "Stock in Europe" or "Stock in North America" by aggregating data across specific `warehouse_id`s linked to a `region_id`.

### Regional Summary Query
The following logic calculates regional availability by joining the `region_warehouses` mapping table with the live inventory data:

```typescript
// apps/merchant/src/routes/inventory.ts

const getRegionalInventory = createRoute({
  method: 'get',
  path: '/{sku}/regional',
  // ... parameters: sku (param), region_id (query)
});

adminApp.openapi(getRegionalInventory, async (c) => {
  const { sku } = c.req.valid('param');
  const { region_id } = c.req.valid('query');
  const db = getDb(c.var.db);

  const warehouses = await db.query<any>(
    `SELECT 
        wi.warehouse_id, 
        w.display_name,
        wi.on_hand, 
        wi.reserved
     FROM warehouse_inventory wi
     JOIN region_warehouses rw ON wi.warehouse_id = rw.warehouse_id
     JOIN warehouses w ON wi.warehouse_id = w.id
     WHERE wi.sku = ? AND rw.region_id = ?`,
    [sku, region_id]
  );

  const summary = warehouses.reduce((acc, w) => ({
    on_hand: acc.on_hand + w.on_hand,
    reserved: acc.reserved + w.reserved
  }), { on_hand: 0, reserved: 0 });

  return c.json({
    sku,
    region_id,
    available: summary.on_hand - summary.reserved,
    breakdown: warehouses
  }, 200);
});
```

### Low Stock Alerts
The framework includes a `checkLowInventory` utility (triggered after adjustments) that evaluates the new availability against a threshold (defaulting to 10 units). If stock falls below this level, it triggers an internal webhook to notify the merchant.
