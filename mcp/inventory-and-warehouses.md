## Data Model and Schema

Fufuni utilizes a multi-warehouse inventory system. Stock is tracked per variant per warehouse to allow for regional distribution and precise fulfillment logic. The core of this system resides in the `inventory` and `warehouses` tables.

### Inventory Table
This table tracks the physical and reserved quantities for every product variant across different locations.

```sql
CREATE TABLE inventory (
  variant_id TEXT NOT NULL,
  warehouse_id TEXT NOT NULL,
  quantity INTEGER NOT NULL DEFAULT 0,
  reserved INTEGER NOT NULL DEFAULT 0,
  updated_at INTEGER NOT NULL,
  PRIMARY KEY (variant_id, warehouse_id),
  FOREIGN KEY (warehouse_id) REFERENCES warehouses(id)
);

CREATE INDEX idx_inventory_variant ON inventory(variant_id);
```

### Warehouse Table
Warehouses represent physical locations. One warehouse is always designated as the default for new product initialization.

```sql
CREATE TABLE warehouses (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  address TEXT,
  is_default BOOLEAN DEFAULT 0,
  priority INTEGER DEFAULT 0,
  created_at INTEGER NOT NULL
);
```

## Transaction Safety in Durable Objects

Inventory management is highly sensitive to race conditions (e.g., two customers buying the last item simultaneously). Fufuni mitigates this by running the backend on Cloudflare Durable Objects (DO). Since each DO is single-threaded and provides a private SQLite instance, all mutations are inherently serialized.

However, complex operations involving multiple tables or logic checks must be wrapped in explicit transactions to ensure ACID compliance.

```typescript
import { Database } from '../db';
import { ApiError } from '../types';

async function performInventoryUpdate(db: Database, variantId: string, delta: number) {
  // SQLite transactions in Fufuni DO ensure that state is consistent 
  // even if the Worker is evicted during the operation.
  await db.transaction(async () => {
    const stock = await db.query<{ quantity: number }>(
      'SELECT quantity FROM inventory WHERE variant_id = ?',
      [variantId]
    );

    if (stock[0].quantity + delta < 0) {
      throw ApiError.invalidRequest("Insufficient physical stock for adjustment");
    }

    await db.run(
      'UPDATE inventory SET quantity = quantity + ?, updated_at = ? WHERE variant_id = ?',
      [delta, Date.now(), variantId]
    );
  });
}
```

## Core Utility Functions (lib/inventory.ts)

The framework centralizes inventory logic into four primary helper functions. These should be used instead of raw SQL queries whenever possible to ensure consistency across the checkout and admin modules.

### getStockLevel(db, variantId)
Calculates the total available stock for a variant across all warehouses. Availability is defined as `quantity - reserved`.

```typescript
export async function getStockLevel(db: Database, variantId: string): Promise<number> {
  const result = await db.query<{ total: number }>(
    `SELECT SUM(quantity - reserved) as total 
     FROM inventory 
     WHERE variant_id = ?`,
    [variantId]
  );
  return result[0]?.total ?? 0;
}
```

### reserveStock(db, variantId, qty)
Called when a customer adds an item to their cart or begins checkout. It moves stock from "available" to "reserved" status.

```typescript
export async function reserveStock(db: Database, variantId: string, qty: number): Promise<void> {
  const result = await db.run(
    `UPDATE inventory 
     SET reserved = reserved + ?, updated_at = ?
     WHERE variant_id = ? 
     AND (quantity - reserved) >= ?`,
    [qty, Date.now(), variantId, qty]
  );

  if (result.changes === 0) {
    throw ApiError.insufficientInventory(variantId);
  }
}
```

### releaseStock(db, variantId, qty)
Called if a checkout session expires or an order is cancelled. It returns the reserved units back to the available pool.

```typescript
export async function releaseStock(db: Database, variantId: string, qty: number): Promise<void> {
  await db.run(
    `UPDATE inventory 
     SET reserved = MAX(reserved - ?, 0), updated_at = ?
     WHERE variant_id = ?`,
    [qty, Date.now(), variantId]
  );
}
```

### deductStock(db, variantId, qty)
Called after a successful payment (e.g., via Stripe Webhook). It permanently removes the items from both the physical `quantity` and the `reserved` pool.

```typescript
export async function deductStock(db: Database, variantId: string, qty: number): Promise<void> {
  await db.run(
    `UPDATE inventory 
     SET quantity = MAX(quantity - ?, 0),
         reserved = MAX(reserved - ?, 0),
         updated_at = ?
     WHERE variant_id = ?`,
    [qty, qty, Date.now(), variantId]
  );
}
```

## Checkout Lifecycle

The inventory lifecycle follows a strict state machine to prevent overselling while ensuring stock is not "leaked" during failed transactions.

1.  **Validation & Reservation**: When the checkout starts, `reserveStock` is called. If this fails, the UI notifies the user that the item is sold out.
2.  **Payment Processing**: The stock remains reserved while the user is on the Stripe hosted payment page.
3.  **Completion**:
    *   **Success**: The `checkout.session.completed` webhook triggers `deductStock`.
    *   **Failure/Expiry**: The `checkout.session.expired` webhook triggers `releaseStock`.

```typescript
// Example: Stripe Webhook Handler snippet
app.post('/webhooks/stripe', async (c) => {
  const event = c.req.valid('json');
  const db = getDb(c);

  switch (event.type) {
    case 'checkout.session.completed':
      const items = await getLineItems(event.data.object.id);
      for (const item of items) {
        await deductStock(db, item.variantId, item.quantity);
      }
      break;
    case 'checkout.session.expired':
      const expiredItems = await getLineItems(event.data.object.id);
      for (const item of expiredItems) {
        await releaseStock(db, item.variantId, item.quantity);
      }
      break;
  }
});
```

```typescript
adminApp.openapi(adjustRoute, async (c) => {
  const { variantId, warehouseId, delta } = c.req.valid('json');
  const db = getDb(c);

  await db.run(
    `INSERT INTO inventory (variant_id, warehouse_id, quantity, updated_at)
     VALUES (?, ?, ?, ?)
     ON CONFLICT(variant_id, warehouse_id) DO UPDATE SET
     quantity = quantity + excluded.quantity,

  );

});
```

## Low-Stock Webhooks

Fufuni monitors inventory levels during the `deductStock` phase. If the remaining quantity for a variant drops below a defined threshold (defaulting to 10 units), the system emits a `low_stock` webhook event.

### Event Payload
```json
{
  "event": "low_stock",
  "data": {
    "variant_id": "var_123",
    "sku": "TSHIRT-BLUE-L",
    "current_quantity": 8,
    "threshold": 10,
    "warehouse_id": "wh_primary"
  }
}
```

### Trigger Logic
```typescript
async function checkThreshold(db: Database, variantId: string, warehouseId: string) {
  const [row] = await db.query(
    'SELECT quantity FROM inventory WHERE variant_id = ? AND warehouse_id = ?',
    [variantId, warehouseId]
  );
  
  const THRESHOLD = 10;
  if (row.quantity <= THRESHOLD) {
    await queueWebhook('low_stock', {
      variant_id: variantId,
      current_quantity: row.quantity,
      warehouse_id: warehouseId
    });
  }
}
```

## Warehouse Management

The `warehouses` endpoints allow administrators to manage fulfillment locations.

### Default Warehouse Behavior
The system identifies a "default" warehouse using the `is_default` flag. When a new product or variant is created, the system automatically initializes an `inventory` row with 0 quantity for the default warehouse to ensure it appears in the stock management UI.

```typescript
// POST /v1/warehouses
const createWarehouse = createRoute({
  method: 'post',
  path: '/',
  request: {
    body: {
      content: {
        'application/json': {
          schema: z.object({
            name: z.string(),
            address: z.string().optional(),
            is_default: z.boolean().optional()
          })
        }
      }
    }
  },
  responses: { 201: { description: "Warehouse created" } }
});

adminApp.openapi(createWarehouse, async (c) => {
  const data = c.req.valid('json');
  const db = getDb(c);
  const id = `wh_${crypto.randomUUID()}`;

  await db.transaction(async () => {
    if (data.is_default) {
      // Unset previous default
      await db.run('UPDATE warehouses SET is_default = 0');
    }
    
    await db.run(
      'INSERT INTO warehouses (id, name, address, is_default, created_at) VALUES (?, ?, ?, ?, ?)',
      [id, data.name, data.address, data.is_default ? 1 : 0, Date.now()]
    );
  });

  return c.json({ id }, 201);
});
```
