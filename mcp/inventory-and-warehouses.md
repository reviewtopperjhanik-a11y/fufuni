## Inventory and Warehouses

### Stock tracking across multiple warehouses

Fufuni keeps two parallel inventory layers:

1. `warehouse_inventory` – the **source of truth** for every physical location  
2. `inventory` – a legacy mirror used only for backward-compatible dashboards and quick SKU-level totals

When a SKU exists in `warehouse_inventory` (≥ 1 row) the system **ignores** the legacy table for availability calculations.  
The merchant dashboard always shows the **aggregated** numbers (`SUM(on_hand)`, `SUM(reserved)`) while the warehouse view keeps the per-location breakdown.

```typescript
// apps/merchant/src/lib/inventory.ts
export async function getAvailableQty(
  db: Database,
  sku: string
): Promise<number> {
  const wh = await db.query<{
    total_on_hand: number;
    total_reserved: number;
  }>(
    `SELECT COALESCE(SUM(on_hand),0)  AS total_on_hand,
            COALESCE(SUM(reserved),0) AS total_reserved
     FROM   warehouse_inventory
     WHERE  sku = ?`,
    [sku]
  );

  if (wh?.length && wh[0].total_on_hand > 0) {
    // multi-warehouse path
    return wh[0].total_on_hand - wh[0].total_reserved;
  }

  // legacy single-warehouse path
  const leg = await db.query<{ on_hand: number; reserved: number }>(
    `SELECT on_hand, reserved FROM inventory WHERE sku = ?`,
    [sku]
  );
  return leg?.length ? leg[0].on_hand - leg[0].reserved : 0;
}
```

Creating or moving stock between warehouses is done through the **warehouse-adjust** endpoint; it automatically inserts missing rows (`ON CONFLICT` is handled manually because SQLite in Durable Objects does not yet support `UPSERT`).

```typescript
// apps/merchant/src/routes/inventory.ts  (excerpt)
const [existing] = await db.query<any>(

    `INSERT INTO warehouse_inventory(id,sku,warehouse_id,on_hand,reserved,updated_at)
     VALUES (?,?,?,0,0,?)`,
    [uuid(), sku, warehouseId, now()]
  );
}
```

### Reservation vs. definitive deduction

| Stage | DB change | When it happens | Rollback |
|-------|-----------|---------------|----------|
| **Reservation** | `reserved += qty` | Item added to cart or checkout started | Cart expiry, payment failure, manual cancel |
| **Commit / Sale** | `on_hand -= qty` **and** `reserved -= qty` | Stripe `payment_intent.succeeded` webhook | Not allowed – sale is final |

Reservation is **warehouse-aware**: the algorithm picks the warehouse with the **highest available qty** (`on_hand - reserved`) and locks the stock there.  
This avoids “splitting” a reservation across warehouses and keeps the pick-list in one physical location.

```typescript
// apps/merchant/src/lib/inventory.ts
export async function reserveInventory(
  db: Database,
  sku: string,
  qty: number
): Promise<void> {
  const whCount = await db.query<{ cnt: number }>(
    `SELECT COUNT(*) AS cnt FROM warehouse_inventory WHERE sku = ?`,
    [sku]
  );

  if (whCount?.[0].cnt) {
    const res = await db.run(
      `UPDATE warehouse_inventory
       SET reserved = reserved + ?, updated_at = ?
       WHERE sku = ?
         AND warehouse_id = (
           SELECT warehouse_id
           FROM   warehouse_inventory
           WHERE  sku = ?
           ORDER  BY (on_hand - reserved) DESC
           LIMIT  1
         )
         AND (on_hand - reserved) >= ?`,
      [qty, now(), sku, sku, qty]
    );

    if (!res.changes) throw ApiError.insufficientInventory(sku);

    // keep legacy table in sync for dashboards
    await db.run(
      `UPDATE inventory
       SET reserved = (SELECT COALESCE(SUM(reserved),0)
                       FROM warehouse_inventory WHERE sku = ?),
           updated_at = ?
       WHERE sku = ?`,
      [sku, now(), sku]
    );
  } else {
    // legacy path
    const res = await db.run(
      `UPDATE inventory
       SET reserved = reserved + ?, updated_at = ?
       WHERE sku = ? AND (on_hand - reserved) >= ?`,
      [qty, now(), sku, qty]
    );
    if (!res.changes) throw ApiError.insufficientInventory(sku);
  }
}
```

Releasing a reservation (cart abandoned, payment failed) is **idempotent** and **warehouse-agnostic**: every warehouse row for the SKU is decreased, but `MAX(reserved - ?, 0)` prevents negative values.

```typescript
await db.run(
  `UPDATE warehouse_inventory
   SET reserved = MAX(reserved - ?, 0), updated_at = ?
   WHERE sku = ?`,
  [qty, now(), sku]
);
```

### Error handling for insufficient inventory

All inventory-mutating helpers in `lib/inventory.ts` **never throw directly**; instead they return `0` or leave the DB unchanged and let the **caller** decide how to surface the problem.  
The route handlers translate the **zero-changes** signal into the proper HTTP error:

```typescript
// apps/merchant/src/routes/checkout.ts  (example consumer)
try {
  await reserveInventory(db, sku, qty);
} catch (e) {
  if (e instanceof ApiError && e.code === 'insufficient_inventory') {
    return c.json({ message: 'Not enough stock', sku }, 409);
  }
  throw e;
}
```

The same pattern applies to `commitSale`: the Stripe webhook handler checks the number of affected rows and **fails the webhook** (HTTP 4xx) so Stripe retries later – guaranteeing **at-least-once** stock deduction without overselling.

```typescript
const res = await db.run(
  `UPDATE warehouse_inventory
   SET on_hand   = MAX(on_hand - ?, 0),
       reserved  = MAX(reserved - ?, 0),
       updated_at = ?
   WHERE sku = ? AND reserved >= ?`,
  [qty, qty, now(), sku, qty]
);

if (!res.changes) {
  // reservation was probably released by expiry
  return c.text('Stock already released', 422); // ask Stripe to retry
}
```

### Quick reference snippets

Create or update warehouse stock (admin endpoint):

```typescript
const delta = 50; // positive = inbound, negative = outbound
await db.run(
  `UPDATE warehouse_inventory
   SET on_hand = on_hand + ?, updated_at = ?
   WHERE sku = ? AND warehouse_id = ?`,
  [delta, now(), sku, warehouseId]
);

await db.run(
  `INSERT INTO warehouse_inventory_logs(id,sku,warehouse_id,delta,reason)
   VALUES (?,?,?,?,?)`,
  [uuid(), sku, warehouseId, delta, 'Inbound shipment #12345']
);
```

Get low-stock SKUs across warehouses (≤ 10 available):

```sql
SELECT sku,
       SUM(on_hand) - SUM(reserved) AS available
FROM   warehouse_inventory
GROUP  BY sku
HAVING available <= 10
ORDER  BY available ASC;
```

Delete a warehouse location (moves stock to **void** – use with care):

```typescript
// 1. move physical stock to a dummy warehouse or write it off
// 2. delete the row
await db.run(
  `DELETE FROM warehouse_inventory WHERE warehouse_id = ?`,
  [warehouseId]
);
// 3. re-aggregate totals into legacy table
await db.run(
  `UPDATE inventory
   SET on_hand = (SELECT COALESCE(SUM(on_hand),0)
                    FROM warehouse_inventory WHERE sku = inventory.sku),
       reserved = (SELECT COALESCE(SUM(reserved),0)
                   FROM warehouse_inventory WHERE sku = inventory.sku),
       updated_at = ?
   WHERE sku IN (SELECT DISTINCT sku FROM warehouse_inventory)`,
  [now()]
);
```

These conventions keep the codebase safe for concurrent carts, idempotent webhooks, and future warehouse expansion without schema changes.
