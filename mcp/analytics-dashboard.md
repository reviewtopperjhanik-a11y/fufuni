## Analytics Dashboard Reference

The Fufuni analytics system provides real-time business intelligence directly from the Durable Object SQLite database. Unlike traditional e-commerce platforms that rely on external event trackers (like Segment or Google Analytics), Fufuni computes metrics on-demand using SQL. This ensures 100% data accuracy regarding financial transactions and customer behavior without third-party cookies or privacy concerns.

All analytics routes are hosted under the `/v1/analytics` prefix and are restricted to users with administrative privileges via the `adminOnly` middleware.

### Common Query Parameters

Every analytics endpoint supports a standard set of query parameters to filter data and format monetary values.

| Parameter | Type | Description | Default |
| :--- | :--- | :--- | :--- |
| `from` | `string (ISO 8601)` | Start date for the reporting period. | `now - 30 days` |
| `to` | `string (ISO 8601)` | End date for the reporting period. | `now` |
| `currency` | `string (ISO 4217)` | Target currency for conversion (e.g., `USD`, `EUR`). | Store default |

Monetary values in responses are always returned in the **smallest unit** (cents) for the requested currency. For example, `$10.50` is returned as `1050`.

```typescript
// Example of the shared validation schema for analytics queries
import { z } from '@hono/zod-openapi';

export const AnalyticsQuerySchema = z.object({
  from: z.string().datetime().optional(),
  to: z.string().datetime().optional(),
  currency: z.string().length(3).optional().default('USD'),
  period: z.enum(['7d', '30d', '90d', 'all']).optional(),
});
```

## Revenue and Financial Tracking

The revenue endpoint aggregates sales data from orders that have reached a successful payment state. Orders with statuses like `pending` or `cancelled` are excluded from these calculations to prevent inflated metrics.

### GET /v1/analytics/revenue

This endpoint returns a summary of income and a daily breakdown suitable for line charts.

**Response Shape:**
```typescript
interface RevenueResponse {
  total_cents: number;
  byDay: Array<{
    date: string; // YYYY-MM-DD
    amount_cents: number;
  }>;
  byProduct: Array<{
    productId: string;
    name: string;
    amount_cents: number;
  }>;
}
```

### Implementation Logic
The server computes "Total Revenue" by summing the `total_cents` column in the `orders` table where the status is in `('paid', 'processing', 'shipped', 'delivered')`.

```sql
-- Example SQL used by the Durable Object to generate daily revenue
SELECT 
    strftime('%Y-%m-%d', created_at) as date,
    SUM(total_cents) as amount_cents
FROM orders
WHERE status NOT IN ('pending', 'cancelled', 'refunded')
  AND created_at BETWEEN ? AND ?
GROUP BY date
ORDER BY date ASC;
```

## Order Lifecycle Metrics

Order analytics focus on fulfillment efficiency and order volume distribution.

### GET /v1/analytics/orders

Returns the distribution of orders across different lifecycle states and the Average Order Value (AOV).

**Response Shape:**
```typescript
interface OrderMetricsResponse {
  total: number;
  avgOrderValue: number; // in cents
  byStatus: {
    pending: number;
    paid: number;
    processing: number;
    shipped: number;
    delivered: number;
    cancelled: number;
    refunded: number;
  };
}
```

The `avgOrderValue` is calculated as `SUM(total_cents) / COUNT(order_id)` for all non-cancelled orders within the selected time range.

## Customer Retention and Acquisition

Customer metrics help merchants understand if their growth is driven by new shoppers or a loyal base.

### GET /v1/analytics/customers

**Response Shape:**
```typescript
interface CustomerMetricsResponse {
  total: number;       // Total unique customers in DB
  newInPeriod: number; // Customers whose first order was in this range
  returningRate: number; // Percentage (0-100) of orders from repeat customers
}
```

### Understanding Returning Rate
Fufuni defines a **Returning Customer** as any customer who has placed more than one order in the history of the store. The `returningRate` returned for a specific period is:
`(Orders placed by repeat customers in period / Total orders in period) * 100`.

```typescript
// Logic within the Analytics DO
const returningOrders = await db.query(
  `SELECT COUNT(id) as count FROM orders 
   WHERE customer_id IN (
     SELECT customer_id FROM orders GROUP BY customer_id HAVING COUNT(id) > 1
   ) AND created_at BETWEEN ? AND ?`
);
```

## Product Performance

Identifying top-performing products is critical for inventory management and marketing focus.

### GET /v1/analytics/products/top

Returns the top 10 products ranked by total revenue generated within the date range.

**Response Shape:**
```typescript
interface TopProductsResponse {
  products: Array<{
    product_id: string;
    product_title: string;
    units_sold: number;
    revenue_cents: number;
  }>;
}
```

The ranking is computed by joining `order_items` with the `orders` table to ensure only paid items are counted.

## Checkout Funnel and Conversion

The funnel analytics track the progression of a user from initial cart creation to successful payment.

### GET /v1/analytics/funnel

**Response Shape:**
```typescript
interface FunnelResponse {
  cartCreated: number;
  checkoutStarted: number;
  checkoutCompleted: number;
  conversionRate: number; // (completed / cartCreated) * 100
}
```

1.  **Cart Created:** A session where at least one item was added to the cart.
2.  **Checkout Started:** A session where the user reached the shipping information step.
3.  **Checkout Completed:** A session resulting in a `paid` order.

## Frontend Visualization

The Merchant Dashboard uses **Recharts** for data visualization. Because Fufuni is built on React 19, it leverages `useQuery` from TanStack Query for efficient data fetching and caching.

### Example: Revenue Chart Component

```tsx
import { useQuery } from "@tanstack/react-query";
import { LineChart, Line, XAxis, YAxis, Tooltip, ResponsiveContainer } from "recharts";
import { Card, CardBody, CardHeader } from "@heroui/react";
import { useSecuredApi } from "@/authentication";
import { formatMoney } from "@/utils/currency";

export function RevenueChart({ period }: { period: string }) {
  const { getJson } = useSecuredApi();

  const { data, isLoading } = useQuery({
    queryKey: ["analytics-revenue", period],
    queryFn: () => getJson(`/v1/analytics/revenue?period=${period}`),
  });

  if (isLoading) return <div className="h-64 animate-pulse bg-default-100 rounded-lg" />;

  return (
    <Card className="w-full h-80">
      <CardHeader>Revenue Growth</CardHeader>
      <CardBody>
        <ResponsiveContainer width="100%" height="100%">
          <LineChart data={data.byDay}>
            <XAxis dataKey="date" hide />
            <YAxis 
              tickFormatter={(val) => formatMoney(val, 'USD')}
              fontSize={12} 
            />
            <Tooltip 
              formatter={(val: number) => [formatMoney(val, 'USD'), "Revenue"]}
            />
            <Line 
              type="monotone" 
              dataKey="amount_cents" 
              stroke="#0070f3" 
              strokeWidth={2} 
              dot={false}
            />
          </LineChart>
        </ResponsiveContainer>
      </CardBody>
    </Card>
  );
}
```

## Performance and Optimization

Fufuni computes analytics **on-demand**. This avoids the "stale data" problem but can become slow if the `orders` or `order_items` tables grow to hundreds of thousands of rows. 

### Database Indexing
To maintain sub-second response times for the dashboard, ensure the following indexes exist in your SQLite schema. These are standard in the Fufuni base migration but should be verified if you add custom analytics.

```sql
-- Speed up date-range filtering
CREATE INDEX IF NOT EXISTS idx_orders_created_at ON orders(created_at);

-- Speed up status distribution queries
CREATE INDEX IF NOT EXISTS idx_orders_status ON orders(status);

-- Speed up Top Products computation (joins and aggregations)
CREATE INDEX IF NOT EXISTS idx_order_items_product_id ON order_items(product_id);
CREATE INDEX IF NOT EXISTS idx_orders_customer_id ON orders(customer_id);
```

### Computation Note
If a store scales beyond 1 million orders, the "on-demand" approach may cause Durable Object CPU timeouts. In such cases, the framework supports a background "Aggregation Worker" that pre-computes daily stats into a `stats_daily` table, though this is disabled by default to simplify the architecture for small-to-medium merchants.
