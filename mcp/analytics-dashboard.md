## Analytics Engine Architecture

Fufuni provides a built-in analytics engine that operates directly on the Durable Object's SQLite database. Unlike traditional e-commerce platforms that rely on external event trackers (like Segment or GA4) for operational reporting, Fufuni aggregates data server-side. This ensures high data integrity and avoids client-side ad-blocker interference.

All analytics endpoints are restricted to users with the `admin:store` permission via the `adminOnly` middleware.

### Dashboard Endpoint Definition

The core of the admin dashboard is the `GET /v1/analytics/dashboard` route. It consumes a `period` parameter to dynamically adjust SQL date filters using SQLite's native `datetime` functions.

```typescript
// apps/merchant/src/routes/analytics.ts
import { createRoute, z } from '@hono/zod-openapi';

export const getDashboardRoute = createRoute({
  method: 'get',
  path: '/dashboard',
  tags: ['Analytics'],
  summary: 'Aggregated store statistics',
  security: [{ bearerAuth: ['admin:store'] }],
  request: {
    query: z.object({
      period: z.enum(['7d', '30d', '90d', 'all']).optional().default('30d'),
    }),
  },
  responses: {
    200: {
      description: 'Dashboard statistics object',
      content: {
        'application/json': {
          schema: z.object({
            revenue: z.object({
              total_cents: z.number(),
              order_count: z.number(),
              avg_order_cents: z.number(),
            }),
            customers: z.object({
              total: z.number(),
              new: z.number(),
              returning: z.number(),
            }),
            top_products: z.array(z.object({
              product_id: z.string(),
              product_title: z.string(),
              units_sold: z.number(),
              revenue_cents: z.number(),
            })),
            low_stock_count: z.number(),
          }),
        },
      },
    },
  },
});
```

## Data Aggregation Logic

### Revenue Calculation
Revenue is calculated by joining the `orders` table with `order_items`. To ensure financial accuracy, the framework applies strict status filtering. Only orders that represent successful transactions are included.

**Verified Rule:** Orders with status `canceled` or `refunded` are strictly excluded from revenue totals.

```sql
-- Internal SQL representation for revenue aggregation
SELECT 
    COALESCE(SUM(oi.unit_price_cents * oi.quantity), 0) AS total_cents,
    COUNT(DISTINCT o.id) AS order_count
FROM orders o
JOIN order_items oi ON o.id = oi.order_id
WHERE o.status NOT IN ('canceled', 'refunded')
  AND o.created_at >= datetime('now', '-30 days');
```

The `low_stock_count` metric identifies products requiring immediate attention. This uses the `LOW_INVENTORY_THRESHOLD` (typically defined in the store configuration).

## Cache Performance Monitoring

Fufuni tracks the efficiency of its Cloudflare KV caching layer. This data is not stored in SQLite but in KV itself to minimize latency and avoid write-contention on the Durable Object.

### KV Cache Stats
The `kvCacheMiddleware` automatically increments counters in KV whenever a request is served or stored.

- **Hits Key:** `analytics:cache:hits`
- **Misses Key:** `analytics:cache:misses`

### Retrieval Endpoint
The `GET /v1/analytics/cache-stats` endpoint returns these real-time values, allowing admins to monitor the Hit Rate (%) and tune TTL (Time-To-Live) settings.

```typescript
// apps/merchant/src/routes/analytics.ts snippet
adminApp.openapi(getCacheStatsRoute, async (c) => {
  const hits = await c.env.KV.get('analytics:cache:hits').then(v => parseInt(v || '0'));
  const misses = await c.env.KV.get('analytics:cache:misses').then(v => parseInt(v || '0'));
  
  const total = hits + misses;
  const hit_rate = total === 0 ? 0 : (hits / total) * 100;

  return c.json({
    kv: { hits, misses, hit_rate },
    cdn: { /* metrics from Cloudflare logs if available */ }
  });
});
```

## Frontend Implementation

The frontend uses **TanStack Query (React Query)** to manage the lifecycle of analytics data. The UI is built using **HeroUI v3** components, focusing on clear data visualization without the overhead of heavy charting libraries.

### Dashboard Data Fetching
The page maintains a `period` state that, when changed, triggers a refetch of the dashboard data.

```tsx
// apps/client/src/pages/admin/analytics.tsx
import { useState } from "react";
import { useQuery } from "@tanstack/react-query";
import { Select, Card, Skeleton } from "@heroui/react";
import { useSecuredApi } from "@/authentication";

export default function AnalyticsPage() {
  const [period, setPeriod] = useState("30d");
  const { getJson } = useSecuredApi();

  const { data, isLoading } = useQuery({
    queryKey: ["analytics-dashboard", period],
    queryFn: () => getJson(`/v1/analytics/dashboard?period=${period}`),
  });

  if (isLoading) return <Skeleton className="rounded-lg h-64" />;

  return (
    <div className="grid grid-cols-1 md:grid-cols-3 gap-4">
      <Card className="p-4">
        <p className="text-sm text-default-500">Total Revenue</p>
        <p className="text-2xl font-bold">
          {formatMoney(data.revenue.total_cents)}
        </p>
      </Card>
      {/* Additional Stat Cards */}
    </div>
  );
}
```

## Extending Analytics

Adding a new metric (e.g., "Discount Code Usage") requires updates to both the Hono backend and the React frontend.

### 1. Update Backend SQL
Modify the dashboard route handler to include the new aggregation.

```typescript
// Inside adminApp.openapi(getDashboardRoute, ...)
const [discounts] = await db.query<{ count: number }>(
  `SELECT COUNT(*) as count 
   FROM orders 
   WHERE discount_code IS NOT NULL 
   AND created_at >= ${since}`
);

return c.json({
  // ... existing fields
  discounts_applied: discounts.count
});
```

### 2. Update Frontend Schema & UI
Update the TypeScript interface and add the display component.

```typescript
interface DashboardData {
  // ... existing fields
  discounts_applied: number;
}

// In the component JSX
<Card className="p-4">
  <p className="text-sm text-default-500">Vouchers Used</p>
  <p className="text-2xl font-bold">{data.discounts_applied}</p>
</Card>
```

### 3. Resetting Analytics
Since analytics are derived from primary data (Orders, Products), there is no "Reset" button for revenue or customer counts. However, Cache Stats can be reset by flushing the KV keys:

```bash
# Example using Wrangler CLI to reset hit counters
wrangler kv:key put --binding=KV "analytics:cache:hits" "0"
wrangler kv:key put --binding=KV "analytics:cache:misses" "0"
```

## Performance Considerations

Because Fufuni runs SQLite inside a Durable Object, aggregations on very large stores (100k+ orders) can impact the DO's response time since it is single-threaded. 

1.  **Indexing:** Ensure `orders.created_at` and `orders.status` are indexed.
2.  **Read-Only Replicas:** For massive datasets, consider offloading analytics queries to a D1 replica or a dedicated Analytics DO that receives events via a queue.
3.  **Memoization:** The `getDashboardRoute` does not use KV caching by default to ensure admins see real-time data. For high-traffic admin panels, consider a short (5-minute) cache.
