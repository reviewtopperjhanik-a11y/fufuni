## Analytics & Dashboard Architecture

The Fufuni framework provides a built-in analytics engine designed to work directly on the edge. Unlike traditional platforms that export data to external warehouses, Fufuni leverages the SQLite capabilities of Durable Objects to compute metrics in real-time. This ensures that the admin dashboard always reflects the current state of the store without synchronization delays or external API costs.

All analytics operations are restricted to administrative users via the `adminOnly` middleware and the `admin:store` scope.

## Dashboard API Endpoint

The primary data source for the admin interface is the `GET /v1/analytics/dashboard` endpoint. This route aggregates several data points into a single payload to minimize round-trips.

### Period Filtering
The endpoint accepts a `period` query parameter. Fufuni uses native SQLite date expressions to filter records, avoiding the overhead of heavy JavaScript date libraries.

```typescript

  const days = period === '7d' ? 7 : period === '30d' ? 30 : period === '90d' ? 90 : null;
  return days ? `datetime('now', '-${days} days')` : `'1970-01-01'`;
};
```

## Revenue and Financial Calculation

In Fufuni, revenue is calculated strictly from "realized" transactions. As per the framework's business logic, orders that are `canceled` or `refunded` are excluded from the primary revenue metrics to ensure financial accuracy for the merchant.

The engine joins the `orders` table with `order_items` to calculate the exact sum, ensuring that even if a base price changes in the product catalog, the historic price captured at the moment of sale in `order_items` is used.

```sql
-- Calculation of total revenue for a specific period
SELECT
  SUM(oi.unit_price_cents * oi.quantity) AS total_revenue_cents,
  COUNT(DISTINCT o.id) AS order_count,
  AVG(oi.unit_price_cents * oi.quantity) AS avg_order_value_cents
FROM orders o
JOIN order_items oi ON o.id = oi.order_id
WHERE o.status NOT IN ('canceled', 'refunded')
  AND o.created_at >= datetime('now', '-30 days');
```

## Cache Performance Monitoring

Fufuni tracks the efficiency of its edge caching layer through the `GET /v1/analytics/cache-stats` endpoint. This data is driven by the `kvCacheMiddleware`, which increments counters in Cloudflare KV every time a request is served or misses the cache.

### Tracked Metrics
The following keys are maintained in the KV namespace:
- `analytics:cache:hits`: Incremented on successful cache retrieval.
- `analytics:cache:misses`: Incremented when data must be fetched from the Durable Object.

```typescript
// Middleware implementation snippet
export const kvCacheMiddleware = async (c: Context, next: Next) => {
  const cacheKey = generateKey(c.req.url);
  const cached = await c.env.KV.get(cacheKey);

  if (cached) {
    await c.env.KV.prepare('INCR analytics:cache:hits').execute(); // Pseudo-code logic
    return c.json(JSON.parse(cached));
  }

  await next();

  if (c.res.status === 200) {
    await c.env.KV.prepare('INCR analytics:cache:misses').execute();
    const body = await c.res.clone().text();
    await c.env.KV.put(cacheKey, body, { expirationTtl: 3600 });
  }
};
```

## Frontend Implementation

The Admin Analytics page (`apps/client/src/pages/admin/analytics.tsx`) uses TanStack Query for state management and HeroUI for presentation.

### Data Fetching Pattern
The UI maintains a local state for the `period`, which triggers a refetch whenever the user changes the selection.

```typescript
import { useQuery } from "@tanstack/react-query";
import { useSecuredApi } from "@/authentication";
import { useState } from "react";

export function AnalyticsDashboard() {
  const [period, setPeriod] = useState<"7d" | "30d" | "90d" | "all">("30d");
  const { getJson } = useSecuredApi();

  const { data, isLoading } = useQuery({
    queryKey: ["analytics", period],
    queryFn: () => getJson(`/v1/analytics/dashboard?period=${period}`),
    // Refresh data more frequently for the dashboard
    refetchInterval: 300000, // 5 minutes
  });

  if (isLoading) return <Spinner />;

  return (
    <div>
      <PeriodSelector value={period} onChange={setPeriod} />
      <StatsGrid data={data} />
    </div>
  );
}
```

## How to Add a New Metric

Follow these steps to add a new metric, such as "Conversion Rate" or "Average Items Per Order."

### 1. Update the Backend SQL
Add the calculation to the `adminApp.openapi` handler in the analytics route.

```typescript
// In apps/merchant/src/routes/analytics.ts
const [basketStats] = await db.query<{ avg_items: number }>(`
  SELECT AVG(item_count) as avg_items
  FROM (
    SELECT order_id, SUM(quantity) as item_count
    FROM order_items
    GROUP BY order_id
  )
`);
```

### 2. Update the Zod Schema
Ensure the OpenAPI schema reflects the new field so the TypeScript types are updated for the frontend.

```typescript
// Update the 200 response schema
responses: {
  200: {
    content: {
      'application/json': {
        schema: z.object({
          // ... existing fields
          basket_metrics: z.object({
            avg_items_per_order: z.number(),
          }),
        }),
      },
    },
  },
}
```

### 3. Consume in Frontend
The `data` object in the React component will now contain the new field. Use a HeroUI `Card` to display it.

```tsx
<Card className="bg-default-50">
  <CardBody className="flex flex-row items-center gap-4">
    <div className="p-2 rounded-lg bg-primary/10">
      <Package className="text-primary" />
    </div>
    <div>
      <p className="text-small text-default-500">Avg. Items/Order</p>
      <p className="text-2xl font-bold">
        {data?.basket_metrics.avg_items_per_order.toFixed(1)}
      </p>
    </div>
  </CardBody>
</Card>
```
