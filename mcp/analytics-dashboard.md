## Analytics API Architecture

Fufuni provides a built-in analytics engine that computes store performance metrics directly from the SQLite database stored in Cloudflare Durable Objects. Unlike traditional e-commerce platforms that rely on external trackers (like Segment or Google Analytics), Fufuni aggregates transactional data on-demand. This ensures 100% data accuracy and privacy compliance.

All analytics endpoints are located under the `/v1/analytics` prefix and are protected by the `adminOnly` middleware.

```typescript
// apps/merchant/src/routes/analytics.ts
import { OpenAPIHono, createRoute, z } from '@hono/zod-openapi';
import { authMiddleware, adminOnly } from '../middleware/auth';
import { type HonoEnv } from '../types';

const analyticsRouter = new OpenAPIHono<HonoEnv>();

// Global middleware for all analytics routes
analyticsRouter.use('*', authMiddleware);
analyticsRouter.use('*', adminOnly);

// Common query parameters for all analytics endpoints
export const AnalyticsQuerySchema = z.object({
  from: z.string().datetime().optional().openapi({ example: '2024-01-01T00:00:00Z' }),
  to: z.string().datetime().optional().openapi({ example: '2024-01-31T23:59:59Z' }),
  currency: z.string().length(3).optional().default('EUR').openapi({ example: 'USD' }),
});

export type AnalyticsQuery = z.infer<typeof AnalyticsQuerySchema>;
```

### Date and Currency Handling

Fufuni treats the `from` and `to` parameters as strict ISO-8601 timestamps. If omitted, the backend defaults to the last 30 days. Because Fufuni supports multi-currency stores, all analytics endpoints accept a `currency` parameter. 

**Critical Fact:** All monetary values in responses are returned as integers in the smallest unit (e.g., cents for EUR/USD). The backend handles conversion using internal exchange rates if the stored order currency differs from the requested analytics currency.

```typescript
// Example of date range computation in SQL
const resolveRange = (query: AnalyticsQuery) => {
  const toDate = query.to ? query.to : new Date().toISOString();
  const fromDate = query.from ? query.from : new Date(Date.now() - 30 * 24 * 60 * 60 * 1000).toISOString();
  return { fromDate, toDate };
};

// SQL usage example
// SELECT SUM(total_cents) FROM orders WHERE created_at BETWEEN ? AND ?
```

## Order Lifecycle and Status Distribution

The `/v1/analytics/orders` endpoint tracks how orders move through the fulfillment funnel. This is essential for identifying bottlenecks in operations.

### GET /v1/analytics/orders
This endpoint returns counts categorized by status and the Average Order Value (AOV).

```typescript
const OrdersResponseSchema = z.object({
  total: z.number(),
  avgOrderValue: z.number().describe("In cents"),
  byStatus: z.object({
    pending: z.number(),
    paid: z.number(),
    processing: z.number(),
    shipped: z.number(),
    delivered: z.number(),
    cancelled: z.number(),
    refunded: z.number(),
  })

```

The `avgOrderValue` is calculated by taking the sum of `total_cents` for all orders (excluding `cancelled`) and dividing by the order count within the requested time range.

## Customer Insights and Retention

Customer metrics help merchants understand if they are growing their base or relying on loyal repeat buyers.

### GET /v1/analytics/customers
This endpoint calculates new customer acquisition versus retention.

- **total**: Total unique customers in the store's history.
- **newInPeriod**: Customers whose first order was placed within the requested range.
- **returningRate**: The percentage of customers in the current period who had already placed at least one order before the `from` date.

```typescript
// SQL Logic for returningRate:
// 1. Get IDs of customers who ordered in current period
// 2. Count how many of those IDs exist in orders WHERE created_at < period.from
const customerStats = await db.query(`
  WITH current_customers AS (
    SELECT DISTINCT customer_id FROM orders WHERE created_at BETWEEN ? AND ?
  )
  SELECT 
    (SELECT COUNT(*) FROM customers) as total,
    (SELECT COUNT(*) FROM current_customers) as active_in_period,
    (SELECT COUNT(*) FROM current_customers WHERE customer_id IN (
        SELECT customer_id FROM orders WHERE created_at < ?
    )) as returning_count
`, [from, to, from]);
```

## Checkout Funnel and Conversion

The funnel represents the "happy path" of a user session. Fufuni tracks specific lifecycle events to compute conversion rates.

### GET /v1/analytics/funnel
Returns step-by-step drop-off data.

1.  **cartCreated**: Total number of unique carts initialized.
2.  **checkoutStarted**: Carts where a shipping address or email was entered.
3.  **checkoutCompleted**: Carts that successfully transitioned to a "paid" order.
4.  **conversionRate**: `checkoutCompleted / cartCreated`.

```typescript
const FunnelSchema = z.object({
  cartCreated: z.number(),
  checkoutStarted: z.number(),
  checkoutCompleted: z.number(),
  conversionRate: z.number().max(1).min(0)
});
```

## Frontend Implementation with HeroUI and Recharts

The Fufuni admin panel uses **React 19**, **TanStack Query (v5)**, and **Recharts** to visualize this data. Components should use the `useSecuredApi` hook to ensure requests include the necessary admin Bearer token.

```tsx
import { useQuery } from "@tanstack/react-query";
import { LineChart, Line, XAxis, YAxis, CartesianGrid, Tooltip, ResponsiveContainer } from 'recharts';
import { Card, CardBody, Select, SelectItem } from "@heroui/react";
import { useSecuredApi } from "@/authentication";
import { formatMoney } from "@/utils/currency";

export function RevenueChart({ period }: { period: string }) {
  const { getJson } = useSecuredApi();
  
  const { data, isLoading } = useQuery({
    queryKey: ['analytics', 'revenue', period],
    queryFn: () => getJson(`/v1/analytics/revenue?period=${period}`)
  });

  if (isLoading) return <div>Loading...</div>;

  return (
    <Card className="w-full h-[400px]">
      <CardBody>
        <ResponsiveContainer width="100%" height="100%">
          <LineChart data={data.byDay}>
            <CartesianGrid strokeDasharray="3 3" />
            <XAxis dataKey="date" />
            <YAxis tickFormatter={(val) => formatMoney(val, 'EUR')} />
            <Tooltip formatter={(val: number) => formatMoney(val, 'EUR')} />
            <Line type="monotone" dataKey="amount" stroke="#0070f3" strokeWidth={2} />
          </LineChart>
        </ResponsiveContainer>
      </CardBody>
    </Card>
  );
}
```

## Performance and Indexing Recommendations

Since Fufuni does not pre-aggregate data (it computes metrics on-the-fly to allow arbitrary date ranges), query performance is directly tied to SQLite indexing. As a store grows beyond 10,000 orders, you must ensure the following indexes are present in the Durable Object SQLite database.

### Required Indexes

To maintain sub-second analytics responses, the following indexes are mandatory for high-volume merchants:

```sql
-- Speed up date range filtering on orders
CREATE INDEX IF NOT EXISTS idx_orders_created_at ON orders(created_at);

-- Speed up status distribution and funnel queries
CREATE INDEX IF NOT EXISTS idx_orders_status ON orders(status);

-- Speed up product ranking queries (Join optimization)
CREATE INDEX IF NOT EXISTS idx_order_items_product_id ON order_items(product_id);
CREATE INDEX IF NOT EXISTS idx_order_items_order_id ON order_items(order_id);

-- Speed up customer retention queries
CREATE INDEX IF NOT EXISTS idx_orders_customer_id ON orders(customer_id);
```

### Cache Headers
The API implementation in `analytics.ts` should ideally include `Cache-Control: private, max-age=60` for dashboard endpoints. This prevents redundant re-computations when an administrator refreshes the page frequently or toggles between tabs, while ensuring data remains fresh within a 60-second window.
