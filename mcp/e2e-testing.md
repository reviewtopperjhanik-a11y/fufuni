## Project Structure and Architecture

The Fufuni E2E suite is located in the `e2e/` directory of the monorepo root. It is designed to validate the full integration between the React frontend and the Cloudflare Workers backend, including authentication flows and administrative CRUD operations.

```bash
e2e/
├── fixtures/               # Generated JSON files storing browser state (tokens, cookies)
│   ├── storage-state-user.json
│   └── storage-state-admin.json
├── tests/
│   ├── setup/             # Automation scripts to perform login and save state
│   │   ├── user.setup.ts
│   │   └── admin.setup.ts
│   ├── public/            # Tests requiring no authentication (SEO, Nav, Product Display)
│   ├── auth/              # Tests for logged-in customers (Checkout, Profile)
│   └── admin/             # Tests for store administrators (CRUD, Dashboard)
├── playwright.config.ts    # Main configuration
└── package.json
```

The framework utilizes Playwright's **Storage State** feature. Instead of logging in before every individual test, the `setup` projects run once, authenticate against Auth0's Universal Login page, and save the session to a JSON fixture. Subsequent tests simply load this state to start as an already authenticated user.

## Running E2E Tests

To run the tests locally, you must have the development environment fully operational (both the Hono backend and the Vite frontend).

### Prerequisites
- Backend running: `wrangler dev` (usually on port 8787)
- Frontend running: `npm run dev` (usually on port 5173)
- Environment variables configured in the root `.env` file.

### Commands
```bash
# From the monorepo root
# 1. Install browser binaries (first time only)
npx playwright install --with-deps

# 2. Execute all tests
npm run e2e

# 3. Execute tests with the UI runner (recommended for debugging)
npx playwright test --ui

# 4. Run a specific category
npx playwright test e2e/tests/admin/
```

## Authentication Setup and Credentials

Fufuni uses three distinct authentication states. These are managed via `playwright.config.ts` projects that define dependencies.

| State | Project | Fixture File | Target |
| :--- | :--- | :--- | :--- |
| **Anonymous** | `public-*` | N/A | Browsing, Product viewing, Static pages |
| **Standard User**| `auth-user` | `storage-state-user.json` | Cart, Checkout, Order history |
| **Administrator**| `auth-admin`| `storage-state-admin.json`| Category/Product CRUD, Settings |

### Auth0 Automation Logic
The setup scripts (`user.setup.ts` and `admin.setup.ts`) use the following environment variables (which must be present in your root `.env` but never committed):
- `E2E_USER_EMAIL` / `E2E_USER_PASSWORD`
- `E2E_ADMIN_EMAIL` / `E2E_ADMIN_PASSWORD`

The setup scripts navigate to the Auth0 hosted login page, perform `page.fill()` on the email and password fields, and wait for the redirection back to the Fufuni SPA before saving the state.

```typescript
// Example logic used in a typical setup (simplified)
import { test as setup } from "@playwright/test";

setup("authenticate as admin", async ({ page }) => {
  await page.goto("/");
  // Click login button in Navbar
  await page.getByRole("button", { name: /connexion|login/i }).click();
  
  // Interact with Auth0 Universal Login
  await page.waitForSelector('input[name="username"]');
  await page.fill('input[name="username"]', process.env.E2E_ADMIN_EMAIL!);
  await page.fill('input[name="password"]', process.env.E2E_ADMIN_PASSWORD!);
  await page.click('button[type="submit"]');

  // Verify we are back on the app
  await page.waitForURL("**/admin/**");
  
  // Save state for future tests
  await page.context().storageState({ path: "e2e/fixtures/storage-state-admin.json" });
});
```

## Writing New Specs

When adding a new test file, you must determine which project it belongs to based on the required permissions.

### Selecting Storage State
To use a specific authentication level, use the `test.use` configuration at the top of your spec file or place the file in a directory matched by a specific project in `playwright.config.ts`.

```typescript
import { test, expect } from "@playwright/test";

// Force a specific storage state if not using the default project matchers
test.use({ storageState: "e2e/fixtures/storage-state-user.json" });

test("User can access profile", async ({ page }) => {
  await page.goto("/profile");
  await expect(page.getByRole("heading", { name: /mon compte/i })).toBeVisible();
});
```

### Selector Strategy (ARIA-first)
Fufuni uses **HeroUI** (Tailwind-based components). Selectors should prioritize ARIA roles and labels to ensure tests are resilient to DOM structure changes and accessible.

1. **Roles**: `page.getByRole('button', { name: 'Save' })`
2. **Placeholders**: `page.getByPlaceholder('t-shirts')`
3. **Alt Text**: `page.getByAltText('Product Image')`
4. **Locators**: Use `data-slot` or `title` only when ARIA labels are missing.

### Helper: Dismissing Cookie Banners
Because Fufuni shows a cookie consent modal on first load, use a helper to prevent click interceptions.

```typescript
async function dismissCookieBanner(page: import("@playwright/test").Page) {
  const acceptBtn = page.getByRole("button", { name: /accept all|tout accepter/i });
  if (await acceptBtn.isVisible({ timeout: 3000 }).catch(() => false)) {
    await acceptBtn.click();
    // Wait for the HeroUI modal backdrop to disappear
    await page.locator('[data-slot="modal-backdrop"]').waitFor({ state: "hidden" });
  }
}
```

## Category Conventions

### Public Tests
These validate the storefront visibility and API health. They should check that critical Worker endpoints (like `.well-known/ucp`) are reachable and returning valid JSON.

### Auth Tests (Checkout Flow)
The checkout flow in Fufuni is a **redirection-based system** (Stripe Checkout).
- **Redirection**: Verify that clicking "Commander" (Checkout) redirects the browser to `checkout.stripe.com`.
- **Note**: You cannot fill card details on the Stripe domain easily due to security frames. To test the "Success" state, navigate directly to `/success` or use Stripe CLI to trigger webhooks.

### Admin Tests (CRUD Discipline)
Admin tests must be self-contained and leave the database in a clean state. Use unique handles with timestamps to avoid collisions.

```typescript
test.describe("Admin Categories", () => {
  const UNIQUE_ID = `test-cat-${Date.now()}`;

  test("should create and then delete a category", async ({ page }) => {
    await page.goto("/admin/categories");
    
    // Create
    await page.getByRole("button", { name: /créer/i }).click();
    await page.locator('input[placeholder="t-shirts"]').fill(UNIQUE_ID);
    await page.locator('button').filter({ hasText: /^create$/i }).click({ force: true });
    
    // Verify
    await expect(page.getByRole("rowheader", { name: UNIQUE_ID })).toBeVisible();

    // Delete (Cleanup)
    const row = page.getByRole("row").filter({ hasText: UNIQUE_ID });
    await row.locator('[title="Supprimer"] button').click();
    await page.getByRole("button", { name: /confirmer/i }).click();
    
    await expect(page.getByRole("rowheader", { name: UNIQUE_ID })).not.toBeVisible();
  });
});
```

## Cleanup Discipline

Since Fufuni uses SQLite inside Durable Objects for the backend, tests run against real data. If a test fails before it can delete its test data, it might pollute subsequent runs.
- Always use `test.afterAll()` or `test.afterEach()` for critical cleanup if the flow is complex.
- Use unique strings (e.g., `playwright-tmp-...`) so that an automated maintenance task can periodically purge abandoned test entries from the database.

## CI Integration

In GitHub Actions, E2E tests are executed as part of the `test.yml` workflow.

### Environment Variables in CI
The CI environment injects specific variables to override local defaults:
- `PLAYWRIGHT_BASE_URL`: The URL of the deployed staging environment (e.g., GitHub Pages).
- `PLAYWRIGHT_API_BASE_URL`: The URL of the preview Worker.
- `PLAYWRIGHT_ENV`: Set to `ci`.

### Failure Artifacts
When a test fails in CI:
1. **HTML Report**: A full report is generated.
2. **Screenshots**: Captured at the exact moment of failure.
3. **Trace**: A `.zip` file containing a step-by-step recording of the browser execution, viewable at `trace.playwright.dev`.

```yaml
# Simplified GitHub Action step
- name: Run Playwright tests
  run: npx playwright test
  env:
    E2E_ADMIN_EMAIL: ${{ secrets.E2E_ADMIN_EMAIL }}
    E2E_ADMIN_PASSWORD: ${{ secrets.E2E_ADMIN_PASSWORD }}
    PLAYWRIGHT_BASE_URL: ${{ steps.deployment.outputs.page_url }}
```

### Static Page Access Verification
A standard requirement for every PR is to ensure static pages (Terms of Service, Privacy Policy) remain accessible and don't return 404 or generic error templates.

```typescript
test("Verify all static legal routes", async ({ page }) => {
  const routes = ["/pages/about", "/pages/privacy-policy", "/pages/terms-of-service"];
  for (const route of routes) {
    const response = await page.goto(route);
    expect(response?.status()).toBe(200);
    await expect(page.getByRole("main")).toBeVisible();
    await expect(page).not.toHaveURL(/error/i);
  }
});
```
