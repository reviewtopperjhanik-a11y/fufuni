## E2E Project Architecture

Fufuni uses Playwright for comprehensive end-to-end testing, covering the React frontend, the Cloudflare Worker backend, and the integration with external services like Auth0 and Stripe. The tests are located in the `e2e/` directory and are organized by user permission levels.

### Folder Structure

```text
e2e/
├── fixtures/               # Exported storage states (JSON)
├── tests/
│   ├── admin/             # Admin-only features (CRUD, settings)
│   ├── auth/              # Authenticated user features (Checkout, Profile)
│   ├── public/            # Anonymous navigation and SEO
│   └── setup/             # Global setup (Auth0 login flows)
├── playwright.config.ts    # Main configuration
└── package.json           # E2E specific dependencies
```

### The Three Auth States

Fufuni tests revolve around three distinct authentication states defined in `playwright.config.ts` and managed via `storageState`:

1.  **Anonymous**: Default state. No session data. Used for `public/` tests.
2.  **Standard User**: Session for a registered customer. Used for `auth/` tests.
3.  **Admin User**: Session for a user with `admin` permissions. Used for `admin/` tests.

```typescript
// Example from playwright.config.ts showing project-based auth
{
  name: "auth-admin",
  use: {
    ...devices["Desktop Chrome"],
    // Automatically injects admin session cookies and localStorage
    storageState: "./fixtures/storage-state-admin.json",
  },
  testMatch: "**/admin/**/*.spec.ts",
  dependencies: ["setup-admin"], // Ensures setup-admin runs first
}
```

## Prerequisites and Running Tests

To run the E2E suite, you must have the local development environment running. This includes the Vite dev server (frontend) and the Wrangler dev server (worker/SQLite).

### Required Environment Variables

Create a `.env` file in the root directory (not committed) with the following credentials. These are used by the setup scripts to perform real Auth0 login:

```bash
E2E_USER_EMAIL=customer@example.com
E2E_USER_PASSWORD=YourPassword123
E2E_ADMIN_EMAIL=admin@example.com
E2E_ADMIN_PASSWORD=AdminPassword123
VITE_APP_URL=http://localhost:5173
PLAYWRIGHT_API_BASE_URL=http://localhost:8787
```

### Execution Commands

Run these commands from the **monorepo root**:

```bash
# Run all tests in headless mode
npm run e2e

# Run tests with the Playwright UI (highly recommended for debugging)
npx playwright test --ui

# Run only a specific category (e.g., admin)
npx playwright test tests/admin
```

## Authentication Setup Logic

Fufuni uses `setup` projects in Playwright to automate the acquisition of authentication tokens. The setup scripts (`setup-user` and `setup-admin`) navigate to the Auth0 Universal Login page, fill in the credentials from environment variables, and save the resulting browser state to `e2e/fixtures/`.

### Validation of Auth State

Before running tests, the setup scripts validate that the session is correctly persisted in `localStorage` under the Auth0 key.

```typescript
import { test as setup, expect } from "@playwright/test";
import * as fs from "fs";
import * as path from "path";

const FIXTURE_PATH = path.join(__dirname, "../../fixtures/storage-state-user.json");

setup("authenticate as standard user", async ({ page }) => {
  // If your setup performs manual login:
  await page.goto("/");
  await page.getByRole("button", { name: /connexion|login/i }).click();
  
  // Auth0 Universal Login interaction
  await page.fill('input[name="username"]', process.env.E2E_USER_EMAIL!);
  await page.fill('input[name="password"]', process.env.E2E_USER_PASSWORD!);
  await page.click('button[type="submit"]');

  // Verify we are back on Fufuni and logged in
  await expect(page.getByRole("button", { name: /mon compte|my account/i })).toBeVisible();

  // Save the state for subsequent tests
  await page.context().storageState({ path: FIXTURE_PATH });
});
```

## Writing New Specs

When adding a new test file, choose the appropriate category folder to automatically inherit the correct `storageState`. Use an **ARIA-first** selector strategy to ensure tests are resilient to UI changes.

### Best Practices for Selectors

*   **Prefer Roles**: `page.getByRole('button', { name: 'Submit' })`
*   **Use I18n Patterns**: Since Fufuni is multilingual, use regex for text: `/ajouter au panier|add to cart/i`.
*   **Target HeroUI Slots**: For complex components, use data-slots: `page.locator('[data-slot="modal-backdrop"]')`.

### Template for a New Spec

```typescript
import { test, expect } from "@playwright/test";

test.describe("Profile Management", () => {
  // This test will use the storageState defined in the Playwright project (e.g., auth-user)
  
  test.beforeEach(async ({ page }) => {
    await page.goto("/profile");
  });

  test("User can update their display name", async ({ page }) => {
    const nameInput = page.getByLabel(/nom d'affichage|display name/i);
    await nameInput.fill("New Playwright Name");
    
    await page.getByRole("button", { name: /sauvegarder|save/i }).click();
    
    // Check for success notification (HeroUI Toast/Alert)
    await expect(page.getByText(/profil mis à jour|profile updated/i)).toBeVisible();
    await expect(nameInput).toHaveValue("New Playwright Name");
  });
});
```

## Admin CRUD and Cleanup Discipline

Admin tests often modify the database (D1/SQLite). To keep the environment stable, every test that creates a resource must delete it. Use unique handles (e.g., timestamps) to prevent collisions during parallel execution.

### The Create-Delete Pattern

```typescript
const TEST_ID = `test-cat-${Date.now()}`;

test.describe("Admin Categories CRUD", () => {
  test("Full lifecycle: Create, Verify, and Delete", async ({ page }) => {
    await page.goto("/admin/categories");

    // 1. Create
    await page.getByRole("button", { name: /créer une catégorie/i }).click();
    await page.locator('input[placeholder="t-shirts"]').fill(TEST_ID);
    await page.locator('button').filter({ hasText: /^create$/i }).click({ force: true });

    // 2. Verify visibility in the HeroUI Table
    await page.reload(); // Bypass KV cache
    const row = page.getByRole("row").filter({ hasText: TEST_ID });
    await expect(row).toBeVisible();

    // 3. Cleanup: Delete the record
    // Target the delete button within the specific row
    await row.locator('[title="Supprimer"] button, [title="Delete"] button').click();
    
    // Confirm in the AlertDialog
    const confirmBtn = page.getByRole("button", { name: /supprimer|delete/i }).last();
    await confirmBtn.click();

    // 4. Final verification
    await page.reload();
    await expect(page.getByText(TEST_ID)).not.toBeVisible();
  });
});
```

## Testing the Worker API Directly

Playwright isn't just for browser automation. You can use `playwrightRequest` to test the Hono backend endpoints directly, ensuring Zod-OpenAPI validations and security headers are working.

```typescript
import { test, expect, request as playwrightRequest } from "@playwright/test";

const API_URL = process.env.PLAYWRIGHT_API_BASE_URL ?? "http://localhost:8787";

test("Worker API Security: /ucp/v1/checkout-sessions requires auth", async () => {
  const apiContext = await playwrightRequest.newContext({ baseURL: API_URL });
  
  // Attempting to post without an Authorization header
  const resp = await apiContext.post("/ucp/v1/checkout-sessions", {
    data: { items: [] }
  });

  // Should return 401 Unauthorized or 400 if validation fails first
  expect([400, 401]).toContain(resp.status());
  
  await apiContext.dispose();
});
```

## CI Integration

In the GitHub Actions CI pipeline, E2E tests run after the build and deployment to a preview environment (or against the dev servers).

*   **Reporters**: CI uses the `github` and `list` reporters.
*   **Artifacts**: Screenshots and videos are only retained on failure to save space and time.
*   **Workers**: CI is limited to 2 parallel workers to prevent overloading the Cloudflare Workers dev environment.

### Environment Variable Injection in CI

In your `.github/workflows/e2e.yml`, secrets must be mapped to environment variables:

```yaml
- name: Run Playwright tests
  run: npm run e2e
  env:
    E2E_ADMIN_EMAIL: ${{ secrets.E2E_ADMIN_EMAIL }}
    E2E_ADMIN_PASSWORD: ${{ secrets.E2E_ADMIN_PASSWORD }}
    PLAYWRIGHT_BASE_URL: ${{ steps.deployment.outputs.url }}
```

### Stripe Redirection Note

As Fufuni uses Stripe Checkout (hosted), the E2E tests can only verify that the user is redirected to `checkout.stripe.com`. You cannot fill in credit card details within the Stripe domain during automated tests. To verify the full flow (success/failure), use the Stripe CLI to trigger webhooks:

```bash
stripe trigger checkout.session.completed
```

Inside Playwright, simply verify the redirection:

```typescript
await page.getByRole("button", { name: /commander|checkout/i }).click();
await expect(page).toHaveURL(/checkout\.stripe\.com|pay\.stripe\.com/, { timeout: 15000 });
```
