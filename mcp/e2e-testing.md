## Project Layout and Test Orchestration

The Fufuni E2E suite is located in the `e2e/` directory, separate from the application source code to ensure a clean boundary between the testing infrastructure and the production code. The configuration in `e2e/playwright.config.ts` defines several projects that target different user roles and environments.

### Directory Structure

- `e2e/tests/public/`: Tests for unauthenticated users (navigation, static pages).
- `e2e/tests/auth/`: Tests for registered customers (checkout, profile).
- `e2e/tests/admin/`: Tests for staff members (CRUD operations, dashboard).
- `e2e/tests/setup/`: Validation scripts for authentication fixtures.
- `e2e/fixtures/`: Storage state JSON files containing Auth0 session tokens.

### Project Configuration

The framework uses a dependency-based execution model. Authenticated tests (e.g., `auth-admin`) depend on a setup project (`setup-admin`) that verifies the existence and validity of a session fixture.

```typescript
// e2e/playwright.config.ts snippet
export default defineConfig({
  projects: [
    {
      name: "public-chromium",
      use: { ...devices["Desktop Chrome"] },
      testMatch: "**/public/**/*.spec.ts",
    },
    {
      name: "public-mobile",
      // Important: postinstall only installs chromium/firefox. 
      // We override iPhone 14 to use chromium.
      use: { ...devices["iPhone 14"], defaultBrowserType: "chromium" },
      testMatch: "**/public/**/*.spec.ts",
    },
    {
      name: "auth-admin",
      use: {
        ...devices["Desktop Chrome"],
        storageState: "./fixtures/storage-state-admin.json",
      },
      testMatch: "**/admin/**/*.spec.ts",
      dependencies: ["setup-admin"],
    },
    {
      name: "setup-admin",
      testMatch: "**/setup/admin.setup.ts",
    },
  ],
});
```

## Authentication and Storage State Fixtures

Fufuni does not perform a browser-based login flow (entering credentials) during E2E runs to avoid Auth0 rate-limiting and flakiness. Instead, we use **Storage State Fixtures**.

### Exporting a Session

1. Run the application locally or access the development environment.
2. Log in manually as the desired user (Standard or Admin).
3. Open the **UserTechnicalInfoModal** (usually accessible via a debug shortcut or the user profile menu in dev builds).
4. Use the "Export Playwright Session" feature.
5. Save the resulting JSON file into `e2e/fixtures/storage-state-user.json` or `e2e/fixtures/storage-state-admin.json`.

### Validating Fixtures

The setup projects ensure that these files are present and contain the required Auth0 keys before running the actual test logic.

```typescript
// e2e/tests/setup/admin.setup.ts
import { test as setup, expect } from "@playwright/test";
import * as fs from "fs";
import * as path from "path";

const FIXTURE_PATH = path.join(__dirname, "../../fixtures/storage-state-admin.json");

setup("validate admin storage state exists", async () => {
  const exists = fs.existsSync(FIXTURE_PATH);
  if (!exists) {
    throw new Error(`Fixture missing: ${FIXTURE_PATH}. Export it from the UserTechnicalInfoModal.`);
  }

  const state = JSON.parse(fs.readFileSync(FIXTURE_PATH, "utf-8"));
  // Ensure the Auth0 SPA SDK key exists in localStorage
  const hasAuthToken = state.origins[0].localStorage.some(
    (e: { name: string }) => e.name.startsWith("@@auth0spajs@@")
  );
  expect(hasAuthToken).toBe(true);
});
```

## Selector Strategy and Resilience

Fufuni uses **HeroUI v3**, which generates complex DOM structures. To write resilient tests, follow the ARIA-first strategy combined with bilingual support.

### Bilingual Selectors

The application supports multiple languages. Even though Playwright is configured for `fr-FR`, the application might render in English depending on user preferences or environment defaults. Always use case-insensitive regex for text-based selectors.

```typescript
// Good: Handles both languages and case sensitivity
await page.getByRole("button", { name: /ajouter au panier|add to cart/i }).click();

// Bad: Brittle if language changes
await page.getByText("Ajouter au panier").click();
```

### HeroUI Table Roles

In HeroUI tables (used extensively in the Admin panel), columns have specific ARIA roles:
- The primary identifying column (e.g., Category Name) uses `role="rowheader"`.
- Secondary columns (e.g., Handle, Price) use `role="gridcell"`.

```typescript
// Targeting a specific row by its category name
const categoryRow = page.getByRole("row").filter({ 
  has: page.getByRole("rowheader", { name: /T-Shirts/i }) 
});

// Targeting an action button within that row
// Note: Icons are often wrapped in divs with 'title' instead of aria-labels
await categoryRow.locator('[title="Delete"] button, [title="Supprimer"] button').click();
```

### Exact Matches with CSS Attributes

When filling forms, `getByPlaceholder` can be ambiguous if multiple fields share similar text. Use CSS attribute selectors for exact, case-sensitive targeting.

```typescript
// Precise targeting for category creation
await page.locator('input[placeholder="t-shirts"]').fill("my-handle"); // Handle field
await page.locator('input[placeholder="T-Shirts"]').fill("My Category"); // Name field
```

## Handling Interaction Blockers

Two components frequently block interactions by rendering backdrops: the **Cookie Consent Banner** and the **Cart Drawer**.

### The Cookie Banner

This modal blocks all pointers on the first visit. You must dismiss it before performing any actions.

```typescript
async function dismissCookieBanner(page: import("@playwright/test").Page) {
  const acceptBtn = page.getByRole("button", { name: /accept all|tout accepter/i });
  if (await acceptBtn.isVisible({ timeout: 3000 }).catch(() => false)) {
    await acceptBtn.click();
    // Wait for the HeroUI backdrop to disappear to avoid "element intercepted" errors
    await page.locator('[data-slot="modal-backdrop"]').waitFor({ state: "hidden" });
  }
}
```

### The Cart Drawer

When an item is added to the cart, the drawer opens automatically. To continue navigating or to click the cart icon again, you must close it.

```typescript
// Add to cart
await page.getByRole("button", { name: /add to cart/i }).first().click();

// Close the drawer using the Escape key
await page.keyboard.press("Escape");
await page.locator('[data-slot="drawer-backdrop"]').waitFor({ state: "hidden" });

// Now we can safely click the Cart icon in the navbar
await page.getByRole("button", { name: /open cart/i }).click();
```

## Admin CRUD and the KV Cache Caveat

The Fufuni backend uses Cloudflare KV for caching category and product lists. When a test creates or deletes a resource, the cache might remain stale for a few seconds, even if the Worker database is updated.

### Cache Invalidation Strategy

After a mutation (POST/PUT/DELETE), use `page.reload()` to ensure the frontend fetches fresh data. React Query's `invalidateQueries` might still receive a `X-KV-Cache: HIT` header from the Cloudflare edge if the refresh happens too quickly.

```typescript
test("Create and verify category", async ({ page }) => {
  await page.goto("/admin/categories");
  
  // ... perform creation steps ...
  await page.locator('button').filter({ hasText: /^create$/i }).click({ force: true });

  // Reload is necessary to bypass potential KV Cache stale hits
  await page.reload();
  await page.waitForLoadState("networkidle");

  // Assert existence
  await expect(page.getByRole("rowheader", { name: /New Category/ })).toBeVisible();
});
```

*Note: Use `force: true` on HeroUI modal buttons because the disappearing backdrop animation often intercepts clicks during the millisecond the modal starts closing.*

## Stripe Checkout Flow

Fufuni uses **Stripe Checkout (Hosted)**. When a user clicks "Commander", the backend generates a session and redirects the entire browser to `checkout.stripe.com`.

### Testing Redirections

Since the checkout happens on a third-party domain, Fufuni E2E tests focus on verifying the redirection rather than filling credit card details.

```typescript
test("Checkout redirects to Stripe", async ({ page }) => {
  await page.getByRole("button", { name: /ouvrir le panier/i }).click();
  await page.getByRole("button", { name: /commander/i }).click();

  // The worker performs a 303 redirect
  const isStripe = await page.waitForURL(/checkout\.stripe\.com|pay\.stripe\.com/, { timeout: 15000 })
    .then(() => true)
    .catch(() => false);

  if (!isStripe) {
    test.skip(true, "Stripe not configured - skipping external redirect test");
  }
  
  expect(page.url()).toContain("stripe.com");
});
```

## Creating a New Spec File

When adding a new test file, choose the correct directory based on the required permissions:

1.  **Public (`tests/public/`)**: No setup required.
2.  **User (`tests/auth/`)**: Uses `storage-state-user.json`. Suitable for testing the cart, orders, and profile.
3.  **Admin (`tests/admin/`)**: Uses `storage-state-admin.json`. Suitable for catalog management.

Example of a new admin test file:

```typescript
import { test, expect } from "@playwright/test";

test.describe("Admin - Product Management", () => {
  test.beforeEach(async ({ page }) => {
    await page.goto("/admin/products");
    // Always dismiss the cookie banner on first navigation in a spec
    const acceptBtn = page.getByRole("button", { name: /tout accepter/i });
    if (await acceptBtn.isVisible()) await acceptBtn.click();
  });

  test("should display product list", async ({ page }) => {
    // HeroUI tables use the 'grid' role
    await expect(page.getByRole("grid")).toBeVisible();
    const rows = page.getByRole("row");
    expect(await rows.count()).toBeGreaterThan(0);
  });
});
```
