## Project Architecture and Structure

The Fufuni E2E suite is located in the `e2e/` directory of the monorepo. It leverages Playwright's "Projects" feature to isolate tests based on user permissions and environment requirements.

```text
e2e/
├── fixtures/               # JSON files containing localStorage/cookies for auth
├── tests/
│   ├── public/             # Anonymous tests (Landing, SEO, Static pages)
│   ├── auth/               # Authenticated user tests (Cart, Checkout, Profile)
│   ├── admin/              # Admin-only tests (Product/Category CRUD)
│   └── setup/              # Authentication scripts (Auth0 login automation)
├── playwright.config.ts    # Main configuration
└── package.json            # Local scripts for the E2E workspace
```

The framework manages three distinct authentication states:
1.  **Anonymous**: Default state (no storage state applied).
2.  **Standard User**: Session stored in `e2e/fixtures/storage-state-user.json`.
3.  **Administrator**: Session stored in `e2e/fixtures/storage-state-admin.json`.

## Running E2E Tests

To run the tests, you must have the backend (Wrangler/Durable Objects) and the frontend (Vite) running locally.

### Prerequisites
- **Dev Server**: `npm run dev` in the root.
- **Environment Variables**: A `.env` file in the root containing:
  - `E2E_USER_EMAIL` / `E2E_USER_PASSWORD`
  - `E2E_ADMIN_EMAIL` / `E2E_ADMIN_PASSWORD`

### Execution Commands
```bash
# Run all tests (Public, User, Admin)
npm run e2e

# Run only public navigation tests
npx playwright test tests/public/

# Run tests in UI mode (Interactive)
npx playwright test --ui

# Run tests for a specific project (e.g., admin)
npx playwright test --project=auth-admin
```

## Authentication Strategy and Setup

Fufuni uses Auth0 Universal Login. Instead of manually logging in before every test, Playwright runs "Setup Projects" once per suite execution. These scripts perform the real browser-based login on the Auth0 hosted page and save the resulting session to the `fixtures/` folder.

### Configuration in `playwright.config.ts`
The configuration maps test folders to specific storage states and defines dependencies so that setup runs before the tests.

```typescript
// playwright.config.ts snippet
projects: [
  {
    name: 'setup-admin',
    testMatch: '**/setup/admin.setup.ts',
  },
  {
    name: 'auth-admin',
    use: {
      storageState: './fixtures/storage-state-admin.json',
    },
    testMatch: '**/admin/**/*.spec.ts',
    dependencies: ['setup-admin'], // Ensures admin login happens first
  },
]
```

### Setup Implementation
The setup scripts automate the Auth0 login flow using the credentials provided in the root `.env` file.

```typescript
import { test as setup } from "@playwright/test";
import path from "path";

const ADMIN_STORAGE_STATE = path.join(__dirname, "../../fixtures/storage-state-admin.json");

setup("authenticate as admin", async ({ page }) => {
  await page.goto("/");
  
  // Trigger Auth0 login (usually via a Login button or navigating to /admin)
  await page.getByRole("button", { name: /connexion|login/i }).click();
  
  // Interact with Auth0 Universal Login page
  await page.waitForURL(/auth0\.com/);
  await page.locator('input[name="username"]').fill(process.env.E2E_ADMIN_EMAIL!);
  await page.locator('input[name="password"]').fill(process.env.E2E_ADMIN_PASSWORD!);
  await page.getByRole("button", { name: /continue/i }).click();

  // Wait for redirect back to the app and confirm session
  await page.waitForURL(process.env.VITE_APP_URL || "http://localhost:5173");
  await page.context().storageState({ path: ADMIN_STORAGE_STATE });
});
```

## Test Categories and Conventions

### Public Tests (`/tests/public/`)
These tests run without any `storageState`. They verify that the site is accessible to search engines and guest users.

```typescript
import { test, expect } from "@playwright/test";

test.describe("Public Accessibility", () => {
  test("Static SEO pages return 200", async ({ page }) => {
    const routes = ["/pages/privacy-policy", "/pages/terms-of-service"];
    for (const route of routes) {
      const response = await page.goto(route);
      expect(response?.status()).toBe(200);
      await expect(page.getByRole("main")).toBeVisible();
    }
  });
});
```

### Authenticated User Tests (`/tests/auth/`)
These tests target features like the shopping cart, checkout, and personal profiles. They assume a valid user session.

**Note on Checkout**: Fufuni uses Stripe Checkout (hosted). Tests should verify the redirection to `stripe.com` but should not attempt to fill card details unless specifically testing the Stripe webhook flow via API.

```typescript
import { test, expect } from "@playwright/test";

test("User can proceed to Stripe Checkout", async ({ page }) => {
  await page.goto("/product/test-product");
  await page.getByRole("button", { name: /ajouter au panier/i }).click();
  
  // Open cart drawer
  await page.getByLabel(/ouvrir le panier/i).click();
  await page.getByRole("button", { name: /commander/i }).click();

  // Verify external redirect
  await page.waitForURL(/checkout\.stripe\.com/);
  expect(page.url()).toContain("stripe.com");
});
```

### Admin Tests (`/tests/admin/`)
Admin tests verify CRUD operations for products, categories, and orders. They require the `auth-admin` project.

## Cleanup Discipline and Data Management

Because Fufuni runs on SQLite (via Durable Objects), E2E tests often interact with real persistent data in the local environment. To prevent test pollution and "Ghost Data" (leftover test records):

1.  **Unique Identifiers**: Always use timestamps or UUIDs in names/handles.
2.  **Sequential Cleanup**: Every "Create" test should be followed by a "Delete" test, or include a cleanup block.

### Example: Robust CRUD with Cleanup
```typescript
import { test, expect } from "@playwright/test";

const TEST_ID = Date.now();
const CATEGORY_NAME = `E2E-Category-${TEST_ID}`;

test.describe("Admin Categories CRUD", () => {
  test.afterAll(async ({ request }) => {
    // Optional: Direct API call for cleanup if UI fails
  });

  test("Create and then delete a category", async ({ page }) => {
    await page.goto("/admin/categories");
    
    // Create
    await page.getByRole("button", { name: /créer une catégorie/i }).click();
    await page.locator('input[placeholder="T-Shirts"]').fill(CATEGORY_NAME);
    await page.locator('input[placeholder="t-shirts"]').fill(`e2e-handle-${TEST_ID}`);
    await page.getByRole("button", { name: /^create$/i }).click();

    // Verify presence
    const row = page.getByRole("row").filter({ hasText: CATEGORY_NAME });
    await expect(row).toBeVisible();

    // Delete (Cleanup)
    await row.locator('[title="Supprimer"] button').click();
    await page.getByRole("button", { name: /supprimer/i }).click();

    // Verify absence
    await expect(row).not.toBeVisible();
  });
});
```

## Writing New E2E Specifications

When adding a new test file:
1.  **Determine the scope**: Does it require a user session?
2.  **Select the Folder**: Place it in `public/`, `auth/`, or `admin/`.
3.  **Selector Strategy**: Use **ARIA-first** selectors (`getByRole`, `getByLabel`, `getByPlaceholder`). Avoid CSS classes which change with HeroUI updates.
4.  **Handling Backdrops**: Fufuni uses HeroUI/Framer Motion. Modal or Drawer closing animations might leave a "backdrop" that blocks clicks. Use `{ force: true }` or wait for the backdrop to be `hidden`.

```typescript
// Example: Handling transient UI states
async function dismissCookieBanner(page) {
  const btn = page.getByRole("button", { name: /accepter/i });
  if (await btn.isVisible()) {
    await btn.click();
    // Wait for the animation to finish so it doesn't block other elements
    await page.locator('[data-slot="modal-backdrop"]').waitFor({ state: "hidden" });
  }
}
```

## CI and Environment Configuration

In GitHub Actions, the E2E suite runs against the production-like build. 

### Environment Variable Mapping
The `playwright.config.ts` uses the following priority for `baseURL`:
1. `process.env.PLAYWRIGHT_BASE_URL` (Set in CI)
2. `process.env.PLAYWRIGHT_ENV === 'local' ? 'http://localhost:5173'`
3. The development deployment URL.

### CI Integration Details
- **Workers**: In CI, workers are capped at 2 to avoid overwhelming the Cloudflare Worker dev tunnel.
- **Retries**: 2 retries are enabled on CI to account for network flakiness in the Auth0/Stripe handshake.
- **Reporters**: Produces `html` (local review) and `github` (inline PR annotations) reports.

```typescript
// playwright.config.ts - CI configuration
export default defineConfig({
  forbidOnly: !!process.env.CI,
  retries: process.env.CI ? 2 : 0,
  workers: process.env.CI ? 2 : 1,
  use: {
    trace: 'on-first-retry',
    screenshot: 'only-on-failure',
  },
});
```
